# Metadata schema and hybrid (lexical + vector) retrieval for Italian AIFA drug documents

Scope: ~800 AIFA documents (RCP/SmPC + FI patient leaflets, ~395 products, 100 active ingredients, 173 MAHs), many near-duplicate generics. Store: Supabase Postgres + pgvector + tsvector. Queries in Italian, Chinese, English.

Method note: some findings below come from first-hand inspection (2026-11-26) of the live AIFA open-data CSV `https://drive.aifa.gov.it/farmaci/confezioni_fornitura.csv` and one RCP PDF downloaded through the `LINK_RCP` API. These are marked "[inspected]". Everything else is cited to a web source.

---

## 1. Which metadata fields matter, which vocabularies exist, and how AIFA fields map to them

### Takeaway
The AIFA package CSV already gives, per package (AIC 9-digit), the product code, name, package description (which embeds strength and form), MAH code and name, procedure type, pharmaceutical form (Italian standard term), ATC level 5, associated active ingredients (Italian names), supply/prescription regime and direct FI/RCP links. The revision date and QRD section structure are only in the PDF text itself (RCP section 10 "Data di revisione del testo", plus a per-page "Documento reso disponibile da AIFA il dd/mm/yyyy" footer). Strength, route, English INN and Chinese names are not columns and must be derived or mapped.

### Inferences
- `FORMA` values ("Compressa rivestita con film", "Gocce nasali, soluzione", "Soluzione iniettabile in siringa pre-riempita") look like the Italian EDQM Standard Terms. Mapping to English EDQM terms/codes is likely a near-exact string join against the EDQM Italian translation, but this was not verified against the EDQM database (account required).
- The ATC level-5 code gives levels 1–4 for free by prefix (`R`, `R01`, `R01A`, `R01AA`, `R01AA08`). Store all five as generated columns (or one `text` plus `LIKE 'R01A%'`/btree prefix) so "decongestionanti nasali" style queries can filter on level 3/4. English ATC level names can come from the WHOCC index (licence caveat above); Italian level names from AIFA's ATC registry (CC BY).
- Recommended per-document (`documents.metadata` / dedicated columns) fields, mostly from the CSV joined on `COD_FARMACO`:
  - `cod_farmaco` (6-digit, PK of the product, join key to the CSV), `aic_list text[]` (all 9-digit package AICs, also parsed from RCP section 8), `codice_ditta`, `mah_name` (RAGIONE_SOCIALE), `product_name` (DENOMINAZIONE), `procedure_type` (TIPO_PROCEDURA), `admin_status`, `supply_regime` (FORNITURA), `atc5` + derived `atc1..atc4`, `ingredients_it text[]` (PA_ASSOCIATI split on "/"), `ingredients_inn_en text[]`, `ingredients_zh text[]` (mapped), `forms_it text[]` and `forms_edqm_en text[]`, `strengths text[]` (normalised, e.g. `1 mg/ml`, from DESCRIZIONE and RCP section 1/2), `routes text[]` (from RCP 4.2 / description), `doc_type` (`RCP`|`FI`), `revision_date` (RCP §10 / FI §6 month-year → first day of month, plus `revision_text` raw), `published_by_aifa_date` (footer date), `version` (e.g. "Versione 10" when present), `equivalence_group` (from Class A/H lists, for generics), `is_reference_product` (if derivable), `language='it'`, `source_url`, `file_hash`.
  - Per-chunk fields: `doc_id`, `cod_farmaco`, `doc_type`, `qrd_section` (e.g. `4.8`), `qrd_section_title` (e.g. "Effetti indesiderati"), `qrd_parent` (`4`), `page_start/page_end`, `chunk_index`, plus denormalised copies of the most-filtered document fields (`atc5`, `ingredients_inn_en`, `product_name`, `mah`, `strengths`, `forms`) so the filter can be applied inside the single RPC without a join, and a `dup_group_key` (see §2).
- Text cleaning before chunking/indexing: strip the repeated per-page AIFA footer/disclaimer and the watermark fragments; otherwise "Agenzia", "Italiana", "Farmaco" and "AIFA" become high-frequency noise tokens in tsvector and in embeddings, and "Fa rm aco" fragments break sentences mid-way.
- RCP §1–2 header blocks are a reliable second source for name/strength/form, useful for FI documents too (FI §6 "Contenuto della confezione e altre informazioni" carries composition and MAH).

### Gaps
- I did not find an official AIFA data dictionary (tracciato) for `confezioni_fornitura.csv`; column meanings above are read from the data.
- Whether the stampati API exposes the revision date or version as metadata (without parsing the PDF) — the only date in the HTTP response/PDF info was the PDF ModDate, which looked like the AIFA publication date, not the text revision date. Treat the PDF §10 text as authoritative.
- FI section numbering was not inspected; per the EMA QRD template, the PL has sections 1–6, but I did not verify an AIFA FI in this pass.
- No verified Italian↔EDQM code mapping, and no AIFA statement on SPOR/IDMP adoption.
- Chinese drug names: no authoritative free INN→Chinese source was found in this pass (candidate sources not verified: WHO INN lists do not include Chinese consistently; Chinese pharmacopoeia names are copyrighted).

## 2. How to use metadata: hard filters vs soft boosts, query-time entity extraction, evidence

### Takeaway
Direct evidence that metadata filtering improves drug-label QA is thin; benchmarks either restrict retrieval to the right label (PharmaQA.IT retrieves only within the gold RCP) or use section-level passages (FDARxBench). The practical design is: detect drug/ingredient/strength/section in the query with a dictionary, apply a hard filter only on high-confidence exact matches (product or ingredient), use soft boosts for section and doc type, and collapse near-duplicate generics so they don't fill top-k.

### Cited Findings
- PharmaQA.IT (EACL 2026 Industry): 861 Italian extractive QA pairs over RCPs from PharmaER.IT (source pool 1,077 RCPs ≥10 pages; generated by Qwen3-VL-235B per page, human-validated by linguists). Mean RCP length 15,149.6 tokens; questions 29.8 tokens; answers 17.8 tokens. Retrieval: for each question they split only "the RCP containing the gold answer" and rank its chunks with multilingual-e5-base (cosine), top-k = 10. Hit@10 by chunk config (tokens–overlap): 64–16: 0.436; 128–32: 0.511; 256–64: 0.580; 512–128: 0.615. Best open model Mistral-Small-24B (ROUGE-L F1 0.656, EM 0.433) at 512–128; best API deepseek-chat (F1 0.679, EM 0.432). Authors fix a single retriever and do not test BM25/hybrid; they list unanswerable, multi-hop across sections/documents and patient-oriented questions as not covered. Dataset: huggingface.co/datasets/VillanovaAI/PharmaQA.IT. — [PharmaQA.IT paper](https://aclanthology.org/2026.eacl-industry.70.pdf)
- PharmaER.IT (CLiC-it 2025): Italian NER dataset built from AIFA RCPs; gold (manually validated) and silver (automatic) corpora; HF card shows labels including "sintomo" and "parte anatomica"; a related paper mentions 2,138 automatically annotated leaflets. — [PharmaER.IT paper, CEUR Vol-4112](https://ceur-ws.org/Vol-4112/109_main_long.pdf); [HF dataset card](https://huggingface.co/datasets/expertai/PharmaER.IT/blob/main/README.md?code=true)
- FDARxBench (2026): 17K+ questions on FDA labels; labels are split into section-level passages with unique IDs for provenance and retrieval; labels are hard because information is heterogeneous. — [FDARxBench arXiv 2603.19539](https://arxiv.org/html/2603.19539v1)
- ClinicalRAG (AAAI 2025) uses hierarchical RAG over label structure for label quality control, 96.1% accuracy in internal validation (internal, not independent). — [ClinicalRAG, AAAI 2025](https://ojs.aaai.org/index.php/AAAI/article/view/35384)
- A Findings-of-ACL 2026 cancer-patient QA paper argues many RAG pipelines use "metadata-blind" indexes and proposes metadata-aware retrieval (via NCBI E-Utilities); closest evidence for metadata-aware retrieval, but not drug labels. — [ACL Findings 2026.1429](https://aclanthology.org/2026.findings-acl.1429.pdf)

### Inferences
- With ~395 products but only 100 ingredients, many RCPs of generics of the same molecule are near-identical except name, MAH, excipients and AIC numbers. Without control, a query like "dose massima di amlodipina" returns 10 copies of the same §4.2 paragraph. Mitigation: compute `dup_group_key = (ingredients_inn sorted, strength set, qrd_section)` and a per-chunk `content_hash` / MinHash on normalised text (product names and MAH masked); at query time, after fusion, keep the best chunk per `(dup_group_key, near-dup cluster)` (diversity collapse), and list the other products as "same text also in: ..." in the citation.
- Hard filter only when the query names a specific product or AIC (exact dictionary hit on DENOMINAZIONE or 9/6-digit code) — then restrict to that `cod_farmaco` (and its FI/RCP). For an ingredient-only query, filter on `ingredients_inn_en && array[...]` (array overlap with GIN index) — this is safe because RCP text of other molecules is never the answer. For strength, form, MAH, section and doc type use soft boosts (a third RRF list or a multiplicative bonus), because users often get strength/form slightly wrong and a hard filter would yield empty results (strict mode would then wrongly refuse).
- Section routing via a small keyword map (e.g. "effetti collaterali/side effects/副作用" → 4.8 RCP / FI §4; "gravidanza/pregnancy/怀孕" → 4.6; "posologia/dose/剂量" → 4.2; "controindicazioni" → 4.3; "interazioni" → 4.5; "conservazione/storage" → 6.4 RCP / FI §5) as a soft boost; doc type boost: patient-style wording → FI, clinician-style → RCP.
- Entity dictionary build (Postgres table `drug_lexicon(term, lang, kind, cod_farmaco, inn_en, atc5)`): brand names from DENOMINAZIONE, Italian INN from PA_ASSOCIATI (strip salt suffix like "NITRATO", "CLORIDRATO" into a separate `salt` field), English INN via a mapping table (100 ingredients — feasible to curate manually or with an LLM and review), Chinese names (100 ingredients — curate manually; LLM-generated then pharmacist-reviewed). Match with `pg_trgm` similarity for typos plus exact `unaccent(lower())` lookup; at 100 ingredients/395 brands, an LLM query-understanding step with the lexicon in the prompt is also cheap.
- Because PharmaQA.IT restricts retrieval to the gold document, its hit@10 of 0.615 is an upper-bound-ish figure for in-document ranking with e5-base; corpus-wide retrieval across 800 near-duplicate documents will be harder, which is the main argument for product/ingredient filtering.

### Gaps
- I found no published ablation that measures accuracy gain from metadata filtering specifically on drug labels (Italian or otherwise). The claim that filtering helps is an engineering inference, to be proven on the local eval set.
- No public Italian drug-name synonym resource (brand ↔ INN ↔ English ↔ Chinese) with a clear licence was found; it must be built from the AIFA CSV (CC BY) plus curated translations.

## 3. Hybrid search: Italian full-text in Postgres, drug names/dosages/ATC codes, fusion, evidence, sparse alternatives

### Takeaway
Postgres ships an `italian` config (Snowball Italian stemmer + Italian stopwords); combine it with `unaccent` in a custom config. Drug names, ATC codes, AIC codes and dosages are better served by a second, non-stemmed `simple` tsvector (and/or `pg_trgm`) than by the stemmed one. Fuse with RRF as in Supabase's reference function (k = 50 default, per-leg weights). Evidence that hybrid beats dense-only on biomedical text is positive but mixed; BGE-M3's own paper reports dense+sparse gains on multilingual benchmarks.

### Cited Findings
- `unaccent` is a filtering dictionary that can be placed before a Snowball stemmer in a custom text search configuration, e.g. `CREATE TEXT SEARCH CONFIGURATION fr (COPY = french); ALTER TEXT SEARCH CONFIGURATION fr ALTER MAPPING FOR hword, hword_part, word WITH unaccent, french_stem;`. — [PostgreSQL docs: unaccent](https://www.postgresql.org/docs/current/unaccent.html)
- The one-argument `unaccent(text)` is not IMMUTABLE (dictionary lookup via search path), so expression indexes/generated columns need an IMMUTABLE wrapper naming the dictionary explicitly (`unaccent('public.unaccent'::regdictionary, $1)`); changing the rules file later requires reindexing. (This point came from the fetch tool's general PostgreSQL knowledge, not the doc page; verify with `\df+ unaccent`.) — [PostgreSQL docs: unaccent](https://www.postgresql.org/docs/current/unaccent.html)
- Supabase hybrid search reference: `hybrid_search(query_text text, query_embedding vector(512), match_count int, full_text_weight float = 1, semantic_weight float = 1, rrf_k int = 50)`; score = `coalesce(1.0/(rrf_k + full_text.rank_ix), 0.0) * full_text_weight + coalesce(1.0/(rrf_k + semantic.rank_ix), 0.0) * semantic_weight`; each leg fetches `least(match_count, 30) * 2` rows; GIN index on the tsvector, HNSW on the embedding; example uses `to_tsvector('english', content)` and `websearch_to_tsquery(query_text)` without an explicit config (falls back to the session default — a mismatch risk if content is indexed with `italian`). — [Supabase hybrid search docs](https://supabase.com/docs/guides/ai/hybrid-search)
- BGE-M3: one model gives dense, sparse (lexical weights) and multi-vector outputs; SOTA on MIRACL (multilingual) and MKQA (cross-lingual); the model card recommends "hybrid retrieval + re-ranking"; the MIRACL hybrid used `s_dense + 0.3 * s_sparse`. — [BGE-M3 paper arXiv 2402.03216](https://arxiv.org/pdf/2402.03216.pdf); [bge-m3 model card](https://huggingface.co/luodian/bge-m3/blob/main/README.md); [bge-m3 MIRACL reproduction](https://huggingface.co/datasets/hanhainebula/bge-m3_miracl_2cr)
- Biomedical evidence for hybrid: a 2025 PubMed QA system found BM25 candidates reranked by MedCPT cross-encoder gave 0.86 accuracy vs 0.83 for MedCPT dense alone and 0.63 for BioBERT dense (GPT-3.5 generator) — this "hybrid" is BM25 + rerank, not score fusion. — [arXiv 2505.07917](https://arxiv.org/pdf/2505.07917)
- BioRAG (BioNLP 2026): RRF of BM25 + dense reported faithfulness 0.534 and context recall 0.507, described as 50% and 85% gains over naive dense retrieval. — [BioNLP 2026.10](https://aclanthology.org/2026.bionlp-1.10/)
- Counter-evidence: a 2026 BioASQ study (250 QA pairs) found the dense baseline (composite 0.822) within 0.005 of the best of five strategies including hybrid. — [arXiv 2605.02520](https://arxiv.org/abs/2605.02520); a 2026 large-scale study ("When Retrieval Doesn't Help") compares BM25, TF-IDF, MedCPT and BM25+MedCPT RRF across 10 datasets; headline numbers not verified. — [arXiv 2606.04127](https://arxiv.org/pdf/2606.04127)

### Inferences
- Two lexical columns per chunk:
  1. `fts_it tsvector` = `to_tsvector('it_unaccent', clean_text)` with `CREATE TEXT SEARCH CONFIGURATION it_unaccent (COPY = italian); ALTER ... ALTER MAPPING FOR hword, hword_part, word WITH unaccent, italian_stem;` — for prose ("effetti indesiderati", "gravidanza", "insufficienza renale").
  2. `fts_exact tsvector` = `to_tsvector('simple', unaccent_imm(normalised_text))` — no stemming, no stopwords, for brand names, INNs, ATC/AIC codes and strength tokens. The Italian stemmer will mangle drug names (e.g. stripping endings of "amlodipina"/"amlodipino" may be fine, but brand names and codes gain nothing and can collide). Weight these with `setweight`: product name/INN/ATC header terms as 'A', section title as 'B', body as 'D'.
- Dosage handling: Postgres's default parser splits "5 mg" into `5` and `mg`, and "5mg" may be parsed as a single numword token; "1 mg/ml" into several tokens. Normalise at index and query time into a single synthetic token (e.g. `5mg`, `1mg_ml`, `2_5mg` for "2,5 mg" — note Italian decimal comma) appended to `fts_exact`; same normaliser in the query parser. Put ATC (`r01aa08`) and AIC (`000590012`) into `fts_exact` as well, plus ATC prefixes (`atc_r01`, `atc_r01a`) as tokens if lexical ATC-level matching is wanted.
- Query side: use `websearch_to_tsquery('it_unaccent', q)` with the config passed explicitly; build an OR-query (Postgres `websearch_to_tsquery` ANDs terms by default, which hurts recall for long natural questions) — e.g. build the tsquery from extracted keywords joined with `|`, and rank with `ts_rank_cd`. Postgres FTS has no BM25 IDF; on 800 docs with heavy duplication this is a real gap — options: `pg_search` (ParadeDB BM25, availability on Supabase not verified), or accept `ts_rank_cd` and let the reranker fix order.
- Fusion: RRF (k≈50–60) over three legs is a reasonable start: dense, `fts_it`, `fts_exact`; weight `fts_exact` higher when the query contains a detected entity/code/dose. Keep weights tunable via eval rather than hard-coded. The myRAG v2 graph already has RRF + optional lexical leg (`RAG_LEXICAL_SEARCH`) and `hybrid_search_chunks`; the Italian config and the exact-token leg are the missing pieces (based on AGENTS.md, not re-verified in code here).
- Sparse learned alternatives: BGE-M3 sparse weights are multilingual (incl. Italian and Chinese) and can be stored as pgvector `sparsevec` (pgvector ≥0.7) with an HNSW index — avoids hand-built Italian stemming and works cross-lingually to a degree. SPLADE multilingual models are less mature for Italian; no Italian-specific evaluation of either was found. Given only ~800 docs (maybe 20–40k chunks), a cross-encoder reranker (multilingual, e.g. bge-reranker-v2-m3 or Cohere/Voyage multilingual) over the fused top-50 likely matters more than which sparse method is used.

### Gaps
- No published evaluation of Postgres `italian` FTS vs BM25 vs learned sparse on Italian drug documents was found.
- No source verified for how `ts_rank_cd` vs true BM25 differs in effect on small, duplicated corpora.
- Whether ParadeDB `pg_search` is installable on hosted Supabase was not checked.
- BGE-M3 per-language (Italian) MIRACL numbers were not extracted (Italian is not a MIRACL language; MKQA includes Italian, numbers not retrieved).

## 4. Cross-lingual handling: query translation vs multilingual embeddings; medical terminology mapping and licensing

### Takeaway
Use multilingual embeddings for the dense leg (no translation needed), and translate/normalise the query into Italian (plus extracted Italian INN/brand) only for the lexical legs; Chinese/English queries otherwise match nothing in an Italian tsvector. MedDRA has an Italian translation and AIFA expects MedDRA terms in RCP 4.3/4.4/4.8, but it is subscription-licensed and may not be redistributed; for this corpus a small self-built IT/EN/ZH synonym table for the 100 ingredients and common adverse-reaction terms is more practical.

### Cited Findings
- Goworek et al. (Nov 2025): dense retrievers trained for CLIR consistently outperform lexical matching and benefit little from document translation; recommend multilingual embeddings/alignment over translation pipelines, especially cross-script. — [arXiv 2511.19324](https://arxiv.org/html/2511.19324v1)
- Ranaldi et al. (2025): query translation (tRAG) can produce wrong translations leading to wrong retrieval; MultiRAG (multilingual retrieval) outperforms monolingual RAG, but cross-lingual variation in retrieved content causes inconsistencies. — [arXiv 2504.03616](https://arxiv.org/html/2504.03616v2)
- Amiraz et al. (2025, Arabic–English RAG): large drops when query and document languages differ; fixes were forcing balanced retrieval across languages or translating the query, both with substantial gains. — [arXiv 2507.07543](https://arxiv.org/pdf/2507.07543v2)
- MedDRA is translated into Italian (and Chinese, among others); one subscription per organisation; subscribers may not sublicense or distribute MedDRA to third parties, and sharing with a non-subscribing organisation violates the licence. — [MedDRA (Wikipedia)](https://en.wikipedia.org/wiki/MedDRA); [MedDRA data-sharing statement (Italian, Law Insider copy)](https://lawinsider.com/it/contracts/iHLcbRNCv4H)
- AIFA guidance on SmPC/PL translations expects MedDRA terminology in clinical sections (SmPC 4.3, 4.4, 4.8) and points to an Italian MedDRA introductory guide. — [AIFA: presentazione traduzioni RCP, FI, etichette](https://www.aifa.gov.it/presentazione-traduzioni-rcp-fi-etichette)
- UMLS historically included an Italian MedDRA source (MDRITA). — [NLM MDRITA source release doc (archived)](https://webarchive.library.unt.edu/eot2008/20090509180820/http:/www.nlm.nih.gov/research/umls/sourcereleasedocs/2009AA/MDRITA)

### Inferences
- Dense leg: embed the raw query (any language) with a strong multilingual model (the project's current embedding — Qwen3 via OpenRouter per the task list — is multilingual; BGE-M3 is an alternative). No translation needed.
- Lexical legs: an LLM "query understanding" call (already a latency budget item) outputs `{lang, query_it, entities: {product, inn_it, inn_en, strength, form, route}, section_hint, doc_type_hint}` as a Pydantic/Zod schema (project rule). Use `query_it` + Italian entity names for `fts_it`/`fts_exact`. Since RCP 4.8 uses MedDRA-style Italian terms, asking the LLM to render adverse-reaction terms in standard Italian medical terminology ("cefalea" not just "mal di testa") improves lexical recall; also index common lay ↔ technical pairs via a Postgres thesaurus/synonym dictionary or just expand the query.
- For voice (latency-sensitive) skip translation and run dense + `fts_exact` only (entity tokens are language-independent: brand, INN often close across IT/EN, codes, doses).
- Licensing: MedDRA requires an MSSO subscription (free tiers exist for some regulators/academia per general knowledge, not confirmed here); do not ship MedDRA term lists in the repo. MeSH Italian translation (by ISS) and SNOMED CT Italian were not researched in this pass; Italy's SNOMED CT membership status not verified. WHO ATC: free online lookup; bulk file paid. EDQM: free with account, attribution, no modification. AIFA data: CC BY 4.0.

### Gaps
- No source found comparing translate-then-BM25 vs multilingual dense specifically for Italian medical/regulatory text or for Chinese→Italian.
- MedDRA free academic/non-commercial licence terms not confirmed (check MSSO site).
- MeSH Italian (ISS translation) and SNOMED CT Italian availability/licensing not researched.

## 5. AIFA-specific data access: open-data listing, document links, revision dates

### Takeaway
`drive.aifa.gov.it/farmaci/confezioni_fornitura.csv` (≈82 MB, semicolon CSV, daily-refreshed per third parties) is the master table: it has AIC, COD_FARMACO, MAH, procedure, form, ATC, ingredients, supply regime and direct FI/RCP download URLs. Revision dates are not in the CSV; parse them from the PDF (RCP §10 month-year, FI last section) and use the per-page "Documento reso disponibile da AIFA il dd/mm/yyyy" footer as the publication date for change detection.

### Cited Findings
- [inspected] `confezioni_fornitura.csv` size 82,562,306 bytes, 160,135 data rows on 2026-11-26; header listed in §1; `LINK_FI`/`LINK_RCP` populated for all non-homeopathic rows. — [AIFA confezioni_fornitura.csv](https://drive.aifa.gov.it/farmaci/confezioni_fornitura.csv)
- [inspected] The stampati endpoint returns the PDF directly (`application/octet-stream`, filename `RCP_{ditta 6-digit}_{farmaco 6-digit}.pdf`); no API key was needed for this GET. — [AIFA stampati API example](https://api.aifa.gov.it/aifa-bdf-eif-be/1.0.0/organizzazione/1136/farmaci/590/stampati?ts=RCP)
- [inspected] RCP text: §9 "Ultimo rinnovo: Giugno 2010"; §10 "Settembre 2026"; "Versione 10"; footer "Documento reso disponibile da AIFA il 01/10/2026" on each page. — same source as above
- Medifontis collects each AIFA source daily and states the packages dataset includes FI/RCP links; it lists other AIFA sources (ATC, equivalence groups, active ingredients, shortages) pointing to the AIFA "Liste dei farmaci" page. — [Medifontis](https://www.medifontis.com/it/it/)
- AIFA "Liste dei farmaci" also offers Class A/H lists by ingredient and by trade name, the ATC registry, and ingredient-per-package with dosage and unit; some files show an older "data ultimo aggiornamento" (e.g. ingredient list dated 12/10/2022). — [AIFA Liste dei farmaci](https://www.aifa.gov.it/liste-dei-farmaci)
- An older AIFA open-data operating manual (April 2019) documents spending/consumption files with fields `atc1`..`atc4` and descriptions; these are separate from the package registry. — [AIFA OpenData Manuale Operativo 2019](https://www.aifa.gov.it/documents/20142/0/OpenDataManualeOperativo03042019.pdf)

### Inferences
- Ingestion keying: one document per `(cod_farmaco, doc_type)`; store `file_hash` and the footer date; a daily/weekly job re-downloads only when the footer date or hash changes (the pipeline already has file/content-hash dedup and versioning stages).
- For centrally authorised products (`Procedura Centralizzata`, 12,608 packages) the Italian RCP/FI is the EMA Italian product information; the same EMA QRD section numbering applies, which makes section parsing uniform across procedure types.
- Revision-date parser: regex for the line(s) after "10. DATA DI REVISIONE DEL TESTO" accepting Italian month names ("Gennaio"…"Dicembre") + year, or dd/mm/yyyy; strip the watermark fragments first, because they are interleaved between the heading and the date in pdftotext output.

### Gaps
- No official statement of the CSV refresh frequency (daily refresh is reported by a third party only).
- Not verified whether the stampati API has rate limits or terms of use beyond CC BY for the CSV; Medifontis notes links do not grant document redistribution rights.
- FI revision-date location/format not inspected.
