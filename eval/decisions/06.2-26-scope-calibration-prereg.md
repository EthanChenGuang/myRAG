# 06.2-26 scope gate calibration: pre-registered criteria

Status: pre-registered. Committed and pushed before the score-only run and before `python -m rag_eval.calibrate scope` ran (D-37 rule of the orchestrator). The criteria below are not changed after the run; a result that misses them is reported as a finding, never fixed by loosening them.

## Precondition (D-34 review gate)

- The real-embedder separation report `eval/reports/q62-scope-separation-real/openai-3-small-1536/report.json` (06.2-42, route A) has `embedder != "fixture-ngram"`, at least 5 groupings and `verdict.d34_separates_at_least_as_well`. Checked before this file was written: `true`.
- The D-34 grouping is kept. This plan writes fixture cells only.

## Inputs

- One score-only run: `npm run test-rag -- --run-config eval/config/runs/q62-scope-score.json --out eval/out/q62-scope-score` (prechunked fixture mode, `RAG_PIPELINE=v2`, `RAG_QUERY_LAYER=true`, `RAG_SCOPE_GATE=true`, with the committed empty `eval/config/scope-gate.json`, so every item is `unsure` and retrieves).
- Rows: one per golden item with a trace. An item is left out, and counted by reason, when it is unknown, traced twice, its committed split differs from `assign_split`, or its trace has no `scope_gate` score (`no_scope_score`).
- Sets: answerable items (`answerable = true`, including the 06.2-41 dominant-language items) and no-answer items (`answerable = false`: the `no_answer` items and the `off_domain` items of 06.2-22).
- Split: dev rows fit, test rows check (the frozen split, `assign_split`).

## Fit and check, per embedding profile and RAG mode (strict, balanced, flexible)

- Profile: the profile the scored run used (`RunManifest.embedding_profile`, else the legacy profile id when `RAG_EMBEDDING_PROFILES` is off). No cell for any other profile.
- Source: `fixture` when the run's embedder is `fixture-ngram` or the run used the fake edge; `--source live` needs `--separation-report` naming a report whose `embedder` is not `fixture-ngram`.
- Target false-refusal rate per mode: `targets_by_mode[mode].target_false_refusal` from `eval/config/refusal-calibration.json` when set, else its single `target_false_refusal`. Today every mode reads the single target, 0.05.
- Dev minimums and holdout minimums: the `fixture` (or `live`) minimums of `eval/config/refusal-calibration.json` (fixture: dev 5 answerable and 3 no-answer, holdout 2 and 1).
- Threshold: `fit_threshold(dev answerable scores, dev no-answer scores, target)` from `rag_eval.calibrate.refusal`. A dev set below the minimums, or a fit that refuses nothing (never-refuse threshold), gives an uncalibrated cell.
- Holdout: the refusal pass rule, `false_refusal_test <= target + max(noise_floor, 1 / n_test_answerable)`, with `noise_floor` from `eval/config/noise.json` (0.02), through `holdout_check`. The cut is `threshold - margin`. The margin is the smallest `k * 0.005` (k = 0 to 40) whose cut passes. No passing margin, or a test set below the minimums, gives an uncalibrated cell with its rates at margin 0.
- Output: `eval/config/scope-gate.json`, validated by `ScopeGateCalibration`, written with the stable JSON writer; `recorded_at` is the scored run's `created_at`, so two runs over one report write identical bytes.

## Acceptance

- Every mode has a cell for the run's profile, and the file says `source: fixture`.
- With the written file and the switch on, a smoke run of the same run config refuses the `off_domain` items in zh, en and it as `out_of_scope`. Missing this is reported as a finding with the counts; the criteria are not changed.
- Fixture evidence proves the wiring and the statistics only. It does not make `RAG_SCOPE_GATE` shippable: the runtime applies a `fixture` calibration only to eval requests, and the live calibration of a real profile is 06.2-33's step. The eligibility comparison against the noise band is 06.2-30's.
