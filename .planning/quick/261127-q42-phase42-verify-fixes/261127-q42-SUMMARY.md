## What changed

- **W-2 (DATA-21):** `DELETE /api/images` now calls `recomputeDirtyDupClusters(scope, { signal })` after the chunk and document
  delete, inside the verified scope (`authorize` returns the scope). The sweep of hard chunk deletes found one more path missing the call:
  the Nango orphan hard delete (`deleteNangoLineages` in `src/lib/nango/sync-manager.ts`, unified pipeline with async off). It now
  recomputes in the owner scope after the rows are gone. The call is gated by the switch and never fails the delete (D-20 contract).
  The other delete paths were already covered: the documents route, soft delete (`soft-delete.ts`, which also serves async Nango) and
  publish/supersede. Two paths were left alone: `scripts/rag/reprocess-documents.js` (legacy script that deletes and re-inserts the
  chunks, no tenant scope) and the legacy Nango path without a tenant (cascade delete, no `tenant_key`, so there is no tenant cluster to
  recompute).
- **W-3:** `phase42-gates.json` labels `versions` as `ROADMAP-4.2-SC3` and `table` as `ROADMAP-4.2-SC5`. The committed
  `eval/reports/phase-04.2/README.md` and `gates.json` got the same label swap by hand. **Deviation:** the report was not re-rendered
  with `--reuse`. Harness runs are gitignored, so `--reuse` needs a fresh run, and a fresh fixture run on `ci/merge-train-39` gives
  different numbers. That run would turn the verdict to FAIL: diversity and identifier drop on the `category:scanned` slice, and
  descriptive items go from 159 to 196. Committing it would have changed values, which the task forbids.
- **W-4:** In `COORDINATOR-04.2.md`, item (a) (ROADMAP SC5 wording) and `04.2-12-golden-rule.md` (resolved by 04.2-37) are marked done.
- **W-5:** Owners assigned in `COORDINATOR-04.2.md`:
  - (j) domain names in `exact-id.ts` / `ids/shapes.ts`: reserved quick `261127-idn-identifier-neutral-names`.
  - `04.2-06-eval-tuning-overrides.md`: Phase 7 regression plan 07-25, with the statistics in 07-24.
  - `04.2-21-embed-sources.md`: product decision, pending the owner.
  - `04.2-02-settings-classification.md`: **not fixed here; the condition is not met.** Of the closed `RebuildMechanism` set, only
    `reparse` re-runs the writers of these stores (`indexDocumentForLookup` in embed-write, `clusterPublishedDocument` at publish);
    `rechunk` and `relex` do not. A classification-only change would therefore be wrong, and the three entries stay `reparse`.
    Owner: reserved quick `261127-rbm-rebuild-mechanisms-42` (contract, generated Zod, checker set and rebuild plan).
- **W-6:** REQUIREMENTS.md LANG-07 gains a note: the dictionary is read with `loadEffectiveDictionary` (the loader behind
