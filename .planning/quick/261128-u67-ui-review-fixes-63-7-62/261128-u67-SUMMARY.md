## Findings and fixes

### 06.3

- **HIGH, paused-run buttons on amber (`source-sync.js:1081`).**
  - Remove documents is now a solid `btn-error`, which uses error-content text.
  - Dismiss run is now solid `bg-base-100 text-base-content border-base-300`.
  - Neither button is a white outline on amber any more.
- **HIGH, overflow below 768px (also at 768 in it).**
  - Connections table: below 1024px each connection stacks into one block. The rows, cells and paused row become `max-lg:block`/`flex-col`, and the header is hidden. Last full reconcile, Status and Mode each get an inline label.
  - Purge records: the same stacking below 768px. The Check badge is in the flow, and Check again sits under Show check.
  - Measured with Playwright: no sideways overflow at 360, 768 or 1024 in any of en, zh, it, with the disclosures open.
- **MED, list 404.** It now shows `error.off` in a neutral `alert` with an info icon (en/zh/it) for both panels. The status line announces it, and the alert host stays empty.
- **MED, Reload panel on the error alert.** It is now a solid `bg-base-100 text-base-content` button, not a white outline. Below 768px it is 48px tall.
- **MED, SharePoint name truncated at 360.**
  - Names use `line-clamp-2 break-words` instead of `truncate`. The "Included by" line wraps too.
  - Below 640px the Open button shows only its icon. Its `aria-label` already names the item.
- **MED, touch targets below 768px.**
  - The `summary` elements (Show files, Show check), the deletion-mode and reason selects, the picker row labels (one hit target with the checkbox) and the picker Open buttons are all 48px.
- **MED, invisible select focus ring.** The deletion-mode and purge-reason selects now get `focus-visible:[outline-color:…--p]`. In the browser this measures as a 2px solid primary outline (`oklch(0.66 0.196 275.75)`), where it was 20% alpha before.

### 07

- **H-1.** `ingestImpactCreateGuard` now uses the counts it is given. When `options.groups` is present (the add-language preview), it opens the dialog with the three groups, the total and the note, and never calls the impact route. The test makes that route answer 500 and asserts zero calls.
  - An unlabelled setting such as `RAG_SUPPORTED_LANGUAGES` is listed once, as monospace. Before, it appeared twice: once as the label fallback and once as code.
- **M-2.** The rollouts comparison stacks Measure, and below 768px the verdict badge, under Language. At 360 the only columns are Language and Candidate now. Measured: no overflow at 360 in en, zh or it.
- **M-3.** Fields with `aria-invalid` get `input-error` / `textarea-error` / `select-error`, and the workspace key input gets `input-error`. Each message is a `text-error font-semibold` line with an icon.
- **M-4.** In `ragUiMapError`, a 400 with no usable `details[].message` and no `error` string now maps to `code.unknown` with the status, for example "The server reported 400.". This replaces the dangling "The request was not accepted:". The change is in shared `rag-ui.js`, so it also applies to the other Config UI panels that use the mapper.

### 06.2

- **MED, first-load 404.** It maps to `error.notAvailable` ("The scope gate is not available on this deployment. Update the app, then reload.", en/zh/it) in a neutral info alert with Reload. Action 404s keep `error.changed`.
- **MED, error shown twice.** On a load failure (401, 403, 404, 5xx, network) the sentence appears only in the alert. The `role=status` line says "Status not loaded." (en/zh/it).
- **MED, Thresholds cut off at 1024.**
  - The Recorded column shows only from 1280px (`max-xl:hidden`).
  - Between 1024 and 1279px the date moves under the profile id as "Recorded: <date>".
  - Profile ids wrap with `md:break-words`.
  - Measured: no overflow at 1024.
  - Note: `index.html` sets `.hidden{display:none!important}` and only overrides it for `md:block`, `md:table-cell` and `lg:table-cell`. New breakpoint pairs therefore have to use `max-*` variants, not `hidden <bp>:x`.
