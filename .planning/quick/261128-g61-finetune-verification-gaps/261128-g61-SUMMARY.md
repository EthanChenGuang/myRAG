# Summary: Phase 6.1 verification gaps closed (G-1, W1, W2, W3, W5, IW-1, IW-3, IW-4)

The G-1 blocker is fixed. A probe card that training builds for the default Qwen base model now passes `checkFinetuneProbe` on an
endpoint that serves the same model. Every item got a test that failed on the old code first (RED commits below). With `RAG_FINETUNE`
off, nothing changes: the slot stays unbound and unsearched, and only `ft-consent revoke` joins the two lists as a command allowed while
off (W5 asks for this).

## Items

### G-1 (BLOCKER): one probe role list on both sides
- `rag_sidecar.contracts.finetune.PROBE_ROLES = ("query", "document", "query")`, defined once. `ProbeSet` now has a required `roles`
  field, a fixed tuple built from `PROBE_ROLES`. A probe file without roles, or with other roles, is refused, so an old probe.json
  computed with the wrong prompts cannot reach a card.
- `train.probe_set` embeds each text with the prompt of its role: texts 0 and 2 with `query_prompt`, text 1 with `document_prompt`.
  The prompt is passed as is (an empty prompt is `""`, not `None`), which matches the TS prefix exactly. Docstring fixed.
- `gen:schemas`: `scripts/gen-zod.mjs` now renders a JSON Schema 2020-12 fixed-length `prefixItems` array as a Zod tuple. Only the two
  probe schemas use it. `finetune-slot.ts` derives `FINETUNE_PROBE_ROLES` from `ProbeSetSchema.shape.roles` and has no local constant.
  The slot provider refuses a stored card whose `roles` differ (`malformed`). A card without `roles` (registered before this change) is
  still checked by its vectors.
- The cross-language regression test is `tests/rag/embeddings/finetune-probe-parity.test.ts`. It runs `train.probe_set` in Python
  (`uv run`) with the default spec from `eval/config/finetune.json` and a sha256 hash encoder. It feeds the card to `checkFinetuneProbe`
  against the fake slot endpoint serving the same encoder and asserts `match`. On the old code it failed with `mismatch`.
- The client-side card schema now requires `probe.roles`, so the TS test cards (`finetune-cli`, `finetune-revoke-prune`,
  `finetune-lifecycle` helper) carry it.

### W1: slot prompts in .env.local and in the Config UI
- New `scripts/config-env-quote.js` `formatEnvValue`. An empty or plain value is written byte for byte as before (`KEY=`). Any other
  value is quoted so that dotenv reads it back unchanged:
  1. double quotes, with `\n` and `\r` escaped, when the value has no `"` and no backslash;
  2. otherwise single quotes, when it has no `'` and no line break;
  3. otherwise backticks, when it has no backtick and no carriage return;
  4. otherwise the save throws instead of changing the value.
- All 12 template sites (4 prompts × 3 templates) in `config-server.js` go through it.
- The four prompt fields are now `<textarea rows="2">`, styled like the existing link-allowlist textarea. Their help text says line
  breaks and trailing spaces are kept. Load and save already handle textareas generically (`field.value`, input events on `textarea`).

### W2: drop reasons by language
- `FilterReport.dropped_by_language: {lang: {reason: n}}` is required. A validator checks that it sums to `dropped` for each reason and to
  `by_language[lang].dropped` for each language.
- `filters.build_report` fills it with every reason for each language. The stdout summary adds the non-zero `{lang}_dropped_{reason}`
  counts. Schemas regenerated.

### W3: prune age
- `prune` now counts a bundle's age from the manifest's `created_at` only. File mtimes no longer extend it. `last_activity` was replaced
  by `created_at`.
- Scheduling is in `docs/finetune-retention.md`: cron or a systemd timer on the host that holds the bundles, never Vercel cron. There is
  also a one-line pointer in AGENTS.md (Phase 6.1).

### W5: revoke while RAG_FINETUNE=off
- `ft-consent revoke` is allowed while off, in `FT_ALLOWED_WHEN_OFF` alongside the two lists. It records `scope none` and the SQL taints
  the versions in the same transaction. The other ft-* commands still refuse. The off message and AGENTS.md now say this.

### IW-1: rag_purge_hook_finetune (migration 0992)
- Number: I fetched every origin branch and took the next free 09xx number after the highest one used (0991 on fix/uf1-direct-insert).
  I pushed a placeholder at once (bcac343d).
- `rag_purge_hook_finetune(p_tenant_key, p_lineage_id, p_document_ids) RETURNS bigint` is SECURITY INVOKER with `SET search_path = ''`,
  revoked from PUBLIC, anon and authenticated, and granted to service_role. It calls `rag_assert_tenant_key` first.
  - **Tenant purge** (no lineage and no ids): deletes the tenant's consent row, taints every version trained on the tenant, and removes
    its key from `tenant_keys`.
  - **Document purge**: taints the tenant's versions, because their weights may hold the purged text, and keeps the consent row and the
    keys. A listed document of another tenant raises 22023.
- Decision: the registry cannot tell which documents a version was trained on, so a document purge taints conservatively (security
  first). Taint goes through `status`, so the 0654 trigger drops slot evidence and deactivates bindings exactly as a revoke does.
- To make key removal possible, the 0651 constraints `tenant_keys_shape` and `tenant_scope_single` now allow an empty `tenant_keys` once
  `tainted_at` is set (dropped and re-added, idempotent).
- Inventory registration is guarded with `to_regprocedure('public.rag_purge_store_inventory()')`, the same way 0976 does it. The
  inventory is not on trunk, so the block only raises a notice. Phase 6.3 (06.3-19) should list `rag_finetune_consent` and
  `embedding_model_versions` under store `finetune`.
- Not folded into the setup files. The 06.1-17 parity base ("database without the fine-tune migrations") now leaves out 0992 together
  with 0651-0654.
- Tests: `tests/rag-db/finetune-purge-hook.test.mts`, both modes, 15 tests: attributes and grants, tenant purge, idempotent second call,
  document purge, cross-tenant document refused, key of the other mode refused, anon and authenticated refused (42501), migration applied
  twice.

### IW-3: tainted active slot
- When a tainted version is on the ACTIVE slot, revoke still records everything (taint, steps, prune when `--prune-root` is given). It
  then prints a "roll back now" line and exits 1. `finetune-cli` and `finetune-release-lifecycle` now expect exit 1 there.
- The `active-profile.ts` startup check has one more step, run only when the active profile's provider is `ft_slot_a` or `ft_slot_b`. It
  reads `rag_finetune_list_models` (best effort) and logs one `[Embedding Profile] ACTIVE PROFILE SERVES A TAINTED FINE-TUNED VERSION
  {profile, model}` warning with the rollback command, carrying ids only. The verdict is unchanged. Other providers make no extra call;
  a test asserts this.

### IW-4: bge-m3 re-embed cost
- `bge-m3` is added to the provider list in `reembed/cost.ts`. `tests/rag/ingest/reembed/cost.test.ts` covers the catalog price, the
  estimate flag and note, the default model, and an unknown provider still being refused.
