# Phase quick-261127-074 Plan 01: Section outlines Summary

This adds a data-driven pass before chunking. Outlines in an operator JSON file named by `RAG_SECTION_OUTLINES` turn numbered section markers that sit mid-line into Markdown headings. Contents runs and cross-references are skipped, and a file holding several products is split into labelled variants. The pass is wired into `chunkDocument`, the parent-child and profile builders, the ingest chunk stage, the ingest dual-write and `rag:rechunk`. Each outlined chunk is stamped with `metadata.section_outline` (`id@version`), and the ingest fingerprint gets `chunk_prep.section_outline`. With the variable unset, every output and every hash is the same as before.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Contents-run detection swallowed the first real section**
- **Found during:** Task 1, while designing the fixture.
- **Issue:** Step 6 takes the longest run whose span fits `max_span_chars`. A contents line followed directly by the first real marker (`… 3 Notes\n1 Name Alpha …`) fits inside 80 characters. The real "1 Name" then joins the run and is dropped with it, so the variant loses its opening marker.
- **Fix:** A contents run now stops before an occurrence of a section it already named, and must hold at least two occurrences. Without the second rule, an outline with a single level-1 section would treat every lone marker as a contents list. The rest of PD-3 (more than half of the level-1 keys) is unchanged. The task 1 fixture, which has the contents line directly before the first variant, covers this.
- **Files:** src/lib/rag/ingest/outline/normalize.ts
- **Commit:** 5c61a98f

**2. [Rule 1 - Bug] The chunk stage threw on a context without a state**
- **Found during:** full vitest run (`tests/rag/table-header-repeat.test.ts`, 3 tests).
- **Issue:** `delete ctx.state.sectionOutline` throws when a caller's stage context has no `state`.
- **Fix:** The key is deleted only when a state exists.
- **Files:** src/lib/rag/ingest/stages/chunk.ts
- **Commit:** e3a057ef (a separate fourth commit, so there are 4 commits instead of 3)
