All four code changes apply only on non-default switch combinations or in CI. With every switch off, the output is byte-identical, because the changed branches run only when the sentinel fires, and the sentinel exists only under `RAG_PARTIAL_ANSWER_RULE` / `RAG_CONTEXT_RELEVANCE_RULE`.

- **B1** `src/app/api/chat/route.ts` (the onFinish cache store): passes `isRefusal: answerTurn.refusedByModel()`, the same check as the `knowledgeBaseContext && !answerTurn.refusedByModel()` gate earlier in the file.   - Effective only with v2, `RAG_SEMANTIC_CACHE` on, and either rule on.
- **B2** `src/app/api/embed/chat/route.ts` (streamText onFinish): a sentinel refusal sets the log outcome to `refused_no_context` with `answerTurn.answerLanguage`, as the chat route does with `setRagLogOutcome`. The cache store gets `isRefusal: refusedByModel` and no sources.
  - The `answered` default after `streamText` returns is kept, because onFinish runs later and overrides it.
  - The cache part also needs `RAG_SEMANTIC_CACHE_EMBED_STORE=true`.
- **gap 6a** `src/lib/rag/security/link-targets.ts`: `compileOutputGuardRules` now calls `parseOutputGuardRules` (from `credential-rules.ts`). The runtime path now also rejects back-references and duplicate rule ids. The committed rules file passes unchanged.
- **gap 6b** `scripts/ci/check-rag-boundary.mjs`: new rule `eval-harness-import`, which applies to `src/` only.
  - Relative specs are resolved against the importing file. Other specs match `eval/harness` as a path segment.

  - The current tree has 0 violations (2650 files scanned).
