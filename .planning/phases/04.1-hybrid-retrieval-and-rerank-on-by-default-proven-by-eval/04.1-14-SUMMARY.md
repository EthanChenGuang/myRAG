# Phase 4.1 Plan 14: legacy_rule judges the legacy pool Summary

**Under `RAG_REFUSAL_FLOOR=legacy_rule`, v2 now refuses on the fixture exactly as legacy does in prechunked mode (21 of 30 no-answer items, 48 of 134 answerable items, same as the legacy run). The `similarity` floor, the legacy pipeline and the gate criteria are unchanged.**

## Diagnosis

Six runs under `eval/out/p41-diag/` (`v2-default`, `v2-default-similarity-floor`, `legacy`; both fixture modes; `--no-gate`, not committed). The per-item join reads each v2 trace's candidates (legs, dense similarity, document name, content) and the floor in force, and checks each candidate against the legacy run's pool for the same item. Ingest runs re-ingest, so pool membership is matched by chunk content, not chunk id.

No-answer items that `v2-default` (legacy_rule) answers, by the candidate that made `legacyRuleFloor` answer. All items count (the gate's n is the gated dev subset):

Floors in force: prechunked 0.1159 (the eval fixture calibration, `evalFloorCalibration`), ingest 0.65 (the calibration file names prechunked only). Synthetic-similarity rows: none decided an item. Exact-id rows appeared in ingest only together with a dense leg (real similarity); no row carried only `exact_id`.

The empty legacy term: `legacyQueryTerms` folds a long Chinese word to `''`, and every text contains `''`. Legacy has the same behaviour, so any Chinese query with a non-empty legacy pool answers in both pipelines. Kept, as the plan requires; it is now bounded by the pool exactly as in legacy.

**Similarity floor, ingest over-refusal.** `v2-default-similarity-floor` ingest refuses 162 of 189 answerable items, 123 of them items legacy answers. Measured cause: `eval/config/fixture-score-calibration.json` names `fixture_mode: prechunked`, so in ingest mode the floor falls back to the legacy text floor 0.65, while the fixture embedder's top similarities sit around 0.2 to 0.6 (examples: general items 0.34 to 0.62, table items 0.20 to 0.32). Left as measured: a fixture-fitted ingest floor says nothing about production (D-03), and only its tool writes that file. Prechunked: 5 of 134 answerable refused, none of them answered by legacy.

## Fix

- `src/lib/rag/legacy/enhanced-retrieval.ts`: `legacyPoolRule` returns the searches `legacySearch` runs (per-strategy threshold and match count through `searchThresholdsFor`/`scaleThreshold`, the fallback pass only above 0.35, `fallbackBelow` 3 or 1, `rpcThreshold` through `evalRpcThreshold`). `legacyFirstPass`, `legacyNeedsFallback` and `legacyMergeFallback` are the strategy post-processing and fallback merge that `legacySearch` already did, moved out unchanged; `legacySearch` now calls them around its two RPCs. `legacyPoolFromRows` runs the same functions over in-memory rows (strictly above the threshold, best first, capped, as the SQL does). `legacyVoicePoolRule` holds the legacy voice search constants; `runVoicePipeline` reads them from it.
- `src/lib/rag/v2/stages/rank.ts`: under `legacy_rule`, `applyRefusal` takes the fused hits that the original query's dense leg returned, replays the rule (voice: the voice rule; others: `legacyPoolRule` with the request's `maxResults`/`RAG_FINAL_RESULT_COUNT`, `fallbackToLowerThreshold`, the embedding profile's thresholds and the eval override when an eval embedding profile is named, as the legacy pipeline passes it), and calls `legacyRuleFloor` with `LEGACY_KEEP_FLOORS` on the pool members only. Evidence text is unchanged from 04.1-01. Stage detail: `<basis> floor=legacy_rule pool=<n>`.
- `src/lib/rag/v2/pipeline.ts`: passes the query stage's `queryContext` to `runRankStages` (one line; the stage order in `query.ts` is untouched).
- `src/lib/rag/context/relevance.ts` exports `LEGACY_KEEP_FLOORS` (literal kept byte for byte for the sentinel); `floor.ts` derives `LEGACY_TEXT_FLOOR`/`LEGACY_IMAGE_FLOOR` from it and adds `emptyLegacyPool`.

Untouched: `decideRefusal`, `cellKey`, `ThresholdCell`, `loadThresholds` (`git diff --stat 8187952^..0fba388 -- src/lib/rag/refusal/gate.ts src/lib/rag/refusal/thresholds.ts src/lib/rag/v2/stages/query.ts` prints nothing). No RAG-mode key. No new RPC, switch value, constant to tune or calibration file. Tenant scope: the pool rule filters rows already returned inside the request's `TenantScope`.

## Deviations

Own RED commit.
2. **Files outside `files_modified`**: `src/lib/rag/v2/pipeline.ts` (passes `queryContext`, one line; plan 04.1.1-05 also edits this file, whichever lands second rebases), `src/lib/rag/pipeline.ts` (voice constants), `src/lib/rag/context/relevance.ts` (export), `tests/rag/characterize-defaults.test.ts` and the three `*-v2-default.json` snapshots.
3. **D-01 snapshots changed**: the plan's Task 2 verify lists `git diff --exit-code tests/fixtures/characterization`. The legacy snapshots are unchanged; the `*-v2-default.json` snapshots encode `legacy_rule` and must move with this fix (D-17 recorded them "once" for the D-01 set).
4. **Pool membership is the dense-leg rank, not "dense similarity present"**: the hybrid search returns a cosine similarity for lexical-only rows too (measured: 21 prechunked and 43 ingest lexical-only candidates with a non-null similarity).
5. **Known approximation**: the pool replay ranks the dense leg by similarity and applies the legacy strategy post-processing (temporal filters, final-score sort, diversity) through the shared functions, but the dense leg itself is capped at the v2 candidate pool size; a legacy pool larger than that cap cannot be fully replayed (the defaults are 25 legacy results against a larger v2 pool).
