## Findings for the product owner

1. **Refusal under v2 is the blocker.** With `legacy_rule` the v2 runs answer nearly every no-answer item in both modes; the `similarity` floor refuses more no-answer items in prechunked mode but in ingest mode refuses most answerable items. Neither meets the baseline band. Fixture cells (`v2-default` vs `-no-cells`) change nothing on the keyless path.
2. **The CI negative controls are not effective on v2.** `degrade: drop_top_candidate` is applied only in the legacy branch of `runRetrieval` (`src/lib/rag/pipeline.ts`), and the v2 eval path ignores `max_results`. Under the D-01 values both controls score like a plain run and pass the gate. After any future flip, CI's negative controls would stop testing anything; this needs a fix in the v2 eval path before this gate is re-run.
3. **Ingest `category:selective_filter` returns no rows under v2.** Those items filter on fixed fixture document ids; v2 finds nothing for them in ingest mode (legacy finds some). Not investigated here.
4. **v2 ingest runs are not deterministic.** Three v2-default ingest runs differ on `category:typo` MRR (the scratch baseline needed `--allow-spread`); prechunked v2 runs were identical.
