# Phase 4.1 Plan 11: Docs for the shipped (unflipped) retrieval defaults

**AGENTS.md and the deployment guide now say what ships: legacy by default, v2 only with an explicit `RAG_PIPELINE=v2`, which answers `languages_not_configured` until the supported languages are chosen and `backend_error` while the Phase 4 migrations are missing; `RAG_PIPELINE=legacy` (or removing the variable) switches back, and CI's legacy tiers prove that switch is exact.**

## Accomplishments

- AGENTS.md §6 "Hybrid retrieval (Phase 4)": one new bullet after the `RAG_PIPELINE=legacy (default)` line (04.1 outcome with the link to `eval/decisions/04.1-retrieval-defaults.md`, LANG-01 for explicit v2, the chat route reporting it as the knowledge-base outage, the switch back and the CI legacy tiers); the sub-switch list gains `auto` (Cohere when `COHERE_API_KEY` is set, which sends query and candidate text to Cohere, else `local_bm25`; Voyage only when named) and `RAG_REFUSAL_FLOOR=similarity` (`legacy_rule`).
- AGENTS.md §14: the v2 strict-refusal line gains one sentence: with `RAG_REFUSAL_FLOOR=legacy_rule` the legacy relevance rule applies while no calibrated rerank threshold applies to the request; fixture cells never apply outside eval. No single global threshold is named (D-26), checked by the test.
- README_DEPLOYMENT_MODES.md, under Migration Guide: "Opting in to hybrid retrieval (v2)": choose languages (picker or the two variables), apply the Phase 4 migrations or the folded setup file, `npm run rag:relex`, set `RAG_PIPELINE=v2`; explicit v2 fails loudly; switch back.
- The error code, the variable names and the `languages_not_configured` literal are copied from the source (`src/lib/rag/lang/resolve.ts` `LANGUAGES_NOT_CONFIGURED`, `src/lib/env.ts`). No log line is quoted: under the shipped default the Phase 3.2 startup line `[RAG Languages] not configured — serving legacy` is never logged (it fires only when an unset variable's shipped default is the new pipeline), so naming it as something an operator sees would be wrong.
