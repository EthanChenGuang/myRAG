# Phase 4.1: Hybrid Retrieval and Rerank On by Default - Research

**Researched:** 2026-11-24 (worktree `planning/recall-layer`, base e90d9cd)
**Domain:** release defaults for the v2 retrieval pipeline; refusal calibration; eval gating
**Confidence:** HIGH for codebase findings (read at the cited lines), MEDIUM for external practice, LOW for how the fixture numbers will come out (not run here: the machine is loaded and the gate is the phase's own work)

## Summary

"On by default" is mostly a config flip, but three code gaps make a naive flip worse than today:

1. **The v2 fallback floor over-refuses.** When the rerank gate is `not_applied`, v2 refuses unless the top dense similarity beats the profile floor (legacy 0.65). Legacy has the same 0.65 but also keeps any candidate whose document name or content contains a query word. v2 has no such rescue, so on the fixture (similarities about 0.3) it refuses 112 of 114 items (recall 0.013). In production the gate is also `not_applied` for every request until live cells exist, because fixture cells apply only in the eval profile; so production v2 would refuse whenever OpenAI 3-small similarity is at or below 0.65, which is common for relevant passages. This is the main risk and the reason for `RAG_REFUSAL_FLOOR=legacy_rule`.
2. **A hosted reranker without a key degrades every request.** `RAG_RERANKER=cohere` with no key resolves to `skipped`/`missing_key` and marks the run degraded. A fresh install has no key. Hence `auto`.
3. **Hosted deployments that never set `RAG_PIPELINE` flip without the Phase 4 migration.** `hybrid_search_chunks` missing yields `backend_error`, which strict mode reports as "knowledge base temporarily unavailable". Hence the implicit-default fallback.

**Primary recommendation:** add the three missing pieces behind switches whose defaults equal today, run a pre-registered gate (G1 to G8, CONTEXT D-12) against the baselines in force on both fixture modes plus a capped live reranker check, and flip all D-01 values in one plan only if it passes. Keep two legacy smoke tiers in CI with all-zero paired differences so `RAG_PIPELINE=legacy` is provably today's behaviour.

## Codebase Findings

### F-1 The v2 floor and why it refuses (HIGH)
- `src/lib/rag/refusal/floor.ts:3` `LEGACY_TEXT_FLOOR = 0.65`; `similarityFloor` (line 40) answers only if `bestText > floors.text` or an image candidate beats 0.25; otherwise `refuse` / `below_similarity_floor`. Lexical-only hits (`similarity === null`) are skipped; if no candidate has a dense score the floor is `not_applied`.
- `src/lib/rag/v2/stages/rank.ts:80-115` `applyRefusal`: the threshold gate decides when it is applied, otherwise the floor over every fused hit, with floors from the active embedding profile's `scoreCalibration` (`src/lib/rag/embeddings/active-profile.ts:58` `context_threshold: 0.65`).
- Legacy equivalent: `src/lib/rag/context/assemble.ts:99-107`. A chunk is kept if `!applyRelevanceFilter || similarity > 0.65 || isRelevantByName || (hasImage && similarity > 0.25)`, where `isRelevantByName` is "some query word longer than 3 characters, stripped to `[a-z0-9]`, is in the filename or in `documents.content`". `documents.content` is the whole document (`src/lib/rag/context/fetch-rows.ts:31` selects `content`). Legacy also limits candidates through its search threshold and `fallbackToLowerThreshold` (`src/lib/rag/pipeline.ts:556-566`).
- v2 assembly runs with `applyRelevanceFilter: false` (`src/lib/rag/v2/stages/context.ts:145`), so the floor is the only v2 relevance check.
- v2 hits carry `document.contentPreview` = `left(d.content, 200)` (`supabase/migrations/0407_hybrid_search_chunks.sql:135`, `src/lib/rag/backend/pgvector.ts:79`), not the whole content. A faithful legacy check over whole documents would need an extra `documents` fetch per request; the plan uses filename, preview and the chunk text of all pool candidates instead (no round trip) and lets the gate measure it.
- Legacy quirk to keep in mind (not changed here): the term rule filters by length before stripping non-`[a-z0-9]` characters, so a Chinese or other non-Latin word of more than 3 characters becomes the empty string, and `includes('')` is always true. Legacy therefore keeps every candidate for most Chinese queries on this rule. `legacy_rule` reuses the predicate unchanged, so v2 inherits the same behaviour; fixing it would change legacy output and belongs to a later phase (candidate for 4.1.1 or 5.1.1, with its own eval).

### F-2 The refusal gate and the eval-only fixture cells (HIGH)
- `src/lib/rag/refusal/gate.ts:61-133` `decideRefusal`: `switch_off`, `reranker_disabled`, `reranker_unavailable`, `relative_scores` (local_bm25), `cell_uncalibrated`, `cell_stale`, then line 100 `cell.source === 'fixture' && profile !== 'eval'` gives `cell_fixture_only`.
- Consequence: in production the gate never refuses until live cells exist (04-43). With `local_bm25` it never applies at all (`relative_scores`). The floor is what production users will see; the eval with fixture cells over-states production refusal quality. The gate therefore runs a second configuration with `RAG_REFUSAL_THRESHOLD=false` (`v2-default-no-cells`), which is exactly production-equivalent today.
- `eval/config/refusal-thresholds.json` has `cells: []` at base; plan 04-39 writes fixture cells for `fake-quality-v1` only.

### F-3 Reranker selection and the missing-key path (HIGH)
- `src/lib/rag/config.ts:211-217` `parseReranker`: `none | cohere | voyage | local_bm25`, unknown values warn and give `none`.
- `src/lib/rag/rerank/select.ts`: `defaultFactory` returns `null` for Cohere or Voyage without a key; `runRerankStage` (`rank.ts:166-170`) records `skipped` / `missing_key` and the run is degraded (04-23 summary). `warnMissingKey` logs once per variable.
- `resolveModel`: Cohere `rerank-v5.0-pro` (quality) / `rerank-v5.0-fast`; Voyage `rerank-3` or per-language map / `rerank-3-lite`; local `bm25-v2`.
- `describeReranker` feeds the config hash; it must resolve `auto` to the concrete provider.
- `local_bm25` (`src/lib/rag/rerank/local-bm25.ts`) normalizes BM25 by the pool maximum and replaces the fused order; with the `none` translator, documents in another language score 0. That is why the no-key fallback is chosen by eval (CONTEXT D-06).

### F-4 Defaults live in more places than the five-location rule names (HIGH)
- `src/lib/env.ts:173-185` fallbacks (`RAG_PIPELINE || 'legacy'`, `RAG_LEXICAL_SEARCH || 'false'`, `RAG_RERANKER || 'none'`, `RAG_REFUSAL_THRESHOLD || 'false'`).
- `src/lib/rag/config.ts:186-190, 428-436` parser defaults (`'' -> legacy`, `parseBooleanSwitch(..., false, ...)`, `'' -> none`). These must flip with env.ts or an empty value would still mean legacy.
- `scripts/init-env.js:342-362` template; `scripts/config-server.js:554, 1368, 1747` three templates (`|| 'none'` style fallbacks); `scripts/config-ui/index.html:6475` `RAG_RERANKER` select; `scripts/rag/env-manifest.json:634` (`managed`); `eval/config/rag-eval-env.json` is derived from init-env by `eval/harness/eval-env.mts` and checked with `--check` (CI drift check).
- Phase 7 plan 07-18 adds a manifest `default` field and 07-30 checks shipped defaults against a decision record; they come later and must take this phase's values as the incumbent (CONTEXT D-20).

### F-5 Who actually flips (HIGH)
- `scripts/init-env.js:595-600` writes `.env.local` only when missing, and the template has `RAG_PIPELINE=legacy` and the explicit Phase 4 switch values. Existing local installs keep legacy after upgrading code. `scripts/config-server.js` rewrites `.env.local` from current values with fallbacks only for missing keys.
- Fresh installs and hosted environments without these variables (Vercel reads `process.env`, `src/lib/env.ts` fallbacks apply) flip. Those are the deployments that may lack migrations 0401 to 0412, hence D-07.

### F-7 Eval gate mechanics (HIGH)
- `eval/src/rag_eval/gate.py:34-56` refuses a run whose golden, corpus, embedder, tier, mode, gate population or request options differ from the baseline; it does **not** compare `run_config_hash`, so a v2 run can be gated against a legacy baseline (this is how Phase 4 D-28(b) compares).
- Band `max(k * spread, floor)` (`gate.py:79`), `eval/config/noise.json`: k 3, floor 0.02, gated prefixes `overall`, `language:`, `category:cross_lingual`, `pair:`; metrics Recall@5, Recall@10, MRR, correct and false refusal.
- Baselines today: prechunked overall Recall@10 0.5195, MRR 0.5260, false refusal 0.3766 (n 77), correct refusal 0.3333 (n 9); ingest overall Recall@10 0.6395, MRR 0.5930, false refusal 0.2442 (n 86), correct refusal 0.5000 (n 12). Spread 0 (deterministic fixture), so the band is the 0.02 floor. Ingest Recall@10 floor 0.6395 - 0.02 = 0.6195, the figure in the phase brief. Plan 04-38 re-records these before this phase; the gate reads the files in force.
- `eval/harness/run-smoke.mts` accepts `--run-config`, `--baseline`, `--fixture-mode ingest`, `--no-gate`; CI (`.github/workflows/pr-smoke.yml:178-225`) runs both smoke tiers plus the negative checks (`--degrade drop_top_candidate`, `--max-results 1`) which must keep failing.
- Run configs `eval/config/runs/v2-all-off.json` and `v2-recommended.json` exist (04-21); the run-config env overlay is validated by `eval/harness/run-config.mts` (`RAG_PIPELINE` values checked, line 70).

### F-8 Latency budgets (HIGH)
- `eval/config/latency-budgets.json`: chat and embed total p50 1000 / p95 2000 ms, rerank 600, search 400, embed 200; voice total p50 400 / p95 800, rerank 250, search 300. Report-only until live measurements ratify them (AGENTS.md §6).
- `src/lib/rag/v2/profiles.ts`: voice deadline 800 ms, rerank reserve 50 ms, rerank floor 80 ms, token budget 2000, no compression. `rank.ts:173-182` skips rerank with `budget_exhausted` when the remainder is below the floor.

### F-9 Characterization tests run on the pinned env (HIGH)
- `tests/helpers/route-fixture.ts:93-99` deletes every `RAG_*` variable and applies `loadPinnedEvalEnv()` (the eval pin derived from init-env). After the flip, every route characterization would silently run v2 and every snapshot would change. The plan adds an `env` option and pins `RAG_PIPELINE=legacy` in the existing describes so their snapshots stay byte-identical, then adds separate v2-default snapshots.
- Snapshots are written only with `UPDATE_CHARACTERIZATION=1` (`route-fixture.ts:41-50`).

### F-10 Live rerank calls from the harness (MEDIUM)
- `eval/harness/fake-edge.mts:866-877` `fixtureProcessEnv` points `COHERE_BASE_URL` and `VOYAGE_BASE_URL` at the fake edge with placeholder keys; the edge accepts only `fake-*` models (line 283-304). A live run must override both base URLs and keys (`proxy-injected`) through the run-config env overlay. Plan 04.1-08 checks first that the overlay is applied after `fixtureProcessEnv`; if not, it adds an explicit `--live-rerank` harness flag as a recorded deviation.
- The calibration tool supports `--run-config` and writes thresholds only with `--write-thresholds` (04-30 summary).

### F-12 The fixture env carries a placeholder Cohere key (HIGH)
- `fixtureProcessEnv` sets `COHERE_API_KEY` to a placeholder and points Cohere at the fake edge, which rejects non-`fake-*` models. Under `RAG_RERANKER=auto` that key would make every fixture and route run choose Cohere with `rerank-v5.0-pro`, get a 400 and run degraded. Plans 04.1-05 and 04.1-06 therefore clear the placeholder whenever the effective reranker is `auto` and the test or run config did not ask for it (`COHERE_API_KEY: "fixture"` keeps it). Runs with any other reranker value, including `v2-recommended`, are unchanged.

### F-11 No migration is needed (HIGH)
- Everything above is TypeScript, config and eval. No SQL function, table or grant changes, so no migration number is taken (0357, 0413 and 0420 to 0423 stay with their owners).

## External Practice (MEDIUM)

- Hybrid lexical + dense with RRF is the default retrieval recommendation of most vector-database vendors and of the BEIR / MTEB literature because it is robust across query types (exact identifiers, rare terms) without tuning (Cormack, Clarke, Buettcher, "Reciprocal Rank Fusion outperforms Condorcet and individual rank learning methods", SIGIR 2009; Weaviate, Qdrant and Elastic hybrid-search documentation). Turning it on by default matches common practice.
- Cross-encoder rerankers give the largest single quality gain in most RAG evaluations but add a network call; vendors document p95 in the low hundreds of milliseconds for tens of documents (Cohere Rerank and Voyage Rerank documentation). Treat these as claims to verify (G7).
- Dark-launch then flip, with an instant kill switch and a guardrail metric set fixed in advance, is the standard pattern for changing defaults (for example Kohavi, Tang, Xu, *Trustworthy Online Controlled Experiments*, 2020, on guardrail metrics and pre-registration). Pre-registering the selection rules (CONTEXT D-04, D-06, D-12) avoids choosing the criterion after seeing the numbers.
- Refusal thresholds calibrated on one score distribution do not transfer to another model or corpus; recalibrate per reranker model and language (Phase 4 D-17 already encodes this). Fixture-calibrated cells must not run in production (gate.ts:100), which is why the no-cells configuration is gated.
