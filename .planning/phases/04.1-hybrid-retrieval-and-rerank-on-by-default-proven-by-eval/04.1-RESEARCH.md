## Summary

"On by default" is mostly a config flip, but three code gaps make a naive flip worse than today:

1. **The v2 fallback floor over-refuses.** When the rerank gate is `not_applied`, v2 refuses unless the top dense similarity beats the profile floor (legacy 0.65). Legacy has the same 0.65 but also keeps any candidate whose document name or content contains a query word. v2 has no such rescue, so with no fixture-fitted floor it refuses almost all fixture items (historical, 04-21 and 04-23 summaries: 112 of the 114 items of that day, recall 0.013; plan 04.1-01 Task 1 measures the current count and records it in its SUMMARY). In production the gate is also `not_applied` for every request until live cells exist, because fixture cells apply only in the eval profile; so production v2 would refuse whenever OpenAI 3-small similarity is at or below 0.65, which is common for relevant passages. This is the main risk and the reason for `RAG_REFUSAL_FLOOR=legacy_rule`.
2. **A hosted reranker without a key degrades every request.** `RAG_RERANKER=cohere` with no key resolves to `skipped`/`missing_key` and marks the run degraded. A fresh install has no key. Hence `auto`.
3. **Hosted deployments that never set `RAG_PIPELINE` flip without the Phase 4 migration.** `hybrid_search_chunks` missing yields `backend_error`, which strict mode reports as "knowledge base temporarily unavailable". Hence the implicit-default fallback. The unified ingest has the same gap on its dual write (F-14).
4. **Deployments that have not chosen their supported languages (added 2026-11-25).** LANG-01 and Phase 3.2 D-02 decide that an implicit v2 default serves legacy until the languages are chosen, and that only an explicit `RAG_PIPELINE=v2` fails with `languages_not_configured`. Hence one resolver for both fallbacks (F-13, CONTEXT D-24) and templates that leave the pipeline implicit (F-15, CONTEXT D-25).

**Primary recommendation:** add the three missing pieces behind switches whose defaults equal today, run a pre-registered gate (G1 to G8, CONTEXT D-12) against the baselines in force on both fixture modes plus a capped live reranker check, and flip all D-01 values in one plan only if it passes. Keep two legacy smoke tiers in CI with all-zero paired differences so `RAG_PIPELINE=legacy` is provably today's behaviour.

## Codebase Findings

### F-1 The v2 floor and why it refuses (HIGH)
- `src/lib/rag/refusal/floor.ts`: `LEGACY_TEXT_FLOOR = 0.65`; `similarityFloor` answers only if `bestText > floors.text` or an image candidate beats 0.25; otherwise `refuse` / `below_similarity_floor`. Lexical-only hits (`similarity === null`) are skipped; if no candidate has a dense score the floor is `not_applied`.
- `applyRefusal` in `src/lib/rag/v2/stages/rank.ts`: the threshold gate decides when it is applied, otherwise the floor over every fused hit, with floors from `evalFloorCalibration(profile)` (eval profile only), then the active embedding profile's `scoreCalibration`, then `LEGACY_PROFILE.scoreCalibration` (`context_threshold: 0.65`, `src/lib/rag/embeddings/active-profile.ts`). `applyRefusal` takes no query argument today; the legacy-rule floor needs the request query threaded in from `runRankStages`.
- Legacy equivalent: `filterCandidates` in `src/lib/rag/context/assemble.ts` (query terms from `queryTermsOf`). A chunk is kept if `!applyRelevanceFilter || similarity > 0.65 || isRelevantByName || (hasImage && similarity > 0.25)`, where `isRelevantByName` is "some query word longer than 3 characters, stripped to `[a-z0-9]`, is in the filename or in `documents.content`". `documents.content` is the whole document (`fetchAssemblyRows` in `src/lib/rag/context/fetch-rows.ts` selects `content`). Legacy also limits candidates through its search threshold and `fallbackToLowerThreshold` (`runPipeline` in `src/lib/rag/pipeline.ts`).
- v2 assembly runs with `applyRelevanceFilter: false` (`src/lib/rag/v2/stages/context.ts`), so the floor is the only v2 relevance check.
- Added 2026-11-25: `eval/config/fixture-score-calibration.json` holds a fixture-fitted `context_threshold` for the one fixture mode it names. `eval/harness/run-eval.mts` installs it through `setEvalScoreCalibration`, and `evalFloorCalibration` returns it for the eval profile only. In the other fixture mode and in every non-eval profile the legacy 0.65 floor applies, so the over-refusal still describes production. Plan 04.1-01 Task 1 measures both fixture modes and records which floor applied.
- v2 hits carry `document.contentPreview` = `left(d.content, 200)` (the `left(d.content, 200)` column of `public.hybrid_search_chunks`, newest definition under `supabase/migrations/`; mapped to `contentPreview` in `src/lib/rag/backend/pgvector.ts`), not the whole content. A faithful legacy check over whole documents would need an extra `documents` fetch per request; the plan uses filename, preview and the chunk text of all pool candidates instead (no round trip) and lets the gate measure it.
- Legacy quirk to keep in mind (not changed here): the term rule filters by length before stripping non-`[a-z0-9]` characters, so a Chinese or other non-Latin word of more than 3 characters becomes the empty string, and `includes('')` is always true. Legacy therefore keeps every candidate for most Chinese queries on this rule. `legacy_rule` reuses the predicate unchanged, so v2 inherits the same behaviour; fixing it would change legacy output and belongs to a later phase (candidate for 4.1.1 or 5.1.1, with its own eval).

### F-2 The refusal gate and the eval-only fixture cells (HIGH)
- `decideRefusal` in `src/lib/rag/refusal/gate.ts`: `switch_off`, `reranker_disabled`, `reranker_unavailable`, `relative_scores` (local_bm25), `cell_uncalibrated`, `cell_stale`, then `cell.source === 'fixture' && profile !== 'eval'` gives `cell_fixture_only`. A cell is keyed by provider, model, query language and pairing (`cellKey`); there is no RAG-mode key, and this phase adds none (CONTEXT D-26; RNK-07 adds it in Phase 4.2).
- Consequence: in production the gate never refuses until live cells exist (04-43). With `local_bm25` it never applies at all (`relative_scores`). The floor is what production users will see; the eval with fixture cells over-states production refusal quality. The gate therefore runs a second configuration with `RAG_REFUSAL_THRESHOLD=false` (`v2-default-no-cells`), which is exactly production-equivalent today.
- `eval/config/refusal-thresholds.json` holds the fixture cells plan 04-39 produced for `fake-quality-v1`. `python -m rag_eval.calibrate refusal` is the only writer of that file; no live cell exists until 04-43.

### F-3 Reranker selection and the missing-key path (HIGH)
- `parseReranker` in `src/lib/rag/config.ts`: `none | cohere | voyage | local_bm25`, unknown values warn and give `none`.
- `src/lib/rag/rerank/select.ts`: `defaultFactory` returns `null` for Cohere or Voyage without a key; `runRerankStage` (`src/lib/rag/v2/stages/rank.ts`) records `skipped` / `missing_key` and the run is degraded (04-23 summary). `warnMissingKey` logs once per variable.
- `resolveModel`: Cohere `rerank-v5.0-pro` (quality) / `rerank-v5.0-fast`; Voyage `rerank-3` or per-language map / `rerank-3-lite`; local `bm25-v2`.
- `describeReranker` feeds the config hash; it must resolve `auto` to the concrete provider.
- `local_bm25` (`src/lib/rag/rerank/local-bm25.ts`) normalizes BM25 by the pool maximum and replaces the fused order; with the `none` translator, documents in another language score 0. That is why the no-key fallback is chosen by eval (CONTEXT D-06).

### F-7 Eval gate mechanics (HIGH)
- `_mismatches` in `eval/src/rag_eval/gate.py` refuses a run whose golden, corpus, embedder, tier, mode, gate population or request options differ from the baseline; it does **not** compare `run_config_hash`, so a v2 run can be gated against a legacy baseline (this is how Phase 4 D-28(b) compares).
- Band `max(k * spread, floor)` (`evaluate_gate` in `gate.py`), `eval/config/noise.json` (k 3 and floor 0.02 when read on 2026-11-25; read again when the gate runs), gated prefixes `overall`, `language:`, `category:cross_lingual`, `pair:`; metrics Recall@5, Recall@10, MRR, correct and false refusal.

## External Practice (MEDIUM)

- Hybrid lexical + dense with RRF is the default retrieval recommendation of most vector-database vendors and of the BEIR / MTEB literature because it is robust across query types (exact identifiers, rare terms) without tuning (Cormack, Clarke, Buettcher, "Reciprocal Rank Fusion outperforms Condorcet and individual rank learning methods", SIGIR 2009; Weaviate, Qdrant and Elastic hybrid-search documentation). Turning it on by default matches common practice.
- Cross-encoder rerankers give the largest single quality gain in most RAG evaluations but add a network call; vendors document p95 in the low hundreds of milliseconds for tens of documents (Cohere Rerank and Voyage Rerank documentation). Treat these as claims to verify (G7).
- Dark-launch then flip, with an instant kill switch and a guardrail metric set fixed in advance, is the standard pattern for changing defaults (for example Kohavi, Tang, Xu, *Trustworthy Online Controlled Experiments*, 2020, on guardrail metrics and pre-registration). Pre-registering the selection rules (CONTEXT D-04, D-06, D-12) avoids choosing the criterion after seeing the numbers.
- Refusal thresholds calibrated on one score distribution do not transfer to another model or corpus; recalibrate per reranker model and language (Phase 4 D-17 already encodes this). Fixture-calibrated cells must not run in production (`decideRefusal`, the `cell_fixture_only` branch), which is why the no-cells configuration is gated.
