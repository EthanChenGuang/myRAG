# Phase 4.1 Plan 04: Safe implicit v2 default Summary

**One resolver, `resolveEffectivePipeline()`, now decides which pipeline serves each request. An explicit `RAG_PIPELINE` is returned unchanged. A defaulted v2 serves legacy when the languages are not configured, or after a Phase 4 function turned out to be missing. That covers the retrieval dispatch, `isV2Pipeline()`, `verifyV2Startup` and the ingest dual write. `DEFAULT_PIPELINE` is still `legacy`, so no request path changes on trunk.**

## Accomplishments

- `config.ts`: `DEFAULT_PIPELINE` stays `'legacy'`. `shippedDefaultPipeline()` and the test-only `setDefaultPipelineForTests()` change the default used by `parsePipeline` and by Phase 3.2's `languageGate`. `RagConfig.pipelineSource` is `'explicit'` when `RAG_PIPELINE` is non-empty in the process environment and `'default'` otherwise; a value of spaces counts as unset. Both the source and the shipped default are part of the memo key.
- `deps.ts`: `readRagEnvInput` fills `pipelineSourceHint` from `rawPipelineEnv()` (tests can override it). `RagDeps.languagesConfigured` defaults to `() => null`.
- `v2/readiness.ts`: the per-process availability flag; `markV2Unavailable(rpc)` logs one `[RAG Config] a Phase 4 database function is missing; running the legacy pipeline until the Phase 4 migrations under supabase/migrations are applied, or set RAG_PIPELINE=legacy` with `{ function }` only. The resolver logs nothing. It checks the language state before availability.
- Retrieval: `runRetrieval` delegates to `dispatchRetrieval`. Media and general-overview requests go straight to legacy, as before. When the resolver says legacy with a fallback reason, a `pipeline_fallback` record is written and the legacy (or voice) pipeline runs. An explicit v2 runs as before. A defaulted v2 runs on a buffered collector. If `runV2Pipeline` returns `v2_unavailable`, those records are dropped, `pipeline_fallback: v2_unavailable` is recorded, and the same input object (same `TenantScope`) re-runs on legacy. Otherwise the buffered records are committed to the caller's trace.
- `v2/pipeline.ts`: a `RetrievalBackendError` that `isMissingPhase4Function` accepts, under a default source, calls `markV2Unavailable` and returns reason `v2_unavailable`. Explicit v2 and every other code still return `backend_error`.
- `isV2Pipeline()` and `verifyV2Startup` read the resolver, so a process serving legacy no longer parses `retrievalFilters` in chat or embed, and startup returns `not_checked` without v2 warnings.
- Ingest: `runEmbed` and `runDeferredEmbed` dual write only when the resolver serves v2. Under a default source, a missing `rag_list_chunking_profiles` (PGRST202 or 42883) marks v2 unavailable and returns without profile children. The legacy chunks, their embeddings and the gap bookkeeping are untouched. Explicit v2 and other errors still fail with `chunking_profiles_unavailable`.

## Deviations from Plan

1. **Phase 3.2 landed first (D-24 "whichever phase lands second").** `config.ts` already had `DEFAULT_PIPELINE` and the Phase 3.2 `languageGate` (`pipelineBlocked` for an explicit v2, a defaulted v2 served as legacy). I kept that gate and made it read the shipped default through `shippedDefaultPipeline()` and the source-aware raw value. The resolver reports `languages_not_configured` both when that gate served legacy (`config.pipelineServedLegacy`) and when the seam returns `false`. The seam's default is still `null`, as the plan says. Plan 04.1-13 should decide whether the 3.2 reader moves onto the seam and the gate's served-legacy branch goes away. The behaviour is the same either way.
2. **RagEnvInput field instead of a config read of deps.** `config.ts` cannot import `deps.ts`, because deps already imports config. The source therefore enters as `RagEnvInput.pipelineSourceHint`, which `readRagEnvInput` fills from `rawPipelineEnv()`. Callers that pass an env object without it, such as the existing tests, get the source from `RAG_PIPELINE` itself.
3. **Buffered trace collector (not in the plan text).** The v2 attempt records an `error` search stage. On a shared collector, the legacy rerun's `deriveStatus` would read that record and report `error`. A defaulted v2 attempt therefore records into a buffer that is committed only when v2 serves the request. Explicit v2 still records directly into the caller's collector.
4. **Literal grep gate.** The plan's check forbids `pipeline === 'v2'` and `pipeline !== 'v2'` in pipeline.ts, switch.ts, startup.ts and embed-write.ts. Those files now compare the resolver's result with `'legacy'` (`!== 'legacy'` / `=== 'legacy'`).
