<objective>
Connect the supported-languages setting of Phase 3.2 to the implicit-default resolver, and prove what a deployment gets while its languages are not chosen.

Purpose: CONTEXT D-24 and LANG-01 (Phase 3.2 CONTEXT D-02, amended, owner decision 2026-11-25). After the flip an install that sets nothing would run v2; LANG-01 says it keeps serving legacy until the supported languages are chosen, and only an explicit `RAG_PIPELINE=v2` fails with `languages_not_configured`. Plan 04.1-04 built the resolver with a language branch behind a deps seam that reports "no reader". This plan plugs the Phase 3.2 reader into that seam, makes sure only one function decides "explicit or default", and proves three cases with the real Phase 3.2 code: languages unset and pipeline unset gives legacy and one startup log; languages unset and an explicit v2 gives `languages_not_configured`; languages set and pipeline unset gives v2.
Output: the seam's default, one decision point, a unit-level test file, and languages-unset variants of the route characterization suites.

Depends on 04.1-04 (resolver and seam) and 04.1-05 (route fixture env that can remove a variable; the suites this plan extends). It also needs the Phase 3.2 LANG-01 implementation on trunk. Phase 3.2 has no plan ids yet, so that edge is the task precondition below, not a `depends_on` entry: when it is not met the plan stops and reports. Phase 3.2 owns the reader, the startup log text, the Config UI banner and the error code; this plan consumes them and rewords none.

This plan runs before the flip. The default pipeline is still `legacy` on trunk, so the tests reach the defaulted-v2 branch through the test-only setter of `DEFAULT_PIPELINE`; plan 04.1-09 reruns them with the shipped default.

Code is named by symbol. Re-read the newest definition of each symbol at execution time, because other phases are editing these files on trunk (CONTEXT D-27).

Commit rule for every task: plain `git commit`; the message ends with the attribution lines (Co-Authored-By and the session link) that the executor's own session supplies; never copy them from a plan. No model identifiers in code comments or commit messages; no secrets.
</objective>
