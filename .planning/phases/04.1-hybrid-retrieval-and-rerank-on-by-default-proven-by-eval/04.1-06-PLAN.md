<objective>
Pre-register the gate for the new defaults and build the tool that applies it.

Purpose: CONTEXT D-12, D-04, D-06, D-13 and research F-7. The pass criteria and the two selection rules are written as data before any number is seen, so the choice of floor and fallback cannot be fitted to the results. The tool reuses the existing noise-band gate for G1 and adds the wider checks (absolute recall floor, refusal rates per fixture mode, every category with n >= 8, latency against the budget file, legacy paired zero). No criterion carries a literal baseline number: the one absolute floor is derived by the tool from the baseline in force and recorded with that file's sha256 (CONTEXT D-12 amended), because the baselines and the golden set keep changing while other phases execute.
Output: eleven run configs with their overlay constraints, the gate module with its derive, check-criteria and evaluate commands and tests, and the criteria file.

Runs after 04-42; independent of the code plans (pure eval). Fixture runs happen in plan 04.1-07. Of the 17 files this plan touches, eleven are run-config JSON files of a few lines each. Code is named by symbol; re-read the newest definition at execution time (CONTEXT D-27).
