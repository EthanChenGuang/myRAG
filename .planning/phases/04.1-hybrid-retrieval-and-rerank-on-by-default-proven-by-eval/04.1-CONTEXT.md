# Phase 4.1: Hybrid Retrieval and Rerank On by Default, Proven by Eval - Context

**Gathered:** 2026-11-24
**Status:** Ready for planning
**Source:** Product-owner decision (Guang, 2026-11-24): hybrid retrieval and rerank ship ON by default. This phase makes that safe and proves it on the eval before the defaults change.

## Phase Boundary

Phase 4 built the v2 pipeline (hybrid lexical + dense search over `hybrid_search_chunks`, RRF, dedupe, switchable rerankers, a calibrated refusal gate with a similarity-floor fallback), every part behind a switch that is off by default (Phase 4 D-23, D-28: "the shipped defaults stay off until the Phase 7 regression"). The product owner has moved the retrieval defaults earlier. This phase:

1. Closes the gaps that would make "v2 on by default" worse than today: the v2 fallback refusal floor (refuses about 112 of 114 fixture items, 04-21 and 04-23 summaries), a missing rerank key that would mark every request `degraded`, and hosted deployments whose database does not yet have the Phase 4 RPC.
2. Defines the gate (exact pass criteria against the baseline, both fixture modes, latency budgets) and runs it, including a small, capped run with the real Cohere and Voyage rerankers.
3. Flips the defaults in all config locations only if the gate passes, keeps `RAG_PIPELINE=legacy` as the single switch back to today's behaviour, and keeps the legacy path under CI with zero paired differences.

Not in this phase: external backends (Weaviate, Qdrant), embedding-profile defaults, the final reranker-model decision on the real locked test split (all Phase 7, ADM-02); live refusal-threshold calibration on the real golden set (Phase 4 plan 04-43); edge ordering, compression, parent-child, iterative scan and translation defaults (stay off); query rewriting (Phase 6).

## Implementation Decisions

### What "on by default" means
- **D-01:** The shipped defaults after this phase are: `RAG_PIPELINE=v2`, `RAG_LEXICAL_SEARCH=true`, `RAG_RERANKER=auto` (new value, D-05), `RAG_REFUSAL_THRESHOLD=true`, `RAG_REFUSAL_FLOOR=legacy_rule` (new variable, D-03). Every other Phase 4 switch keeps its Phase 4 default (`RAG_CONTEXT_EDGE_ORDER=false`, `RAG_CONTEXT_COMPRESSION=false`, `RAG_PARENT_CHILD=false`, `RAG_HNSW_ITERATIVE_SCAN=off`, `RAG_EXACT_SCAN_CUTOFF=0`, `RAG_LEXICAL_TRANSLATION=false`, `RAG_EXACT_ID_LOOKUP=false`). The tiers stay `quality` (chat, embed) and `fast` (voice).
  - `RAG_REFUSAL_THRESHOLD=true` is safe by construction: the gate applies only `calibrated` cells, and fixture cells apply only in the eval profile (`src/lib/rag/refusal/gate.ts:100`). Until live cells exist (04-43) production refusal is decided by the floor (D-03). Turning it on now means live cells take effect the moment they are calibrated, without another default change.
- **D-02:** The defaults change in one plan (04.1-09), after the gate passes (04.1-07). Every plan before it adds code behind switches or new values whose defaults equal today's behaviour, so trunk behaviour does not change until the flip.

### Refusal under v2 (the calibration problem)
- **D-03:** New switch `RAG_REFUSAL_FLOOR=similarity|legacy_rule`. It selects the fallback floor the `refusal` stage uses whenever the rerank threshold gate returns `not_applied` (Phase 4 D-30).
  - `similarity` is today's D-30 floor (top dense similarity above the profile's `context_threshold`, legacy 0.65, or an image above 0.25). Introduced as the default so v2 is unchanged until the flip.
  - `legacy_rule` applies the legacy relevance rule of `filterCandidates` (`src/lib/rag/context/assemble.ts:106`): the request is answered if at least one candidate passes `similarity > text floor`, or has an image with `similarity > image floor`, or matches the legacy query-term rule (a query word longer than 3 characters, folded to `[a-z0-9]`, found in the document filename or in the candidate's text). The predicate is extracted from `filterCandidates` into one shared function so legacy and v2 cannot drift, and legacy output stays byte-identical.
  - Evidence text: v2 hits carry only a 200-character `contentPreview` of the document (`hybrid_search_chunks`, `supabase/migrations/0407_hybrid_search_chunks.sql:135`), while legacy reads the whole `documents.content` (`src/lib/rag/context/fetch-rows.ts:31`). `legacy_rule` checks the filename, the preview and the chunk text of every pool candidate (no extra round trip). This is stricter than legacy per document; the gate measures whether it raises false refusal.
  - Why not calibrate a dense floor instead: the fixture embedder's similarities (~0.3) and OpenAI 3-small similarities differ, a floor fitted on fixtures says nothing about production, and there is no real golden set yet. `legacy_rule` reproduces the refusal semantics users have today; calibrated rerank cells (04-43, live) supersede it per cell.
  - Why not "any lexical-leg hit": the lexical tsquery is an OR of tokens (`public.rag_lexical_tsquery`, `supabase/migrations/0401_lexical_index.sql`), so near-miss no-answer questions almost always hit; correct refusal would collapse.
- **D-04:** The floor choice is made by the eval with a pre-registered rule (D-12): `legacy_rule` becomes the default only if it passes the gate; if both pass, the one with the higher overall correct-refusal rate wins, ties go to `legacy_rule`; if neither passes, the flip stops (D-13).

### Reranker default and the no-key path
- **D-05:** New `RAG_RERANKER` value `auto` (existing values unchanged):
  - `COHERE_API_KEY` set: Cohere (tier per entry point, D-10 of Phase 4: `rerank-v5.0-pro` chat and embed, `rerank-v5.0-fast` voice).
  - Otherwise: the no-key fallback, `local_bm25` or `none` (fused order), chosen by the eval (D-06). The fallback is recorded as stage detail `auto:<provider>`; it is never `degraded` and never logs the missing-key warning, because nothing is misconfigured.
  - `VOYAGE_API_KEY` alone does not select Voyage under `auto`: that key exists for the Voyage embedding profile, and using it for rerank is a new spend and a new data flow the operator did not ask for. Voyage stays available with `RAG_RERANKER=voyage`. (Product-owner question Q-2.)
  - Explicit `cohere` or `voyage` without a key keeps today's behaviour (`skipped`, `missing_key`, degraded, one warning): an operator who named a provider has a misconfiguration worth seeing.
  - The retrieval config hash (`describeReranker`, `src/lib/rag/rerank/select.ts`) records the resolved provider and model, never `auto`, so cache keys and traces stay comparable.
  - Per-profile hosted use is a code constant (`AUTO_HOSTED_PROFILES`, default chat, embed, eval, voice) so the decision record can take voice off hosted rerank if the live latency check fails (D-09) without a new variable.
- **D-06:** No-key fallback rule (pre-registered): `local_bm25` is chosen only if, on both fixture modes, it passes the gate and its overall Recall@10, overall MRR and `category:cross_lingual` Recall@10 are each at or above the `none` run's value minus the noise band; otherwise `none`. Reason: `local_bm25` replaces the fused order with pure BM25 over the pool (`src/lib/rag/rerank/local-bm25.ts`), and with the `none` translator cross-language candidates score 0 and sink (ties keep fused order), so it can hurt the cross-lingual slice.

### Upgrade safety
- **D-07:** Implicit versus explicit pipeline. When `RAG_PIPELINE` is unset or empty and the default is v2, the pipeline is `v2 (default)`; when it is set to `v2`, it is `v2 (explicit)`. If `hybrid_search_chunks` is missing in the database (PostgREST `PGRST202` or Postgres `42883` from the RPC), a `v2 (default)` process switches to legacy for the rest of its life, re-runs the failing request on legacy, and logs one `[RAG Config]` error naming the missing migrations. A `v2 (explicit)` process keeps today's behaviour (`backend_error`). Existing installs are mostly unaffected anyway: `scripts/init-env.js` never rewrites an existing `.env.local` (`checkAndCreateEnvFile`, line 597) and its template has written `RAG_PIPELINE=legacy` explicitly since Phase 2; the flip reaches fresh installs and hosted deployments that never set the variable (for example Vercel, where `src/lib/env.ts` fallbacks apply).
- **D-08:** Chunks without `lexical_text` (written before Phase 3) are still served by the dense leg; the docs tell upgraders to run the migrations and `npm run rag:relex`. No new SQL in this phase.

### Voice, embed and other entry points
- **D-09:** Voice keeps its Phase 4 settings (fast tier, 250 ms rerank timeout capped by the 800 ms deadline with a 50 ms reserve and an 80 ms floor, `src/lib/rag/v2/profiles.ts`) and the 04-28 v2 voice path. Gate: voice p95 under 800 ms with injected delays (04-28 test re-run under defaults), and the live Cohere `rerank-v5.0-fast` p95 for 75 chunks at or below 250 ms (`eval/config/latency-budgets.json`). If the live voice p95 exceeds 250 ms, the decision record removes voice from `AUTO_HOSTED_PROFILES` (voice then uses the no-key fallback); the deadline skip stays as the runtime guard either way.
- **D-10:** Behaviour to preserve (AGENTS.md §14) is covered by named characterization cases under the new defaults: strict mode with web search off answers verified `empty` with the localized "information not available" response; a knowledge-base failure stays "temporarily unavailable" or `degraded`; web search with Exa still works when strict retrieval is empty; `source_images` survive chat, embed and voice; `RAG_SYSTEM_PROMPT` keeps `{{context}}` and the context format (Phase 4 D-15); `general overview` requests keep running legacy (`src/lib/rag/pipeline.ts:497`).
- **D-11:** Multi-tenant: the 04-41 two-tenant matrix and the multi-tenant route tests run with `RAG_PIPELINE` unset (implicit default) in addition to explicit v2. No tenant input changes; `hybrid_search_chunks` stays service-role only.

### The gate
- **D-12:** Pass criteria, all on the fixture corpus, against the baselines in force when the gate runs (today `eval/baselines/fixture-baseline.json` and `eval/baselines/fixture-ingest-baseline.json`; plan 04-38 re-records them before this phase), with the noise band of `eval/config/noise.json` (`max(k * spread, floor)`, today k=3, floor 0.02, spread 0, so the band is 0.02). The gate runs two candidate configurations: `v2-default` (the D-01 set; fixture cells apply because the eval profile is used) and `v2-default-no-cells` (the same with `RAG_REFUSAL_THRESHOLD=false`, which is what production does while no live cell exists), each on the keyless path (`auto` resolves to the fallback) and on the hosted path against the fake edge (`v2-default-hosted-fake`, `v2-default-hosted-fake-no-cells`, Cohere with the `fake-quality-v1` model). All four must pass every criterion:
  - **G1** `python -m rag_eval.gate` passes in both fixture modes (no gated slice: overall, `language:*`, `category:cross_lingual`, `pair:*`, beyond the band on Recall@5, Recall@10, MRR, correct-refusal rate, false-refusal rate).
  - **G2** Ingest-mode overall Recall@10 is at least 0.6195 (today's 0.6395 minus the band) and at least the baseline in force minus the band; prechunked overall Recall@10 at least the baseline minus the band (today 0.4995).
  - **G3** Overall false-refusal rate at most baseline plus band and overall correct-refusal rate at least baseline minus band, in both modes (today: ingest false refusal at most 0.2642, correct refusal at least 0.48, that is no fewer of the 12 no-answer items refused; prechunked at most 0.3966 and at least 0.3133). `category:no_answer` correct refusal is checked the same way. The 95% upper bound of the false-refusal rate is reported next to every estimate (04-26).
  - **G4** No `category:*` slice with n of at least 8 drops beyond the band on Recall@10 or MRR (wider than the noise-config gate, as Phase 4 D-28(b) asks).
  - **G5** Latency on the fixture (report contract `stage_latency_ms`): the eval-profile run's p95 total within the chat `total_p95_ms` (2000) and its rerank stage p95 within 600 ms; voice is shown by the 04-28 injected-delay budget test under the defaults (p95 under 800 ms, plan 04.1-12). Fixture latency proves wiring only; the hosted numbers come from G7.
  - **G6** With `RAG_PIPELINE=legacy` set explicitly, every paired difference against the legacy baselines is zero in both modes, and the legacy characterization snapshots are byte-identical.
  - **G7** (live, capped, report-only; plan 04.1-08) Real Cohere `rerank-v5.0-pro` and `rerank-v5.0-fast`, and Voyage `rerank-3` and `rerank-3-lite`, on the fixture dev split: Recall@10 and MRR with threshold refusal off, and p95 rerank latency for 75 candidates. The `auto` hosted provider (Cohere) is kept only if its fixture Recall@10 and MRR are at or above the `local_bm25` and `none` runs minus the band, and its chat p95 is at most 600 ms; voice per D-09. A failing hosted check makes the decision record set `AUTO_HOSTED_PROFILES` to exclude the failing profile; it does not block the flip of hybrid and the no-key path.
  - **G8** Under the D-01 values set explicitly (before the flip, plan 04.1-07) the CI negative checks still fail as designed (`--degrade drop_top_candidate`, `--max-results 1`), and the 04-41 two-tenant matrix passes in both tenancy modes (D-11); `status: flip` requires it. Plan 04.1-12 repeats the matrix with nothing set as the post-flip proof.
- **D-13:** If G1 to G6 or G8 fail for every allowed floor and fallback choice, plan 04.1-09 does not run: the decision record says `not_flipped` with the offending slices, and the phase returns to the product owner. Thresholds, baselines and the noise band are never edited to make the gate pass.
- **D-14:** Real golden items. Today all 114 golden items are `synthetic_fixture`. EVAL-14 makes real (`production`, `human`) items the gate population once they exist (Phase 5.1.1 feedback loop, Phase 7 07-22 promotion). The decision record states that the fixture result is provisional; when the real dev split first reaches the live calibration minimums (`eval/config/refusal-calibration.json`, live: 20 answerable, 10 no-answer), the same G1 to G4 run on it, and a failure is fixed at its cause or answered by the single switch back to legacy. That re-run is a live-verification item of this phase.
- **D-15:** The decision record is `eval/decisions/04.1-retrieval-defaults.json` (Pydantic model in `eval/`, no Zod pair, since no TypeScript reads it; precedent 04-25) plus `eval/decisions/04.1-retrieval-defaults.md`. It holds the chosen values (D-01, D-04, D-06, D-09), every criterion with its numbers, the run ids, the baseline hashes and `provisional: true` (fixture). Phase 7's defaults decision (07-17, 07-25, 07-30) takes these values as the incumbent.

## Open questions for the product owner

- **Q-1 (default adopted, PO may override): which reranker is the default when a hosted key exists?** Default: `auto` picks Cohere (`rerank-v5.0-pro` chat, `rerank-v5.0-fast` voice) when `COHERE_API_KEY` is set. Alternative: Voyage `rerank-3`. Plan 04.1-08 measures both on the fixture with real calls; the decision record shows the numbers and the PO can switch the preference in one constant.
- **Q-2 (default adopted, PO may override): may `auto` use `VOYAGE_API_KEY`?** Default: no (D-05), because that key exists for embeddings and rerank adds spend and a data flow. Override: `auto` falls back to Voyage when only the Voyage key is set.
- **Q-3 (default adopted, PO may override): no-key fallback.** Default: decided by the pre-registered rule D-06 (`local_bm25` only if it does not hurt cross-language or overall quality, else fused order).
- **Q-4 (default adopted, PO may override): voice on hosted rerank.** Default: yes if the live fast-tier p95 is at most 250 ms (D-09), else voice uses the no-key fallback.
- **Q-5 (default adopted, PO may override): edge ordering on by default?** Default: no (not part of the 2026-11-24 decision; Phase 4 D-28(c) evidence can justify it later).
- **Q-6 (default adopted, PO may override): what if the gate fails?** Default: no flip, decision record `not_flipped`, back to the PO (D-13).
