# Phase 4.1 Plan 18: stopped at stop point 1 (Task 1 measurement)

**I stopped the plan at stop point 1. The 200-character preview is not the main cause of the ingest-mode difference between `legacy_rule` and legacy. The main cause is legacy's exact-identifier lookup. In ingest mode, legacy answers through `exact_id` rows that carry the synthetic similarity 1.0, and the D-28 pool replay leaves those rows out on purpose. No product code, eval config, gate report or decision record changed. Tasks 2 and 3 did not run, and no default was touched (D-29).**

Legacy does keep them, through `filterCandidates` (similarity 1 > 0.65).

## Counterfactual (fix applied, not committed)

I implemented the planned fix and its tests (RED, then GREEN: 140 of 140 in `tests/rag/refusal`) and ran `v2-default` ingest once more (`eval/out/p41f-diag/v2-default-ingest-fix`). The fix reads the pool members' whole `documents.content` through `fetchAssemblyRows`, only when the floor refuses on the hits' own text.

The fix is correct for what it targets, but it cannot close G-02 on its own. Following the stop rule, I reverted it. The patch is kept as `04.1-18-task1-evidence-read.patch` in this directory: the `rank.ts` evidence read, the `access` hand-off in `v2/pipeline.ts`, 4 parity cases and 8 evidence-read policy cases. It adds no SQL and no switch.

## Other findings

- **Prechunked fixture floor is stale against the golden set.** `eval/config/fixture-score-calibration.json` records `golden_sha256` `0f206916…aa6fa61` (fitted with `v2-recommended`). The golden set in force is `dc812d5f…d8eb6`. The plan assumes that the harness refuses an entry with a mismatched hash "as today". It does not: `fixtureScoreCalibrationFor` checks no hash. Adding that check would turn off the prechunked floor (fallback to 0.65) and change what `v2-default-similarity-floor` runs on in prechunked mode. I left it unchanged.
- **Task 2 needs a tool change.** The floor-writing path of `calibrate refusal` is behind `--write-thresholds`, which also merges `eval/config/refusal-thresholds.json`, a protected file. It also overwrites the whole floor file, which would drop the prechunked entry. Fitting the ingest floor therefore needs a floor-only write (for example `--write-floor`) and a per-mode `modes` map in the file. I drafted tests for this and did not commit them, because the plan stopped.

## Decision needed (owner / planner)

The ingest gap is a D-28 question, not a preview question. Options:

1. Let `legacy_rule` admit `exact_id` rows as pool members with legacy's keep rule (similarity 1.0 keeps), which reproduces legacy. This revises D-28's "synthetic similarity is not a pool member", and the test that pins it changes.
2. Keep D-28 and accept that `legacy_rule` differs from legacy whenever exact-id lookup is on. The ingest gate then judges that difference.
3. Either way, the preview fix in the patch can land as a small parity fix. It flips 2 non-gated items.

Task 2 (the ingest fixture floor) is independent of this question and can run as planned with the tool change described above.
