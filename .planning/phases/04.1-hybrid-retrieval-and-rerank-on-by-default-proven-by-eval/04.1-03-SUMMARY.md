# Phase 4.1 Plan 03: RAG_RERANKER=auto Summary

**`RAG_RERANKER=auto` reranks with Cohere when `COHERE_API_KEY` is set and with the local fallback otherwise, never marks a keyless request degraded, and hashes as the provider it resolved to. The default stays `none` until 04.1-09.**

## Accomplishments

- `parseReranker` accepts `auto` (trimmed, any case); `none`, `cohere`, `voyage`, `local_bm25`, empty and unknown values behave as before. `auto` does not add `rerank` to `disabledStages`.
- `effectiveProvider` resolves `auto`: a profile in `AUTO_HOSTED_PROFILES` with a Cohere key gets `cohere` (`rerank-v5.0-pro` for chat, embed, eval; `rerank-v5.0-fast` for voice via the tier); otherwise `AUTO_NO_KEY_FALLBACK` (`local_bm25`, model `bm25-v2`, or `none`), reason `auto_fallback`, no missing-key warning.
- `describeReranker` (and so the retrieval config hash) records the resolved id and model, never `auto`: auto-without-key hashes like explicit `local_bm25`, auto-with-key like explicit `cohere` (test `auto hashes as its resolved provider`).
- Rerank stage: keyless auto runs `ok` with detail `auto:local_bm25`, gate `not_applied/relative_scores`, not degraded; fallback `none` gives `disabled` with detail `auto:none`, gate `reranker_disabled`, not degraded; auto with key matches explicit Cohere (same order, same decision, same status) with detail `auto:cohere`; a Cohere timeout under auto still skips, degrades and lets the floor decide (Phase 4 D-11).
- Explicit `cohere`/`voyage` without a key unchanged (`skipped`, `missing_key`, degraded, warning).
