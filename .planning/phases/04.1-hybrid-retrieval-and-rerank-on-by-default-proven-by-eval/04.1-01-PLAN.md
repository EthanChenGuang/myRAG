<objective>
Give v2 a fallback refusal floor with today's legacy refusal semantics, behind a new switch whose default keeps v2 exactly as it is.

Purpose: CONTEXT D-03 and research F-1. Under v2 the similarity floor, when no fixture-fitted floor applies, refuses almost all fixture items (measured at execution time in Task 1 and recorded in the SUMMARY; the count in the 04-21 and 04-23 summaries is historical), and in production the rerank gate is not applied for any request until live cells exist (`decideRefusal`, the `cell_fixture_only` branch), so the floor decides what users see. Legacy keeps a candidate when a query word appears in its document; v2 has no such rule. This plan ports that rule into the floor through one shared predicate.
Output: `relevance.ts` with the shared predicate, `legacyRuleFloor`, the `RAG_REFUSAL_FLOOR` parse, and tests.

Code is named by symbol. Re-read the newest definition of each symbol at execution time, because other phases are editing these files on trunk (CONTEXT D-27).

Runs after Phase 4's automated close (04-42). Config-location sync of the new variable is plan 04.1-02 (same wave, disjoint files); the default stays `similarity` until plan 04.1-09.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines (Co-Authored-By and the session link) that the executor's own session supplies; never copy them from a plan. No model identifiers in code comments or commit messages; no secrets.
</objective>
