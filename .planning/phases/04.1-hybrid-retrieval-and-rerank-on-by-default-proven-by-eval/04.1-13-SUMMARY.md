# Phase 4.1 Plan 13: Language state connected to the implicit-default resolver Summary

**The resolver now gets the language state from Phase 3.2's own reader, and one rule decides whether `RAG_PIPELINE` was set. With languages unset, a defaulted v2 serves exactly what legacy serves on chat, embed, eval and voice (same snapshot files, byte for byte, `hybrid_search_chunks` never called, one startup line). An explicit v2 answers `languages_not_configured`, which the chat route reports as a knowledge-base outage, never as "information not available". With languages set, the defaulted v2 runs v2.**
