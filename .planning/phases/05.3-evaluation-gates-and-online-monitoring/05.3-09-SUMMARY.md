# Phase 5.3 Plan 09: Judge labels and review-item strata summary

**Expert answer-check labels with tenant RLS (0965), plus sampling strata, the representative and re_review reasons and a service-role enqueue function on the Phase 5.1.1 review queue (0967).**

## Accomplishments
- `public.rag_judge_labels`: authenticated users can read and write labels only where `rag_is_domain_expert(tenant_key)` is true, and only under their own `labelled_by`. A composite FK ties each label to its review item's tenant, and the label is deleted with its item.
- `public.rag_review_item_strata`: source, stratum and weight are stored beside each review item, so the 5.1.1 table keeps its columns. It is service-role only and its rows are deleted with their review item.
- The reasons check now also accepts `representative` and `re_review`. Every 5.1.1 reason is still accepted and unknown reasons are still rejected.
- `public.rag_review_items_enqueue(p_tenant_key, p_source, p_rows)` returns the number of items inserted. A second call with the same rows inserts 0. A key of the other deployment mode raises 22023, and anon or authenticated callers get 42501.
- Both files are no-ops on a database without `rag_review_items` and are idempotent. Neither is folded into the setup files (D-56).
