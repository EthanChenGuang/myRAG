# Phase 5.3 Plan 04: RAG-affecting keys, rag_settings_hash and one secret-name rule

The manifest records which settings are RAG-affecting, the app gets a generated copy of that list, and the config server and the app now share one settings-hash implementation and one secret-name rule.

## Accomplishments

- Every manifest entry has `ragAffecting`: 189 names are true (185 entries plus the 4 names in `ragAffectingExtra`: `NEXT_PUBLIC_AI_PROVIDER`, `NEXT_PUBLIC_MYRAG_DEPLOYMENT_MODE`, `NEXT_PUBLIC_OPENAI_MODELS`, `NEXT_PUBLIC_OPENROUTER_MODELS`) and 46 entries are false.
- False means one of these: a secret according to `isSecretName` (*_API_KEY, *_SECRET, LANGFUSE_PUBLIC_KEY, REDIS_URL, RAG_MONITOR_WEBHOOK_URL and others); `LANGFUSE_*`; one of the six Phase 5.3 switches; a log or feedback switch (`RAG_RETRIEVAL_LOG`, `RAG_RETRIEVAL_LOG_RETENTION_DAYS`, `RAG_ANSWER_FEEDBACK`, `RAG_REFUSAL_FEEDBACK`, `RAG_EMBED_FEEDBACK`, `RAG_SOURCE_OPEN_SIGNAL`, `RAG_DOMAIN_EXPERT_REVIEW`, `RAG_TERMINOLOGY_MINING`); eval endpoint access (`RAG_EVAL_ENDPOINT_ENABLED`, `RAG_EVAL_ALLOWED_SCOPES`); UI only (`NEXT_PUBLIC_RAG_INGEST_REALTIME`); or capacity and retention (`RAG_INGEST_WORKER_CONCURRENCY`, `RAG_INGEST_JOB_RETENTION_DAYS`, `RAG_INGEST_MAINTENANCE`, `RAG_INGEST_MAINTENANCE_INTERVAL_SECONDS`, `VOICE_MAX_ACTIVE_ROOMS`, `RAG_VOICE_TOKEN_TTL_SECONDS`).
- The default run of `check-config` now fails in three cases: a `RAG_*` entry has no `ragAffecting`, any entry has a non-boolean value, or `rag-affecting.generated.json` is missing or differs from the manifest. The failure message names `node scripts/check-config.mjs --write-rag-affecting`.
- `ragSettingsHash(values, names, isSecret = isSecretName)`:
  - It is the sha256 of `JSON.stringify` over the sorted, de-duplicated pairs. That string is identical to `canonicalJson` for this flat object.
  - Secrets enter as `set` or `unset`.
  - `RAG_SYSTEM_PROMPT`, `RAG_PRE_CONTEXT` and `RAG_POST_CONTEXT` enter as their own sha256 (assumption A7).
  - A missing name counts as `''`.
- `ragAffectingDiff(before, after, names)` returns the sorted names whose values differ, with a missing value treated as `''`.
- The shared vector `tests/fixtures/rag-settings-hash-vector.json` contains a non-ASCII value and a literal escaped `\n`. It was generated by an independent Python implementation and is checked from `node --test` and from vitest.
- `scripts/config-server-security.js` (`isSecretConfigEntry`) and `src/lib/config-env-allowlist.ts` (`isSecretEnvName`, `isReadableEnvEntry`) now both use `secret-name.cjs`. Their exported names stay the same, and a parity test runs one name table through all three functions.

## Decisions Made

- **Wider secret rule.** The two name patterns were identical. Only the config server also treated `MCP_CUSTOM_SERVERS`, `REDIS_URL` and `MCP_*_ENDPOINT` as secrets, so that wider rule became `isSecretName`. As a result `isSecretEnvName` now also reports those names as secrets. None of them is in `CONFIG_WRITABLE_ENV_NAMES`, so the in-app allowlist behaves the same.
- **Names marked true because their class was unclear** (a spurious check is safer than a missed one):
  - every ingestion-side setting: parser, `LLAMACLOUD_*`, chunking, captions, translation, scan checks, upload approval, scope-tag suggest, supersession detection, `RAG_EMBED_BATCH_MODE`, `RAG_PARSE_POLL_BUDGET_MS`
  - provider and backend endpoints: `*_BASE_URL`, `RAG_SIDECAR_URL`, `WEAVIATE_URL`, `QDRANT_URL`, `RAG_VECTOR_SYNC_MAX_LAG_SECONDS`
  - timeouts: `RAG_STAGE_TIMEOUTS`, `RAG_GROUNDEDNESS_TIMEOUT_MS`, `RAG_DOMAIN_EMBEDDING_TIMEOUT_MS`
  - other: `RAG_EMBED_TENANT`, `RAG_EVAL_RETRIEVAL_MIN_SIMILARITY`, `NEXT_PUBLIC_RAG_IMAGE_ALLOWLIST`, `RAG_SEMANTIC_CACHE_*`, `RAG_DISABLED_STAGES`
- **Import path for app code.** The typed API is re-exported from `@/lib/rag`, so app code (05.3-21 to 23, 51) has an import path that passes the boundary check.

## Deviations from Plan

1. **Bug fix: `RAG_CONTEXT_TOKEN_BUDGET` was treated as a secret.** The `TOKEN` pattern matched and no benign rule covered it. As a result the config server masked a numeric context switch, and the rule would have forced the name to `ragAffecting: false`. `TOKEN_BUDGET` is now on the benign list. The name table in `tests/lib/rag-settings-hash.test.ts` failed on the old code ("expected true to be false"). With this fix `GET /api/config` on the config server returns the value of `RAG_CONTEXT_TOKEN_BUDGET`.
2. **Boundary rule exemption.** `check-rag-boundary` flagged `require('../src/lib/rag/config-gate/secret-name.cjs')` in the config server as a `deep-import`. The rule now exempts only `.cjs` files directly under `lib/rag/config-gate/` (`SHARED_CJS`). TypeScript deep imports and nested paths still fail, and tests cover both cases.
3. **Extra files.** I added `.d.cts` declaration files beside the two `.cjs` modules, following the precedent of `config/rag/validate-language-settings.d.cts`, and the export line in `src/lib/rag/index.ts`.
4. **No migration was created.**

Not unified, because these copies run in other runtimes:
- `eval/src/rag_eval/defaults_decision.py` and `phase_compare.py` (Python)
- `scripts/config-ui/rag-panels/ingest-impact.js` (browser)
