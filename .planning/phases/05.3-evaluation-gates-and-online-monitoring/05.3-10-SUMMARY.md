# Phase 5.3 Plan 10: Query clusters and weekly drift storage Summary

**Per-tenant, service-role-only storage for query clusters (real[] centroids, opaque ids, assignments cascading with the retrieval log) and weekly drift numbers, in migrations 0966 and 0968, tested on PGlite in both modes.**

## Performance

- **Duration:** about 45 min
- **Tasks:** 2
- **Files modified:** 5 (4 created, 1 test line changed)

## Accomplishments

- 0966: `rag_query_cluster_sets` (status current or superseded, embedder, dimension, k, fitted_at, query_count, distance_threshold; one current set per tenant), `rag_query_clusters` (centroid `real[]` checked one-dimensional with no NULLs, member count; no vector column or index) and `rag_query_cluster_assignments` (primary key `log_id` referencing `rag_retrieval_log(id) ON DELETE CASCADE`, cluster id c-NN or `novel`, distance 0 to 2). Clusters and assignments reference the set through `(set_id, tenant_key)`, so the database itself refuses a row whose tenant differs from its set's.
- `rag_query_clusters_write` validates the whole input before any write (centroid length equals the dimension, numbers only, opaque unique ids, non-empty list), supersedes the tenant's current set and returns the new set id. Other tenants' sets are untouched.
- `rag_query_cluster_assign` joins every row to the log under `l.tenant_key = p_tenant_key`; rows of another tenant or missing rows are dropped and counted.
- 0968: `rag_drift_weekly` (primary key tenant and week, divergence 0 to 1, null_p95 0 to 1, state ok, warn or alert, report jsonb) and `rag_drift_weekly_upsert`.
- No text column beyond tenant key, status, embedder id and cluster ids; the test asserts the column set.
