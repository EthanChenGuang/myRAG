# Phase 5.3 Plan 14: Instruction-sensitive fake generator and the smoke-harness env overlay Summary

**The fixture smoke tier can now answer with a fake generator that refuses a no-answer item only when the prompt tells it to, and can run proposed settings from an overlay file. A prompt that drops the refusal instruction fails the false-answer ceiling with no model call.**

## Accomplishments

- `config/rag/prompt-directives.json` holds generic refusal-directive and negation patterns for zh, en and it. They describe the instruction, never a subject. `hasRefusalDirective` detects the eval route's default template ("If information is not available in the context, say so clearly").
- In `--answers` runs the fake generator gets the no-answer questions (golden items with `answerable` false) and the template the route assembles under the run's env. A no-answer question with context then gets:
  - the item language's refusal text from `eval/fixtures/refusal-texts.json`, when the template has the directive;
  - otherwise a fixed neutral unsupported answer, which cites no block and matches no refusal text.
- `--env-overlay <file>` takes `{ "env": { NAME: value } }`:
  - a name outside the RAG-affecting list, a secret name, a non-string value or a URL with credentials ends the run with exit 2, and the offending names are listed;
  - the overlay is refused together with `--base-url`;
  - names the fixture layer cannot exercise are not applied and go to `overlay-report.json` under `not_evaluated`, with a reason code;
  - the fixture pins are set again after the overlay.
- Measured on the prechunked fixture with `--answers --gates eval/config/quality-gates.json --gates-mode report`:

  | Prompt | false_answer_rate (overall) | Result |
  | --- | --- | --- |
  | default template | 0.00 | passed |
  | overlay without a directive | 0.32 (8 of 25) | failed |

  Each run takes about 13 s.

## Deviations from Plan

1. **`--env-overlay` applies the overlay through a new pin re-application step rather than literally through `extra` alone.** The overlay is merged with any run-config env into `envOverrides`, which reaches `applyFixtureProcessEnv`'s `extra`. `reapplyFixturePins` then sets the fake-edge values, the deployment mode and the embedder again. A run-config run without an overlay keeps today's order, because run-config may legitimately set `COHERE_BASE_URL` to `''`.
2. **Pinned names are listed as not evaluated rather than refused**, with reason `fixture_pin`, or a more specific reason where one fits. The reason is in Key decisions above.
3. **Extra reason codes** `fixture_pin` and `external_service`.
4. **`FAKE_INSTRUCTION_GENERATOR_MODEL`** is a new generator id for `--answers` runs.

## Deferred / for plan 05.3-15

- Without `--citations` the context blocks carry no `[S<k>]` labels. The fake generator therefore answers every answerable item with the English no-context sentence, as it did before this plan, and the plan required that output to stay byte-identical. With `--answers`, the English answerable items then score as refusals. Prechunked `--answers` measurements:

  | Slice | false_refusal_rate |
  | --- | --- |
  | en | 1.00 |
  | overall | 0.56 |
  | retrieval-only overall (no `--answers`) | 0.34 |

  Plan 05.3-15 should either turn `--citations` on together with `--answers`, or teach the fake generator to answer unlabelled context, before it records baselines with answers on.
