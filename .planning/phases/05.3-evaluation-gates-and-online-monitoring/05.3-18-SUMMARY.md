# Phase 5.3 Plan 18: Judge calibration seed set Summary

## Accomplishments

- `generate_seed.py`: standard-library generator (fixed seed 5301 plus the language index) that builds, per language (zh, en, it), 60 base cases from structural templates about a synthetic unit. Contexts state two of three attributes; the question asks about one; the answer kind fixes the labels. Long/short pairs and expanded/assertive perturbation groups are emitted after their base with `base_id`, `pair_id` or `perturbation_group`. Output is one JSON object per line, stable order, `ensure_ascii=False`. `--check` exits 1 when the committed file differs or a case fails `JudgeSeedCase`.
- `seed.jsonl`: 324 cases (108 per language: 60 base, 12 long, 12 short, 12 expanded, 12 assertive), all `review_status: "draft"`; `grep -c approved` is 0.
- `test_judge_seed_fixture.py`: 15 tests; thresholds are named constants at the top (`MIN_BASE_CASES_PER_LANGUAGE = 50`, `MIN_POSITIVE_SHARE = 0.40`, `MAX_POSITIVE_SHARE = 0.60`, `MIN_LENGTH_PAIRS_PER_LANGUAGE = 10`, `MIN_PERTURBATION_GROUPS_PER_LANGUAGE = 10`). It never requires draft: after H-5, approved cases pass when they carry `reviewed_by` and the marker says confirmed.

## Deviations

1. A fifth answer kind (`off_unsupported`) is added to the plan's four so that answer relevance can sit between 40% and 60% while keeping at least 10 fully supported bases for the length pairs.
2. The generator imports `JudgeSeedCase` lazily inside `--check` to validate; generation itself is standard library only.
3. `--check` carries human review fields from the committed file over before comparing, so the byte-for-byte check keeps working after H-5; until then every case is draft and the comparison is plain byte for byte.
4. No migration (none needed by this plan).
