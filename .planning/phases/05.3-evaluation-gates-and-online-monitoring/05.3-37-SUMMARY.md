## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Imported and sampled review items failed the ReviewItem contract**
- **Found during:** Task 1
- **Issue:** 0967 (05.3-09) allows reasons `representative` and `re_review` and a null `trace_id`, and 05.3-36 imports items with reasons `['representative']` and no trace. The `ReviewItem` contract (Python and generated Zod) still allowed only the Phase 5.1.1 mining reasons and required a trace id, so `exportGolden` skipped every imported item, `toReviewItem` dropped it from the expert review list, and the Python twin of the export line would have rejected it. 05.3-09's SUMMARY left the contract change to "the plan that owns the contract"; no later 05.3 plan names it.
- **Fix:** `ReviewItemReason` (mining reasons plus `representative`, `re_review`) for `ReviewItem.reasons` and the export twin; `trace_id: str | None`. `MiningReason` itself is unchanged (mining counts and config keep their keys). `review-access.ts` already handled a missing trace id.
- **Files modified:** `rag-sidecar/src/rag_sidecar/contracts/feedback_loop.py`, generated schemas and `contracts.generated.ts`, `eval/src/rag_eval/review_queue.py`
- **Verification:** the Task 1 test failed on the old code (imported item missing from the export) and passes now; sidecar contract test added.
- **Committed in:** `48fb97fd`

**2. [Rule 2 - Missing functionality] Writer could not keep a parent's split or write into a docgroup set**
- **Found during:** Task 3
- **Issue:** `write_drafted_items` always assigned splits by the item-id hash and refused docgroup manifests, so variants would land in a split other than their parent's (leakage) and could not be added to a promote-db domain set.
- **Fix:** entries may carry a pinned split, tags and a base item; `freeze_splits` honours pins for new ids; with pinned entries and a docgroup manifest the writer uses `freeze_group_splits`, and `split.py` treats `paraphrase_of:<id>` like a confirmed near-duplicate when forming groups. The flat draft path (no pinned entries) runs exactly the old code, including its docgroup refusal.
- **Files modified:** `eval/src/rag_eval/draft/writer.py`, `eval/src/rag_eval/split.py` (not in the plan's file list)
- **Verification:** `test_draft_paraphrase.py` (item-rule and docgroup sets), `test_draft_writer.py`, `test_split.py`, `test_draft_cli.py`, full eval suite
- **Committed in:** `9ef692d1`

**3. [Rule 3 - Blocking] Pinned test of the committed gate population**
- **Found during:** Task 2
- **Issue:** `eval/tests/test_gate_population.py` asserted the committed file equals `provenances=["production","human"]`.
- **Fix:** the expectation now names `historical` too; mode `legacy` and `min_items` 100 are still asserted.
- **Committed in:** `86dca767`
