# Phase 5.3 Plan 36: Historical questions import Summary

**Admins can load historical user questions into one tenant's review queue as cold-start material, from `npm run rag:questions-import` or in batches from the Config UI. Every question is masked, rows that still change under the masker are rejected, text is capped at 2000 characters, the log's fingerprint deduplicates within the file and against the queue, and the only output is counts.**

## Accomplishments

- `parseQuestionFile(text, { format, column })`: a hand-written RFC 4180 reader (header row, quoted commas, doubled quotes, quoted line breaks, CRLF, BOM) and a JSON-lines reader. It returns `column_not_found` or `too_many_rows` (above 20,000), and a malformed line or a non-string value becomes an empty row.
- `prepareQuestions(values)`: trim, `maskPII`, the residual check, fingerprint (`queryFingerprint`, shared with the retrieval log), dedupe within the file, the 2000-code-point cap, and the language code (`und` when nothing is detected).
- `importQuestions(admin, { tenantKey, prepared, dryRun, now })`: checks the tenant key form, looks up existing fingerprints for that tenant 200 at a time, and enqueues new rows 500 at a time through `rag_review_items_enqueue(tenant, 'historical', rows)`. Returns `{ read, added, duplicates, rejected_pii, truncated, empty, by_language }`.
- CLI `rag:questions-import -- --tenant <key> --file <csv|jsonl> [--format] [--column question] [--dry-run]`: reads the file in place (size check before `readFile`), never copies it, and prints two `[Monitor]` count lines.
- `POST /api/rag/admin/questions-import`: takes `{ organizationId, format, column, dry_run, rows }` batches of at most 60 KB and 2000 rows, derives the tenant on the server, and answers the same counts with `dry_run`. It logs one `[Monitor]` line with counts.

## Deviations from Plan

- **File added outside `files_modified`:** `src/lib/rag/feedback-loop/query-codes.ts`. The fingerprint was inline in `buildRetrievalLogRow`, and `retrieval-log.ts` loads the app environment through `../deps`, which needs unrelated keys. Exporting from there would have broken the CLI and the PGlite test. Writing a second fingerprint function is prohibited, so the existing one was moved. `retrieval-log.ts` now imports and re-exports it, so its importers did not change.
- **File added outside `files_modified`:** `src/lib/rag/index.ts` gained barrel exports, because the app routes import from `@/lib/rag`.
- **Signature:** `importQuestions` takes `{ tenantKey, prepared, dryRun, now }`, where `prepared` is the output of `prepareQuestions`. The plan named `questions`. This lets the route and the CLI share the same two-step call.
