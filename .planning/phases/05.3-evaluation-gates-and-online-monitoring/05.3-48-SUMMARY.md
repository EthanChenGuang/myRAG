## Deviations

1. **Reference commit.** The plan says to record the reference on the pre-phase commit, which is 1315b1a9, the parent of 4e3ccfb9, the first 05.3 code commit. That commit is the Phase 5.1.1 closing summary. Since then, trains 30 to 33 have merged Phases 4.2, 4.4 and 5.2 and changed the fixture corpus, the golden set and both baselines. A reference from 1315b1a9 would therefore differ for reasons outside Phase 5.3. The reference was recorded at 49e260b4 instead, with every switch unset, and this file records the reason. The "switches off equals no 5.3 effect" claim rests on the paired-zero comparison and the off-path checks, not on a pre-phase snapshot.
2. **Answer hash.** The reference stores `answer_sha256` instead of the answer text. Byte equality holds either way, and some fixture answers repeat corpus text that the domain-neutrality rule would not allow in a new file.
3. **List checks.** The change-record and pilot-user lists are checked through `tests/helpers/pglite-admin.ts`, not through the routes. The fake edge serves no table read of `rag_config_change_records` (404, unsupported table). It also returns a scalar RPC as `[{fn: value}]`, so the control asserts the row count rather than `requested: true`. Both are limits of the harness, and `eval/harness/fake-edge.mts` was not changed.
4. **Extra files.** Two files outside `files_modified` were added: `tests/rag-e2e/phase53-defaults-probe.mts` (precedent: `phase32-all-off-probe.mts`) and `eval/config/phase5.3-comparison.json` (the spec `phase_compare` needs).
5. **Webhook secret.** `RAG_MONITOR_WEBHOOK_SECRET` is not in the comparison spec. A schema-2 spec refuses names that look like credentials, and unset is the default.
6. **Cross-phase pairing.** `rag_eval.gate` against the 1315b1a9 baselines exits 2 because the golden and corpus hashes differ. No cross-phase paired difference exists. This is stated in comparison.md, and no baseline was touched.
