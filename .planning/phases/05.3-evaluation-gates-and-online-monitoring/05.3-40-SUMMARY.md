## Deviations from Plan

1. **[Contract] `GatesCollection` wrapper.** The plan says `collect_gates_section` returns a validated `WeeklyGatesSection`; it returns `GatesCollection` whose `section` is that model. `WeeklyGatesSection` is `extra=forbid` and has no field for the not-read markers, the release-override source (database or github) or the per-set overdue counts the behaviour list asks for. Changing the contract would touch the schema registry and the TS side outside this plan, so the extras live in the wrapper, the Markdown and the standalone JSON (`not_read`, `release_sources`, `overdue_by_set`); `WeeklyReport.gates` holds the contract section only.
2. **[Test] `test_weekly_report.py` stats test.** It asserted exactly one request; the weekly report now also calls the three gates routes, so the test filters to the stats route. A new test checks the attached section.
3. **[Workflow] Tenant list file.** drift, stale-scan and re-review need a tenant key, which cannot be recovered from the private set's hash directory. The weekly steps read keys from `eval/golden/private/tenants.txt` on the operator's runner (one per line, `#` comments), print only tenant hashes, and skip with a notice when the file is absent.
4. **[Workflow] Generator model variable.** `judge_calibration run` requires `--generator-model`; the workflow takes it from `vars.RAG_JUDGE_GENERATOR_MODEL` and includes it in `HAS_JUDGE_KEYS`, so the skip notice reads "judge keys or generator model not configured". The lint names it `JUDGE_CALIBRATION_WORKFLOW` because `JUDGE_CALIBRATION` already names the calibration file path.
5. **[Lint] `check_nightly_triggers`.** The trigger rules were moved out of `check_nightly` into their own function so the push-trigger case has a unittest; behaviour is unchanged.
