## Deviations

1. **[Rule 2] The node self-tests are wired into `ts-checks`**, together with 05.3-38's `post-release-status.node-test.mjs`, which that SUMMARY left for this plan. The commit is separate (`851b5976`).
2. **Extra safety checks beyond the plan:** the deployment's `meta.githubCommitSha` must match the sha; `ROLLING` is treated as a promotion in progress; the promote workflow must not check out the promoted sha; the lint requires a non-cancelling concurrency group; and "pr-smoke not found while a source is unreadable" is reported as unreadable (exit 2) instead of not required. Each one fails in the safe direction.
3. The promote job checks out the repository even though the script needs no install. The script must come from the default branch, so the checkout stays, with `persist-credentials: false`.

## Threats

T-05.3-391 (forged status): creator check, with tests for a write user, a user whose permission cannot be read, a foreign bot and a spoofed `type`. T-05.3-392 (a skipped job passes): aggregate loop and lint. T-05.3-393 (settings writes): the protection reader only issues GET; nothing in this plan calls a settings endpoint. T-05.3-394 (sha injection): input only through env, a 40-hex check, and a lint rule. T-05.3-395 (double promotion): PROMOTED and ROLLING checks, plus 409 handling.

Residual risk: whether `GITHUB_TOKEN` with `contents: read, statuses: read` may call the collaborator permission endpoint is unverified (research). If it is refused, an admin-posted status is refused, which is the safe direction; statuses from the bot are unaffected.
