# Phase 5.3 Plan 31: Query topic clusters Summary

**Reproducible per-tenant topic clusters of masked production questions: a pure seeded spherical k-means module on the backfill sampler's `seededRandom`, and `refreshClusters`, which fits, extends or refits a tenant's cluster set through the 0966 writers.**

## Performance

- **Duration:** about 60 min
- **Tasks:** 2
- **Files:** 4 created, 1 modified

## Accomplishments

- `seededRandom` in `src/lib/rag/ingest/backfill/sample.ts` is now a named export (O-3 item 4). No other change; the backfill tests pass unchanged.
- `kmeans.ts`: `chooseK` (30 → 4, 200 → 10, 800 → 20, 5000 → 40, never above n), k-means++ seeding on cosine distance, Lloyd iterations on the unit sphere that stop when no assignment changes or at 50 passes, merging of clusters under 5 members into the nearest centroid (smallest first), `assignNearest` with the `novel` bucket, the 95th-percentile distance threshold and `carryClusterIds`.
- `clusters.ts` `refreshClusters`: reads the tenant's masked queries of the last 30 days on the injected service-role client (paged), skips with `{ written: false, reason: 'too_few_queries' }` below `min_queries`, embeds through `embedQueries` (injectable) in batches of 96, and either assigns new rows to the current set or fits a new one, writing only through `rag_query_clusters_write` and `rag_query_cluster_assign`. Query text and per-query vectors stay in memory.
- Default config is the `sampling` block of `eval/config/monitor-alerts.json` (`loadClusterSamplingConfig`).
- No switch of its own: plan 05.3-32's weekly sample job carries `RAG_REPRESENTATIVE_SAMPLE` and calls this service.

## Decisions Made

See `key-decisions` in the frontmatter. For downstream plans:
- 05.3-32 (weekly sample): call `refreshClusters(serviceRoleClient, { tenantKey })` once per tenant before drawing strata; the result says whether it refit and the set id. A `too_few_queries` result writes nothing; the caller decides what the sample does then.
- 05.3-33 (drift): cluster shares come from `rag_query_cluster_assignments` of the current set; `novel` is its own bucket.

## Deviations from Plan

1. **[Rule 2 - Interface] `mergeSmallClusters(result, vectors, minSize)` and `distanceThreshold(result, vectors, percentile)`** take the vectors as a second argument; the plan's signatures had no place for them, and both need member vectors. Exported names are as planned.
2. **[Test expectation] Same-month assign test:** the novel threshold is the 95th percentile of fit-time distances, so a few in-distribution new rows go to `novel` by design (4-5 of 20 in the fixture). The test asserts that the outlier is novel, that every other new row is either novel or in a cluster whose members share its synthetic topic group, and that the set and centroids stay unchanged.

No migration was created (the plan uses 0966 from 05.3-10).
