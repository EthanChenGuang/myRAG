# Phase 5.3 Plan 43: Setting checks panel and refusal calibration marks

## Accomplishments

- **Setting checks panel** (`#rag-administration-setting-checks`, deployment-wide). A summary shows the saved mode (`mode.off|warn|enforce`) and the live model check (On/Off) from `configManager.savedConfig`, plus `mode.pending` while the unsaved `#RAG_CONFIG_GATE` differs. Sub-tabs Last check, Evaluation runs and Settings use `gatesUiSubTabs`. `initSettingChecksPanel` is idempotent: a second call refreshes and keeps the selected sub-tab. It is bound to every `[data-tab="rag-administration"]` link and runs on `DOMContentLoaded` when the tab is active.
- **Last check** loads `GET /api/config/rag-gate/check/latest` through `fetch` with same-origin credentials and a 15-second timeout. It draws the check as the dialog does: changed setting names, one verdict line per layer (a missing layer reads Skipped), failed rows first in the evidence table with the rest under Show all checks, and the not-covered line, untested notice and threshold notice. It ends with `last.savedAs`. It offers no save or override. With the saved mode off it shows `off.title`/`off.body` and makes no request; a 404 shows `last.empty.*`. It reads named fields only: no setting value and no override reason.
- **Evaluation runs** loads `GET /api/rag/admin/eval-run-requests?limit=20` through `gatesUiFetch`, 20 at a time with Load more runs (cursor). Status mapping: pending and running as such; done as Passed or Failed, or No result when the result is missing; skipped with its reason (`no_real_set`); failed as No result. Skipped is never green. The workspace column shows the `#workspace-selector` name, or the tenant key in `font-mono break-all`, and is hidden in single-tenant mode. Unknown reasons stay as code. The view ends with `runs.drainHint` naming `python -m rag_eval.tenant_nightly --drain` and starts no run.
- **Settings** moves the `gate` group out of `#rag-phase053-settings` on first mount only and translates its `data-rag-i18n` texts. The combination notes are recomputed on `change`: `warn.liveNeedsGate` (warning) and `warn.enforceFirst` (info, saved `off` changed straight to `enforce`).
- **Refusal calibration marks.** A cell with `pending` gets "Uncalibrated after a change" (`reranker_model`, `embedding_model`, `tokenizer`) or "Possibly stale" (`score_shift`) as a `badge-warning badge-outline` after the existing badges, and a 12px hint with the date in `<time>`. With a mark, every badge keeps its own line next to the unchanged "Not calibrated" and "Stale". Two new warnings: `uncalibrated_after_change` shows the count, the command in code and a `warning.changedSettings` line with each env name in code; `possibly_stale_scores` shows the count and a `btn btn-link btn-xs` "Review alerts" that opens the Monitoring Alerts view (`gatesUiOpenMonitorAlerts`). The legend gains `legend.pending` and `legend.shift` when the route sends the new fields. After a refresh of the panel (Refresh status or Reload panel, not the first load) `window.gatesUiRefreshBanner()` runs. A status without the new fields renders exactly as before: a snapshot recorded on the unchanged code checks this.

## Decisions (for STATE)

- **Dependency merge.** origin/exec/05.3-42 conflicted with main in AGENTS.md, both setup SQL files and tests/rag-db/schema-equality.test.mts. Main folded Phase 4.1.1 (0471–0473) and the branch folded Phase 6.1 (0651–0654); both appended a section at the end of the setup files with no overlapping objects. Resolution keeps both, in migration order: 4.1.1, then 6.1, which closes the file. The FOLDED_MIGRATION regex covers both, both per-phase tests and both `assert…Secured` calls stay, the end-of-file test expects the 4.1.1 section and then the 6.1 section, and AGENTS.md lists both as folded. `git diff --diff-filter=D --stat origin/main HEAD` shows no deleted file. schema-equality: 43/43.
- The runs route sends `checks` as failed check names (codes), not check objects (05.3-25 `projectRequest`). So "Show failed checks" lists the check labels (unknown names as code) instead of an evidence table: the UI states no measured value or limit the server did not send (UI-SPEC 6.2).
- The Last check view keeps the dialog's untested and threshold notices as well as the layers and evidence ("as the dialog drew them"). They hold names only.
- `last.savedAs` is left out when the config server sends `saved_as: null` (no decision recorded yet). An unknown value is shown as code.
- An eval-run request whose status is `failed`, or `done` without a result, shows No result with the shared `reason.missing` sentence, because the gates-ui rule requires a reason on every No result and the route carries none for these.
- The refusal panel keeps its own loading, refresh, sign-in and error states. They render the same as gates-ui's states, and switching to the shared helpers would have changed the markup this plan must keep unchanged for a status without the new fields.
- `data-refusal-badges` and the stacked badge column appear only on rows with a mark, and the legend entries only when the route sends the new fields. This keeps the old render byte-identical (snapshot).
- "Review alerts" uses `REFUSAL_LABELS['action.reviewAlerts']` with the banner's words (`banner.alertsAction`: Review alerts / 查看告警 / Esamina avvisi), since UI-SPEC 12.5 names the button but gives no REFUSAL key for it.
- Env names in `warning.changedSettings` are code segments only when they look like env names (`^[A-Z][A-Z0-9_]*$`); any other string is plain text.
