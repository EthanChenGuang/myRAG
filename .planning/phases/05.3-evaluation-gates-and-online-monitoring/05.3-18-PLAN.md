<objective>
Create the seed calibration set: at least 50 synthetic, neutral, labelled answers per language with length pairs and perturbation groups (D-31).

Purpose: before the review queue holds enough expert labels, judges are calibrated against this set once a human has confirmed its labels (EVAL-24).
Output: a deterministic generator, the committed `seed.jsonl`, a fixture test.

Labels stay `draft` in this plan; confirming them is human checkpoint H-5 (plan 05.3-50), and a draft label can never produce a gating cell (plan 05.3-17). Depends on 05.3-03 (`JudgeSeedCase`). Rollout position: D-60 step 4.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan.
</objective>

  <action>
Write `generate_seed.py`: a deterministic script (fixed seed, standard library only) that builds cases from structural templates written in zh, en and it. A template describes a synthetic record with named attributes (an item with an identifier, a numeric attribute, a state, a date in a made-up calendar-free form) and produces: contexts that state some attributes; a question about one attribute; and an answer of one of these kinds, which fixes the labels by construction: fully supported and relevant; supported but off the question (faithful, not relevant); relevant but stating an attribute value the contexts do not give (not faithful, unsupported_content true); mostly supported with one added unsupported statement (unsupported_content true). For a share of the supported cases it also emits a long and a short version with one `pair_id`, and for a share of all cases an `expanded` and an `assertive` variant with one `perturbation_group` and the base case's id as `base_id`.

Emit at least 50 base cases per language, balanced between 40% and 60% positive for faithfulness and for answer relevance, ids of the form `seed-<lang>-NNN` with a variant suffix, every case `review_status: "draft"`. Use invented tokens for names of things (letter and digit codes), no real-world subject. Write `seed.jsonl` with one JSON object per line in a stable order. Running the script with `--check` regenerates in memory and exits 1 when the committed file differs.
  </action>
