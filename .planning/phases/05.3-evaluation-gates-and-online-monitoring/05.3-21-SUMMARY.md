# Phase 5.3 Plan 21: shared setting-check core and the config-changes route

The config server and the app now share one module for the save decision, the change record and the check store. Admins can list change records and record release overrides through `/api/rag/admin/config-changes`.

## Accomplishments

- `decideSave({ mode, before, after, ragGate, readCheck, names })` returns `{ kind: 'write', gateResult, checkId, overrideReason }` or `{ kind: 'refuse', status, error }`:
  - Mode `off`, or a save with no RAG-affecting change, writes with `not_required` and never calls the reader.
  - `enforce` writes only in two cases: a `done` check whose id is a uuid, whose `rag_settings_hash` equals the proposed hash and whose result is `pass`; or an override reason of 10 to 500 characters after trimming. The override is recorded with the matching check's result, or with `skipped` when no check matches. Anything else answers 409 `rag_gate_required`. A reason outside the bounds answers 400 `invalid_reason`, checked before any check is read.
  - `warn` always writes. It records the matching check's result, or `skipped` when no check matches.
  - A reader that throws, or a check of another hash, counts as no check.
- `buildChangeRecord` reads only named inputs, so a value passed in by mistake never reaches the row. It writes:
  - `changed_keys` from `ragAffectingDiff`, or the given keys filtered to env-name form
  - `before_hash` and `after_hash`, computed by `ragSettingsHash` or passed in
  - `gate_summary`: check, failed and skipped counts, sorted offender check names and the result of each layer. `release_sha` and `github_actor` are kept only on `release_override` and `local_prerelease` records.
  - the trimmed reason, cut at 500 characters
  - uncalibrated cells that match both the contract pattern and the 0960 column check
- Check store under `eval/out/config-gate/<uuid>.json`:
  - Writes go to a temporary file in the same directory, then a rename, with mode 0600.
  - A missing file, non-JSON, a non-uuid id, a `check_id` that differs from the file name, or a shape failure reads as `null`. The app wrapper also applies `ConfigGateCheckSchema`.
  - `cachedCheck` returns a `done` check of the same hash, finished within the last 30 minutes. It ignores error results and finish times later than now.
- `insertChangeRecord` and `listChangeRecords` never throw; they return `{ ok: false, reason }`. The list selects named columns only. The wrapper drops rows that fail `ConfigChangeRecordSchema`.
- The route:
  - `GET ?since=<date or timestamp>&limit=<1..500, default 200>` is admin only and returns `{ records, counts: { by_source, by_result } }`, with each override reason cut at 200 characters.
  - `POST` takes a `.strict()` body. Accepted sources are `release_override`, `local_prerelease` and `cli`. A release override must carry a reason, and release fields are refused on `cli`. The actor is the admin's user id. Without hashes in the body, both hashes are the `rag_settings_hash` of the deployment's own environment. The route answers 201 `{ record_id }`, or 503 `rag_gate_record_failed` when the insert fails.
  - Logs carry the `[Config Gate]` prefix with the record id and source only.

## Decisions Made

- **Mode normalisation:** the value is trimmed and lower-cased. Empty or missing means `off`; `warn` and `enforce` mean themselves; any other value fails closed as `enforce`. In the fixture, an unknown mode refuses and ` ENFORCE ` enforces.
- **Override in `warn`:** a reason outside the bounds is dropped (stored as `null`) and the save still goes through, because `warn` never refuses.
- **`cachedCheck` does not cache `error` results.** A timeout or crash can be retried at once.
- **Route defaults:** without hashes in the POST body, `before_hash` and `after_hash` both take the deployment's current `rag_settings_hash`. A release override then records the settings the release ran with. A caller that knows both hashes, such as the CLI's `record-change`, passes them.
- **POST answers 201** for a created record.

## Deviations from Plan

1. **Extra file `gate-core.d.cts`.** It follows the `settings-hash.d.cts` precedent, so the TypeScript wrapper gets types from the CommonJS module.
2. **Extra exports.** `normaliseMode` (exported from `@/lib/rag` as `normaliseGateMode`) and the optional `names` input on `decideSave` and `buildChangeRecord`. In the CommonJS module `names` defaults to the generated list; the wrapper defaults it to `RAG_AFFECTING_NAMES`.
3. **`decideSave` is async**, so the reader may be sync or async.
4. **Bug found during GREEN:** the first `since` validator threw on `2026-13-45`, because chained zod refinements kept running after the date had already failed. The RED route test caught it ("RangeError: Invalid time value"), and I fixed it before the GREEN commit by using a single validator.
5. **No migration was created.** 0960 already existed from 05.3-07.
6. **No `.env.local` writer.** This plan adds no code that writes `.env.local`; that stays with 05.3-23 and 05.3-51.

Purge hooks: none added. No new store was created; `rag_config_change_records` is deployment-wide and belongs to 05.3-07.
