# Phase 5.3 Plan 41: Shared gates-ui helpers, page attention banner and Judge calibration panel

One shared vocabulary for verdicts, evidence, errors and loading states; a page banner for open alerts and refusal thresholds that stopped applying; a read-only Judge calibration panel.

## Accomplishments

- `gates-ui.js` (loaded right after `rag-fetch.js`): `GATES_UI_LABELS` with every UI-SPEC 12.2 key plus the banner keys in en, zh and it (identical key sets, counts written as "label: number"); the verdict line maps every server value onto the closed list, only `pass`, `passed` and `success` are `badge-success`, and an unknown or missing value is "No result" with a reason sentence (an unknown code is shown in `code` inside "Reason code: …"); the evidence table puts failed and no-result rows first and the rest under "Show all checks: {count}", and a check without a limit reads "no limit, report only"; rates read `38.0% (76 of 200)`, scores two decimals, dates `dateStyle: medium`, all through `Intl`; sub-tabs with a roving tabindex (Left, Right, Home, End); a native confirmation dialog with default focus on the Keep button, Escape and backdrop cancel and focus return; `gatesUiMapError` maps 401/403 to the shared sign-in message with the app address, 404 with the saved switch on to `error.switchedOffApp`, 500/503 to `error.unavailable` with the view name, thrown or timed-out requests to the shared network message; `gatesUiFetch` wraps the fetcher in try with a 15-second timeout.
- Banner: `#rag-attention-banner` is the first child of `div.p-6`. `gatesUiMountBanner(config)` runs from `loadConfig()` and after a successful save with the saved configuration; it requests `monitor/alerts?status=open&limit=1` only with `RAG_MONITOR=true` and `refusal-calibration` only when `RAG_CONFIG_GATE` is not `off` or `RAG_MONITOR=true`. Rows: "Open monitoring alerts: N" with Review alerts (activates RAG administration, clicks `[data-monitor-tab="alerts"]` when the Monitoring panel exists, scrolls, focuses its `h3`) and "Refusal thresholds not applied after a setting change: N" (cells whose `pending.reason` is not `score_shift`) with Open refusal calibration. `alert-error` when a returned open alert has severity `alert`, else `alert-warning`; no alert role, no animation, neutral `btn btn-sm`. A failed request leaves its row out silently; no row above 0 means no banner element. Refreshes on page load, each RAG administration tab click, and `window.gatesUiRefreshBanner()`; nothing polls.
- Judge calibration panel: one GET of `/api/rag/admin/judge-calibration`, one Refresh status button, one legend `details`, no input controls. Floors line from the route's floors (omitted when the route sends none), warnings (`none_enforced` info, `calibration_invalid` error, `expired_cells` and `judge_changed` warning, unknown codes as the route message with `lang="en"`), one table per role headed by `Judge version: <first 8 chars>` with the full fingerprint in `title` only, Status as the anchor with reasons as sentences under the badge, kappa/accuracy/length bias/probes flagged only when the route names `kappa_below_floor`, `accuracy_below_floor`, `length_bias` or `perturbation`, holistic note, empty state with the command. Columns hide below 1024px (into "Show all measures") and Checked below 768px (as a line under the status). Bound to every `[data-tab="rag-administration"]` link; idempotent init.
- With `RAG_MONITOR=false` and `RAG_CONFIG_GATE=off` the page makes none of this plan's banner requests and shows no banner (the judge panel has no switch and loads only when its tab opens, per UI-SPEC 6.1).

## Deviations

- Banner strings live in `GATES_UI_LABELS` (`banner.title`, `banner.alerts`, `banner.alertsAction`, `banner.uncal`, plus `banner.uncalAction`) instead of `MONITOR_LABELS`, because the banner is in `gates-ui.js` and `monitor.js` does not exist yet. Plan 05.3-44 can reuse them.
- Added `reason.missing` to `GATES_UI_LABELS` (en, zh, it): the sentence a Skipped or No result verdict carries when the server sent no reason, so those verdicts never stand without a reason.
- Added `table.caption` to `JUDGE_CAL_LABELS` for the visually hidden table caption and region label (UI-SPEC 9.12).
- Route reason codes are mapped to the UI-SPEC keys: `n_below_minimum` → `reason.too_few_labels`, `labels_not_confirmed` → `reason.labels_unconfirmed`; `kappa_undefined` and anything else read "Reason code: {code}.".
- Judge rows keep the route's order (the route sorts by the language registry, which is zh, en, it), instead of a browser-side sort with hard-coded codes that `check-language-literals` refused.
- The judge library (`deepeval`, `ragas`) is shown as a 12px mono line under the measure only when two cells of one role share language and measure, so the rows stay distinguishable; it is not shown otherwise.
- Responsive classes `max-lg:hidden` / `max-md:hidden` instead of the UI-SPEC's `hidden lg:table-cell` (see the pattern note). The existing Refusal calibration panel has the same latent problem (its `hidden lg:table-cell` columns never show); not changed here, reported below.
- The banner's `alert-error` decision sees only the alerts the `limit=1` request returns; the alerts route has no per-severity count. A severe alert behind a newer warn alert shows `alert-warning` until a route field exists.
- `gatesUiMountBanner` also runs after a successful save with the newly saved configuration, so a banner turned on or off by a saved switch follows without a reload.
- Banner refresh after Acknowledge, Resolve, Run monitor now and a Refusal calibration refresh is available through `window.gatesUiRefreshBanner()`; the calls belong to the Monitoring panel (05.3-44) and to `refusal-calibration.js`, which this plan does not edit.
