# Phase 5.3 Plan 05: false_answer_rate, answer-aware refusal and the absolute gate Summary

**The eval report now has a false-answer rate and refusal scoring that checks the answer text. A new `rag_eval.absolute_gate` checks the fixed ceilings, the judge floors, the test-set composition and the stale share from one report, with no baseline. It exits 11 or 12 even when the noise-band gate passes.**

## Performance

- Tasks: 2 of 2, TDD (RED commit, then GREEN), 5 commits
- Diff: 10 files, +1274 / -10

## Accomplishments

- `false_answer_rate` is on every slice. It uses the same population as `correct_refusal_rate` and is not in `noise.json`.
- Answer-aware refusal (O-1): an answer that, after normalisation, exactly equals a known refusal text of the item's language counts as a refusal. A refusal sentence inside a longer answer does not count.
- The gate population drops paraphrased items (D-53) and every item whose lifecycle status is not `active` (D-49). It returns the counts the runner needs (plan 05.3-13).
- `absolute_gate.evaluate` covers:
  - ceilings by `rag_mode` (D-05, D-07);
  - no-answer share per language and pooled (D-08);
  - stale share (D-49);
  - nightly judge floors gated by calibration (D-09, D-30).

  Every check keeps `passed`, `failed`, `insufficient_n`, `report_only` and `skipped` as separate results. In report mode the failures are still listed, but the exit code is 0.
