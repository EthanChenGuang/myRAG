# Phase 5.3 Plan 45: Test set coverage sub-view

Admins can now see in the Config UI how well each workspace's test set matches its real questions. The view shows the weekly difference with the server's state and the route's limits, and an eight-week trend. It shows up to 40 topic groups plus "Not in any group", each with both shares and neutral bars on one scale. When the report includes them, it also shows the weighted scores, the offline and online gaps, and the votes and refusals. It follows `#workspace-selector`, and its only action is Refresh coverage.

## Accomplishments

- `monitorCoverageView(report, locale)` is a pure builder over the drift route's named fields only. It shows the divergence to two decimals, and the badge comes from the server's `state`; an unknown state gets no badge. The limits line uses the route's `limits`. The trend always has 8 rows, newest first: the reported week is the current row, and earlier weeks are computed as ISO weeks, which handles year boundaries and 53-week years. A missing week shows an em dash with the hidden text `cov.noWeek`. Groups are sorted by real-question share, with `novel` among them as "Not in any group"; the view keeps at most 40 plus the bucket. Both bar columns divide by the single largest share in the table. Scores, gaps and rates are `null` (left out) when the route doesn't send them.
- The sub-view replaces the 05.3-44 `window.initMonitorCoverage` hook with `MonitorPanel.loadCoverage()`. It renders the workspace line, Week of {date} and Refresh coverage, then:
  - the Difference section (value, badge, limits, 8-week table);
  - Topic groups (ids in `code.font-mono` with `break-all`, share cells with `gatesUiShareBar`, hidden below 768px);
  - the scores `dl`;
  - Offline and online scores (verdicts: Above the limit, Not enough data, Within limits);
  - Votes and refusals (numbers only, no state column).

  Every table has an `sr-only` caption and sits in a focusable `role="region"` scroll container. A refresh keeps the content in place, dimmed and `aria-busy`.
- With Weekly sampling (`RAG_REPRESENTATIVE_SAMPLE`) off, nothing is requested and the view shows an off state without numbers. A 404 while the saved switch is on shows `error.switchedOffApp`, like the other panels.
- Changing `#workspace-selector` drops the shown report. The view reloads at once if Test set coverage is open, otherwise the next time it opens.

## Decisions

- **Gap verdict `passed`** is worded `cov.state.ok` ("Within limits", `badge-ghost`). The UI-SPEC wording covers only `fail` and `insufficient_sample`, and green is reserved for the Passed verdict of a setting check (UI-SPEC 13).
- **Votes and refusals columns.** The producer (`eval/src/rag_eval/drift.py`) sends `refusal_rate` and `not_helpful_rate` per slice. Its only offline value is the refusal rate of the test items. That value appears in a new column `cov.col.offlineRefusal` "Refusals (offline)" (zh 拒答（离线）, it Rifiuti (offline)). The spec's False and Correct refusals (offline) columns appear only when the route sends `false_refusal_rate` or `correct_refusal_rate`. A column appears only when at least one row has a value for it.
- **Counts** are written `{value} (n = {n})` (`cov.withN`) for the online judge mean and the online rates.
- **Off state** strings `cov.off.title` / `cov.off.body` point to Weekly sampling under Question sources › Settings. They contain no counts and no digits (UI-SPEC 11 rule 14).
- **Status line** after a load: `cov.loaded` "Test set coverage loaded: {week}." in the panel's `aria-live` status region.
- **Drift command** in the empty state: `python -m rag_eval.drift --tenant <key> --set <private set directory>` (the CLI's two required arguments).
- **All four tables scroll inside focusable regions,** including the 3-column trend table, for consistency.

## Deviations from Plan

- **The 05.3-44 `window.initMonitorCoverage(panel)` hook is gone.** `refresh()` now calls `this.loadCoverage()` directly. Nothing else referenced the hook (`git grep initMonitorCoverage` is empty), and keeping the view inside `MonitorPanel` reuses its config, fetcher, status and error mapping.
- Five strings beyond the UI-SPEC 12.4 table were added (see Decisions), in en, zh and it.
- `gatesUiSliceText` is not exported by gates-ui.js, so `monitorSliceText` formats slices locally with the exported `gatesUiLabel` and `gatesUiLanguageName`. gates-ui.js was not edited.
