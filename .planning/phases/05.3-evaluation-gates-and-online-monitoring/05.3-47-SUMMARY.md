# Phase 5.3 Plan 47: Review queue answer check, tags and source summary

**Experts now see where each review item came from (weekly sample, re-review, pilot user, imported question, under-covered topic group) and record a three-question answer check with no default and no judge score; the strata source is read per tenant only for items the expert can already see.**

## Accomplishments

- `source` on `GET /api/rag/review/items` and `GET /api/rag/review/items/[id]`, read from `rag_review_item_strata` with the admin client for exactly the item ids the expert's RLS read returned, filtered by that item's `tenant_key` in SQL and again in code (D-41, D-55, research X-9).

## Deviations from Plan

### Auto-fixed

**1. [Rule 2, missing critical] ReviewItem contract rejected Phase 5.3 items**
- **Found during:** Task 1
- **Issue:** `ReviewItemSchema` required `trace_id` and `channel` and allowed only the 7 mined reasons, while 0967 writes items with neither and with `representative` / `re_review`. `toReviewItem` drops rows that fail the contract, so every sampled or imported item vanished from the queue.
- **Fix:** widened `ReviewItem` in `feedback_loop.py` (new `ReviewItemReason`, `ReviewItemSource`), regenerated with `npm run gen:schemas`; pinned `GoldenExportLineSchema` channel and reasons to the 5.1.1 shape so the Python twin `_GoldenExportLine` still matches.
- **Commit:** `e6814c05`

**2. Key name `item.noAnswerImported`**
- UI-SPEC 12.7 calls the imported no-answer text `item.noAnswer`, but that key already holds the 5.1.1 text for mined items whose answer is not kept. Overwriting it would change 5.1.1 behaviour, so the new text has its own key.

**3. Route-level two-tenant test**
- Added one case to `tests/api/review-items-two-tenant.test.ts` (not in the plan's file list) for D-55's route-level two-tenant coverage of the source read and filter.
