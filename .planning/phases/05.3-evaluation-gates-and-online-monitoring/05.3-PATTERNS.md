## Pattern Assignments

### 1. New contract modules (model, transform)

**Analog:** `rag-sidecar/src/rag_sidecar/contracts/baseline.py` (result contracts) and `contracts/retrieval.py` (config file with cells and provenance).

**Base class and imports** — every contract module declares its own `_Contract`; copy it, do not import it across modules:
```python
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field


class _Contract(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
```

**Result contract shape** (`GateOffender`, `GateResult` in `baseline.py`) — the model for `AbsoluteGateResult`, `CompositionResult`, `ReleaseGateResult`, `ConfigGateCheck`:
```python
class GateOffender(_Contract):
    slice: str
    metric: str
    baseline_mean: float
    threshold: float
    observed: float
    direction: Literal["higher", "lower"]


class GateResult(_Contract):
    passed: bool
    offenders: list[GateOffender]
    skipped: list[str]
    mismatches: list[str]
    paired: PairedReport | None = None
```
`skipped` is already its own list here and is never folded into `passed`; CONTEXT "specifics" requires the same in every new result contract.

**Committed config file with cells** (`RefusalCell`, `RefusalThresholds` in `retrieval.py`) — the model for `JudgeCalibration` / `JudgeCalibrationCell` and for `QualityGates`:
```python
class RefusalThresholds(_Contract):
    schema_version: Literal[1] = 1
    cells: list[RefusalCell] = Field(default_factory=list)
    provenance: ConfigProvenance = Field(default_factory=lambda: ConfigProvenance(source="defaults"))
    config_hash: str | None = Field(default=None, pattern=r"^[a-f0-9]{64}$")

    @model_validator(mode="after")
    def _unique_keys(self) -> "RefusalThresholds":
        keys = [cell.key for cell in self.cells]
        if len(keys) != len(set(keys)):
            raise ValueError("duplicate refusal cell keys")
```
`RefusalCell._key_matches_dims` (the key must equal its dimension fields joined by `|`) and `_calibrated_needs_threshold` are the precedent for the D-09 validator "a `holistic` metric can never carry a floor" and for a `JudgeCalibrationCell` key of `fingerprint|role|language|library.metric`.

**Provenance and hash** (`retrieval.py`): `ConfigProvenanceSource = Literal["defaults", "sweep", "calibration", "fixture", "live"]`, `compute_config_hash(model, exclude={"provenance", "config_hash"})` with `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=False)`. H-8 moves `provenance.source` from `defaults` to `live`.

**Additive Literal values** (D-03) go in `contracts/golden.py`: `Category`, `Provenance`, and note `UNANSWERABLE_CATEGORIES = frozenset({"no_answer", "small_talk"})` beside them. `ReviewReason` in `contracts/review.py` gains `representative` and `re_review` (append to whatever Literal trunk has after 5.1.1 plan 01).

**Optional additions only** (RESEARCH Pitfall 3): `SliceMetrics` and `EvalReport` are `extra="forbid"` and validated against every committed baseline, report sample and `tests/fixtures/contracts/samples.json`; new fields (`false_answer_rate`, `rag_mode`, `golden_set_version`, `golden_manifest_sha256`, `stale_count`, `stale_share`) need defaults.

**Registration** — three places, in the same plan, never in parallel with another contract plan:
1. `contracts/__init__.py`: import block per module plus the `__all__` list.
2. `contracts/samples.py`: one private builder per model (`_baseline()`, `_judge_report()`, `_eval_report()` are the pattern) feeding `build_samples()`.
3. `rag_sidecar/export_schemas.py`: the `CONTRACTS` registry; `export_all` writes `rag-sidecar/schemas/` and `tests/fixtures/contracts/samples.json`.
Then `npm run gen:schemas` (`scripts/gen-zod.mjs`) regenerates `src/lib/rag-eval/contracts.generated.ts`. No hand-written Zod twin (D-01).

**Test analog:** `rag-sidecar/tests/test_review_contract.py` (imports `build_samples`, `CONTRACTS`, `SCHEMAS_DIR`; a `_item(**overrides)` factory; `pytest.raises(ValidationError)` cases), and `rag-sidecar/tests/test_retrieval_contracts.py` for cell validators.

**Pure evaluation, then I/O in `_main`** — `evaluate_gate(report, baseline, noise) -> GateResult` has no I/O; `_main` reads with `Model.model_validate_json(_read(resolve_cli_path(args.x)))`, writes `gate.json` and `gate.md` through `_write_text` (tmp file + `replace`), prints to stderr, returns the code. `absolute_gate.evaluate(...)` follows the same split (RESEARCH Pattern 1).

**Mismatch list** (`_mismatches`): a tuple of `(name, observed, recorded)` checks ending with the hint `"re-record the baseline: npm run eval:baseline"`. `rag_mode` (RESEARCH F-2) and the D-47 version rule are added here; note that today the `golden_sha256` check makes any golden change a mismatch, so D-47 needs the comparison moved to per-item hashes from the manifest.

**Crash must not look like a regression:**
```python
def main(argv: list[str] | None = None) -> int:
    try:
        return _main(argv)
    except SystemExit:
        raise
    except Exception as exc:  # noqa: BLE001 - any crash must not look like a regression
        print(f"gate: INTERNAL ERROR {type(exc).__name__}: {exc}", file=sys.stderr)
        return EXIT_INTERNAL
```

**Markdown** (`render_gate_markdown`): `# Eval gate`, a `Result:` line with the exit code, then `##` sections each ending in `None.` when empty. The `absolute` section is one more block of the same form.

**Metric source** (`eval/src/rag_eval/metrics.py`, `_slice`): `false_answer_rate` is computed from the same `unanswerable` list as `correct_refusal_rate`:
```python

false_refusal_rate=_mean([1.0 if r.refused else 0.0 for r in answerable]),
false_refusal_upper_95=upper_bound(sum(1 for r in answerable if r.refused), len(answerable)),
```

**Caller** (`eval/harness/run-smoke.mts`, `main`): the gate is spawned with `runPython('rag_eval.gate', ['--report', ..., '--baseline', baselinePath, '--noise', NOISE_PATH, '--out', outDir])` and its code is returned unchanged; add `--gates` beside `NOISE_PATH`.

**Test analog:** `eval/tests/test_gate.py` (`_slice_values`, `_report(**fields)`, `_stat`, `_baseline(**fields)` builders that validate through the contracts; imports `EXIT_INTERNAL, EXIT_REGRESSION, evaluate_gate, main`). 2. **`SECURITY DEFINER` in D-55.** D-55 says every new SQL function is `SECURITY DEFINER`. An invoker function needs no 0410 entry. Either follow D-55 literally (every function in 0410) or follow the newer convention and say so in the plan.
3. **`tenant_key` on new tables.** D-55 names "the 0502 pattern per mode". 0502's generated column only works for a table with `organization_id` and `user_id`.
