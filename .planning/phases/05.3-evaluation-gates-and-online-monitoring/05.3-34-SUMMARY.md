# Phase 05.3 Plan 34: Representativeness, weighted scores and weekly drift Summary

**Real test sets now carry production cluster strata, real-set reports show a report-only production-weighted recall@5 next to the gated score, and `python -m rag_eval.drift` writes and posts the weekly drift report with a permutation-null noise guard.**

## Deviations

- production-shares.json is written beside the set rather than under reports/ (Task 2 reads it beside the set; Task 3 named the reports directory). The DriftReport file is `drift-<tenant_hash>-<week>.json` instead of `drift-<week>.json`, so two tenants never overwrite each other.
- `assign(set_dir, ...)` also takes an optional `manifest_path`; `build_drift_report` takes keyword-only extras (`week`, `eval_report`, `tolerance`, `gap_min_sample`, `drift_min_sample`, `tenant_key`) after the six planned arguments.
- `--inputs` (a saved drift-inputs JSON) was added so the no-credentials path can still write the private report; without it the tool writes nothing and exits 0 with a notice.
- The insufficient-items reason is printed by the CLI and returned by `state_and_reason`; the DriftReport contract has no reason field and was not changed.

Not run here (no live app, no private data).
