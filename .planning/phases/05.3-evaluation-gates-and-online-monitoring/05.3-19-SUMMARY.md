# Phase 5.3 Plan 19: Answer check, judge calibration status and export routes Summary

**Domain experts record supported, relevant and unsupported-content verdicts under RLS; admins read which judges count and the calibration tool pulls one tenant's labelled cases with text re-read under that tenant.**

## Performance

- **Duration:** about 55 min
- **Completed:** 2026-11-26
- **Tasks:** 2
- **Files modified:** 11

## Accomplishments

- `GET|POST /api/rag/review/items/{id}/answer-check`: strict Zod body (`zod/v3`), `Cache-Control: no-store`, fields `supported`, `relevant`, `unsupported_content`, `labelled_at`. Labels are read and written with the caller's session client, so `rag_judge_labels` RLS decides; the tenant comes from the visible item row. The update path writes only the columns 0965 grants; a concurrent first save falls back from the unique violation to the update. No judge score is read, accepted or returned.
- `GET /api/rag/admin/judge-calibration` (`requireAdminOrDeny`): `{ success, floors, running, cells, warnings }`. A cell is `uncalibrated` when older than `max_age_days` (reason `expired`) or when its fingerprint differs from the running judge of its role (reason `fingerprint_mismatch`); warnings `none_enforced`, `calibration_invalid`, `expired_cells`, `judge_changed`. Rows ordered by role, then the language registry order.
- `GET /api/rag/admin/judge-calibration/export?tenant=` (`checkAdmin`, Bearer or session): validates the tenant key for the deployment mode, then requires it in `rag_admin_tenant_keys(actor)`. Returns `{ success, tenant_key, cases[], skipped { no_answer, changed_chunk, no_context } }`; each case has `item_id`, `language`, `question`, `answer`, `contexts[] { chunk_id, document_id, text }` and `labels[] { supported, relevant, unsupported_content, labelled_at }`. Text passes through `maskPII`; contexts are the kept snapshot candidates read through `fetchServableChunks` (current, ready, not quarantined, same tenant). Logs carry a tenant hash and counts only.

## Deviations from Plan

1. **Imports through `@/lib/rag`, not by module path.** The plan says routes import `@/lib/rag/judge/<module>` directly, but `scripts/ci/check-rag-boundary.mjs` rejects deep imports from app routes. The modules are exported from `src/lib/rag/index.ts` instead (`7687b3ce`).
2. **Language order from the registry.** The first version sorted rows by a literal `zh, en, it`; `check-language-literals` rejected it, so the order now comes from `getLanguageRegistry()` (`7687b3ce`).
3. **Extra skip counter `no_context`** for a labelled item without a kept candidate (none in the plan's two counters fits it). An item without a masked question counts as `no_answer`.
4. **"Changed chunk"** is detected as a kept chunk that is no longer servable or moved document (chunks are immutable per version; re-ingestion writes new rows). The snapshot carries no content hash to compare against.
5. **Test helper extended** (`insert`, `rpc`) so the label writes and `rag_admin_tenant_keys` run against real RLS in PGlite.
6. Plan verify names `npm run typecheck:new`; the full `tsc` gate from the brief was run too.

No migration was created (the plan needs none; 0965 comes from 05.3-09).
