# Phase 5.3 Plan 42: Pre-save setting check dialog and save guard

## Accomplishments

- **One guard for three save paths.** `window.ragSettingCheck.beforeSave(request)` fronts `configManager.saveConfig()` (after the Phase 3.2 guard, which on this branch is `window.ragIngestImpactGuard`, not `window.ragBeforeConfigSave`), the global `saveRagPrompt()` and `saveModelConfiguration()`. The mode is read from `configManager.savedConfig` (last loaded or saved), never from the unsaved select.
- **Mode off is byte-identical.** With `RAG_CONFIG_GATE` off or unset the guard resolves `{ proceed: true }` with no request, and each caller posts exactly today's body (`JSON.stringify({ config: this.config })`, `{ preContext, postContext }`, `JSON.stringify(modelConfig)`); `ragGate` is added only with a decision. Tested on the real request (URL, method, headers, body string).
- **Held is not failed.** `proceed: false` posts nothing, shows no error toast, and the header indicators show `indicator.held` with `alert-warning` for 3 seconds; Edit settings or Escape also shows the `outcome.held` toast. `saveRagPrompt` returns `'held'`; `saveConfig` treats a held prompt after a saved config as held; the template chooser's retry loop breaks on `'held'` and its 10-second timeout does not fire while the dialog is open.
- **409 `rag_gate_required` without a dialog** hands the same request to `required(request)` once (no "Failed to save" toast); with the guard script missing the save posts as today and a 409 shows `error.required`.
- **The dialog** (`dialog#rag-setting-check.modal`, no backdrop close, `modal-box w-11/12 max-w-2xl`): changed settings by label and env name (never a value), the three layers always (a missing layer reads Skipped `no_answer`), the merged evidence table with failed rows first and the layer as a second line, not-covered line, untested and threshold notices, reason field (10–500 trimmed characters, sent once, cleared after saving, never echoed), mode note, polite status region. Waiting: indeterminate progress, running layer, `m:ss` elapsed (`aria-hidden`, announced once a minute); polls every 2 s for 30 s then every 5 s; No result after 630 s or three failed polls; cached results open with `checking.cached`; 409 busy opens Busy with the start time; Run check again sends `force: true`. Saving disables every control, shows a spinner and `Saving…`, and ignores Escape. Saved shows the outcome sentence with the record id; Not saved shows `error.changed`, `error.recordFailed` (reason kept) or `error.saveFailed` with the status.
- Requests to the config server use `fetch` with `credentials: 'same-origin'` and `x-config-ui: 1`, a 15-second client timeout per call.
- Section skeleton `#rag-administration-setting-checks` after Judge calibration and the extended RAG administration intro ("…, identifier patterns, check settings before they apply, and follow monitoring alerts, …").

## Deviations

- **Phase 3.2 guard name.** The plan and UI-SPEC name `window.ragBeforeConfigSave`; this branch's Phase 3.2 guard is `window.ragIngestImpactGuard` (already awaited first in `saveConfig`). The setting check runs after it with the values it leaves, as the contract orders.
- **Script tag position.** `setting-check.js` loads after `judge-calibration.js` (still after `gates-ui.js`), because `tests/ui/judge-calibration-panel.test.ts` pins judge-calibration.js directly after gates-ui.js.
- **`saveFailed` returns a promise of the next decision** and a page helper `ragGuardedSave(request, post)` runs the post/retry loop, so a refused save can be retried from the dialog (same save button, Run check again) without the dialog posting. `isOpen()` was added to the guard API for the callers and the template timeout.
- **Existing tests updated:** `config-ingest-impact-panel.test.ts` loads the new page helpers into its `saveConfig` harness; `config-languages-panel.test.ts` pins the new intro sentence the plan asked for.
- **Status region visually hidden** (`sr-only`) inside the dialog: every message it announces is already visible elsewhere in the dialog (Impeccable polish).
- **Reason too-short line** appears from the first keystroke as well as on blur, so the count of missing characters updates while typing.
