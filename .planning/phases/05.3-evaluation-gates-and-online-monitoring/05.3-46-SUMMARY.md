# Phase 5.3 Plan 46: Question sources panel

The three non-failure sources of the review queue (weekly sample, pilot users, imported historical questions) are now manageable per workspace from the Config UI, with counts, dates, masked e-mails and ids as the only content shown.

## Accomplishments

- **Panel chrome.** `#rag-administration-question-sources` follows the Feedback loop card. Sub-tabs Weekly sample (default), Pilot users, Import questions, Settings, built with `gatesUiSubTabs` (roving tabindex). The panel follows `#workspace-selector`: it shows "Workspace: {name}" and reloads the selected view on `change`. `lang` is set on the root. Init is idempotent, bound to every `[data-tab="rag-administration"]` link, and runs on `DOMContentLoaded` when the tab is already active.
- **Weekly sample.** With `RAG_REPRESENTATIVE_SAMPLE` off (saved configuration first, page input second) it renders `sample.off.*` and makes no request. With a missing prerequisite it renders `sample.needs.log` / `sample.needs.review`, naming `RAG_RETRIEVAL_LOG` / `RAG_DOMAIN_EXPERT_REVIEW` in `code`, and leaves out Run sample now. Before the first run it renders `sample.empty.*`. Otherwise a list of "label: number" items (last sample as `<time>`, questions added as the anchor, the three sources, topic groups with refit date, questions not in any group) and a by-language table. Run sample now disables itself with a spinner and `run.running`; the status region then says `run.done` with the run's `added`, or `run.failed`. A 404 while the switch is saved on shows `error.switchedOffApp`; 401/403 shows the sign-in alert in the view, and Settings stays usable.
- **Pilot users.** One labelled field (`name="pilot-user"`, `autocomplete="off"`, `spellcheck="false"`) and Add pilot user in a `form` (Enter submits). An empty field shows `pilot.empty.field` and keeps focus. 404 `user_not_found` and 409 `already_pilot` show `pilot.notFound` / `pilot.exists` at the field in `text-error` with `aria-invalid`. 201 clears the field, reloads the list, says `pilot.added` and returns focus. The list shows the masked e-mail (or the user id in `code`), the date added, and Remove pilot user with `action.removeAria`. Removal is confirmed through `gatesUiConfirm` (default focus Keep pilot user); on 200 the row leaves and focus moves to the next row's button or the field; a 404 says `pilot.gone` and reloads. Pages of 50, then Load more pilot users. `pilot.explain` states the weight and cap only when the route sends them.
- **Import questions.** Native file input (`accept=".csv,.jsonl,text/csv,application/x-ndjson"`). The file is read once in the browser with `File.text()`. Files over 10 MB or 20,000 rows show `import.tooLarge` before anything is sent; an unclosed CSV quote or a malformed JSON line shows `import.badFormat` with its line number (never the row); a first line without columns shows `import.noColumn`. The column select (disabled until a file is read) is filled from the CSV header cells or the first JSON line's keys with `textContent`. Check file sends every batch with `dry_run: true`, at most 60 KB of JSON and 2,000 rows each, 60-second timeout per batch, with a determinate `<progress>` and the controls disabled. Import questions is rendered only after a check of the same file and column that would add at least one question; otherwise `import.nothingNew`. One primary button is on screen at a time. A failed batch stops the run and shows the sums so far with `import.interrupted` (400 adds `import.badFormat`, 413 `import.tooLarge`, other errors the mapped message). With expert review off the form is replaced by `import.needs.review`. Nothing from the file is rendered, logged or written to web storage.
- **Settings.** The `sample` group moves once from `#rag-phase053-settings` into the Settings view, localized through `data-rag-i18n`, and keeps its save hint. `warn.sampleNeedsLog` / `warn.sampleNeedsReview` are recomputed on `change` of `RAG_REPRESENTATIVE_SAMPLE`, `RAG_RETRIEVAL_LOG` and `RAG_DOMAIN_EXPERT_REVIEW`.

## Deviations

- **Label keys beyond UI-SPEC 12.6:** `count.item` ("{label}: {value}", so zh uses the full-width colon), `sample.clusters.noDate` (no refit date yet), `sample.col.added`, `pilot.col.actions`, `pilot.shown` (load-finished announcement), `import.counts.caption` and `import.col.count` (table caption and header). Same keys in en, zh and it.
- **Error placement:** a data view's error alert sits inside that view (not in the panel-level alert host), so a 401 on one view never hides the Settings sub-view (UI-SPEC 6.12 "Settings sub-views stay usable when the panel's data calls answer 401 or 403").
- **400 from the import route:** `import.badFormat` names the first file line of the failed batch, because the route does not say which row it rejected.
- **Client question cap:** a question longer than 8,000 characters is cut in the browser so one row always fits a 60 KB batch. The server still shortens to 2,000 after masking and counts it as shortened.
- **config-rag-panel-binding test:** the "binds each link once" test now compares the listener count before and after a second `DOMContentLoaded`, because `gates-ui.js` (a dependency loaded for this panel) binds its own banner-refresh click on the same link.
