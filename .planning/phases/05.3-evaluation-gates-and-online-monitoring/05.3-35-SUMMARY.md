# Phase 5.3 Plan 35: Real-set golden evidence, stale scan and re-review Summary

**Real golden sets can now be registered against the tenant's documents, scanned for stale evidence using the 0969 trigger flags, and sent for re-review on a 90-day cycle, through three admin routes that return only codes, ids and counts.**

## Accomplishments

- `golden-evidence.ts`: `normalizeQuote` (NFKC, `toLowerCase` plus the full case foldings `toLowerCase` misses, whitespace including U+001C to U+001F and NEL, Unicode punctuation), `checkEvidence` (per-name document lookup under the tenant, chunk text read with the current and ready filter, compared in memory), `registerEvidence`, `pendingEvidence`, `clearEvidence` (0969), `enqueueReReview` (0974) and `weekStart`.
- Routes `evidence-check` (at most 500 spans, quotes up to 4000 characters, names up to 500), `register` (GET pending, POST rows, POST `action: clear`), `re-review` (at most 100 items). All answer `Cache-Control: no-store` and log `[Monitor]` with counts only.
- `golden_set.py`: the two "needs plan 05.3-35" exits are gone. `register`, `stale-scan --base-url` and the new `re-review` run on sets under `eval/golden/private/` only. `mark_stale` is shared by the fixture and the real scan.
- `tests/helpers/pglite-admin.ts`: `ilike()`, and RPC arguments of an array type (text[]) are bound as arrays, as PostgREST does. Before this they were sent as JSON, which `rag_golden_evidence_clear` rejected.

## Deviations from Plan

1. **[Files] Extra files.** `src/app/api/rag/admin/golden/_lib.ts` (shared guard), `eval/fixtures/normalize-text-vectors.json` (the shared vector the plan asks for when no twin exists), `src/lib/rag/index.ts` (public exports for the boundary check), `src/lib/rag/feedback-loop/retrieval-log.ts` (exports the 5.1.1 fingerprint instead of copying it), `tests/helpers/pglite-admin.ts` (ilike, array arguments), `eval/tests/test_golden_set.py` (the placeholder test now asserts that fixture sets are refused).
2. **[CLI] `--tenant` on stale-scan.** The plan's command line for `stale-scan --base-url` names no tenant; the routes need one, so `--tenant` is required with `--base-url` (and for `register` and `re-review`).
3. **[Output] re-review prints `overdue: N, queued: M, inserted: K`.** The plan names the first two; `inserted` tells a same-week repeat (0) from a first run.
4. **[Route] The register route takes `set_id`.** 0969 keys rows by set, so GET and both POST forms take `set_id`; Python sends the manifest's `set_id`.
5. **[Test helper] Array binding changes the PGlite admin helper for every array-typed RPC argument.** All tests importing it were rerun and pass.
6. No migration: this plan adds none, so no number was claimed.
