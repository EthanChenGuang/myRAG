# Phase 5.3 Plan 51: setting-check guard on the app's .env.local writers

The setting check is now enforced on the three app routes that write `.env.local`: the in-app settings save (`POST /api/config`), the RAG prompt save (`POST /api/config/rag-prompt`) and the model list save (`POST /api/config/models`). Together with the two config-server writers of plan 05.3-23, all five writers of research F-5 are covered (O-4).

## Accomplishments

- `guardAppEnvWrite({ updates, ragGate, actorUserId, route, root? })` runs after each route's own validation and before `writeEnvUpdates`:
  - **Mode `off`:** returns at once. It reads no check, writes no record and adds nothing to the response, so every route answers byte for byte as before.
  - **No RAG-affecting change:** the save is written without a check in every mode, for example a change to the app name only.
  - **`enforce`:** the save needs a stored `done` check whose `rag_settings_hash` equals the hash of the proposed values and whose result is `pass`, or an override reason. Without one the route answers 409 `{ success: false, error: 'rag_gate_required', message: RAG_GATE_REQUIRED_MESSAGE }`. The message tells the admin to run the check in the Config UI. A reason outside 10 to 500 characters answers 400 `invalid_reason`, and a malformed `ragGate` answers 400 `invalid_rag_gate`.
  - **`warn`:** always writes. A malformed `ragGate` counts as none.
  - **Records:** every written RAG-affecting change gets one `rag_config_change_records` row with source `config_ui`. The row holds the admin's user id as actor, the changed key names, the before and after hash, the gate result and summary, the reason and the check's uncalibrated cells. It never holds a value or prompt text, and a test asserts that the proposed prompt is absent from the row.
  - **Failures:** an override whose record cannot be written, or whose admin id cannot be resolved, answers 503 `rag_gate_record_failed` and writes nothing. Any internal failure in `enforce`, including a missing check store directory or an unreadable env file, answers 409, never 500. In `warn`, a failure lets the save through without a record.
- The current values come from `.env.local`, parsed the same way the writer and plan 05.3-22's check route parse them, so the hashes match. The mode is the stricter of the running process's `RAG_CONFIG_GATE` and the value in `.env.local`. `RAG_CONFIG_GATE` is not app-writable (`isWritableEnvName` is false), so the app cannot switch its own gate off.
- Before inserting a record, the guard tries the same `applyEnvUpdates` the writer will run. A save the writer would refuse leaves no record, and the route answers it through its existing 400 path.
- Logs use the `[Config Gate]` prefix with the route name, result and record id only.
- The models route now builds its updates once (`modelConfigUpdates`), so the guard and the writer see the same map.
- The writers test checks that the four names written by `updateEnvFile` (logo and favicon uploads) and by `custom-servers-store` are outside the generated RAG-affecting list: `NEXT_PUBLIC_HEADER_LOGO_URL`, `NEXT_PUBLIC_AI_RESPONSE_LOGO_URL`, `NEXT_PUBLIC_FAVICON_URL` and `MCP_CUSTOM_SERVERS`. A second test reads those three source files and asserts they write only these names. If the manifest makes one of them RAG-affecting, or a writer starts writing another name, the test fails.

## Deviations from Plan

1. **The admin id is resolved through a resolver.** The routes keep `requireAdminOrDeny` and pass `actorUserId: () => adminUserId(request)`, which calls `checkAdmin` only when a record is written.
   - Why: replacing `requireAdminOrDeny` with `checkAdmin` broke `tests/lib/misc-type-fixes.test.ts`, which mocks `@/lib/admin-route-auth` with `requireAdminOrDeny` only. The must-have says existing tests pass unchanged.
   - Cost: a guarded save in warn or enforce mode makes a second admin lookup.
   - `actorUserId` also accepts a plain string.
2. **The guard returns a status and body, not a `NextResponse`.** The routes import it from `@/lib/rag`, because `check-rag-boundary` refuses deep imports, and `@/lib/rag` should not import `next/server`.
3. **Additions beyond the plan:**
   - 400 `invalid_rag_gate` for a malformed `ragGate` in enforce mode
   - the export `RAG_GATE_INVALID_REASON_MESSAGE`
   - the stricter-of-two mode rule
   - the dry run of `applyEnvUpdates` before a record is inserted
4. **Responses in mode off are unchanged.** `ragGate` appears in a success response only when a record was written. In mode off, and for saves that change no RAG-affecting name, the response carries no `ragGate` key.
5. **A non-override save whose record fails behaves by mode.**
   - In `warn`, and in `enforce` with a passed check, the save is written and the failure is logged. D-16 refuses only overrides that cannot be recorded.
   - An unresolvable admin id in `enforce` without an override answers 409.

No migration was created, and no purge hook is needed, because no new store was added. No `.env.local` variable was added.
