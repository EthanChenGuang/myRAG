# Phase 5.3 Plan 52: DATA-24 purge hook for golden items Summary

**`rag_purge_hook_golden_items` removes the evidence rows and answer-check labels that come from a purged lineage, per tenant. Each affected golden item keeps a flagged tombstone, so it stays in the stale scan.**

## Accomplishments
- Migration 0976 adds `public.rag_purge_hook_golden_items(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint`. It is SECURITY INVOKER with `SET search_path = ''` and calls `rag_assert_tenant_key` first. Execute is revoked from PUBLIC, anon and authenticated and granted to service_role.
- For the tenant only, the hook deletes the evidence rows on the purged versions. Each affected item gets one tombstone (`00000000-0000-0000-0000-000000000000`, 64 zeros, needs_check true), and its remaining rows are flagged. Labels of review items whose kept candidate names a purged version are deleted. The hook returns the evidence rows plus labels removed.
- The labels step is skipped when `rag_judge_labels` or `rag_review_items` is missing, so the migration applies and runs without Phase 5.1.1.
- The guarded Phase 6.3 inventory block creates nothing when `rag_purge_store_inventory()` is absent, which is the case on trunk.
- The hook is listed in `PHASE53_SERVICE_ROLE_FUNCTIONS`. The phase test excludes the future re-created 6.3 inventory, and records why.
