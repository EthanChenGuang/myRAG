# Phase 5.3 Plan 27: Monitor evidence helpers and the daily run Summary

**Four tenant-guarded migrations (0972 to 0975) and `runDaily`, which aggregates the log, evaluates the rules per tenant, attaches ten sample trace ids and the configuration changes of each alert's window, and upserts one open alert per dedup key.**

## Accomplishments

- `0972 rag_monitor_alert_evidence`: sample trace ids (md5 order, at most 10, only ids in the alert table's form) of one tenant's rows in the window that match `p_match` (any listed condition: status, outcome, refusal_decision, refusal_reason, feedback_vote, zero_result, groundedness_flagged; `{}` matches all), language `all` drops the language filter; plus every retrieval config hash first seen by that tenant in the window or the two days before.
- `0973 rag_monitor_cluster_shares`: counts per cluster, language (und for null) and channel of the tenant's rows since a date, current cluster set only.
- `0974 rag_review_items_enqueue_re_review`: inserts `re_review` items with status open and no strata row; ON CONFLICT DO NOTHING on the 5.1.1 key; malformed payload 22023, writes nothing.
- `0975 rag_monitor_runs`: deployment-wide, counts only, RLS on with no policy, service role only.
- All three functions: SECURITY INVOKER, `SET search_path = ''`, `rag_assert_tenant_key` first, own REVOKE from PUBLIC, anon, authenticated and GRANT to service_role, `to_regclass` guards (empty result without the 5.1.1 tables or the 0966 cluster tables). Not folded into the setup files.
- `phase53-migrations.test.mts`: the file list was already derived from every 0960 to 0979 file; added the three functions (21 entries) and a not-folded name check that includes `rag_monitor_runs`.
- `runDaily(admin, { now, source, day?, env?, config?, registry?, budgets? })`: RAG_MONITOR off returns `switched_off` without touching the client; log off returns `log_off`; otherwise aggregates, reads cells of the window plus `baseline_days + 7` days (paged by 1000), runs `evaluateRules`, then each context-input rule, correlates every candidate with `windowConfigChanges`, upserts through `upsertAlerts`, runs `rag_monitor_purge(400)`, deletes run rows older than 400 days, records the run and logs `[Monitor]` counts and alert ids.

## Deviations from Plan

1. **[Contract] Profile activation source.** The plan's behaviour line says an embedding profile activation is listed with source `profile_activation`; the `MonitorAlert.config_changes` contract has `embedding_profile` and `chunking_profile` for activations read from their tables, so those are used. `profile_activation` stays the source of a change record written by an activation.
2. **[Contract mismatch] Bin layouts and companions.** 0971 writes 22 latency bins on edges 0 to 15 000 ms; the contract has 18 bins on edges 50 to 20 000 ms. `toDailyCell` maps each 0971 bin to the contract bin holding its upper edge (exact up to 5 s, coarser above). Contract `companions` is an array, 0963 requires an object: stored keyed by rule. `cluster_ids` has no 0963 column and is not stored.
3. **[Test helper] `tests/helpers/pglite-admin.ts`** gained `rpc()` (named arguments, scalar results unwrapped), `gte/gt/lte/lt` and `range()`. Additive; every test importing it was rerun.
4. **[Options] `runDaily` takes optional `day`, `env`, `config`, `registry` and `budgets`** so the tests can pin the rules and register a context rule for one run without mutating the shared registry.
5. Migration numbers 0972 to 0975 were free on every origin branch and were claimed with a stub commit pushed first.
