# Phase 5.3 Plan 02: Phase 5.3 switches and settings reader

Six D-57 switches, all off by default, in every config location; one call-time reader `monitorSettings()`; the hidden Config UI settings block.

## Accomplishments

- The six switches exist in `src/lib/env.ts`, the `scripts/init-env.js` template (new "EVALUATION GATES AND MONITORING" section), the new-file template and both rewrite templates of `scripts/config-server.js`, `scripts/config-ui/index.html`, `scripts/rag/env-manifest.json` (status `managed`, description each) and the regenerated `eval/config/rag-eval-env.json`.
- `RAG_MONITOR_WEBHOOK_SECRET` joins the below-32-characters warning in `POST /api/config` and in `saveConfig()`.
- Both names containing `WEBHOOK` are already secrets for `isSecretConfigEntry` (config server) and `isSecretEnvName` (app), so the URL and the secret are never returned by `GET /api/config`, an empty field on save means unchanged, and neither is writable through the in-app `/api/config` allowlist.
- `#rag-phase053-settings` (class `hidden`) after the Phase 3.2 block inside the RAG administration tab: groups `gate`, `monitor`, `sample`; ids and names equal the env names; visible labels, `aria-describedby` help lines, env names as `code[translate=no]`, `data-rag-i18n` keys from UI-SPEC 12.3, 12.4 and 12.6, a `settings.saveHint` line per group; the URL is `type="url"` with `inputmode="url"`, the secret `type="password"` with the page's reveal button; no `value` attributes. No script, handler or request is added, so the page makes no new request on load.
- `monitorSettings(source = env)` returns `{ monitor, webhookUrl, webhookSecret, configGate, configGateLive, representativeSample }`: booleans are on only for `true`; `RAG_CONFIG_GATE` accepts off | warn | enforce (case-insensitive, trimmed), anything else is `off` with one `[Config Gate]` warning; a webhook URL that is not a parseable `https://` URL is `null` with one `[Monitor]` warning; a secret under 32 characters is `null`.
