<objective>
Show refusal cells that a reranker, embedding-model or tokenizer change made unreliable, both for proposed values (setting check) and as a standing warning, and stop applying cells calibrated for another embedding model (D-18, D-24).

Purpose: "changing the reranker model marks its refusal cells uncalibrated with a warning" (EVAL-23, success criterion 2), and a shifted score distribution flags the cells as possibly stale (OBS-03, success criterion 3).
Output: the pure pending logic, a CLI for the config server, the status and route additions, the runtime embedding-model rule, tests.

Planner resolution: the reranker provider and model of the running and proposed configuration are resolved through the same TypeScript reader the runtime gate uses for `cellKey`, so the config server spawns `pending-cli.ts` instead of re-implementing it in CommonJS. Change records are read with the service-role client directly (no dependency on plan 05.3-21).

Depends on 05.3-01 (`RefusalCell.embedding_model`), 05.3-07 (change records), 05.3-08 (alerts) and 05.3-12. Rollout position: D-60 step 5. Trunk is changing under other sessions: re-read `status.ts`, `gate.ts` and `thresholds.ts` before editing; never rely on a line number.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan.
</objective>
