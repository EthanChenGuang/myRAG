# Phase 05.3 Plan 25: Tenant nightly requests on import and re-embed completion — Summary

**A finished bulk import or re-embedding run now leaves one pending `rag_eval_run_requests` row per tenant (with `RAG_CONFIG_GATE` warn or enforce), and admin routes let the drain claim and close those rows and the Config UI list them.**

## Accomplishments
- `requestTenantNightly(rpc, { tenantKey, reason, refId })` calls `rag_eval_run_request_enqueue` (0961). It never throws, does nothing with the gate off, and logs `[Config Gate]` with the reason code and the error name or code only.
- `finishBatch` calls it right after the `completed` status write, for `scopeKey(batch.scope)`. `runReembed`'s `complete()` calls it once per tenant key of the report (plus the run's own tenant key when the run is scoped), sorted. Neither hook changes statuses, totals, end report or log output.
- `GET /api/rag/admin/eval-run-requests?limit=&cursor=` returns `{ requests[], next_cursor }`. The fields are `id, tenant_key, reason, ref_id, requested_at, updated_at, status, skip_reason, result, checks, counts`, with no text. `POST { action: 'claim', limit }` and `PATCH /[id] { status, skip_reason?, result_summary? }` complete the drain contract. Zod bodies use `zod/v3` with `.strict()`.

## Deviations from Plan
- **Re-embed tenant set:** the plan says "one row per tenant of its report". The hook also adds `run.tenantKey` when the run is scoped. A derived run, or a resumed run with nothing left to embed, has an empty `tenants` record, and it would otherwise request nothing for the tenant it re-embedded.
- **Claim and close are tenant-scoped:** the plan resolves the tenant set through `rag_admin_tenant_keys` only for the list. Claim and close use the same set (security first, T-05.3-252).
- **Barrel export:** the routes import from `@/lib/rag`, because `check-rag-boundary` forbids deep imports from `src/app`.
- **TDD order in Task 2:** the route code was written before its test file. The test was written against the contract in the plan's behavior list, with no separate RED commit.
- **Migration number:** none needed. The plan uses 0961 from 05.3-07 and claims no number.
- **`npm run typecheck:new`** in the plan's verify lines was replaced by the brief's `npx next typegen && npx tsc --noEmit` gate.
