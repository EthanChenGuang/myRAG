<objective>
Serve the same BGE-M3 profile from the sidecar for deployments that must keep text in-house, and prove both serving modes return identical vectors (D-26).

Purpose: EMB-11's "both serving modes return identical dense vectors, so switching needs no re-embedding".
Output: sidecar embed route and embedder, the `bge-m3` extra, the serving switch in the provider, recorded vectors with an identity test, a nightly job.

One human step (Task 3): the model weights are a pickle file, so a person confirms the pinned revision before the image bakes it; the same person records the hosted vectors with a DeepInfra key, runs the sidecar recording, and applies migration 0811 to the live database.

Phase 3.2 groundwork this plan uses: the contracts `EmbedRequest` and `EmbedResponse` (03.2-06), the config field `bgeM3Serving` read from `RAG_BGE_M3_SERVING` (03.2-03), the sidecar router and extra conventions of the hidden-text checker (03.2-35, 03.2-36) and the fake sidecar helper as 03.2-37 left it.
</objective>
