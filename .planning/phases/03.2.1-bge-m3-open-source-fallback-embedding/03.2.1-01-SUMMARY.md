# 03.2.1-01 SUMMARY: BGE-M3 hosted profile, catalog language declarations, migration 0811

## What was built

- **Task 1 — hosted provider** (`70874c1a` RED, `576d6af6` GREEN). `src/lib/rag/embeddings/bge-m3.ts` posts to `${DEEPINFRA_BASE_URL}/embeddings` with `model: BAAI/bge-m3`, `encoding_format: float`, the bearer `DEEPINFRA_API_KEY`, no dimension, no instruction (documents, single query, query batch). Up to 128 inputs per request; vectors mapped by the response `index`; every vector checked for 1024 components and L2-normalized in double precision (`truncateAndNormalize`; a zero vector raises `zero_norm`); a different returned model raises `EmbeddingProfileMismatch('model')`; profile dims other than 1024 are refused before any request. Empty list or empty string → `embedding_input_empty`; above 4096 cl100k_base tokens → `embedding_input_too_long`, before any request; never truncated; text sent as given (no Unicode normalization). Missing key → the Qwen configuration error. `bge-m3` added to `EmbeddingProviderId`, the registry provider list and defaults, `canonicalModelId`, the catalog and `DEFAULT_MODELS`; the price comes from the catalog, so `prices.ts` needed no edit. No new variable or secret.
- **Task 2 — language declarations** (`7b7794eb`, `58809a50` RED, `2045d092` GREEN). `config/rag/embedding-model-languages.json` (`schema_version` 1, `default_profile`, one entry per catalog model) is now the only source of `supportedLanguages`. The app adapter in `settings.ts` reads the active profile and its catalog declaration (`validateConfiguredLanguagesAgainstActiveProfile`); with the registry unreachable it checks the default profile and reports `verifiedAgainstActiveProfile: false`. App startup runs the same check once when the language variables are set and logs `[RAG Languages] the embedding profile does not declare a chosen language` with the profile id and languages; nothing is read while they are unset. The scripts (init-env, config server) already read the file through `scripts/rag/language-settings-context.js` (03.2-09) and were not edited; the shared case file proves all three entry points give the same answer. The validator file is unchanged.
- **Task 3 — migration 0811** (`5b023296` RED, `9b94633a` GREEN). Seeds `bge-m3-1024` (bge-m3, BAAI/bge-m3, 1024, halfvec, available, no doc-type scope, no query instruction) with `ON CONFLICT DO NOTHING`, and `chunk_embeddings_bge_m3_1024_hnsw` / `chunk_translation_embeddings_bge_m3_1024_hnsw` (halfvec(1024), cosine, m 64, ef_construction 200, `WHERE profile_id = 'bge-m3-1024'`), `NOTIFY pgrst`. No function, grant or policy change. Fixture tests (both modes): row shape, legacy still active, both indexes, gate refuses `incomplete` then `eval_missing`, 1024 vectors stored and 768 refused, two `embedding_host` values in one profile, second apply changes nothing.

## Behaviour changes

- None with defaults: nothing is activated, no switch added, shipped languages zh/en/it are declared by every unscoped-capable model. A deployment whose active profile's model does not declare a chosen language now gets a startup warning (previously not checked against the profile).
