# 03.2.1-03 SUMMARY: BGE-M3 in the profile comparison, inactive-profile parity, operator docs

## What was built

- **Task 1 (tracer): comparison arm and serving-mode figures** (`ed135012` RED, `4f12f869` GREEN).
  - The harness now backfills every target profile side by side in the fixture database: `voyage-4-large-2048` and `bge-m3-1024` by default. All re-embed runs start at the corpus midpoint, so the pre-migration slice still holds. A fixture `bge-m3` provider (fixture embedder at 1024 dims, host `fixture-bge-m3`) stands in for the model. No profile is activated.
  - Each arm gets gated and candidate eval runs. The BGE-M3 serving file measures the mode `RAG_BGE_M3_SERVING` selects (default `hosted`): backfill chunks per second, p50/p95 of the `embed` stage from the arm's gated report, and the catalog price with the run's cost. The other mode is written as unmeasured.
  - The CLI writes `comparison.json` and `comparison.txt`. The JSON carries `wiring_proof: true` and the label. The text lists every arm with overall, language, category and `pair:<query>-><document>` rows. Under the BGE-M3 arm come one `serving hosted` line and one `serving sidecar` line.
  - A fixture run gives no default-candidate verdict and has no "default candidate" line in its text.
- **Fixture evidence refusal.** The global EMB-05 gate (`rag_activate_embedding_profile`, 0309/0425/0652) is unchanged and never had a fixture rule. The finetune lifecycle tests rely on that: they activate from fixture comparisons. So the refusal sits before the gate and keys on the new `wiring_proof` flag. `comparison_to_activation_evidence` raises `FixtureEvidenceRefused`, and `rag:embedding record-evidence` refuses the comparison with `evidence_refused: fixture_evidence`. Comparisons built without `--wiring-proof`, such as the finetune helper's, behave as before.
- **Task 2: operator docs** (`e26ae26b`). AGENTS.md section 6 now has a BGE-M3 subsection: the profile id, seeded `available`, and activation only through `rag:embedding` and EMB-05. It also covers `RAG_BGE_M3_SERVING=hosted|sidecar` (hosted reuses `DEEPINFRA_API_KEY`), the `bge-m3` extra and image with weights baked at a pinned revision, and the CPU sizing (about 2.3 GB of weights, plan 4–5 GB of RAM). It states that sidecar mode never falls back (`embedding_sidecar_unavailable`), that 0811 is not folded, and how the comparison and its `not measured` cells work. Handy Scripts gains the `docker build --target bge-m3` row. The old note "(0811 unused)" in the 08xx migration line was stale and now names the BGE-M3 profile.
