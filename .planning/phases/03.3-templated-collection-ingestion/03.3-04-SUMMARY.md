# Phase 03.3 Plan 04: tenant line pattern module Summary

**Tenant heading and boilerplate line patterns can now be checked before saving and run once per document in the 04.2-14 worker under a deadline. Nothing calls the module yet, so runtime behaviour is unchanged.**

## Upstream facts confirmed (Task 1 gate)
The gate command passed. 04.2-14 and its transitive dependencies (04.2-01, -03, -04, -34, 04.1-12) all have SUMMARYs on this branch. No hand-off note was needed.

- (a) `validateIdentifierPattern(pattern: string, flags: string)` returns `{ ok: true; flags: 'gu' | 'giu'; storedFlags: 'u' | 'iu'; probeChars; witnesses }` or `{ ok: false; findings: { code }[] }`, with codes from `IDENTIFIER_PATTERN_FINDING_CODES`.
- (b) `runPatternInWorker({ patterns: { id, source, flags }[], inputs, maxSpans? }, { deadlineMs?, signal? })` returns one of these:
  - `{ kind: 'ok', elapsedMs, spans: { patternId, inputIndex, start, end }[], counts, alphanumeric }`
  - `{ kind: 'timeout' }`
  - `{ kind: 'error', error: 'invalid_regex' | 'worker_failed' | 'aborted' }`

  The worker's default deadline is 1000 ms, and at most 4 workers run at once.
- (c) `checkIdentifierPattern(pattern, flags, { signal? })` applies `no_alphanumeric` last, after the timing rule, and returns it as the only finding.

## API for 03.3-07, -10, -12, -14
```ts
export const TENANT_LINE_PATTERN_KINDS = ['heading', 'boilerplate_line'] as const;
export const TENANT_LINE_PATTERN_LIMITS = { maxPatternLength: 200 };
export const TENANT_LINE_FINDING_CODES = ['too_long', 'invalid_regex', 'invalid_flags', 'backreference', 'lookbehind',
  'nested_unbounded_quantifier', 'matches_empty', 'heading_not_anchored', 'probe_too_slow'];
export const TENANT_LINE_MATCH_WINDOW = 200;          // UTF-16 code units; 199 when the cut would split a surrogate pair
export const TENANT_LINE_DEFAULT_DEADLINE_MS = 3000;  // caller value clamped to 100..30000

type TenantLinePatternValidation =
  | { ok: true; storedFlags: 'u' | 'iu'; compiledFlags: 'gu' | 'giu' }
  | { ok: false; findings: { code: TenantLineFindingCode }[] };   // ordered as TENANT_LINE_FINDING_CODES

validateTenantLinePattern(kind, pattern, flags): TenantLinePatternValidation                 // sync static re-check (loader, 03.3-07)
checkTenantLinePattern(kind, pattern, flags, { signal? }): Promise<TenantLinePatternValidation> // save time (03.3-07, 03.3-14)
matchTenantLinePatterns(
  { patterns: { id, kind, pattern, flags }[], lines: string[] },
  { deadlineMs?, signal? },
): Promise<
  | { kind: 'ok'; hits: { inputIndex; patternId; start; end }[]; skipped: string[] }
  | { kind: 'timeout' }
  | { kind: 'error'; error: 'too_many_patterns' | 'too_many_lines' | 'invalid_pattern_id' | 'invalid_regex' | 'worker_failed' }>;
```
- The request limits are at most 100 entries and 20,000 lines. An id must be 1 to 64 characters and unique. All of these are checked before any worker call.
- `hits` holds at most one hit (the first match inside the window) per line and pattern. Hits are sorted by line index, then by request order. `skipped` lists the ids that failed the static re-check; those entries are never sent to the worker.
- When no entry passes or there are no lines, the result is `ok` with no hits, and no worker is started.
- An aborted signal, before or during the call, rejects with the abort reason. `checkTenantLinePattern` does the same.
- What a hit means is up to the caller. 03.3-12 keeps only matches at offset 0. 03.3-10 removes the matched lines. A caller maps `timeout` to `tenant_pattern_timeout` and takes the unruled path.

**Measured call time:** one call with 5,000 lines of 200 characters and 100 anchored heading patterns took 154 ms on the first run and 108 to 109 ms when warm. This was on the 4-CPU executor container, and the time includes starting the worker.

## Decisions for STATE
- Tenant line patterns run only in the 04.2-14 worker, with one call per document, a 200-unit window, a deadline of 3000 ms by default and clamped to 100..30000, and at most 100 patterns and 20,000 lines per call.
- A heading pattern must be anchored, which is finding `heading_not_anchored`. A boilerplate line may match punctuation only.
