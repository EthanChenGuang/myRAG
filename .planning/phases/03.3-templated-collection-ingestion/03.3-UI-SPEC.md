## 0. Findings that shape this contract

1. **Two neighbourhoods, two markups.** The Phase 3.2 ingestion switches sit in `div[data-rag-settings-group="ingest"]` inside
   the hidden `#rag-phase032-settings` block; `ingest-impact.js` moves the group into the Settings sub-tab of the "Ingestion
   changes" panel. A control there is `div.form-control.mb-4` with a `select-sm`, readable option text and a help row ending
   with the variable name in `code`. The Phase 4.2 switches sit in `#rag-tuning-switches` (Retrieval pipeline card): checkboxes
   whose label carries the variable name in parentheses, selects whose option text is the value.
2. **No JavaScript is needed.** The page loader fills any element whose `id` is a config key (`checked` for a checkbox, `value`
   otherwise) and the change handler saves by `id`. The save guard of `ingest-impact.js` sends changed keys to the server,
   which classifies them; its revert path handles checkboxes.
3. **Two tests pin the neighbourhoods.** `config-phase32-switches.test.ts` fixes the group list of the 3.2 block and the count
   of `settings.affectsStored` markers (10), and forbids straight quotes in its copy. `config-phase42-switches.test.ts` fixes
   the number of dividers in the tuning box (4). This contract adds no group, divider or marker, so both pass unedited.
4. **The 3.2 localizer replaces `textContent`.** A keyed node holds text only; a command in `code` is its sibling, not its child.
5. **`rag:rechunk` and `rag:relex` are in `package.json`; `rag:attributes` is not yet** (D-24 plan). The ingest group has a zh
   and it table and falls back to the static English for a missing key; the tuning box has keys but no table on trunk.

## 1. Design direction (frontend-design pass)

An admin turns on a mechanism for collections of near-identical documents, in a dashboard they already know. Each switch says in
one line what it does, what it needs and what to run for documents already stored. **Direction: fit the surface.** Each control
has the form of the control above it; no new colour, type, spacing value, icon, box, heading or divider. The copy is the only
design material. **Rejected:** a box of its own for the six (breaks finding 3, splits ingestion switches over two places); a
pointer to a panel that does not exist; a live "needs" warning (needs a script; the help states the need at all times and the
server logs one `[RAG Config]` warning, D-03); disabling a dependent control (the loader fires no `change`, so it would go stale).

## 8. Copywriting Contract

English is the static markup and the contract. Mechanism only: no word, name, code system, heading name or example value of any
subject area (owner rule). "Workspace" is the page's word for a tenant. Copy inside the 3.2 block uses curly quotes (’) only.

Primary CTA: none (no button; the page's existing change handler saves). Empty state: none (a control at its default).
Error state: none new (a failed save uses the page's existing message; ingestion-side changes pass the existing save guard).
Destructive confirmation: none.

| Key | Copy |
|-----|------|
| `RAG_PAGE_BOILERPLATE.label` | Page boilerplate cleaning |
| `RAG_PAGE_BOILERPLATE.opt.off` / `.detect` / `.rules` / `.both` | Off / Detect repeated lines / Workspace rules / Detect and workspace rules |
| `RAG_PAGE_BOILERPLATE.help` | Before a document is split into chunks, removes lines that repeat at the top or bottom of its pages, lines that match the workspace’s rules, or both. The stored parse output is not changed. Needs the unified ingest pipeline. |
| `RAG_PAGE_BOILERPLATE.stored` | Stored documents: they keep their current chunks until a chunking profile is rebuilt with {command} |
| `RAG_SECTION_RULES.label` | Section rule sets |
| `RAG_SECTION_RULES.opt.off` / `.on` | Off / On |
| `RAG_SECTION_RULES.help` | Splits a document at the headings that its workspace’s rule set allows; other headings stay body text. A document that does not satisfy its rule set is split the usual way and marked for review. A workspace without a rule set is not changed. Needs the unified ingest pipeline. |
| `RAG_SECTION_RULES.stored` | Stored documents: they keep their current chunks until a chunking profile is rebuilt with {command} |
| `RAG_DOC_ATTRIBUTES.label` | Document attributes |
| `RAG_DOC_ATTRIBUTES.help` | Stores attributes with each document and its chunks, checked against the workspace’s attribute schema. A value with an unknown key or the wrong type is rejected. Needs the unified ingest pipeline. |
| `RAG_DOC_ATTRIBUTES.stored` | Stored documents: no rebuild is needed; they have no attributes until you import them with {command} |
| `RAG_ATTRIBUTE_HEADER.label` | Attribute header in search text |
| `RAG_ATTRIBUTE_HEADER.help` | Adds one line, rendered from the workspace’s header template and the document’s attributes, to the text used for embedding and keyword search. The line is never sent to the answering model. Needs document attributes. |
| `RAG_ATTRIBUTE_HEADER.stored` | Stored documents: their search text has no attribute header until a chunking profile is rebuilt with {command} |
| `RAG_LEXICAL_QUANTITY.label` | Numbers with units as single search terms |
| `RAG_LEXICAL_QUANTITY.help` | A number followed by a unit symbol also matches as one term in keyword search, whatever its spacing, digit grouping, decimal separator or letter case. Calibrated refusal thresholds belong to one tokenizer version; calibrate them again after the rebuild. |
| `RAG_LEXICAL_QUANTITY.stored` | Stored documents: rebuild their search text with {command} |
| `RAG_ATTRIBUTE_FILTER.label` | Attribute filter |
| `RAG_ATTRIBUTE_FILTER.help` | `off` ignores attributes. `hard` limits retrieval to the documents whose attributes match a value named in the question or sent with the request, and searches again without the limit when that finds nothing. `soft` keeps every document and ranks the matching ones higher. Needs document attributes and the v2 pipeline. |

- `{command}` is the `code` element of the table in section 7; it always ends the line and there is exactly one per line.
- A "Needs …" sentence is always the last sentence of the help. "The unified ingest pipeline" is `RAG_INGEST_PIPELINE=unified`,
  "the v2 pipeline" is `RAG_PIPELINE=v2`, "document attributes" is the switch labelled so. `RAG_LEXICAL_QUANTITY` needs nothing.
- In `RAG_ATTRIBUTE_FILTER.help` the three values are `code.font-mono.text-xs[translate=no]`, as in `RAG_RESULT_DIVERSITY.help`.

## 9. Accessibility and keyboard

- Selects: `label[for]` equal to the select's id. Checkboxes: the `input` is inside its `label`, so the whole row is the target.
- Every control names its help through `aria-describedby`; every id named there exists exactly once in the document.
- Tab order is DOM order, no `tabindex`: ingest group `RAG_CAPTION_LANGUAGE`, `RAG_PAGE_BOILERPLATE`, `RAG_SECTION_RULES`,
  `RAG_DOC_ATTRIBUTES`, `RAG_ATTRIBUTE_HEADER`; tuning box `RAG_LEXICAL_STEM_IT`, `RAG_LEXICAL_QUANTITY`, …,
  `RAG_IDENTIFIER_FILTER`, `RAG_ATTRIBUTE_FILTER`, then `RAG_EMBED_TENANT`. Space toggles a checkbox; arrow keys change a select.
- Focus outlines are DaisyUI's, unchanged. No colour carries meaning, nothing animates, and text contrast is the neighbours'
  in both themes. Commands, variable names and values carry `translate="no"`.
- Narrow screens: selects are `w-full`, help rows wrap (`flex-wrap`), commands break (`break-all`); usable at 360px.

## 11. Decisions made in this contract

1. **Host of the four ingestion switches:** the existing `ingest` settings group. They are shown and hidden with it.
2. **Control types are those of the brief.** The `ingest` group has only selects today (its on/off switches are Off/On
   selects); the two checkboxes are its first. The loader, the change handler and the save guard handle them unchanged.
3. **`RAG_LEXICAL_QUANTITY` joins the keyword-terms group; `RAG_ATTRIBUTE_FILTER` joins the last group**, next to the
   identifier filter, which limits retrieval the same way. No sixth group (finding 3).
4. **No `settings.affectsStored` sentence.** The stored-documents line carries that information and names the command.
5. **One command per line, printed only once it exists** (command gate, section 7). The refusal recalibration of D-33 is a
   sentence in the help. `rag:rebuild` for the legacy profile (D-21) and `rag:rules` (D-34) are not printed: the brief names
   three commands, and `rag:rules` is not in `package.json`.
6. **English only.** Keys are attached so zh and it rows can be added to `INGEST_IMPACT_LABELS` later; until then a zh or it
   admin sees these four controls in English inside a localized group. Every neighbour in the tuning box is English today.
7. **No script change.** `INGEST_IMPACT_SETTINGS_IDS` is not extended (it feeds only that panel's own warnings), and the
   tuning box gets no combination note.
