# Phase 3.3 Plan Index

26 plans in 10 waves (ids 03.3-01 to 03.3-26). Plans in the same wave share no file in `files_modified`; every file touched by two or more plans is ordered by a `depends_on` path (list below). Every plan opens with a read-only gate task that checks the named `*-SUMMARY.md` files and symbols and stops with a hand-off note under `handoffs/` when one is missing (CONTEXT D-01). Gates on other phases are hard: a stopped plan writes no SUMMARY.

Cross-phase gates (also in each plan's `depends_on`): **04.2-14** for plan 04 (and, through it, 07, 10, 12, 14); **04.2-18, 04.2-34, 04.2-35** for plan 16; **04.2-19, 04.2-22** for plan 21; **04.1.1-06** for plans 18 and 19. Everything else needs only trunk as of 2026-11-26 (Phases 3, 3.1, 3.2 and 4 deliverables, located by symbol).

Rules that hold for every plan:
- Only plan 03.3-01 changes Pydantic contracts and generated Zod.
- No function owned by another phase is redefined (`hybrid_search_chunks`, `rag_write_chunks`, `rag_write_profile_chunks`, `rag_set_document_fields`, the `template_row` builders); migration 1019 stays unused (D-02, D-28).
- No tenant pattern is compiled or run outside the 04.2-14 worker (D-11).
- Domain neutrality: plans, code, defaults, tests, fixtures and Config UI text contain no word, name, code system, heading list or pattern of an example domain; test data is invented and described by structure.
- PGlite plans (marked P) never run at the same time as another fixture-database plan in one tree (`use_worktrees: false`).
- Only plan 03.3-26 touches live services. Only plans 03.3-20 and 03.3-25 write `eval/baselines/*`.
