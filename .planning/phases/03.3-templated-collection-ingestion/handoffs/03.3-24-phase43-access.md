# 03.3-24 hand-off: Phase 3.3 retrieval reads and Phase 4.3 access groups

Date: 2026-11-26. For: Phase 4.3 (document access groups), D-11. Status: Phase 4.3 is **not** on trunk (no migration defines
`p_access_keys`), so nothing is missing yet; this note lists what 4.3 must extend.

## Functions that read documents at retrieval time

Per 4.3 D-11 each needs `p_access_keys text[] DEFAULT NULL` and `p_access_all boolean DEFAULT false`, applied in the same WHERE clause
as the tenant predicate (`p_access_keys IS NULL OR p_access_all OR d.access_groups && p_access_keys`), service_role only,
`SET search_path = ''`:

| Function | Migration | Why it needs the filter |
| --- | --- | --- |
| `rag_attribute_filter_values(p_tenant_key text, p_limit integer)` | 1008 | Lists the values of current, ready documents; a value of a document the caller cannot see must not be matchable or suggested. |
| `rag_attribute_documents(p_tenant_key text, p_filters jsonb, p_limit integer)` | 1008 | Returns the document ids the hard filter and the `attr:0` soft list search. |
| `rag_attribute_identifier_documents(p_tenant_key text, p_after uuid, p_limit integer)` | 1007 (plan 03.3-16 landed) | Feeds the identifier index; the identifier lookups of Phase 4.2 already get the 4.3 filter, so this feed only needs it if 4.3 reads it at query time. |

The in-process attribute lexicon (`attributeLexiconFor`, cached per tenant key) is built from `rag_attribute_filter_values`. Once the
values are access-filtered the cache key must include the caller's access scope (or the lexicon must hold only tenant-wide values and the
document ids be filtered per caller).

- Migration number 1019 (reserved in the Phase 3.3 block for this change) stays unused.
- If Phase 4.3 lands on trunk before this note is acted on, the status above becomes "parameters missing"; the coordinator assigns spare
  migration 1010 for the redefinition.
