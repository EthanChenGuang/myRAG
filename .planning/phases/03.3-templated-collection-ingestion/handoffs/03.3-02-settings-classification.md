# Hand-off 03.3-02: settings classification of the six Phase 3.3 switches (D-03)

For: coordinator. Date: 2026-11-26.

| Variable | Values (default first) | Classification in `config/rag/settings-classification.json` | Mechanism |
| --- | --- | --- | --- |
| `RAG_SECTION_RULES` | `off`, `on` | `ingestion` | `rechunk` |
| `RAG_PAGE_BOILERPLATE` | `off`, `detect`, `rules`, `both` | `ingestion` | `rechunk` |
| `RAG_DOC_ATTRIBUTES` | `false`, `true` | `query` (see gap below) | — |
| `RAG_ATTRIBUTE_HEADER` | `false`, `true` | `ingestion` | `rechunk` |
| `RAG_ATTRIBUTE_FILTER` | `off`, `hard`, `soft` | `query` | — |
| `RAG_LEXICAL_QUANTITY` | `false`, `true` | `both` | `relex` |

Gap: D-03 classifies `RAG_DOC_ATTRIBUTES` as ingestion-side with no rebuild (stored documents get attributes through
`rag:attributes`, plan 03.3-13). The classification contract requires a rebuild mechanism on every `ingestion` or `both` entry and has
no value meaning "no rebuild". The switch is therefore classified `query`, like `RAG_SCOPE_TAGS`. If the owner wants an explicit
"import, no rebuild" mechanism, the contract (and its Pydantic model, plan 03.3-01's area) needs a new mechanism value first.
