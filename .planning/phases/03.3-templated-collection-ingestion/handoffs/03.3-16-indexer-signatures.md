## Indexer
- File: `src/lib/rag/ingest/write-indexers.ts` (same path as `files_modified`).
- `export async function indexDocumentForLookup(input: IndexDocumentInput): Promise<IndexDocumentReport>`
- `IndexDocumentInput`: `{ writer: LookupIndexWriter; scope: TenantScope; documentId: string; tables: boolean; identifiers: boolean; signal: AbortSignal; loadPatterns?: (scope, { signal }) => Promise<TenantIdentifierPatterns> }`.
  `LookupIndexWriter = Pick<IngestWriter, 'listDocumentChunksForIndex' | 'writeChunkIdentifiers' | 'writeTableRows'>`. The input carries no RPC client.
- `IndexDocumentReport.identifiers`: `{ chunksIndexed, chunksWritten, documentIdentifiers, documentChanged, truncated, tenantPatterns } | null`; `warnings: IndexWarningCode[]` (`index_tables_failed`, `index_identifiers_failed`, `identifier_patterns_unavailable`).
- Never throws for an indexing failure (only when aborted); a failed part is logged once under `[Ingest]` with its code.

## How identifiers are built and written
- Chunks are read by `readChunks` (writer `listDocumentChunksForIndex(documentId, after, 500)` → `IndexChunkRow { id, chunkingProfileId, chunkIndex, sectionPath, content }`), all chunking profiles.
- `indexIdentifiers`: sorts chunks (legacy profile first, profile id, chunk index, id); per chunk `extractChunkIdentifiers(content, patterns.expressions)` (`src/lib/rag/identifiers/extract.ts`) → `ChunkIdentifiers { raw: string[]; norm: string[]; truncated }`, raw and norm index-aligned, de-duplicated by norm, capped at `MAX_CHUNK_IDENTIFIERS = 256`, each at most `MAX_IDENTIFIER_CHARS = 200`.
- Rows `{ chunkId, raw, norm }` are written in pages of 500 with `writer.writeChunkIdentifiers(documentId, rows)` → RPC `rag_write_chunk_identifiers(p_tenant_key, p_document_id, p_rows)` (0860), row shape `{ chunk_id, raw, norm }`.
- The document union is computed in SQL by `rag_write_chunk_identifiers` from the stored chunk arrays (first seen by the same order, de-duplicated by norm, 2048 cap); `unionIdentifiers` in TS only produces the report counts. Merging into the chunk rows is therefore enough for the union.
- Merge point for this plan: inside `indexIdentifiers`, after the per-chunk `ChunkIdentifiers` are complete and before the rows are built and written.
