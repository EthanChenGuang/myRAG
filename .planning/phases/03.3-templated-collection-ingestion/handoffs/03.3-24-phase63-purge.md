# 03.3-24 hand-off: Phase 3.3 purge hook for Phase 6.3

Date: 2026-11-26. For: Phase 6.3 (source deletion sync and purge), plan 06.3-19.

## Hook

`public.rag_purge_hook_doc_attributes(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint`
(migration `1009_phase33_purge.sql`). SECURITY INVOKER, `SET search_path = ''`, service_role only; asserts the tenant key first.

For the tenant's documents of the lineage or the listed ids it:
- sets `attributes`, `attribute_header`, `attribute_header_stamp` to null on the documents;
- sets `attributes`, `attribute_header_stamp` to null on their chunks;
- deletes the tenant's `rag_staged_attributes` rows whose `(source, source_key)` is one of those documents'.

It returns the number of changed rows (documents + chunks + staged rows deleted); a second call returns 0, and another tenant's key
changes nothing (`tests/rag-db/phase33-purge.test.mts`, both modes).

## Request

`rag_purge_hook_doc_attributes` is **not** one of the reserved names in 06.3-19 (`table_rows`, `duplicate_clusters`, `translations`,
`golden_items`). Please call it from `rag_purge_foreign_stores` under the same guard
(`pg_catalog.to_regprocedure('public.rag_purge_hook_doc_attributes(text,uuid,uuid[])') IS NOT NULL`) and record its count under a key
such as `doc_attributes`.

## Branch taken

Branch (b): `rag_purge_store_inventory()` does not exist on trunk, so 1009 adds no inventory row. When 0728 lands, the inventory needs:
- a hook row for `rag_staged_attributes` (purged by the hook above; it holds values by source key, not by document id);
- exempt rows (tenant settings, no document reference) for `rag_section_rule_sets`, `rag_boilerplate_rules`,
  `rag_attribute_definitions`, `rag_attribute_header_templates`.

The new columns on `documents` and `document_chunks` go with their rows when the purge deletes the rows; the hook matters for a purge
that keeps rows (for example a soft purge or a verify pass) and for the staged rows.
