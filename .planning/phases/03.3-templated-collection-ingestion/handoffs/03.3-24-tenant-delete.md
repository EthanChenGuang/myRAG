# 03.3-24 hand-off: tenant rule-data delete (coordinator)

Date: 2026-11-26. For: the coordinator (tenant offboarding / organization delete).

`public.rag_tenant_rule_data_delete(p_tenant_key text) RETURNS TABLE (relation text, deleted bigint)` exists (migration
`1009_phase33_purge.sql`). It deletes one tenant's rows from the five Phase 3.3 tables and returns one row per table in this order:
`rag_section_rule_sets`, `rag_boilerplate_rules`, `rag_attribute_definitions`, `rag_attribute_header_templates`,
`rag_staged_attributes`. Documents and chunks are not touched. SECURITY INVOKER, `SET search_path = ''`, service_role only; a key of
the other deployment mode is rejected.

**Nothing on trunk calls it yet.** Whatever deletes a tenant (organization delete, personal workspace delete) should call it once.

After the call, the in-process loaders keep their entries until their time to live ends (60 s; 5 s for a failed load) or their
invalidators run: `loadTenantRules` (`invalidateTenantRules`), `loadAttributeSchema` (its writers), `loadHeaderTemplate`
(`invalidateHeaderTemplate`), `attributeLexiconFor` (`invalidateAttributeLexicon`). A caller in the app process should run those
invalidators for the tenant key after the delete; other instances expire within the time to live.
