# 03.3-17 operations notes (for plan 03.3-25)

Date: 2026-11-26. Source: plan 03.3-17 (TPL-05, D-26, D-27).

## Rewrite sites and the in-step rule

- A chunk is "in step" when its own `attribute_header_stamp` equals its document's stamp (`rag_attribute_headers` in chunk mode returns
  only those). The sites that rewrite text of stored chunks (re-embed, recaption, deferred backfill embeddings, relex, translation
  producer) put the header into the text only for chunks in step; every other chunk gets today's text.
- Relex never changes a stamp: relex of a chunk that is not in step drops no stamp and adds no header. Relex reads the header only when
  its caller passes `attributeHeader: true` (`rag:relex` passes the effective `RAG_ATTRIBUTE_HEADER`); the fixture harness passes nothing.
- A translation row has no stamp. A chunk rewritten in place (relex, recaption) keeps its translation's old lexical text until
  `rag:translate` produces the translation again. The text embedded for a translation is the translated content alone, unchanged.
- Recaption also rewrites `lexical_text`; for a chunk in step that text gets the header as one more prefix part, so the chunk's two texts
  keep one header state.

## Rebuild after a header change

- A header change is classified `rechunk`: `rag:rebuild start --mechanism rechunk` selects the stale-header documents together with the
  fingerprint-affected ones and builds the side-by-side `rb-` chunking profile; activation stays with `rag:chunking activate`.
- The `rb-` profile has the legacy child size and no parents. A tenant whose doc type serves a parent-child profile builds a new profile of
  the same preset with `rag:rechunk` instead.
- Chunking profiles are per doc type, not per tenant: in multi-tenant mode the `rb-` profile covers every tenant's documents of the type.
- The fingerprint coverage count of the Config UI is not extended by the stale-header documents.
