## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| One tenant's rule data and values to another tenant's request | The most severe failure class of this project |
| Purge and tenant-delete callers to tenant data | A tenant, a lineage and version ids cross here |
| Client roles to the new functions and tables | anon and authenticated must never reach them |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-2401 | Information disclosure | a rule, value, template or staged row crossing tenants | critical | mitigate | Matrix over every store, function, cache and the stage in both modes; key-mode assertion per function; value strings asserted absent from traces and logs |
| T-03.3-2402 | Tampering | purge hook or tenant delete touching another tenant | high | mitigate | `rag_assert_tenant_key` first, tenant in every predicate, two-tenant purge cases in both modes |
| T-03.3-2403 | Elevation of privilege | new functions callable by clients | high | mitigate | REVOKE and GRANT on exact signatures; catalog and fake-edge refusal assertions; static scans |
| T-03.3-2404 | Information disclosure | purged values surviving in staging or a later version | high | mitigate | Hook clears staged rows of the purged source keys; Phase 6.3 note asks for the call; inheritance never reads a purged version |
| T-03.3-2405 | Repudiation | open access-parameter, purge-call and tenant-delete items forgotten | low | mitigate | Three hand-off notes collected by plan 03.3-25 |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
