<objective>
Define every structured contract Phase 3.3 needs, once, in Pydantic v2, and regenerate the Zod schemas.

Purpose: D-04 (TPL-01..09). Later plans only import these types. Every addition is optional and left out of the serialised object while unset, so stored fingerprint parts, the repository profiles, the language-pack registry, stored manifests, committed configs and the fixture baselines stay byte-equal (D-05).
Output: one new contract module, nine extended modules, exported JSON Schemas, regenerated Zod, samples, tests.

Rules for every task:
- Locate code by symbol name, never by line number, and re-read the newest definition first: other sessions execute Phases 4.1.1, 4.2 and 5 on trunk and regenerate the same files. After any rebase run `npm run gen:schemas` again; never hand-merge a generated file.
- Domain neutrality: field names, descriptions, defaults and samples carry no word, name, code system, heading name or example value of any real subject area. Samples are invented and described by structure (an attribute key `alpha_code` typed as a code, a heading pattern anchored at the line start, a unit symbol of two letters).
- No constant is bumped: not `LEXICAL_VERSION`, `EMBEDDING_TEXT_VERSION`, `HASH_NORMALIZATION_VERSION`, a profile `version` or a `pack_version`. No file under `config/rag/` or `rag-sidecar/config/rag/` is edited here.
- The Pydantic `StageName` literal is not changed: `attribute_resolve` is a v2-internal stage that plan 03.3-02 registers (adding it here would fail `tests/rag/query/stage-names.test.ts` until that plan lands).
- Contracts carry structure and limits only. Regular-expression safety checks stay in plan 03.3-04; a repository profile that names `rule_sections` is refused by `checkProfile` in plan 03.3-06, not by a model validator, because the effective per-document chunker passes through the same model.
- Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/03.3-templated-collection-ingestion/handoffs/03.3-01-<topic>.md` and are listed in the SUMMARY under `## Hand-offs`.
