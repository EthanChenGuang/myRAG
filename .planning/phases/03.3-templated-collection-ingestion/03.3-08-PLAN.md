<objective>
Store each tenant's attribute schema and give every later plan one way to read it and one way to check values against it.

Purpose: TPL-03 and the storage half of TPL-08 (CONTEXT D-22, D-12, D-02; RESEARCH Pattern 4). Values on documents are plan 03.3-11, the import command plan 03.3-13, the admin route and the barrel exports plan 03.3-14.
Output: migration 1003, the schema service with its per-tenant loader, the pure validator, three test files.

Rules for every task:
- Locate code by symbol name and re-read the newest definition first; never by line number.
- Domain neutrality: no word, name, code system or example value of any real domain in SQL, code, comments or tests. Test keys and values are invented and described by structure (a key `alpha_code` typed as a code, a key `beta_list` typed as a list, a value of 201 characters).
- SQL follows CONTEXT D-02: `SECURITY INVOKER`, `SET search_path = ''`, schema-qualified names, `PERFORM public.rag_assert_tenant_key(p_tenant_key)` first, the tenant in every predicate, `REVOKE ALL … FROM PUBLIC, anon, authenticated` and `GRANT EXECUTE … TO service_role` on the exact signature. Idempotent; not folded into the setup files. No function, table or trigger of another phase is redefined.
- Only plan 03.3-01 edits Pydantic contracts and generated Zod: import the generated attribute definition, schema and value types under the names its SUMMARY records; declare no second schema for them.
- Logs, typed errors and test failure messages carry ids, counts and code words only: never an attribute value, and never a database message.
- No bump of `LEXICAL_VERSION`, `EMBEDDING_TEXT_VERSION`, `HASH_NORMALIZATION_VERSION`, a profile `version` or a `pack_version`. No existing file is edited by this plan, so with the switch off nothing changes.
- PGlite plan: never run at the same time as another fixture-database plan in the same tree (`use_worktrees: false`).
- Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/03.3-templated-collection-ingestion/handoffs/03.3-08-<topic>.md`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin input (keys, types, flags) to the tenant's schema | Tenant-supplied text reaches SQL and later a template renderer |
| One tenant's schema to another tenant | Keys describe what a tenant stores |
| PostgREST clients to the new functions | Service-role only |
| Attribute values to logs and error bodies | Values are tenant data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-801 | Information disclosure | definitions read or changed across tenants | critical | mitigate | Tenant assertion first and the tenant in every predicate; actor checked against `rag_upload_approval_keys`; two-tenant tests in both modes; cache keyed by the tenant key with a two-key test |
| T-03.3-802 | Elevation of privilege | functions callable by anon or a non-admin actor | high | mitigate | INVOKER, empty search_path, REVOKE and GRANT on exact signatures; `not_admin` for writers and no rows for the list; fake-edge test and the static scans |
| T-03.3-803 | Tampering | hostile keys or values (braces, control characters, oversized lists) | medium | mitigate | Key pattern in SQL and service; closed type set; 200-character and 50-value limits; a key is the only text ever placed in a template placeholder check |
| T-03.3-804 | Information disclosure | attribute values or database messages in errors and logs | medium | mitigate | Errors carry key, code and index only; unknown database errors become `unavailable`; marker-value and placeholder-secret tests |
| T-03.3-805 | Denial of service | unbounded definitions per tenant | low | mitigate | Limit of 30 under an advisory lock, tested with a 31st key |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
