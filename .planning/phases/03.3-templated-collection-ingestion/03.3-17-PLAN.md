<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored header (tenant text) to embedding and lexical text | Must never reach the text sent to the model |
| One tenant's header to another tenant's chunks | Maintenance jobs handle several tenants in one batch |
| A tenant setting to every tenant's stored output | The builders are shared by all tenants |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-1701 | Tampering | header text reaching the prompt (injection carrier) | high | mitigate | The header enters only the embedding header line and the lexical prefix; content, parents, assembled context and citation quotes are tested byte-equal and marker-free |
| T-03.3-1702 | Information disclosure | one tenant's header on another tenant's chunk in a mixed batch | critical | mitigate | Reads are grouped by the row's own tenant key and the read function names the tenant in every predicate; two-tenant batch tests at build and rewrite sites |
| T-03.3-1703 | Tampering | every tenant's stored text changing without a switch | high | mitigate | Optional builder fields whose absence returns today's output; no version constant changed; existing text tests and the defaults-equal test pass unchanged |
| T-03.3-1704 | Tampering | a chunk whose embedding and lexical text hold different header states | medium | mitigate | In-step rule at rewrite sites; the stamp written with the texts at build sites; stale listing and rebuild selection |
| T-03.3-1705 | Information disclosure | header or values in logs, traces or stage details | medium | mitigate | Counts and code words only; hot-path log test with the marker |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
