# Phase 3.3 Plan 17: Attribute header in embedding and lexical text Summary

**The tenant's stored attribute header now reaches the embedding text and `lexical_text` of its chunks at every build and rewrite site,
every chunk records which header it was built with, and a header change is rebuilt side by side through `rag:rebuild --mechanism rechunk`.
The text sent to the model never holds the header, and with the switch off nothing changes.**

In-step rule: rewrite sites take a header only from the chunk-mode read, which returns rows only for chunks whose stamp equals their
document's; every other chunk gets today's text. Metadata key `ATTRIBUTE_HEADER_STAMP_KEY` (`attribute_header_stamp`), clearing value
`ATTRIBUTE_HEADER_STAMP_NONE` (`none`), both from 03.3-15. A failed header read: ingest stages fail with `attribute_header_read_failed`;
re-chunk fails the run with that reason; re-embed fails the batch with that reason (resumable); recaption fails the run (resumable); relex
throws `RelexInputError('rpc_failed:rag_attribute_headers')`; rebuild throws `RebuildUnavailable('rag_attribute_header_stale')`.

Builders: `EmbeddingTextInput.attribute_header?: string | null` — a string (also `''`) replaces `template_header`; null/absent is today.
`ChunkLexicalInput.attributeHeader?: string | null` — non-empty is pushed onto the path prefix (after a legacy title), before image extras,
body and row lines. No version constant, profile version, pack version or `embedding_text_version` changed; no SQL function redefined.

## Rebuild selection

- `selectAffected(candidates, mechanism, proposal, staleHeaderIds?)`: for `rechunk` the stale ids are selected (each once, with or
  without a fingerprint) together with the fingerprint-affected ones; other mechanisms ignore the set; without it the result equals today.
- `rebuildSettingsHash(mechanism, proposal, staleHeaderDigest?)`: the digest is hashed only when given (pinned today's hex
  `0a39141b…aa27646` for one fixed input). `startRebuild` passes a digest only when the stale set is non-empty: sha256 of the canonical JSON
  of sorted `[tenant_key, document_id, document_stamp]` triples. A changed stamp gives a new hash and a new `rb-` profile id.
- Only for `rechunk` while `attributeHeaderEnabled()`; switch off: no listing, selection, hash and plan equal today. `planRebuild` unchanged.
- Only candidates of the tenant whose listing named them count.

## Behaviour changes

None while `RAG_ATTRIBUTE_HEADER` is effectively off (default): no header read anywhere, texts and metadata byte-equal (no new key),
relex callers that pass nothing (the fixture harness) never read. With the switch on and no template: texts equal today, build sites write
the stamp key with `none`. With a template: the tenant's header is in embedding text and `lexical_text` of its chunks, never in content,
parents, the assembled context or citation quotes (tested with a marker).

## Deviations

- New test file `tests/rag-db/attribute-header-sites.test.mts` instead of extending `tests/rag-db/attribute-header.test.mts` (left as 03.3-15
  wrote it): the suites of that file load `env.ts` and the language settings before the fake edge exists, which freezes the Supabase URL.
- `src/lib/rag/ingest/relex/cli.ts` (not in files_modified) passes `attributeHeader: currentIngestConfig().attributeHeader` to relex. Relex
  takes the switch from its caller like `tableRowSerialization`: reading the switch inside relex built the ingest deps inside the fixture
  harness before its environment existed and broke later ingests.
- Recaption also gets the header in the `lexical_text` it rewrites (plan named only the embedding text), so a recaptioned chunk keeps one
  header state in both texts.
- `deferredGroups` in `backfill/orchestrate.ts` is exported for the unit test.
- The re-chunk stage proof of "a resumed run writes the same texts" relies on the stored-header read being repeated per call (same stored
  value); no separate resume test was added.
