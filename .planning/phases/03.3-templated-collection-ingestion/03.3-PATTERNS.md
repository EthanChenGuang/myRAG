**How to use this file.** Trunk moves under this phase, so every anchor is a **symbol name inside a file**. Line numbers are never given. Excerpts were copied on the mapping date; before copying one, find the symbol again and use what is there. Every trunk analog path below returned a non-empty `git ls-files`. Analogs that exist only on an unmerged branch are marked **[branch]** with the ref to read them from; a plan that needs one is gated on the matching `*-SUMMARY.md` (CONTEXT D-01) and re-reads the merged definition.

**Domain neutrality.** Some analog files contain example-domain vocabulary (dimension names in `ingest/scopes/*`, kind names in the chunker registry, a sample template in the comment above `renderTemplateHeader`, fixture text under `eval/fixtures/ingest/`). Copy the *shape* only. No new module, comment, default, test or fixture repeats any of those words; excerpts here elide them with `// ...` where that keeps the excerpt real.

**Where the inputs disagree with each other or with the code** (the planner carries these into the plans).

1. **Migration numbers.** RESEARCH.md "SQL conventions and migration allocation" lists 1003 = review flag, 1004 = attribute definitions, 1006 = identifier feed, 1007 = header template. CONTEXT D-02 and the plan index say 1003 = attribute definitions, 1004 = `rag_flag_document_review`, 1006 = header template, 1007 = identifier feed. **CONTEXT and the plan index win.**
2. **Column name.** RESEARCH.md writes `documents.attribute_stamp`; CONTEXT D-02 and D-26 write `documents.attribute_header_stamp`. Use the CONTEXT name on both tables.
3. **Security mode of the closest SQL analog.** Every function in `0805_scope_tags.sql` is `SECURITY DEFINER` with `SET search_path TO ''`; `0818_upload_scopes.sql`, `0851` and the functions of `0858` **[branch]** are `SECURITY INVOKER`. D-02 requires INVOKER for every new function except trigger functions that write across RLS. Copy the *body* of the 0805 setter and the *header* of 0818 / 0858.
4. **`NOTIFY` position.** 0818 sends `NOTIFY pgrst` after `COMMIT`; 0851 and 0854 send it before. Use the 0854 order (inside the transaction).
5. **Worker flags.** The RESEARCH.md worker example passes `flags: 'gu'` literally. Stored flags are `'u' | 'iu'`; the compile flags come from `validateIdentifierPattern(...).flags` (`'gu' | 'giu'`). The wrapper passes the validator's value, never a literal.
6. **`terminology` is half on trunk.** The stage name, its timeouts and its latency budgets are on trunk (`OPTIONAL_STAGES`, `V2_*` tables in `config.ts`, `eval/config/latency-budgets.json`), but `runTerminologyStage` and the `afterTransforms` hook of `runQueryLayer` exist only on `origin/exec/04.1.1-06`. `attribute_resolve` "sits where the terminology stage sits" (D-29), so plan 19 needs that hook; it is covered by the 04.1.1-06 gate.
7. **The exact-id leg stands down under any document-id filter.** `hasNarrowingFilters` in `v2/stages/search.ts` returns true for a non-empty `filters.documentIds`, and the `exact_id_lookup` block is disabled then. A hard attribute filter therefore switches that leg off for the request (RESEARCH Pitfall 7). Record it on the trace; do not change `hasNarrowingFilters`.
8. **Cache key.** `cacheKeyFilterParts` in `cache/keys.ts` carries only `scopes`, `scopesIncludeUntagged` and `effectiveOn`; it has no document-id part and no caller in `src/` yet. D-30 puts the resolved attribute state into the retrieval config hash, which is already a key part (`retrievalConfigHash`). The explicit `attributes` filter needs either that same block or its own optional key part; plan 19 decides and tests it.
9. **`03.3-UI-SPEC.md`** was written after this map started (it is in the phase directory now); the six static controls of plan 02 follow it.
10. **No `phase42_gate.py` on trunk.** The 4.2 gate tool named as a precedent in RESEARCH.md is unexecuted. The on-trunk analog for a pre-registered gate file plus tool is `eval/config/defaults-gate.json` with `eval/src/rag_eval/defaults_gate.py`.

**Stamp trigger (1001 column, 1006 trigger body).** Analog: the whole of 0851. Copy the function and the trigger, replacing the key, the column and the value check:
```sql
CREATE OR REPLACE FUNCTION public.rag_chunk_lexical_dict_version()
RETURNS trigger LANGUAGE plpgsql SECURITY INVOKER SET search_path = '' AS $fn$
DECLARE
  v_value text;
BEGIN
  IF NEW.metadata IS NULL OR pg_catalog.jsonb_typeof(NEW.metadata) <> 'object' THEN
    RETURN NEW;
  END IF;
  IF pg_catalog.jsonb_typeof(NEW.metadata -> 'lexical_dict_version') IS DISTINCT FROM 'string' THEN
    RETURN NEW;
  END IF;
  v_value := NEW.metadata ->> 'lexical_dict_version';
  IF v_value ~ '^s[0-9]{1,9}(\.w[0-9]{1,9})?$' THEN
    NEW.lexical_dict_version := v_value;
  END IF;
  RETURN NEW;
END
$fn$;
-- CREATE TRIGGER ... BEFORE INSERT OR UPDATE OF metadata ON public.document_chunks FOR EACH ROW ...
```
It touches only `NEW`, so it stays INVOKER; a write without the key leaves the column as it was. The 0851 header states why the lexical trigger and the chunk writers are not redefined; say the same for `template_row` builders.

**1002, 1003, 1006 (CRUD over a tenant settings table).** Analog **[branch]**: `git show origin/exec/04.2-14:supabase/migrations/0858_identifier_functions.sql`. Shape of a writer (`rag_identifier_pattern_create`):

## Shared Patterns

### Tenant scope in TypeScript
**Source:** `exactIdLookup` in `src/lib/rag/retrieval/exact-id.ts`; `tenantKeyOf` in the branch pattern service
**Apply to:** every new service, loader and resolver
Admin services take `{ actorUserId, tenantKey, signal }` from the route guard instead (`ScopeAdminInput`). No request field, env value or file content names a tenant, except `--tenant` on a CLI, which is checked with `backfillScope`.

### SQL function frame (D-02)
**Source:** `0818_upload_scopes.sql`, `0854_identifier_index.sql`, `0858` **[branch]**
**Apply to:** every function in 1002 to 1009
```sql
LANGUAGE plpgsql SECURITY INVOKER SET search_path = ''
-- first statement:
PERFORM public.rag_assert_tenant_key(p_tenant_key);
-- every predicate names the tenant; built-ins are pg_catalog.-qualified
REVOKE ALL ON FUNCTION public.<fn>(<exact signature>) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.<fn>(<exact signature>) TO service_role;
NOTIFY pgrst, 'reload schema';
```
`BEGIN; ... COMMIT;`, idempotent forms only (`IF NOT EXISTS`, `CREATE OR REPLACE`, `DROP TRIGGER IF EXISTS`), a header comment with purpose, security mode, purge statement and "Idempotent; not folded into the setup files". Admin writers take `p_actor uuid` and test `p_tenant_key = ANY (public.rag_upload_approval_keys(p_actor))`. No function owned by another phase is redefined.

### Fixed code words from SQL to the caller
**Source:** `failureOf` in `ingest/scopes/admin.ts`; `callRpc` in the branch pattern service
**Apply to:** rule, schema, template, attribute and import services
The first word of the SQL message (`/^[a-z_]+/`) is looked up in a fixed set; anything else becomes `unavailable` (or `backend_error`); SQLSTATE 22023 maps to an invalid-argument code. A database message never leaves the module.

### Tenant-keyed cache with a test reset
**Source [branch]:** `store` / `invalidate` / `reset…ForTests` in `identifiers/patterns.ts`; `cacheEntryFor` / `invalidateTerminologyCache` in `terminology/load.ts`
**Apply to:** rule loader, attribute schema loader, value lexicon, header template read
`Map` used as an LRU (delete then set on a hit, evict the first key over the cap), a TTL from the injected clock, a shorter TTL after a failure, invalidation by the writers, one two-tenant test.

### Switch enabled test and ignored-input warning
**Source:** `uploadScopesEnabled`, `warnUploadScopesIgnored` in `ingest/scopes/upload.ts`
**Apply to:** attributes on upload and manifest, the four ingestion switches
Input that arrives while the feature is off is ignored with one warning that carries a count and a fixed reason.

### Once-only configuration warnings
**Source:** `problem(warnings, key, message, data)` in `ingest/config.ts` and `config.ts`; `logOnce` in `v2/startup.ts`
**Apply to:** unmet needs (D-03), unknown values, the hard-filter startup warning, a closed upstream gate's fallback
Prefix `[RAG Config]`; one line per key per process; each module with such a set has a `reset…ForTests`.

### Optional v2 stage
**Source:** `runStage` / `stageSpec` in `src/lib/rag/pipeline.ts`, used in `v2/stages/search.ts` (the `exact_id_lookup` block)
**Apply to:** `attribute_resolve`
`onFail: 'skip'`; the name is in `OPTIONAL_STAGES` with a timeout per profile and a latency budget; switched off through `applyV2DisabledStages`.

### Log and trace content
**Source:** stage options above; the `console.log('[RAG Admin] ...', { id, count })` lines of the scope routes; `console.error('[Ingest] upload scope tags not stored', { reason, code })`
**Apply to:** every stage, route, CLI and ingest hook of the phase
Counts, ids and fixed codes only. Never a pattern, heading name, attribute key's value, template text, removed line or query text. Prefixes: `[Ingest]`, `[RAG Admin]`, `[RAG Config]`, `[Document Search]`, and a `[<Tool>]` prefix per CLI as `[Backfill]`.

### Off-identity
**Source:** `tests/rag-e2e/defaults-equal-phase3.test.mts`; `buildPayload` in `v2/config-hash.ts`; `OmitNoneModel`; `tests/rag/lexical-options-identity.test.ts`

### Public surface of `@/lib/rag`
**Source:** `src/lib/rag/index.ts`; rule `deep-import` in `scripts/ci/check-rag-boundary.mjs`
