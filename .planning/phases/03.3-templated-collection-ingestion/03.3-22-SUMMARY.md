## Metrics (D-36)

Per item, computed from the golden tags and the run's own trace:
- `named_document_hit` (tag `feature:attribute_named`): a kept chunk at rank 5 or better belongs to the asked document. The asked document is the first gold span's document, compared case-folded. A refused item counts as False.
- `wrong_document_at_1` (same tag): the rank-1 kept chunk belongs to another document. None when nothing is kept.
- `variant_correct` (tag `feature:variant`): the rank-1 kept chunk matches a gold span. A refused item counts as False.
- `quantity_matched` (tag `feature:quantity`): None when the run's lexical leg did not run. Otherwise True when a candidate with lexical rank 1 matches a gold span.
- `attribute_filter_fallback`: the block's `fallback` flag. It is None when the trace has no block or no hard filter was attempted. "Attempted" means `mode == hard` and either `explicit` or `matched_attributes > 0`.

Per slice:
- `named_document_recall`, `wrong_document_at_1`, `variant_accuracy`, `quantity_match_rate` and `attribute_filter_fallback_rate`: the mean over defined values. They stay unset when n is 0.
- `boilerplate_token_share` (`metrics.boilerplate_token_share` / `templated_boilerplate_share`): set only on `by_category.templated_collection`, and only when the golden set holds such items. It is computed over the distinct candidate chunks of templated fixture files. Text is compared after NFKC, whitespace collapse and replacing each digit run with `0`. Tokens are letter/digit runs, with each Han character counted alone. The declared top, bottom and fragment lines are counted; footer lines are not. n is the chunk count.
- `report.md` gains a "Templated collection" section only when one of these values is set. A report with no templated item dumps byte-equal to the snapshot recorded with the pre-change code.

## Gate tool

- `python -m rag_eval.phase33_gate check --spec <file>`: validates the gates file, every run it names (present in the comparison spec with the fixture mode its name ends in) and the noise file. Exits 0 or 2.
- `python -m rag_eval.phase33_gate evaluate --spec <file> --reports <harness dir> --out <dir>`:
  - Reads `<dir>/<run>/{report.json,traces.jsonl,run.json}` plus the golden file that run.json names.
  - Writes `gates.json` (spec sha256, last commit and commit count, and per gate: measures, offenders, alignment) and `README.md` (requirement-to-gate table).
  - Exits 0 when every gate passes, 1 when one fails, 2 on an invalid spec or a missing run, and 70 on an internal error.
- Missing data, or fewer than `min_dev_items` defined dev values, fails a gate with `missing_data`.
- The `tpl-v2-off` reference is built with `baseline_from_report`. It is aligned on the run's `corpus_sha256` and request options, and every alignment is recorded.

## Deviations and decisions

- **Commit order.** The gates file is the last commit of the plan's own files. The SUMMARY comes after it because the executor brief commits the SUMMARY last.
- **"Hard filter attempted"** means `mode == hard` and (`explicit` or `matched_attributes > 0`).

- **Missing data on tag gates.** The named-document gate needs at least `min_dev_items` defined values for recall, wrong document at rank 1 and cited document each. The boilerplate gate fails as missing data when either share is unmeasured or n is 0.
- **Snapshot file.** The byte-equal snapshot lives at `eval/tests/data/templated-off/`, with its shared inputs in `eval/tests/test_templated_off_inputs.py`. Neither path is in `files_modified`.
- **Purge hooks.** No new store, so no purge hook. No migration, so no migration number was claimed.
