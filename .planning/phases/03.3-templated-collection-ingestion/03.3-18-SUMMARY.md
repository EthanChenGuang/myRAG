no request changes. Plan 03.3-19 wires the stage.

## TypeScript reference

`config/rag/attribute-filter.json`: `{ schema_version: 1, rules_version: 1, soft_weight: 0.5, id_cap: 2000 }` (fixture-fitted starting
values, D-30). `attributeFilterConfig()` memoised; `setAttributeFilterConfigForTests(config | null)` parses the override.

`src/lib/rag/retrieval/attributes.ts`:
- `attributeLexiconFor(scope, options)`: `rag_attribute_filter_values` with `p_limit = 5001`; LRU of 256 tenant keys, 60 s TTL, 10 s after a
  failure (a cached failure rethrows); key = `scopeKey(scope)`; matcher built lazily per `minHanChars` via `buildMatcher`, one entry per
  (key, value), `kind` `identifier` for `code`, `alias` otherwise. Values with fewer than two letters/digits or that are lexical stop words
  get no entry; short Han values are dropped by `buildMatcher`. Over the cap: `truncated`, empty matcher.
- `invalidateAttributeLexicon(tenantKey | 'all')`, `resetAttributeLexiconForTests()`, `attributeLexiconSizeForTests()`.
- `resolveAttributeFilter(scope, query, explicit, options) → AttributeResolution`:
  `{ explicitIds: string[] | null; hardIds: string[] | null; softIds: string[]; counts: { explicitKeys, matchedKeys, aliasMatches, ambiguous, softKeys }; tooBroad; lexiconTruncated; lexiconUnavailable; aliasUnavailable; stateDigest: string | null }`.
  Options: `signal`, `client`, `now`, `config`, `terminology` (else `config.v2.terminology`), `terminologyLoader`, `minHanChars`.
- Rule for explicit keys: a key of the explicit filter is never resolved automatically (and is excluded from the ambiguity check); the
  explicit filter is resolved with one rpc even when the lexicon failed or is truncated.
- Calls: explicit (one rpc), hard automatic keys (one rpc, AND), soft keys (one rpc), each ambiguous value once per key; `p_limit = id_cap + 1`.
  A result above the cap is too broad: not returned as explicit/hard, first `id_cap` ascending ids go to `softIds`.
- `stateDigest`: SHA-256 hex over `{ explicit, hard, soft, ambiguous, tooBroad }` with sorted keys and values.
- Errors: rpc message starting `unknown_attribute` → `AttributeFilterError` (400; path `attributes.<key>` for explicit keys absent from the
  lexicon, else `attributes`); anything else → `RetrievalBackendError` (code only). Logs: one `[Document Search]` warning with the code when
  the lexicon is unavailable.

`src/lib/rag/query/filters.ts`: `parseRetrievalFilters(body, { attributeFilter? })`; while off the strict schema answers
`[{ path: 'attributes', message: "Unrecognized key(s) in object: 'attributes'" }]`. While on: limits of D-12 with paths
`attributes`, `attributes.<key>`, `attributes.<key>.<index>`; keys and values sorted, values de-duplicated, empty lists dropped.
`buildRetrievalFilters({ ..., attributeDocumentIds? })` intersects last; empty → `[NO_DOCUMENT_ID]`; never copies `attributes`.
