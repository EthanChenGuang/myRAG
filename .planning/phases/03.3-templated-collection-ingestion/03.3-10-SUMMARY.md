# Phase 3.3 Plan 10: Page boilerplate cleaning in ingestion — Summary

**With `RAG_PAGE_BOILERPLATE` on, repeated page lines and tenant-ruled lines are removed between parse and chunk, in the chunk stage and in `rag:rechunk`. Each document gets a report and review flags when needed, and a resumed run replays the same removal. With the switch off, nothing changes: no call, no read, no write, no snapshot.**

Every SUMMARY in the transitive `depends_on` exists: 03.3-01..05, 03.3-07, 04.2-01/03/04/14/34, Phase 4 and Phase 4.1. 1004 was free on every origin branch, so this plan claimed and pushed it first. No hand-off was needed for the gate.

Shapes read from the upstream SUMMARYs:
- `ChunkPrepSnapshot { fingerprint; boilerplate?: { mode, cleanerVersion, rulesVersion, ruleIds: {id, version}[], removedLineKeys: string[] }; sectionRules?; warnings: string[]; truncated }`. The removed-line list is a single `string[]`, so the 03.3-05 removal record `{ keys, lineDigests }` goes into it as tagged entries: `k:<lineKey>` and `d:<lineDigest>`. `ingest/types.ts` was not edited.
- `chunk_prep`: `{ boilerplate?: { mode, cleaner_version, rules_version, rule_fingerprint (64 hex) }, section_rules?: { rule_set_id, version } }`, with at least one sub-part.
- Loader: `TenantRules { ruleSet, boilerplateRules: { id, version, kind, pattern, flags, maxLength, minPageShare, docType, source }[], ruleIds, fingerprint, loadFailed, skipped }`.
- Cleaner removal record: `{ keys: string[]; lineDigests: string[] }`, both sorted.
- Wrapper verdict: `{ kind: 'ok', hits: { inputIndex, patternId, start, end }[], skipped } | { kind: 'timeout' } | { kind: 'error', error }`.

## API for 03.3-12, 03.3-17, 03.3-24

```ts
prepareChunkInput({ markdown, parseChunks, pageLines, baseChunker, mode: 'detect'|'rules'|'both', rules?, snapshot?, deadlineMs?, signal? })
  -> Promise<{ markdown, parseChunks, chunker /* === baseChunker in this plan */, report: BoilerplateReport, review: ReviewCode[], warnings: string[], snapshot: ChunkPrepSnapshot }>
loadPageLines(context: ArtifactContext, { reuseOfVersion? }) -> Promise<PageLines | null>   // docling.json, then page-texts.json, then the reused version's page-texts.json
applyPrepareOutcome({ writer, db, documentId, tenantKey }, { report, review }, { signal? })   // metadata.boilerplate via setFields, one rpc per review code
needsPatternCall(mode, rules, snapshot?) / needsPageLines(mode, rules) / candidateLines(markdown) / uncleanedSnapshot(mode)
REVIEW_CODES = ['section_rules_not_satisfied', 'boilerplate_above_threshold', 'tenant_pattern_timeout']
TENANT_RULES_UNAVAILABLE, BOILERPLATE_SNAPSHOT_TOO_LARGE, PREPARE_FAILED ('prepare_failed'), NO_RULES_FINGERPRINT ('0' x 64)
CHUNK_PREP_SNAPSHOT_CAP = { maxEntries: 2000, maxJsonBytes: 262144 }
```

- Order inside the function: candidate lines (distinct, trimmed, outside fences, not table rows, not titled headings, at most 200 characters, at most 20,000 lines), then at most one wrapper call, then `cleanBoilerplate` with `protectedLines: []` (03.3-12 fills it), then the text map over the parser chunks, then the review codes and the snapshot. With a snapshot, only `replayRemoval` and the text map run.
- Snapshot fields used: `fingerprint` (the loader fingerprint, or 64 zeros when no rule was consulted), `boilerplate.{mode, cleanerVersion, rulesVersion, ruleIds (boilerplate rules only), removedLineKeys (tagged)}`, `warnings` (warning codes plus `tenant_pattern_timeout`, which a replay cannot recompute), `truncated`. `sectionRules` is left for 03.3-12.
- Over the cap, nothing is applied. The warning is `boilerplate_snapshot_too_large`, `truncated` is true, `removedLineKeys` is `[]`, and a replay applies nothing.
- A wrapper `error` verdict, or a failed loader result, gives the warning `tenant_rules_unavailable` and cleaning by detect only.
- Review codes are pushed as warnings only through the existing `includes` guard. They are stored in `metadata.review_reasons` and on `needs_review` by the rpc.
- Gap detail word in re-chunk: `prepare_failed`. A scope that cannot be resolved stays `tenant_scope_refused`.

Chunk stage (`stages/chunk.ts`): when `ctx.config.pageBoilerplate` is not `off`:
- A caption-only (`image_caption`) chunker is not cleaned. It records `uncleanedSnapshot(mode)`.
- Otherwise the stage uses the snapshot from `ctx.state.chunkPrep`. Without one it loads the rules (`loadTenantRules(ctx.input.scope, { docType: identity.docType, source: ctx.input.source })`, not in detect) and the page lines (only when `needsPageLines`; type-change reuse is skipped for a sanitized parse).
- It yields with reason `deadline` when a worker call is needed and less than 3000 + 2000 ms is left.
- Then it calls `prepareChunkInput` and sets `ctx.work.parseText` / `parseChunks`, runs `applyPrepareOutcome` with `scopeKey(ctx.input.scope)`, and stores the snapshot.
- The off path runs today's statements in today's order.

Re-chunk (`rechunk/run.ts`):
- `prepare` takes a scope resolver: the session's cached `scopeFor`, or, in the dry run, `input.scopeFor ?? defaultScopeFor`.
- It cleans `parse.md` with the tenant's current rules (no snapshot) before `buildProfileChunks`.
- `buildDocument` calls `applyPrepareOutcome` after `writeProfileChunks` succeeds. A failed flag adds the warning `review_flag_failed` and does not stop the run.
- Worker deadline: `TENANT_LINE_DEFAULT_DEADLINE_MS`. The command has no per-document budget to compare against.

Page-text artifact restore paths:
- The fixed LlamaParse chain adds `page-texts.json` to `attempt.artifacts` only. `result.artifacts`, the Markdown, `page_count` and the request are unchanged, so no cache key changes. `applyParseResult` stores the artifact.
- The parse cache (`parse-cache.ts`, also used by the queued parse-external callback) stores and restores every attempt artifact, page-texts included.
- A cache entry made while the mode was off has no page texts. A hit on it then gives `boilerplate_pages_unavailable` for a LlamaParse document.
- A type change does not copy `page-texts.json`. `loadPageLines` falls back to the reused version's copy.

Fingerprint:
- `collectFingerprintParts` adds `chunk_prep` only when `ctx.state.chunkPrep` exists. `expectedFingerprintFor` adds, replaces or removes the boilerplate sub-part for a proposed `RAG_PAGE_BOILERPLATE`.
- It removes `section_rules` for `RAG_SECTION_RULES=off` and leaves it for `on`. `needsRechunkDryRun()` / `ImpactCounts.needsRechunkDryRun` mark that case.
- `RAG_PAGE_BOILERPLATE` is in the variables whose saved value is compared (`savedFingerprintValues` reads the effective ingest mode).

## Behaviour changes

With `RAG_PAGE_BOILERPLATE` effectively off: none. With it on (unified pipeline only):
- Cleaned text reaches the chunks, the dual-write profiles and `documents.content`. `parse.md` and the version content hash stay raw.
- The report is stored in `metadata.boilerplate`. A document is flagged `needs_review` with `review_reasons` and is still published.
- LlamaParse stores `page-texts.json` (detect or both).
- The fingerprint carries `chunk_prep`.

## Deviations

- **`status.ts` edited** (not in `files_modified`): needed for the resume truth (D-09); see the bug fix above.
- **Re-chunk DB cases are in their own file, `tests/rag-db/boilerplate-rechunk.test.mts`.** The Supabase admin client is a process singleton bound to the first fixture's edge, so a second fixture database cannot share a file.
- **The DB pipeline tests use the text parser.** The full-pipeline `both` case with Docling page structure and Docling chunks is covered at function level instead: the detect, Docling-chunk field mapping and page-lines cases in `prepare-chunk-input.test.ts`. The pipeline-level cases cover a tenant line rule in `rules` mode, `detect` without page structure, two-tenant isolation, resume after a deleted rule, and the flag function in both modes. Above-threshold flagging and the timeout flag are proven at stage level with a fake rpc.
- **Call-site identity is not a separate DB test.** The two call sites pass the same stored `parse.md` and the same rule data to the same function. `dualWriteProfiles` chunks `ctx.work.parseText`, which is the cleaned text (planner note c).
- **`DryRunRechunkInput.scopeFor`** (optional) was added. The default backfill resolver cannot resolve personal tenants in the fixture, and an operator may also want the session resolver. Without it the dry run uses `defaultScopeFor`, as planned.
- **`FingerprintImpact` has no `needs_rechunk_dry_run` field.** It is strict and generated, so the marker is internal (`ImpactCounts.needsRechunkDryRun`). See `handoffs/03.3-10-impact-dry-run-marker.md`.
- **Two choices the plan left open.** A wrapper `error` verdict maps to the warning `tenant_rules_unavailable`. A failed review flag in re-chunk becomes the run warning `review_flag_failed`.
- **The migration was committed before its test,** to claim number 1004 across parallel executors. Its tests came in the Task 3 RED commit and pass.
