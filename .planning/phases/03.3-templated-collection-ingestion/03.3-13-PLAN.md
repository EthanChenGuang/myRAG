<objective>
Give an operator one command that sets the attributes of a tenant's documents from a file, by source key, with a report before anything is written.

Purpose: TPL-04, first half (CONTEXT D-24, D-23, D-12; RESEARCH Pattern 4, pitfall 9). The identifier feed is plan 03.3-16 and the header re-render plan 03.3-15; both hook in behind this plan's run function.
Output: `attributes/import.ts`, `attributes/cli.ts`, the `rag:attributes` script, two test files.

Rules for every task:
- Locate code by symbol name and re-read the newest definition first; never by line number.
- The import file is JSON Lines, one object per line with `source_key`, `attributes` and an optional `source` (absent: the backfill source exported by plan 03.3-11); it is parsed with the generated import-row schema of plan 03.3-01, never a second schema. The file is tenant data and lives outside the repository: tests write their files to a temporary directory, and no import file is committed.
- Domain neutrality: test keys, values and source keys are invented and described by structure (`alpha_code`, `beta_list`, source keys `set-a/item-001`, a marker value used only to prove it is never printed).
- The tenant is named only by `--tenant` and checked with `backfillScope`; no line of the file can name a tenant.
- No SQL in this plan: every write goes through `importAttributeRows` of plan 03.3-11. No parser, chunker, embedding or object-store call.
- Output and logs carry counts, line numbers, code words and attribute keys, never a value; prefix `[RAG Attributes]`.
- With the switch off the command writes nothing; no existing file other than `package.json` is edited.
- Task 3 runs a PGlite test: never run it at the same time as another fixture-database plan in the same tree (`use_worktrees: false`).
- Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/03.3-templated-collection-ingestion/handoffs/03.3-13-<topic>.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator command line to tenant data | `--tenant` selects whose documents are rewritten |
| Import file to the database | Keys, values and source keys are untrusted text from outside the repository |
| Values to terminal output and logs | Values are tenant data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-1301 | Information disclosure | an import reaching another tenant's documents | critical | mitigate | Tenant only from `--tenant` through `backfillScope`; the import function names the tenant in every predicate; same-source-key test with two tenants in both modes |
| T-03.3-1302 | Tampering | hostile file (unknown keys, wrong types, oversized values, repeated keys) | medium | mitigate | Generated row schema, `validateAttributes`, all-or-nothing refusal with exit 3, SQL re-check per batch |
| T-03.3-1303 | Denial of service | one statement updating every chunk of a large collection | medium | mitigate | 50,000-row cap, batches of 200 rows, outbox effect printed, an equal value updates no row |
| T-03.3-1304 | Information disclosure | values in output or logs, or an import file committed to the repository | medium | mitigate | Counts, line numbers, code words and keys only; marker-value test; test files live in a temporary directory |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
