# Phase 3.3 Plan 06: rule_sections Chunker Summary

**The pure chunker kind `rule_sections` cuts a document into the sections a tenant rule set allows, using only resolved hit data. It is registered for the chunk stage, re-chunk and parent-child. No document selects it yet, so every stored output stays byte-equal.**

## Contract field names (Task 1 gate)

The gate passed: the 03.3-01 SUMMARY exists, `rule_sections` and `section_rules` are in `contracts.generated.ts`, and no chunker module existed before this plan. From `ProcessingProfileSetSchema` → `profiles[].chunker`:

- `kind`: one of `markdown_sections | legal_clauses | table_aware | invoice | image_caption | rule_sections`
- `section_rules` (optional, strict): `rule_set_id` (lower-case UUID), `version` (int >= 1), `skip_toc` (bool, default true), `toc_min_run` (int 2..20, default 3), `hits`: record of trimmed line text → `{ name: string 1..80, level: int 1..6, restart: bool default false }`. The Pydantic side caps `hits` at 5000 entries with keys of 1..1000 characters that are already trimmed. The Zod record does not enforce the caps.

## Exported API (for plan 03.3-12)

`src/lib/rag/ingest/chunkers/rule-sections.ts`:

```ts
type ResolvedSectionRules = NonNullable<ProcessingProfile['chunker']['section_rules']>;
type SectionHeadingHit = ResolvedSectionRules['hits'][string];
interface RuleSectionsOptions extends MarkdownChunkOptions { rules?: ResolvedSectionRules | null }
const RULE_SECTIONS_WITHOUT_RULES = 'rule_sections_without_rules';

function scanRuleSections(markdown: string, rules: ResolvedSectionRules | null | undefined): RuleSectionScan;
function chunkRuleSections(markdown: string, options: RuleSectionsOptions): ChunkResult;

interface RuleSectionScan { events: RuleHeadingEvent[]; sections: RuleSection[]; variants: RuleVariant[] }
interface RuleHeadingEvent {
  lineIndex: number;          // line index after CRLF normalisation and split at '\n'
  text: string;               // trimmed line text, the hit key
  name: string; level: number; restart: boolean;
  variantIndex: number | null; // 1-based; null before the first occurrence or with fewer than two occurrences
  skippedAsToc: boolean;
}
interface RuleSection { path: string[]; lines: string[]; heading: number | null /* index into events */; variantIndex: number | null; variantLabel: string | null }
interface RuleVariant { index: number; label: string; lineIndex: number }
```

- With an empty or absent `hits` map, `scanRuleSections` returns no events and one section (empty path, all lines). `chunkRuleSections` packs that section and returns the warning `rule_sections_without_rules`.
- Registry: `CHUNKERS.rule_sections = (markdown, config, sentences) => chunkRuleSections(markdown, { ...budget(config, sentences), rules: config.section_rules })`.
- Chunk metadata on variant chunks: `variant_index` (1-based integer) and `variant_label`. Every chunk has `page_start`/`page_end` null.

## Walk rules

- **Heading test:** a line is a heading only when its trimmed text is an own key of `rules.hits` (`hasOwnProperty`). The test ignores lines inside fenced blocks, fence lines and table lines (a line that starts with `|`, a separator row, or a pipe line directly followed by a separator row). Markdown heading lines that are not hits stay in the body unchanged.
- **Nesting:** a hit of level L pops every open entry of level >= L, then pushes itself.
- **Variant label:** the trimmed occurrence text, with Markdown heading marks stripped via `HEADING`, cut to 80 code points. When any two labels of the document are equal, every label gets `" " + index` appended.
- **Variants:** a document has variants only when at least two restart-flagged hits occur outside skipped runs. Each occurrence starts variant n and resets the heading stack. Every section from the first occurrence on gets the label as its first path element. Text before the first occurrence gets neither the label nor the metadata keys.
- **Table-of-contents runs** (with `skip_toc`; K = `toc_min_run`): a run is consecutive hit events with only blank lines between them. A run of at least K is skipped except its last line, which opens its section. Clarification 1 (planner): the last line of a run is the heading of the body that follows. Clarification 2 (planner): a run whose levels deepen at every step is a heading chain and is kept. A hit inside a skipped run is not a restart occurrence, but its event still records the variant open at its position.
- **Packing:** each section goes through `chunkTableSection(path, lines, budget, warnings)`, so splitting, whole-row table cuts and packer warnings work as in every other chunker.
- **Parent-child:** structure mode takes one parent per rule section up to the parent cap, and every child keeps its parent's path with the variant label first. `none` mode cuts children by rule sections. `fixed` mode never calls the registry: its output equals the `markdown_sections` fixed output. Parent-child drops the variant metadata keys (D-19), but the path keeps the label.
