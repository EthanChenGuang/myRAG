  <behavior>
    - `buildQuantityUnits(block, aliases?)` builds the unit table once; `quantityTokens(normalized, units)` is pure, takes text that is already normalised (NFKC, lower case, accents folded) and returns tokens in order of appearance: `_q_` + canonical number + unit symbol.
    - Grammar: a number is digits, optionally in groups of three joined by a grouping separator, with at most one decimal separator followed by digits; then optional whitespace (ordinary or no-break); then the longest unit of the table at that position; the character after the unit is not a letter (end of text counts); the number does not start inside a word or inside a longer digit run.
    - Canonical number: grouping removed, decimal point, trailing zeros and a trailing point stripped, leading zeros reduced to one digit.
    - One quantity, many spellings: `2.5 kg`, `2,5 kg`, `2.5kg`, `2,5kg`, `2,50 kg` each give exactly `_q_2.5kg`; `1.250,5 ml` and `1,250.5 ml` give `_q_1250.5ml`; `10 %` and `10%` give `_q_10%`; `0,75 l` gives `_q_0.75l`.
    - Ambiguity: `1.250 ml` and `1,250 ml` give `_q_1.25ml` then `_q_1250ml`; `0,750 l` gives only `_q_0.75l` (a grouped number does not start with 0); `1.250.000 g` gives only `_q_1250000g`.
    - Not matched: a number without a unit; a unit without a number; a number followed by a word that only starts with a unit symbol; digits that follow a letter directly; a symbol that is not in the table.
    - Aliases: with `aliases` mapping an invented word to a table symbol, number plus that word gives the token with the symbol; an alias whose symbol is not in the table is ignored; the alias word is matched as a literal.
    - Limits: a number longer than 24 characters is skipped; a token longer than 64 characters is dropped, never cut; a 10,000-character run of digits and separators finishes inside the test timeout.
    - Table rules: symbols are compared in NFKC lower-case form; a symbol with whitespace, a quote, a backslash or a digit makes `buildQuantityUnits` throw, naming the index only.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Document and query text to the tokenizer | Untrusted text is scanned for numbers and units on the ingest and request paths |
| Tenant alias words to the matcher | Tenant data reaches the tokenizer through the option (from plan 03.3-21 on) |
| Repository registry data to every tenant's index | A change to the unit block changes tokens for all tenants once the switch is on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-901 | Denial of service | quantity scan on long digit runs | medium | mitigate | One left-to-right pass, 24-character number limit, 64-character token limit; tested with a 10,000-character run |
| T-03.3-902 | Tampering | alias word used as a pattern | medium | mitigate | Aliases are `Map` keys only; no expression is built from tenant text; symbols with whitespace, quotes, backslashes or digits are rejected when the table is built |
| T-03.3-903 | Tampering | lexical query built from tokens | low | mitigate | Every token passes `acceptsToken` (no quote, backslash or whitespace, at most 64 characters), the same rule `rag_lexical_tsquery` enforces |
| T-03.3-904 | Tampering | stored output of every tenant changes without a switch | high | mitigate | Option absent means the same arrays; probe-table literals, existing cases and the fixture corpus are pinned; no version constant and no `pack_version` changes |
| T-03.3-905 | Information disclosure | tenant unit words in the repository | low | mitigate | The registry holds general symbols only; tenant words arrive only through the option |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
