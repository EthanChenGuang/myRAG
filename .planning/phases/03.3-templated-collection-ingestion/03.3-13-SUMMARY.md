# Phase 3.3 Plan 13: rag:attributes import Summary

An operator can set the attributes of a tenant's already-ingested documents from a JSON Lines file by source key, with a dry-run report
before anything is written, in batches of 200 rows, and run the same file again without any change. No parser, chunker, embedding or
object-store call; every write goes through `importAttributeRows` (migration 1005).

## Command reference

`npm run rag:attributes -- --tenant <key> --import <file> [--dry-run | --apply]`

- `--tenant` and `--import` required; `--dry-run` / `--apply` take no value and exclude each other; repeated flag, flag without value,
  unknown option → usage.
- Exit codes: 0 done, 1 failed, 2 report only, 3 file refused, 64 usage (also: switch off, refused tenant, unreadable file). A tenant that
  cannot be checked (`unavailable`) exits 1.
- File: one `{ "source_key", "attributes", "source"? }` per line (strict generated schema); absent `source` → `BACKFILL_SOURCE`
  (`config_upload`); blank lines skipped; duplicate `(source, source_key)` → `duplicate_key`; row 50,001 → `too_many_rows` (reading stops).

Output lines (prefix `[RAG Attributes]`):
- Refused file (exit 3): `rows read: n`, `errors: n`, `  <code>: n` per code (sorted), `  line L: <code>[ <key>]` for the first 50,
  `  ... n more`, `file refused: nothing was written`.
- Dry run: `rows read`, `documents to change`, `documents unchanged`, `rows to stage`, `staged rows unchanged`, `chunk rows to update`;
  without `--apply`: `report only: nothing was written; run again with --apply to write` (exit 2).
- Apply: per batch `batch i of n: documents changed a, unchanged b, rows staged c, chunk rows updated d`; totals `documents changed`,
  `documents unchanged`, `rows staged`, `staged rows unchanged`, `chunk rows updated: <n> in <b> batches`,
  `vector sync outbox rows added: <n>` (exit 0).
- Apply failure: `failed at batch k of n: <word>; k-1 of n batches applied` and `applied batches stay applied; running the same file again
  completes the import` (exit 1).
- Switch off: `SWITCH_OFF_LINE` = `[RAG Attributes] RAG_DOC_ATTRIBUTES is off: it needs RAG_DOC_ATTRIBUTES=true and RAG_INGEST_PIPELINE=unified; nothing was read or written`.

## TypeScript reference

- `readImportFile(path, { signal })` → `{ rows: ImportFileRow[]; errors: ImportLineError[] }`; throws `ImportFileError` when the file cannot
  be read. `ImportFileRow { line; source; sourceKey; attributes }`, `ImportLineError { line; code: ImportLineCode | AttributeErrorCode; key? }`.
- `runAttributesImport(input: { scope: TenantScope; file: string; apply: boolean }, deps: AttributesImportDeps)` →
  `AttributesImportOutcome { exitCode: 0|1|2|3; status: 'done'|'failed'|'report_only'|'refused'; rowsRead; errors; dryRun: ImportTotals | null;
  applied: ImportTotals | null; batches; batchesApplied; changedDocumentIds: string[] }`.
  `ImportTotals { documentsChanged; documentsUnchanged; chunksUpdated; staged; stagedUnchanged; outboxRows }`.
- `AttributesImportDeps { rpc?: RpcClient | null (default getIngestDeps().db()); signal; io: RunnerIo; loadSchema?: (scope, signal) => Promise<LoadAttributeSchemaResult> (default loadAttributeSchema fresh) }`.
- `main(argv, io, signal, overrides: AttributesCliOverrides)`; overrides: `rpc`, `loadSchema`, `resolveScope(tenantKey)`, `enabled()`.
- Hooks for later plans: 03.3-15 (header re-render) and 03.3-16 (identifier re-index) hook in behind `importAttributeRows` and
  `outcome.changedDocumentIds` (apply pass only; empty on a dry run or an unchanged rerun). 03.3-14 adds its script beside `rag:attributes`
  in `package.json` (line after `rag:backfill`).
