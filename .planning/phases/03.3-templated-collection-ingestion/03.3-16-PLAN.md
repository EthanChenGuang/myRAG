<objective>
Make identifiers that live in a document's attributes findable by the Phase 4.2 exact filter and near-miss guard, by feeding them through the one indexer that owns the identifier columns.

Purpose: TPL-04, second half (CONTEXT D-25, D-01; RESEARCH F-13). Until the gate of Task 1 opens, attributes are stored and filterable through TPL-06 and nothing is written to an identifier column.
Output: `attributes/identifier-feed.ts`, a small extension of the 4.2 indexer, the re-index after an import and on request, migration 1007 (one listing function), tests.

Rules for every task:
- The upstream code does not exist at planning time. `files_modified` names the indexer by the path plan 04.2-18 declares (`src/lib/rag/ingest/write-indexers.ts`); Task 1 records the real paths and signatures, and Tasks 2 and 3 follow that record. Locate code by symbol name and re-read the newest definition first.
- Only `indexDocumentForLookup` writes `identifiers_norm` and `identifiers_raw`; this plan adds no second writer, no SQL that touches those columns and no change to a 4.2 migration.
- 1007 is needed for one reason: the 4.2 backfill listing skips documents that are already indexed, and the re-index after a flag change needs the tenant's documents that carry attributes. SQL follows CONTEXT D-02 (INVOKER, empty search_path, tenant assertion first, the tenant in every predicate, REVOKE and GRANT per signature). Idempotent; not folded into the setup files.
- Domain neutrality: identifier examples are shapes (letters, digits, separators) under invented keys such as `alpha_code`; no example-domain word, code system or product name.
- Logs and output carry counts and code words only: never an identifier, a value or a key's value.
- The edit inside the 4.2 indexer is additive and behind both switches; with `RAG_DOC_ATTRIBUTES` off its call list and written rows equal the ones before this plan.
- PGlite plan: never run at the same time as another fixture-database plan in the same tree (`use_worktrees: false`). Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/03.3-templated-collection-ingestion/handoffs/03.3-16-<topic>.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Attribute values to the identifier columns | Tenant-supplied text becomes a filterable identifier |
| One tenant's attribute identifiers to another tenant | The 4.2 lookups read these columns |
| Operator command line to tenant data | `--tenant` selects whose documents are re-indexed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-1601 | Information disclosure | entries from another tenant's attributes or definitions | critical | mitigate | Schema and attributes are read for the indexer's own tenant only; the 1007 listing names the tenant in every predicate; two-tenant tests in both modes |
| T-03.3-1602 | Tampering | a second writer of the identifier columns drifting from the 4.2 rules | high | mitigate | The merge happens inside `indexDocumentForLookup`; no SQL of this plan touches the columns; the re-index calls the same routine |
| T-03.3-1603 | Tampering | hostile attribute value as an identifier | medium | mitigate | Values passed `validateAttributes` (200 characters) and are normalised by `normalizeIdentifier`; an empty normalised form is skipped |
| T-03.3-1604 | Information disclosure | identifiers or values in logs and output | medium | mitigate | Counts and code words only; marker test |
| T-03.3-1605 | Denial of service | re-index of a whole tenant | low | mitigate | Report first, keyset pages of at most 1,000, only documents that carry attributes |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan |
</threat_model>
