  <behavior>
    - `cleanBoilerplate({ markdown, pageLines, mode, config, lineHits, fragmentRules, protectedLines })` with `mode` one of `detect`, `rules`, `both` returns `{ markdown, removal, report, aboveReviewShare, warnings }`. `removal` is `{ keys, lineDigests }`: the sorted normalised keys removed by detect and the fragment rule, and the sorted digests (`lineDigest`: the first 16 hexadecimal characters of the SHA-256 of the trimmed text) of the lines removed as line hits, so the record stays small and holds no tenant-matched text.
    - detect (modes `detect`, `both`): on a six-page document whose pages each open with the same short line and close with a line that differs only in its number, both lines are removed everywhere they stand alone in the Markdown, and no other line changes byte for byte. A key counts for a page when it is among the first or last N keys of that page; it is removed when its page count divided by the page total reaches the page share and its token count is at most the line limit. A line that repeats on every page but sits in the middle of the pages stays; a repeated edge line longer than the token limit stays; a document with fewer pages than the minimum page count (the config key when the contract has one, else the exported constant `MIN_PAGES_FOR_PAGE_RULES` of 3) removes nothing by detect or by the fragment rule, so a one-page document never loses its first and last lines.
    - Fragment rule (modes `rules`, `both`; one entry per tenant fragment rule with a maximum length and a minimum page share): a stand-alone line whose key is at most the smaller of the rule's length and the config maximum, present on at least the larger of the rule's share and the config share of pages, is removed; the same short text inside a longer line stays.
    - Line hits (modes `rules`, `both`): a line whose trimmed text is in `lineHits` is removed; in mode `detect` the set is ignored.
    - No page structure (`pageLines` null): detect and the fragment rule contribute nothing and `warnings` holds `boilerplate_pages_unavailable` once (both need page shares); line hits still apply.
    - Protected classes win over every rule: a line inside a fenced block (and the fence lines), a table row, a Markdown heading with a title, and a line whose trimmed text is in `protectedLines` stay even when their key or text is in a removal set; tests cover each class with a line that would otherwise be removed.
    - A removed line is deleted with its line break; when the lines before and after it are both blank, one of the two is deleted. With nothing to remove the returned Markdown is the input string itself and `lines_removed` is 0.
    - Report (`BoilerplateReport`): `cleaner_version` (`CLEANER_VERSION`), `rules_version` (from the config), `lines_removed`, `tokens_removed` (sum of `countTokens` over removed lines), `share` (removed tokens divided by the tokens of the input Markdown, rounded to four decimals, 0 for empty input). Beside it the result carries the review verdict `share > review share`.
    - Determinism and replay: two calls with equal input give deeply equal output; `replayRemoval(markdown, removal, protectedLines, config)` on the original Markdown returns the cleaned Markdown byte for byte with a report equal to the first one, and on the cleaned Markdown changes nothing; `removalTextMap(removal, protectedLines)` returns a function that applies the same line removal to any text (used for Docling chunk fields), leaves a text without a removed line unchanged and may return an empty string.
    - Line endings: a document with CRLF line breaks keeps them on every surviving line.
    - Never throws on any string; the module contains no regular-expression constructor call and imports no pattern or worker module.
  </behavior>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored parse output (docling.json, page texts) to the reader | Written by a parser from an uploaded file; shape and size are not trusted |
| Cleaning rules to document content | A rule that matches too much deletes real text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-501 | Tampering | cleaner deletes real content | high | mitigate | Protected line classes (fence, table row, heading, protected set) tested one by one; edge window, page share and token limits from one validated file; report with counts and a review verdict; the raw text is never changed by this module's callers (D-07) |
| T-03.3-502 | Denial of service | malformed or huge docling.json | medium | mitigate | Reader never throws, reads at most 10000 pages and 5000 keys per page, returns null for a shape without pages |

| T-03.3-504 | Information disclosure | hidden spans kept in docling.json reach the output | medium | mitigate | The reader yields comparison keys only; removal deletes lines of the Markdown and never copies text from the page structure (D-14) |
| T-03.3-505 | Tampering | thresholds drift into prose or patterns | low | mitigate | Numbers-only walk test and the generated schema |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed |
