<objective>
Give the phase one thin, safe way to check and run tenant line patterns: a save-time check, a static re-check and a run-time match, all built on the validator, probe and worker of plan 04.2-14.

Purpose: TPL-08 for the heading patterns of TPL-01 and the boilerplate line patterns of TPL-02 (CONTEXT D-11; RESEARCH F-23, pitfall 11). Callers come later: plan 03.3-07 (save-time check before every write, static re-check in its loader), plans 03.3-10 and 03.3-12 (run-time match, once per document), plan 03.3-14 (import file validation).
Output: `src/lib/rag/patterns/tenant-line-pattern.ts` and its vitest file.

Rules for every task:
- Locate code by symbol name and re-read the newest definition first; never by line number. The 04.2-14 modules are read from this tree once the gate passes (`src/lib/rag/identifiers/{validate,probe-worker,patterns}.ts`).
- A tenant pattern is attacker-shaped input. This module builds no expression from tenant text and calls no matching method (exec, test, match, matchAll, replace, search, split) with one; every match runs in the 04.2-14 worker under a deadline. No second validator, probe or worker: this module adds only the anchoring rule, the match window, the request limits and the verdict mapping (TPL-08).
- Compile flags handed to the worker are the `flags` field of the validator's result, typed with the validator's exported compile-flag type; they are never written as a literal.
- The module writes no log line. Verdicts and refusals carry ids, input indexes, offsets and finding codes only.
- Domain neutrality: test patterns are shapes (a digit run and a dot at the line start, a run of hyphens, a fixed invented word such as `qorvane`) and test lines are invented; no heading list, line or word of a real domain.
- No existing file is edited and nothing calls the new module in this plan.
- Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/03.3-templated-collection-ingestion/handoffs/03.3-04-<topic>.md`.

Planner note: `validateIdentifierPattern` (04.2-14) constructs the pattern once on the calling thread for its compile check and runs no match with it; that is the only construction outside the worker and it belongs to the shared validator TPL-08 names. The save-time probe is `checkIdentifierPattern` with a sole `no_alphanumeric` finding read as acceptance, so the probe set and the 50 ms rule stay in one place; the gate stops the plan if the merged function no longer decides that rule last.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tenant pattern text to the server's regular-expression engine | JavaScript has no regex timeout; a stored pattern runs on every document of its binding |
| Document lines to the worker | Long or numerous lines inflate the worker's work |
| Pattern and line text to logs and verdicts | Both are tenant data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-401 | Denial of service | catastrophic tenant pattern | high | mitigate | 04.2-14 static checks and probe at save time; run-time matching only in the 04.2-14 worker with a clamped deadline; 200-character window; tested with `^(?:x|x)*y` at save time and at run time |
| T-03.3-402 | Denial of service | oversized run-time request | medium | mitigate | At most 100 patterns and 20,000 lines per call, lines cut to 200 code units; the worker's resource limits and its four-worker cap stay in force |
| T-03.3-403 | Information disclosure | patterns or lines in logs and verdicts | medium | mitigate | The module writes no log line; verdicts carry ids, indexes, offsets and codes; console-spy and source-grep gates |
| T-03.3-404 | Tampering | unanchored heading pattern splitting body text mid-line | medium | mitigate | `heading_not_anchored` at save time and at run time; the entry is skipped and reported by id |
| T-03.3-405 | Tampering | a stored pattern written past the service | medium | mitigate | Static re-check of every entry before each run; a failing entry is never sent to the worker |
| T-03.3-406 | Information disclosure | one tenant's hits reaching another tenant's caller | low | mitigate | No cache or module state; hits index only the caller's own lines and ids |
| T-03.3-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed; `node:worker_threads` is built in |
</threat_model>
