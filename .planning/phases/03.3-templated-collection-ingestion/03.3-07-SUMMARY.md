# Phase 3.3 Plan 07: Tenant rule storage Summary

**Tenant section rule sets and boilerplate rules can now be stored per tenant through actor-checked service-role functions, validated with the shared pattern checks before every write, and read by ingestion for one binding from a tenant-keyed cache. Nothing calls the service or the loader yet, so runtime behaviour is unchanged.**

## Upstream facts confirmed (Task 1 gate)
The verify command passed: SUMMARYs of 03.3-01, 03.3-03, 03.3-04 and 04.2-14 are on this branch (03.3-04's dependency 04.2-14 and its own chain were confirmed by 03.3-04), both tables are in `1001_phase33_schema.sql`, the wrapper and the two 04.2-14 symbols exist, the generated schemas exist, no 1002 file existed. No hand-off note was needed.

- `rag_section_rule_sets`: `id`, `tenant_key`, `name` (1..80, not blank), `doc_type` / `source` (null or `^[a-z][a-z0-9_-]{0,63}$`), `enabled` (default true), `rules` jsonb (object with `headings` array of 1..60), `version` integer >= 1 (default 1), audit columns. UNIQUE (tenant_key, name); partial unique index on (tenant_key, COALESCE(doc_type,''), COALESCE(source,'')) WHERE enabled.
- `rag_boilerplate_rules`: `id`, `tenant_key`, `name`, `kind` (`line` | `fragment`), `pattern`, `flags` (`u` | `iu`), `max_length` (1..200), `min_page_share` double ((0, 1]), `doc_type`, `source`, `enabled`, `version`, audit columns; shape check line XOR fragment; UNIQUE (tenant_key, name).
- Wrapper: `checkTenantLinePattern(kind, pattern, flags, { signal })` (save time) and `validateTenantLinePattern(kind, pattern, flags)` (static re-check); kinds `heading` | `boilerplate_line`; finding codes `too_long, invalid_regex, invalid_flags, backreference, lookbehind, nested_unbounded_quantifier, matches_empty, heading_not_anchored, probe_too_slow`.
- Contracts: `SectionRuleSet` {name, doc_type?, source?, enabled, headings[{pattern, flags, name, level, required, restart}], require_increasing_numbers, skip_toc, toc_min_run}; `BoilerplateRule` {name, kind, pattern?, flags?, max_length?, min_page_share?, doc_type?, source?, enabled}. The generated `BoilerplateRule` does not enforce the line/fragment field split; the service and SQL do.

## API for 03.3-10, -12, -14, -24

### SQL (1002, service_role only, SECURITY INVOKER, `search_path = ''`)
```
rag_section_rule_sets_list(p_actor uuid, p_tenant_key text)
  -> TABLE(id, name, doc_type, source, enabled, rules jsonb, version, created_at, updated_at)   -- creation order; non-admin: no rows
rag_section_rule_set_upsert(p_actor uuid, p_tenant_key text, p_rule_set jsonb, p_id uuid DEFAULT NULL) -> same row
rag_section_rule_set_delete(p_actor uuid, p_tenant_key text, p_id uuid) -> uuid
rag_boilerplate_rules_list(p_actor uuid, p_tenant_key text)
  -> TABLE(id, name, kind, pattern, flags, max_length, min_page_share, doc_type, source, enabled, version, created_at, updated_at)
rag_boilerplate_rule_upsert(p_actor uuid, p_tenant_key text, p_rule jsonb, p_id uuid DEFAULT NULL) -> same row
rag_boilerplate_rule_delete(p_actor uuid, p_tenant_key text, p_id uuid) -> uuid
rag_tenant_rules_for(p_tenant_key text, p_doc_type text, p_source text)   -- STABLE, no actor
  -> TABLE(entry 'rule_set'|'boilerplate_rule', id, name, version, doc_type, source, precedence 1..4, rules jsonb,
           kind, pattern, flags, max_length, min_page_share)
```
- Upsert without an id inserts (version 1); with an id replaces every field of that row and raises its version by one.
- Refusals: `not_admin` (42501), `not_found` (P0002, unknown id or another tenant's id), `name_exists` (23505), `limit_reached` (54000, DETAIL `rule_sets` | `boilerplate_rules` | `heading_patterns` | `binding`), malformed payload 22023 (message `invalid_argument`, DETAIL names the field). The tenant assertion refuses a key of the other deployment mode.
- Precedence: 1 type and source, 2 type, 3 source, 4 tenant-wide. One rule-set row at most (the enabled one with the lowest level); every enabled matching boilerplate rule by level, then creation.

### Service (`src/lib/rag/ingest/rules/service.ts`)
```ts
interface RuleAdminInput { actorUserId: string; tenantKey: string; signal: AbortSignal }   // from the route's admission only
listSectionRuleSets(input) -> { ok: true; items: StoredSectionRuleSet[] } | RuleFailure
saveSectionRuleSet(input, ruleSet: unknown, id?) -> { ok: true; item: StoredSectionRuleSet } | RuleFailure
deleteSectionRuleSet(input, id) -> { ok: true; id } | RuleFailure
listBoilerplateRules / saveBoilerplateRule(input, rule: unknown, id?) / deleteBoilerplateRule(input, id)   // same shapes, StoredBoilerplateRule
sectionRulesEnabled(): boolean; pageBoilerplateEnabled(): boolean
StoredSectionRuleSet = { id, version, createdAt, updatedAt, ruleSet: SectionRuleSet }
StoredBoilerplateRule = { id, version, createdAt, updatedAt, rule: BoilerplateRule }
RuleFailure = { ok: false; reason: 'not_admin'|'not_found'|'name_exists'|'invalid_argument'|'unavailable' }
            | { ok: false; reason: 'limit_reached'; limit: 'rule_sets'|'boilerplate_rules'|'heading_patterns'|'binding'|null }
            | { ok: false; reason: 'invalid_tenant_pattern'; patternIndex: number; findings: TenantLineFindingCode[] }
```
Exported constants: `RULE_FAILURE_REASONS`, `RULE_LIMIT_NAMES`, `TENANT_RULE_LIMITS` (10, 40, 60, 80, 200).
Validation order: actor and tenant key shape, id shape, heading count (> 60 is `limit_reached`/`heading_patterns`), strict contract parse, line/fragment split, `source` in `INGEST_SOURCES` (`doc_type` is checked by the contract enum), every pattern through `checkTenantLinePattern` (`heading` or `boilerplate_line`), then the rpc. A successful write or delete calls `invalidateTenantRules(tenantKey)`.
**Writers need an actor**: the 03.3-14 import command must pass an admin user id; there is no actor-less writer.

### Loader (`src/lib/rag/ingest/rules/load.ts`)
```ts
loadTenantRules(scope: TenantScope, { docType, source }, { signal? }) -> TenantRules
TenantRules = { ruleSet: LoadedSectionRuleSet | null; boilerplateRules: LoadedBoilerplateRule[]; ruleIds: { kind, id, version }[];
                fingerprint: string /* sha256 hex of canonicalJson({ ruleSet, boilerplateRules }) */; loadFailed: boolean; skipped: number }
LoadedSectionRuleSet = { id, version, docType, source, headings: { pattern, flags, name, level, required, restart }[],
                         requireIncreasingNumbers, skipToc, tocMinRun }
LoadedBoilerplateRule = { id, version, kind, pattern|null, flags|null, maxLength|null, minPageShare|null, docType, source }
invalidateTenantRules(tenantKey: string); resetTenantRuleCacheForTests()
TENANT_RULE_CACHE = { ttlMs: 60000, failureTtlMs: 5000, maxTenants: 256, maxBindingsPerTenant: 64 }
```
The tenant key is `scopeKey(scope).toLowerCase()` after `assertTenantScope` (an unminted scope throws). A malformed binding value answers the failed result without an rpc and is not cached. Every result is frozen and JSON-plain.

## Deviations from Plan
1. **Boilerplate upsert argument name** is `p_rule` (the plan says "the same shapes"; the rule-set one is `p_rule_set`).
2. **`check-rag-boundary` doc-type rule**: a null check on the binding's document type in the loader tripped `doc-type-branching`; the shape check moved into `validBindingValue(value)`, which does not branch on the type.
3. **Parallel-insert test**: PGlite serialises queries on one connection, so the "two parallel inserts at the limit" cases (rule sets at 10, boilerplate rules at 40) prove the count check under the lock, not a real race; the advisory lock is the race guard on Postgres.
4. **Switch functions** read optional fields that plan 03.3-02 adds to `IngestConfig`; until it lands they answer false (the plan's off state). They also require `pipeline === 'unified'`.
5. Migration number 1002 as planned.
