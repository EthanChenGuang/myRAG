<objective>
Make the vector-sync outbox able to carry a lineage-wide purge and a stale-id repair: the SQL half of the RET-05 delta added on 2026-11-25 ("the outbox also carries DATA-24 purges").

Purpose: RET-05. DATA-24 (Phase 6.3) removes every version of a lineage from every store "through the RET-05 outbox". The existing `documents` DELETE trigger of 0702 already enqueues a `document` row per deleted version, but only for enabled targets and only for the synced (active and backfilling) embedding profiles, and it leaves no record a verification query can read. A purge record names the lineage and its document ids once, reaches every backend that holds points, and can be verified.
Output: migration 0740, the generic `rag_*` resolution of the fake edge confirmed, two PGlite test files.

Backend half: depends on 07-02 (outbox, targets, index state, claim functions; read 07-02-SUMMARY.md for the names as built), 07-06 and 07-11 (earlier editors of eval/harness/fake-edge.mts, the read and reconcile functions) and 07-10 (so every wave-4 migration exists before 0740 lands). Phase 6.3 (DATA-24) is not planned at revision 4: this plan needs nothing from it and fixes the function name and signature it calls. Plan 07-36 adds the drain, store and reconcile handling; plan 07-37 uses the stale-repair function and checks the Phase 6.3 call.

Planner resolutions (revision 4, owner rule: take the recommended option):
- The purge record carries the lineage's document ids because the outbox is notification-only (D-01) and the rows are gone when the worker runs; ids are identifiers, not content (same reasoning as the 05.1.1 D-29 purge seam: "resolve a lineage's document ids before it deletes the lineage").
- Applicable targets are "enabled, or has index state for the tenant", not "enabled" alone, so switching a backend off before a purge cannot leave withdrawn vectors behind.
- No new env var: with no target ever enabled the function is a no-op, like every 0702 trigger.
- 0740 is not folded into the setup files; plan 07-31 folds 0701 to 0707 only and applies 0740 onward through the unfolded path of the schema-equality test.

Execution note: every PGlite test applies every file in supabase/migrations/. With `workflow.use_worktrees` false, land 0740 before 07-13 and 07-14 start their PGlite-backed tests or after they finish, never during. Locate every existing function by name in the highest-numbered migration that defines it; never by line number.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines (Co-Authored-By and the session link) that the executor's own session supplies; never copy them from a plan. No model identifiers in code comments or commit messages; no secrets.
