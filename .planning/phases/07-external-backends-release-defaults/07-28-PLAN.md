<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant A to tenant B through the cache | a cached answer is the fastest path to a cross-tenant leak |
| cache to external stores | cached sources must agree with what the stores and Supabase still serve |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-90 | Information disclosure | a cached answer served to another tenant on an external backend | critical | mitigate | canary case per backend; tenant key in the cache key; source re-validation on every hit |
| T-07-91 | Information disclosure | a stale cached answer after a synced delete, replace or quarantine | high | mitigate | invalidation triggers plus source re-validation, asserted after drain on every backend |
| T-07-92 | Tampering | an entry crossing a backend switch | medium | mitigate | the backend and its index parameters are part of the retrieval config hash in the key |
| T-07-115 | Information disclosure | an embed-scope cached answer served to another tenant | critical | mitigate | embed-scope cache canary per backend; tenant-ignoring fake cache backend rejected by the Supabase source re-check |
| T-07-116 | Information disclosure | voice reading or writing cached answers | medium | mitigate | spied RPC asserts no cache check or store on the voice path (Phase 6 D-32) under every voice backend setting |
| T-07-SC | Tampering | npm/pip/cargo installs | high | accept | no package installed by this plan |
</threat_model>
