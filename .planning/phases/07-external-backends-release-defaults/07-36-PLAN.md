<objective>
Make the drain worker, the two vendor stores and reconcile carry out DATA-24 purges: the TypeScript half of the RET-05 delta added on 2026-11-25 ("the outbox also carries DATA-24 purges").

Purpose: RET-05. Plan 07-35 made the outbox able to hold a lineage-wide purge record and fixed the function Phase 6.3 calls. A purge is only real when every point of every version of the lineage is gone from every collection of every external backend that holds points, and when reconcile keeps it gone. Without this plan a `purge` row would be claimed and never processed.
Output: purge.ts, the three store additions, the drain and reconcile changes, unit tests with the fake store and mocked vendor clients, and a PGlite end-to-end test. The real-store cases run in the backend-canary tier through plan 07-44.

Backend half: depends on 07-35 (purge functions), 07-06 (store interface, fake store, thin drain), 07-07 and 07-08 (vendor stores), 07-09 (full drain engine: claim wrappers, coalescing, backoff, slice log) and 07-11 (reconcile and the index-state upsert). Phase 6.3 is not needed: the tests enqueue through rag_vector_sync_enqueue_purge directly, which is the seam Phase 6.3 calls (plan 07-37 checks that call). Rollout position: D-26 steps 2 and 6 (sync module, reconcile), extended for purges.

Planner resolutions (revision 4, owner rule: take the recommended option):
- A purge sweeps every collection the store lists with the `myrag_chunks_` prefix, not only the synced profiles of rag_vector_sync_profiles, because a retired or rolled-back profile's collection can still hold the lineage's points.
- Deletion is followed by a count in the same group, and a non-zero count fails the row instead of completing it, so a status of done always means "verified empty" at that moment.
- Reconcile does not delete purged points itself; it re-opens the purge through rag_vector_sync_purge_reopen, so every external delete still goes through the outbox and the drain (D-01 single path) and the status function stays truthful.
- Points of a purged document that reappear make the index state stale, which sends that tenant to pgvector (RET-09) until the next drain; re-validation (D-10) already drops them on any request in between.

Locate every function by name (claimBatch, completeRows, failRow and checkpointRow in claim.ts; drainSlice and drainUntilEmpty in drain.ts; reconcileSlice in reconcile.ts; the index-state upsert in 0707_vector_sync_reconcile.sql by the table it writes, rag_backend_index_state), never by line number.
