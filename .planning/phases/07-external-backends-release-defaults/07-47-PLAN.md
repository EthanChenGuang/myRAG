Planner resolutions (revision 4, owner rule: take the recommended option):
- Rollouts are a query-side and publish-side pointer per tenant; they never write vectors or chunks. The candidate profile must already hold vectors (backfilling, Phase 3 D-39 dual write), and its external collections already sync while it is backfilling (plan 07-06's rag_vector_sync_profiles), so no new sync path is needed.
- The traffic share is per tenant, not per request, so one tenant never mixes two profiles inside a conversation and the cohort comparison of plan 07-49 compares tenants.
- The bucket salt is stored per rollout and generated at start, so two rollouts do not pick the same tenants by construction.
- Under Phase 3.1.1 per-document-type selection, an embedding_profile rollout replaces only the default profile; a document type with its own selected profile keeps it (recorded on the span).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator to rollout tables | the CLI and admin routes decide which tenants get a candidate configuration |
| rollout state to the request path | the arm changes the profile and collection a request reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-155 | Information disclosure | a candidate profile's collection serving another tenant | critical | mitigate | the arm only selects the profile; tenant filters, re-validation and the mixed-rollout canary with a planted foreign point stay in force |
| T-07-156 | Spoofing | a caller choosing its arm | high | mitigate | the arm is resolved from the server-side scope and the rollout tables only; no request field is read |
| T-07-157 | Tampering | rollback deleting data | medium | mitigate | rollback changes membership and publish pointers only; tests assert collections and versions are untouched |
| T-07-158 | Elevation of privilege | client roles changing rollouts | high | mitigate | RLS without policies, REVOKE from client roles, rag_assert_tenant_key in every keyed function |
| T-07-SC | Tampering | npm/pip/cargo installs | high | accept | no package installed by this plan |
</threat_model>
