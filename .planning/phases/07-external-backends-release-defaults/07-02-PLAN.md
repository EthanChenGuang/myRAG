<objective>
Create the change-capture half of RET-05: the notification-only outbox, the sync-target switch table, the index-state table, the enqueue triggers and the claim RPCs (D-01, D-04, D-11 table, A-7, A-12).

Purpose: Supabase stays the only source of truth; every insert, update, delete (including FK cascade), version publish, quarantine, release, soft delete, re-embed and profile flip becomes an outbox row in the same transaction, but only when an operator has enabled a target. Default installs see no write amplification.
Output: migrations 0701 to 0703 and three PGlite test files.

Backend half: depends only on Phase 3, 3.1 and 4 plans: 03-09 (embedding_profiles, chunk_embeddings, 0309), 03-10 (version publish), 03-37 (quarantine), 03.1-39 (rag_soft_delete_document), 04-05 (PGlite role shim), 04-06 (lexical_text), 04-07 (chunk parent_id and chunking_profile_id, variant status, rag_assert_tenant_key), 04-33 (chunking activation), 04-42 (Phase 4 fold). Rollout position: D-26 step 1.

Planner resolutions recorded here (A-12): the outbox gets a `cursor text` column (paged expansion of `profile` and `tenant` rows and of large documents); `entity_id` is text so it holds a chunk or document UUID, a tenant key or a prefixed profile id (`embedding:<id>`, `chunking:<doc_type>`); trigger events enqueue the `document` entity, because under Phase 4 chunking profiles a chunk's servability depends on its whole document (the legacy-row fallback of plan 04-15), and the worker re-syncs the whole document; the `chunk` entity is used by reconcile repairs. Concurrency on PGlite (single connection) is tested as sequential claims plus lease expiry; a real-Postgres SKIP LOCKED run is part of the live checkpoint (plan 07-29).

Commit rule for every task: plain `git commit`; the message ends with the attribution lines (Co-Authored-By and the session link) that the executor's own session supplies; never copy them from a plan. No model identifiers in code comments or commit messages; no secrets.
</objective>
