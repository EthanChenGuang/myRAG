<objective>
Complete the shared application tokenizer that Phase 3 created (D-07, RET-03), move its rules into data, add the query side, bump `LEXICAL_VERSION` to 2, add the ICU check, and give ingest and the backfill one lexical_text builder.

Purpose: RET-03 requires one tokenizer for every backend and a Chinese exact-term match; research Pattern 4 shows codes must be cut out before segmentation, NFKC must run first and Han bigrams cover segmentation drift. The version bump resets nothing yet (no thresholds exist) but forces `rag:relex` (plan 04-16) to rebuild every chunk (D-08).
Output: tokenizer v2 with rules.json, ICU check, chunkLexicalText used by the Phase 3 enrich stage, and an exact-id compatibility fix.

Legacy note (D-23 "with RAG_PIPELINE=legacy, nothing in this phase runs"): the tokenizer and lexical_text are stored data shared by both pipelines, not a v2 stage. D-07 bumps the one tokenizer in place and D-08 has rag:relex rebuild lexical_text while the deployment is still on legacy, so the enrich stage writes v2 lexical_text whatever RAG_PIPELINE says. What D-23 protects is legacy behaviour, and this plan proves it: the only legacy reader of lexical_text, the Phase 3 exact-id lookup, gets the compatibility fix of Task 3, and both legacy smoke tiers must show zero paired differences.
