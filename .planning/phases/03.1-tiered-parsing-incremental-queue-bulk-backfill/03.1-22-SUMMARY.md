# Phase 03.1 Plan 22: Queued fixed path tracer Summary

**One queued upload now runs end to end through the app, the ledger, the sidecar job function and both callbacks, and its chunks equal Phase 3's.**

## Accomplishments

- `enqueueIngest` runs identify, file_hash_dedup and store_original in the app (new version, not current, original stored), writes `queued-input.json` next to the original, inserts the ledger row with the settings snapshot and returns `{ jobId, documentId, status }`. An unchanged file returns `skipped_duplicate` with the existing document and a terminal ledger row. `submitIngest` picks `ingest()` or the queue by `RAG_INGEST_ASYNC`; no write path calls it yet (later plans).
- `StateStore` seam: runner, parse and images save state through `saveContextState`. Default = the document row, so inline runs are unchanged (814 existing ingest tests still pass). The ledger store advances the job per stage with `cursor`, status and per-stage timing; a queued run never writes `documents.processing_state`.
- `parse-external` (chain mode) rebuilds the stage context from the job row, runs the unchanged chain (`parseToResult`), stores the result under the SQL-derived cache prefix and returns `done` with a cache id, or `pending` with a continuation that is only honoured when it names the parse job in the job's own `stage_state` (a foreign continuation is ignored).
- `advance` (post_parse) reads the cached result (id checked in SQL against the job's tenant), applies it with the same function the inline parse stage uses, then runs the remaining stages in a slice of at most 40 s with the ledger as state store. Cursor-based, idempotent, with a progress guarantee at any budget; terminal advance writes ready, quarantined or skipped_duplicate; stage failures fail the job and the version.
- Both routes check the sidecar secret (`internalApiKeyMatches`, refuses when `RAG_SIDECAR_SECRET` is unset) before any ledger call, validate with the generated strict schemas, validate their own response, and mint the tenant from the job row.
- Sidecar: `process_job` (fixed: chain parse with pending polling, one `fixed_chain` attempt, advance loop honouring `wait_ms`, failure classification), `WorkerEnv`, `run_once` (claim, per-job heartbeat, exit code by outcome).

## Decisions Made

- The enqueue stages cannot write `stage_state` (no parameter in `rag_enqueue_ingestion_job`, no SQL changed). What identify decided (doc type origin, detection, image slot, options, type change) is stored as `queued-input.json` under the version's own prefix and read back by the callbacks through the scoped writer.
- Cache entries of the chain use parser `chain` and version `chain-v1:<RAG_PARSER>:cloud=<on|off>`; the worker computes the options hash (F-12), the app returns 400 without one. A cached result is not used for an auto-typed document until its type was refined by this job (the refinement happens while parsing).
- Cursor = name of the last completed stage; the response `stage` is the next request's cursor. A request whose cursor is not the stored position returns the stored position and does nothing; a finished job answers with its terminal status.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `rag_sidecar.ingest` package init imported the Docling stack**
- **Found during:** Task 1 (Python tests could not import any ingest module without `docling_core`, which this environment does not have and must not install)
- **Fix:** exports resolve lazily (PEP 562); `__all__` unchanged. Test first (`test_ingest_package_lazy.py`).
- **Commits:** `e268ad3`, `d5dd446`

**2. [Rule 1 - Bug] Python `LedgerClient` could not parse a real `ingestion_jobs` row, nor the attempt number**
- **Found during:** Task 1 e2e (first run of the real worker against the fake edge)
- **Issue:** rows carry an `error` column and `detect_counts: {}`, both refused by the strict contract; `rag_record_parse_attempt` answered a one-column row.
- **Fix:** `_job_from_row` strips `error` and maps `{}` to null; `record_attempt` reads a one-column row. Tests first.
- **Commits:** `b7db2fa`, `c5d710e`, `255ebf9`, `0378b3e`

**3. [Rule 1 - Bug] TS `ledger.ts` read only arrays**
- **Issue:** PostgREST answers a function that returns one composite row or one scalar with the bare value; `enqueueJob`, `advanceJob`, `getJobInternal` and `recordAttempt` would have thrown `no_row` / `bad_response` against a real project (the fake edge always returns arrays).
- **Fix:** normalise to an array in `callRpc`. Test first (`ledger.test.ts`).
- **Commits:** `ba27df9`, `0fcd017`

**4. [Rule 1 - Bug] resume past `embed` failed as `write_incomplete`**
- **Found during:** Task 2 (stage idempotency RED)
- **Issue:** `rehydrateFromStore` never restored `chunksWritten`, so any run resumed after the embed stage failed in `write`. A queued job hits this on every slice boundary; inline `resumeIngest` had the same latent failure.
- **Fix:** restore it from the recorded `chunkCount` once embed is reached.
- **Commit:** `f457499`

**5. [Rule 1 - Bug] a spent slice budget yielded before running any stage**
- **Fix:** the first stage of a slice gets `minMsNeeded = -Infinity` (the runner yields when the time left is below it, and a spent budget is negative).
- **Commit:** `f457499`

**6. [Rule 1 - Bug] a pending parse wrote a post-parse cursor to the ledger**
- **Fix:** the ledger store adds `cursor` only once a stage has completed. Test first.
- **Commits:** `2f9f9df`, `e201028`

### Plan wording adjusted

- `documents.processing_state` is `NOT NULL DEFAULT '{}'`, so "never written" is asserted as "still `{}`", not null.
- The `StateStore` lives in `state-store.ts`, not `runner.ts` (runner imports the stages that need the helper). `runIngestStages` gained a `partial` option so the enqueue stages end as `processing` instead of failing; the enqueue run uses a null store.
- `parse-external` chain mode returns `done` with `cache_id` only: a chain result has no per-page text, and sending `result` would ship the whole markdown. The worker therefore records the attempt with the placeholders `parser: chain`, `parser_version: phase3-chain`, `tier: structured`, `preset: structured_layout`, pages 1..1; the real `parser_used` and `parser_version` are set on the ledger row by `parse-external`'s advance.
- `readParseResultForJob` returns `{ result, artifacts, entry }` (the artifacts such as `docling.json` are copied into the version folder by `applyParseResult`); a merged Docling entry is refused with `merged_entry_unsupported` (no json_docling re-chunk in this plan).
- "Fixed equals Phase 3" compares inline ingest for tenant o:B against the queued path for tenant u:A inside one PGlite database, not two databases (the harness installs process-wide fakes for one database).
- Extra files beyond the plan list: `state-store.ts`, `queued-context.ts`, `callbacks/common.ts`, `eval/harness/queued-ingest.mts`, `queued-callbacks-two-tenant.test.mts`, `queued-parse-pending.test.mts`, `internal-auth.test.ts`, `state-store.test.ts`; `src/lib/rag/index.ts` exports the new public functions because routes outside `src/lib/rag` may only import the index.
