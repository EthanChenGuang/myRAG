# Phase 03.1 Plan 26: Batch API embeddings for backfill Summary

OpenAI Batch API embedding client for backfill with a recorded fake: request building within provider limits, submit-and-record before the first poll, custom_id-mapped collection with dimension checks, missing-only resubmission, a two-batch open limit and resume of open rows.

## What was built

- `src/lib/rag/ingest/backfill/batch-api.ts`
  - `buildBatchLines(chunks, profile, limits?)`: custom_id `<chunk_id>:<embedding_text_version>`, body with the profile model and `dimensions` only when the profile is truncated below 1536; files of at most 50,000 lines and 190 MiB; a single oversized input throws `too_large`.
  - `submitBatch`: upload with purpose `batch`, create with `/v1/embeddings` and `24h`, then `rag_record_embed_batch` with `provider_batch_id`, `input_file_id`, count and status. If the record call fails the thrown `EmbedBatchError` carries `providerBatchId`.
  - `pollAndCollect`: polls every 60 s on an injectable clock (`deps.clock`, `deps.pollIntervalMs`), mirrors non-terminal status to the row, streams the output and error files line by line, returns `vectors`, `missing`, `errored`, `rejected`.
  - `resubmitMissing`: sends only the missing chunks (throws `open_limit` when more files than free slots), then supersedes the old row.
  - `embedViaBatchApi`: resume, open limit (default 2), re-submission, per-input attempt cap (default 3, then reported `unresolved`), `onVectors` hand-over before the row is closed. Uses the existing `openai` client only; no package added.
- `tests/helpers/fake-openai-batch.ts`: http server for `POST /v1/files`, `GET /v1/files/{id}/content`, `POST /v1/batches`, `GET /v1/batches/{id}` with scripted states, shuffled output order, an error file, wrong-dimension and failing lines, request counts, an ordered event log and the largest observed number of open batches.
- `tests/rag/ingest/backfill-batch-api.test.ts`: 29 tests.

## Known limits and deferred items

- A kill between the provider's batch create and the `rag_record_embed_batch` call can still orphan one batch (the plan's design records after create, as the row needs `provider_batch_id`). The failure path surfaces the provider batch id in `EmbedBatchError.providerBatchId`; a pre-create pending row was not added.
- The default poll sleeps once per round for all active batches (cadence 60 s), a batch created right after another finished is polled at once.
- Writing vectors with the Phase 3 profile writer and publishing is 03.1-49 (`onVectors` is the hook for it).
- `tests/rag/langfuse-pins.test.ts` and the rest of the full suite, `tests/*.test.mts`, `check-workflows.py`, `check-config.mjs` were not run in this worktree; this plan touches only the three files above.
