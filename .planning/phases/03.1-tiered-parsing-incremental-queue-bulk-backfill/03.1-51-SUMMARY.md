## Accomplishments

- **The gap was a bug.** In the tiered run, en-selective-filter-001 came back with no candidates. `warehouse-floorplan.png` is a corpus text upload: a caption, `text/markdown`, which keeps the image's name. The worker sends text and image files to the app's native mode, and native mode decided "image" from the `.png` name, so it captioned the text bytes. Native mode now parses `ctx.input.text` when the upload is text, the same way the Phase 3 chain does. The probe tiered run then matched fixed on all 168 items.
- **Gate (Task 1).** `rag_eval.parse_gate` loads N runs per mode (report.json plus the new ingest-ledger.json). Before comparing, it checks that the runs share the golden file, filter, population, embedder, request options and corpus per mode, and that each ledger has the expected routing mode. It averages each item's metrics per mode and takes paired differences per gated slice, using `paired._stat` for n and the bootstrap interval. The band comes from the fixed runs' spread. It writes `parse-gate.json` (a `ParseGateReport`) and `parse-gate-details.json` (cells, bands, pages per tier). Exit codes: 0 pass, 10 regression, 2 mismatch or unreadable, 3 run failure.
- **Sweep (Task 2).** `python -m rag_eval.parse_gate sweep [--skip-runs] [--write-config]`:
  - Runs the three forced-tier builds and the fixed builds, then splits fixtures and items by the Phase 1 rule.
  - Routes the 6 dev fixtures for all 150 grid points in one sidecar call.
  - Finds each dev item's evidence page by locating its quote in the recorded parses, and projects the item's Recall@5 from the forced run of the tier that page is routed to.
  - Keeps only candidates within the band of fixed, picks one, and then routes and scores the 3 test fixtures once.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Native mode captioned queued text uploads named like images**
- **Found during:** Task 1 (the input gap named in 03.1-47)
- **Issue:** `nativeParseResult` called `imageMime(filename, mimeType)`, which matches on a `.png` name, before it looked at the text input. A Config UI caption (text named `x.png`) was re-captioned from its own text bytes under tiered routing. A real captioner would have failed on those bytes.
- **Fix:** a text upload returns its text, as in `parseToResult`.
- **Files:** src/lib/rag/ingest/callbacks/native.ts, tests/rag/ingest/parse-external.test.ts
- **Commits:** 675e1675, 86cd75bc

**2. [Rule 3 - Blocking] The ledger data the gate needs was not written anywhere**
- The routed build kept per-job rows only in its PGlite database. `IngestRoutingOptions.ledgerOut` (set by run-smoke to `<out>/ingest-ledger.json`) now dumps each queued job's row, together with the page count the harness knows (fixed routing records no page counts).
- **Files:** eval/harness/ingest-mode.mts, eval/harness/run-smoke.mts. **Commit:** baa74dc3

**3. [Rule 3 - Blocking] The scanned character limit was a constant**
- `SCANNED_MAX_CHARS = 30` in l1.py could not be swept, so it is now `l1.scanned_max_chars` with default 30. `npm run gen:schemas` regenerated the JSON schema, Zod and samples.
- **Commit:** f5d853e2

**4. [Scope] The sweep needs the sidecar environment**
- The eval venv has no pdfplumber or pypdfium2, so routing per candidate runs in `rag_sidecar.preflight.sweep`, which the eval side calls through `uv run --directory rag-sidecar --frozen`. `build_routing_report` gained an optional `cfg` argument.

**5. [Scope] Test-split section and sweep evidence**
- `ParseGateReport` is a shared contract with no field for the sweep, so the sweep and its once-scored test split live in `threshold-sweep.json`, which is what `thresholds_ref` points at. `parse-gate.json` stays a pure `ParseGateReport`.

**6. [Plan wording] package.json script**
- `eval:parse-gate` calls `rag_eval.parse_gate`, which runs the six harness runs itself, the same way `eval:baseline` does, instead of chaining six `npm run test-rag` calls in the script.
