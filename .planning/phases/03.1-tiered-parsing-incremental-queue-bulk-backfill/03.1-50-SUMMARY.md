# Phase 3.1 Plan 50: Optional Ray runner Summary

`python -m rag_sidecar.ingest.ray_runner --batch <id>` runs a backfill batch on Ray Data through the same ledger claim (`rag_claim_ingestion_job`, runner `ray`) and the same `process_job` as the worker. An opt-in end-to-end test shows `--runner ray` and `--runner worker` end with equal ledger rows and chunks, and that a killed Ray run resumes. Both run in a separate optional CI workflow, never in the PR pipeline.

## Behaviour changes

- New module `rag_sidecar.ingest.ray_runner` (the CLI from 03.1-48 already spawns it with `--runner ray`). Exit 0 when no job of the batch is open, 1 on a runner failure, 3 when the worker environment is incomplete, 143 on SIGTERM (Ray is shut down first).
- `LedgerClient.claim_one` returned a validation error, not `None`, when the job could not be claimed: `rag_claim_ingestion_job` returns a NULL composite, which PostgREST (and the fake edge) send as an object with every column null. It now returns `None`. `run_once` exits 2 for this case as documented, where it crashed before.
- New `LedgerClient.list_batch_jobs` returning `BatchJobRef`s.
- Default image, worker and app are unchanged: importing `rag_sidecar.ingest`, the worker, `rag_sidecar.main` or the runner module never imports ray (subprocess test with an import recorder).

**4. Equality test design**
- Each run backfills its own organization tenant in one database (worker, Ray, Ray killed and resumed) instead of a fresh database per runner: the in-process app routes keep module-level clients bound to the first fake edge. Personal tenants are not used because the fake edge has no auth admin API for the tenant lookup.
- Compared: every ingest ledger column except ids, tenant, document/lineage ids, refs, `stage_state`, `locked_by`, `runner`, lease/run_after, timestamps, `timings` and `est_cost_usd`. In attempts, `ms`, `cache_hit` and `est_cost_usd` are left out. The dry-run sample is compared by status counts. The batch id seeds the sample, so which files hit the parse cache differs between batches.
- Runner `ray` is checked on live leases. A terminal transition clears `runner` and `locked_by`, so a sampler records them during the run.
- The resumed batch is compared without `retries` and `attempts`: a job in flight at the kill is reclaimed once more.
- Budget: the premium page budget is 0, and spent stays within `budget_usd` and equal between runners. No fixture page reaches premium today, because the sidecar's tiered flow does not escalate yet. So the compared needs_review set is `multi-column-en` / `quality_check_failed`, not a `budget_exhausted` set (see Deferred).
- The availability probe uses `uv run --no-sync`, so the test never installs ray.
