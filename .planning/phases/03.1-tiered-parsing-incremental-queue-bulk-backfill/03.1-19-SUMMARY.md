# Phase 03.1 Plan 19: Cloud and budget guard Summary

One guard module refuses cloud work by switch, per-document cap, tenant page budget and batch USD budget before any byte leaves, and it sits at the single LlamaParse v2 entry with Docling as the cloud-off fallback.

## What was built

- `cloud-budget.ts` checks in the order cloud switch (live), per-document page cap (queued tiered, kind parse only), atomic tenant page reservation (`rag_reserve_parse_budget`), batch USD reservation (`rag_reserve_batch_budget`). A refusal returns `{ ok: false, reason }` with one of `cloud_not_allowed`, `over_page_cap`, `budget_exhausted`, `batch_budget_exhausted`; when the batch refuses, the page reservation just taken is released.
- Inline and fixed callers (no job, not queued, or routing not tiered) get `{ ok: true, handle: null }` after the cloud-switch check only, so Phase 3's unmetered LlamaParse use is unchanged.
- `settle(handle, pagesSent)`, `release(handle)` and `readMonthlyUsage(tenantKey?)` map one-to-one to the SQL functions. Database errors fail closed with `CloudGuardError` (stable code, no row text).
- Logging is `[Ingest] cloud call refused { reason, kind }`; no file name, key or bytes.
- `llamaparse-v2.ts` calls `assertCloudAllowed('parse')` at `parse()` and again at `submit()` (the only place bytes leave), throwing `CloudRefused`. With `request.guard` set it reserves before the first upload and hands the handle to the caller through `onReserved`; a resumed job is not reserved again.
- `chain.ts` treats `CloudRefused` as skip-LlamaParse (reason recorded in `fallbacks`, no second log line) and continues to Docling.

## Deviations from Plan

**1. [Rule 3 - Blocking] `ParseRequest` gets an optional `guard` field (shared.ts)**
- **Found during:** Task 2
- **Issue:** the plan has the v2 entry accept a guard context from the parse-external route, but the request type lives in `parsers/shared.ts`, which is not in the plan's file list.
- **Fix:** added `ParseGuard { context, onReserved? }` and `guard?: ParseGuard` to `ParseRequest`. Unset for every existing caller.
- **Files modified:** src/lib/rag/ingest/parsers/shared.ts
- **Commit:** 6b7b9f4

**2. [Rule 2 - Correctness] Guarded requests do not resubmit a lost job**
- **Issue:** the v2 client resubmits once when the service forgets a job; for a metered request that would be a second upload under one reservation.
- **Fix:** with `request.guard` set a lost job ends as `job_lost`. Unguarded behaviour is unchanged.
- **Commit:** 6b7b9f4

**3. Live config read from `process.env`, not `env.ts`**
- `env.ts` is evaluated once at import, so it cannot give the live re-check D-08 and D-18 require. The guard builds a snapshot from `process.env` for the six queue variables and passes it to `loadQueueConfig`. No new env variables were added, so no config-sync change.
