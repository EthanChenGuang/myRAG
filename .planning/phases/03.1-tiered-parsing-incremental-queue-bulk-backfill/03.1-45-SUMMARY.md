## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] No 20-page digital fixture exists**
- **Issue:** the parse fixtures are 1-10 pages or bench-100.
- **Fix:** the test cuts bench-100 pages 11-30 with pypdfium2 (through `latency_sidecar.py slice`) into a temp dir and builds renumbered recordings there. Preflight classifies it `text_pdf`, all 20 pages `fast`.
- **Commit:** 7ba6f764

**2. [Rule 3 - Blocking] Identical uploads became duplicates**
- **Issue:** the second upload of the same bytes or the same parsed content ended `skipped_duplicate` (file hash, then content hash).
- **Fix:** each upload gets a byte suffix after `%%EOF` (new sha) and recordings whose page 1 names the upload; each fixed-routing upload gets its own fake LlamaParse spec. The test now fails fast on `skipped_duplicate`.

**3. [Rule 3 - Blocking] No session and no `after()` outside Next.js**
- **Fix:** the test sets the global `AsyncLocalStorage` before any Next module loads, runs each handler inside a work store (with an `afterContext` that starts the tasks once the response is returned) and a request store with the `sb-<ref>-auth-token` cookie, and answers `/auth/v1/user` from a fetch wrapper (the fake edge has no auth routes). No product code or shared harness file changed.

**4. [Rule 3 - Blocking] Slow converter**
- The plan's "slow converter" has no knob in the sidecar. A test-only launcher (`tests/rag-e2e/latency_sidecar.py serve`) wraps `RecordedRangeConverter.convert` with a sleep and runs `rag_sidecar.main:app` under uvicorn. The no-backfill cases run plain `uvicorn rag_sidecar.main:app`. This adds a third file to the plan's two.

### Plan differences

- **Backfill overlap:** with 20 back-to-back uploads, only the first backfill job ran during them (4 of 20 overlapped); see Issues. Each upload in the SC5 case is now sent once a backfill job holds a slot (at most 30 s wait, not counted in its latency), and the test asserts at least 18 of 20 uploads overlapped a running backfill job.
- **`--test-name-pattern` order:** the plan's Task 1 verify (`... --test tests/... --test-name-pattern "stats"`) runs the whole file on Node 22, because an option after the file path is not applied to the file. `node --import tsx --test --test-name-pattern stats tests/rag-e2e/ingest-latency.test.mts` runs only the stats cases.
- **Routing switch in one process:** `env` from `@/lib/env` is read once at import, so the test sets `process.env` and the `env` object, then calls `resetQueueConfigForTests()`; every job's snapshot is asserted to carry the expected routing.

**Total deviations:** 4 auto-fixed blocking issues, all test-side.

## Issues Encountered

- **Backfill starves under steady uploads (not fixed, design question for D-23):** `IngestWorker._claim_slots` passes `allow_batch = slots_left > 1`, so a batch job is claimed only while every slot is free. Each wake also restarts the 2 s poll timer, so while uploads arrive less than about 2 s apart, every claim happens with an upload queued and no backfill job starts. SC5 (uploads not delayed) holds; backfill throughput under continuous uploads is zero. A "batch jobs hold at most concurrency − 1 slots" rule would let backfill share the second slot. Recorded here for the planner; not logged in `deferred-items.md` to avoid conflicts with the parallel plans.
- `npm run typecheck:new` reports 25 diagnostics in other test files on this base (`tests/rag-db/*`); none in the files of this plan.
