# Phase 3.1 Plan 41: L3 detect-vlm Summary

**Layer L3: a guarded detect-vlm callback returns validated page-structure verdicts for pages where L1 and L2 disagree, and the sidecar preflight applies them (complex gives premium) without ever sending a page with cloud off or failing a job when L3 is refused.**

## Accomplishments

- **App side.** The route checks the sidecar secret, the UUID, the strict body (1 to 20 pages, no tenant field), the lease, and that the job snapshot has `vlm_detect` on with tiered routing. The handler then checks images (PNG signature, 8 MiB cap, no duplicate pages, at most `l3.max_pages_per_doc`), calls `reserveVlm` (cloud switch live, one vlm budget page per image, batch USD at the L3 cost from the routing data) and only then calls the model, four pages at a time with a 20 s per-page timeout and a 45 s request budget. Answers are validated with `PageStructureVerdictSchema`. Every page sent is settled; a request with nothing started releases the reservation. With cloud off, budget 0 or an exhausted batch, every page comes back `refused` and the stub receives nothing.
- **Worker side.** `l3_refine` runs only for snapshots with `vlm_detect`, tiered routing, cloud allowed and a page budget. It renders at most 20 disagreement pages in page order with pypdfium2 (scale 1.5, at most 2000 px a side, own PNG encoder so no Pillow is needed), calls the app through `VlmApp`, and replaces the L1 and L2 signals of every page that got a verdict (`L3Page`, layer L3). Refused pages, failed pages, unknown or duplicate answers and any exception leave the pages untouched. `run_preflight(..., vlm_app=...)` plugs it in before the page tiers and fills `detect_counts.L3`.
- **Bridge.** `LoopVlmApp` hands `AppClient.detect_vlm` to the loop that owns the client, so the pool-thread preflight can call it; it refuses to run on that loop (deadlock).

## Deviations from Plan

**1. [Rule 1 - Bug] Failed pages are omitted, not returned with `verdict: null, refused: null`**
- **Found during:** Task 1 verification against the worker contract
- **Issue:** the plan says a page whose answer fails validation is "returned as failed (no verdict)". The Pydantic `DetectVlmPageResult` validator rejects a page with neither field, so the worker's `DetectVlmResponse.model_validate` would fail the whole L3 call. The generated Zod schema does not encode that rule.
- **Fix:** such pages are left out of `pages`; tests assert the verdict-xor-refused rule on every 200 response.
- **Commit:** 3a8762a6

**2. [Rule 2 - Critical] Pages with an invalid answer are settled, not released**
- **Issue:** the plan says an invalid answer "releases its page". The reservation is one row per (job, attempt, kind), so a single page cannot be released, and counting only valid answers would let injected page text make answers invalid and spend unmetered (T-03.1-94).
- **Fix:** settle counts every page whose model request started; only unstarted pages are released (the whole reservation when none started).
- **Commit:** 68d4ceff

**3. [Rule 2 - Critical] 409 `vlm_not_enabled` and image checks added**
- Fixed routing makes `reserveVlm` return an unmetered handle, so the route refuses jobs whose snapshot does not have `vlm_detect` on with tiered routing. The PNG signature, size cap, duplicate-page and page-count checks run before any reservation. Commit 68d4ceff.

**4. [Rule 3 - Blocking] `src/lib/rag/index.ts` edited**
- The RAG boundary check (`deep-import`) rejects a route importing the handler directly, so `handleDetectVlm` is re-exported from `@/lib/rag` like `handleAdvance`. One line; not in the plan's file list. Commit 68d4ceff.

**5. Plan wording kept where it conflicts with nothing**
- `l3_refine` is synchronous and takes a `VlmApp` (not the async `AppClient`) because `run_preflight` runs in a pool thread; `LoopVlmApp` adapts the client.
- `l2.py` is untouched: `L3Page` subclasses `L2Page` in `l3.py`.
- A repeat call for the same (job, attempt) cannot reserve again (unique reservation row, 23505): the route answers 500 `guard_error` and the worker keeps the D-49 rule.

**Total deviations:** 4 auto-fixed (1 bug, 2 critical, 1 blocking). **Impact:** none on scope; the two behavioural deviations follow the worker contract and the cost-control threat.
