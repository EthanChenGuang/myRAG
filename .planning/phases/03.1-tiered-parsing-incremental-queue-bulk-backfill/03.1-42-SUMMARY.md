# Phase 3.1 Plan 42: Per-page escalation Summary

**Failing pages now climb the parse ladder one step at a time (fast to a structured preset chosen by the failed condition, structured to premium through parse-external) within the two-escalation, max_tier, cloud, cap and budget limits; passing pages keep their cached results, D-52 boundary pages are pulled without using an escalation, and anything that cannot climb ends needs_review with marked pages and a reason.**

## Accomplishments

- `escalation.py` (pure): `plan_escalations(attempts_by_page, snapshot, ladder, max_per_page=)` returns the units to re-parse and the blocked pages with their reason (`escalation_off`, `escalations_exhausted`, `max_tier`, `cloud_not_allowed`, `over_page_cap`, or the guard's earlier refusal); `choose_kept` keeps the first passing attempt per page, else the best score, ties to the earlier attempt, never a refusal; `review` applies D-16 (blocked pages, premium-tier pages refused by budget or cap even when the lower tier passed, the cloud routing note).
- `tiered.py`: after the initial range checks, rounds of `plan_escalations` run each unit through the converter (Docling presets, one cache entry per unit, D-56) or parse-external premium (`_premium_attempt`, sub-PDF of the unit's pages, one reservation per escalation), re-check it and add it to the page history. The kept result per page is assembled with `slice_pages` and merged; `page_ranges` is the final per-page state (tier, preset, parser, cache entry, status `ok`/`escalated`/`needs_review`), run-length encoded. Attempts carry reason `initial`, `escalation` or `table_boundary`; `rag_record_ingestion_attempt` raises `escalations` for each escalation attempt.
- Worker-side refusal from the snapshot (D-18): with `cloud_allowed=false`, or more premium pages than `premium_max_pages_per_doc`, no premium request is made for initial ranges or escalations; the refused attempt is still recorded.
- End to end: an empty fast page 1 of `digital-text` is escalated to `structured_ocr` (reason `escalation`, failed `empty_text`, page published from the escalation); with the cloud off, L3 on and `min_tier=premium` for invoice and scanned types, all ten parse fixtures end `ready` or `needs_review` (`multi-column-en`: `cloud_not_allowed` after its escalation was blocked) with zero requests at the LlamaParse stub, the vision stub and the detect-vlm route, and no parse-external call at all; budget 0 ends `needs_review budget_exhausted`; ten premium pages over a cap of nine send nothing, reserve nothing and end `needs_review over_page_cap`.

## Deviations from Plan

### Auto-fixed / added

**1. [Rule 2 - Missing critical] Worker refuses premium from the snapshot (D-18, T-03.1-95)**
- **Issue:** 03.1-40 cut a sub-PDF and called parse-external for premium ranges even when the snapshot had the cloud off, and the per-document cap was only checked per request by the guard (a document with two premium ranges could pass it range by range).
- **Fix:** `_snapshot_refusal` counts all premium pages of the document; cloud off or over the cap refuses locally, records a refused attempt and falls back to structured. The planner applies the same rules to escalation units.
- **Commit:** c6c17245

**2. [Rule 3 - Blocking] FakeLedger did not count escalations**
- The SQL function raises `escalations` for reason `escalation`; the test fake did not. Two lines in `rag-sidecar/tests/ingest_fakes.py` (not in the plan's file list), with a test. Commit c6c17245.

### Plan differences

- **Planner signature:** `plan_escalations(attempts_by_page, snapshot, ladder, *, max_per_page)` instead of `(checks, attempts_by_page, snapshot, ladder)`: the per-page failed conditions of every check travel inside the attempts, which also covers refused steps and reclaimed jobs.
- **Over-cap e2e:** the plan's 250-page document with cap 200 has no recorded fixture (the recorded converter needs per-page recordings for the file hash); the test uses `mixed-routing` (10 pages, all premium through the `invoice_receipt` override) with cap 9, which exercises the same rule.
- **Task 3 commit order:** the end-to-end behaviour was already implemented by Task 2, so the e2e test landed as one commit; its RED run against the base worker is recorded above.
- **Task 2 unit tests** live in `test_ingest_escalation.py` behind a `flow` skip marker so the planner tests still run without the chunking and preflight extras.
- **Default budget 0:** an escalation from a failing structured page asks the app for premium and the guard refuses with `budget_exhausted`, so such a page now ends `needs_review budget_exhausted` (before: `quality_check_failed`). This follows D-16 (a budget block, a retry may do better).

**Total deviations:** 2 auto-fixed (1 critical, 1 blocking) plus the differences above. **Impact:** no scope beyond the tiered PDF path.
