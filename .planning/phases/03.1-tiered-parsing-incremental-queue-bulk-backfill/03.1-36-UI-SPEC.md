## 0. Findings that shape this contract (read first)

These are facts from the code, not preferences. Items 1 and 2 need a planner or product-owner decision; see section 14.

1. **The live upload monitor is not `process-documents.js` / `status-monitor.js`.** `index.html` never loads either file. The upload the
   user sees runs in an inline `class DocumentProcessor` declared at the top level of a classic `<script>` in `index.html` (line ~13113),
   which renders into `#queue-items`, `#results-list` and `#activity-log`. `process-documents.js` also declares a top-level
   `class DocumentProcessor`, so loading it with a `<script>` tag as it stands throws "Identifier 'DocumentProcessor' has already been
   declared". This contract specifies behaviour **on the visible monitor**. Section 9.6 gives the recommended file split so the plan's
   acceptance greps and the visible UI both hold.
2. **The admin job detail route does not return the provisional flag.** `projectJob` (`_lib.ts`) omits `provisional_published_at`, so
   polling the admin detail route (as the plan says) cannot render "Searchable, still improving" (D-30). The owner-scoped route of
   03.1-28 returns `provisional`, but it needs a Supabase session, not the admin session. This contract renders the provisional state
   from `job.provisional === true` and treats the field as **absent means not provisional**, so the UI stays correct when the field is
   missing. Someone must decide where the field comes from (section 14, Q1).
3. **The 202 `{ jobId, documentId, status }` upload response arrives with 03.1-29 (wave 6), after this plan (wave 5).** Task 2 is
   built and tested against stubs. Today the route still answers 200 inline, which must keep today's display.
4. **`ragFetch` maps every 403 to the admin sign-in message**, including the workspace-membership 403 (`{ error: 'Forbidden' }`) from
   `resolveWorkspace`. The panel tells these apart by `body.error` (section 8).
5. **`ragFetch` does not catch network failures.** A thrown `fetch` rejects the call. The panel wraps every call (section 8).
6. **Budget arithmetic:** `rag_reserve_parse_budget` admits a reservation only while
   `pages_reserved + pages_used + vlm_pages_used + new <= budget`. Parse pages, L3 pages and reservations are **disjoint** and all three
   count against the one monthly budget. The meter stacks them (section 6.3).
7. **The existing RAG panels bind their init only to the first `[data-tab="rag-administration"]` link** (the desktop sidebar), and
   they re-mount on every click. The mobile drawer link at line ~9358 never initialises them. The Ingestion panel must not copy this
   (section 6.1).
8. **The Config UI has no icon usage today** (Bootstrap Icons 1.11.3 is loaded but no `bi-*` class is used; the chrome uses emoji). The
   sibling RAG panels use neither. This panel uses Bootstrap Icons, always `aria-hidden="true"` and always next to a text label.

## 1. Design direction (frontend-design pass)

**Subject.** An operator console for a document-ingestion queue, inside an existing admin dashboard.
**Audience.** A deployment admin at a desktop, usually answering one of three questions: "why did this document fail or stop?", "what did
it cost in paid pages?", "can I fix it from here?".
**Primary job.** Find failed and needs-review jobs, see why, retry or delete them; watch this month's paid-page spend.

**Mode.** Impeccable "Operate": the panel must read as a working tool of its category first. Navigation, controls, tables and dialogs are
the standard ones the Config UI already uses (DaisyUI 4 classes on native elements). The world lends type, palette, density and one
signature move, nothing else.

**Signature move: orange means paid pages.** The project's brand orange (`myrag-primary` `#FF6417`, light theme `myrag-primary-dark`
`#E05A15`) is used in this panel for exactly one meaning: pages that consume the metered premium budget. It fills the budget meter and
the premium segments of the **page-tier ribbon**, a thin bar in the job detail that shows the document's page ranges to scale, coloured
by the tier each range was parsed at. An admin who sees orange in a job's ribbon knows those pages were paid for, and the same orange in
the budget meter shows where the month's pages went. Nothing else in the panel is orange.

**Review against generic defaults (what was changed and why).**
- Rejected a hero-metric budget tile (big number, small label, accent). The budget is a stacked meter plus one plain sentence, because the
  admin needs the split (parse, L3, reserved) more than a headline number.
- Rejected one card per job (the quarantine panel's pattern). Jobs are comparable rows that an admin scans by status and time, so they
  are a table; cards would hide the comparison.
- Rejected emoji headings (the tab title uses one; the sibling section headings do not). Section headings are plain text.
- Rejected meta strings joined with middle dots and "WORD — fragment" labels. Metadata sits in a definition list with real labels.
- Rejected a modal for the job detail. Detail opens inline under its row (a disclosure), because it neither interrupts nor needs
  protected focus. The only modal is the Delete confirmation, which does need protected focus.

**Quality floor (built without announcing it).** Visible keyboard focus, `prefers-reduced-motion` respected, all text at least 4.5:1,
tabular numerals in tables, responsive down to 360 px, every state in section 7 present.

## 4. Spacing Scale

Tailwind spacing utilities only; no arbitrary pixel values.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `mt-1` | Icon to label inside a badge or button; label to its help line |
| sm | 8px | `gap-2`, `mb-2` | Buttons in a row, filter radios, heading to its description, legend swatch to text |
| md | 12px | `gap-3`, `mt-3` | Legend items, rows of the detail definition list, filter row to table |
| lg | 16px | `mb-4`, `p-4` | Between blocks inside one sub-view, detail region padding |
| xl | 24px | `gap-6`, `mt-6` | Between the budget strip and the sub-tabs; between sibling panels (existing `grid gap-6`) |
| 2xl | 32px | `.card-body` default | Card padding (DaisyUI default, unchanged) |

Exceptions:
- DaisyUI `table-sm` cell padding (8px block, 12px inline) is used as shipped.
- Meter height 8px (`h-2`), ribbon height 12px (`h-3`); segments of both are separated by a 2px gap (`gap-0.5`) so boundaries survive low
  contrast.
- Row actions are `btn md:btn-sm`: 48px tall below 768px (touch), 32px from 768px up (desktop admin density).

## 5. Typography

Exactly four sizes and two weights, matching the sibling panels (`h3.text-lg.font-semibold`, `p.text-sm.text-base-content/70`).

| Role | Size | Weight | Line height | Tailwind | Where |
|------|------|--------|-------------|----------|-------|
| Panel heading | 18px | 600 | 1.33 (`leading-7`) | `text-lg font-semibold` | "Ingestion" |
| Sub-heading | 16px | 600 | 1.5 (`leading-6`) | `text-base font-semibold` | Budget title, "Page ranges", "Parse attempts", settings group headings, dialog title |
| Body | 14px | 400 | 1.43 (`leading-5`) | `text-sm` | Descriptions, table cells, status messages, buttons (`btn-sm` text) |
| Meta | 12px | 400 (600 for table headers) | 1.33 (`leading-4`) | `text-xs` | Table headers (`font-semibold`, override DaisyUI's 700), legend, help lines, badges, IDs, secondary row text |

Rules:
- Numbers in tables, the legend and the meter text use `tabular-nums`; counts and page numbers are right-aligned in their columns.
- Description paragraphs cap at `max-w-prose` (65ch). Table text never wraps mid-word except file names and IDs in the detail, which use
  `break-all`.
- No all-caps labels, no letter-spaced eyebrows, no italic emphasis inside headings.
- The panel root carries `lang="<locale>"` (`en`, `zh` or `it`) for the language its strings are rendered in, so screen readers switch
  voice correctly inside the English page.

### 6.1 Placement and mount

```
RAG administration (existing tab #rag-administration, .card.bg-base-100 > .grid.gap-6)
  1. Document types         (existing  #rag-administration-doc-types)
  2. Ingestion              (NEW       #rag-administration-ingestion)

  4. Embedding profiles     (existing  #rag-administration-profiles)
```

The order follows the document's path: a type is chosen at upload, the job runs, the scan may quarantine it, the embedding profile embeds
it. The tab's intro sentence becomes: "Manage document-type defaults, ingestion jobs, quarantined uploads, and embedding profiles using
your existing admin session."

- `index.html` loads `<script src="rag-panels/ingestion.js"></script>` exactly once, after `rag-panels/embedding-profiles.js`.
- `initIngestionPanel()` is idempotent: the first call mounts; later calls call `panel.refresh()` (reload list and budget, keep filter,
  sub-tab and open detail). Bind it to **every** `[data-tab="rag-administration"]` element (`querySelectorAll`), and call it on
  `DOMContentLoaded` when that tab is already the active one.
- The panel reads the workspace from the existing `#workspace-selector` (Document Processing tab), exactly as `doc-types.js` does:
  `organizationId = selector.value || null`, sent as `?organizationId=` on every job and budget call. Tier calls never send it (they are
  deployment-wide). On `change`, the panel closes any open detail, aborts in-flight requests, resets to the first page and reloads list
  and budget.

### 6.3 Budget strip (`GET /api/rag/admin/parse-budget`)

Response used: `{ month, budgetPages, maxPagesPerDoc, tenants: [{ tenantKey, reserved, used, vlmUsed }] }`.

- Title (16/600): `budget.title` with `{month}` formatted by `Intl.DateTimeFormat(locale, { year: 'numeric', month: 'long', timeZone:
  'UTC' })` from `month` (`YYYY-MM`). Icon button `btn btn-ghost btn-sm btn-square` with `bi-arrow-clockwise`, `aria-label` = `budget.refresh`.
- Meter: `div[role=meter]` full width, `h-2 rounded-full bg-base-300 flex gap-0.5 overflow-hidden`, `aria-valuemin=0`,
  `aria-valuemax=budgetPages`, `aria-valuenow=used+vlmUsed+reserved`, `aria-valuetext` = `budget.meterText`. Segments in this order,
  widths proportional to `budgetPages` (each non-zero segment at least 2px):
  1. parse pages (`used`): solid orange.
  2. L3 vision pages (`vlmUsed`): orange with 45-degree stripes (`repeating-linear-gradient(45deg, orange 0 3px, transparent 3px 6px)`
     over `bg-base-300`), so it differs from parse pages by pattern, not by a second hue.
  3. reserved (`reserved`): orange at 35% opacity.
  4. remaining: the track (`bg-base-300`).
  Orange is `#FF6417` under `data-theme="dark"` and `#E05A15` under `data-theme="light"` (3.2:1 against `base-200` in light, 5.8:1 in dark).
- Legend (12px, `flex flex-wrap gap-3`): three items, each a 12px swatch drawn like its segment plus `budget.parse`, `budget.l3`,
  `budget.reserved` and the number in `tabular-nums`. The numbers carry the information; the meter is supplementary.
- Sentence (12px, `text-base-content/70`): `budget.remaining` then `budget.cap`.
- When `tenants.length > 1` (not possible with today's route, kept for the D-19 "per tenant" wording), render a `table-sm` under the
  legend with columns Workspace key (`font-mono`), Parse pages, L3 vision pages, Reserved; the meter then shows the sum.
- Conditional notes, each a `p.text-xs` (or `alert` where stated) under the sentence:
  - `budgetPages === 0`: hide the meter, keep the legend numbers, show `budget.zero`.
  - `used + vlmUsed + reserved > budgetPages > 0`: meter fills completely, sentence is replaced by `budget.over` in `text-warning`.
  - `#RAG_PARSE_ROUTING` value is `fixed`: show `budget.fixed`.
  - `#RAG_PARSE_PREMIUM_PAGE_BUDGET` (the Settings input) holds a number different from `budgetPages`: show `budget.pending`.

### 6.9 Upload monitor (Document Processing tab, Task 2)

The visible monitor is the inline `DocumentProcessor` (finding 1). Its markup (Processing Queue, Live Processing Monitor, Processing
Results cards) does not change; only the states it can show grow.

- **200 response (inline ingest):** unchanged. Same result row, same "completed" wording, same counters.
- **202 response with `jobId`:** the request is done, so the processor moves on to the next file at once. A result row is created
  immediately with status `queued` and updated **in place** as polling answers (one row per upload, never duplicated). The row shows:
  status icon, file name, the localized status (section 12.7), and, when known, the stage code in 12px mono. Polling uses the
  `organizationId` that was selected **when the file was uploaded**, not the current selector value.
- **Polling** `GET /api/rag/admin/ingest-jobs/{jobId}` through `ragFetch`: every 2 s for the first 60 s, then 5 s, 10 s, 20 s, then every
  30 s. Paused while `document.hidden`, resumed with an immediate poll on `visibilitychange` to visible. Stops at a terminal status
  (`ready`, `failed`, `needs_review`, `quarantined`, `skipped_duplicate`), after 30 minutes in total (`monitor.stopped`), on 401/403/404
  (with the matching message), and after 5 consecutive 503 or network failures (`monitor.stopped`). A single 503 or network failure keeps
  polling on the backed-off cadence and shows `monitor.retrying` as a 12px muted line until the next good answer.
- **Terminal and special displays:**
  | Job state | Icon / colour (existing classes) | Text |
  |-----------|-----------------------------------|------|
  | non-terminal, `provisional === true` | `bi-search`, `text-info` | `status.provisional` ("Searchable, still improving"); the row also counts as searchable |
  | `ready` | existing completed look, `text-success` | `status.ready` |
  | `needs_review` | `bi-exclamation-triangle`, `text-warning` | `monitor.needsReview` with the localized reason |
  | `failed` | existing failed look, `text-error` | `monitor.failed` with the localized error class, plus `btn btn-xs btn-outline` `action.retry` |
  | `quarantined` | `bi-shield-exclamation`, `text-warning` | `monitor.quarantined` |
  | `skipped_duplicate` | `bi-skip-forward`, `text-base-content/70` | `monitor.duplicate` |
- **Retry from the monitor:** `POST /api/rag/admin/ingest-jobs/{jobId}/retry` (same `organizationId`), button disabled with
  `action.retrying` while in flight; on success the row returns to `status.queued` and polling restarts at 2 s; errors use section 8.
- **Counters:** a 202 upload counts toward "Processed Today" and the success rate only when it reaches `ready` (success) or `failed`
  (failure). `needs_review`, `quarantined` and `skipped_duplicate` count as processed, not as failures.
- **Activity log:** one entry when queued (`monitor.log.queued`) and one at the terminal status (`monitor.log.ready` /
  `monitor.log.failed` / `monitor.log.needsReview`). No entry per poll. The existing `logActivity` writes `innerHTML`, so every new message
  passes the file name and reason through the existing `escapeHtml` first (or `logActivity` switches to `textContent` for these entries).
- **Live announcement:** `#results-list` gets `aria-live="polite"` only for terminal transitions: the row's status text is updated with
  `textContent` and a visually hidden `span` announces `monitor.announce`. Intermediate stages are not announced.

## 9. Keyboard, screen reader and focus

1. **Sub-tabs.** `role=tablist` with `aria-label` `panel.tabsLabel`; each `button[role=tab]` has `aria-selected`, `aria-controls`, roving
   `tabindex` (0 on the selected, -1 on the others). Left/Right move and activate, Home/End jump to first/last. Panels are
   `div[role=tabpanel][aria-labelledby][tabindex=0]`.
2. **Filters.** Native radios in a `fieldset` with `legend`: Tab enters the group, arrow keys move and select (each move triggers one list
   load; the previous request is aborted). Kind is a native labelled `select`.
3. **Table.** Tab order per row: disclosure button, Retry, Delete. Enter or Space on the disclosure toggles the detail; focus stays on the
   button. Escape inside an open detail closes it and returns focus to its button.
4. **Delete confirmation.** A native `<dialog class="modal">` created with DOM APIs (never `utils/modal.js`'s HTML-string `open()`, which
   would inject the file name as HTML), opened with `showModal()`, `aria-labelledby` the title, `aria-describedby` the body. Focus starts
   on Cancel (`autofocus`); Escape and the backdrop cancel; Tab is trapped by the browser. On close, focus returns to the Delete button
   that opened it, or to the status region when that row is gone. The file name is inserted with `textContent`.
5. **Live regions.** One polite status region per sub-view and one for the budget strip. Announce: load finished with count
   (`jobs.loaded`), empty results, action outcomes, errors. Do not announce detail auto-refresh ticks or the running hint.
6. **Focus visibility.** Use DaisyUI's `focus-visible` outline on every control; the disclosure button adds
   `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2`. Never `outline: none` without a replacement.
7. **Names.** Icon-only buttons have `aria-label`. Row actions include the file name (`action.retryAria`, `action.deleteAria`). Tables have
   captions and `th[scope=col]`. Times use `<time datetime>`.
8. **Motion.** Only the chevron rotation (150 ms, ease-out) and DaisyUI's spinner. Under `prefers-reduced-motion: reduce` the chevron does
   not animate and spinners are replaced by their text (`motion-reduce:hidden` on the spinner element).
9. **Zoom and text size.** At 200% zoom nothing clips: no fixed heights except the 8px meter and 12px ribbon; table cells wrap; the filter
   row wraps.

## 11. What must never be shown (operator allow-list)

1. The panel renders **only** the fields named in sections 6.3 to 6.9, through the builder functions, never by iterating a job object's
   keys. A field the server adds later stays invisible until it is added here on purpose.
2. Never rendered, even if a response contains them: `original_ref`, `settings`, `stage_state`, `source_key`, `file_sha256`,
   `locked_by`, `timings`, `trace_id`, `lease_until`, `run_after`, `runner`, `lineage_id`, `preflight_ref`, `detect_counts`,
   `routing_note`, `embedding_profile`, `priority`, `page_ranges[].cache_id`, `page_ranges[].parser`, `override.updated_by` (a user id;
   the date is shown instead). The test stubs a job carrying all of these with marker values and asserts none of the markers appears in
   the DOM.
3. `tenant_key` is not rendered in the list or the detail (the workspace name is shown instead). It appears only as "Workspace key" in the
   per-tenant budget table, and only when the budget answer holds more than one tenant.
4. No configuration value whose name matches `/(KEY|SECRET|TOKEN|PASSWORD)/i` is read or rendered by `ingestion.js`. The script reads
   exactly four config inputs: `#RAG_PARSE_ROUTING`, `#RAG_INGEST_ASYNC`, `#RAG_INGEST_PIPELINE`, `#RAG_PARSE_PREMIUM_PAGE_BUDGET`. The
   relocated settings block contains no key, secret or password input.
5. No document text, chunk text, markdown or database error text (the routes never return them; the panel never asks).
6. Every server string (file names, reasons, error classes, parser names, `details[].message`) is inserted with `textContent`. The test
   injects `<img src=x onerror=alert(1)>` in a file name, a reason and a parser name and asserts no element is created from them
   (T-03.1-82). The monitor's existing `innerHTML` paths escape new values with `escapeHtml`.
7. No `Authorization` header is added (the admin session cookie is forwarded by the config server; T-03.1-81).

## 12. Copywriting Contract

Voice: plain verbs, sentence case, names from the admin's view. Errors say what happened and what to do. One action keeps one name:
"Retry" (job action) is never used for reloading a view, which is "Reload".

Placeholders in braces are filled by the builders. Numbers use `Intl.NumberFormat(locale)`. Plural forms use `Intl.PluralRules` for `en`
and `it` (`one` / `other`); `zh` has one form.

## 13. Color

DaisyUI theme tokens are the contract; the hex values are the DaisyUI 4.4 defaults for reference only and are never hard-coded, except the
two orange values, which come from the page's `tailwind.config`.

| Role | Token | Reference (dark / light) | Usage |
|------|-------|--------------------------|-------|
| Dominant (60%) | `base-100` | ≈ #1D232A / #FFFFFF | Tab card behind the panel; detail region and dialog box |
| Secondary (30%) | `base-200`, `base-300` | ≈ #191E24, #15191E / #F2F2F2, #E5E6E6 | Panel card; meter and ribbon track; table borders |
| Text | `base-content`, `/70` for secondary | ≈ #A6ADBB / #1F2937 | All text; muted lines use `/70` (never lower for text) |
| Accent (10%) | `primary` (DaisyUI) | theme primary | Retry buttons, tier Save buttons, checked status radio, focus outline |
| Data accent | `myrag-primary` / `myrag-primary-dark` | #FF6417 (dark) / #E05A15 (light) | Paid pages only: budget meter segments and swatches, premium segments and swatch in the page-tier ribbon |
| Info | `info` | theme info | In-progress badges (outline), structured tier segment, tier-bounds note, provisional badge |
| Success | `success` | theme success | Ready badge (outline) |
| Warning | `warning` | theme warning | Needs-review and quarantined badges, sign-in alert, over-budget sentence, settings combination warnings |

Accent reserved for: Retry (row, detail, monitor), Save (tier bounds), the checked status-filter radio, focus outlines. Nothing else is
`primary`. Orange is reserved for metered premium and L3 pages, nothing else (not headings, not links, not the panel title).
