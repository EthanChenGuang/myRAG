## Task 2: Fold migrations into the setup files

- **What is folded.** Per mode, the 0351-0359 files sit between the Phase 3 and Phase 4 sections. They follow `migrationFiles(mode)` order: the common 0353 file, then that mode's 0353 file, never the other mode's. After the Phase 4 section of 04-42 comes a second section with 0420-0424. Each file is copied verbatim under a `-- >>> path` line, so every function keeps its migration's SECURITY mode, search_path and REVOKE/GRANT lines.
- **Why 0420-0424.**
  - 0420-0423 are Phase 3.1 queue hardening.
  - 0424 was reported by 03.1-49. With 04-42 folding 0401-0413, folding 0420-0424 keeps the folded set a contiguous migration prefix. Only Phase 6 (0601, 0602) stays migration-only.
  - 0424 must follow 0408, which it replaces, so it cannot go in the earlier section.
  - The guard that 0424's author wrote into the Phase 3 copy of `rag_write_chunks` is left as it was. The folded 0424 is now the final definition.
- **0409 and 0410.** These stay as 04-42's notes. The 3.1 functions get their grants from their own files, the same grants 0410 gives them, so nothing is duplicated. `tests/rag/search-rpc-grants.test.ts` passes.
- **Bug fixed (RED first).** The common 0353 file created `rag_ingest_broadcast_read` on `realtime.messages` before the mode file defined `rag_ingest_realtime_topic_allowed(text)`. Every Supabase project, where `realtime.messages` exists, failed the migration with `function public.rag_ingest_realtime_topic_allowed(text) does not exist`. PGlite did not catch this because it has no Realtime schema. The policy block now sits in each mode file right after the function, and the common file has a one-line note. The end state is unchanged.
- **Tests.**
  - `schema-equality`: `FOLDED_MIGRATION` also covers `035[1-9]` and `042[0-4]`. New tests check that:
    - every Phase 3.1 migration is folded;
    - both sections appear verbatim, in place and in loader order;
    - the setup alone equals the setup with both sections cut out plus the Phase 3.1 migrations;
    - each setup carries its own mode's topic rule and not the other mode's (function source compared);
    - with a Realtime stub, every migration applies in loader order and the folded setup alone has the same broadcast policy and topic rule, and folded plus migrations equals frozen plus migrations.
  - The policies dump now includes the `realtime` schema.
  - `definer-search-path-pglite` and `search-rpc-grants-pglite`: the folded setup file alone, in both modes, leaves every SECURITY DEFINER function with a fixed search_path. With hosted default function grants, none is open to anon or PUBLIC, and the Phase 3.1 definers are present.
