## Decisions taken while planning (for the orchestrator)

1. D-34's unique index is widened to (batch_id, kind, source_key) so a sampled file can hold its dry_run job and its ingest job in one batch (03.1-01, 03.1-20).
2. Native tier for html and docx runs in the worker through the Phase 3 Docling adapter (Phase 3 research F-11: the app has no extractor for them); txt, md, csv and images stay native in the app through parse-external (03.1-34, 03.1-40). pptx and xlsx route as structured (Claude's discretion).
3. Backfill document rows are created at first claim through an `advance` phase `begin` (same route, extended contract) rather than a fourth callback (03.1-02, 03.1-46).
4. A dry_run job ends with status ready and stage check, with no document row (03.1-40).
5. The admin job list is deployment-scoped across tenants, like the 03-37 quarantine list (03.1-24).
6. The Realtime topic is derived on the client from what it already knows; the status route returns no tenant key (03.1-38).
7. Sidecar-only settings beyond D-42: RAG_INGEST_APP_RATE (callback token bucket) and the test-only RAG_INGEST_CONVERTER and RAG_INGEST_RECORDED_DIR, documented with placeholders in rag-sidecar/.env.example (03.1-27). RAG_INGEST_WORKER_CONCURRENCY is read by both the app (snapshot, Config UI) and the sidecar.
8. All live checkpoints use gate="blocking-human" so auto mode cannot approve them.
9. ROADMAP.md was not edited (this run writes only under the phase directory); its Phase 3.1 "Plans" line should list these 54 plans.
