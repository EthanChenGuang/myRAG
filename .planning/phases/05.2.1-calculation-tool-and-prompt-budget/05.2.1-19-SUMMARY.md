# Phase 5.2.1 Plan 19: Voice agent calculation tool, checked speech and history budget

The voice agent now offers `calculate` on turns that voice-rag marks. It runs each call through `POST /api/internal/voice-calc`. On a checked turn it holds the text back from speech until the check route answers, then speaks the recomputed value. With `VOICE_AGENT_CONTEXT_LENGTH` set, it trims its own history to a quarter of the model window and reports the window and the history size to voice-rag. If the app sends no `calc` member and the variable is unset, the request, the context string, the speech and the stored turn are the same as before.

## Behaviour

- **Without the offer** (no `calc` member): no `tools` in the completion request. Sentences go to speech as before (single match per delta, then the final fragment). The text is not changed, and the stored message has no `calc` field. A pipeline test confirms this, including a literal `[S1]` in the text, which stays untouched.
- **With the offer**: one function tool `calculate`, whose parameters are `calc.tool_schema` and whose description is the chat tool's. Tool-call deltas are assembled per index. Once the first tool-call delta arrives, speech and display are held from the current sentence boundary. After a round that ends with calls, each valid call goes to `executeCalc`. An invalid call (bad JSON, wrong name) gets `{status:'rejected', reject_reason:'invalid_request'}` without a route call. A failed route call gets `{error:'calculation_unavailable'}`. The assistant `tool_calls` message and the `tool` messages are appended, and the next completion is requested. After two tool rounds, the next request carries no `tools`, so the model must answer in text. A further tool-call stream is not executed.
- **Checked turn** (`calc.check` true and a tool was called): the whole text is sent to `checkCalc` with the traces (`origin: 'tool'`, request, result, `anchor_offset` = text length at the tool call, at most five). A replacement span inside the held part is applied to the raw text. Alias markers are then removed, and only then are the sentences handed to TTS. When the check fails or returns null, the text is spoken with markers removed, and the status is `not_verified`. With the check off, the text after the tool streams again sentence by sentence (markers removed), and the status is `not_verified`.
- **Stored turn**: the history and the voice-chat message keep the spoken text as `content`. Tool turns add a top-level `calc: { stated, recomputed, status }` field, which the voice-chat `passthrough()` schema stores as-is in `chats.messages`. The primary check is the corrected check if there is one, else the first check.
- **Offered turn without a tool call**: streams as before. Alias markers are removed from speech and display, because the context now carries `[Sn]` labels and they must not be spoken.
- **Supersession**: checked after every `executeCalc` and `checkCalc` await. A tool turn superseded while it waited speaks nothing, sends no final payload and records no history. This holds even after the new turn resets the cancel flag.
- **History (D-87)**: with `VOICE_AGENT_CONTEXT_LENGTH` set, `trimHistory` runs before retrieval on the non-system history. It drops the oldest whole turns (a user message plus what follows it) until the rest fits 25% of the window. The trimmed list goes to the LLM, and `historyTokens` (the kept size) goes to voice-rag together with `modelContextLength`. The stored transcript is not trimmed. With the variable unset, `rag.query` is called with exactly today's arguments and body.
- **Logs**: the new lines are `[Voice Calc]` (round, call count, statuses; check done or not_verified, status, trace count), `[VoicePipeline] History trimmed` (dropped count, tokens) and `[RAG] Voice calc call failed` / `answer malformed` (action, HTTP status, failure count). None of them carries text.

## Decisions (for STATE)

- **History share 0.25** of the window (left to Claude's discretion under D-87). Estimate: one token per three characters, rounded up, plus 4 tokens per message, with tool calls counted as JSON. This overestimates on purpose; tiktoken is not an agent dependency.
- **Accepted `VOICE_AGENT_CONTEXT_LENGTH` values** are integers from 1,024 to 10,000,000, the voice-rag range. The plan says "a positive integer". A value below 1,024 would make every voice-rag call answer 400, so out-of-range or malformed values count as unset, with one `console.warn`.
- **Where the variable lives**: agent variables such as `VOICE_SERVER_QUERY_REWRITE` are documented only in `voice-agent/.env.example`, not in the app's five config locations or `scripts/rag/env-manifest.json`, which cover the app's `.env.local`. `VOICE_AGENT_CONTEXT_LENGTH` follows that convention.
- **Hold starts at the first tool-call delta.** Text streamed before it is already spoken. A replacement span that starts before the hold point is not applied to speech, and the stored status still records the check. This keeps D-76's "turns without a tool call stream as today".
- **Traces only for calls the route evaluated.** A call that failed validation or transport has no trusted request or result, and an invalid trace would make the check route answer 400 for the whole turn. With no trace, the check is skipped and the turn is `not_verified`.
- **Calc metadata as a top-level message field**, not a content part. The frontend content-part renderer does not know a `calc` part type. A calc-only turn keeps a plain string `content`.
- **Tool description** is copied from `src/lib/rag/generation/calc-tool.ts` (domain-neutral). The agent is a separate package and cannot import app code.
- **Voice-calc timeout** is 10 s per call, so a hung route cannot hold speech forever.

## Deviations

1. `calc_tool.ts` also exports `splitSentences`, `summarizeCheck`, `buildCalculateToolSpec`, `MAX_TOOL_ROUNDS` and `createToolCallAccumulator`, beyond the five names in the plan. The pipeline needs them, and keeping them pure makes them testable.
2. `executeCalc` / `checkCalc` take the scope token as an extra last argument. The route needs `x-rag-scope-token`, and the client does not hold the token.
3. `query()` takes `historyTokens` as a fifth optional argument. The window comes from the client's `contextLength` option, which by default reads `VOICE_AGENT_CONTEXT_LENGTH`.
4. The sentence-queueing code, which was duplicated in two near-identical closures, is now one `queueSentence` helper. Behaviour is unchanged apart from one debug log wording: the old "(stream)" suffix on the incremental-timing log line is gone.
