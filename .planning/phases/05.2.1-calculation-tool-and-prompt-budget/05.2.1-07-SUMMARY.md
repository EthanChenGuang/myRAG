# Phase 5.2.1 Plan 07: Calculation evaluator Summary

**`evaluateCalc(raw, { aliases })` turns a model-authored calculation request into an exact, step-listed `CalcResult` or a typed rejection, with sources checked against this request's aliases, units compared by normalized identity only and every bound read from `config/rag/calc-limits.json`.**

## Accomplishments
- `config/rag/calc-limits.json` and `limits.ts`: validated with `CalcLimitsSchema` at import (an invalid file throws a configuration error), `calcLimits()`, `calcLimitsVersion()` for the 05.2.1-13 config hash.
- `units.ts`: `normalizeUnit` and `sameUnit`, no table.
- `evaluate.ts`: names resolve through a `Map`, operations through the frozen `OPERATIONS` table via `applyOperation`, depth is the longest argument chain, bit and display bounds after each step; every `CalcError` becomes its reason and any other exception becomes `invalid_request`. No I/O and no float token (the existing float-ban scan covers the new files).
- `reject.test.ts`: a seeded generator puts code-like fragments (calls, template literals, arrows, statements, import/require, prototype names, backticks, braces, tags, SQL, shell substitutions, newlines) with random affixes into each of 18 string fields; 720 generated cases plus every fragment alone in every field, all rejected, none throws. Also an extra `expression` key, a JSON `__proto__` key, each D-69 reason and each of the seven limits.
