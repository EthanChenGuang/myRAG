## Behaviour changes
- Eval only, with `RAG_PROMPT_BUDGET` on. The eval route plans before retrieval and passes the packing budget. It trims history oldest-first, finalizes the built request and asserts the question is last. It records `prompt_budget`, `usage` and `answer_error` on the trace.
- Off, eval requests and traces are as before. Chat, embed, voice, strict refusal, webSearch, `source_images` and `{{context}}` are unchanged.
- `PromptBudgetPlan` gains `packingBudget`, an additive field that no product route reads yet.

## Bug found: the document budget is in the wrong unit for packing
`planPromptBudget` gives `documentBudget` in factor-scaled tokens, but packing (`packByRank` / `selectWithinBudget`) counts raw cl100k tokens. Packed documents therefore re-estimate up to `factor ×` the plan: in the RED route test, 2,950 estimated against 2,588 planned. Fix: `packingBudget = floor(documentBudget / factor)`, used by the eval route. Test: `tests/rag/context/prompt-budget.test.ts` "gives the packing budget in raw counter tokens", which failed on the old code with `expected undefined to be 800`.
**Not fixed here (outside this plan's route chain):** `src/app/api/chat/route.ts`, `src/app/api/embed/chat/route.ts` and `src/app/api/internal/voice-rag/route.ts` still pass `documentBudget` as `documentTokenBudget`. On a turn with no history left to drop, they return `prompt_budget_exceeded` for evidence that would have fit after correct packing. Each should switch to `plan.packingBudget`.

**Deviation from the Task 3 "no answer_error" check:** 3 items end with `prompt_budget_exceeded` at finalize, after retrieval, with no history to drop. The fake never saw them, so no request exceeded the window. The built documents exceed the planned document budget by 8 to 17 estimated tokens. The cause is assembly framing that packing's per-block estimate does not count: block separators, and the truncated first block's rendering in v2. For example, v2 `en-context-overflow-001` has documents 2,336, system 767, question 28 and reserve 512. That leaves 453 of the required 461 margin. The fix belongs in packing (count the framing, or trim after rendering), which is shared code from plan 05.2.1-04. Plan 23's gates should expect this until it is fixed.
