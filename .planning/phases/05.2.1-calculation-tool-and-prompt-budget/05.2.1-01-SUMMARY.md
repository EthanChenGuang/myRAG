# Phase 5.2.1 Plan 01: Contracts Summary

**Every Phase 5.2.1 structure (the calculation request, result, trace and check, the prompt-budget config, calibration and trace, and the golden, checks and trace additions) is defined once in Pydantic, with generated Zod and samples. The generated `CalcRequestSchema` is a strict, union-free object that can serve as the `calculate` tool's input schema.**

## Performance

- **Duration:** about 75 min
- **Tasks:** 3 of 3
- **Files:** 2 contract modules and 2 test files created; 6 contract or export files and 2 test files modified; schemas, Zod and samples regenerated

## Accomplishments

- `calc.py`: identifiers follow `^[a-z][a-z0-9_]{0,31}$`, with constructor, prototype, valueof, tostring and hasownproperty rejected. Numbers are decimal strings of at most 30+30 digits, or ISO dates, which are checked to be real dates. Units come from a closed character class with no brackets, quotes, backticks, semicolons, equals or braces. `CalcSource` is a single object, not a union: chunk takes an alias only, question takes nothing, fact_tool takes a tool and a key. Step arguments must name an operand or an earlier step. `result` must name a step. Limits are applied as list lengths.
- `prompt_budget.py`: the D-80, D-81, D-86 and D-88 fields, with bounds (near_limit_ratio 0.5–1, margin_ratio 0–0.5, default_window ≥ 1024, refine_max_calls 1–4, factor ≥ 0.5, default_factor ≥ 1, encoding fixed to cl100k_base).
- `ReviewReason` gains calc_mismatch and calc_unverified; every earlier value still validates.
- `AnswerChecks.calc`, `calc_items` and `prompt_budget` are typed. `{}` still validates, and the new keys are omitted when unset.
- `GoldenItem`: multi_step_calc requires `calc` and context_overflow requires `overflow`, each on its own category only. No existing item rule changed.
- `RagTrace`: the new members are optional and omitted when unset. `answer_error` is a code pattern, so provider text is rejected.
- `CONTRACTS` gains 5 validation-mode and 3 serialization-mode entries. The samples include a request that uses every operation once, a rejected result, one check per status, an exceeded budget trace, and a calibration with a measured and a default family. Variants cover the golden items, the AnswerChecks and RagTrace members, and a conversion operand.
