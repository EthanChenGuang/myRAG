# Phase 5.2.1 Plan 15: Voice calculation route, voice-rag offer and voice prompt budget

The voice agent now reaches the calculation through the server. The new `POST /api/internal/voice-calc` evaluates (`execute`) and checks (`check`) calculations against chunk text that the server reads itself, inside the caller's tenant scope. `voice-rag` tells the agent per turn whether to offer the tool, with which aliased sources and which schema. It also sizes the voice evidence to the agent's window. Every part is behind its switch (`RAG_CALC_TOOL`, `RAG_CALC_CHECK`, `RAG_PROMPT_BUDGET`). With the switches off, both routes behave as before.

## Behaviour

- **voice-calc**: the order is server key (500 when unset, 401 when wrong, the body is not read), then JSON (400), then body schema (400 `{ error: 'invalid_body', path }`, first issue path), then `resolveVoiceScope` (its status), then `RAG_CALC_TOOL` (404 `calc_tool_disabled`), then `check` with `RAG_CALC_CHECK` off (`{ check: null }`, nothing read). Body limits: question up to 4,000 characters, at most 20 sources with unique aliases `S1`..`S999` and UUID chunk ids, `answer_text` up to 8,000 characters, at most 5 traces (`CalcTraceSchema`), `request` validated by `CalcRequestSchema`. `execute` answers `{ result: CalcResult }`. `check` answers `{ check: { checks, notices, replacement } }`, where `replacement` is `{ start, end, text }` for a corrected primary check, else null. The log line is `[Voice Calc]` with the action, status or statuses, reject reason and counts only. A failed source read answers 503 `knowledge_base_unavailable`. The route enqueues no review item (plan 19 records both values).
- **Scoped sources**: `loadVoiceCalcSources` makes one batched chunk read (`id in (...)`, `is_current`, `status = ready`) and one batched document read (`id in (...)`, current and ready, plus the tenant predicate). This is the predicate of the voice keyword fallback and the reference resolver: an organization scope uses `organization_id`; a personal scope uses `user_id` with `organization_id IS NULL`; single-tenant mode uses current and ready only. A chunk outside the scope, quarantined or not current is absent from the map, so `evaluateCalc` rejects it as `unknown_source` and the check cannot locate its operands (`trace_invalid`).
- **voice-rag offer**: with `RAG_CALC_TOOL` on and `shouldOfferCalcTool(query, result texts, D-09 language)` true, the response gains `calc: { offered: true, check: RAG_CALC_CHECK, sources: [{ alias: 'S<position>', chunk_id }], tool_schema: <rag-sidecar/schemas/CalcRequest.schema.json> }`. When the response carries a `context` string, each block gets its alias label: in the tagged context, a `[Sn]` line right after `<doc id="cn" ...>` (the Phase 5 header position); in the untagged agent format, `[Sn] ` before `[Context from document ...]`. Without the offer the string is unchanged.
- **voice-rag budget**: the body takes optional `modelContextLength` (integer 1,024 to 10,000,000) and `historyTokens` (integer 0 to 10,000,000). An out-of-range value answers 400 `Invalid modelContextLength` / `Invalid historyTokens`, with the switch on or off. With `RAG_PROMPT_BUDGET` on and a window given, the budget is `min(voice_document_budget, window − voice_system_reserve − historyTokens − question − voice_answer_reserve − margin)` through `planPromptBudget`. Without a window it is the fixed `voice_document_budget` (2000). The budget goes to `runRetrieval` as `options.documentTokenBudget`. The trace gets a `prompt_budget` stage with counts (window, documents, system, history, question, reserve, near_limit, fixed, dropped_documents from `result.packing`). When even the question does not fit, the route answers 413 `{ error: 'prompt_budget_exceeded', message: notices.prompt_too_long }` in the question's language, before retrieval.

## Decisions (for STATE)

- **Two batched queries, not one.** The plan says "in one query". A PostgREST embedded inner join (`documents!inner`) would put the tenant filter on the embedded table. The fixture edge does not support that, and a single FK must be assumed. One batched chunk read plus one batched document read keeps the reads bounded (no N+1, at most 20 ids) and uses the same filter shape as `refs/resolve.ts` and the voice keyword fallback.
- **Aliases are positional.** `S<n>` is the result's position, so the context labels and the agent's own labels agree. A result without a UUID chunk id (the legacy `'unknown'` placeholder) gets no source entry. Its alias number is skipped, not reused.
- **The replacement text has no unit.** A `NumberMatch` span ends after the digits or the magnitude word (a percent sign is only flagged). So the replacement is the recomputed value formatted exactly like the `calc_corrected` notice value (same places rule), without the unit. This needed `spanValue` on `checkCalculation`'s outcome and `replacement` on `runCalcChecks`'s outcome. `replacement` is present only for a corrected primary, so existing `toEqual` assertions on the outcome still hold.
- **The voice budget needs the window.** `historyTokens` without `modelContextLength` falls back to the fixed voice budget. The plan defines planning "with both fields", and a history size alone says nothing about the window.
- **Planner `reservedTokens { system, history }`.** The voice parts are token counts, not text. They are added to their part as given: not multiplied by the family factor, the history reserve is never trimmed (the agent trims its own history), and `exceeded` is still decided by system, question, reserve and margin, so "even the question does not fit" means 413. The family is null (default factor) because the agent's model id is not sent.
- **Switch order in voice-calc** follows the plan: the scope is resolved before the switch checks. With `RAG_CALC_TOOL` off, an authenticated caller still gets 404 after the token check.
- **Language**: `createAnswerTurn(...).answerLanguage` (D-09) for the offer, the check's number format and the 413 text. When null (languages unset), '' lets the registry fall back to the primary language, then English.
- **The calculation instruction (part 6) is not added to the voice answer block.** `composeSystemPrompt` has no calculation input yet. The agent registers the tool from `calc.tool_schema` (plan 19). Adding it would change the composer, which is outside this plan.
