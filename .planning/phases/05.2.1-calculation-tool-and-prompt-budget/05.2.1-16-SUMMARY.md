# Phase 5.2.1 Plan 16: Calculation and prompt-size UI Summary

**Answer rules card shows calculation limits, window coverage and two budget warnings from new config-server fields; calculate tool parts are silent in the chat; calculation notices and review reasons are pinned in en, zh and it.**

## Performance

- **Tasks:** 3
- **Files modified:** 6 (1 created)

## Accomplishments

- `GET /api/config/answer-rules` returns `calc.limits` (from `config/rag/calc-limits.json`) and `budget` (count of listed models without a context window, default window, measured and defaulted family names). No factor value, sample count or run id is returned. A missing or invalid data file answers 500 with a code (`answer_rules_calc_missing|invalid`, `answer_rules_budget_missing|invalid`, `answer_rules_calibration_missing|invalid`).
- The Answer rules card fills the limits line and the two window lines. Family names render as `font-mono` code with `translate="no"`, through `textContent` only. `warn.overflowNeedsBudget` shows when `refine` is selected with the budget off. `warn.budgetUnknownModels` shows as `alert-info` when the budget is on and the count is above 0. zh and it texts come from UI-SPEC 14.3.
- `visibleToolParts` in `chat-message.tsx` removes `calculate` tool calls and their results before rendering, copying and approval handling. This includes a result that carries only the call id, a rejected call, and an `__REQUIRES_APPROVAL__:<id>:calculate` marker. All other tool parts render as before.
- AnswerNotices already had `calc_corrected` (Calculator, caution, order 3) and `calc_not_verified` (Calculator, neutral, order 4) from Phase 5.2. New tests pin the order, tone, icon, `lang`, one block per notice, exact-duplicate removal, text-only rendering, and that the number in the answer text is left unchanged.
- The review reasons `calc_mismatch` and `calc_unverified` were already in `review-labelling.js` (05.2-37). A test now pins their en, zh and it labels.

## Deviations from Plan

1. **[Rule 1 – Bug] Tokenizer family source.** I first derived the family names from the judge family table (`config/rag/model-families.json`). The budget planner looks up factors by provider prefix (`modelFamily` in `model-window.ts`), so I mirrored that in `answerRulesTokenizerFamily` and added a parity test (`623a0d2`).
2. **No edit to `answer-notices.tsx`, `review-labelling.js` or `index.html`.** Phase 5.2 (05.2-35/37) already implements both calculation kinds and both reason labels. Plan 05.2.1-02 already placed the static inputs and the line hosts. This plan adds tests that pin these.
3. **`notices.prompt_too_long`.** No client change. `prompt_budget_exceeded` is emitted by the chat-route plans (05.2.1-14/18), which are not merged yet. The chat and embed already render the in-band SSE error text, so the server's registry text will show unchanged.
