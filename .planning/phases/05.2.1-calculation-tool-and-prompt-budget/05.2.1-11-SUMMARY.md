# Phase 5.2.1 Plan 11: the calculation check — Summary

Deterministic check of the calculations in an answer (D-73, D-74, D-75, D-95): numbers located per language from the registry `number_format`, recomputation with `evaluateCalc`, operand presence in the cited block or the question, the stated-number rule, and the three outcomes with their notices and review reasons. Three pure modules; nothing is wired yet (chat 18, embed 22, eval 17, voice 15).

## Accomplishments
- `findNumbers(text, format, stats?)`: one linear scan (no backtracking regex). Grouping only between whole digit groups (1–3 digits, then groups of exactly 3), decimal marks, full-width digits when the format declares them, magnitude words (longest first, case-folded, whole word when the word is cased letters), percent flag, leading sign only where it cannot be subtraction. Digit boundaries on both sides; a run that a grouping character or decimal mark continues in a way the format does not allow (`1,25` in en, `3.5` in it) is skipped as a whole; citation markers, URLs and identifiers (digits right after a cased letter: `S12`, `v2`) are skipped. Returns `{ start, end, value: Rational, raw, percent, places, power }` in UTF-16 offsets. No language branch in code.
- `formatNumber(value, places, format, unit?)`: half-even at `places`, the format's first grouping character and decimal mark, then the unit (`%` attached, others after a space).
- `checkCalculation(input)` returns `{ check: CalcCheck, noticeValue }`: recompute over the aliases that have block text (rejection → `trace_invalid`); operand presence (each list value; ISO date operands must occur literally) → `operand_not_located`; `locateStatedNumber` (D-95) → `stated_not_found`; comparison within the declared rounding → `verified` / `corrected`. `trace_hash` is sha256 of `canonicalJson(request)`; `stated_span` marks the stated number. Every returned check validates against `CalcCheckSchema`.
- `stepsListed(rawText, trace, result, language, before?)`: every labelled non-result step's recomputed value appears before `before`.
- `runCalcChecks(input)` returns `{ checks, primary, notices, reviewReasons }`; never throws (`check_error`); one `[Calc]` log line with counts, statuses and reasons only, none when nothing was checked.

## Decisions (for STATE)
- **Grouping spaces follow the data exactly.** en lists U+2009 (thin space), it lists U+0020. A listed space-class separator also accepts the typographic spaces U+00A0, U+2009, U+202F; a plain ASCII space groups only where the format lists it (so en "1 250" is two numbers, it "1 250,5" is 1250.5). Reason: fewer false joins of separate numbers.
- **Malformed runs are skipped whole** rather than split (en "1,25", "1250,000"), so no part of a longer written number is ever matched (T-05.2.1-22). Runs over 60 digits are skipped (the CalcLimits schema bound).
- **Full-width punctuation is not mapped**; only full-width digits (when `fullwidth_digits`). A zh `，` is a clause comma, so mapping it to grouping would join list items.
- **Sign rule:** `-`/`−` counts only after start, whitespace, `(`, `=` or `:` and when the previous non-space character is not a digit (`10 - 5` and `10-12` stay subtraction/range).
- **Identifiers:** digits right after a cased letter (`S12`, `v2`) are not numbers; uncased scripts (Han) are unaffected (`共3项` finds 3).
- **Stated number (D-95 detail):** citing sentences are scanned from the last; the first with a candidate wins. Operand and intermediate step values are skipped unless they equal the recomputed result (so a `min`/`cap` result equal to an operand is still found). Fallback: nearest candidate to `anchor_offset` (text end when null; distance 0 when the anchor is inside the number).
- **Comparison:** with a round step, exact equality with the (already rounded) recomputed value; otherwise the recomputed value rounded half-even to the stated places (≤ 10) at the stated magnitude's scale ("2.1 million" compares 2.1 with the recomputed value in millions).
- **Operand presence is strict equality of rationals** (a block "deduct 5" does not locate operand -5). ISO date operands are located only by their literal ISO string; other written dates give `operand_not_located` (honest `not_verified`).
- **Notice value places:** the round step's places; else the stated places when it has no magnitude word; else the recomputed display's places.
- **runCalcChecks input shape:** `traces` is a plain array (05.2.1-09's holder is not merged); `invalid` accepts a count or the holder's array; `blocks` is `{ alias, text, language? }[]`. Checks order: traces, then invalid blocks; `primary` is the last. A rejected tool trace is skipped; when only rejected traces exist, the trace_missing rule applies.
- **trace_missing:** ordered-list markers at line start (`1.`, `2)`) are ignored; the check records the first unsupported number as `stated` and `stated_span`.
