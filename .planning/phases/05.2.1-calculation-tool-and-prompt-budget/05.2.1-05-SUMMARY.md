# Phase 5.2.1 Plan 05: Registry data for calculation and prompt budget

The language registry now has what Phase 5.2.1 needs. Each pack has a per-language number format and a neutral list of words that signal a computation, and the calculation, trailing-block and condensed-history texts exist in zh, en and it. Code reads these values through one reader, and the trailing-block tag is defined in one place.

## Behaviour changes

None with the switches off. The new fields and texts are read only by later 5.2.1 plans. `instructions.calculation` is composed only when the calculation tool is offered. The two new labels also reach the browser's `FIXED_TEXTS`, which holds only notices and labels, and no component reads them yet.

## Deviations

1. **pack_version not bumped.** The plan asked for a bump. I didn't do it, because the bump would change the ingest fingerprint of every document whose OCR languages are recorded, against Phase 3.3 D-05. Side effect: `answerRulesHashComponent.packVersion` does not change for the new calculation wording. This has no effect until a calculation switch ships.
2. **`notices.prompt_too_long` already existed.** I left it unchanged.
3. **`texts.ts` edited** (outside `files_modified`) to export `fallbackLanguages()`.
4. **Extra files updated to keep the shared key lists in sync:** `config/rag/validate-language-settings.cjs` (TEXT_KEYS), `tests/fixtures/rag/language-pack-completeness-cases.json` (three new cases) and the counts in `tests/rag/lang/texts.test.ts` (39→42 keys, 26→28 client keys).
