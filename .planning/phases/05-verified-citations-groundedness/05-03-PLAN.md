Build the pure, split-safe citation-marker parser the alias path depends on (D-04) and the one grammar both the server and the chat UI use.

  <behavior>
    - findCitationMarkers("a [S3] b") returns one marker {start, end, aliases:["S3"]}; "[S3, S5]", "[S3，S5]" and "[S3、S5]" return one marker with two aliases; "[S3][S5]" returns two markers; "【S3】" and "［S3］" return one marker each
    - "[S0]", "[S03]", "[s3]", "[S 3]", "[S3" (unclosed), "[Source 3]" and "[S3 and S5]" return no marker
    - stripCitationMarkers("Paris [S1] is big【S2】.") returns "Paris is big." with whitespace before a removed marker collapsed and punctuation kept
    - neutralizeCitationMarkers on block text containing "[S1]" or "【S12】" returns text where findCitationMarkers finds nothing and the visible characters other than one inserted zero-width space are unchanged; text without markers is returned identical (same string)
    - MAX_MARKER_HOLD_CHARS equals 16
  </behavior>
  <action>
Per D-04 and research Pattern 2: one module with no imports outside the standard library. Openers `[`, `【`, `［`; closers `]`, `】`, `］` (any opener may close with any closer); alias token is `S` followed by a digit 1-9 and more digits, with no inner whitespace; separators inside one marker are `,`, `，` or `、` with optional spaces. findCitationMarkers returns markers in text order with their UTF-16 offsets. neutralizeCitationMarkers inserts U+200B between `S` and its digits inside every marker it finds (research P-8: the quote snapshot is then the neutralized text "exactly as sent"). Tests first.
  </action>

No imports from `ai` or any provider. Write the exhaustive split tests first.
