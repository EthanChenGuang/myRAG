<objective>
Create the server-side answer-record table with select-own RLS and server-only writes, following the Phase 3 migrations convention, and prove isolation on PGlite.

Purpose: D-16 (table, columns, access rules, tests) and D-03 (the full citation snapshot lives here, independent of documents and chunks). Multi-tenant safety is the project's worst-case failure, so the table is readable only by its owner and writable only by the server role.
Output: one common migration, one per-mode tenant-key migration, schema and RLS tests.

Planner resolution (recorded in 05-PLAN-INDEX.md): chat_id is nullable. The web client creates a new chat's row only after the first answer finishes (src/app/page.tsx debouncedSave then safeCreateChat), so the first answer of a new chat has no chat row when the server writes its record; plan 05-09 attaches the record to its chat when the owner's chat row lists the answerId. The foreign key and ON DELETE CASCADE from D-16 are kept.

Runs after Phase 4 and Phase 3.1 are complete. Relies on: plan 03-01 (supabase/migrations layout, eval/harness/migrations.mts ordering by name, generated tenant_key expression), 04-05 (PGlite role shim with anon, authenticated, service_role and auth.uid()), 04-42 (latest fold of both setup files). Rollout position: D-26 step 3. Execution note: this plan builds PGlite databases; in one working tree do not run it at the same time as plan 05-04.
