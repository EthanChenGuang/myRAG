<objective>
Compare embedding profiles on the golden set per language and per cross-lingual pair (D-43, success criterion 8), report documents ingested before the migration separately, and record the eval evidence the activation gate requires (D-40(c)), so success criterion 10 is shown end to end.

Purpose: EMB-05(c): activation refuses unless the target profile shows no regression beyond the noise band against the active profile, with the pre-migration slice reported; XLG-02: each profile is compared on the cross-lingual slice per pair.
Output: Pydantic comparison and evidence contracts with generated Zod, the comparison builder, the profile-compare harness with pre-migration orchestration, the evidence SQL function and CLI command, tests.

Runs after Phase 2 is complete (every 02-* plan has a SUMMARY).

Scope note (file count, 15): kept as one plan on purpose. Four files are produced by `npm run gen:schemas` (EmbeddingProfileComparison and ActivationEvidence schema JSON, contracts.generated.ts and samples.json) and are never hand-edited. Eleven files are authored; the task file lists hold 7, 3 and 3 entries (Task 1's seven include the regenerated contracts.generated.ts, so it authors six, and Task 2 extends Task 1's test file), and the contracts, the comparison harness and the evidence recording are one chain that success criterion 10 checks end to end.

Deviations from CONTEXT.md (research adjustments adopted):
- F-7 amends D-43: the default-candidate rule reads threshold-free candidate metrics, because another model's score scale changes refusal behaviour under the legacy thresholds.
- The evidence is written only by the CLI with the service key and is bound to the backfill run id and checked against embedded_at by the gate (research security row on forged evidence).
