Build the Config UI side of Phase 3 (D-17, D-18, D-31, D-36, D-45): the upload picker and document-list type change, and three panels (Document types, Quarantine, Embedding profiles) that call the admin routes with a verified Supabase admin session.

Runs after Phase 2 is complete (every 02-* plan has a SUMMARY).

Decisions inside the plan:
- The Config UI has no Supabase session of its own. The RAG panels sign the admin in against Supabase Auth's password endpoint with the public URL and anon key and keep the access token in sessionStorage; the app's requireRagAdmin (delivered by the admin security fix, verified by plan 03-07) verifies it. The existing admin and config routes are out of this plan's scope (D-31); security fixes outside Phase 3 made them admin-only (src/lib/admin-session.ts signs the `admin_session` cookie, and a later fix moves config/* and mcp/* routes onto the same guard). This plan must not change those routes, loosen their checks, or remove any auth header their proxies forward; re-read scripts/config-server.js at HEAD and reuse its shared header-forwarding helper if one exists.
- Panels are separate script files mounted from index.html (research constraint: large files carry regression risk), and plain DOM code matches the existing Config UI modules.
