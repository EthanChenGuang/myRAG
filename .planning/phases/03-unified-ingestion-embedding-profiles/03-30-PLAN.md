<objective>
Teach the document list, delete and status readers about versions (D-11, research §"Related readers and deleters"), so users see one current entry per document and deletes remove the whole lineage.

Purpose: DATA-07 keeps superseded versions for citations; without this the UI would list them as duplicates and a delete would leave older versions behind.
Output: four route updates and tests; behaviour on legacy-only data is unchanged.

Runs after Phase 2 is complete (every 02-* plan has a SUMMARY) and after the documents-route security fix, which lands before Phase 3. That fix gives DELETE and PATCH a session check, resolveTenantScope, a tenant predicate on the read, the delete and the PATCH, and a 404 for another tenant's id, tested in tests/rag/documents-route.test.ts. This plan builds on it and never weakens it.

Deliberate behaviour changes, recorded in the SUMMARY:
- Closing the unauthenticated delete and update is the security fix's change, not this plan's: before it, the route used supabaseAdmin with no session check and no tenant predicate. This plan keeps that closure and replaces the fix's ownership predicate with the tenant_key column plan 03-01 adds (the same expression as scopeKey).
- DELETE widens from one row to the caller's whole lineage (D-11), filtered by tenant_key, so one request can only remove versions in its own tenant.

Decision inside the plan: the current-version filters apply in both pipelines (no switch). That is behaviour-preserving only because plan 03-01 makes every legacy row current version 1: rows that existed are backfilled by 0301, and rows a legacy writer inserts later are completed by the 0305 BEFORE INSERT triggers. This plan therefore relies on 03-01's legacy-shape trigger test and adds a post-migration legacy-writer row to its own fixture (same reasoning as D-08).

Also builds on the images security fix (merged at 7fbdb00): /api/images GET and DELETE now require a session in both modes, run repairOwnerMembership and resolveTenantScope, apply the scope predicate to the list and the delete, and answer 404 for an image that is not the caller's; tests/rag/images-route.test.ts covers it. Task 2 adds only the current-version filter after that scope check.
