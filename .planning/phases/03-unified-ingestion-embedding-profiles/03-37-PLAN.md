Give admins release and delete for quarantined documents (D-31) over fail-closed admin routes, with every action audited and release going through the publish swap.

Decision inside the plan: a quarantined new version never replaced the clean current one (plan 03-10's publish rule), so release performs the swap and delete only removes the quarantined version.

Admin scope (stated so the cross-tenant list is not mistaken for a leak): requireRagAdmin (plan 03-07) checks admin_users, so a RAG admin is a deployment admin who already manages every tenant's documents through the Config UI. The quarantine list therefore spans tenants and shows each item's tenant_key. Tenant owners and organization members are not RAG admins; they see their own document's quarantined status through plan 03-30's list, never the snippets or rule details.
