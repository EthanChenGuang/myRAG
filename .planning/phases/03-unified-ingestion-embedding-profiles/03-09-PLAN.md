Deviations from CONTEXT.md (research adjustments adopted):
- F-8 amends D-35: `p_dims` cannot be a halfvec type modifier, so the RPC reads dims from embedding_profiles, uses dynamic SQL, and treats p_dims only as a cross-check; it also takes `p_require_active` (false only for the eval route's profile comparison) and the tenant predicate is `e.tenant_key = p_tenant_key`.
- F-9 part 2: the RPC sets `hnsw.iterative_scan = relaxed_order` when the installed pgvector is 0.8.0 or later (filtered scans otherwise under-fill, measured 1 of 15).
- F-7 amends D-36: embedding_profiles gains `score_calibration` jsonb (the legacy row holds today's constants 0.7, 0.65, 0.28, 0.25 so nothing changes while RAG_EMBEDDING_PROFILES=off) and `query_instruction` text (F-5).
- Research dimension decision amends D-34: 1024-dim Voyage and Qwen3 profiles are seeded as `available` so plan 03-36's `--derive-from` can fill them from 2048 vectors and the live eval can compare both.
- D-39's "gap recorded in embedding_backfill_runs" is a child table `embedding_backfill_gaps(run_id, chunk_id, profile_id, reason, recorded_at)`, so gaps are queryable per run.
- The gate is in this plan (SQL only); the CLI, admin routes and the evidence writer come in plans 03-40 and 03-46.
