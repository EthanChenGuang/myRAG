Implement the switchable embedding providers (D-33, EMB-01) with the facts the research confirmed, plus the registry rules that make a dims or model mismatch detectable (EMB-03, EMB-05(d)).

Purpose: profiles (plan 03-09) store vectors per provider and dims; ingestion (03-28), re-embed (03-36) and queries (03-26) all embed through these providers.

Deviations from CONTEXT.md (research adjustments adopted):
- F-5 amends D-33: the Qwen3 query format is `Instruct: {task}\nQuery:{query}` with no space after `Query:` (model card), and the instruction text is recorded on the profile row (plan 03-09).
- Research Qwen3 recommendation: never send `dimensions`, `input_type` or `custom_instruction`; request native 4096 dims from both hosts, truncate and re-normalise in the app, and record the serving host (`embedding_host`) so primary/fallback shares are reportable.
- Providers are called with `fetch` (Voyage) and the existing `openai` SDK with a base URL (DeepInfra, OpenRouter): no new npm packages.
