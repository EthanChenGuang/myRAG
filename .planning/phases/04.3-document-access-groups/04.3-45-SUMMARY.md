# Phase 04.3 Plan 45: access groups in the Config UI upload queue, stored-documents table and Connectors tab

**An operator can restrict a file to groups (or mark it Everyone) straight from the Config UI upload queue. Restricted and fallen-back documents carry a badge in the stored-documents table, and a connected provider card warns when its documents fell back to "Uploader and admins only". With the switch off, or a workspace without groups, the queue and its upload form are exactly what Phase 3.2 left.**

## What was built

- **Queue control (Task 1, D-16, UI-SPEC 6.7).** `refreshUploadPickerDefaults` loads the groups of the selected workspace (`GET /api/rag/access-groups`, every page, 50 per page, at most 20 pages) next to the doc-type defaults and stores `{ enabled, personal, groups, shown }` as `uploadPicker.access`. `shown` needs the switch on, an organization workspace (or `s:default`) and at least one group; any failed request hides the control. The queue host `div[data-queue-extras]` is now also created when `shown` is true (one condition added to the existing `extrasWanted`; no second host). `AccessGroupsQueueControls.mount` runs after `scopeTagsMountQueueControls` and appends one `[data-access-groups-queue]` wrapper after Replaces…: a `details.dropdown` with the trigger (`picker.trigger` / `picker.everyone` / `picker.groups`, `bi-people` or `bi-lock`, plus a screen-reader-only `picker.aria` with the file name), the menu (`term.everyone`, a fieldset `field.onlyGroups` with one checkbox per group, `picker.note`, and `picker.clear` once touched, `max-h-72 overflow-y-auto`), and under it the "Visible to" label with removable chips while groups are chosen. Ticking Everyone unticks the groups, ticking a group unticks Everyone, unticking the last group returns to untouched; Escape closes the menu onto its trigger. Choices of groups that disappear on reload are dropped; at 50 chosen groups (the server limit) the other boxes are disabled.
- **Form field.** `buildUploadForm` gains two optional arguments (the queue item and the picker) and appends `access` = `{"everyone":true}` or `{"groupIds":[...]}` (ids only) through `AccessGroupsQueueControls.uploadField`; untouched, hidden or missing controls leave the entries exactly `file`, `doc_type` (byte-identical form). Both `processFile` call sites pass `fileItem` and `this.uploadPicker`.
- **Refusal.** A 400 `group_not_allowed` answer becomes `error.groupNotAllowed` on the failed row and calls `refreshUploadPickerDefaults()`, which reloads the groups. The file is not stored (the server refuses before anything is written, 04.3-23).
- **Stored-documents badge (Task 2, UI-SPEC 6.8).** `createDocumentRow` marks each row with `data-access-groups-doc` (setAttribute); after the rows are appended `renderDocuments` calls `AccessGroupsDocumentBadges.apply(tableBody, organizationId)`. With the switch on and an organization workspace it reads `GET /api/rag/access-groups/documents?ids=` (200 ids per call) and appends, under the file name, the `badge.restricted` badge (`bi-lock`, `badge.restrictedHint` as title) or the warning badge `audience.uploaderOnly` (`bi-shield-exclamation`); Everyone rows get nothing and no group name is shown. `docs.manageHint` is appended inside `#documents-table-container` (the container cleanup keeps only its known children). A re-render cancels an answer still in flight; re-applying never duplicates.
- **Connectors notice (Task 2, D-20, D-22).** Connected provider cards gain a static `<div data-connector-extras></div>` hook; after `renderProvidersList` sets the markup, `applyAccessNotices` passes each connected card's `connection_id` to `AccessGroupsConnectorNotices.apply`, which reads `GET /api/rag/access-groups/connector-map/fail-closed` and the switch state, and appends `div.alert.alert-warning` with `connector.failClosed` (switch on) or `connector.failClosedOff` (switch off) and the count through `Intl.NumberFormat`, plus **Open connector mapping**: clicks the RAG administration menu link, mounts the panel, scrolls `#rag-administration-access` into view (`behavior: 'auto'` under `prefers-reduced-motion`) and calls the panel's `selectMapping()`, which selects the sub-tab and focuses its heading.
- **Label parity (Task 3, decision 26).** `tests/ui/access-labels-parity.test.ts` lists the 164 keys of UI-SPEC 12.2 (51), 12.3 (65) and 12.4 (48) and checks each exists in `ACCESS_GROUPS_LABELS` and `access-group-labels.ts` and is identical in en, zh and it. No difference existed, so no string changed; a one-character mutation of a Config UI string fails it (checked by hand).

## Decisions (for STATE)

1. **Where the groups come from.** The queue reads the admin groups list (`GET /api/rag/access-groups`), not `mine`: the Config UI operator is an admin, so every group of the workspace is offered (UI-SPEC 6.7). Its `enabled` and `personal` fields decide whether the control, the badges and the hint render.
2. **Badges and hint only while the switch is on.** A restricted label is not enforced while off (D-09), so the table stays as today then; the Connectors notice is the only piece shown with the switch off (D-22 wording), as the spec says.
3. **One host, a tail marker.** The Access control lives in Phase 3.2's queue host; `scope-tags.js` keeps `data-queue-extras-tail` children on re-render instead of a second host.
4. **Form contract unchanged.** One `access` field, JSON, group ids only, as recorded in 04.3-23; untouched sends nothing.
5. **Purge hook / store inventory:** none needed, no store added. No migration, no new env variable.

## Deviations

1. **[Rule 3] `scripts/config-ui/rag-panels/scope-tags.js` changed** (not in `files_modified`): two lines so a scope-tag re-render keeps the Access control (decision 3).
