## Decisions (for STATE)

- **Admin model:** `o:` = organization role owner/admin or the organization's `owner_id`; operator `admin_users` rows grant nothing in an `o:` tenant (consistent with "nobody is implicitly ..." in multi-tenant mode). `u:` = the owner only.
- **Effective keys** include `u:<caller>` when a current document carries it (D-05 key set filtered per A-05). Order: `all`, then the rest sorted with `COLLATE "C"` so the TypeScript hash is deterministic.
- **Setter normalisation:** keys are trimmed and lower-cased before dedupe/sort; NULL and blank elements are dropped; a malformed key raises a new reason word `invalid_access_key` (not listed in the plan; needed so no invalid key is stored before the table CHECK fires).
- **Setter lineage:** a document whose `lineage_id` is NULL is treated as its own lineage; the lineage rows are locked `FOR UPDATE` before the before-label is read. `before_groups` is the label of the lineage's current version (else the newest). Two requested ids of one lineage give one audit row (document id = the smaller requested id) and the same outcome for both. `skipped_connector` and `not_found` rows return `after_groups` NULL.
- **Connector-managed** = a `nango_sync_records` row links any version of the lineage in the tenant.
- **Visibility:** `p_access_all` skips only the label predicate, never the tenant (and, for chunks, never the current/ready rule). NULL or empty keys (or a NULL element) without `p_access_all` raise `access_keys_empty`, matching `hybrid_search_chunks` (fail closed). `rag_documents_visible` applies no status rule (any version, D-15 read paths); callers that must hide quarantined/pending documents filter status themselves.
- **Enforcement audit:** `before_groups`/`after_groups` stay NULL for `enforcement_set`; `reason` is `enforced_on` or `enforced_off`. A NULL argument raises `enforced_required`. The audit table's tenant-key CHECK was widened rather than inventing a placeholder tenant key, because the plan names the tenant key `deployment` and the 0920 CHECK rejected it.
