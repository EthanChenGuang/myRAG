# Phase 04.3 Plan 13: derived stores under access groups

**Answer records carry the cited documents' label sets (keys only, NULL when off), a citation of a document the reader can no longer see keeps its quote and loses its link, restricted retrieval-log and review rows are hidden from direct reads by restrictive policies and shown masked to in-tenant experts through the server reader, and both semantic cache backends apply the caller's access.**

## Behaviour changes (all off-state equal to today)

- **Answer records.** `access_sets` is written only when `accessSets` is passed (plan 14 computes it from `RetrievalResult.accessLabels`); without it the insert body is today's and the column is NULL. No restrictive policy on `rag_answer_records`: the owner keeps their delivered history (A-13).
- **Answer read path** (`GET /api/rag/answers`, `GET /api/rag/answers/{id}`). With access groups off, `answerReaderVisibility` returns null and no lookup is added. With them on, the reader's tenant scope is resolved from the record's organization (membership re-checked), the access scope from the session user, and one batched `visibleDocumentIds` call marks hidden documents `unavailable`; `citationDisplayEntries` then renders the quote without a link. Any failure marks every document unavailable.
- **Review queue.** With access groups off, routes call the readers exactly as before. With them on, `listReviewItems`/`getReviewItem` add items that the restrictive policy hid, for tenants where the caller's own `rag_is_domain_expert` call is true, with `query_masked`, `candidates`, `label` and `answer_masked` blanked. Chunks route unchanged: a hidden item is not found there, so no chunk text is served. Direct UPDATE (labelling) of a hidden item affects no row.
- **Retrieval log.** No grant or permissive policy added; the restrictive policy is defence in depth (tested with a simulated grant + `USING (true)` policy in a rolled-back transaction).
- **Semantic cache.** pgvector `rag_cache_check` gets `p_access_keys`/`p_access_all` (nothing while off, so the 5-argument body is unchanged). A redisvl hit with any source the caller cannot see, or a failed check, is a miss and is not invalidated.

## Decisions (for STATE)

1. **Migration number 0934, not 0931.** 0931 was created by plan 12; the brief forbids editing another plan's migration. 0934 was the next free number on every origin branch and was pushed at once.
2. **Self-contained policy helper.** Plan 06's `rag_caller_access_keys()` / `rag_caller_is_access_admin()` are not on this branch (06 is not in depends_on; on train 36 they are 0926). `rag_caller_reads_access_sets(tenant, sets)` computes the caller's keys (`all`, `u:<uid>`, `g:<id>` of groups in that tenant) and tenant admin (rules of `rag_resolve_access_scope`) itself from `auth.uid()`, so 0934 works whether or not 0926 is present. plpgsql so the `organization_members` branch compiles in single-tenant mode.
3. **CHECK is inline** (`jsonb_typeof = 'array'`), following train 35's 0921 change; element validation lives in the predicate, which fails closed.
4. **0410 entry** for the new DEFINER function (section 2, authenticated helper), following the standing rule plans 03, 04 and 12 applied; allow-listed in `tests/helpers/security-definer-allow-list.ts`.
5. **"Drop the document link" = availability `unavailable`.** `CitationRecord.documentId` is required by the generated contract; the existing `documents` availability map already controls the link (`linkDocumentId`), so no contract change.
6. **Masked review rows** come from a second admin read restricted to the caller's confirmed expert tenants and rows with non-NULL sets, merged by `(mined_at, id)` and cut to the page size, so the cursor contract is unchanged.
7. **Cache access hooks injected** (`SemanticCacheIo.access`) with lazy imports in deps.ts, avoiding the `cache → tenant/access → deps` cycle and env loading in the backend tests that plan 12 decision 5 described.
8. **`accessGroupsEnabled()`** exported on its own line so the A-14 seam test's exact `export { scopeAccessFilter }` line stays.
