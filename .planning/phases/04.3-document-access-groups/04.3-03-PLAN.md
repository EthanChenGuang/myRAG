<objective>
Phase tracer: one restricted document stays invisible to an outsider of the same tenant, end to end, through `runRetrieval`, the v2 search stage, the pgvector backend and `hybrid_search_chunks` on a PGlite fixture database, while a member of its group and an admin still get it.

Purpose: prove the whole enforcement path (column, copy trigger, SQL predicate before ranking, branded scope, argument helper, backend, pipeline) on one leg before the other legs, stores and surfaces are built on it (SEC-12, D-05, D-11, D-12).
Output: the first parts of migrations 0921, 0922 and 0930; `src/lib/rag/tenant/access.ts`; `access` threaded through one path; the tracer test.

Standing rules (04.3-PLAN-INDEX.md): block 0920 to 0939 only, never folded; every function `SET search_path = ''`, schema-qualified, followed by literal top-level REVOKE and GRANT; existing functions keep their security mode (A-04); locate every function and symbol by name and read its newest definition at execution time (another session may have landed Phase 3.2's `0802_hybrid_search_scopes_dates_und.sql`: then that body, with `p_scopes`, `p_scopes_include_untagged` and `p_effective_on`, is the one to extend, and its signature is one more to drop); fixtures neutral (`group-a`, `member-a`, `outsider`); `npm ci --ignore-scripts` first when `node_modules` is absent; this plan builds PGlite databases, so do not run it at the same time as another fixture-database plan in this working tree.

Scope of the slice: `RunRetrievalInput.access` is accepted and threaded through the v2 search path here; plan 04.3-08 threads it through every other leg and plan 04.3-09 makes it required at every entry point (D-05 is complete there). When the field is absent, `runRetrieval` treats it as mode off only while `RAG_DOC_ACCESS_GROUPS` is off, and returns the retrieval error status (the existing "knowledge base temporarily unavailable" path) while it is on, so absence never widens visibility.
</objective>
