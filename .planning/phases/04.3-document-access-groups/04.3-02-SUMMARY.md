## Deviations from Plan

1. **[Rule 3 - Blocking] D-26 table renamed to `rag_access_security_events`.** `public.rag_security_events` exists on trunk (Phase 5.2, 0942) with columns `source`, `action`, `detector`, `rule_ids`, `document_id`, `chunk_id`, `uploader_id`, `trace_id` and NOT NULL CHECKs, plus alert functions in 0943. A same-named `CREATE TABLE IF NOT EXISTS` in 0920 would either win on fresh installs (breaking 0943) or be skipped on upgrades (losing the 4.3 columns). The planned columns are kept under the new name. Later plans 05 (`rag_security_event_record`), 07, 14 and 53 must use `rag_access_security_events`.
2. **[Rule 2 - Missing critical] 0410 entry for the new SECURITY DEFINER function.** `tests/rag-db/search-rpc-grants-pglite.test.mts` ("upgraded database ... locked by 0409 and 0410") failed without it: an upgraded hosted database that grants EXECUTE on new functions by default would leave `rag_access_groups_on_org_member_delete()` open to PUBLIC, anon and authenticated. Added the guarded entry (standing rule from 04.2-03).
3. **Commit order.** The migration was committed and pushed before the test to claim number 0920 at once (brief rule after the 0864 collision), so there is no separate RED commit. Test strength was checked by mutation instead: removing the audit `REVOKE ALL ... FROM service_role` turns two tests red.
4. **Fixture user names.** The plan's `group-a`, `group-b`, `member-a`, `member-b`, `outsider` are used; an extra `leaver` user covers the organization-leave cascade.
