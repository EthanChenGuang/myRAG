# Phase 04.3 Plan 24: document, enforcement and label-check routes

**Admins can now list a workspace's documents with their audience and relabel one or many of them over HTTP, and operators can read the enforcement status, run the startup sync and run the label check. The document routes use plan 22's `requireAccessAdmin` (deployment admin or organization owner/admin). Status, sync and drift use the operator guard (`checkAdmin`), because enforcement is deployment-wide. Every answer carries `Cache-Control: no-store`, and failures follow plan 22's `failureOf` mapping.**

## Routes (request and response)

Failures use plan 22's shapes: `{ success: false, error, details? }`. Zod failures return 400 `Invalid request data` with `details: [{ path, message }]`. Guard denials are 401, 403 `Admin access required`, 403 `Forbidden` or 503. Service reasons map through `failureOf`: 409 conflicts, 404 `not_found`, 400 for other reasons, and 503 `access_groups_unavailable` with no database message.

| Route | Guard | Request | 2xx answer |
|-------|-------|---------|------------|
| `GET /documents` | `requireAccessAdmin` | `?organizationId=&filter=restricted\|uploader_only\|everyone\|all&q=&cursor=` (filter defaults to `all`; q ≤ 200, cursor ≤ 600) | `{ success, personal, documents: [Audience], nextCursor, counts: { restricted, uploaderOnly, everyone, all } }`. Counts use the same `q`. 50 per page |
| `GET /documents?ids=` | `requireAccessAdmin` | `?organizationId=&ids=<uuid>,<uuid>,…` (1–200 UUIDs; cannot be combined with filter, q or cursor) | `{ success, personal, audiences: [Audience] }`. Only documents that are current in the workspace are returned; other workspaces' ids and superseded versions are left out |
| `PUT /documents/access` | `requireAccessAdmin` | strict `{ organizationId?, documentIds: uuid[1..500], everyone: true }` or `{ organizationId?, documentIds, groupIds: uuid[1..50] }`. Exactly one of `everyone` and `groupIds` | `{ success, changed, skipped, notFound, audiences: [Audience of each changed document] }`. A single connector document returns 409 `access_managed_by_connector`. A single unknown or other-workspace id returns 404 `not_found`. A deleted group returns 400 `unknown_group` |
| `GET /status` | `requireAccessOperator` | none | `{ success, status: { runningSwitch, databaseFlag, status, ready, reasons, objects, embedGroup: { key, valid, exists, name } \| null, checkedAt } }` |
| `POST /status/sync` | `requireAccessOperator` | none | same as `GET /status`, after the startup sync ran. A failed flag write shows up as `flag_write_failed` in `reasons`, with `status: 'not_ready'`, and is not an HTTP error |
| `POST /drift` | `requireAccessOperator` | none | `{ success, stores: [{ store, rows }], checkedAt }`. Only stores that exist are listed (`rag_access_groups_drift` reports present stores only). No repair action |

`Audience` = `{ documentId, filename, docType, source, status, createdAt, kind: 'everyone'|'uploader_only'|'groups', groups: [{ id, name }], peopleCount, fallbackReason, connectorManaged }`. Groups are returned as id and name pairs, never as keys. `checkedAt` is ISO 8601 text, or `null` before the first startup check.

Audit, propagation to every store, tenant cache invalidation and the external sync enqueue all run in the setter's database triggers (plans 05 and 20). The route only calls `setDocumentsAccess` with the guard's user id as actor (actor kind `admin`, reason `admin_set`).

## Decisions (for STATE)

1. **Operator guard:** `requireAccessOperator` wraps `checkAdmin`, which requires an `admin_users` row with a verified session. It is used for status, sync and drift. A multi-tenant organization owner or admin who is not in `admin_users` gets 403 `Admin access required`, and no enforcement RPC runs (tested).
2. **`ids` mode is exclusive.** Combining `ids` with filter, q or cursor returns 400, so a badge lookup can never be read as a page.
3. **The filter defaults to `all`** on the server. The UI sends `restricted` explicitly (UI-SPEC 6.4 default).
4. **Personal workspaces:** the document routes run in a personal workspace and set `personal: true`. Relabelling to everyone works there, and group ids return `unknown_group`. This follows from the SQL, which has no personal-tenant check on these functions.
5. **`checkedAt` is returned as ISO text.** The service holds epoch milliseconds.
6. **Drift time** is the time the route answered. The SQL returns no time.
7. **Purge hook or store inventory:** none, since no store was added. **No migration**, so no migration number was claimed.
