# Phase 04.3 Plan 21: typed access services through `@/lib/rag`

**Every access operation the routes, the upload path and the Nango sync need is now a typed function in `src/lib/rag/access/`, exported through `@/lib/rag`. Each takes the verified `TenantScope` (tenant key from `scopeKey` only), checks its input before any call, calls the service-role SQL of plans 05, 20 and 30, and parses the rows into camelCase objects. A failure raises `AccessGroupsError` with a reason word from a fixed list and never the database message.**

## Reason list

`AccessGroupsError.reason` is one of: `invalid_key`, `reserved_key`, `invalid_name`, `group_exists`, `member_exists`, `not_a_workspace_member`, `unknown_group`, `unknown_user`, `empty_access`, `count_required`, `not_found`, `personal_tenant`, `mapping_exists`, `rule_exists`, `bad_domain`, `access_managed_by_connector`, `group_not_allowed`, `invalid_argument`, `invalid_cursor`, `invalid_filter`, `actor_required`, or `null` (unknown failure). SQL words `mapping_not_found`, `rule_not_found` and `document_not_found` fold into `not_found` (one 404 answer, UI-SPEC 8.2). Malformed-input words the TypeScript checks catch first (`invalid_provider`, `invalid_kind`, `invalid_status`, `invalid_principal`, `invalid_offset`, `invalid_access_key`, `invalid_actor_kind`, `too_many_*`, `group_required`, `enabled_required`, `owner_required`) fold into `invalid_argument`. `count_required` also carries `error.count`, the current count from the server message. `error.code` is the SQL state or one of `db_unavailable`, `bad_response`; `error.message` is `[RAG Access] <rpc> failed (<code>) <reason>` only.

Suggested HTTP mapping for plan 22: `count_required`, `group_exists`, `member_exists`, `mapping_exists`, `rule_exists`, `access_managed_by_connector` → 409; `not_found` → 404; `personal_tenant` → the personal-workspace view; `db_unavailable` → 503; every other reason → 400.

## Decisions (for STATE)

1. **Keys are built only here.** `setDocumentsAccess` accepts `{ everyone: true }` or group ids (UUIDs) and sends `['all']` or sorted `g:<id>`; anything key-shaped (`g:…`, `all`, `u:…`) in `groupIds`, or an empty list, raises `empty_access` before any call (T-04.3-211).
2. **Relabel outcomes.** `changed`, `skipped` (connector-managed) and `notFound` counts; `audiences` is the 0924 audience view of the changed documents (a second call, `rag_access_document_audience`). A one-document call raises `access_managed_by_connector` or `not_found` instead of returning counts. Audit reason for admin relabels: `admin_set`.
3. **Upload labelling** (`setUploadAccess`) re-checks the key pattern (`all | g:<uuid> | u:<uuid>`), collapses to `{all}` when `all` is present, and writes with actor kind `system`, reason `upload`, actor = the uploader. Group membership was already checked by `uploadAccessKeys` (plan 07); the SQL re-checks tenant membership of every key.
4. **Status.** `accessStatus` reads `rag_access_enforced()` fresh, takes the readiness verdict from `getAccessStartupVerdict()` (`status`, `ready`, `reasons`, `objects`, `checkedAt`), and resolves the embed group with `rag_access_group_by_key` in the embed tenant (`resolveEmbedScope` on `RAG_EMBED_TENANT`, injectable as `deps.embedScope`). `embedGroup` is `null` without a configured key, else `{ key, valid, exists, name }` (`valid: false` for a key that fails the group-key pattern: UI `form.badKey`). No group id and no other group name is returned. Lookup failures give `databaseFlag: null` or `exists: false`, never a throw.
5. **`syncAccessStatus`** calls `syncAccessEnforcementNow` with the same admin client (plus optional startup overrides), then reports as `accessStatus`.
6. **Connector map rows** have `id: null` for a source group seen at a sync that has no mapping yet (0925 returns those rows; UI-SPEC 8.1 "id or null").
7. **`matchConnectorMembers`** returns an array aligned with the input addresses (member id or `null`); the 1-based `idx` from SQL is mapped back, and no address is returned.
8. **Domain rules** are validated in TypeScript with the 0925 pattern (`bad_domain`), lower-cased and trimmed; a non-domain rule with a domain is `bad_domain` too. New rules are created off.
9. **Candidates** below 2 characters return `[]` without a call; queries are trimmed and cut to 200 characters; limit capped at 20.
10. **Logs** carry rpc, code, reason and counts only (`[RAG Access] access call failed`, `documents relabelled`, `connector document fell back`).
11. **Purge hook or store inventory:** none needed; this plan adds no store.
