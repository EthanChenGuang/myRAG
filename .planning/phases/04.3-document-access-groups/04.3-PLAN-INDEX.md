## Rules that apply to every plan

- **Owner rule (illustrations are not product content, REQUIREMENTS domain neutrality).** Fixtures, copy, placeholders and examples are synthetic and neutral: groups `group-a`, `group-b`; people `member-a`, `member-b`, `outsider`; files like `document-a.pdf`; domains `example.org`. Nothing says what a group is for.
- **Seams and trunk moves (D-30, A-11).** Other sessions merge to trunk daily. Every plan locates functions, symbols and files by name and reads the newest definition at execution time; line numbers in research are orientation only. A seam that is absent at execution time is handled in its guarded form and recorded in the plan's SUMMARY. Plan 02 writes `04.3-SEAMS.md`; plan 11 refreshes it.
- **Migrations (D-31, A-04).** Block 0920 to 0939 only; never folded into the setup files; ordered and idempotent; common file first, then `.single-tenant.sql` / `.multi-tenant.sql`; file names match `^(\d{4}_[a-z0-9_]+)(?:\.(single-tenant|multi-tenant))?\.sql$`; header comment with purpose, decision ids, security mode and "Idempotent"; `BEGIN; ... COMMIT;`; constraint adds inside a `pg_constraint` existence check; guarded DDL (`to_regclass`) only around tables, never around `CREATE FUNCTION`; every function `SET search_path = ''`, schema-qualified, `pg_catalog.` built-ins, followed by literal top-level `REVOKE ALL ... FROM PUBLIC, anon, authenticated` and `GRANT EXECUTE ... TO service_role`; only `rag_access_enforced`, `rag_caller_access_keys` and `rag_caller_is_access_admin` are granted to `anon` and `authenticated` (allow-listed); existing functions keep their security mode, new ones are INVOKER unless they must read a table the caller cannot; every redefinition drops every older signature; the last file per mode (0931) defines a function.
- **Switch off is the baseline (D-09).** With `RAG_DOC_ACCESS_GROUPS=off` no new RPC argument is sent, no new SQL text is generated, no `access_scope` stage or `access` trace block appears, the app renders none of the new UI, and every route answers as today.
- **Fail closed everywhere.** A lookup error, a startup verdict that is not ready, an unresolved scope, a missing seam, an unmappable connector permission or a deleted group never widens visibility.
- **Not visible equals unknown.** A document the caller may not see behaves exactly like one that does not exist: same status, body, count, empty text and title (UI-SPEC section 11).
- **Logging.** Tag `[RAG Access]` (Nango code keeps its `logger` calls); ids, codes and counts only; never keys, group names, addresses or content.
- **Barrel ownership.** Only plans 03, 07 and 21 edit `src/lib/rag/index.ts`; every other plan imports what those export. Routes import from `@/lib/rag` only.
- **External backends (A-14).** No plan of this phase edits the Qdrant or Weaviate adapters, `src/lib/rag/backend/qdrant/`, `tests/rag/backend-conformance/cases.ts` or the vector-sync outbox. Phase 7 plans 07-38 and 07-39 own them and read the two seams below.
- **PGlite plans run one at a time.** `workflow.use_worktrees` is false: plans that build PGlite fixture databases (02, 03, 04, 05, 06, 10, 11, 12, 13, 16, 20, 21, 23, 30, 51, 53 and the integration parts of 08) do not run at the same time in one working tree, even when they share a wave. Run them one after another inside the wave.
- **Verification commands.** Every `<automated>` is followed by `<fails_when>`. Count gates carry a baseline measured at `820cba1`; gates that already hold at HEAD are marked `GUARD MUTATION` with what turns them red.
- **Install.** Run `npm ci --ignore-scripts` first when `node_modules` is absent.
- **Commits.** Plain `git commit` with the attribution lines the executor's own session supplies. `.env.local` is created by `scripts/init-env.js` and is never committed.
- **Admin guard.** `checkAdminOrOrgAdmin` (Phase 3.2 plan 16) when it is on trunk, else the equivalent in `src/app/api/rag/access-groups/_auth.ts` built on `checkAdmin` and `isOrganizationMember(..., ['owner', 'admin'])`; plan 22 records which.

## Planner resolutions (not covered verbatim by CONTEXT)

- **Access rides on the tenant scope (A-14).** `RunRetrievalInput` gains no separate `access` field; `runRetrieval` reads `scopeAccessFilter(input.scope)` once and passes the filter to every leg as a required parameter (D-05 as amended). `resolveAccessScope` returns the tenant scope with the access attached.
- **Upload field.** One optional multipart field `access` holding JSON `{"everyone": true}` or `{"groupIds": [...]}`; absent means untouched (UI-SPEC decision 5). Plan 23 records the final format for plans 45 and 46.
- **Upload audit.** Initial labels at upload are written with actor = uploader, actor kind `system`, reason `upload` (the A-07 actor kinds have no uploader kind).
- **Group deletion with an unknown uploader.** The document falls back to the deleting admin's `u:` key, never to `all` (D-18 fail-closed reading).
- **Connector documents.** New connector files are ingested owner-only (`u:<owner>`) and their source sharing is applied right after ingest (RESEARCH Pitfall 7 for connectors); the permission step also runs before the not-modified skip.
- **Owner's own answer records.** No restrictive policy on `rag_answer_records` for the owner (A-13 keeps delivered history); the read path drops links to documents no longer visible.
- **Enforcement audit.** `enforcement_set` rows use tenant key `deployment` (the flag is deployment-wide).
- **Embed effective keys.** `rag_access_group_by_key` returns `labels_current` so the embed scope hashes its effective keys (A-05).
