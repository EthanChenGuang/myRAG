# Phase 04.3 Plan 51: same-tenant cross-group canary matrix (pgvector)

## What was built

- **Seed** (`eval/harness/access-groups.mts`): one database per deployment mode, one tenant (`o:<org>` / `s:default`), identities
  member-a, member-b, outsider and an admin (org admin role / `admin_users`), groups `group-a` and `group-b` created with
  `rag_access_group_create`, members added with `rag_access_member_add`, labels set with `rag_set_document_access_groups`. Per
  language (zh, en, it) one restricted document with a child chunk, an image chunk, an overview chunk, a parent, a stored translation
  and a separate exact-id document; one `all` control document. The Phase 4.2 stores (table rows, identifier index, versions,
  duplicate cluster) are seeded through the product indexer and dedupe service (`seedLookupRows`, `clusterLookupCopies`) and
  restricted to group-a. Documents stay inside the harness, never in `eval/fixtures/corpus`. Content is neutral and synthetic.
- **Matrix**: scopes are resolved with `resolveAccessScope` and the eval identity (`{ kind: 'eval', userId }`, the eval run's
  `RagRunOptions.user_id`), with `RAG_DOC_ACCESS_GROUPS=on` and the database flag synced through `verifyAccessGroupsStartup`.

pipeline and language.

- Qdrant and Weaviate: owned by Phase 7 (07-39, A-14).

## Deviations

1. **Dependency merges.** As instructed, merged `origin/exec/04.3-23` (one conflict in `src/lib/rag/index.ts`, kept both export
   sets). 04.3-16 had no SUMMARY, so `origin/ci/merge-train-37` was merged too: 19 conflicting files, train-37 structure, both
   sides' features kept. The access filter was threaded into the train's refactored `candidateRows` / `digitLookalikeMatches`
   (identifier suggestions and the OCR look-alike read), into the translation leg (`buildTranslationArgs`, lazy
   `scopeAccessFilter` as in `search()`) and into the supersession pair read, which now reads only the access-filtered document
   ids. Contracts were regenerated with `npm run gen:schemas` (it leaves no diff). 0410 is the train body plus the guarded 04.3
   grant lines. The catalog sentinel now classifies the admin (0924), connector (0925), lexstats (0902) and security-admin (0945)
   functions as EXEMPT.
2. **Merge follow-up fixes.** `tests/rag-db/table-lookup.test.mts` failed after the merge: `table-lookup.ts` imported
   `tenant/access` eagerly, which loads server env. It now loads it lazily (the same fix train-35 made in pgvector), and the unit
   cases pass `access: { mode: 'off' }`. `tests/rag/context/version-conflict.test.ts` failed on the pair-read order and now
   keeps the request order. Both tests failed before the fix and pass after it.
3. **Re-upload variant.** A new version is inserted into the lineage with the default label and published by flipping
   `is_current`. This exercises the D-19 inheritance trigger. The full `ingest()` path with `accessKeys` is covered by
   `access-upload.test.mts` (plan 23).
4. **Cache variant.** It checks that `cacheAccessKeyPart` differs between the outsider and member-a, then runs
   `rag_cache_store` / `rag_cache_check` directly under one key hash.
5. **Citation variant.** It calls `createCitationRecheck` and `recordSecurityEvent` against the real database. The session wiring
   is covered by the plan 14 unit tests.
6. **TDD.** This plan only adds tests over existing code, so no RED commit fails on product code. The two negative controls show
   that the matrix fails when the predicate or the backend filter is removed.
