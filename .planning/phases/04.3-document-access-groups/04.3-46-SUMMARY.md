## How it works

- **Store.** `useAccessGroupsStore.load(organizationId)` calls `GET /api/rag/access-groups/mine` (15 s timeout, `no-store`) and keeps the answer: `enabled`, `personal`, `isAdmin`, `ownGroups`, `assignableGroups` (id and name only; any extra field such as a key is dropped). With the switch off, on a failure or on a malformed answer, `mine` is the off answer. A failure writes a string into `error` (`access_groups_mine_<status>`, `_network` or `_timeout`) and never throws. A late answer for an older load is ignored. The dashboard loads it when the upload tab opens, when the workspace changes and when the groups must reload.
- **Picker.** It is rendered when `enabled && !personal && assignableGroups.length > 0`. The menu holds Everyone, a separator, the "Only these groups" label, one checkbox item per assignable group, a separator, the note and, for a touched value, Clear choice. Checkbox items keep the menu open. The state rules follow UI-SPEC 6.2.3. A group the caller can no longer assign is dropped from the display and from the next toggle.
- **Form.** `access` is appended only when the picker is shown and the value is touched: `{"everyone":true}` or `{"groupIds":[...]}`, the 04.3-23 format. The form for an untouched value or a hidden picker is byte-identical to today's (tested).
- **Refusal.** On 400 `group_not_allowed`, the file stays in the queue with its choices. The temporary "processing" row is removed (nothing was stored), the queue row shows `error.groupNotAllowed` (`role="alert"`), the groups reload and the dashboard goes back to the Upload tab. Changing the picker clears the message. The refused value is kept as chosen, so pressing Upload again without a change is refused again rather than falling back to Everyone.
- **Audience.** For a non-admin, `buildAudienceView` returns the reading `restricted`, the word "Restricted" and the hint, and nothing else, whatever the input carries. For an admin it returns the group names line, the people count and, for the fallback audience, the warning tone and the reason. An unknown reason code is rendered in a `code` element inside `reason.other`. `AudienceLine` renders nothing for Everyone in the list and the text in a dialog. The field never offers the fallback audience, cannot be saved empty, pre-chooses nothing for a mixed selection or a fallback document, keeps chips in memory while Everyone is chosen, disables the second radio when no group exists, and shows `field.widen` / `field.widenMany`. `deriveAudienceField(...).submit` is the relabel body choice (group ids or everyone).

## Decisions (for STATE)

1. **Value model:** `{ kind: 'untouched' | 'everyone' | 'groups', groupIds }`, so "untouched" is a state of its own and never becomes Everyone by accident.
2. **The upload row lives in `upload-queue-row.tsx`** (Phase 3.2 moved it out of the dashboard), so the picker is wired there through an `access` prop. The dashboard passes `access` only when the picker is visible.
3. **Refused file stays queued** (see "Refusal" above) instead of becoming a failed row in the stored list, because the file was not uploaded.
4. **Non-admin reading is `restricted`:** the uploader of a fallen-back document sees the neutral mark too; the warning tone and the reason are an admin's.
5. **Strings are generated from the UI-SPEC tables** (12.2, 12.3, 12.4, 12.6 and the `mine.adminSingle` note): 182 keys per locale. All 492 strings shared with plan 42's Config UI table (`ACCESS_GROUPS_LABELS` on `exec/04.3-42`) match exactly; I compared them once with a scratch script. The parity vitest named in UI-SPEC 12 needs both files on one branch and belongs to whichever plan lands second.
6. **No migration, no store, no env variable:** no migration number was claimed, no purge hook was needed, and nothing was synced to the five config places.
