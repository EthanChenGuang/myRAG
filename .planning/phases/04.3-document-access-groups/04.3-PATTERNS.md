### 2. `0921_access_groups_columns.sql` (migration, triggers)

**Analog:** `rag_parent_currency_from_document` and `rag_sync_parent_currency` in `0413_chunking_activation.sql`; `rag_chunks_legacy_defaults` in `0425_search_path_empty.sql`.

**Copy-from-document on the derived row, propagate from the document** (`0413`):

```sql
CREATE OR REPLACE FUNCTION public.rag_parent_currency_from_document()
RETURNS trigger
LANGUAGE plpgsql
SECURITY INVOKER
SET search_path = ''
AS $$
DECLARE
  v_current boolean;
BEGIN
  SELECT d.is_current INTO v_current FROM public.documents d WHERE d.id = NEW.document_id;
  IF FOUND THEN
    NEW.is_current := NEW.is_current AND v_current;
  END IF;
  RETURN NEW;
END
$$;

CREATE OR REPLACE FUNCTION public.rag_sync_parent_currency()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ''
AS $$
BEGIN
  UPDATE public.document_parents p
  SET is_current = NEW.is_current
  WHERE p.document_id = NEW.id AND p.is_current IS DISTINCT FROM NEW.is_current;
  RETURN NULL;
END
$$;

DROP TRIGGER IF EXISTS rag_document_parents_currency ON public.document_parents;
CREATE TRIGGER rag_document_parents_currency
  BEFORE INSERT OR UPDATE OF is_current ON public.document_parents
  FOR EACH ROW EXECUTE FUNCTION public.rag_parent_currency_from_document();

DROP TRIGGER IF EXISTS rag_documents_sync_parent_currency ON public.documents;
CREATE TRIGGER rag_documents_sync_parent_currency
  AFTER UPDATE OF is_current ON public.documents
  FOR EACH ROW
  WHEN (OLD.is_current IS DISTINCT FROM NEW.is_current)
  EXECUTE FUNCTION public.rag_sync_parent_currency();
```

The same file ends its trigger section with a one-off `UPDATE ... FROM public.documents d` that brings existing rows in line, then `REVOKE ALL ... FROM PUBLIC, anon, authenticated` for both trigger functions and `GRANT EXECUTE ... TO service_role` for the propagating one.

**Why the copy function must be `SECURITY DEFINER` here** (comment inside `rag_chunks_legacy_defaults`, `0425`): "SECURITY DEFINER so the lookup does not depend on what the inserting role may read: the chunk's tenant_key is always its document's, whatever the writer sent." Single-tenant clients can insert chunks directly, so the access copy trigger needs the same mode. Do not edit `rag_chunks_legacy_defaults`; add a new trigger function (RESEARCH Pattern 3).

**Guarded DDL for tables that may not exist** (`chunk_translations`, Phase 4.2 stores): the house form is `IF to_regclass('public.<table>') IS NOT NULL THEN <literal ALTER/CREATE INDEX/CREATE TRIGGER> END IF;` inside a `DO` block, as `0353_ingestion_transitions.*.sql` does with `to_regclass('realtime.messages')`. Functions stay top-level (RESEARCH Pitfall 9).

### 3. `0922_access_resolution.sql` (migration, request-response)

**Analog:** `rag_admin_tenant_keys` in `0425_search_path_empty.multi-tenant.sql` for "who administers which tenant" and for mode detection inside a common function.

```sql
CREATE OR REPLACE FUNCTION public.rag_admin_tenant_keys(p_actor uuid)
 RETURNS text[]
 LANGUAGE plpgsql
 STABLE SECURITY DEFINER
 SET search_path TO ''
AS $function$
DECLARE
  multi_tenant boolean;
  keys text[];
BEGIN
  IF p_actor IS NULL OR NOT EXISTS (SELECT 1 FROM public.admin_users a WHERE a.id = p_actor) THEN
    RAISE EXCEPTION 'not_admin';
  END IF;
  multi_tenant := EXISTS (
    SELECT 1 FROM pg_catalog.pg_attribute
    WHERE attrelid = 'public.documents'::regclass AND attname = 'user_id' AND attnotnull AND NOT attisdropped
  );
  IF NOT multi_tenant THEN
    RETURN ARRAY['s:default'];
  END IF;
  keys := ARRAY['u:' || p_actor::text];
  keys := keys || COALESCE(
    (SELECT array_agg('o:' || m.organization_id::text) FROM public.organization_members m WHERE m.user_id = p_actor AND m.role IN ('owner', 'admin')),
    '{}'::text[]
  );
  RETURN keys;
END
```

Note the difference RESEARCH section 4 records: this function requires `admin_users` even for organization admins. `rag_resolve_access_scope` must admit an organization `owner`/`admin` for that organization only (D-04), so copy the role test (`m.role IN ('owner', 'admin')`) but not the `not_admin` raise.

**Tenant-key-first, INVOKER, service_role only** (`rag_cache_sources_current` in `0603`): every new service function opens with `PERFORM public.rag_assert_tenant_key(p_tenant_key);`, is `SECURITY INVOKER` unless it must read a table the caller cannot (A-04), has `SET search_path = ''`, uses `pg_catalog.`-qualified built-ins, and ends the file with a `REVOKE ALL ... FROM PUBLIC, anon, authenticated` / `GRANT EXECUTE ... TO service_role` pair per signature.

## Shared Patterns

### Migration file conventions
**Source:** `0602_hybrid_include_undated.sql`, `0603_semantic_cache.sql`, `0413_chunking_activation.sql`
**Apply to:** every 09xx file
- Header comment: number, purpose, decision ids, security mode, "Idempotent".
- `BEGIN; ... COMMIT;` around the file; `NOTIFY pgrst, 'reload schema';` after function signature changes.
