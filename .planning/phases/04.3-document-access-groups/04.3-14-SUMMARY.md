# Phase 04.3 Plan 14: citation recheck, restricted traces, reference tool, label sets

**Every citation is rechecked against the caller's access in one batched call before the finish metadata is built; a citation the caller may not see is dropped, counted in `accessViolations` and recorded as an id-only security event after the response. Traces and the Langfuse export never carry text of restricted chunks, the reference tool is built per request, and the derived stores receive the cited documents' label sets.**

## Behaviour changes

Off (`RAG_DOC_ACCESS_GROUPS` unset or off): `createCitationRecheck` returns undefined, so no transform is added and the stream, finish metadata, answer record, retrieval-log row, `[RAG Trace]` line, Langfuse export and eval trace are as today (tests: "without recheck (mode off)", "with access groups off …", "has no access field while access is off", "exports everything as today while access is off", "with access off the trace carries no access block"). The one exception is the reference tool (below).

On:
- **Recheck (D-26).** A `finishGateTransform` holds the `finish` part until `recheck(chunkIds of every attached block)` settles, so the synchronous `messageMetadata` callback reads the final result. The filter is applied when metadata and records are read, so transform order does not matter. A citation is dropped when any of its chunk ids is denied or its document has a denied chunk; the kept ones are renumbered `n = 1..k` so no gap shows. `accessViolations` appears only when above 0, and nothing in the answer text marks it (UI-SPEC decision 14). If the recheck rejects, cannot be built, or has not settled when metadata is read, every citation is dropped (fail closed) and the stream continues.
- **Every path.** Chat alias path (session transforms), direct Claude path (the gate goes first in the Claude stream's `extraTransforms`), non-streamed path (`ingestFullText` awaits it), and the eval route (also `settleAccessCheck()` after the Claude answer).
- **Security event.** On a violation from a check that ran, `scheduleSecurityEvent` writes `citation_access_violation` with the dropped chunk and document ids and the trace id as request id, after the response. A failed check writes no event (it is not proof of a violation); it is recorded on the trace as `access_recheck_failed`.
- **Trace.** Chat generation stage: rule `access_violation`, count `access_violations`; collector violations feed the log line. Eval trace: `access: { mode, violations }`.
- **Log line (D-25).** `access_mode`, `access_set` (first 8 hex characters of the set hash; `ACCESS_ADMIN_HASH` for admin_all), `access_violations`. Never keys, group ids or names.
- **Langfuse (D-25).** With `LANGFUSE_CAPTURE_CONTENT`, a kept chunk of a document not labelled exactly `all` is exported as `{ chunk_id, similarity, rank }`. A document with no known label set counts as restricted while access is on. A review export with any such chunk keeps only `model` (query, context and answer are dropped).
- **Label sets (A-06).** `accessSetsFor(result.accessLabels, ids)` gives one sorted key array per document (`UNKNOWN_ACCESS_SET`, a group key nobody holds, for a document whose labels were not read, so the row is readable only by admins). The chat route passes the cited documents' sets to `scheduleAnswerFinish` (`accessSets`); the retrieval-log row gets `access_sets` for the logged candidates' documents.

## Reference tool (D-15)

The module-level `const documentReferenceTool` is gone. `createDocumentReferenceTool(usedDocuments)` is built inside the request handler where the tool map is assembled, after retrieval (so from the access-filtered documents), and passed as `useDocument`. It matches a call by document id, or by name/filename (the context carries names, not ids), answers with the stored name of the matched document, and answers anything else with `NEUTRAL_REFERENCE_RESULT` (`{ success: false, message: '', internal: true }`), the same whether or not such a document exists. It logs only the matched id and relevance, not the model's free text. No state lives at module level.

**Behaviour change while off:** a `useDocument` call naming a document that is not among this request's used documents (by id or name) now gets the neutral result instead of echoing the model's name. Calls about used documents behave as before. The tool result is internal (the UI shows sources from `usedDocuments`). This follows the plan's must-have (D-15, A-12), which is not gated by the switch.

## A-12 note (public `chat-images`)

Image URLs of restricted documents are not returned to callers outside their groups: `source_images` are built only from the access-filtered retrieval result and `usedDocuments`, and the reference tool now accepts only those documents. The image bytes stay in the public `chat-images` bucket, so anyone who already has a URL can fetch it. Signed image URLs remain deferred (backlog).

## Decisions (for STATE)

1. The recheck filters at read time (`finishMetadata`, `fullRecords`, `accessCheck`) rather than inside the cached `finalize()`, so the alias, Claude and fallback paths share one rule and transform order cannot leak a citation. Unsettled means denied.
2. Denied documents are the documents of denied chunks; a citation is dropped when it names a denied chunk or such a document (security first).
3. A failed recheck drops every citation and counts them in `accessViolations`, but writes no security event; the trace carries `access_recheck_failed`.
4. A scope whose recheck cannot be built (`createCitationRecheck` throws, e.g. access on with an unresolved scope) gets a rejecting recheck in both routes, so it fails closed.
5. `TraceAccess` is exported as its own schema (`TraceAccess.schema.json`, sample added) so the generated Zod names it.
6. Access state for traces is set once in `runRetrieval` (`recordAccessScope`), so voice and embed traces also log the mode; the routes only add violations.
7. Unknown labels count as restricted in the Langfuse export and as `UNKNOWN_ACCESS_SET` in stored sets.
8. No migration, so no migration number was claimed. No new store, so no purge hook or inventory entry.
