## Behaviour changes

- Switch off (default): the retrieval request, response and trace of every route equal today's. The chat route makes no extra auth call while off (guarded by `accessGroupsEnabled()`); the other routes call `resolveAccessScope`, which returns the off scope with no lookup. The only new output while off is the `[RAG Access] body_group_claim_ignored` warning when a body names `accessGroups` or `groups`.
- Switch on: every route's scope carries the caller's keys. A refusal (lookup failure, startup not ready) keeps the scope unresolved; `runRetrieval` then fails closed with status `error` (`access_scope_missing`), so each route reuses its existing failure path. A refusal is never reported as "information not available".
- Strict "information not available", webSearch with Exa, `source_images`, `{{context}}`, voice and embed chat: unchanged with the switch off; covered by the characterization suites below.

## Decisions (for STATE)

1. A refusal hands `runRetrieval` the unresolved scope instead of adding a new branch to each route. With the switch on it returns status `error` / `access_scope_missing`, so every route reuses its existing failure path unchanged (chat: unavailable/degraded; embed: unavailable stream; voice-rag: 503 `knowledge_base_unavailable`; eval: 500 retrieval failed; media: continue without context).
2. Chat calls `getSessionUser` for access only while `RAG_DOC_ACCESS_GROUPS` is on (`accessGroupsEnabled`), so the off path makes no extra auth call. A `getSessionUser` throw resolves as anonymous (least privilege), never as a refusal-free admin.
3. Eval run: the strict `RagRunRequest` contract already rejects a top-level `accessGroups` with 400. The claim is logged once before validation (from a cloned body) and the contract is unchanged (A-15).
4. generate-image also logs `accessGroups` / `groups` multipart form fields.
5. No migration, so no migration number was claimed. No store added, so no purge hook or inventory entry.
