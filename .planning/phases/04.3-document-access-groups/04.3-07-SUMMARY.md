## Resolution rules (as built)

| Case | Result | Database calls |
|---|---|---|
| switch off | mode `off`, one shared access object minted once | none |
| personal scope, identity user = owner | `admin_all`, `setHash = ACCESS_ADMIN_HASH` | none (after the readiness gate) |
| anonymous, or eval without a user | keys `all`, hash of `all` | none |
| embed, empty group key | keys `all` | none |
| embed, key found | keys `all`, `g:<id>`; hash over `all` + `g:<id>` when `labels_current`, else over `all` | `rag_access_group_by_key` |
| embed, key not found | keys `all`; `[RAG Access] embed_group_not_found` logged once per process (tenant key only, never the group key) | `rag_access_group_by_key` |
| user, or eval with a user | `is_admin` → `admin_all`; else keys `all`, `u:<user>`, `g:<id>` per group; `setHash = hashAccessKeys(effective_keys ∩ keys ∪ {all})` | `rag_resolve_access_scope` |
| null admin client | 503 `access_unavailable` | — |
| RPC error, throw, empty answer, malformed group id | 503 `access_lookup_failed` | — |
| aborted signal | 503 `access_aborted` | — |
| identity user id not a UUID | 503 `access_identity_invalid` | — |
| switch on and startup verdict not `ready` | 503 `access_not_ready` (waits for a pending or first check) | — |

Every refusal is logged as `[RAG Access] access scope refused { reason }`, with no input text.

## Startup verdict

`verifyAccessGroupsStartup` runs once per process (`register()` in `src/instrumentation.ts`, inside the `Promise.all`) and never throws:
1. Writes `rag_access_set_enforced(p_enforced = switch)` and reads the flag back through `rag_access_enforced()`.
2. Switch off: verdict `off`, no readiness or drift call. A failed write is logged once (`flag_write_failed` / `flag_readback_mismatch`, warn) and does not affect retrieval.
3. Switch on: `rag_access_readiness()` (`TABLE(ready, reasons, objects)`, plan 11), `accessFilter` capability of the selected backend (`getRetrievalBackend()`, loaded lazily to avoid an import cycle), and the drift count. The verdict is `ready` only when nothing failed. Reason codes: `admin_client_missing`, `flag_write_failed`, `flag_readback_mismatch`, `readiness_unavailable` (the function is missing, errored or returned an unexpected shape), `readiness_not_ready` plus the readiness reasons, `backend_without_access_filter`, `startup_failed`. `objects` holds the object names readiness gave.
4. Drift: rows above zero from `rag_access_groups_drift()` are logged once as `[RAG Access] drift { stores: { <store>: <count> } }`.
5. Each call has a 5 s timeout (injectable); a timeout counts as a failure, so startup never hangs.

`syncAccessEnforcementNow()` reruns the checks and returns the new verdict (Config UI sync, plan 24). `getAccessStartupVerdict()` returns `{ status: not_checked | off | ready | not_ready, flagValue, reasons, objects, checkedAt }`.

## Behaviour changes

- With `RAG_DOC_ACCESS_GROUPS=off` (default): at every start the app writes the database flag `false` (one setter call and one read). That is the A-03 "env is the source of truth" rule; it changes nothing for retrieval or for the client (RLS from plan 06 is inactive while the flag is false). Nothing else calls the new code yet; entry points adopt `resolveAccessScope` in plan 09.
- With the switch on: an instance whose startup check is not ready refuses every access resolution with 503 `access_not_ready`.
- `sameAccessFilter` (backend request integrity check from plan 03) now compares the mode, the set hash and the key sets directly, instead of requiring `setHash = hash(keys)`. That was needed because A-05 makes the hash cover only the effective keys. The pgvector forged-hash test still passes.

## Decisions (for STATE)

1. **`mintAccessScope(mode, keys, { setHash })`**: tenant-internal option so the resolver can store the A-05 effective-key hash. It is validated as 64 hex characters, and the default stays the hash of the keys.
2. **`ACCESS_ADMIN_HASH`** = SHA-256 of `mode:admin_all`. A mode-off scope keeps the default hash of no keys. Tests that mint `admin_all` directly keep the default hash, and the resolver always uses the constant.
3. **Effective keys are intersected with the caller's keys** (and `all` is always included) before hashing, so a resolver answer can never put a foreign key into the hash.
4. **Readiness gate is pull-based**: `resolveAccessScope` imports `accessReadyForResolve` from `access-startup.ts` and awaits the memoized check. If `register()` never ran, the first request starts the check itself, so there is no open path. A verdict of `off` while a request resolves with the switch on is also refused.
5. **Gate order**: the identity UUID check comes first, then the readiness gate, then the owner, anonymous and embed short-cuts. All resolutions with the switch on, including those that make no database call, need a ready verdict.
6. **Embed on a personal tenant** uses the same path as any tenant (lookup when a key is configured). Personal tenants have no groups, so a configured key logs `embed_group_not_found` and the caller gets `all`, as RESEARCH §3 states.
7. **`uploadAccessKeys`**: with access off, any group choice is `group_not_allowed`; an empty or non-UUID id list is `group_not_allowed`; returned keys are sorted and de-duplicated.
8. **`createCitationRecheck`** returns a function that **rejects** when the check cannot run (plan 14's "a recheck that rejects drops both and flags") and resolves to the visible subset otherwise. The visibility helpers return only ids that were asked for.
9. **`recordSecurityEvent`** defaults the user to `scope.userId` and returns `false` on failure without throwing. It logs counts only.
10. **Boundary rule scope**: `mint-access-scope` covers `mintAccessScope` and `withAccess` named imports, a namespace import of `tenant/access` or `tenant/access-brand`, and require destructuring, outside `src/lib/rag/tenant/`. A namespace import of `tenant/scope` was already caught by `mint-scope`. `access-rpc` covers the six resolver, flag, readiness, drift and embed-group RPCs in every scanned file outside `src/lib/rag/tenant/` and `src/lib/rag/access/`. `access-admin-rpc` covers the four exact names and the four prefixes outside `src/lib/rag/`. `tests/` and `scripts/tests/` stay allowlisted.
11. **Purge hook or store inventory**: none needed, because this plan adds no store.
