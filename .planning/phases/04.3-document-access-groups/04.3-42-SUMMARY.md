# Phase 04.3 Plan 42: Config UI Access groups panel, Groups sub-view

**Operators can now create, rename and delete access groups and add or remove members from the Config UI. A group can be deleted only after the dialog has shown how many documents and members it affects. Groups is the panel's default sub-tab. It follows the workspace chosen under Document Processing, and a personal workspace shows why it has no groups.**

## Behaviour

- **Sub-tabs.** The order is Groups, then Enforcement. Groups is selected on mount. Once all groups are loaded, its label is `tab.groups` with the count ("Groups: 2"). While no list is loaded, while the workspace is personal, or while more pages remain, it reads "Groups", because the route reports no total. Later calls to `initAccessGroupsPanel()` refresh both views. They keep the selected sub-tab, an open form with its values, and an open members region.
- **Workspace.** `organizationId` comes from the value of `#workspace-selector`, as in the other panels, and goes in the query string of every call. The script inserts the line "Workspace: {name}" above the alert host. It is shown only while `#workspace-selector-container` is visible (multi-tenant). On `change`, the panel closes the form, the editor and the members region, then reloads. `personal: true` in the answer shows `groups.personal`, with no New group and no table.
- **Table.** The Group cell is a `th scope=row` with:
  - the name (14px, `break-words`);
  - the key in `font-mono text-xs break-all translate=no`;
  - the `group.sourceConnector` badge for `source: connector`;
  - below 768px, a 12px line "Members: n / Documents: n".

  Members and Documents are `hidden md:table-cell` and right-aligned in `tabular-nums`. The actions are Manage members, Rename group and Delete group. Each has an `*Aria` name that includes the group, and wraps (`whitespace-normal`, full-height `btn` below `md`). The table sits in a focusable `overflow-x-auto` region. The list pages by 50. After **Load more groups**, focus moves to the first new row's Manage members.
- **New group.** The form opens inline, and focus goes to Name. The key is suggested from the name: lower case, any run outside `[a-z0-9]` becomes one hyphen, and the result is cut to 63 characters. A name without an ASCII letter, or one that would give `all`, suggests nothing. Once the key is typed by hand, it is no longer overwritten. **Create group** stays disabled until the name is filled and the key matches `^[a-z0-9][a-z0-9-]{0,62}$` and is not `all`. The findings line names what is missing, and the button's `aria-describedby` points to it. A key error shows once, at the Key field (`aria-invalid`). Enter does not submit, and Escape closes the form and returns focus to New group. After a create:
  - the form closes;
  - the list reloads quietly (the new row is added locally if it falls outside the first page);
  - `create.done` is announced;
  - focus moves to the new row's Manage members.

  A 409 `group_exists` puts `error.groupExists` at the Key field, moves focus there and keeps both values.
- **Rename.** One row is edited at a time. The editor shows the key read-only. **Save name** is disabled while the name is empty and sends `PATCH /{id} { name }`. On success it announces `rename.done` and returns focus to Rename group. Escape and **Cancel editing** return focus as well. A 404 or a timeout gives the mapped message and a list reload.
- **Members region.** It is a full-width row under the group, with `aria-expanded` and `aria-controls` on the toggle. Only one region is open at a time, and its toggle reads **Close members**. Opening it moves focus to the search field.
  - **Search** runs 400 ms after the last key and only from 2 characters (`members.searchHint` below that). Enter runs it at once. While a search runs, a spinner with "Searching members…" shows and earlier results stay. No match gives `members.noMatch` with the query as text. The list shows at most 20 results. Each result has Add member, or "In this group".
  - **Add member** and **Remove member** act at once. They announce `member.added` and `member.removed`, update the group row's member count, and reload or redraw the table. After a remove, focus goes to the next Remove member button, or to the search field when the list is empty. `member_exists` and `not_a_workspace_member` show their message and reload the members and the search.
  - A member without a display name shows the e-mail, or the id in `font-mono`. `members.empty` replaces the table when the group has no members, and `groups.adminNote` is always shown. Escape anywhere in the region closes it and returns focus to the toggle.
- **Delete dialog.** It is a native `dialog.modal` whose title, counts and body are wired with `aria-labelledby` and `aria-describedby`. Focus starts on **Keep group**.
  - **Counting.** The dialog opens with a spinner and `delete.counting`, and **Delete group** stays disabled until `GET /{id}/impact` answers. The three counts then show as a `dl`: the numbers are right-aligned in `tabular-nums`, zeros included, and the first row is bold. `delete.mappings` appears only when `mappingCount > 0`.
  - **Count failure.** A failed count shows `delete.countUnavailable` with **Count again**, and Delete group stays disabled. A 404 on the count closes the dialog with `error.changed` and a reload.
  - **Deleting.** The delete sends `{ expectedCount: onlyCount }`. A 409 `count_required` recounts, with Delete group disabled, and shows the new numbers before the button is enabled again. A 404 or a timeout closes the dialog with the message and a reload. Any other failure shows an inline `role="alert"` line, and the dialog stays open.
  - **Cancel.** Escape (`cancel`) and the backdrop do nothing while the delete runs.
  - **Success.** The row is removed, `delete.done` is announced with `fellBack`, and focus moves to the status region. After Keep group, focus returns to the opening button, or to the status region if that button is gone.
- **Text only.** Every server string is set through `ragUiEl` as text. The tests inject `XSS_PAYLOAD` and `javascript:` into group names, keys and member names. No element is created, no `a` exists, and there are no `innerHTML` writes.
- **No switch, no env variable, no server change.** The panel calls only the plan 22 routes. With `RAG_DOC_ACCESS_GROUPS=off`, nothing outside the Config UI changes. The admin routes work with the switch off (plan 22), so groups can be prepared first.

## Decisions (for STATE)

1. **The delete dialog is panel-built, not `ragUiConfirmDialog`.** The shared helper enables its confirm button from the start and always closes after `onConfirm`. D-18 needs a confirm that stays disabled until the counts arrive, and a `count_required` recount that keeps the dialog open. `rag-ui.js` is not edited ("later panels use these helpers; they do not edit them"). The dialog repeats the helper's behaviour: native `dialog.modal`, focus on the safe button, cancel and backdrop refused while the request runs, and focus returned to the opener or the status region. It uses the helper's `ragUiNextId`, `ragUiButtonBusy`, `ragUiSpinner`, `ragUiIcon` and `ragUiEl`.
2. **Extra label keys**, in en, zh and it: `tab.groupsPlain`, `panel.workspaceDefault`, `groups.caption`, `rename.running`, `members.adding`, `members.removing`, `members.searching`, `members.loading`, `members.unavailable`, `members.results` and `delete.countsLabel`. They cover the `*.running` texts, the loading, unavailable and caption sentences, and the label before the count is known, none of which are in UI-SPEC 12.3.
3. **The error mapper stays in one place.** `group_exists`, `member_exists`, `not_a_workspace_member` and `count_required` were added to `mapAccessGroupsError`, before its generic 409 handling.
4. **Network and 503 on reads** show the view's `*.unavailable` sentence with Reload panel, as plan 41 did for Enforcement.
5. **`alert.unmapped` is not rendered yet.** Its button opens the Connector mapping sub-tab, which plan 44 adds. `GET /` already returns `alerts.unmappedSourceGroups`.
6. **Purge hook or store inventory:** none, because no store was added. **No migration**, so no migration number was claimed.
