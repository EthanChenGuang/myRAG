## Contract for plans 31 and 32 (TypeScript mappers)

`p_principals` is a JSON array of objects:

| kind | fields | mapped when | key |
|------|--------|-------------|-----|
| `user` | `member_id` (uuid or null, from `rag_connector_match_members`) | the id belongs to the tenant (`rag_access_user_in_tenant`) | `u:<id>` |
| `group`, `team`, `workspace` | `id` (the source id; Drive group addresses are trimmed and lower-cased in SQL) | a `rag_connector_group_map` row of the tenant, provider and kind whose group is in the tenant | `g:<group>` |
| `domain` | `id` (the domain; trimmed, lower-cased) | an enabled `domain` rule of that provider and domain | `all` |
| `anyone`, `public` | — | an enabled rule of that provider and kind | `all` |

`p_status` is `ok` or `source_error`. Outcome reasons: `source_mapped` (all mapped), `owner_only` (no principal at all: `{u:<owner>}`, not fail closed), `unmapped_source` and `source_error` (both `{u:<owner>}`, `fail_closed = true`). `all` among the mapped keys gives exactly `{all}` (the setter's rule). Error words (22023, first in the message): `invalid_provider`, `invalid_status`, `owner_required`, `invalid_principal`, `too_many_principals`, `document_not_found`, `unknown_user`; for the admin functions `invalid_offset`, `group_required`, `mapping_not_found`, `unknown_group`, `invalid_kind`, `mapping_exists`, `rule_not_found`, `enabled_required`, `bad_domain`, `rule_exists`, `too_many_addresses`.

## Decisions (for STATE)

- **Fallback state store.** Added `rag_connector_document_access` (one row per lineage: last reason and `fail_closed`), because a source error leaves no principal rows and an unchanged label writes no audit row, so neither could back `rag_connector_fail_closed_counts`. It cascades with its document; no purge hook needed (document-scoped, like `rag_connector_document_principals`).
- **Principals on a source error** are deleted for the lineage (nothing is known), so the mapping list shows only principals of the last successful read. Principals of every version of the lineage are replaced, then stored under the document id passed in.
- **User principals** are matched by the caller with `rag_connector_match_members` and passed as `member_id`; SQL re-checks tenant membership, so a forged or outside id is unmappable (fail closed), never `unknown_user`.
- **Empty principal list** with status ok gives `{u:<owner>}` with reason `owner_only`, `fail_closed = false` (nothing was unmappable).
- **Owner not in tenant** raises `unknown_user` before any write (the setter would refuse `u:<owner>` anyway).
- **Group lookup matches provider, kind and id**, and joins the group's tenant again (defence in depth over plan 02's same-tenant trigger).
- **Confirmed address** = `auth.users.email_confirmed_at` not null and `deleted_at` null (read through `to_jsonb`, so the fixture shim needs the column; the test adds it). Matching is case-insensitive on trimmed addresses. `s:` = every confirmed user, `o:` = organization members and owner, `u:` = that user only.
- **Document counts** in both lists are the number of document lineages whose last apply left that principal unmapped ("fell back because of it"); a mapped row shows 0 until a document still waits for its next sync.
- **Rule creation** always stores `enabled = false`, whatever `p_enabled` says; a change needs `p_id` and a non-null `p_enabled`. Creating a mapping or rule relabels nothing (applies at the next sync).
- **Audit rows**: `connector_map_set` (reason `created`/`changed`, before/after `{g:<id>}`), `connector_map_delete` (reason `removed`), `sharing_rule_set` (reason `created`/`enabled`/`disabled`), actor kind `admin`; document label changes go through the setter as `document_set` with actor kind `connector`. Unchanged outcomes write no row.
- **Paging**: `rag_connector_map_list` returns 50 rows per call by offset, with `total` on every row; `rag_connector_rules_list` is unpaged (capped at 1000 rows; rules are few).
