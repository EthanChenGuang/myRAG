# Phase 04.3 Plan 31: Google Drive sharing to access groups, fail closed

**`syncSourcePermissions` reads one synced Drive file's sharing through `nango.proxy` (`permissions.list`, read-only), maps each entry to a principal, matches user addresses to tenant members through `matchConnectorMembers` and applies the result with `applyConnectorAccess` (both from `@/lib/rag`). Any fetch, paging, mapping or matching error applies `source_error`, so the document is left to its owner and the tenant admins. No address leaves the function.**

## Behaviour

- **Request:** `GET /drive/v3/files/{fileId}/permissions` with `supportsAllDrives=true`, `fields=nextPageToken,permissions(id,type,role,emailAddress,domain,deleted,allowFileDiscovery,permissionDetails)`, `pageSize=100`, `pageToken` paging and `retries: 3`. Nothing else is called at the source.
- **Mapping:** `user` → address (trimmed, lower-cased) matched to a member id, unmatched → `{ kind: 'user', memberId: null }` (unmappable, closes the document in SQL); `group` → `{ kind: 'group', id: <address trimmed, lower-cased> }`; `domain` → `{ kind: 'domain', id: <domain lower-cased> }`; `anyone` → `{ kind: 'anyone' }`. `deleted: true` entries are ignored; every role grants read; inherited shared-drive entries count like direct ones; duplicate principals are dropped.
- **Fail closed** (`status: 'source_error'`, no principals) with `sourceError` one of: `fetch_failed`, `missing_scope` (401/403 whose body names insufficient scopes), `malformed` (non-object page, `permissions` not an array, unknown type, missing address or domain, non-string token), `incomplete` (more than 50 pages), `too_many` (over `CONNECTOR_MAX_PRINCIPALS`), `match_failed`, `unsupported_provider` (Dropbox and Notion until plan 32), `apply_failed` (see decision 3). A later page that fails never yields a partial list.
- **Summary:** `{ counts: { user, group, domain, anyone }, failClosed, reason, sourceError }`. No address, no keys, no file id. Logs (`logger.error/debug('Nango', …)`) carry provider, error kind and the summary only, never the error object.
- **D-22:** the step reads no switch; it runs and applies with `RAG_DOC_ACCESS_GROUPS=off`.

Behaviour change for users: none yet. Nothing calls `syncSourcePermissions` until plan 32 wires the five sync loops.

## Decisions (for STATE)

1. **Malformed entries fail the whole read** rather than being skipped: a group or domain without its identifier, or an unknown type, could hide a principal that would have closed the document.
2. **Partial reads fail closed:** a failed later page or more than 50 pages is `source_error`, since a missing unmappable entry would leave a wider label.
3. **Apply refusal:** if the mapped apply (`status: 'ok'`) throws, the step applies once more with `source_error` and empty principals (`sourceError: 'apply_failed'`); if that also throws, the error propagates to the sync loop (plan 32 records it on the sync record). The service error message carries no address.
4. **Unsupported providers** fail closed here until plan 32 adds their readers, so a caller wired early can never widen access.
5. **Summary drops `keys`**: the plan's summary holds counts, the fail-closed flag and the reason; `sourceError` was added so the sync banner can tell a missing scope from an outage.
6. **Injectable deps:** `{ access: AccessServiceDeps, nango?, matchMembers?, applyAccess? }`; defaults are `getNango()` and the `@/lib/rag` services. The caller builds `access` (`{ db: () => getSupabaseAdmin(), signal }`).
7. **Purge hook / store inventory:** none needed; no store added.
