# Phase 04.3 Plan 22: group and member routes

**One API under `/api/rag/access-groups` now serves group and member administration for both surfaces, and `GET /mine` serves every signed-in user's own groups. Every route runs guard, parse, workspace, operation in that order; bodies are strict Zod (`zod/v3`); the actor of every write is the user id the guard verified; every answer carries `Cache-Control: no-store`.**

## Admin guard used

`checkAdminOrOrgAdmin` from `src/lib/admin-route-auth.ts` (Phase 3.2 plan 16) is on this branch, so `requireAccessAdmin` wraps it and adds nothing to its admission rule:

- single-tenant: a verified user in `admin_users`, for `s:default`;
- multi-tenant: a deployment admin (`admin_users`) who is also `owner`/`admin` of the named organization, or (no admin_users row) an `owner`/`admin` of exactly the named organization. A deployment admin who names no organization gets their personal workspace.

On top of it, `requireAccessAdmin` splits the 403: a verified caller who is not a member of the named organization at all gets `403 Forbidden` (UI `error.workspace`); a member who is not an admin gets `403 Admin access required`. A deployment admin who is not owner/admin of the organization gets `Forbidden` (the `workspace_forbidden` reason of the existing guard). The scope is then minted by `resolveTenantScope` from the verified user id and organization (it re-checks membership); no route builds a tenant key itself.

`organizationId` comes from the query string, or from the body on POST/PATCH/DELETE `/{id}`; if both are given and differ the answer is 400 (after the guard, which then checks the query's workspace).

## Routes (request and response)

All failures are `{ success: false, error, details? }`. 401 / 403 `Admin access required` / 503 `Admin verification is unavailable` come from `adminDenied`; 403 `Forbidden` and 503 `Workspace verification unavailable` from the workspace step. A Zod failure is 400 `Invalid request data` with `details: [{ path, message }]`. Unless noted, ids in paths must be UUIDs (else 400 with details).

| Route | Request | 2xx answer |
|-------|---------|------------|
| `GET /` | `?organizationId=&cursor=&limit=` (limit 1–50) | `{ success, personal: false, enabled, groups: [{ id, key, name, source, createdAt, memberCount, documentCount }], nextCursor, alerts: { unmappedSourceGroups, enforcement: { runningSwitch, databaseFlag, status, ready, reasons } } }`; personal workspace: `{ success, personal: true, enabled, groups: [], nextCursor: null, alerts: { unmappedSourceGroups: 0, enforcement } }` |
| `POST /` | `{ organizationId?, key, name }` (strict; name trimmed 1–200) | 201 `{ success, group: { id, key, name, source, createdAt } }` |
| `GET /mine` | `?organizationId=`; any verified session | switch off: `{ success, enabled: false }` only, no database call. On: `{ success, enabled: true, personal, isAdmin, ownGroups: [{ id, name }], assignableGroups: [{ id, name }] }`. A non-member of the organization gets 403 `Forbidden`; no session 401 `Authentication required` |
| `PATCH /{id}` | `{ organizationId?, name }` (strict) | `{ success, group }` |
| `DELETE /{id}` | `{ organizationId?, expectedCount }` (strict, integer ≥ 0, required) | `{ success, fellBack, relabelled }`; stale count: 409 `{ success: false, error: 'count_required', count: <current> }` |
| `GET /{id}/impact` | `?organizationId=` | `{ success, impact: { onlyCount, sharedCount, memberCount, mappingCount } }` (pass `onlyCount` back as `expectedCount`) |
| `GET /{id}/members` | `?organizationId=` | `{ success, members: [{ userId, displayName, email, addedAt, source }] }` |
| `POST /{id}/members` | `{ organizationId?, userId }` (strict, UUID) | 201 `{ success, member: { groupId, userId, addedAt } }` |
| `DELETE /{id}/members/{userId}` | `?organizationId=` | `{ success, removed: true }`; not a member: 404 `not_found` |
| `GET /members/candidates` | `?organizationId=&groupId=<uuid>&q=` (q ≤ 200) | `{ success, candidates: [{ userId, displayName, email, already }] }`, at most 20; `q` under 2 characters (after trim) answers `[]` without the candidate search |

`enabled` is `RAG_DOC_ACCESS_GROUPS === 'on'` for this process. Admin routes work with the switch off (UI-SPEC: "every sub-view works"); only `/mine` collapses to `enabled: false`.

### Error codes (UI-SPEC 8.2)

`failureOf` maps `AccessGroupsError.reason`:

- 409: `group_exists`, `member_exists`, `count_required` (with `count`), `mapping_exists`, `rule_exists`, `access_managed_by_connector`
- 404: `not_found` (unknown id and other-tenant id alike; id routes in a personal workspace answer the same)
- 400: every other known reason as the error string (`invalid_key`, `reserved_key`, `invalid_name`, `not_a_workspace_member`, `unknown_group`, `personal_tenant`, ...)
- 503 `access_groups_unavailable`: no reason (database failure, bad response) and `actor_required` (only a broken guard could cause it). The database message never reaches the answer; the log line is `[RAG Access] access groups route failed` with rpc, SQL state and reason.

## Decisions (for STATE)

1. **Guard:** `checkAdminOrOrgAdmin` (present), wrapped by `requireAccessAdmin`, plus the Forbidden/Admin-required split above.
2. **Field names are camelCase** (as the services return them), not the snake_case of the doc-type routes.
3. **Alert inputs in `GET /`:** `unmappedSourceGroups` counts connector-map rows with `id: null` (they sort first; the scan stops at the first mapped row, at most 20 pages of 50). `enforcement` omits the embed group (read by plan 24's status route only), so an organization admin never sees the embed tenant's group name; `accessStatus` is called with `embedScope: () => null`.
4. **Personal workspace:** `GET /` answers `personal: true` with no groups and no group RPC; `POST /` answers 400 `personal_tenant`; id routes answer 404.
5. **Missing `expectedCount`** is 400 with details (path `expectedCount`), a wrong one 409 `count_required` with the current count.
6. **`/mine` checks the session before the switch** (401 without a session even with the switch off).
7. **Non-route helpers live in `_responses.ts`/`_auth.ts`:** Next.js route files export only handlers and `runtime`.
8. **Purge hook or store inventory:** none; no store added. **No migration**, so no migration number was claimed.
