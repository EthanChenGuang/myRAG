## Decisions (for STATE)

- **Delete fallback per lineage.** The uploader is the `user_id` of the lineage's current version (else the newest); the whole lineage falls back to that `u:` key, or to the deleting admin's key when the uploader is unknown. Lineages that keep another key get a `document_set` audit row with reason `group_deleted` (A-07: every label change is audited); fallen-back lineages get one `document_fallback` row each; then one `group_delete` row (`before_groups = {g:<id>}`). Connector-managed lineages are relabelled too, because removing a key only narrows access.
- **Counted confirmation.** `count_required` compares `p_expected_only_count` with the count of current documents labelled exactly `{g:<id>}`, recounted after locking the group row and every version carrying the key; the message carries the current count so the dialog can show it.
- **Member audit target.** `rag_access_audit` has no person column, so member rows carry the member key `u:<id>` in `after_groups` (add) or `before_groups` (remove).
- **Actor required** on every write (`actor_required`), since every admin route has a verified actor.
- **Display name** = `raw_user_meta_data.full_name`, then `.name`, then the e-mail, then the id; read through `to_jsonb(u)` so the fixture shim (id, email only) works. Single-tenant candidates are confirmed, not-deleted `auth.users` rows (the same rule as `rag_access_user_in_tenant`); multi-tenant candidates are organization members plus the owner. Members are listed only while still in the tenant.
- **Candidates** return nothing (no error) below 2 characters; the query is trimmed and cut to 200 characters; `%`, `_` and `\` are escaped; limit is capped at 20.
- **Pages and cursors.** Groups order by `name COLLATE "C", id`; documents by `filename COLLATE "C", id`. The cursor is base64 of `<id>:<name or filename>`, returned on every row; a page is at most 50 rows. A malformed cursor raises `invalid_cursor`.
- **Audience.** `kind` is `everyone` for `{all}`, `uploader_only` when the array is exactly `{u:<uploader>}`, else `groups` (a document with no known uploader that fell back to the admin's key reads `groups` with zero groups and people count 1). `group_ids`/`group_names` are ordered by group id. `fallback_reason` is set only when the latest `document_set`/`document_fallback` audit row of the lineage produced the current label and its reason is `group_deleted`, `unmapped_source` or `source_error`; a later admin relabel clears it. `connector_managed` follows the setter's rule; `source` is the provider of the newest linking `nango_sync_records` row (NULL for uploads). Superseded versions and other tenants' ids are ignored.
- **my groups.** Built on `rag_resolve_access_scope` (same admin model as 04.3-05); a non-admin's assignable groups are their own groups (D-16); a user outside the tenant gets `false, [], []`.
- **Counts** take the same optional file-name query as the list, so the four numbers match the list under a search.
