# Phase 04.3 Plan 47: Access groups tab in the app's workspace settings

**Owners and admins of a team workspace now have an Access groups tab in the workspace settings modal. It lists groups, creates and renames them, manages members by search, deletes a group only after showing the three counts, and maintains connector mapping and sharing rules. It uses the same `/api/rag/access-groups` routes as the Config UI. With the switch off, for a member, or in a personal project, the modal is the same as before: two tabs and the same footer.**

## How it works

- **Visibility.** `showAccessGroupsTab({ enabled, userRole, isPersonal })` is true only when the switch is on, the role is owner or admin, and the workspace is not personal. The modal first checks role and `isPersonal` (the switcher sets it when the opened workspace is in its personal list). Only then does it call `GET /api/rag/access-groups/mine?organizationId=` for that workspace, using the store's pure `accessGroupsMineUrl` and `readAccessGroupsMine` without touching the shared store, which belongs to the current workspace. The tab appears when the answer is `enabled && !personal`. Until then the `TabsList` stays `grid-cols-2`. If the tab disappears while it is selected, the modal goes back to General.
- **Classes.** The trigger and content class strings are the siblings' strings. The cards use the sibling card string with `p-5`, rows use the `WorkspaceTab` member-row string with `p-3`, and Create group, Save name, Create mapping, Create rule and Turn rule on use the modal's Save button string. Delete group in the dialog is `variant="destructive"`. Tests compare the strings against the modal source.
- **Status.** Outcomes and write errors go to one `p[role=status][aria-live=polite].text-sm` at the top of the tab, styled like the modal's existing success and error blocks. No `alert()` or `confirm()` is used (a test checks this). On the Access groups tab the footer shows only Close.
- **Failures (one mapping, `failureOutcome`).** 401 or 403 from any call replaces the whole tab with `error.notAdmin`. A read that fails with 503, a network error or a timeout shows the view's unavailable sentence with Reload groups (or Refresh mapping) and keeps earlier content dimmed (`opacity-60`, `aria-busy`). A write that times out gives `error.outcomeUnknown` and reloads. A 404 gives `error.changed` and reloads. Any other code gives `error.invalid` with the detail.
- **Groups.** `GET /?limit=50` with Load more groups (cursor). Each row shows the name (14/600), the key in mono, Members and Documents counts formatted with `Intl.NumberFormat`, the From a connector word, Manage members (`aria-expanded`, `aria-controls`) and a `MoreHorizontal` menu (sr-only `group.actionsAria`) holding Rename group and Delete group (in destructive text). The New group form suggests the key from the name until the key is edited. A name with no ASCII letter or digit, or a name that would suggest `all`, suggests nothing. Create group stays disabled while the findings line (`aria-describedby`) names what is missing. The pattern and the reserved word `all` are checked in the browser. A 409 `group_exists` (and 400 `invalid_key` or `reserved_key`) shows the message at the Key field, moves focus there and keeps both values. After creation the new row's Manage members takes focus.
- **Members.** Opening moves focus to the search field. The search runs from 2 characters, 400 ms after the last key or at once on Enter, and shows at most 20 results. A late answer for an older query is ignored, and earlier results stay while a new search runs, with a spinner and `members.searching`. Messages: `members.searchHint`, `members.noMatch` (the query as text), `members.already`. Add member and Remove member act at once. 409 `member_exists` and 400 `not_a_workspace_member` show their sentences and reload. A member without a name shows the e-mail address, or else the id in mono. Escape closes the region and focus returns to Manage members.
- **Delete dialog.** It opens with `delete.counting` and Delete group disabled. It shows the three counts as "label: number", including 0, plus the mapping count only when one exists. If the count fails, it shows `delete.countUnavailable` with Count again, and the group cannot be deleted. `DELETE` sends `expectedCount = onlyCount`. A 409 `count_required` recounts. `delete.done` reports `fellBack`. Keep group has initial focus, and Escape and the backdrop do nothing while the delete runs.
- **Connector mapping.** `GET connector-map` (offset paging) and `GET sharing-rules` load together. Unmapped rows come first, with the Not mapped badge (amber, icon and word). Source ids appear exactly as given, in `code.font-mono.break-all[translate=no]`. An unknown kind is shown as its code in mono. The access-group `Select` starts with Not mapped. Save mapping is enabled only when the choice differs and turns into POST (seen row), PUT or DELETE (`mappingSaveIntent`). Remove mapping appears on mapped rows. `mapping.personalNote` shows whenever the server says `visibilityApplies: false` (multi-tenant mode). Rules show a `Switch` with the word On or Off and `rules.toggleAria`. Turning a rule on opens a dialog with the source, the rule and the document count, focused on Keep rule off. Turning it off acts at once. Add domain rule checks the host name in the browser (`rules.badDomain`) and creates the rule off. Both tables sit in focusable `overflow-x-auto` regions with sr-only captions.

## Decisions (for STATE)

1. **The modal reads `/mine` itself** for the workspace it was opened for, rather than calling `useAccessGroupsStore.load`. The store holds the current workspace's answer for the picker and the marks, and the modal can be opened for another workspace.
2. **The role check is client-side for display only.** The server re-checks the role on every call, and any 401 or 403 replaces the tab content (T-04.3-471).
3. **Kind of a New mapping** comes from the source: Google Drive is `group`, Dropbox is `team`, Notion is `workspace` (D-21). The form keeps the three fields of UI-SPEC 6.5.
4. **Read failures do not repeat in the status region.** The unavailable sentence appears once, in the view, with its reload button. Write failures and outcomes go to the status region.
5. **No migration, store, env variable or purge hook.** No migration number was claimed, and nothing was synced to the five config places.

## Deviations

1. **[Rule 2] New label `members.searching`** (en "Searching…", zh, it), because UI-SPEC 7 requires "a spinner with text" during member search and the table had no such key. It is app-only, so the Config UI parity of shared keys is not affected.
2. **No dedicated labels for some outcomes.** "Load more" on the mapping table reuses `action.loadMoreGroups`. Creating a domain rule reports `rules.turnedOff` for the new rule, which is accurate because a rule is always created off. `rule_exists` and `mapping_exists` on an inline row save report `error.changed` and reload. Running buttons other than create and delete show `save.running`.
3. **Members region heading is `h5`** under the card's `h4`, so no level is skipped (UI-SPEC 9.1 names h4 for the Config UI's panel layout).
4. **Sibling tab icons gain `flex-shrink-0`** (see Behaviour changes). The trigger class strings are unchanged.
5. **`contain: inline-size` on the tab root.** Without it, the mapping tables and unbroken 120-character names widened the modal's grid to 825px at 360px. With it, the tab follows the modal's width, and wide tables scroll inside their own regions.
