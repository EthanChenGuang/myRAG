<objective>
Close the direct-client side door: restrictive row-level policies on documents, chunks and parents so a PostgREST read with the anon key or a user token sees only what the caller's groups allow while enforcement is on.

Purpose: server code filters its own reads, but a client can call the REST API directly (D-15); single-tenant read policies admit anon (A-01), so the policy must cover both client roles.
Output: migration 0923 (common helper file plus two mode files), `tests/rag-db/access-rls.test.mts`, allow-list entries.

Standing rules (04.3-PLAN-INDEX.md): block 0920 to 0939, not folded; `DROP POLICY IF EXISTS` then `CREATE POLICY`; schema-qualified names (`public.documents`), even though the older 0405 analog is not; every function `SET search_path = ''`; neutral fixtures; PGlite plan, run alone in this working tree.
</objective>
