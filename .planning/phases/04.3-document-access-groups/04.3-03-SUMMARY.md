## Behaviour changes

- With `RAG_DOC_ACCESS_GROUPS=off` (default): no change in logic. The pgvector backend sends the exact pre-plan argument object (tested), `hybrid_search_chunks` builds the same SQL text, chunks default to `{all}`.
- With `RAG_DOC_ACCESS_GROUPS=on` and a scope never resolved for access, `runRetrieval` returns status `error`, reason `access_scope_missing`, before any stage (fails closed; logged `[RAG Access]`). ## Decisions (for STATE)

1. **Brand split into `access-brand.ts`.** `scope.ts` is imported nearly everywhere; importing `access.ts` (which needs `config` and `deps` for the switch) from it would pull heavy modules into `scope.ts`. The brand primitives live in `access-brand.ts` (only `node:crypto`), `access.ts` re-exports them and adds `scopeAccessFilter` / `accessRpcArgs`. A checker-registration hook was rejected because an exported registrar would let any code accept forged access scopes.
2. **`admin_all` sends `p_access_keys: ['all']`, `p_access_all: true`.** The keys must be non-NULL so the enforcement guard does not raise; the A-14 admin shape carries no keys, so the sentinel `all` is sent.
3. **`mintAccessScope` normalizes** keys to lowercase, de-duplicates, sorts, validates the format, refuses `keys` mode without keys and `off` mode with keys.
4. **Filter equality check in the backend** (`sameAccessFilter`): mode equal, and for `keys` the request's `setHash` must equal the scope's and must be the hash of its own keys; mismatch throws `RetrievalBackendError('hybrid_search_chunks', 'access_filter_mismatch')` before any RPC.
5. **`access` is required on `BackendSearchRequest`**, so every caller must state it. The request builders (`variantSearchRequest`, `createRetrievalPort`, `runBindingLegs`) take an optional `access` and default to `scopeAccessFilter(scope)`; the search stage passes the value `runRetrieval` computed once. Binding legs and the port are therefore covered too (plan 08 still owns translation, parents, exact-id and the other legs).
6. **0410 entries** added for the two new DEFINER functions (`rag_access_enforced()`, `rag_access_groups_from_document()`), following the standing rule 04.3-02 applied.
7. **Copy trigger is only `BEFORE INSERT OR UPDATE OF access_groups` on chunks** as the plan states; propagation of a document relabel to its chunks (AFTER UPDATE on documents) is a later plan. The D-12 join check on `d.access_groups` keeps a stale chunk label from leaking meanwhile.
8. **Tracer seeds** neutral nonsense marker words (`zephyrquill`, `lanternmoss`); the multi-tenant case uses an organization with member-a and outsider as members; one fake edge is shared across both modes (`useDatabase`) because `env.ts` reads the edge URL once per process.
