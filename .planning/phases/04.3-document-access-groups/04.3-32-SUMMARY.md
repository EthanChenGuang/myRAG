# Phase 04.3 Plan 32: Dropbox and Notion mappers, the permission step in every sync loop

**Every connector sync now maps each processed file's source sharing onto its document, also when the content is unchanged, so a sharing change at Google Drive, Dropbox or Notion reaches the label on the next sync. New and changed copies are written owner-only (`u:<owner>`) and mapped right after ingest. Anything that cannot be read or mapped leaves the document to its owner and the tenant admins, and the sync answer says how many.**

## Confirmed Dropbox surface (official spec, `github.com/dropbox/dropbox-api-spec`, `sharing_files.stone`, `sharing_folders.stone`, `files.stone`, `auth.stone`)

The HTML reference page served only navigation to the fetcher, so the routes were read from Dropbox's own Stone spec, which the reference is generated from.

| Route (POST, RPC, via `nango.proxy` `providerConfigKey: 'dropbox'`) | Scope | Body | Answer |
|---|---|---|---|
| `/2/sharing/list_file_members` | `sharing.read` | `file` (path or `id:`), `include_inherited` (Boolean, default `true`: members who only have access through a parent shared folder), `limit` UInt32 1..300 (default 100), `actions` optional | `SharedFileMembers`: `users` (UserFileMembershipInfo), `groups`, `invitees`, `cursor?` |
| `/2/sharing/list_file_members/continue` | `sharing.read` | `cursor` | `SharedFileMembers`; error union adds `invalid_cursor` |
| `/2/sharing/list_folder_members` | `sharing.read` | `shared_folder_id`, `limit` UInt32 1..1000 (default 1000), `actions` optional | `SharedFolderMembers`: `users`, `groups`, `invitees`, `cursor?` |
| `/2/sharing/list_folder_members/continue` | `sharing.read` | `cursor` | `SharedFolderMembers` |

- Member kinds: `UserInfo { account_id, email, display_name, same_team, team_member_id? }` (under `users[].user`); `GroupInfo { group_id, group_name, ... }` (under `groups[].group`); `InviteeInfo` is a union, tag `email` carries the address (`invitees[].invitee = { ".tag": "email", "email": ... }`), tag `other` has none. Every membership has `access_type`; all access types grant read here.
- `files/list_folder` entries of files inside a shared folder carry `sharing_info.parent_shared_folder_id` (`FileSharingInfo`).
- Missing scope: `AuthError.missing_scope` (`TokenScopeError { required_scope }`), HTTP 401, body `{ "error_summary": "missing_scope/...", "error": { ".tag": "missing_scope", "required_scope": "sharing.read" } }`; `proxyErrorKind` reports it as `missing_scope`.

The app calls `list_file_members` with `include_inherited: true, limit: 300` and, when the listing gave a `parent_shared_folder_id`, `list_folder_members` with `limit: 1000`; both follow `cursor` through `/continue` (at most 50 pages each, `retries: 3`).

## Confirmed Notion workspace id path

`getNango().getConnection('notion', connectionId)` answers `ApiPublicConnectionFull` (`@nangohq/node` 0.69.14, `@nangohq/types` `connection/api/get.d.ts`), whose `credentials` are `AllAuthCredentials`; `OAuth2Credentials` extends `CredentialsCommon { type, raw }`. Nango keeps the Notion token response (`POST /v1/oauth/token`, required `workspace_id`) in `raw`, so the path is **`credentials.raw.workspace_id` with `credentials.type === 'OAUTH2'`**. COVERAGE.md's Notion workspace row now names that path. Read once per sync run (a memo on the run, never across requests); only its presence is logged.

## Behaviour

- **Five loops** (`syncGoogleDriveDocuments`, `syncGoogleDriveFilesByIds`, `syncNotionPagesByIds`, `syncNotionPageWithChildren` through `syncNotionPagesByIds` with the same run, and both generic loops of `syncDocumentsForConnection`, single folder and multi-folder): one step per processed file. An unchanged file gets it on its existing document just before the skip; a new or changed file is ingested owner-only and gets it on the returned document; if ingest fails after the file had a document, that old copy gets it too. Files beyond `MAX_FILES_PER_SYNC` are untouched, as before (A-16, T-04.3-327 accepted). No separate permission-call cap.
- **Owner-only at ingest:** `accessKeys: ['u:<owner>']` (unified: on the lineage right after begin; legacy: `access_groups` in the INSERT, the path plan 23 prepared).
- **Wrong-document guard (new):** the step changes a label only when the document is a `nango` document of this connection, this owner and this file (`source_file_id` or `source_key`). Ingest can answer with `duplicateOf` an unrelated document (a content duplicate of another upload); without the guard the connector would relabel, and possibly widen, someone else's document. Tested.
- **Dropbox:** users and email invitees are user principals by address (trimmed, lower-cased), groups are group principals by `group_id`. An invitee without an address, a user without an email, a group without an id, a non-string cursor, a failed page or more than 50 pages fail closed.
- **Notion (D-21):** a page maps to `{ kind: 'workspace', id: <workspace_id> }` plus `{ kind: 'public' }` when `public_url` is set. No workspace id (missing, non-string, non-OAuth2 credentials, `getConnection` throws) is `source_error` with `sourceError: 'workspace_unknown'` for every page of the run; no empty or invented id ever reaches the apply. A non-string `public_url` is `malformed`. `syncNotionPagesByIds` passes the page object it already read; otherwise the reader GETs `/v1/pages/{id}` with retries.
- **Stats and answer:** `SyncStats.failClosed` counts documents the step left with the fallback audience; multi-folder and top-level aggregation sum it. `POST /api/nango/sync` answers `{ ...stats, failClosed }` (0 when absent); the syncAll results carry it per connection. `nango_sync_records.metadata.access` = `{ counts: { user, group, domain, anyone, workspace, public }, failClosed, reason, sourceError }`; no address, key or file id.
- **Apply failure:** if even the closed apply fails, the file counts as `failed` (unchanged file: record left as it was; changed file: record `failed`, the new copy keeps its owner-only label).
- **D-22:** no switch is read; tested with `RAG_DOC_ACCESS_GROUPS=off`.
- **Multi-tenant:** the step runs in the owner's personal tenant scope (`nangoOwnerScope`), tested; visibility for anyone else is unchanged.

Behaviour change for users: with `RAG_DOC_ACCESS_GROUPS` off, none visible (labels are stored, not enforced, D-09). With it on, synced documents follow their source sharing; unmappable ones are owner and admins only.

## Decisions (for STATE)

1. **One step per file, not two:** before the skip for unchanged files, after ingest for written ones, and on the old copy after a failed ingest, so no processed file keeps a wider label and a changed file costs one permission read.
2. **Wrong-document guard** in the sync manager (not SQL): source, connection, owner and file must match before any apply.
3. **Dropbox shared folder:** `list_file_members` already includes inherited members; `list_folder_members` of `parent_shared_folder_id` is read as well (COVERAGE INTEGRATE row). Union of both, deduplicated.
4. **`workspace_unknown`** is a new `SourceErrorKind`, so the sync banner can tell a missing Notion workspace id from an outage.
5. **Summary counts** gained `workspace` and `public` (all six kinds always present); two plan 31 Drive tests updated to the six-key shape.
6. **Providers without a reader** (box, confluence in the generic loop): new copies are written owner-only and the step does nothing; they are not counted in `failClosed`.
7. **Purge hook / store inventory:** none needed; no store added. No migration, so no migration number claimed.
