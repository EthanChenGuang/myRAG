<objective>
Build the server-side resolution of a caller's access scope, the startup check that keeps the database flag equal to the env switch and blocks retrieval when something cannot filter, the batched visibility helpers, and the boundary rules that keep all of it inside the RAG module.

Purpose: groups come only from verified identity (D-05, D-06, D-07), membership is read fresh per request (D-08), and the switch on never runs with a path that cannot filter (D-10, A-03).
Output: resolver, startup module, visibility module, exports through `@/lib/rag`, boundary rules with self-tests, unit tests.

Standing rules (04.3-PLAN-INDEX.md): plans 03, 07 and 21 are the only plans that edit `src/lib/rag/index.ts`; later plans import what is exported here; log tag `[RAG Access]` with ids, codes and counts only; errors carry no input text; neutral fixtures; `npm ci --ignore-scripts` first when `node_modules` is absent. `rag_access_readiness()` is written by plan 11; this plan calls it by name and treats a missing function as not ready (fail closed).
</objective>
