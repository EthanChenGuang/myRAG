## Behaviour

- **Sub-tabs.** The order is now Groups, Documents, Connector mapping, Enforcement.
  - Connector mapping loads only when first selected: `GET connector-map` and `GET sharing-rules` run in parallel. Opening the panel sends no extra request.
  - Panel refreshes and workspace changes reload the sub-view once it has been opened.
  - The tab label is `tab.mappingUnmapped` with the count while source groups are not mapped, otherwise `tab.mapping`.
- **alert.unmapped.** While the count is above zero, the panel's alert host shows `alert alert-warning` `alert.unmapped` with the count and **Open connector mapping**. It shows on every sub-view, whether the switch is on or off.
  - The count comes from `GET /` (`alerts.unmappedSourceGroups`).
  - Once every mapping page has been loaded, the count is taken from the rows on screen instead, so it updates right after a save.
  - **Open connector mapping**, here and on the Documents rows from plan 43, selects the sub-tab and focuses its `h4` heading (`data-access-groups-mapping-heading`, `tabindex=-1`).
- **Mapping table.** Columns: Source, Group or team at the source (`th scope=row`), Documents, Access group, Actions.
  - Unmapped rows come first, keeping the server order within each part. They carry the `badge-warning badge-outline` Not mapped badge with `bi-exclamation-triangle`.
  - The source id is shown exactly as given, in `code.font-mono.text-xs.break-all[translate=no]`, followed by the kind in words: Group, Team, or Whole workspace for Notion.
  - Product names come from the Connectors tab's provider configuration (`window.connectorsConfig.config.providers[].button_label`). When that is not loaded, the names from `src/lib/nango/types.ts` are used. They are never translated.
  - Documents is `hidden md:table-cell`. Below md, the count shows under the id as "Documents: n".
- **Access group select and Save mapping.** The select's first option is Not mapped; the others are the workspace groups by name.
  - Save mapping is enabled only when the select differs from the saved value.
  - What Save mapping does:
    - on an unmapped row: POST `{ provider, kind, externalPrincipalId, groupId }`;
    - on a mapped row with another group: PUT `{ groupId }`;
    - on a mapped row with Not mapped: DELETE, the same as **Remove mapping**.
  - `organizationId` goes in the query string, as on the other routes.
  - Outcome messages: `mapping.saved` and `mapping.removed`, which end with when the change applies. Focus then moves to the status region and the table reloads quietly.
- **New mapping form.** Fields: Source (select), Group or team ID at the source (mono input with `autocomplete=off`, `spellcheck=false` and `translate=no`), Access group (select).
  - The findings line `mapping.need` names the missing fields. **Create mapping** is disabled until all three are filled and is described by that line.
  - The kind comes from the source: Google Drive gives `group`, Dropbox `team`, Notion `workspace` (D-21).
  - `mapping_exists` shows `error.mappingExists` at the id field (`aria-invalid`, focused), and the form stays open.
  - Escape and **Close form** close the form and return focus to New mapping.
- **Multi-tenant mode.** The `alert-info` `mapping.personalNote` shows above the tables when the answer says `visibilityApplies: false` (A-10).
- **Empty states.** `mapping.empty.title` and `.body` for the mapping table; `rules.empty` for the rules table.
- **Personal workspace.** `groups.personal` replaces both tables.
- **Errors.** A sign-in or workspace failure replaces the sub-view with one shared alert. A 503 or network failure shows `mapping.unavailable` with Reload panel.
- **Paging.** The mapping table shows 50 rows and pages by `offset` with **Load more source groups**; focus moves to the first new row's select. The rules table pages in the browser, 50 rows at a time, with **Load more rules**.
- **Sharing rules.** Columns: Source, Shared with (`th scope=row`; the domain is a code element), Documents, Counts as Everyone.
  - The toggle is `toggle toggle-sm` inside a label with the visible word On or Off. Its accessible name is `rules.toggleAria`.
  - **Turning a rule on** reverts the toggle and opens `ragUiConfirmDialog`:
    - primary tone, with focus on **Keep rule off**;
    - the body names the source, the rule and the document count;
    - **Turn rule on** sends PUT `{ enabled: true }`, then `rules.turnedOn`.
  - **Turning a rule off** sends PUT `{ enabled: false }` at once, then `rules.turnedOff`.
  - **Add domain rule** opens a form with Source and Domain:
    - the domain is trimmed and lower-cased, then checked with the same pattern as the server;
    - a malformed domain shows `rules.badDomain` with `aria-invalid`, and Create rule stays disabled;
    - the POST body has no `enabled` field, so a rule is always created off;
    - the message is `rules.created`.
- **Nothing in the view starts a sync.** Every outcome message says when it applies.
- **Text only.** Source ids, domains and group names are rendered with `textContent`. The tests inject `XSS_PAYLOAD` and `javascript:`: no element is created, no `a` exists and `innerHTML` is never written.
- **No switch, no env variable, no server change.** The view calls only the plan-33 routes.

## Decisions (for STATE)

1. **Lazy load.** Connector mapping loads on its first selection, like Documents.
2. **Unmapped count.** It comes from `GET /` until every mapping page is loaded; after that, the rows on screen are counted. When the mapping list is not complete, a mapping write also reloads `GET /` quietly to refresh the count.
3. **Kind of a hand-made mapping** follows the source: `group` for Google Drive, `team` for Dropbox, `workspace` for Notion. The form has no kind field, as UI-SPEC 6.5 specifies three fields.
4. **New label keys** in en, zh and it:
   - table captions: `mapping.caption`, `rules.caption`;
   - load announcement: `mapping.loaded`;
   - findings lines: `mapping.need`, `rules.need`;
   - select placeholder: `mapping.form.choose`;
   - row select name: `mapping.selectAria`;
   - Load more buttons: `action.loadMoreMapping`, `action.loadMoreRules`;
   - outcome of creating a rule: `rules.created`;
   - the 409 `rule_exists` message: `error.ruleExists`.

   None of these is in UI-SPEC 12.4.
5. **Error codes.** `mapping_exists` and `rule_exists` are field errors (`principal`, `domain`), shown at their form. When `mapping_exists` comes from a table row (a race), it is reported as `error.changed` and the table reloads. `bad_domain` shows `rules.badDomain` at the field. `personal_tenant` is answered with `groups.personal` and a reload.
6. **A group mapped outside the loaded group pages** is shown in the select by its id, never by an invented name.
7. **Purge hook or store inventory:** none, because no store was added. **No migration**, so no migration number was claimed.
