# Phase 04.3 Plan 08: the access filter on every leg of the RAG module

**`runRetrieval` reads the access filter once and passes it, as a required parameter, to every leg of both pipelines. That covers the SQL legs (the legacy search RPCs, exact id, invoices, parents, cluster sources) and the table reads (references, voice keyword fallback, assembly and version re-reads, overview reads). An outsider of the same tenant now gets no restricted marker from any leg in any profile (chat, media, overview, voice), under legacy and v2 and in both deployment modes, while member-a and `admin_all` still get it. When the mode is not off, the trace records the resolution time as `access_scope`, and the result carries the labels of the documents it used, on the server only. With the switch off every payload is unchanged.**

## Behaviour changes

- Switch off (default): the request bodies are unchanged. `accessRpcArgs` of an off filter is `{}`, and `withAccessGroups` adds no query parameter when the filter has no keys. No `access_scope` stage is recorded and no `accessLabels` read is made. A `scope: null` request still returns `no_tenant` before any access work; its filter is the off filter.
- Keys mode: every leg filters before ranking and limits. A restricted document name or id resolves exactly as an unknown one does: same used documents, same context shape and the same `ignored` count path.
- `admin_all`: the RPCs get `p_access_all=true` and the table reads have no predicate, so the rows are the same as before this phase.
- Signatures: `access` is now a required parameter of `searchByEmbedding`, `vectorSearch`, `profileVectorSearch`, `legacySearch`, `exactIdLookup`, `exactIdStage`, `expandParents`, `runContextStages`, `resolveDocumentRefs`, `voiceKeywordFallback`, `fetchAssemblyRows`, `fetchVersionColumns` and `fetchOverviewDocuments`. `findInvoices(scope, filters, deps)` now needs `filters` and `deps.access`; it has no caller outside `src/lib/rag`. `runRefsStage` takes the filter as its fifth argument. `runQueryStages` takes `access?` and falls back to `scopeAccessFilter(scope)`, which fails closed while the switch is on (the D-05 pattern of `runV2Pipeline` and `SearchStagesInput`).

## Decisions (for STATE)

1. **Pure helper module `src/lib/rag/tenant/access-filter.ts`**, at the same path and with the same design as train 35. The leaf legs (supabase-rpc, exact id, invoices, parents, references, voice fallback, fetch-rows, overview, the v2 context stage, legacy search) import only it, so they load no server env. Importing `tenant/access.ts` from `invoices.ts` would load `config`/`deps` → `env.ts`, and `tests/rag-db/invoices.test.mts` would then fail at module load (`OPENAI_API_KEY is required`). The CI `ts-db` shard sets no OpenAI key. `tenant/access.ts` re-exports the four names, so `@/lib/rag` and the pinned `export type { ScopeAccessFilter } from './tenant/access'` line are unchanged. **Merge note for the train:** train 35 adds the same file with plan-03's `sameAccessFilter` (`setHash === hashAccessKeys(keys)`). Keep this branch's version, which is plan 07's key-set comparison: the A-05 effective-key hash needs it (04.3-07 decision, deviation 2). Also keep `accessTableFilter` and `withAccessGroups`.
2. **`findInvoices` takes the filter as a required dependency** instead of deriving it from the scope. Deriving it would need the config import that decision 1 avoids. It has no production caller yet, so plan 09 (or whoever wires a route) passes `scopeAccessFilter(scope)`.
3. **`runQueryStages.access` is optional** and falls back to `scopeAccessFilter(scope)`. That matches `runV2Pipeline` and `SearchStagesInput`, and avoids changing about 20 query-layer tests. `runV2Pipeline` always passes it.
4. **`access_scope` latency**: `endedAt = collector.now()`, `startedAt = endedAt - accessScopeTiming(scope)`. A scope minted without a timed resolution (tests, direct mints) records 0 ms with `detail: 'untimed'`. The latency budget entries already exist in `eval/config/latency-budgets.json` (25/25/15 ms).
5. **`accessLabels` is a non-enumerable property holding a `ReadonlyMap`**, set after dispatch on the object `runRetrieval` returns. `JSON.stringify`, `NextResponse.json` and spreads can never carry it. Plans 13 and 14 read it from the returned object before copying the object. A failed read (no admin client, query error, throw) leaves it absent and logs `[RAG Access] Access labels not read { code }`. Consumers must treat an absent map as unknown labels and not store derived rows. Ids are collected from `usedDocuments`, `candidates`, `relevantChunks`, `kept` and `voice.results`.
6. **References answer as an unknown name does.** The name lookups and the id lookups carry the predicate. A restricted id or name lands on the same `ignored` / not-found paths as a foreign or missing one, and logs only the existing counts.
7. **Fake-edge `ov` validation**: every key must match the 0921 label shape (`all` or `u:`/`g:` plus a uuid). Surrounding double quotes are stripped. A list must hold 1 to 1000 keys. The keys are bound as one `text[]` parameter.
8. **No migration**, so no migration number was claimed. Every SQL function already took `p_access_keys` and `p_access_all` (0930, 0933).
9. **Purge hook or store inventory**: none, because no store was added.
