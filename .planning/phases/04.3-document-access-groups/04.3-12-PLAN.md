<objective>
Keep the semantic cache correct under access groups: a key part per effective group set, a live visibility recheck at lookup, and invalidation on relabel.

Purpose: SEC-13 success criterion 3 ("the semantic cache never serves an answer across different group sets") and D-24.
Output: migration 0931 (first part), the cache key part, tests.

Stored labels (D-23, A-06): D-23 also asks entries to store the union of their source documents' `access_groups`. A-06 replaces that union with per-document label sets and, through RESEARCH R-6, records that for the cache the stored copy is redundant because the lookup re-checks the live documents in `source_versions`. This plan therefore adds no label column to `rag_semantic_cache` and `rag_cache_store` is not changed; the live recheck in `rag_cache_check` is the delivered form of D-23's stored-label check, and the SUMMARY states this.

Standing rules (04.3-PLAN-INDEX.md): 0931 is the last file of the block in each mode, so it must create or change a function (RESEARCH Pitfall 8); do not replace `rag_semantic_cache_on_documents_update`, add a new trigger beside it; transition-table triggers cannot have a column list, so compare `access_groups` in the function body; read the newest `rag_cache_check` by name (Phase 6 may have moved it); the outbox and its triggers belong to Phase 7 (A-14); PGlite plan, run alone in this working tree.
Execution note (A-11 / PLAN-INDEX standing rule): this plan builds PGlite fixture databases; do not run it at the same time as another fixture-database plan of the same wave in the same working tree.
