## 0. Findings that shape this contract (read first)

Facts from the code and from research. Each one changes what the UI can show or do.

1. **Phase 3.2's UI is a hard dependency and is not on trunk yet.** `scripts/config-ui/rag-panels/rag-ui.js`, the queue host
   `data-queue-extras`, `scope-tag-picker.tsx` and the Document tags panel exist only as plans (03.2-57 to 03.2-64). ROADMAP lists
   Phase 3.2 under "Depends on". The UI plans of this phase are ordered after those plans. An executor who finds one of these
   hosts missing reports a blocked dependency; it does not build a second helper file, a second queue host or a second picker
   row (CONTEXT: "this phase extends those surfaces; it does not create parallel ones").
2. **No route under `/api/rag/access-groups/` exists.** Section 8.1 lists what each view needs. The path prefix is fixed by
   D-28; methods and field names are **proposals to the backend plans**. The behaviour they support is the contract.
3. **Two design systems, as in 3.2.** The Config UI is a static page with DaisyUI 4.4.24 over the Tailwind Play CDN and
   Bootstrap Icons. The app is Next.js with shadcn-style local components over Radix and lucide icons. Tokens are declared
   per surface and never mixed.
4. **The app has two places that look like "organization settings".** `workspace-settings-modal.tsx` (opened from the
   workspace switcher, takes `organizationId` and `userRole`, two tabs in a `grid-cols-2` list) and `settings/tabs/WorkspaceTab.tsx`
   (inside the user's Settings dialog, holds collaborators and invitations). The admin view goes into the first, the member's
   own view into the second (section 14, decisions 1 and 12).
5. **The workspace settings modal styles itself with literal brand values**, not theme tokens: surface `#FFF1E5` / `#212121`,
   cards `#FFF0E8` / `#1A1A1A`, borders `#FFE0D0` / `#2A2A2A`, accent `#FF6417`. A tab added to it reuses the class strings of its
   sibling cards, tab triggers and Save button verbatim. No value that is not already in that file is written.
6. **The app's stored-documents table has no selection, no bulk action and no admin-only row content.** It has three columns
   and a 90px actions column with two 28px icon buttons; widths come from `calculateOptimalColumnWidths`. Bulk relabel needs a
   checkbox column and a selection bar, both new, both admin-only.
7. **The app has no badge, popover, command or alert-dialog primitive.** `src/components/ui/` provides `dialog`,
   `dropdown-menu` (with checkbox and radio items), `select`, `checkbox`, `switch`, `tabs`, `table`, `input`, `button`,
   `scroll-area`. Everything here is built from these; no shadcn block is added.
8. **The share dialog shows one generic sentence for every failure** (`'Failed to share chat'`). The refusal of D-27 needs its
   own message, chosen by the response code, not by the message text.
9. **The shared-chat page answers every failure with `notFound()`.** Research (section 11, pitfall 13) requires a viewer who
   may not see a cited document to get exactly the answer of an unknown link. So the page gains no new state and no sign-in
   prompt (section 6.13).
10. **The env switch is the source of truth, and three values can disagree** (A-03): the value saved in `.env.local` (what the
    Config UI page holds), the value the running app started with, and the database flag the app writes at startup. The
    Enforcement view shows all three and names the one action that fixes each disagreement.
11. **Connector mapping changes who sees a document only in single-tenant mode** (A-10). In multi-tenant mode connector
    documents stay in the personal workspace of the person who connected the source. Both mapping views say so in one sentence
    instead of presenting a control that silently does nothing.
12. **Every sync recomputes a connector document's access from the source** (D-20). An admin's manual change to such a
    document would be overwritten at the next sync, so the relabel controls are disabled for connector documents and say where
    to change access instead (section 14, decision 9).
13. **A personal workspace has no access groups** (research section 4: groups exist for organization tenants and for
    `s:default`). The Config UI panel says so when a personal workspace is selected; the app tab is not rendered for personal
    projects.
14. **A client cannot know whether an upload will become a new version.** D-19 makes a new version inherit the access of the
    version it replaces. The upload picker therefore has an untouched state that sends nothing and says what the server will
    do in both cases; it never claims "Everyone" for a file whose access it does not know (section 6.2.3).
15. **The app's UI language set is 18 languages; label modules carry en, zh and it** and fall back to English
    (`doc-type-labels.ts`). New app strings follow that shape. Config UI panels pick `zh` or `it` from `navigator.language`.
16. **The Config UI documents table and the Connectors tab build rows with template strings** (`document-manager.js`,
    `connectors-config.js`). What this phase adds to them is built with DOM calls and appended; no new value goes through a
    template string.

## 1. Design direction (frontend-design pass)

**Subject.** Who inside one workspace may get answers from which document.
**Audience.** A workspace owner or admin (app) or the deployment operator (Config UI) at a desktop, who arrives with one of
these questions: "who can see this document?", "why can only one person see these synced files?", "what happens to its
documents if I delete this group?", "is the restriction actually being applied?". And a member who uploads a file and must
say who it is for, or who wants to know which groups they are in.
**Primary job.** Make the audience of a document readable at a glance and changeable in one place, and never let a failure
or a deletion widen it.

**Mode.** Impeccable "Operate". These are working tools inside two existing products. Sections, sub-tabs, tables, badges,
alerts and dialogs are the ones the sibling panels and dialogs use. No new navigation, no new control type.

**Organizing idea: every document states who can see it, in the same words, everywhere.** One sentence form, the
**audience line**, is used in the upload row, the document lists, the relabel dialogs, the delete confirmation and the
connector warning. It has exactly three readings: Everyone; the named groups; uploader and admins only. An admin who has
read it once in the document list can read every other screen of this phase without learning anything new. It continues
the "hold line" of 3.2 (state, reason, action) for the one audience that needs attention.

**Signature element: the audience field** (section 6.2.2). The same line in its editable form: two radios, and under the
second a row of group chips that ends in an "Add group" control. Chips appear only where an audience is being chosen;
wherever it is only read, group names are plain words. The field cannot be saved empty, and the reading "uploader and
admins only" can never be chosen in it: it is something the system falls back to, so it is shown and explained, not offered.

**Review against generic defaults (what was changed and why).**
- Rejected a colour per group. Chips are neutral outlines; a group is identified by its name. Colour would be the only
  carrier and would not survive twenty groups.
- Rejected a permissions matrix (documents by groups with checkboxes). The question asked is per document, the lists are
  long, and a grid of ticks invites accidental widening.
- Rejected a lock icon on every unrestricted row. Everyone is the quiet default and carries no mark; only a restricted
  document is marked, so the mark means something.
- Rejected stat tiles for "groups, members, restricted documents". The counts sit in the rows they belong to.
- Rejected a red or green toggle for enforcement. The state has six values with different remedies; it is a badge with a
  word, a sentence and at most one button.
- Rejected a type-the-name confirmation for deleting a group. The decision D-18 asks for the count; the dialog shows three
  counts and says what happens to each.
- Rejected a "you do not have access" state anywhere a member looks. A document a caller may not see behaves exactly like
  a document that does not exist (section 11).
- Rejected emoji, middle-dot meta strings, all-caps labels and arrows on buttons. The Config UI page's existing emoji
  headings are not extended to the new panel.

**Quality floor (built without announcing it).** Visible keyboard focus, `prefers-reduced-motion` respected, tabular
numerals in number columns, usable down to 360px, every state in section 7 present, every server string inserted with
`textContent` (Config UI) or as a React text child (app). Text added by this phase meets 4.5:1, with one inherited
exception recorded in section 14 (the label of the app's existing brand button).

## 4. Spacing Scale

Tailwind spacing utilities only; no arbitrary pixel values. Same scale as `03.2-UI-SPEC.md`.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `mt-1`, `px-1` | Icon to label inside a badge, chip or button; a name to its second line; a field to its help line |
| sm | 8px | `gap-2`, `mb-2`, `p-2` | Buttons in a row, chips side by side, heading to its description, gap between queue-row controls |
| md | 16px | `gap-4`, `mt-4`, `mb-4`, `p-4` | Between form fields, toolbar to content, padding of inline form regions, editor rows and the members region |
| lg | 24px | `gap-6`, `mt-6`, `space-y-6` | Between sibling panels and between the cards of the app tab; between sub-blocks of one sub-view |
| xl | 32px | `.card-body` default, `py-8`, `w-8` | Config UI card padding (DaisyUI default); empty-state blocks; the selection checkbox column |
| 2xl | 48px | `h-12` (DaisyUI `btn` height) | Touch-size row actions below 768px in the Config UI |
| 3xl | 64px | not used | Reserved for page-level spacing |

Exceptions (both multiples of 4, both only inside `workspace-settings-modal.tsx`, both because the sibling tabs of that modal
use them and a tab switch must not shift content by 4px):
- 20px (`p-5`) card padding of the two cards of the Access groups tab.
- 12px (`p-3`) padding of a group row and a member row, as the member rows of `WorkspaceTab.tsx` have.

No 2px, 6px or 10px spacing appears in new markup.

Component internals outside the scale (not spacing tokens, do not restyle):
- DaisyUI `table-sm` cell padding, `input-sm`, `select-sm`, `checkbox-sm`, `radio-sm`, `toggle-sm`, `btn-sm` (32px), `btn-xs`
  (24px, the chip remove button) and `btn` (48px) are used as shipped. Row actions are `btn md:btn-sm`: 48px tall below 768px,
  32px from 768px up.
- App: the upload picker trigger is `h-8` (32px) with `px-2` and `gap-1`, equal to the `DocTypePicker` trigger and to 3.2's two
  triggers beside it. Row icon buttons in the document table are `h-7 w-7` (28px), equal to the two existing ones; the chip
  remove button is `h-6 w-6` (24px). All meet the WCAG 2.2 AA target size (24px).
- App: the document table's actions column grows from 90px to 124px for the third icon button
  (`ACTIONS_WIDTH` in `calculateOptimalColumnWidths`), and a 32px checkbox column is added for admins.

Sizes that are not spacing: icons are `h-3.5 w-3.5` in triggers, chips and badges and `h-4 w-4` in buttons, as the siblings
use; the members list and the picker menu are capped at `max-h-72` (288px) and scroll; the queue dropdown is `w-72`.

## 5. Typography

### 5.1 Config UI

Exactly four sizes and two weights, the same as the sibling panels and 3.2.

| Role | Size | Weight | Line height | Tailwind | Where |
|------|------|--------|-------------|----------|-------|
| Panel heading | 18px | 600 | 1.33 (`leading-7`) | `text-lg font-semibold` | "Access groups" |
| Sub-heading | 16px | 600 | 1.5 (`leading-6`) | `text-base font-semibold` | Sub-view block titles (`h4`), dialog titles, empty-state titles |
| Body | 14px | 400 | 1.43 (`leading-5`) | `text-sm` | Descriptions, table cells, the audience line, alert text, status messages, form labels, buttons |
| Meta | 12px | 400 (600 for table headers) | 1.33 (`leading-4`) | `text-xs` | Table headers (`font-semibold`), group keys, second lines in cells, help lines, badges, chips, env names |

Rules:
- Number columns and counts use `tabular-nums`; numbers are right-aligned in their columns.
- Description and alert paragraphs cap at `max-w-prose`.
- Group keys, source group ids, domains and env names use `font-mono text-xs` with `translate="no"`. Group **names** are
  ordinary text. Nothing else is monospace.
- No all-caps labels, no letter-spaced eyebrows, no label above a heading, no single emphasised word inside a heading.
- The panel root carries `lang="<locale>"`. Text left in English inside a localized panel (unknown server messages) is
  wrapped in an element with `lang="en"`. Group names and file names carry no `lang`; they are the tenant's own words.

### 6.2 The audience line and the audience field

#### 6.2.1 Audience line (read-only)

One builder per surface (`AccessGroupsAudienceLine(view)` in the Config UI, `AudienceLine` in the app), fed by one pure
view-model function. It is the only code that turns a document's access into words.

| Reading | When | Config UI | App |
|---------|------|-----------|-----|
| Everyone | The document's access is `all` | The text `audience.everyone`. No badge, no icon | Nothing in the document list (the quiet default). In dialogs: the text `audience.everyone` |
| Named groups | One or more groups | `badge badge-outline badge-sm gap-1` with `bi-lock` and `badge.restricted`, then `audience.groups` with the group names in plain words, comma-separated | `RestrictedMark` (below), then, for admins, `audience.groups` as a 12px muted line, truncated, full text in `title` |
| Uploader and admins only | The system fell back to the uploader's key (D-18, D-20) | `badge badge-warning badge-outline badge-sm gap-1` with `bi-shield-exclamation` and `audience.uploaderOnly`, then the reason sentence (`reason.*`), then one action: **Edit access**, or **Open connector mapping** when the reason is a source one | The mark in its warning tone with `ShieldAlert` and `audience.uploaderOnly`; for admins the reason as a 12px line; the row's Edit access button is the action |

- A document that also carries people from its source's sharing (connector user shares, D-20) appends
  `audience.people` ("people at the source: {count}") after the groups. The count only; no names, no addresses.
- **What a non-admin sees.** The server gives a non-admin one boolean per document (research section 11). The app then
  renders `RestrictedMark` alone, with `badge.restrictedHint` in `title` and as its accessible description: no group
  names, no reason, no count. The uploader of a fallen-back document sees the same mark; the reason is the admin's.
- `RestrictedMark` (app): `span.inline-flex.items-center.gap-1.text-xs.text-muted-foreground` with `Lock` (`h-3.5 w-3.5`,
  `aria-hidden`) and the word. Warning tone: the classes of the existing `warning` tone of `IngestStatusBadge`
  (`text-amber-700 dark:text-amber-300`) with `ShieldAlert`. No border, no background, no upper case; it sits under the
  file name where the existing source mark sits.
- Reasons the UI knows: `group_deleted`, `unmapped_source`, `source_error`. An unknown reason shows its code in
  `font-mono` inside the sentence `reason.other`.

#### 6.2.2 Audience field (editable; the signature element)

Used in three places with identical behaviour: the Config UI document editor row, the Config UI bulk dialog, and the app's
Edit access dialog (single and bulk).

```
fieldset   legend: "Visible to"
  ( ) Everyone                       help: field.everyoneHelp.<mode>
  (•) Only these groups              help: field.onlyGroupsHelp
        [ group-a  x ] [ group-b  x ] [ Add group v ]        chip row, shown while the second radio is chosen
        findings line                                        field.needGroup, while no chip is present
  field.widen                                               only when Everyone is chosen for a document that is restricted now
  field.effect                                               12px
```

- **Chips.** One per chosen group, in the order of the group list. A chip is the group name and a remove button whose
  accessible name is `action.removeGroupChip` ("Remove group: group-a"). Chips are neutral outlines, wrap onto more lines,
  and a long name breaks inside its chip (`break-words`, `max-w-full`).
- **Add group** opens a menu of the groups not yet chosen (Config UI: `details.dropdown` with one `button` per group; app:
  `DropdownMenu` with one `DropdownMenuItem` per group). Choosing one adds its chip and keeps the menu open; when every
  group is chosen the control is disabled. With no group in the workspace the menu shows `field.noGroups`.
- Choosing **Everyone** hides the chip row and keeps its chips in memory, so switching back restores them.
- The save button is disabled while "Only these groups" has no chip; `field.needGroup` is on screen and referenced by the
  button's `aria-describedby`. The field can therefore never be saved empty (D-02).
- "Uploader and admins only" is not offered. When the edited document currently has that reading, neither radio is
  pre-chosen, the current audience line is shown above the field, and the save button stays disabled until a choice is
  made.
- **Bulk.** When the selected documents do not share one audience, neither radio is pre-chosen and `field.mixed` is shown.
  The choice **replaces** the access of every selected document; there is no "add to" or "remove from" mode.
- **Who may choose what** (D-16, D-17). Admins get every group of the workspace. The field is never shown to a non-admin
  (only the upload picker is).
- `field.widen` is a sentence with `bi-exclamation-triangle` / `AlertTriangle` in the warning text colour; it is not a
  second confirmation.

#### 6.2.3 Upload picker (compact form)

The same choice at upload, where space is one row. Three states of the value: untouched, Everyone, groups.

| State | Trigger text | Sent with the upload | Line under the file name |
|-------|--------------|----------------------|--------------------------|
| Untouched (initial) | `picker.trigger` ("Access") | Nothing. The server applies D-16 and D-19: a new document is visible to everyone; a new version keeps the access of the version it replaces | None |
| Everyone | `picker.everyone` ("Everyone") | The explicit choice of everyone | `audience.everyone` and a clear button |
| Groups | `picker.groups` ("Groups: {n}") | The chosen group ids | "Visible to" followed by one removable chip per group |

- The menu holds: the checkbox item `term.everyone`; a separator; the label `field.onlyGroups`; one checkbox item per group
  the caller may assign (their own groups; for an admin, every group); a separator; the 12px note `picker.note`; and, when
  the value is not untouched, the item `picker.clear` ("Clear choice"), which returns to untouched.
- Ticking Everyone unticks every group; ticking a group unticks Everyone; unticking the last group returns to untouched.
- The client sends group **ids** only. It never sends or builds a principal key, and never sends a user key (D-06).
- **Not rendered** when the server reports the switch off, or when the caller has no group to assign (a non-admin who is
  in no group can only upload for everyone). Never rendered for images or temporary documents (3.2 finding 8).
- A group the caller may not assign is refused by the server (`group_not_allowed`): the file is not uploaded and the row
  shows `error.groupNotAllowed`; the picker reloads its groups.

## 7. State matrix

Every row is required. "Status region" is the panel's `div[role=status][aria-live=polite].text-sm` (Config UI) or the tab's

### 7.1 States every data view has

| State | What the user sees |
|-------|--------------------|
| First load | A spinner with the view's `*.loading` text in the content host; status region the same |

## 9. Keyboard, screen reader and focus

1. **Headings.** The panel title is `h3`; block titles inside a sub-view and the members region title are `h4`. In the app
   tab the two card titles are `h4`, as the sibling cards. No level is skipped.
2. **Sub-tabs (Config UI).** `role=tablist` with an `aria-label`; each `button[role=tab]` has `aria-selected`, `aria-controls`
   and a roving `tabindex`. Left and Right move and activate, Home and End jump. Panels are
   `div[role=tabpanel][aria-labelledby][tabindex=0]`. The app tab uses the Radix `Tabs` behaviour as shipped.
3. **Audience field.** A `fieldset` with `legend`; the two radios form one radio group. The chip row is a `ul` (`role="list"`)
   named by the second radio's label; each chip is an `li`. Removing a chip moves focus to the next chip's remove button,
   or to "Add group" when it was the last. A polite live region inside the field announces "group-a added" and
   "group-a removed" (`chip.added`, `chip.removed`).
4. **Chip remove buttons** are real `button`s, 24px, with the accessible name `action.removeGroupChip`. They are the only
   icon-only buttons this phase adds to the Config UI.
5. **Forms.** Every control has a visible `<label for>`. Help lines and findings are wired with `aria-describedby`; invalid
   fields carry `aria-invalid="true"`. The key, the source group id, the domain and the embedded chat group have
   `autocomplete="off"`, `spellcheck="false"` and `translate="no"`. Enter in a text field does not submit, except in the
   member search, where it runs the search. Escape closes an inline form, an editor row or the members region and returns
   focus to the button that opened it.
6. **Disabled primary buttons.** The reason is on screen and referenced by `aria-describedby` (Create group, Save access,
   Create mapping, Delete group while counting).
7. **Dialogs.** Config UI: native `<dialog class="modal">` with `showModal()`, `aria-labelledby` and `aria-describedby`. App:
   `Dialog` with `DialogTitle` and `DialogDescription`. Focus starts on the safe button (Keep group, Keep rule off, Keep
   current access). Escape and the backdrop cancel; while a request runs they do nothing. On close, focus returns to the
   opening button, or to the status region when that button is gone. Group and file names are inserted as text.
8. **Members region.** The toggling button carries `aria-expanded` and `aria-controls`. Opening moves focus to the search
   field. The result list is a `ul`; each result's button is named `action.addMemberAria` with the person's name.
9. **Row actions** carry the group, member or file name in their accessible name (`*Aria` keys: "Delete group: group-a").
   Dates use `<time datetime>`.
10. **Selection.** Row checkboxes are named `select.aria`; the header checkbox `select.allAria` and takes the mixed state
    when some rows are ticked. The selection bar is announced once through the status region (`bulk.selected`), not on
    every tick.
11. **Toggles and switches.** Each has a visible label and the word On or Off as text next to it; state is not carried by
    position or colour alone. The accessible name includes the rule and the source.
12. **Live regions.** One polite status region per panel or tab. Announced: load finished with counts, action outcomes,
    errors. A failed enforcement sync and the share refusal are `role="alert"`, because they answer an action just taken.
    Alerts rendered on load have no alert role.
13. **Tables.** Visually hidden `caption`, `th scope="col"`, the group, file or source-group cell as `th scope="row"`. A table
    that can scroll sideways sits in `div.overflow-x-auto[tabindex=0][role=region][aria-label]`.
14. **Not colour alone.** Every state, badge and warning has a word and an icon. Restricted and "Uploader and admins only"
    differ by word and icon, not only by tone.
15. **Focus visibility.** DaisyUI's `focus-visible` outline on every control; `summary` elements and scroll regions add
    `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2`. In the app, the shipped
    `focus-visible:ring-2` of `Button` and the Radix focus styles are kept. Never `outline: none` without a replacement.
16. **Motion.** Only the spinners. Under `prefers-reduced-motion: reduce` they are hidden (`motion-reduce:hidden`, or
    `motion-reduce:animate-none` for `Loader2`) and their text remains. Nothing slides, fades or pulses; the selection bar
    appears without animation.
17. **Zoom and text size.** At 200% zoom nothing clips: no fixed heights except the capped scroll regions; chips, cells,
    toolbars and button rows wrap.
18. **Language.** `lang` on the panel root; text left in English carries `lang="en"`.

## 11. What must never be shown or done

1. **A document a caller may not see does not exist for that caller.** No list row, no count, no "n documents hidden",
   no disabled row, no different empty-state text, no search hint, no suggestion and no error wording reveals it. "Not
   found" is one sentence for unknown and not-visible alike.
2. **No "you do not have access" state in chat, embed, voice or the shared view.** A question about a restricted document
   from an outsider gets the existing information-not-available answer, unchanged. A citation dropped by the
   post-generation check (D-26) is simply absent; the answer shows no "a source was removed" note.
3. **Non-admins never see:** a group they are not in, a member list, a member count, the groups of a document, the reason
   a document fell back, the uploader of a document, or how many documents a group has (D-29).
4. **The share refusal names nothing:** no document, no group, no number of documents.
5. **Principal keys are never rendered or built in the browser:** `all`, `g:<uuid>`, `u:<uuid>`, tenant keys, set hashes.
   The browser sends group ids and the word for everyone; the server builds keys. A user key is never offered, chosen or
   sent.
6. **Nothing here widens access without an explicit admin action.** No default, suggestion or bulk shortcut pre-chooses
   Everyone for a restricted document; "uploader and admins only" is never replaced by Everyone automatically; a sharing
   rule is created Off.
7. **Every server string** (group names, keys, member names and addresses, file names, source group ids, domains, reason
   and error codes, `details[].message`) is inserted with `textContent` in the Config UI and as a React text child in the
   app; never `innerHTML`, never `dangerouslySetInnerHTML`, never a template string that becomes markup. Tests stub each
   with `<img src=x onerror=alert(1)>` and assert that no element is created. A group name is tenant-written text and is
   treated like any other untrusted string.
8. **Views render named fields only,** through builder functions, never by iterating an object's keys.
9. **No document content.** No chunk text, parent text, quote, preview or image appears in any view of this phase, and the
   views call no route that returns one. Security events and the access audit have no screen in this phase.
10. Never rendered even when a response carries it: user ids when a display name exists, the addresses of people a source
    shares with (only their count), raw permission objects from a source, set hashes, request ids, function bodies. A
    readiness reason names the object (a function or table name) and nothing else.
11. No value of a variable whose name matches `/(KEY|SECRET|TOKEN|PASSWORD)/i` is read or rendered by any new script.
    `RAG_EMBED_ACCESS_GROUP` holds a group key, not a secret, and is shown.
12. No `Authorization` header from the Config UI, no token in browser storage, no second sign-in form. The app's share
    request keeps the header it sends today.
13. **Nothing is logged** to the console from group names, member names, addresses, file names or source group ids; logs
    carry counts and codes only.
14. **Domain neutrality.** Placeholders, examples, empty states and fixtures use `group-a`, `group-b`, `member-a`, `member-b`,
    `outsider`, `document-a.pdf` and `example.org`. No copy suggests what a group is for (no department, role, project or
    customer names).

## 12. Copywriting Contract

Voice: plain verbs, sentence case, names from the user's side of the screen. A message that reports a problem says what
happened and what to do next; errors do not apologize. One action keeps one name through its flow: the row button, the
dialog's confirm button and the outcome message say "Delete group", "Delete group", "deleted".

**Words used, and words avoided.** "Access group" and "group" for the thing; "member" for a person in it. "Visible to" for
a document's audience; "Everyone" for the unrestricted audience (the stored word `all` is never shown); "Restricted" for a
document that is not visible to everyone; "Uploader and admins only" for the fallback audience (the words "fail closed",
"principal", "key" for anything but the group's own key, "ACL", "label", "scope" and "permission" are not shown, except
"Label check" as the name of the consistency check). "At the source" for a connected product; "mapped" and "not mapped"
for the link between a source group and an access group. "Enforced" for the working state. A group's **key** is called
"Key" and appears only where it is created, shown under its name, or typed for embedded chat.

**Action labels are verb + noun in every locale.** Accessible names extend the visible label and start with the same verb
("Delete group: group-a"). In-flight text ("Deleting…") is status on a disabled button, not a label. Not actions, so not
verb + noun: sub-tab names, filter radios, select options, the picker trigger ("Access", "Everyone", "Groups: 2"), toggle
words. No button is labelled "Cancel", "OK", "Submit" or "Close" alone: a button that backs out says what stays ("Keep
group", "Keep rule off", "Keep current access") or what it closes ("Close form", "Close members", "Cancel editing"). The
workspace settings modal's own footer button is existing and unchanged.

**Counts are written as "label: number"** ("Members: 4", "Selected: 3"), so no string needs a plural form in en, zh or it.

**Nothing in the copy says what a group is for.** Examples and placeholders are `group-a`, `group-b`, `document-a.pdf`,
`example.org` (REQUIREMENTS domain-neutrality rule).

**Where the strings live.** Config UI: one `{ en, zh, it }` table, `ACCESS_GROUPS_LABELS`, in `access-groups.js`, read through
one function that fills `{placeholders}` and falls back to English. App: `access-group-labels.ts` in the `doc-type-labels.ts`
shape. The strings of 12.2 to 12.4 are used by both surfaces and must be identical in both tables; a vitest case loads
both and compares every shared key in all three locales. A placeholder shown as `{variable}` or `{code}` is replaced by a
`code` element, not by text. Numbers use `Intl.NumberFormat(locale)`; times `Intl.DateTimeFormat(locale, { dateStyle:
'medium', timeStyle: 'short' })`. Product names of sources (Google Drive, Dropbox, Notion) come from the existing provider
configuration and are not translated.
