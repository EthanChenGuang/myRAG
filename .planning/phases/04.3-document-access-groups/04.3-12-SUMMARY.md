Label sets are stored only on rows that keep content without a live source link (plan 13).

## Behaviour changes

- Switch off (`RAG_DOC_ACCESS_GROUPS=off`): `rag_cache_check` called without access arguments behaves exactly like 0603. The key part is the constant `off`, so every cache key hash changes once on deploy. The cache only empties; nothing is served wrongly.
- With keys: a hit is served only when every `source_versions` document of the tenant has `access_groups && keys`. Not visible means a miss with no entry id, answer or distance (so an outsider learns nothing about a near entry), and the row stays. A row whose sources are not current is still deleted, even on an outsider's lookup. `p_access_all` (admin) skips the visibility check.
- A refusal entry has no sources, so only its key hash protects it. That hash includes the access part.
- Any UPDATE that changes `documents.access_groups` (the plan 05 setter, service_role, DEFINER writers) deletes every cache row of the old and new tenant keys in the same statement. Updates with an unchanged label keep the cache. An array reorder counts as a change, which is conservative.
- Query layer: `cacheAccessKeyPart(scope)` is computed inside the existing key `try`. With the switch on and a scope not resolved for access it throws, and the stage records `skipped/key_unavailable` and never calls `check` (fail closed, test in `stage.test.ts`).

## Decisions (for STATE)

1. **Not visible → NULL distance.** Pitfall 10 is applied, and the miss also hides the distance so it cannot be used as an existence side channel.
2. **Trigger name `rag_access_semantic_cache_update`**, outside the `rag_semantic_cache_documents_%` and `rag_semantic_cache_%` patterns that schema-equality and semantic-cache-invalidation assert on, so the Phase 6 trigger inventory checks stay exact.
3. **Trigger guarded, functions not.** The CREATE TRIGGER sits inside a `to_regclass('public.rag_semantic_cache')` check (DROP first, NOTICE when absent). Functions are created unconditionally, per the standing rule.
4. **0410 entry** for the new DEFINER function (standing rule from 04.3-03/04).
5. **`cacheAccessKeyPart` lives in `cache/access-key.ts`; `keys.ts` keeps a pure `accessKeyPartOf(filter)`.** Importing `tenant/access` from `keys.ts` pulled `deps` and `@/lib/env` (eager validation) into the cache backends, and it closed a cycle `cache/index → pgvector → keys → tenant/access → deps → cache/index`. `semantic-cache-adapter` and `semantic-cache-canary` failed with `OPENAI_API_KEY is required on the server`. A test now pins keys.ts to type-only imports beyond `node:crypto`. Plan 13 imports `cacheAccessKeyPart` from `@/lib/rag/cache/access-key`.
6. **Recorded key constants updated** (`effective-dates-query`, `scopes-filter`: `fb5354…` → `4fb84a…`). This is the one-time key change the plan states.
7. **Purge hook / store inventory:** none, because no new store was added.
