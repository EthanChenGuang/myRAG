# Phase 04.3 Plan 41: Config UI Access groups panel, Enforcement sub-view

**Operators can now see in RAG administration whether access groups are enforced. If they are not, the panel says why and offers the one action that fixes it. The panel shell, the labels table for the phase and the error mapper are ready for plans 42 to 45 to extend.**

## Behaviour

- **State (A-03).** `buildAccessGroupsEnforcementView(saved, status)` is pure. It reads the saved setting, plus `runningSwitch`, `databaseFlag`, `status`/`ready` and `reasons` from `GET /status`. The result is `unknown` (no answer, or an unknown running value), then `blocked` (running on and not ready), then `unsynced` (the running switch differs from the database flag; a `null` flag counts as different), then `restart` (saved differs from running), then `enforced` or `off`. **Sync enforcement** is offered in `unsynced`, and in `blocked` only when `flag_write_failed` or `flag_readback_mismatch` is among the reasons.
- **Saved setting.** It comes from `window.configManager.savedConfig` when the page has loaded its config, else from the select. After a save it comes from the new `rag:config-saved` event. When either variable changed, `settings.restart` appears under the fields.
- **Reasons.** The codes the server sends today are `flag_write_failed`, `flag_readback_mismatch`, `admin_client_missing`, `readiness_unavailable`, `readiness_not_ready` plus readiness codes, and `backend_without_access_filter`. Codes with their own sentence use it. `readiness_not_ready` is dropped when specific codes follow it. Any other code renders in `font-mono` inside `blocked.reason.other`. Object names fill `{name}` as code elements.
- **Label check.** Only stores the server reports are shown, and only stores with differing rows go in the table. Known names map to labels: `document_chunks`, `document_parents`, `chunk_translations`, `rag_table_rows`, and clusters for later. Unknown names are shown as code sentences. There is no repair button.
- **Settings.** The `[data-rag-settings-group="access"]` group moves out of the hidden `#rag-phase043-settings` block, and its ids are unchanged, so load, Save All Changes and check-config keep working. zh and it are applied through `data-rag-i18n`. The what-it-does-now line follows the select before saving. The embedded chat group check runs in this order:
  1. `form.reservedKey` (`all`) or `form.badKey`, from the key pattern `^[a-z0-9][a-z0-9-]{0,62}$`.
  2. Then, when the field equals the key the running app checked, `found` with the group name or `notFound`.

  `warn.embedNeedsSwitch` shows while the select is Off. The check line and the warning are wired into the input's `aria-describedby`.
- **Errors.** `mapAccessGroupsError` maps:
  - a timeout on a write to `error.outcomeUnknown`, then a reload;
  - 404, and 409 on a write, to `error.changed`;
  - 400 `invalid_key` / `reserved_key` to the key messages;
  - everything else through `ragUiMapError`, which splits 403 by `body.error`.

  401 and 403 replace the state with the sign-in alert and Reload panel; the Settings block stays usable. A 503 or network failure shows `enforce.unavailable` and keeps earlier content at `opacity-60`. A failed sync (an HTTP failure, or the flag still not written) shows `sync.failed` with `role="alert"`.
- **Alert host.** `alert.blocked` shows when the state is blocked. `alert.off` shows while the running app has the switch off. Each has **Open enforcement**, which selects and focuses the Enforcement tab.
- **No switch changed.** No new env variable. With `RAG_DOC_ACCESS_GROUPS=off` nothing outside the Config UI changes.

## Decisions (for STATE)

1. **Extra label keys** beyond UI-SPEC 12.5, in en, zh and it: `settings.title`, `enforce.title`, `enforce.checking`, `enforce.checked`, `enforce.unavailable` (the view's unavailable sentence, missing from the spec), `enforce.reasons`, `enforce.dlLabel`, `value.none`, `blocked.reason.flag_readback_mismatch`, `blocked.reason.backend_without_access_filter` (the codes plan 24's service actually sends) and `drift.caption`. `RAG_DOC_ACCESS_GROUPS.opt` is split into `.opt.off` / `.opt.on`, the keys plan 01's markup uses.
2. **Top-level names.** The plan requires the names `buildAccessGroupsEnforcementView`, `mapAccessGroupsError` and `initAccessGroupsPanel`, so helpers use the lower-case `accessGroups…` prefix. A test pins the allowed prefixes, so no unprefixed global can enter the shared script scope.
3. **Sub-tabs.** Enforcement is the only sub-tab so far. Plan 42 adds Groups as the default; `mount()` builds the tab list from one array.
4. **`rag:config-saved`.** A one-line additive dispatch in `saveConfig` after `savedConfig` is set. No other code listens to it yet.
5. **Purge hook or store inventory:** none, because no store was added. **No migration**, so no migration number was claimed.
