## How it works

- **Member view.** `buildMyAccessGroupsView({ mine, status, error, knownEnabled, singleTenant, retrying }, language)` returns `hidden`, `groups` (title, `{id,name}` chips, `mine.help`), `text` (`mine.none`, `mine.admin` or, single-tenant, `mine.adminSingle`) or `unavailable` (`mine.unavailable`, Reload groups). It only reads `ownGroups`; assignable groups, counts and members never reach the view. Chips are `<li>` text children with `truncate` and `title`, no remove button. `MyAccessGroups` loads the plan 46 store for its workspace (team org id, or `null` single-tenant) and is placed only for a non-personal team workspace (multi-tenant) and in GeneralTab when `!isMultiTenant()`.
- **When the unavailable line shows.** The mine route checks auth and the workspace before the switch, and answers `enabled: false` when the switch is off. So a 5xx means the switch is on and shows the line; a 4xx (signed out, not a member, bad id) shows nothing; a network error or timeout shows the line only if an earlier answer for this workspace was enabled, otherwise nothing (cannot tell the switch is on, so today's view).
- **Share refusal.** On a non-OK answer the button reads the JSON body; `shareFailureOf(status, body)` is `restricted` only for 403 with `error === 'restricted_content'` (status and code, never message text). The dialog then replaces the generate button with `div[role=alert]` (Link2Off `aria-hidden`, `share.refused`, `share.refusedNext` in `text-muted-foreground`): no link, no retry, the dialog close is the way out. The state resets on chat change. Every other failure, including 503 `access_groups_unavailable`, keeps today's red line.
- **Sync line.** `syncResultLines(stats, mode, language)` returns `sync.failClosed` with the `Intl`-formatted count when `failClosed > 0` and the mode is single-tenant; nothing in multi-tenant mode, for 0, a missing or non-finite count. The banner gets `flex-wrap` and the line (`AlertTriangle` `aria-hidden`, `text-amber-700 dark:text-amber-300`, full row) only when there is a line; otherwise its markup is unchanged.

## Behaviour changes

- Switch on: the three surfaces above. Switch off: `/mine` answers `enabled: false` (member view hidden), the share route never returns `restricted_content`, and `failClosed` stays 0 (plan 32), so all three components render as today.
- One extra GET `/api/rag/access-groups/mine` when the Settings General tab (single-tenant) or Workspace tab of a team workspace opens. With the switch off the route answers without a database call (04.3-22).
