## Behaviour (switch on)

- **Data.** `mapApiDocumentToProcessed` keeps the 04.3-15 fields as `doc.access`. A non-admin's row keeps only the boolean, whatever else the record carries. A record without `restricted` (switch off) carries no access.
- **Mark.** Under the file name, next to the source mark: nothing for Everyone. Otherwise `AudienceLine context="list"` from `rowMarkView`: for admins the mark, then group names, the people count and the fallback reason; for non-admins the mark and `badge.restrictedHint` only. It renders in readOnly too, and is capped at the computed name-column width.
- **Controls.** `showAccessControls` shows them only for `enabled && isAdmin && !readOnly && !personal`. With them come the third icon button (Lock, sr-only `action.editAccessAria`; disabled with `docs.connectorManaged` for connector rows and for rows that are not ready), the 32px checkbox column, a reserved `min-h-9` selection bar (`bulk.selected`, Change access, Clear selection) and a polite sr-only status region.
- **Dialog.** Title `edit.title` (file as text) or `bulk.title`. The description is the current audience line, or `bulk.selected`. Then `AudienceField`, Keep current access (initial focus) and Save access (disabled, described by `field.needGroup` while empty). While saving, Escape and outside clicks do nothing. On close, focus returns to the opener. After a bulk save the bar is gone, so focus goes to the header checkbox, or to the status region.
- **Save.** `PUT /api/rag/access-groups/documents/access` with `{ organizationId?, documentIds, everyone | groupIds }`. The rows update in place from `audiences`. The outcome (`save.done`, `save.doneMany`, plus `save.skipped`) goes to the status region and the app toast. Errors are mapped in one place, `readAccessSaveResponse`:
  - 400 `unknown_group`: `error.groupGone`; the dialog stays open, the groups reload and the remaining chips stay.
  - 409 `access_managed_by_connector`: `docs.connectorManaged`; the rows reload.
  - 404: `error.changed`.
  - 401 or 403: `error.notAdmin`, and mine reloads.
  - Other 400: `error.invalid` with the detail.
  - Thrown request, 5xx or anything else: `error.outcomeUnknown`, and the rows reload.
- **Selection.** Select-all takes the selectable filtered rows on screen only. Connector, processing and access-less rows are not selectable. The selection is pruned to the rows currently shown, so a row hidden by the search box is never relabelled by mistake (T-04.3-482). A mixed selection pre-chooses nothing (`field.mixed`). `bulk.selected` is announced once, when the selection starts.
- **Mine.** The dashboard now also loads `/mine` on the Stored tab, but only once the server has sent access fields, so with the switch off no request is added.
- **Switch off (D-09).** No access field, no mark, no button, no checkbox column, no bar, no status region, the same column widths, and the same table-container class string.

## Decisions (for STATE)

1. **No edit controls in a personal workspace.** No groups exist there, so there is nothing to choose. The mark still renders.
2. **Selection limited to the rows shown** (pruned on every render). Filtering the list narrows the selection, so Change access never touches hidden rows.
3. **The table is a labelled scroll region only while the admin columns exist** (UI-SPEC 9.13). At 360px the three row actions stay reachable inside the region, and the page itself never scrolls sideways. The admin layout uses the computed date and status widths; the off layout keeps today's fixed widths.
4. **Mixed checkbox.** The shared `Checkbox` shows a dash for `indeterminate` and an aria-hidden icon. Its only other user, `nango/file-picker`, never sets `indeterminate`, so nothing changes there.
5. **No migration, no env variable, no store.** No migration number was claimed, no purge hook or store inventory entry was needed, and nothing was synced to the config places.
