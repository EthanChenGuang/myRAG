# Phase 04.3 Plan 43: Config UI Access groups panel, Documents sub-view

**Admins can now see who each document of the workspace is visible to and change it in the Config UI, one document at a time or in bulk. The audience is always shown in one of three readings: Everyone, the named groups, or Uploader and admins only. The audience field cannot be saved empty and never offers Uploader and admins only. The browser sends only document ids and either `everyone: true` or group ids.**

## Behaviour

- **Sub-tabs.** The order is now Groups, Documents, Enforcement. Groups is still the default. Documents loads the first time it is selected, so opening the panel sends no extra request. Later panel refreshes and workspace changes reload it once it has been opened.
- **Audience line (`AccessGroupsAudienceLine`).** It renders the view from `buildAccessGroupsAudienceView(audience, locale)`:
  - **Everyone:** the plain text `audience.everyone`.
  - **Named groups:** a neutral `badge-outline` with `bi-lock` and Restricted, then `audience.groups` with the names. Names are joined with ", " (zh: "、"). When people at the source share the document, `audience.people` with the count follows. Names and the count only: no ids, no keys.
  - **Uploader and admins only:** a `badge-warning badge-outline` with `bi-shield-exclamation`, the reason sentence, and one action. The action is **Open connector mapping** for source reasons or connector documents, otherwise **Edit access**.
  - **Unknown values:** an unknown reason renders as `reason.other` with the code in a `font-mono` code element. An unknown `kind`, or `groups` with no group, is read as Uploader and admins only with the kind as its code, so an unknown value never reads as Everyone.
- **Documents table.** Filter radios (`input.btn.btn-sm` in a fieldset): Restricted (the default), Uploader and admins only, Everyone, All. The search matches file names, runs on Enter or 400 ms after the last key, and sends `q`. The list pages by 50 with **Load more documents**; focus then moves to the first new row. Columns: checkbox, File (`th scope=row`), Document type, Visible to, Source, Actions.
  - Document type and Source are `hidden lg:table-cell`. Below `lg`, the source shows under the file name.
  - Visible to is `hidden md:table-cell`. Below `md`, the audience line shows under the file name.
  - Source uses the Ingestion panel's `source.*` labels when that panel is loaded, otherwise the stored value.
  - Empty states: `docs.empty.restricted` for the Restricted filter with no search, otherwise `docs.empty.filter`. A personal workspace shows `groups.personal`. Failures use the shared sign-in, workspace or `docs.unavailable` alerts.
- **Editor row.** **Edit access** opens a full-width row under the document, headed `edit.title`. Only one row is edited at a time. Opening an editor clears any selection.
  - The field shows Everyone or Only these groups with their help lines. The Everyone help line is `field.everyoneHelp.org` in multi-tenant mode and `.single` otherwise.
  - The chip list (`ul role=list`) is named by the second radio's label. **Add group** is a `details.dropdown` with one button per group not yet chosen, capped at `max-h-72` and scrolling. It stays open after an add. When every group is chosen it becomes a disabled button.
  - Choosing Everyone hides the chips but keeps them, so choosing Only these groups again restores them.
  - **Save access** is disabled when no group is chosen (`field.needGroup`), when the selection is mixed (`field.mixed`) and when nothing is chosen (`field.choose`). Its `aria-describedby` points to whichever of these is shown.
  - An uploader-only document shows its current line labelled `field.current` and pre-chooses nothing.
  - `field.widen` shows when Everyone is chosen for a document that is restricted now.
  - Saving PUTs `{ documentIds: [id], everyone: true }` or `{ documentIds: [id], groupIds }`, with `organizationId` in the query string as on every other route. On success the row's Visible to cell updates from the answer's `audiences`, the status region says `save.done` with the file name and the new audience line, and focus returns to Edit access. Escape and **Cancel editing** close the editor and return focus there.
- **Connector documents.** Edit access and the row checkbox are disabled. The row shows `docs.connectorManaged`, which describes the disabled button. A connector document that fell back also shows **Open connector mapping**. Clicking it calls `selectMapping()`, which selects the `mapping` sub-tab and focuses its `[data-access-groups-mapping-heading]`. This is tested with a stubbed mapping panel; see the deviations for how the button behaves before plan 44.
- **Selection and bulk.** Row checkboxes are labelled `select.aria` and the header checkbox `select.allAria`. The header checkbox ticks the rows on screen that are not connector documents and shows the mixed state (`indeterminate`).
  - The selection bar shows `Selected: n` with **Change access** and **Clear selection**. It is announced once, when the first row is ticked. Ticking a row closes an open editor.
  - **Change access** opens a native `dialog.modal`. Its `aria-labelledby` is `bulk.title` and its `aria-describedby` is `bulk.selected`. Focus starts on **Keep current access**. The box scrolls (`max-h-[calc(100dvh-2rem)]`), so Save access stays reachable.
  - Different audiences show `field.mixed` with no radio chosen and Save access disabled. `field.widenMany` shows when Everyone is chosen and any selected document is restricted.
  - The save sends every selected id. Afterwards the status region says `save.doneMany`, plus `save.skipped` with the count when connector documents were skipped. The selection clears, focus moves to the status region, and the list reloads quietly.
  - Escape and the backdrop do nothing while the save runs.
- **Errors.**
  - **400 `unknown_group`:** `error.groupGone` in the editor or dialog and in the status region. The groups reload, and the field keeps the chips whose groups still exist. The editor or dialog stays open.
  - **409 `access_managed_by_connector`:** `docs.connectorManaged` and a reload.
  - **Other 404 or 409:** `error.changed` and a reload.
  - **Thrown or timed out:** `error.outcomeUnknown` and a reload.
- **Field edge states.**
  - With no group in the workspace, the second radio is disabled and `field.noGroups` is its help line. Everyone stays available.
  - Removing a chip announces `chip.removed` and moves focus to the next chip's remove button, or to Add group after the last one. Adding a chip announces `chip.added`.
- **Text only.** Every server string goes through `ragUiEl` as text. The tests inject `XSS_PAYLOAD` and `javascript:` into file names, group names and reason codes. No element is created, no `a` exists, `innerHTML` is never written, and no principal key pattern appears in the panel.
- **No switch, no env variable, no server change.** The panel calls only the plan-24 routes. With `RAG_DOC_ACCESS_GROUPS=off`, nothing outside the Config UI changes.

## Bug fixed outside the plan

`byData()` and the focus step after Remove member (plan 42) called `.filter` and `.find` directly on `querySelectorAll` results. A browser `NodeList` has no `filter` or `find`, so these calls would throw in a real browser. The fake DOM returns arrays, which hid the bug. Both now go through `Array.from`. The regression case "the panel never chains array methods on a NodeList" fails on the plan-42 code.

## Decisions (for STATE)

1. **One field class.** `AccessGroupsAudienceField` serves both the editor row and the bulk dialog. Plans 45, 46 and 49 can reuse it, for example `new AccessGroupsAudienceField(panel, { groups, known, choice, chips, mixed, restrictedNow, many, mode })` with `bindSave(button)`.
2. **Unknown kinds fail closed in the view.** An unknown `kind`, or `groups` with no group, reads as Uploader and admins only with a code, never as Everyone.
3. **`organizationId` goes in the query string** of the PUT, as on the other routes. The body holds only document ids and `everyone` or `groupIds`.
4. **Lazy load.** Documents loads on its first selection. This avoids a request, and a status announcement, when the panel opens on Groups.
5. **Bulk saves reload the list quietly** instead of patching rows, because a filter can drop the changed rows. A single save patches its row in place, as UI-SPEC 6.4 says.
6. **New label keys** in en, zh and it: `docs.filterLabel`, `docs.caption`, `docs.loaded`, `field.choose` and `field.current`. They are the fieldset legend, the table caption and region name, the load announcement, the reason for a disabled Save when nothing is chosen, and the label of the current audience line. None of them is in UI-SPEC 12.
7. **Purge hook or store inventory:** none, because no store was added. **No migration**, so no migration number was claimed.
