# Phase 6.1 Plan 06: Tenant-scoped, consent-checked export with document split and decontamination Summary

**`python -m rag_eval.finetune export` writes a per-run bundle of current, ready chunks for an explicit tenant list after the consent RPC has confirmed that exact list and purpose; every chunk carries a document-level split, golden-test documents are forced to test, and a row of another tenant aborts the run with nothing written.**

## Accomplishments
- `cli.py`: the D-03 command table (`export`, `generate`, `filter`, `import-mined`, `mine`, `kit`, `train`, `evaluate`, `card`, `prune`, `run` → `export`, `generate`, `filters`, `mined`, `miner`, `kit`, `train`, `evaluate`, `card`, `prune`, `pipeline`). Later plans only add modules.
- `bundle.py`: run directories at mode 0700 (regardless of umask), atomic 0600 JSONL writes validated by the given contract (a row of another model is a `TypeError`), streaming `JsonlWriter` with `abort()`, manifest IO.
- `split.py` and `decontam.py` per D-09/D-10; `GoldenIndex` caches the golden n-grams and skips candidates by the size bound.
- `export.py`: `SupabaseExportSource` (service key, `tenant_key`/`is_current`/`status` filters, keyset paging, per-row tenant check, error codes without bodies) and `FixtureExportSource` (D-36 resolved-path guard).

## Deviations from Plan
1. **Extra helpers** beyond the listed exports: `golden_test_document_ids`, `GoldenIndex`, `default_golden_paths`, `load_golden_items`, `split_bucket`, `bundle.JsonlWriter`, `read_manifest`, `sha256_file`. Additive.
2. **Fixture mode with several tenants** exports the fixture corpus once per tenant (ids differ per tenant) rather than refusing; it never calls the consent RPC, as the plan's fixture-mode bullet says.
3. **Token-count fallback** cannot be recorded in `ExportedChunk`/`DatasetManifest` (no field); it is printed as `token_count=estimated`. With the sidecar installed (the normal eval install) tiktoken is always used.
4. `--batch-rows` overrides `config.export.batch_rows` (used by the paging test).
