# Phase 6.1 Plan 12: Training kit, trainer and image Summary

**`python -m rag_eval.finetune kit --bundle <run> --out <kitdir>` builds a train-and-dev-only kit with a hashed manifest, and `train --kit <kitdir> --out <modeldir> [--loss ...] [--matryoshka]` verifies it, refuses any test data, trains per D-15 and writes the model, the effective TrainingRunConfig, a TrainingRunReport and the probe vectors; the CUDA training image and its hashed lock are committed.**

## Accomplishments
- `kit`: copies the three mining outputs, writes the dev corpus, the resolved `TrainingRunConfig` and `kit-manifest.json` (tenants, base model with prompts, counts, sha256 per file), built in a staging directory and moved into place only when every check passed.
- `train`: kit verification first, host library and model-dimension checks, D-15 wiring through an injectable `TrainLibrary` (real sentence-transformers names or fakes), report and probes after training, checkpoints removed.
- Image and lock: digest-pinned NVIDIA CUDA runtime base, uv-installed hashed lock, non-root user, signature check at build time.

## Signature check (sentence-transformers 6.2.0, transformers 5.17.0, torch 2.15.0+cpu, datasets 5.0.1)
Printed with `inspect.signature` before writing the trainer. Import paths used: `sentence_transformers.sentence_transformer.trainer.SentenceTransformerTrainer`, `.training_args.SentenceTransformerTrainingArguments` and `BatchSamplers` (defined in `sentence_transformers.base.sampler`), `.losses.{CachedMultipleNegativesRankingLoss, MultipleNegativesRankingLoss, GISTEmbedLoss, CachedGISTEmbedLoss, MatryoshkaLoss}`, `.evaluation.InformationRetrievalEvaluator`. Differences from 06.1-RESEARCH.md:
- `CachedMultipleNegativesRankingLoss` also takes `mini_batch_num_tokens`, `directions`, `partition_mode`, `hardness_mode`, `hardness_strength` (unused).
- `SentenceTransformerTrainingArguments` defaults `optim` to `adamw_torch_fused` and `report_to` to `none`; `warmup_ratio` still exists (factory default).
- `InformationRetrievalEvaluator`'s primary metric for the evaluator named `dev` is `dev_cosine_ndcg@10`, so `metric_for_best_model` is `eval_dev_cosine_ndcg@10`.
- `CachedMultipleNegativesRankingLoss` (and the cached GIST loss) refuse a StaticEmbedding model (inputs cannot be split into mini-batches); see deviation 1.
`check_signatures()` asserts every keyword passed exists (finetune_train test and the image build).

## Deviations from Plan
1. **The CPU smoke test trains with `MultipleNegativesRankingLoss`.** sentence-transformers 6.2.0 refuses Cached(MNRL|GIST) on a StaticEmbedding model. The cached default is verified by the fake-trainer test and the signature check; it runs on the real base model in 06.1-19.
2. **TrainingRunReport is unchanged.** The plan lists config sha256, dataset manifest sha256, base revision, seed, git commit and library versions in the report; the 06.1-02 contract keeps those in `TrainingRunConfig`. The model directory carries both, and the report's `training_config_sha256` binds them (no contract or generated schema change).
3. **Library versions come from the lock, and train enforces them** (`library_versions_differ`), so a run is reproducible only in the image environment; the plan did not name the check.
4. **requirements-train.lock is not a pure `uv export`.** `eval/uv.lock` resolves torch from the CPU index. The lock keeps every eval pin (tested) and takes torch 2.15.0 from PyPI with its CUDA wheels, resolved by `uv pip compile --generate-hashes` with an exclude-newer cutoff of 2026-11-12 for the added wheels (cuda-pathfinder 1.9.1 was too new, 1.8.6 used). The repository's `eval/uv.lock` is unchanged; no package was added to any project.
5. **Image runs code from PYTHONPATH** instead of installing rag-sidecar and rag-eval as packages, so no unpinned `uv_build` backend is fetched; `rag-sidecar/config` is copied because the contracts read the language registry at import (found by simulating the image layout).
6. Extra drift test `test_train_lock_pins_the_eval_lock_versions_with_hashes`.
7. `eval/tests/test_finetune_export.py` (outside the plan's files): the unbuilt-command test now uses `card` instead of `train`.
