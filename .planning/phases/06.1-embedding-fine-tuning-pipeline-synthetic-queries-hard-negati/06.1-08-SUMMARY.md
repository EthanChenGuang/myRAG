# Phase 6.1 Plan 08: Synthetic query filters and FilterReport Summary

**`python -m rag_eval.finetune filter --bundle <run> --budget-usd <x> [--dry-run] [--fixture --skip-judge]` reads both raw query files and writes `queries.kept.jsonl`, `queries.test.kept.jsonl` and `filter-report.json`. Rules run in the D-07 order (shape and language, verbatim copy, near duplicate, golden overlap), then a budgeted, cached LLM answerability judge sees only the rule survivors. The report counts every drop per reason and per language, records `round_trip: not_applied`, and contains no query or chunk text.**

## Accomplishments
- Character n-gram rules that work for Chinese as well as Latin scripts: containment of 5-grams and a sparse-DP longest common substring catch copied text; tenant-wide exact duplicates and per-chunk 3-gram Jaccard duplicates are dropped, keeping the first by style order.
- Golden decontamination through `decontam.GoldenIndex` (fixture golden plus the private file when present).
- The judge stage uses `QueryLLM.judge_answerability` with `Budget` over `prices.judge`, checks the budget before every batch, caches every verdict, and stops cleanly (exit 5) with nothing written, so a re-run resumes without paying again.
- No change to `cli.py`: its dispatch table already pointed `filter` at `rag_eval.finetune.filters:main`.

## Deviations from Plan
1. **Test sentences.** The plan's behaviour examples use a product warranty sentence. Following the brief's domain-neutrality rule, the tests use the same structure with a neutral "sample retention period is 24 months from the creation date" sentence in en, zh and it, plus neutral paraphrases.
2. **Extra paths, all additive:** `--dry-run` (D-06 projection); the `unknown_chunk_ref` reason (already in `DropReason`) for a query whose chunk is not in the bundle; integrity refusals for inputs whose hash differs from the manifest; the manifest `files` map records the kept files; `--skip-judge` without `--fixture` is refused with exit 2.
3. **Incomplete runs write nothing.** `FilterReport` has no completeness field, so a budget stop, an LLM failure or an unusable judge batch writes no kept file and no report (stderr says how many calls were made). This keeps `kept + sum(dropped) == raw` true for every report that exists.
4. **near_duplicate per file.** Duplicates are checked inside the train/dev file and inside the test file separately. A train query identical to a test query is not dropped here: the two files come from different documents under the D-10 document split.
