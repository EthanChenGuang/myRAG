# Phase 6.1 Plan 16: Fixture pipeline end to end with leakage invariants Summary

**`python -m rag_eval.finetune run --fixture --out <dir> [--tiny]` chains export, generate, filter, import-mined, FakeEncoder vectors, mine, kit, train, evaluate and card on the committed fixture corpus with fakes and no network, and one test file checks the leakage, decontamination, tenant and no-text invariants on its output.**

## Accomplishments
- `pipeline.py`: the `run` command (already in the 06.1-01 dispatch table), fixture LLM and judge, synthetic 5.1.1 TrainingPair sample, production vectors in the 06.1-10 file format, fake trainer library and model, tiny StaticEmbedding route, pipeline report with reproducible report hashes.
- The fixture inputs are adversarial on purpose: golden questions in generated and mined queries, test-document expert negatives on train pairs, held_out rows, two tenants with identical texts. The guards have to fire for the invariants to hold.
- Mutation checks run during execution (not committed): removing mined's negative split guard makes the run fail at kit (`bundle_contains_test`) and the fixture fails; disabling the golden filter fails the golden invariant.

## Deviations from Plan
1. **Tenants.** The plan names tenant `s:default`; the fixture run exports the same corpus as two multi-tenant keys (purpose `deployment`). With `s:default` the split gives 22 train chunks, 0 dev, 85 test (14 of 19 documents forced to test by the golden set; of the other five, four hash to train and one to test), and kit refuses `no_dev_pairs`. Tenant key is the only input to the bucket besides the content hash. Card scope is therefore `deployment`.
2. **Synthetic mined sample** is generated from the exported chunks at run time (`inputs/training-pairs.synthetic.ndjson`) instead of using `eval/tests/fixtures/finetune/training-pairs.sample.ndjson`, whose chunk ids belong to a hand-built test bundle and would all drop as `unknown_chunk`.
3. **Fixed clock**: the pipeline rewrites the export manifest's `created_at` to a fixed value right after export (before any later step hashes it), so the dataset manifest hash and everything bound to it reproduce. No change to `export.py`.
4. **Reproducible hash list** excludes `training-report.json` (it records wall-clock `duration_seconds`) and `offline-eval.provenance.json` (its model fingerprint covers that file).
5. **The FN audit runs** with the fixture judge (zero prices, budget 0) instead of `--skip-audit`; it samples 50 negatives and passes (0 answerable).
6. **Fakes live in product code** (`pipeline.py`) because the command runs outside pytest; they are language-agnostic (no per-language templates) so `check-language-literals` stays clean.
7. `eval/tests/test_finetune_export.py` changed (outside the plan's files), see above.
