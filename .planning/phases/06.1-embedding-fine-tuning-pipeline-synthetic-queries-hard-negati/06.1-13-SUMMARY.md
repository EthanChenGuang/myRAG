# Phase 6.1 Plan 13: Offline evaluation, model card and prune Summary

**`python -m rag_eval.finetune evaluate --bundle <run> --finetuned <modeldir|vectors:<profile>> [--base <id>] [--zero-shot]` scores the test split per tenant for the base, fine-tuned and production models and applies the D-19 gate; `card` turns the report, probe and training report into the `ModelVersionCard` that `ft-models register` accepts; `prune` deletes text-bearing bundle files past retention or for a revoked tenant.**

## Accomplishments
- `evaluate`: per-tenant exact cosine search over the tenant's whole corpus, Recall@10 / MRR@10 / nDCG@10 overall, by language, by cross-language pair and by source, paired bootstrap 95% intervals (1000 resamples, seed 42), the noise band from `eval/config/noise.json`, the offline promotion rule with enumerated reasons, `offline-eval.json` plus a provenance file. `--zero-shot` scores every base model in `finetune.json` (plus production when its vectors are present) and writes `zero-shot.json` ranked by Recall@10.
- `card`: status `candidate` / `rejected_offline` from the report, scope from the manifest purpose, tenant keys from the manifest, prompts from the evaluated base model, probe from `probe.json`, `training_config_sha256` from `training-report.json`, artifact URI checked by the contract.
- `prune`: age by the later of `created_at` and file mtimes, `--tenant` for D-29 revocation, keeps manifests and reports.

## Deviations from Plan
1. **Reason name.** The plan's test says `language_regression:zh`; the merged contract (`OfflineRejectReason`, 06.1-02) only allows `language_slice_below_production` and forbids repeats, so the report carries that reason once. The failing language is visible in `models.*.by_language` and the deltas.
2. **`--finetuned vectors:<profile>`** reads fine-tuned vectors stored in the 06.1-10 layout under another profile; the plan wrote `<modeldir|vectors>` without a syntax. A card can only be made for a model directory (the provenance of a vectors run has no weights fingerprint).
3. **Provenance file** `offline-eval.provenance.json` is an addition: without it a card could pair any passing report with any weights. It is a local Pydantic model (eval-only, not in the generated Zod contracts).
4. **zero-shot.json** uses a local Pydantic `ZeroShotReport` (eval-only; no contract existed for it).
5. **Optional Zod check of the card** (plan Task 2 marks it optional) not added; the Pydantic validation is in every card test.
6. **Kits outside the bundle**: prune only sees `kit*/` directories inside the bundle; a kit written with `--out` elsewhere is an operator deletion (noted in the module docstring).
