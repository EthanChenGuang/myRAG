# Phase 6.1 Plan 03: Consent and model registry (0651) Summary

**Opt-in fine-tune consent per tenant and a model-version registry, both service_role only, with revocation tainting every affected model version in the same transaction.**

## Performance

- **Duration:** about 45 min
- **Completed:** 2026-11-26
- **Tasks:** 3
- **Files modified:** 4

## Accomplishments
- `supabase/migrations/0651_finetune_registry.sql` (number 0651 was free on trunk and on every `exec/06*` and `exec/queue-hardening` branch): two tables and six functions, all `SECURITY DEFINER`, `SET search_path = ''`, schema-qualified, revoked from PUBLIC, anon and authenticated, granted to service_role. Idempotent (`IF NOT EXISTS`, `CREATE OR REPLACE`, precheck for `rag_assert_tenant_key`); re-applying it keeps the rows (tested).
- `rag_finetune_consent_for_export` refuses an empty or null key list, a null, malformed or other-mode key, a duplicate, an unknown purpose, more than one key for `private`, and names the first key whose consent does not cover the purpose.
- `rag_finetune_register_model` validates the whole card in SQL and checks consent against the card scope; `rag_finetune_set_consent` returns `tainted_versions` for the versions the call tainted.
- Two-tenant tests in multi-tenant mode; in single-tenant mode only `s:default` is valid through the functions, so a second tenant is seeded straight into the tables to show that revoking `s:default` leaves its rows alone.

## Deviations from Plan

**1. Allow-list: no entries added (Task 3)**
- **Issue:** the plan says to add the six functions to `tests/helpers/security-definer-allow-list.ts` as service-role-only entries. That file lists only definers that stay callable by `authenticated`. An entry there would approve an authenticated grant, and the lock test would then accept the wrong ACL.
- **Fix:** the functions are named in the file's comment as service_role only, and `finetune-registry.test.mts` asserts `allowListEntryFor` returns nothing for each of them. This follows the precedent of `rag_purge_retrieval_log` and `rag_mine_failed_queries`.

**2. 0410 upgrade lockdown (found while running the gates)**
- **Issue:** `tests/rag-db/search-rpc-grants-pglite.test.mts` opens every function's grants to simulate an older database and expects 0410 to lock them again. It failed for the six new functions.
- **Fix:** added guarded `REVOKE`/`GRANT` entries to 0410 section 1, as 04.2-03 did (`f7d6ea77`).

**3. Extra columns** `revoked_by` (consent) and `tainted_at`, `updated_at` (versions), for audit.

**4. Folding into the setup files** is not done here. D-32 assigns it to the end of the phase (06.1-17).
