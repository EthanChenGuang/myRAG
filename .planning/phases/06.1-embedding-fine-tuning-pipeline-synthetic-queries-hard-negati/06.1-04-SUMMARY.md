# Phase 6.1 Plan 04: Fine-tune switch and slot settings Summary

**`RAG_FINETUNE` and the nine slot endpoint settings now exist in the manifest, the five config locations, the settings classification and the eval pin. The switch defaults to off and fails closed, and the endpoint key is always masked by the config server.**

## Accomplishments
- Manifest: 10 new `managed` entries with empty `knownGaps`, after `RAG_DOMAIN_EMBEDDINGS`.
- Defaults at every site: `RAG_FINETUNE=off`; `RAG_FT_EMBED_API_KEY=`, `RAG_FT_SLOT_{A,B}_BASE_URL=`, `_MODEL=`, `_QUERY_PROMPT=`, `_DOCUMENT_PROMPT=` (all empty, no secrets).
- `src/lib/env.ts`: `RAG_FINETUNE` is `'on'` only for the exact value `on`, otherwise `'off'`. The slot fields are strings that default to `''`. No app module reads them yet; 06.1-14 is the first reader.
- Config server: the save, standard and full templates write all ten names (`RAG_FINETUNE` defaults to `off`).
- Config UI: a "Fine-Tuned Slots" section in the Ingestion and embedding profiles card. It holds the off/on select, the shared key as a password field with a show/hide button, and two fieldsets (Slot A, Slot B), each with base URL (`type="url"`), model version, query prompt and document prompt. The help text says that binding, consent and activation are CLI-only (`npm run rag:embedding`). Each control has a `label for`, a `name`, `autocomplete="off"` and an `aria-describedby` help line.
- Eval pin regenerated with `npx tsx eval/harness/eval-env.mts --write` (164 values; 10 new).
