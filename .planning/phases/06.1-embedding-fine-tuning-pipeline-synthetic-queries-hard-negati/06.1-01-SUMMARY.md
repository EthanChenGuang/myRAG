# Phase 6.1 Plan 01: Fine-tune contracts, config and optional extras Summary

**Every Phase 6.1 structured output is defined once as Pydantic v2 in `rag_sidecar.contracts.finetune`, `eval/config/finetune.json` holds the pipeline defaults, and the fine-tune libraries are optional, locked eval extras.**

## Accomplishments
- 18 named contracts (40 `_Contract` classes counting sub-models): FinetuneConfig, ExportedChunk, DatasetManifest, SyntheticQuery, SyntheticQueryBatch, AnswerabilityVerdict, FilterReport, FinetunePair, MiningReport, TrainingRunConfig, TrainingRunReport, IrMetrics, OfflineEvalReport, ProbeSet, ModelVersionCard, QueryVectorRow, ChunkVectorRow, VectorFileHeader. No `TrainingPair` here (test asserts it).
- Validators refuse: unknown language; tenant keys other than `s:default`, `u:<uuid>`, `o:<uuid>`; card dims ≠ 1024; `artifact_uri` with userinfo, query or fragment; a tenant-scope card or private manifest with more than one tenant; any other split rule; non-unit or non-1024 probe vectors; probe texts other than the three fixed `PROBE_TEXTS`.
- D-31 field walk: every `str` reachable from the five report models is a patterned id/hash alias, a Literal or the registry Language enum.
- `eval/config/finetune.json`: generator and judge models equal `draft.json`'s `claude_model`; the three base models are pinned to their revisions (Qwen default, instruct query prompt with a neutral task sentence; e5 `query: `/`passage: `; bge-m3 empty); CachedMNRL recipe; prices null (unknown cost).

## Package approval and lock (Task 3)

Approved by the orchestrator on 2026-11-26 ("approved: per-package cutoffs"), after the first approved recipe proved unresolvable.

- Extras: `finetune-data = [anthropic==2.12.0, httpx==0.28.1, numpy==2.5.5]`; `finetune = [sentence-transformers[train]==6.2.0, torch==2.15.0 (PyTorch CPU index), numpy==2.5.5]`.
- Recipe: plain `uv lock` (every existing locked version kept) with `[tool.uv] exclude-newer-package` = `2026-11-12T00:00:00Z` (today minus 14 days) for each new transitive package.
