### Cost estimate (from the fixture dry runs)

`eval/config/finetune.json` ships every price as `null`, so the dry run prints `cost unknown`. Set the four prices (generator, judge per Mtok; `gpu_hour_usd`; `reembed_usd_per_mtok`) in a copy of the config passed with `--config`, then rerun the dry runs on the real bundle: those numbers replace this estimate.

Per eligible chunk (fixture ratios; real chunks are longer, so input grows with chunk size):
- generation ≈ 81 input + 126 output tokens (3 queries per chunk)
- judge ≈ 3 × (101 input + 20 output) tokens
- total ≈ 384 input + 186 output tokens per eligible chunk

`generation_and_judge_usd ≈ N_eligible × (384 × P_in + 186 × P_out) / 1e6`. Example: 10,000 eligible chunks ≈ 3.84 M input + 1.86 M output tokens. Approve a `--budget-usd` of about 1.5 × the real dry-run projection.

GPU: one epoch, `CachedMultipleNegativesRankingLoss`, batch 256 / mini-batch 32, bf16 on a 0.6B model; record wall-clock hours × `gpu_hour_usd`. Re-embed: chunk tokens of the tenant scope × `reembed_usd_per_mtok` (self-hosted endpoint: GPU hours instead).
