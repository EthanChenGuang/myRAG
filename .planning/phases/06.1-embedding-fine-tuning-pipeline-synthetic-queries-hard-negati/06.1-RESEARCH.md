## Summary

The repository already has everything a fine-tuned model needs to go live *safely*: side-by-side profiles in `chunk_embeddings` with a partial HNSW index per profile (`0308_chunk_embeddings.sql:22-35`), a resumable, tenant-scoped re-embed job (`0315`, `npm run rag:reembed`), and an activation gate that refuses incomplete, mixed-model, unproven or stale profiles (`0309_profile_activation.sql:11-113`) fed by `rag_record_eval_evidence` (`0318`). What is missing is (1) the training-data pipeline, (2) the trainer and its offline evaluation, (3) a provider that can serve a model nobody hosts publicly, and (4) governance (consent, registry, revocation, retention).

The recommended design keeps the gate untouched and adds **two fixed fine-tune slots** (`ft-a-1024`, `ft-b-1024`) whose HNSW indexes are created once by migration. A model version is bound to a free slot, re-embedded, evaluated and activated exactly like any other profile; the next version uses the other slot (blue/green). This avoids dynamic DDL in a SECURITY DEFINER function, keeps "never mix vectors" structural (one model per slot, bind refused while the slot has rows), and makes rollback the existing pointer flip.

The production model is hosted (OpenAI 3-small or Qwen3-8B on DeepInfra), so it is not a sentence-transformers model and cannot be passed to `mine_hard_negatives`. The default miner therefore reuses the production vectors already stored in the database plus query vectors computed through `@/lib/rag`, and reimplements `mine_hard_negatives`' filtering semantics in NumPy (parity-tested against the library on a tiny model). That also lets mining run on this CPU-only machine.

**Primary recommendation:** sentence-transformers 6.2.0 (pinned; 6.3.0 was published 2026-11-11, inside the two-week freshness window), `CachedMultipleNegativesRankingLoss` with mined hard negatives and `NO_DUPLICATES` batching on `Qwen/Qwen3-Embedding-0.6B` (zero-shot compared with bge-m3 and multilingual-e5-large-instruct first), relative margin 0.05, document-level 80/10/10 split with golden-test documents held out, offline gate then the EMB-05 gate on the real golden set.

### sentence-transformers (docs fetched 2026-11-24; PyPI latest 6.3.0 on 2026-11-11, 6.2.0 on 2026-10-21)
- `sentence_transformers.util.mine_hard_negatives(dataset, model, anchor_column_name=None, positive_column_name=None, corpus=None, cross_encoder=None, range_min=0, range_max=None, max_score=None, min_score=None, absolute_margin=None, relative_margin=None, num_negatives=3, sampling_strategy="top", query_prompt_name=None, query_prompt=None, corpus_prompt_name=None, corpus_prompt=None, include_positives=False, output_format="triplet"|"n-tuple"|"labeled-pair"|"labeled-list", output_scores=False, batch_size=32, faiss_batch_size=16384, use_faiss=False, use_multi_process=False, verbose=True, cache_folder=None, as_triplets=None, margin=None)`. `relative_margin=0.05` "discards negatives whose similarity is greater than `positive_score - abs(positive_score) * 0.05`"; the docs' tip recommends `relative_margin=0.05, num_negatives<=10, sampling_strategy="top", use_faiss=True` = NV-Retriever "TopK-PercPos (95%)". `range_min` skips the most similar ranks "to avoid marking texts as negative that are actually positives". Source: https://sbert.net/docs/package_reference/util/hard_negatives.html
- Losses (module `sentence_transformers.sentence_transformer.losses` in 6.x docs): `MultipleNegativesRankingLoss(model, scale=20.0, similarity_fct=cos_sim, gather_across_devices=False, directions=('query_to_doc',), partition_mode='joint', hardness_mode=None, hardness_strength=0.0)`; `GISTEmbedLoss(model, guide, temperature=0.01, margin_strategy='absolute', margin=0.0, contrast_anchors=True, contrast_positives=True, gather_across_devices=False)`; `CachedGISTEmbedLoss(..., mini_batch_size=32, mini_batch_num_tokens=None, ...)`; `MatryoshkaLoss(model, loss, matryoshka_dims, matryoshka_weights=None, n_dims_per_step=-1)`; `CachedMultipleNegativesRankingLoss` (GradCache, `mini_batch_size`). The docs recommend `BatchSamplers.NO_DUPLICATES` for MNRL/GIST-family losses. Source: https://sbert.net/docs/package_reference/sentence_transformer/losses.html

### Literature (recipe rationale)
- Synthetic query generation per passage + consistency filtering: Promptagator (Dai et al., 2022), InPars (Bonifacio et al., 2022), GPL (Wang et al., 2022). Round-trip filtering keeps queries the retriever already finds; we keep it optional/off (D-07e).
- Hard negatives with positive-aware margins reduce false negatives: NV-Retriever (Moreira et al., 2024), cited by the sentence-transformers docs.
- GradCache / cached MNRL enables large effective batches on one GPU (Gao et al., 2021).
- Document-level (not pair-level) splits are needed because pairs from the same document share vocabulary and leak (general IR evaluation practice; BEIR-style held-out corpora).

### Pattern 1: contracts (Pydantic, frozen, extra=forbid)
`FinetuneConfig`, `ExportedChunk`, `DatasetManifest`, `SyntheticQuery`, `SyntheticQueryBatch` (LLM tool output), `AnswerabilityVerdict` (LLM tool output), `FilterReport`, `FinetunePair`, `MiningReport`, `TrainingRunConfig`, `TrainingRunReport`, `IrMetrics`, `OfflineEvalReport`, `ProbeSet`, `ModelVersionCard`, `QueryVectorRow`, `ChunkVectorRow`. Validators: language ∈ {zh,en,it}; tenant key shape `s:default|u:<uuid>|o:<uuid>`; card `dims == 1024`; `artifact_uri` without userinfo/query/fragment; no free-text field in reports (counts, ids, hashes only).

### Pattern 2: export and split
Supabase REST with the service key (like `SupabaseWorkspaceSource`) filtered by `tenant_key`, `is_current = true`, `status = 'ready'`, keyset by id; first call `rag_finetune_consent_for_export(p_tenant_keys text[])` which returns each key's scope and refuses (raises) if any is not `deployment`. Directory source for fixtures. Split per D-10; decontamination per D-09.

### Pattern 3: generation
One LLM call per batch of chunks (≤ `batch_chars`), tool `submit_queries` returning `SyntheticQueryBatch{items:[{chunk_ref, language, style, query}]}`; chunk refs are batch-local indexes, mapped back; unknown refs dropped and counted. Cache file `cache/generate/<sha256(content_hash|prompt_version|model)>.json`. Budget meter from response `usage`.

### Pattern 4: filters
Normalization `nfkc → casefold → remove whitespace and punctuation`; `char_ngrams(s, n)`; `containment(q, c, 5)`; `lcs_len` by suffix automaton or DP bounded by query length (queries ≤ 200 chars). Judge prompt sees only (query, chunk), returns `AnswerabilityVerdict`.

### Pattern 5: mining (vectors backend)
For each tenant: `S = Q @ C.T` (float32, normalized), per query: positive score `p`; candidates sorted by score, ranks `[range_min, range_max)`, drop `s > p - |p|*relative_margin` (and absolute/min/max if set), drop guarded ids (D-12), take top `num_negatives` (or random with seed). Memory: chunk the query matrix (1024 queries per block). Corpus restricted to train-split documents for train pairs (D-10).

### Pattern 6: training

### Pattern 7: offline evaluation
Exact search (NumPy) per tenant; Recall@10 = share of queries with any relevant chunk in top 10; MRR@10; nDCG@10 (binary). Paired bootstrap (1000 resamples, seed) over queries for ft − production and ft − base. Production model = stored vectors + query vectors from `embed-queries`.

## Common Pitfalls
1. **False negatives** in mined negatives (duplicate passages, neighbour chunks) teach the model to push away correct answers → margin + guards + FN audit (D-11, D-12).
2. **Pair-level split leakage** inflates offline metrics → document-level split, negatives for train from train docs only (D-10).
3. **Golden contamination** makes the EMB-05 gate meaningless → D-09.
4. **Mixed-model index** when an endpoint is redeployed with other weights behind the same URL and model name → probe check (D-24) on top of the `embedding_model` column check.
5. **Prompt mismatch** between training and serving (Qwen instruct, e5 prefixes) silently degrades recall → prompts on the card, written to the slot, probe vectors computed with them.
6. **Catastrophic forgetting** on general and cross-lingual queries → forgetting slices in the gate (D-20), 1 epoch default, low LR.
7. **Round-trip filter bias** → off by default (D-07e).
8. **Cost overrun** on big corpora → required budget, dry-run projection (D-06).
9. **Cross-tenant leakage** through shared candidate pools or a shared model → per-tenant mining/eval, explicit consent and tenant list (D-28).
10. **Rollback slot overwritten** → bind refuses the active and the previous-active slot (D-22).

## Cost and Latency (formulas; numbers are live items)
- Generation tokens ≈ chunks × (prompt_overhead/batch + chunk_tokens + 3 × 25 output); judge ≈ queries × (chunk_tokens + 60) input + 20 output. For 30,000 chunks of ~300 tokens: ≈ 10–12 M input and ≈ 2.5 M output tokens for generation, ≈ 30 M input for the judge; cost = tokens × the price table in `finetune.json` (operator fills prices; dry-run prints the projection).
- Training: ~90k pairs × 1 epoch on Qwen3-0.6B at batch 256 with CachedMNRL ≈ 1–3 GPU hours on one 24–80 GB GPU (estimate, LOW confidence).
- Re-embed: corpus tokens / endpoint throughput; a 0.6B model on one GPU embeds thousands of chunks per minute.
- Query latency: one short query on a warm 0.6B endpoint is typically tens of ms plus network; must fit the 200 ms `embed` budget (live measurement).
