# Phase 6.1 Plan Index

20 plans in 10 waves. Plans in the same wave share no file in `files_modified`; every file touched by two plans is ordered by a `depends_on` path (`tests/helpers/security-definer-allow-list.ts`: 03 → 05 → 10 → 20; `src/lib/rag/embeddings/cli.ts`: 15 → 20). Every plan runs after Phase 6, Phase 3.1.1 and Phase 5.1.1 are complete (roadmap dependency). Live checks are the four checkpoints of 06.1-19; everything else is automated on CPU with fakes (see `06.1-RESEARCH.md` Validation Architecture).

PGlite note: 03, 05, 10, 15, 17, 20 and 18 build PGlite databases that apply every migration. `.planning/config.json` sets `workflow.use_worktrees` to false, so in one working tree never run two of them at once (03 in wave 1, 05 in wave 2, 10 in wave 3, 15 in wave 4, 17 in wave 5, 20 in wave 6 are alone in their waves among PGlite plans).

UI: UI-SPEC waived (D-34, orchestrator decision): 06.1-04 adds one field group to the existing Config UI Embedding profiles card; it runs web-design-guidelines on `scripts/config-ui/index.html`, writes the `## Design skills` table and passes `scripts/ci/check-frontend-design-summary.mjs`.

Package approval: 06.1-01 is `autonomous: false` only for Task 3 (approve the pinned package list before `uv lock`, CONTEXT Q9). The `finetune` extra must be installed at execution so `finetune_train` tests run; 11, 12 and 18 run them with `FINETUNE_TRAIN_REQUIRED=1` (a skip fails).
