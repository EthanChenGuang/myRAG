# Phase 6.1 Plan 07: Budgeted, cached synthetic query generation Summary

**`python -m rag_eval.finetune generate --bundle <run> --budget-usd <x> [--dry-run]` writes three queries per eligible chunk (keyword, question, colloquial) in the chunk's language, plus one cross-language query for a seeded 15% of chunks. It goes through a structured Anthropic tool call behind a `QueryLLM` protocol, checks the budget before every call, and caches results per (content hash, prompt version, model), so a stopped run resumes without paying again.**

## Accomplishments
- `llm.py`: the protocol both LLM steps use (generation here, the judge in 06.1-08 and the false-negative audit in 06.1-11). The Anthropic adapter forces tool use with `SyntheticQueryBatch.model_json_schema()` (and a `JudgedBatch` schema for the judge) and takes its model ids from `finetune.json`. It escapes chunk text inside `<chunk ref=… language=… [extra_language=…]>` delimiters and raises `LLMOutputInvalid` (code plus the billed usage) on refusal, truncation, a missing tool call or an invalid payload. Errors are re-raised `from None` with the key scrubbed.
- `budget.py`: the `Budget` meter and the character-based projection. The dense-script ratio is chosen from the registry pack's `script`, so no language code is hard-coded.
- `generate.py`: the command, the raw row model, the report model and the deterministic helpers (`cross_language_target`, `cache_key`, `plan_batches`, `estimate_batch_usage`).
- `finetune_fakes.py`: `FakeQueryLLM`. Tests never read a real key and make no network call.

## Deviations from Plan
1. **Raw row model.** The plan says "write rows as SyntheticQuery with chunk_id, tenant_key, split". `SyntheticQuery` is a frozen `extra=forbid` tool-output contract, so the rows use a new eval-side model, `RawSyntheticQuery`, that carries those fields. No sidecar contract changed.
2. **Null prices.** A real run with null generator prices is refused (exit 2) instead of running unmetered. The plan only specified the dry-run message for this case.
3. **Exit 1** is used for bundle integrity failures (a chunk of a tenant outside the manifest, or a `chunks.jsonl` hash that differs from the manifest) and for LLM call failures. Exit 5 is reserved for the budget stop, as the plan asks.
4. **Extra exports**, all additive: `build_request`, `requested_styles`, `generation_languages`, `CacheEntry`, `CachedQuery`, `GenerateReport`, `JudgedBatch`, the `render_*` and `*_system_prompt` helpers, `prices_known`, `chars_per_token`.
5. **Manifest update.** generate adds the sha256 of both raw files to the manifest's `files` map.
