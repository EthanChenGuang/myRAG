# Phase 6.1 Plan 02: Fine-tune contracts in JSON Schema and Zod Summary

**The 18 Phase 6.1 contracts are exported to JSON Schema and Zod with one sample each, and the generated ModelVersionCard schema refuses the same bad cards as Pydantic for dims, artifact_uri and tenant scope.**

## Accomplishments
- `export_schemas.py` registers FinetuneConfig, ExportedChunk, DatasetManifest, SyntheticQuery, SyntheticQueryBatch, AnswerabilityVerdict, FilterReport, FinetunePair, MiningReport, TrainingRunConfig, TrainingRunReport, IrMetrics, OfflineEvalReport, ProbeSet, ModelVersionCard, QueryVectorRow, ChunkVectorRow and VectorFileHeader. The generated file now has 170 schemas; `TrainingPairSchema` appears exactly once (5.1.1's).
- `samples.py` gains `_finetune_models()` with placeholder values only (`s:default`, `example-org/example-embedding`, neutral widget sentences, the fixed `PROBE_TEXTS`). The probe vectors are 1024-dim unit vectors, so samples.json grows by about 6,900 lines.
- `tests/rag/finetune/contracts.test.ts` uses the generated schemas only: each sample parses and round-trips, plus the card rejection cases and two shape checks (unknown language, unknown query style).

## Deviations from Plan
1. **finetune.py edited** (not in files_modified). The plan allowed for an unexported URI pattern by deferring to a 06.1-15 helper, and it had no fallback for the tenant-scope rule. I exported both rules into the schema instead, so Zod enforces them now. Python behaviour is unchanged: the pattern is implied by `_check_artifact_uri`, and the anyOf is schema-only (`json_schema_extra`). Only the error type for a rejected URI changes (pattern mismatch now, not a value error).
2. **Extra Python test file**, `rag-sidecar/tests/test_finetune_contract_export.py`. It checks the export modes, the samples and the schema rules, and gave Task 1 its RED commit.
