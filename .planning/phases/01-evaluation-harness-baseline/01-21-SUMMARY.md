# Phase 1 Plan 21: Contract Samples and Zod Parity Tests Summary

**Python-built samples of all 17 exported contract models are committed and parsed by the generated Zod schemas, with tests proving strictness, null and default handling, deterministic regeneration and stale-output detection.**

## Performance

- **Duration:** about 6 minutes
- **Tasks:** 2
- **Files modified:** 6

## Accomplishments

- `build_samples()` produces a valid synthetic instance per model in the CONTRACTS registry, plus three variants (RagTrace answer null, no_answer GoldenItem with null expected_answer, RagRunRequest with only `query`).
- `export_all(out_dir, samples_path)` now writes samples.json next to the schemas, atomically and with sorted keys; `npm run gen:schemas` regenerates everything and leaves the tree clean (no changes to existing schemas or contracts.generated.ts).
- `tests/contracts.test.ts` parses every sample and variant with `<Model>Schema`, checks the round trip is lossless, and rejects an unknown key on all 17 models.
- `tests/schema-parity.test.ts` proves byte-identical regeneration from a foreign working directory, that a changed schema changes the generated output, and exit 1 for an empty directory, a duplicate title, a cyclic `$ref` and malformed JSON (no partial output left).
