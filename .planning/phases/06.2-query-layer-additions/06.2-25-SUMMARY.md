## Behaviour

- **Contract (D-05, P-17).** `SubQuestionFilter.versions: VersionScope | None`, reusing the RET-11 type (no new shape). Regenerated with `npm run gen:schemas`; sample `_p62_versions_filter` (`{to: 2024-12-31}`).
- **Narrowing (D-06, P-35, T-06.2-69).** `narrowFilters(base, proposed, vocabulary, versionRules?)`; `VersionRules = { versionScopeEffective, versionQuestion, callerCurrent? }`:
  - caller asked `versions: current` → the proposal's versions is ignored (rest of the proposal still narrows);
  - `current` narrows a non-current caller scope (variant reads current only);
  - `all` / range widen a current base only with `RAG_VERSION_SCOPE` effective for the request (voice never, embed needs `RAG_EMBED_VERSION_SCOPE`) and a version question; otherwise dropped as unknown;
  - against a caller range: ranges intersect (empty → `dropped_empty_intersection`), `all` leaves the caller range; a range with no bound or reversed bounds is dropped;
  - no rules → no widening.
  `isVersionQuestion(text, reasons)`: gate `R3_COMPARISON` or `R2_RELATIVE_TIME`, a relative-time match, or a standalone year token; checked on the standalone and the raw query in `run-layer.ts`.
- **Search.** `planToVariants` copies the applied spec's versions to `QueryVariant.versionScope`. `runSearchStages` re-checks each variant scope with `effectiveVersionScope` (ignored scopes are stripped), searches that variant with its own scope and every other leg with the shared one; the filtered-search retry uses the shared scope (never wider). Backend routing, `superseded_dense_unavailable` and the output `versionScope` (context version labels) follow the request scope, else the first sub-question scope. Same in the delegated port. The tenant still comes only from the request scope.
- **Cache (RET-11 text, T-06.2-70).** `subQuestionVersionScope(plan.sub_question_specs)` feeds the semantic_cache facts; a non-current sub-question scope bypasses with `version_scope`; `current` does not.
- **Caller current.** `requestsCurrentVersions(body)` (parse output unchanged); chat, embed and internal run routes pass `callerVersionsCurrent: true` only when the body said `versions: "current"`.
- **Prompt.** `shared.subq-filters` v2 lists `versions` and its values; joins the hash only while `RAG_QUERY_SUBQ_FILTERS` is effective (unchanged rule), so the hash with the switch off is unchanged.
- **Glossary → LANG-07 (D-14).** Proven, no production change: translation TERM entries reach the 4.2 dictionary matcher; a multi-word Latin target is one `_t_` token (index and query side), a Han target one token in zh, another tenant's dictionary holds none.
- **Off state.** With `RAG_QUERY_SUBQ_FILTERS` off (default) the decomposer prompt and plan are unchanged; with `RAG_VERSION_SCOPE` off no variant scope is sent. Strict refusal, webSearch with Exa, `source_images`, `{{context}}`, voice and embed unchanged.
