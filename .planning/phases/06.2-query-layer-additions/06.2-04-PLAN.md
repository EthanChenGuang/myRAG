<objective>
Store the translation glossary inside the TERM dictionary: one new column, the TERM functions re-created to read and return it, and the validator, CSV and list route extended additively.

Purpose: D-13 (glossary pairs are TERM entries of kind translation with a target language), D-02 (migration block, hardening), D-15 (the list route filters the Glossary view needs). This keeps one dictionary under TenantScope with 4.1.1's layering.
Output: migration 0980 with a PGlite suite, and additive changes to four TERM modules and the list route with their tests.

<assumption_delta_decision>
Primary noun: TERM entry (one dictionary, D-13). Decision: add-alongside — a nullable target_language on the existing entry, required only for kind translation. Rationale: D-13 locks one dictionary and a nullable column keeps every 4.1.1 row, writer and CSV file valid. Accepted debt: if a second kind ever needs a target language, the entry would be promoted to a (source language, target language) pair with a data migration.
</assumption_delta_decision>

Rollout position: D-32 step 7 (glossary migration and TERM extensions), moved early because nothing in it waits on other 6.2 code. Cross-phase edges: 04.1.1-03 and -04 create the tables and writers, 04.1.1-14 folds them (the newest definitions may sit in the setup files), 04.1.1-05, -06, -09 and -11 last edit the four TERM modules and the route, 03.2-07 provides the enabled-language settings. This plan adds a migration that every PGlite test applies: do not run it at the same time as another PGlite plan (use_worktrees is false).

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan. No secrets, keys, real queries or chunk text in code, tests, logs or commit messages.
</objective>
