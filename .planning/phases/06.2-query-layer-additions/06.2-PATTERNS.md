## Pattern Assignments

### `src/lib/rag/query/completeness.ts` and the `post-checks.ts` change (utility, transform)

**Analog:** `src/lib/rag/query/post-checks.ts`

**Imports and types** (lines 1-34): a sibling relative import, result types as discriminated unions, skip records that never
carry query text.
```typescript
import { keepsProtectedTokens } from './protected';

export type PostCheckSkipReason = 'protected_token_lost' | 'length' | 'empty' | 'cap';

/** A skip record names the transform and the reason only; it never carries query text. */
export type PostCheckSkip = {
  kind: CheckedKind;
  reason: PostCheckSkipReason;
  index?: number;
  count?: number;
};

export type SubQuestionsCheck = { subQuestions: string[]; notCompound: boolean; skipped: PostCheckSkip[] };
export type SubQuestionsInput = { questions: readonly string[]; input: string; protectedTokens: readonly string[] };
```

**Core pattern, and the call site that must be re-ordered** (`checkSubQuestions`, lines 83-116). The last `if` is the union
check that today discards a decomposition that lost one protected token (RESEARCH F-1, Pitfall 1):
```typescript
export function checkSubQuestions(sub: SubQuestionsInput, limits: PostCheckLimits): SubQuestionsCheck {
  const { input, protectedTokens } = sub;
  const questions = sub.questions.filter((q) => q.trim().length > 0);
  if (questions.length === 0) return { subQuestions: [], notCompound: true, skipped: [] };
  // … per-question checks push to `kept` or `skipped` …
  if (kept.length > limits.maxSubQuestions) {
    skipped.push({ kind: 'decompose', reason: 'cap', count: kept.length - limits.maxSubQuestions });
    kept.length = limits.maxSubQuestions;
  }

  if (kept.length > 0 && !keepsProtectedTokens(kept.join('\n'), protectedTokens)) {
    return { subQuestions: [], notCompound: false, skipped: [{ kind: 'decompose', reason: 'protected_token_lost' }] };
  }

  return { subQuestions: kept, notCompound: false, skipped };
}
```
Rule for the plan: with `RAG_QUERY_DECOMPOSE_COMPLETENESS` on, the order is per-question checks → `checkDecompositionCompleteness`
→ cap → union check. With the switch off, `checkSubQuestions` is called exactly as today (byte-identical result).

**Helpers to reuse, not re-write:** `charCount`, `normalizeForCompare`, `failure` (same file, lines 36-60) and, from
`protected.ts`, `scanProtected`, `extractProtectedTokens`, `keepsProtectedTokens` (NFC, case-sensitive, verbatim). Lexical-class
matching uses `normalizeLexical` from `src/lib/rag/lexical/tokenize.ts`, which is exported only after Phase 4.1.1 (precondition).

**Result shape for a parse that can fail** (`parseRetrievalFilters`, lines 116-171): `{ ok: true; filters? } | { ok: false; details }`,
empty lists and `from > to` rejected. A sub-question filter that fails validation is dropped and traced (D-06), it is not an error
response.

**Intersect-only narrowing with a no-match guard** (`buildRetrievalFilters`, lines 173-204). `narrowFilters` copies this shape:
start from the base, intersect, never widen.
```typescript
/** An id no document has: an empty intersection of two document lists must match nothing, and an empty list reads as no filter downstream. */
const NO_DOCUMENT_ID = '00000000-0000-0000-0000-000000000000';

export function buildRetrievalFilters(input: { explicit?: RetrievalFilterInput; referencedDocumentIds: string[] }): RetrievalFilters {
  const explicit = input.explicit ?? {};
  const result: RetrievalFilters = { currentOnly: true };
  if (explicit.dateRange) result.dateRange = { ...explicit.dateRange };
  // …
  if (explicitIds && explicitIds.length > 0 && referenced.length > 0) {
    const refSet = new Set(referenced);
    const narrowed = explicitIds.filter((id) => refSet.has(id));
    result.documentIds = narrowed.length > 0 ? narrowed : [NO_DOCUMENT_ID];
  }
```
Difference to state in the plan: for a sub-question filter an empty intersection **drops the proposal** (D-06), it does not use a
no-match sentinel. `documentIds`, `sources`, `invoice`, `include_undated` and `includeUntagged` are copied from the base and are
never set from model output (RESEARCH F-2).
