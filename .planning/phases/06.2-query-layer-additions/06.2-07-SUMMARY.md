# Phase 06.2 Plan 07: Glossary view Summary

Admins list, add, edit, delete and import glossary pairs in a new Glossary tab of the Terminology panel. Rows without a supported target language show as Incomplete and are never given a guessed target.

## Task 1: precondition (D-01)

`04.1.1-13-SUMMARY.md` exists, `scripts/config-ui/rag-panels/terminology.js` exists and `index.html` has `#RAG_TRANSLATION_GLOSSARY` (06.2-02). All 314 transitive dependency plans have a SUMMARY on this branch.

Entry points terminology.js exposes: sub-tabs from `ragUiSubTabs` (`this.tabs`, tablist with roving tabindex, `select(id)`, `current()`); the entry editor is inline in the Entries tab (no dialog frame); the import flow is the "Import and export" tab (`renderImport` / `renderImportResult` / `runImport`, file pick, dry run, apply, replace confirmation); pagination is offset + `list.range` with Previous/Next; one polite status region `[data-terminology-status]`.

## Task 2: Glossary view

- `glossary.js`: `initGlossaryView(host, api)` (idempotent: first call mounts, later calls refresh), labels `GLOSSARY_LABELS` en/zh/it from UI-SPEC 12.2, helpers from `rag-ui.js`.
- List: `GET /api/rag/admin/terminology?kind=translation&layer=…&source_language=…&target_language=…&search=…` (organization added by the panel). Columns Source terms (row header, `lang`, `translate=no`, "Other forms: n", source language as "name (code)"), Required translation, State badge with icon and word, Actions. Invisible characters as `[U+XXXX]` in the table only. `normalized_variants` and `entries_sha256` are never rendered.
- Notes: `note.switchOff` when the page's `#RAG_TRANSLATION_GLOSSARY` is unchecked (reads it, writes nothing, no request) with "Open query layer settings"; `note.monolingual` with one supported language, and then no Add or Import action.
- Form: `dialog.modal`, two fieldsets (Source, Translation), only supported languages, the source language disabled as target, a cleared target when the source changes to it, validation on submit with Save enabled, focus on the first failing field, no `maxlength`. Enter saves from Required translation, Ctrl/Cmd+Enter from a textarea. Closing with typed changes asks in the footer. Escape and the backdrop do nothing while a save runs. Unsaved form values ask before leaving the page.
- Body sent: `kind: translation`, `mode: one_way`, `language` = source, `source_language`, `target_language`, `layer`, `expected_version` (layer version of the last list), organization in the body.
- terminology.js: Glossary tab right after Entries, refresh on layer or workspace change, `glossaryApi()`, and the import hooks.

## Behaviour changes

New tab only. The Terminology panel's other tabs, routes and request shapes are unchanged; the import tab opened directly shows no glossary additions. No env variable, no route, no SQL.

## Deviations

- **Rule 1 (scope):** terminology.js got more than "two lines": the tab and init call plus the glossary API object, refresh on layer/workspace change and three import hooks UI-SPEC 6.2.4 assigns to this phase. All are inert when glossary.js is not loaded.
- **No Target language column in the dry-run report** (UI-SPEC 6.2.4 item 2): the import report has no per-row target data. Recorded in key-decisions.
- **Delete 409** uses the shared confirmation dialog's message line plus an automatic reload instead of a "Reload entries" button inside the dialog.
- **Row actions** do not move under the first cell below 768px (see key-decisions).
