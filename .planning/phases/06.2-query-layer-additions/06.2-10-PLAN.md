<objective>
Give query-language detection a confidence among the enabled languages and a fallback chain, with the sidecar language-ID step as an optional HTTP client.

Purpose: D-17 (confidence, chain sidecar then previous turn then UI language then primary, LLM-reported override, traced source) and the app side of D-18 (the sidecar endpoint and package come in 06.2-13 behind the approval checkpoint; this client works against a fake sidecar).
Output: the resolver, the never-throw client, gate and run-layer wiring, the LLM-reported language read from condense and translate outputs, the case file and three tests.

<assumption_delta_decision>
Primary noun: LanguageDetection {language, confidence, source}. Decision: promote — the resolved detection becomes the one value the gate, translation targets and answer-language instruction read; the bare detector output is demoted to the first step of the chain. Rationale: LANG-08 turns a single derived language into a chosen one with a fallback chain, so consumers must see where it came from. Not add-alongside: a second, parallel language value would let the gate and the answer-language line disagree.
</assumption_delta_decision>

Rollout position: D-32 step 8 (LANG-08 detection; the sidecar step follows in 06.2-13). Cross-phase edges: 03.2-07 (enabled and primary languages), 03.2-10 (numeric confidence and candidates on detectLanguageWithConfidence), 03.2-11 (last edit of rewrite-gate.ts), 06-13 (condense), 06-16 (native translate), 06-23 (translate in run-layer). In-phase: 06.2-06 last edits run-layer.ts.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan. No real queries in fixtures; no query text in logs.
</objective>
