# 06.2-35 SUMMARY: Auto routing in chat and embed

## What was built

- **Chat** (`src/app/api/chat/route.ts`):
  - At the model read, a request whose `settings.model` is exactly `auto` is resolved with `resolveRequestedModel` against `currentModelRoutingConfig()`. The result is the quality id, and it is routable only with `RAG_MODEL_ROUTING=auto` in effect. Every other request (explicit or absent) keeps today's expression `requested || 'openai/gpt-4o-mini'`.
  - `auto` therefore never reaches `isGPTModel`, the citation session, the cache key, the prompt budget, `runRetrieval` options, `prepareReasoningConfig`, `getMaxTokensForModel` or the provider.
  - A routable turn creates the citation session with `routingCandidates: [fast, quality]`.
  - After retrieval, right after `knowledgeContextAttached` and before the calc offer and `citationSession.attach`, `routeModel` runs on the turn's `queryClassification`, `retrievalResult.queryPlan`, `countTokens(context)` (0 when no knowledge context is attached) and `effectiveQueryParams('chat')`. The routed id replaces `model`, `modelWithWebSearch` and `isGPTModel`, and `citationSession.setFinalModel` is called before `attach`. A routed Claude model takes the GEN-01 Citations path through the 06.2-29 session.
  - The router runs only when retrieval ran. With RAG disabled for the turn, Auto keeps the quality model.
- **Embed** (`src/app/api/embed/chat/route.ts`):
  - `resolveEmbedAutoModel` handles only the exact `auto` request. When the resolved id is outside the embed allowlist, it falls back to the default embed model and is not routed (T-06.2-79). `resolveEmbedModel` is otherwise today's function, without the Auto placeholder branch.
  - The classification is now held in a local and passed to `queryLayerInputs` unchanged. It is still one call, only while the layer is on.
  - Routing runs after the cache-hit and knowledge-base-unavailable returns, on the retrieved turn. A routed id outside the allowlist keeps the quality model, with rule `invalid_routing_id`.
- **Cache key**: on a routable Auto turn, `cacheContext.generatorModel` is `auto|<fast>|<quality>` in both routes. Explicit turns and Auto with routing off keep the model id.
- **Trace**: every Auto turn with a trace records a `model_route` stage with attributes `{tier, rule, selection}` only (no query or prompt). Explicit turns record nothing new. One `[Model Routing]` log line carries tier and rule.
- WhatsApp, voice and the approve route are untouched.

## Deviations

1. **Cache key shape.** I used `auto|<fast>|<quality>`, the shape 06.2-29 committed for the eval route, instead of the plan text's `auto:<fast>|<quality>`. With this shape, eval, chat and embed share one key part (06.2-29 "Decisions for STATE").
2. **Stored Auto with routing off goes to the quality model.** Before this plan, the 06.2-02 placeholder `resolveStoredAutoModel` sent it to the list's default model. D-19 and this plan's truth require the quality model. It is the only change with `RAG_MODEL_ROUTING` off, and it affects only a request whose stored selection is literally `auto`: the selector offers Auto only while routing is effective. Explicit and absent selections are unchanged. `resolveStoredAutoModel` stays in `src/lib/chat/auto-model.ts` (its tests still pass), but no route uses it now.
3. **Exact match on `auto`.** Only the exact string goes through the resolver. Case or whitespace variants keep today's path, so no explicit request changes.
4. **`model_route` is recorded as a stage record** (`name: 'model_route'`, `attributes`), because the chat and embed traces have no per-request field like the eval `RagTrace.model_route`. Embed records it too.
