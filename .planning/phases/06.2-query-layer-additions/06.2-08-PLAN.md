<objective>
Carry each turn's standalone query and query language from the server to the client and back, and pass the UI language, so the next turn can fall back to the previous standalone query and the language chain has its previous-turn and UI-language steps.

Purpose: D-22 (standalone query in message metadata for chat and embed; WhatsApp in 06.2-12) and the request side of D-17 (UI language, previous-turn language). The server can only stream metadata on the assistant message, so the client copies it onto the user message (research F-10, P-12).
Output: stream metadata in two routes, client persistence and request changes, the embed body field, and three test files.

Rollout position: D-32 step 9 (QRY-12 metadata), placed early because it needs only the 06.2-03 types. Cross-phase edges: 05-15 last edits answer-metadata.ts, chat.ts, page.tsx and the round-trip test; 05.1.1-09 and 05.1.1-10 and 06-36 last edit the two routes; 02-32 the embed request; 06-13 and 06-27 provide queryPlan and the query-layer inputs of both routes.

This plan edits `src/app/page.tsx`, so it is a UI plan for the design gate even though nothing visual changes: run web-design-guidelines on the touched file and record frontend-design and Impeccable as n/a in the SUMMARY's `## Design skills` table.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan. No secrets, real queries or customer text in tests.
</objective>
