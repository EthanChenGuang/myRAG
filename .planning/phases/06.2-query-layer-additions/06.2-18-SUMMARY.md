## Behaviour

- **Loader (D-26, P-28).** `getCentroidSnapshot(scope, profileId)` is synchronous. A miss answers `null` and starts one background refresh; an entry older than 60 s is served while one refresh runs. The refresh reads `rag_scope_centroids_list`, `rag_scope_examples_list` and `rag_scope_status` (5 s timeout) and keeps at most 200 centroids (largest member counts first) and 100 examples. It stores them as unit-normalized `Float32Array`s and keeps no example text. `unsupported` is `has_scoped_binding` (D-38, P-13). A load error keeps the previous snapshot or null, logs once per code with `[Scope Gate]`, and waits 5 s before retrying. The cache key is `tenantKey|profileId`. `invalidateCentroidCache(scope)` drops every profile of that tenant only, and discards a refresh already running for it (generation counter).
- **Build (D-25, D-30, D-34).** `rebuildScopeCentroids(scope, { profile?, signal?, reembedExamples? })` calls `rag_scope_centroids_rebuild` on the admin client. Its only tenant input is `scopeKey(scope)`, and the profile defaults to the active one. It returns per-kind groups and chunks and then invalidates that tenant. With `reembedExamples`, examples stored under other registered profiles are embedded with the target profile and added; texts already present are skipped and the limit stops the run.
- **Examples.** `addScopeExample` trims the text and returns `text_empty` or `text_too_long` (more than 500 code points) without embedding. It pre-checks for a duplicate (same case- and whitespace-folded key as the SQL rule) and returns `example_exists`, and returns `limit` at 100 examples. Then it embeds with the active profile (legacy: `embedder`; others: `profileEmbedder`) and calls `rag_scope_example_add`. An embedding failure or a wrong dims count returns `embedding_unavailable` and stores nothing. SQL refusals map 23505 → `example_exists`, 54000 → `limit` and 22001 → `text_too_long`. Add and delete invalidate only that tenant; deleting another tenant's id returns `not_found`.
- **Status and rebuild.** `scopeGateStatus` returns per-kind group counts, chunks included, newest update, the example count, `rebuildRunning`, `unsupported`, and `npm run rag:scope-centroids -- --tenant <key>`. `startScopeRebuild(scope, { waitMs = 2000 })` answers `done` with counts, `started` when the rebuild outlasts the wait, `running` while an admin-started rebuild for the tenant is in flight, and `failed` with a code.
- **Hook.** `scope_centroids` is registered in `syncBuiltInHooks` only while `queryAdditions.effective.scopeGate` is true (`RAG_SCOPE_GATE` with the query layer on). When it is off, the hook is unregistered and makes no SQL call. It turns the event's tenant key into a scope with `storeScopeForTenantKey`; a malformed key makes no call. It rebuilds for the active profile and does not re-embed examples. It races the rebuild against the abort signal, and an error or timeout is logged once per code. The publish always succeeds.
- **CLI.** `npm run rag:scope-centroids -- --tenant <key> [--profile <id>]`, with `--help` exiting 0. A missing or malformed tenant key, or an unknown profile, exits 2 with a usage line. Without `SUPABASE_SERVICE_ROLE_KEY` it exits 1. It rebuilds, re-embeds the tenant's examples into the profile and prints counts only.
- **Off state.** Everything is inert with the switches at their defaults: the hook is not registered, and no request path calls the loader yet (06.2-21 adds the stage). Strict refusal, webSearch, `source_images`, `{{context}}`, voice and embed are untouched.
- Logs carry counts and codes only; tests check that no example text appears in logs or snapshots (T-06.2-53).
