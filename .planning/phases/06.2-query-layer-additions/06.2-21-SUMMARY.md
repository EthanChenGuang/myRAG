## Behaviour

- **Scoring (D-26, D-38, P-04).** `scoreScope({ queryVectors, snapshot, cell, flags })` normalizes each query vector, takes the maximum dot product to the snapshot's unit centroids (`score`) and to its negative examples (`negative_score`). With a calibrated cell: score ≥ threshold → `in_scope` (`above_threshold`, scoring stops at the first query that reaches it); a negative example closer than every centroid → `out_of_scope` (`negative_closer`); score < threshold − margin → `out_of_scope` (`below_threshold`); otherwise `unsure` (`within_margin`). Everything else is `unsure`: `no_snapshot`, `no_centroids`, `no_query_vector` (none of matching dims), `translate_skipped`, `scoped_binding` (snapshot `unsupported`, P-13), `uncalibrated`; the score is still reported whenever it can be computed.
- **Kernel.** A plain JavaScript loop over 8 × 300 vectors at 2048 dimensions measured p50 5–10 ms, p99 6–17 ms on this host, above the 5 ms budget, so `maxDot` runs a 247-byte hand-assembled WebAssembly SIMD function (text format in the file comment); it is checked against `maxDotJs` (dims 4, 7, 1536) and falls back to it if WebAssembly SIMD is unavailable. The last reference list stays resident in the module memory. Benchmark (score.test.ts, 8 queries × 200 centroids + 100 examples at 2048 dims, 300 runs, no early exit): p99 about 2.2–3.5 ms here. The 06.2-18 centroid cap (200) was not lowered.
- **Calibration (D-27, P-36).** `eval/config/scope-gate.json` is the empty `ScopeGateCalibration` written by the eval tooling's `write_config_atomically` (`_stable_json`), from this one-off command (run from `eval/`):
  `uv run --frozen python /tmp/write_scope.py` with
  `write_config_atomically(Path("config/scope-gate.json"), ScopeGateCalibration(recorded_at=datetime(2026, 11, 27, tzinfo=timezone.utc), source="fixture", cells=[]))`.
  `scopeGateCalibrationFor(profileId, ragMode)` returns `{threshold, margin}` only for a `calibrated` cell of that profile and mode; null for bypass, a missing or uncalibrated cell or an invalid file (one `[Scope Gate]` warning). With the committed file the gate is score-only everywhere until 06.2-26 writes cells.
- **Stage (D-26).** In `runV2Pipeline`, right after the `embed` stage and before translation planning and search, only when `scopeGateEnabledFor(config, profile)` (switch effective, not voice) and the stage is enabled for the request: `runStage(spec('scope_gate', 'skip'))` calls `runScopeGateStage` with the request scope, the embedding profile id (`embedding.profile?.id ?? LEGACY_PROFILE.id`), the request RAG mode, the variants and the variant embeddings the embed stage made (HyDE excluded), and the query plan (translate in `gate.transforms` and in `skipped` → `translate_skipped`). No LLM call, no I/O (`getCentroidSnapshot` never awaits). The stage record's detail is the label. A throw or timeout gives `scopeGateFailOpen` (`unsure`, reason `failed`/`timeout`) and one `[Scope Gate]` log line per reason.
- **Short-circuit.** Only `out_of_scope` returns `buildOutOfScopeResult`: status `empty`, reason `out_of_scope`, `skipReason: 'out_of_scope'`, `refusalCandidate: true`, empty context, `scopeGate` set, query plan kept. Strict chat then takes the existing "information not available" path (the chat route's empty-status rule), webSearch strict calls Exa as before. `unsure` and `in_scope` continue unchanged and carry `scopeGate` on the result.
- **Soft status.** `statusRecords` always drops `scope_gate`, so a gate failure never makes the result degraded.
- **Cache (T-06.2-61).** The ticket from the `semantic_cache` check stays on the out_of_scope result (the trace still reads `miss`), with `turn.skipReason = 'out_of_scope'`; `storeRules` returns the new store-only bypass `out_of_scope`, so chat, embed and eval never store such a turn. No caller change was needed.
- **Eval route (D-29).** The trace carries `scope_gate`, `searches_counted` and `speculative` from the result, each only when present; `refusalReasonOf` returns `out_of_scope` for that result, and `refused` is true through `refusalCandidate`.
- **Off state.** With `RAG_SCOPE_GATE` off (default) or in voice, no `scope_gate` record is written, the snapshot is never read and the result is deep-equal to a run where the gate says `in_scope` (stage.test.ts). Strict refusal, webSearch with Exa, `source_images`, `{{context}}`, voice and embed are untouched. Logs carry labels, reasons and counts only, never query text.
