# 06.2-29 SUMMARY: rule router for Auto, citation-session final model, eval support

## What was built

- **Router** (`src/lib/rag/generation/model-router.ts`). Pure functions with no LLM call. The imports are type-only contracts, `../config` (defaults) and `../query/rewrite-gate` (the R11 length test). A test checks that it imports nothing from retrieval, search, embedding, pipeline, backend, rerank, Supabase or `@/lib/rag`.
  - `resolveRequestedModel(requested, routing, fallback?)` (D-19):
    - An explicit id stays.
    - `auto` resolves to the quality id. It is `routable` only with `RAG_MODEL_ROUTING=auto`.
    - An empty request takes the fallback.
    - It never returns `auto`. A configured `auto` id falls back to the D-35 quality default.
  - `routeModel(input)` (D-20) sends a turn to the fast tier with rule `simple_lookup` only when all of these hold:
    - the classifier says `document_search`;
    - none of R3, R5, R6 or R8 fired (read from the gate result, else from `plan.gate.reasons`);
    - there are no sub-questions and no `sub_question` variant;
    - there is no `translated` variant;
    - `isLongQuery` is false;
    - the context has fewer than `routing_fast_max_context_tokens` tokens.

    Any other turn gets the quality tier with one of these rule ids: `no_classification`, `not_document_search`, `gate_comparison`, `gate_elliptical`, `gate_compound`, `gate_language_mismatch`, `decomposed`, `translated`, `long_query`, `large_context` or `invalid_routing_id`.
  - `initialModelRoute` gives the trace for a turn that was not routed: `explicit_choice`, `routing_off`, or `not_generated` (a routable turn that generated nothing).
- **Citation session** (P-30).
  - `routingCandidates` turns the labeler on before retrieval when either routing id would turn it on.
  - `setFinalModel(id)` works only before `attach`. It refuses `auto` or an empty id, and it throws after `attach`.
  - After that call, `attach` (`selectCitationStrategy`) and `startClaude` (`anthropicIdFor`) use the final model. So a routed Claude fast model takes the GEN-01 Citations path with its own Anthropic id.
- **Eval route.**
  - `options.selected_model` is resolved once at the top. With it present it takes precedence over `generator_model`.
  - A routable turn gives the session both candidates. Its cache key part is `auto|<fast>|<quality>` (research F-8: the routed model is unknown at check time).
  - On a generated turn, routing runs after retrieval and before `attach`: context tokens come from `countTokens(result.context)` and the params from `effectiveQueryParams('eval', options.query_params)`. The routed id then serves the tool capability, the output cap, the budget reserve and generation.
  - The trace records `model_route`. `effective_config.generator_model` keeps the resolved (pre-routing) id, so it stays the same across a run.
  - A `[Model Routing]` log line carries the tier and the rule only.
  - Without `selected_model` nothing changes.
- **Delay table.**
  - `eval/fixtures/generator-delays.json` gives the two D-35 ids a delay: fast 40 ms, quality 160 ms. Every other model gets 0.
  - `withGeneratorDelays` wraps the stub and fake generator factories in `run-eval.mts` with AI SDK middleware (`wrapGenerate` / `wrapStream`) and keeps the factories' `canUseTools` / `maxOutputTokens` hooks. A model with delay 0 is returned unwrapped, so every current fixture run is unchanged.
  - The live generator is not wrapped.

## Finding (for the owner and 06.2-30 / 06.2-35)

**With `NEXT_PUBLIC_MCP_SYSTEM_ENABLED` not `true` (the default), `classifyQuery` returns `conversational` for every query.** It returns early on "MCP System is DISABLED". With MCP on, `document_search` matches only `what…about|tell me about|explain…about` and price or plan words.

So the fast tier as D-20 defines it almost never fires on a default deployment, and Auto then behaves like the quality model. I implemented D-20 literally; the plan truth says "only when the classifier says document_search". The route test turns MCP on to reach the fast path.

Recommendation for the owner: change the rule in a follow-up plan before 06.2-30 measures eligibility. One option is to accept `conversational` when retrieval returned context, or to drop the classifier condition. Whichever is chosen, keep the off state unchanged.
