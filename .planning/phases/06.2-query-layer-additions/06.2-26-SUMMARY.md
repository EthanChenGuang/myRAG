## Task 2: the calibrate scope subcommand

`eval/src/rag_eval/calibrate/scope.py`, registered as `scope` in `calibrate/__main__.py`:

- Rows: one per golden item, from the run's `traces.jsonl` and `run.json`. These are left out and counted: unknown items, duplicate traces, split mismatches and `no_scope_score`.
- Per mode: `fit_threshold` on dev, with the target `targets_by_mode[mode].target_false_refusal` or else the single target. The cut `threshold - margin` is checked with `holdout_check` for margin = k × 0.005, k = 0..40, and the first passing margin wins. A dev set below the minimums, a fit that refuses nothing, too little test data or no passing margin all give an uncalibrated cell, with its rates at margin 0.
- Ship gate:
  - A `fixture-ngram` run writes `source: fixture`.
  - A real-embedder run needs `--source live`.
  - `--source live` needs `--separation-report` naming a non-`fixture-ngram` report that has a D-34 verdict. It is refused on a fixture run.
  - `--profile` must equal the scored run's profile.
  - Every refusal writes nothing and exits 2.
- Output is validated by `ScopeGateCalibration` and written atomically as stable JSON. `recorded_at` is the run's `created_at`, unless the cells are unchanged; then the file's own value is kept (`40dd1b6e`).

## Deviations

1. **[Rule 2, security] Runtime guard: fixture scope calibration is eval-only** (`193cffdb` RED, `cb2aa617`). The fixture eval scores under `openai-3-small-1536`, the same id production uses. Without the guard, the committed fixture cells would refuse real chat and embed questions as soon as `RAG_SCOPE_GATE` is turned on. `scopeGateCalibrationFor(profile, mode, { evalRun })` returns null for a `source: fixture` file unless `evalRun`; the pipeline passes `profile === 'eval'`. This is the same rule as the refusal gate's `cell_fixture_only`. RED: 2 assertions failed (score.test.ts, stage.test.ts). Existing stage and score tests that use calibrated cells on chat requests now use `source: live`. The e2e test that read "the committed empty calibration" now sets an empty one explicitly.
2. **[Rule 3, blocking] The harness builds scope centroids** (`1cc2dac1`). The first score-only run traced `no_centroids` for 447 items, because no fixture build wrote centroids. With `RAG_SCOPE_GATE` effective under v2, `eval/harness/scope-gate-fixture.mts` runs `rebuildScopeCentroids` on the home, q62 and dominant-language databases, and primes the snapshot before each request. The isolated tenants share the tenant key `single`, so a cached snapshot would otherwise score the wrong database. Nothing changes with the switch off: both fixture modes gave paired differences all zero.
3. **recorded_at kept for unchanged cells** (`40dd1b6e`). The pre-registration said `recorded_at` is the run's `created_at`. That would make the plan's drift check fail on every fresh run, so the file's own timestamp is kept when source and cells are unchanged. It is an output-format detail; no gate criterion changed.
4. Precondition path: the route A report sits in its own subdirectory (`openai-3-small-1536/`), as 06.2-42 recorded.
