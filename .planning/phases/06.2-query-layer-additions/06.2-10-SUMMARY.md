# Plan 06.2-10 Summary: query-language confidence and fallback chain

Under the query layer, the query language is now resolved among the enabled languages before the rewrite gate. The result carries a confidence and the chain step that chose it, and it is traced on `QueryPlan.language_detection`. With the layer off nothing of this loads.

## Task 2: resolver, gate and run-layer wiring, LLM-reported override, case file
- `resolveQueryLanguage({ text, enabled, primary, previousTurnLanguage, uiLanguage, profile, params, signal, sidecar })`:
  - With one enabled language, the result is `single_language`, confidence 1, and the detector is not called.
  - Otherwise the detector runs on the *prose* of the query, which is the text minus code tokens (identifiers, paths, numbers).
  - A detection is low confidence when any of these hold: it is not confident; the text mixes Han and Latin with neither at 70% or more; it has three words or fewer (not applied to Han-dominant text); more than half its tokens are code (judged on the full text); or its confidence is below `language_confidence_threshold`.
  - For a low-confidence query the chain runs in order: sidecar (Task 3), previous turn, UI language, primary. A hint counts only when its primary subtag is enabled.
- Gate: `GateContext.language` is optional; when present it replaces `detectGateLanguage`. The gate stays pure and synchronous, and the bench test still passes.
- run-layer:
  - The resolver is called before `needsRewrite`, and only when the language variables are set and the settings are configured. Otherwise the gate keeps its own detector, exactly as before.
  - The detection goes on the plan, including the small-talk plan.
- LLM-reported language:
  - `finishCondense` exposes `reportedLanguage` (from `CondensedQuery.language`). `finishTranslate` exposes `sourceLanguage` (the first valid `QueryTranslation.source_language`), and the query-layer translator forwards it through `onSourceLanguage`.
  - A condense report naming an enabled language sets the translation source and targets.
  - The condense report, or failing that the translate report, sets `plan.language`, which is the answer-language input read by `answerLanguageOptions`. `language_detection` then becomes `{ source: 'llm', confidence: 1 }`.
  - The gate's decision (`plan.gate.lang`, the transforms) and the semantic-cache key (`gate.lang`) are untouched.
  - Both fields are added only when set, so result shapes are unchanged when nothing is reported. The LangChain adapter goes through the same finishers, so it needed no edit.
- Case file: 30 lines, each with the fields `id, kind, text, enabled, primary, previous_language, ui_language, expected_language, expected_source`.
  - For each of zh, en and it there are 3 short, 3 accent-free and 3 mixed-script cases. For zh, "accent-free" means romanized text without tone marks.
  - Three extra cases cover the hints: a single enabled language, a UI language that is not enabled, and a previous turn that is not enabled.
  - Every case resolves to its expected language and source in `tests/rag/lang/detect-cases.test.ts` (the vitest unit tier, P-31).

## Task 3: never-throw langid client and chain step 1
- `requestLanguageId(text, candidates, { timeoutMs, signal, url?, secret?, fetch? })` follows the groundedness-client pattern:
  - It sends `x-sidecar-secret` and a `LangidRequestSchema`-validated body: the text capped at 1000 code points, plus the enabled candidates.
  - Its own timeout is combined with the request signal through `AbortSignal.any`.
  - It returns null for: a missing URL or secret (no request is sent), an aborted request, a timeout, an HTTP error, a body that fails `LangidResponseSchema`, or a language that is null or outside the candidates.
  - It logs one `[Langid]` line on failure, with status and latency only; success logs nothing.
- Chain step 1 runs only when all of these hold: the effective `RAG_LANGID_SIDECAR` is on, `langidConfigured()` is true, the profile is chat, embed or eval (never voice), and the detection is low confidence. It uses `langid_timeout_ms` (30) from the params file.

## Behaviour changes (query layer on only)
- Low-confidence queries now take the chain's language instead of the gate detector's guess. With no hints this means `RAG_PRIMARY_LANGUAGE`. For example, a two-word Latin query with one Italian stopword now resolves to the primary language unless the previous turn or UI language says otherwise.
- Confident queries keep the gate detector's language. Every confident case in the tests agrees with `detectGateLanguage`.
- With the layer off, or with the language variables unset, nothing changes: `parity-off.test.ts` asserts the resolver module is never loaded.

## Decisions for STATE
- The LLM-reported language takes precedence: condense first, then translate. It sets `plan.language` (the answer-language input) and the translation targets. `plan.gate.lang` and the cache key stay with the resolved detection.

- Mixed-script threshold 0.7 and the code-dominated share of 0.5 are code constants in `resolve-query-language.ts`; the confidence threshold stays in `eval/config/query-params.json` (0.6).
