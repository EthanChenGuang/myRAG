# 06.2-43 SUMMARY: D-20 revision 1 (the fast tier on a default deployment)

## What was built
- `routeModel` (`src/lib/rag/generation/model-router.ts`) now replaces only the classifier test:
  - `document_search` continues as before;
  - `conversational` continues only when `retrievalHit === true`, and otherwise returns quality `conversational_no_hit`;
  - every other category returns `not_document_search`, as before.
- The guards after the classifier test are shared and keep their order and rule ids: R3/R5/R6/R8, `decomposed`, `translated`, `long_query` (`isLongQuery`, unchanged) and `large_context`.
- The final fast result names `conversational_lookup` or `simple_lookup` by category.
- `invalid_routing_id` and `no_classification` still come first.
- The module stays pure; the import-purity test passes.
- `retrievalHit` is computed by each route from the retrieval result, never from the request (T-06.2-104):
  - chat: `knowledgeContextAttached && retrievalResult.kept.length > 0 && context.trim().length > 0`
  - embed: `!smallTalkTurn && result.kept.length > 0 && context.trim().length > 0`
  - eval: `result.kept.length > 0 && result.context.trim().length > 0` (the eval route has no small-talk flag)
- Nothing else in the routes changed: the routing position, the cache key part `auto|<fast>|<quality>`, `setFinalModel` before `attach`, the `model_route` stage attributes and the `[Model Routing]` log line (tier and rule only).
- `RAG_MODEL_ROUTING` off or an explicit model: `routeModel` is not called, so behaviour is byte-identical. No env variable, config key, params key or contract field was added. Voice, WhatsApp and the approve route were not touched.
