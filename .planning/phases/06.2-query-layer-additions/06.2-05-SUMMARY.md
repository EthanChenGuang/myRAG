## native_review rule (Task 1 record)

03.2-31 marks an item whose drafted native review is not approved with `report_only_reason`; `counts_in_gated_slices` then keeps it out of `aggregate`'s gated members (`counting`) and out of `report_gate_items`, which feeds the paired report. The new metrics are computed inside `_slice` on those same members and paired through the same `paired_report` loop, so they follow the rule without extra code. `by_language_category` stays the ungated report-only grouping it was.

## Behaviour changes

- None for today's golden set: no item has sub_questions, so no ItemResult, SliceMetrics, paired cell, baseline cell, gate entry or report column changes. Verified: smoke default mode on this branch versus the base commit (origin/exec/06.2-01) gives identical gate.json and gate.md, and report.json differs only in run_id and stage latency timings.
- Once items carry sub_questions (06.2-22, 06.2-31): reports show the four metrics; gate lists them as not gated until the baseline is re-recorded, then gates them on overall, language:*, category:scoped_compound and category:version_compare (other category slices stay report-only).
- `ship_check` now tolerates per-item metrics that an item does not carry (needed once noise.json names the new metrics; before, it would raise KeyError).

## Deviations

1. **Files beyond files_modified:** gating against the noise band lives in `gate.py` (evaluate_gate, _category_rows) and baselines are recorded in `baseline.py`; both had to learn the new metrics for the plan's truths (gate output lists, 06.2-22 re-record). `ship_check.py` (`.get` lookup) and `defaults_gate.py` + `tests/test_defaults_gate.py` (equality check minus SUBQ_METRICS) were needed because they read the committed noise.json and would otherwise crash or turn stale.
