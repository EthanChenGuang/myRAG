## Behaviour changes

- Query layer off (default): none. runRetrieval gets no new keys, no language setting is read, the stream carries no `rag`, metadata and `language` in request bodies are ignored.
- Query layer on: finish metadata (or the strict-refusal / kb-unavailable start metadata, or the cache-hit finish metadata) carries `rag` from `queryPlan.standalone` (fallback `original`), capped at 1000 characters, language from `queryPlan.language`.
- Query layer on: the previous user message's `metadata.rag` is parsed with the generated strict `RagTurnMetadataSchema` (safeParse); valid values reach runRetrieval as `previousStandaloneQuery` / `previousTurnLanguage` (language only if enabled). Chat `settings.language` and embed body `language` reach runRetrieval as `uiLanguage` only if enabled. Invalid values are dropped, never a 400.
- Client: stored chats keep `rag` on the turn's user message (moved off the assistant message); older messages without it load, save and send exactly as before.
- Embed window sends the primary subtag of `navigator.language` as `language` (server ignores it with the layer off).

## Decisions

- The three turn inputs are passed only while `isQueryLayerEnabled()`: their only consumers are query-layer stages, and this keeps the layer-off runRetrieval input and the D-02 "legacy reads no language setting" rule intact.
- `rag` is added on refusal and cache-hit paths too (only with a plan), so a refused turn still gives the next turn its standalone query.
- Server helpers live in `src/lib/rag/query/turn-metadata.ts` and are exported from `@/lib/rag` (the boundary check forbids deep imports of `lang/settings` from routes).
- Turn rag precedence on the client: the answer's streamed value wins over a value already stored on the user message.
- The embed window validates `rag` with a small shape check instead of importing the 464 KB generated contracts into the embed bundle; the server re-validates with the generated schema.
- Logging: one `[Query Layer] Previous turn metadata` line with presence, validity and length only, and only when metadata was sent.
