**How inputs are found**
- Relative paths resolve against the working directory first, then the repo root, so `../eval/out/q62-*` works from `eval/`.
- The arm key is the directory name without the `q62-` prefix.
- A directory that holds `whatsapp-report.json` and no `report.json` is the WhatsApp input.
- Directories matching `(^|-)defaults(-ingest)?$` are the defaults parity runs (letter a), for example `q62-30-defaults` and `q62-30-defaults-ingest`.
- Any other directory is listed under `ignored_runs`.

**Test results.** `--tests` takes the vitest JSON reporter output (`npx vitest run <files> --reporter=json --outputFile=<path>`). The letters read these files:

| Letter | Test files |
|---|---|
| c | `tests/rag/query/glossary-translate.test.ts`, `tests/rag/query/glossary-rewrite.test.ts`, `tests/rag/ingest-translate-glossary.test.ts` |
| d | `tests/rag/lang/detect-cases.test.ts`, `tests/rag/lang/resolve-query-language.test.ts`, plus the case file `eval/fixtures/lang-detect/cases.jsonl` (count and sha256) |
| f | `tests/rag/query/speculative.test.ts`, `tests/rag/model-router.test.ts` |
| g | `tests/rag/query/history-fallback.test.ts`, `tests/whatsapp/history.test.ts` |
| h | `tests/rag/scope/stage.test.ts` |

A file that is missing or failing fails its letter, and the evidence names the file.

## Rules as implemented

**Slices.** Values are computed from the report's gated items (`report_gate_items`) for overall, language, category and `pair:` slices, using `paired.item_metrics`. Sub-question coverage is pooled over sub-questions.

**Noise band.** `max(k * spread, floor)`. The reference is a single run (spread 0), so the band is the floor (0.02).
- A regression is a metric worse than the reference beyond the band, named `slice:metric`.
- An improvement is a metric strictly better than the reference.

**Switch entries**

| Switch | Arm vs reference | Eligible when |
|---|---|---|
| `RAG_QUERY_DECOMPOSE` | decompose vs single-pass | Sub-question rule (below) |
| `RAG_QUERY_DECOMPOSE_COMPLETENESS` | completeness vs decompose | Sub-question rule |
| `RAG_QUERY_SUBQ_FILTERS` | subq-filters vs completeness | Sub-question rule |
| `RAG_TRANSLATION_GLOSSARY` | glossary vs single-pass | No regression and the letter-c tests pass |
| `RAG_SPECULATIVE_RETRIEVAL` | speculative vs single-pass | All-turns pre-retrieval p95 strictly lower and no regression |
| `RAG_MODEL_ROUTING` | routing vs single-pass | Generation p95 strictly lower, no regression, and both refusal rates within the band in both directions on overall, every language and every category slice |
| `RAG_SCOPE_GATE` | scope-gate vs single-pass | Overall correct-refusal rate up, no false-refusal regression on any slice, and letter a passed (off equals baseline) |
| `RAG_QUERY_VOICE_TRANSFORMS:translate` | voice-translate vs voice-no-translate | Voice rule (below) |

- **Sub-question rule:**
  - `category:scoped_compound` must be measured in both arms, and `category:version_compare` must also improve once both arms measure it.
  - Each target improves on both families: all-evidence recall @5/@10 and sub-question coverage @5/@10. Within a family, at least one k is better and none is worse.
  - No slice regresses.
- **Routing note:** answer correctness is a live judge run, and the switch's notes say so.
- **Voice rule:**
  - `category:cross_lingual` improves on recall@5, recall@10 or MRR, with none of them worse.
  - No regression on any slice, which includes every pair.
  - The candidate's query-stage p95 is within the voice query budget (300 ms from `eval/config/latency-budgets.json`).
  - Improved pairs go to `improved_slices`, the per-pair table goes to `voice_pairs`, and the p95 goes to the notes.
- **Missing arm:** the switch is ineligible, and the note names the missing arm.

**Pre-retrieval time (D-37, P-09).** The trace has no wall-clock "end of fuse", so the tool derives it:
- the sum of `access_scope`, `query_gate`, `condense`, `terminology`, `semantic_cache`, `embed`, `scope_gate`, `search` and `fuse`,
- plus the slowest member of the parallel group (`normalize_dates`, `expand`, `hyde`, `decompose`, `translate`),
- minus `speculative.overlap_ms`.

A turn without `fuse` is excluded. The report shows all turns plus the new-variant and no-new-variant splits; a turn counts as new-variant when its plan has a variant whose kind is not `original`. If 06.2-24 adds a direct measurement to the trace, `pre_retrieval_ms` is the one place to read it.

**D-31 checklist (all nine letters)**

| Letter | Passes when |
|---|---|
| a | Every defaults run has gate passed and paired all_zero |
| b | Completeness vs single-pass passes the sub-question rule |
| c | The glossary entry is eligible and the c tests pass |
| d | The case file is present and the d tests pass |
| e | Both voice arms are present with pair slices and passed gates |
| f | The speculative arm traces `speculative`, the routing arm traces `model_route`, and the f tests pass |
| g | The WhatsApp report passed and the g tests pass |
| h | Unanswerable items are refused with `out_of_scope`, the scope-gate p95 is within the chat `scope_gate` budget (5 ms), there is no false-refusal regression, letter a passed, and the h test passes |
| i | Always passes: the record was written by the tool |

**LANG-08 slice (P-21).** Per arm, traces whose `query_plan.language_detection.source` is not `detector` or `single_language` are grouped as `language_source:<source>`, with the item count, recall@5 and false-refusal rate. This slice is report-only.

**Writing the outputs**
- `<out>/report.json` and `<out>/report.md` use stable JSON with `sort_keys`.
- The decision record uses `report_hash` = sha256 of `report.json`.
- `recorded_at` is taken from `--recorded-at`. Otherwise it is kept from an equal previous record, else it is the current time. Two runs therefore write identical files.

**`--check`**
- `eval/out/` is gitignored, so `report.json` carries every arm summary (slice values, latencies, counts) together with the input paths and sha256s.
- `--check` re-derives the switches and checklist from those summaries and compares both the report and the decision record. A hand edit exits 1.
- When the raw run files are still present, it also flags inputs whose sha256 changed.
