## Behaviour

- **Eval route voice entry (D-16, P-26, T-06.2-73).** With `options.entry_profile: "voice"`, `/api/internal/rag/run` calls `runRetrieval` with profile `voice`.
  - The scope comes from the eval scope check. The route never reads a voice token from the request.
  - The route still needs the eval secret and stays disabled in production unless enabled.
  - Only `max_results` is passed through, as `maxResults`.
  - Eval-only options do not apply under the voice entry: overrides, disabled stages, query-layer overrides, filters, semantic cache, citations and answer generation. `stageOverrides`, `retrievalFilters`, `cacheContext` and `citationLabeler` are all absent, and the trace answer is `null`.
  - The trace's `kept` holds `result.voice.results` in rank order. `document_name` is the first of `metadata.document_title`, `filename`, `name`, or else the document id. `kept_by` is `rerank` when the result has a rerank score, otherwise `similarity`.
  - `used_documents` lists each voice document once. `context` is the tagged voice context, or else the untagged voice context.
  - Stage latencies come from the voice-profile collector, so the real voice timeouts apply (translate 250 ms under the layer). The eval profile's 60 s timeouts do not.
  - A missing query context gets `defaultQueryContext()`.
  - An empty voice result is traced as `refused`. A retrieval `error` answers 500.
  - With `entry_profile` set to `eval` or left out, the route behaves exactly as before.
- **Fixture floor for the eval voice call.** The fixture-fitted score calibration set by the harness applied only to profile `eval`. Under `voice` the production floor (0.65) refused 290 of 356 fixture items, and recall@5 was 0.186 with every pair at 0.
  - `RunRetrievalInput.evalEntry` is set only by the eval route's voice entry. When it is set, `evalFloorCalibration('voice', { evalEntry: true })` returns that calibration.
  - Chat, embed and media never read the calibration, and neither does the real voice route.
  - Outside the harness the calibration is null, so production voice is unchanged.
  - After the fix the voice arm scores recall@5 0.862, and its per-pair values equal the text baseline.
- **Router and timeout (Task 2 behaviour).** No change was needed. Voice translate runs only when listed, with the 250 ms timeout. A scripted 400 ms translate is skipped with reason `timeout` at 250 ms, and the original query is still searched. Unlisted, translate never calls the model. The default list stays `condense_history,normalize_dates`.
- **Run configs and harness.**
  - The run-config top-level key `entry_profile` accepts `eval` or `voice`. Only `voice` is recorded, as `entryProfile`.
  - The harness sends `entry_profile: "voice"` on every request and records it in the manifest's `request_options`, so it also enters `run_config_hash`.
  - A voice entry run is retrieval-only. The in-process default answers are dropped. An explicit `--answers`, citations, groundedness, cache pairs or a run-config `generator_model` is refused.
  - `run-smoke` gates a voice entry run against `eval/baselines/fixture-voice-baseline.json`, using the same noise band and the same `pair:` slices. A prechunked text baseline cannot be compared, because `request_options` differ. In ingest mode or with `--base-url`, a voice run skips the relative gate unless `--baseline` is given.
- **Two arms (D-16).** `q62-voice-no-translate.json` and `q62-voice-translate.json` set `RAG_PIPELINE=v2` and `RAG_QUERY_LAYER=true`. They differ only in `RAG_QUERY_VOICE_TRANSFORMS` (`condense_history,normalize_dates` versus the same list plus `translate`).
- **Real voice-rag route per pair.** `tests/rag/voice-rag-cross-lingual.test.ts` runs on the in-process fixture with a scope token signed with a placeholder secret. It runs under today's voice default (legacy pipeline). One cross_lingual item per pair returns its gold document: `en->it` xl-en-it-01, `en->zh` xl-en-zh-01, `it->en` xl-it-en-01, `it->zh` xl-it-zh-01, `zh->en` xl-zh-en-01, `zh->it` xl-zh-it-02. Without a token the route answers 401.
