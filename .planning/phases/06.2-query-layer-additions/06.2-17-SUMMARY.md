# 06.2-17 Summary: glossary enforcement in rewriting and document translation

With `RAG_TRANSLATION_GLOSSARY` effective (raw switch on, `RAG_QUERY_LAYER=true`, `RAG_PIPELINE=v2`), glossary source terms found in a query
survive condense, expand and decompose verbatim in both frameworks, and document translations carry the tenant's required target terms,
are corrected once, or are not stored. With the switch off nothing here runs: no glossary read, the same prompts, post-check results and
stored translations as before.

## Task 1: seam check (D-01)

All depends_on SUMMARYs are on the branch (06.2-14, 03.2-48, 03.2-49, 06-15, 06-35, 06-37). Seams found:

| Seam | State |
|------|-------|
| `glossaryFor(scope: { tenantKey }, source, target): Promise<Glossary>` | stub returning `{ version: 'none', terms: [] }` |
| Where produce.ts stores a translation | `flush()` → `rag_write_chunk_translations` (rows carry `glossary_version`); failures → `rag_record_translation_gaps` |
| Job counters | `TranslationRunSummary { translated, gaps, remaining, stopped, byLanguage }`; the translate job callback writes `{ translated, gaps, remaining }` as stage state |

## Task 2: rewriting (commits 622a983e RED, c9d3856e GREEN)

- `glossarySourceSurfaces(text, lang, glossary)` returns the source surfaces present in the text, as written there, for every target
  language of the pairs whose source is the query language (the 06.2-14 matcher rules, mapped back through the normalization offsets).
- The post-checks take an optional `glossaryProtected` list, checked with `keepsProtectedTokens` after the gate's tokens. For
  sub-questions it is a union check (the kept list together keeps every term), not a per-question one, so a comparison still splits.
  HyDE keeps skipping the check (A-10); translate never gets the list (06.2-14 enforces translation).
- `CondenseInput`, `ExpandInput` and `DecomposeInput` (and the finisher Picks) carry `glossaryProtected`; LangChain passes its input to
  the shared finishers, so both frameworks discard the same way. The list is never sent to the model.
- run-layer reads the tenant glossary once per request (request signal, 4.1.1 loader cache) only when the switch is effective and a scope
  exists, and shares that read with translate. `onGlossary` reports the loaded version for the hash. `gate.protectedTokens` is unchanged,
  so `checkBypassReason` is unchanged and a glossary-only query stays cacheable.

## Task 3: document translation (commits 3cef537a, 0f7f5f44 RED, a15af121 GREEN)

- `glossaryFor` with the switch effective: the tenant's TERM translation pairs for that direction (`pairs`), the prompt `terms` (one per
  source surface) and the TERM effective version as `glossary_version`. The scope is minted from the stored tenant key
  (`scopeForStoredTenantKey`); the SQL guard in `rag_term_effective` checks the deployment mode. A dictionary that cannot be read throws
  `GlossaryUnavailable`; the producer then stops the run (`glossary_unavailable`, the job retries) instead of translating unenforced.
- Producer, per chunk: the prompt lists only the pairs the chunk needs; after the translation, `enforceGlossary` → stored as is (`ok`),
  stored corrected (`corrected`) or not stored (`lost`) and recorded as gap `glossary_term_lost`, counted as `glossaryRejected` on the run
  summary and `glossary_rejected` on the job stage state. Logs carry counts only, never terms or chunk text.
- Two tenants: each job reads only its own tenant's pairs (unit test and PGlite two-tenant test).

## Behaviour changes (switch effective only)

- A condense, expand or decompose output that drops a glossary term in the query is discarded (`protected_token_lost`); the original is
  still retrieved.
- The glossary is read for rewrites too, not only when translate has targets, so the hash's glossary block carries the loaded version
  more often (switch on only).
- Document translations: glossary-aware prompt, `glossary_version` = TERM version, corrected or rejected chunks, a new stop reason.

## Decisions for STATE

- Glossary terms stay a separate `glossaryProtected` list in the post-checks, never in `gate.protectedTokens` (P-16); sub-questions use a
  union check.
- Document translation reads the switch from the same query-layer config (effective needs `RAG_QUERY_LAYER=true` and `RAG_PIPELINE=v2`).
- A lost glossary term in document translation is a gap `glossary_term_lost`; a glossary read failure stops the run, never translates
  unenforced.
