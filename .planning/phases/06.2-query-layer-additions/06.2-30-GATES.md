## Arms (measurement; not a pass/fail gate on their own)

Each arm: `npm run test-rag -- --run-config eval/config/runs/q62-<arm>.json --out eval/out/q62-<arm>` (prechunked fixture mode), arms `single-pass`, `decompose`, `completeness`, `subq-filters`, `glossary`, `scope-gate`, `speculative`, `routing`. Voice arms: `--run-config eval/config/runs/q62-voice-no-translate.json --out eval/out/q62-voice-no-translate` and the same for `q62-voice-translate`. WhatsApp: `node --import tsx eval/harness/whatsapp-entry.mts --run-config eval/config/runs/q62-whatsapp-multi-turn.json --out eval/out/q62-whatsapp-multi-turn`.

An arm's own relative-gate exit code is recorded, not acted on: the arms change retrieval by design. Eligibility is decided only by `rag_eval.compare query-additions` with its committed rules (06.2-39 SUMMARY): sub-question rule, glossary, speculative (all-turns pre-retrieval p95 strictly lower, no slice beyond the noise floor 0.02), routing (generation p95 strictly lower, refusal rates within the band per language and category), scope gate (correct refusals up, no false-refusal regression, scope_gate p95 within 5 ms), voice translate (cross_lingual up, voice query p95 within 300 ms).

Pre-declared reporting rules:
- Routing: count of turns per `model_route.rule`; zero fast-tier turns means Auto is "not measured", never "no gain".
- Voice translate: count of items per pair (en->zh, it->zh) whose trace raised `R8_LANGUAGE_MISMATCH`; zero means "not measured". `RAG_QUERY_VOICE_TRANSFORMS` stays `condense_history,normalize_dates`.
- Scope gate: fixture evidence only; the fixture cells of `eval/config/scope-gate.json` apply to the fixture profile.
