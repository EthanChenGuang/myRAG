<objective>
Route Auto turns to a fast or a quality model by rule, after retrieval, without ever replacing a model the user chose, and make the effect measurable on fixtures.

Purpose: D-19 (Auto entry semantics, explicit choice never replaced, routing off resolves to quality) and D-20 (pure rule router after retrieval, inputs, trace, Citations path, eligibility measurement).

<assumption_delta_decision>
Primary noun: the requested model selection (an explicit model id or auto). Decision: promote — each route resolves the selection once at its top into a concrete model id, and every helper below reads only the resolved id; the raw request value is demoted to an input of resolveRequestedModel. Rationale: Auto turns a chosen model into a derived one; letting helpers read the raw value is how auto leaks to a provider. Invariant test: no code path after resolution sees the string auto.
</assumption_delta_decision>

Output: the router, a citation-session change, wiring in chat, embed and the eval route, a mock-generator delay table and three tests.

Rollout position: D-32 step 13 (LAT-06 routing). Cross-phase edges: 05-16 and 05.1-16 last edit strategy.ts and session.ts; 06-32 and 06-36 own the cache key and the last route edits. In-phase: 06.2-02 (Auto entry and IDs), 06.2-03 (params), 06.2-23 (last chat, embed and eval-route edits), 06.2-27, 06.2-12 and 06.2-22 (order of run-eval.mts edits).

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan.
</objective>
