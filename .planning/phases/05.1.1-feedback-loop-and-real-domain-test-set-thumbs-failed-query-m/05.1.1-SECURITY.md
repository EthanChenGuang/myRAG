## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser and embed widget to feedback routes | `/api/rag/retrieval/{traceId}/feedback|signal` (session), `/api/embed/feedback` (anonymous, signed token) | vote, reason codes, trace id; no free text |
| PostgREST (anon, authenticated) to `rag_retrieval_log` | must see nothing; service role is the only reader and writer | ids, scores, language codes, masked query (masked_query mode only) |
| Request path to the `after()` log task | the write must never affect the response | retrieval result, tenant key from the verified scope |
| Authenticated expert to `rag_review_items` | visibility decided by RLS (`rag_is_domain_expert`) plus the Phase 4.3 restrictive policy on `access_sets` | masked query, candidate ids, labels |
| Review routes to `document_chunks` with the admin client | must re-apply the item's tenant (and, with access groups on, the caller's document access) | chunk text, file names |
| Service-role mining and enqueue functions to the queue | copy rows across tables under one tenant | log rows, snapshot ids, access label sets |
| Operator and CI to private eval data | labelled cases leave the database only to `eval/golden/private/` | golden items, reports (ids, hashes, counts) |
| Config UI to `.env.local` | switches and one secret (`RAG_EMBED_FEEDBACK_SECRET`) | secret presence only |
