# Phase 5.1.1 Plan 14: Dictionary, training and golden exports with the leakage guard Summary

**An operator admin can now pull each tenant's labelled cases as dictionary candidates, training pairs and golden candidates, and record which were exported and their frozen splits. A document in the test split never becomes the positive of a train pair.**

## Accomplishments
- `GET /api/rag/admin/feedback-loop/export?kind=&tenant=`: `requireAdminOrDeny` first, 404 with `RAG_DOMAIN_EXPERT_REVIEW` off, 400 for an unknown kind, a missing or invalid tenant, a tenant of the other deployment mode, or an extra parameter, 503 when the admin client is missing or a read fails. Otherwise 200 `application/x-ndjson`, `Cache-Control: no-store`, `X-Export-Count`, one contract-valid line per item or term.
- `POST /api/rag/admin/feedback-loop/export/mark`: same guard and switch; strict body (1 to 500 unique ids, `split` dev|test only with `split_group`); 200 `{marked, conflicts, ignored}`, or 409 with the same body when the trigger refused a split change.
- Log lines: `[Feedback Loop] export {kind, tenant: <16-hex hash>, count, skipped}`, `[Review] chunks {export: 'golden', tenant hash, count}` for the golden re-read, `[Feedback Loop] export marked {tenant hash, counts}`. No text, query or tenant key is logged.
- `check-rag-boundary` stays green: the routes import only from `@/lib/rag`, and the exports read chunk text through the shared `fetchServableChunks`.

## Contract stated for Phase 6.1
`TrainingPair.hard_negatives[].confirmed` is `true` only when the domain expert marked that snapshot candidate not relevant (`ExpertLabel.not_relevant_chunk_ids`). Phase 6.1's "expert-rejected negatives first" rule (06.1 D-08) takes `confirmed: true` first. Confirmed negatives may rank below the positive; unconfirmed ones always rank above the lowest-ranked positive. Pairs with `split: held_out` must never be trained on. Chunk text is resolved by id under `tenant_key` at training time.
