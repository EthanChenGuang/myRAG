# Phase 5.1.1 Plan 13: Verified expert labels and tenant-scoped review search Summary

**Experts label a review item only with evidence that is really in their own tenant's current chunk text, and can search their tenant for evidence the retrieval missed. Nothing about the search is logged, traced or exported.**

## Accomplishments
- `POST /api/rag/review/items/{id}/label`: 404 with the switch off, 401 without a session, 400 for a schema violation (the D-18 rules included), 404 for an item RLS hides, 409 for an exported item, 400 with the span index and reason for evidence that fails, 200 otherwise. The write goes through the caller's SSR client, so the RLS update policy and the guard trigger decide. Log line `[Review] label {expert, item: <16-hex hash>, status, triage}`.
- `POST /api/rag/review/items/{id}/search {query}` (1..500 characters, strict body): reads the item through RLS, mints the scope from its stored `tenant_key` with `backfillScope`, runs `runRetrieval` (chat, flexible, maxResults 30, private trace, `logContext: { skip: true }`), re-reads the hits under that tenant and returns `{rank, chunk_id, document_id, document_name, section, text, score}`. Log line `[Review] search {expert, item hash, count}`, never the query.
- `check-rag-boundary` stays green: the search uses `runRetrieval` inside `@/lib/rag`, and routes import only from `@/lib/rag`.

## Deviations from Plan
1. **Files outside files_modified.** `tests/helpers/review-fixture.ts` (shared two-tenant seed), `tests/helpers/pglite-rest-client.ts` (`update(...).select()` with RETURNING, and `auth.admin.getUserById` for `backfillScope`), `src/lib/rag/index.ts` (exports, because routes may only import `@/lib/rag`) and `src/lib/rag/feedback-loop/review-access.ts` (the chunk read became `fetchServableChunks`, shared by plan 12's chunk route, the label check and the search; plan 12's tests pass unchanged).
2. **Normalisation removes whitespace and punctuation instead of collapsing whitespace.** The plan's must-have says "collapsed whitespace", but the same must-have and the task require the twin of `normalize_text`, which removes both. The fixture proves equality.
3. **The review search also passes a private trace collector.** `logContext: { skip: true }` is passed as planned; the extra collector stops the Langfuse export of the query (see key decisions).
4. **The Task 2 test changed after its RED commit**: it compared the minted scope with `scopeKey` from another module instance, which throws (scope tokens are registered per module instance). It now compares the scope's kind, user and organization.
5. **The normalize fixture generator was a one-off run with eval's `uv` environment**; the JSON records its source. No Python file was committed.
