# Phase 05.1.1 Plan 16: Embed answer rating — Summary

**Embed visitors can rate an answer with a thumb up or down, plus up to three reasons after thumb down. The control appears only when the server sent a feedback token for that answer, so with the defaults both embed surfaces stay exactly as they were.**

## Accomplishments

- `src/app/embed/chat.js/route.ts`: inside `sendMessage`, the `data:` branch reads `messageMetadata.feedbackToken` from the `start` event and keeps it in a local. When the answer is stored (non-empty text, no error branch), `attachRating(messageDiv, token)` appends the rating row to that answer's own message div, held by reference rather than by the reused ids. The thumbs are 32px icon buttons with `aria-label`, `title` and `aria-pressed` inside `role="group"`. The status text is `role="status"` / `aria-live="polite"`. Thumb down adds a legend and three toggle chips. Icons are lucide 0.471.2 path data built with `createElementNS`. One constant `<style>` element is appended inside `#myrag-widget-container`, and every selector starts with `#myrag-widget-container .myrag-fb`. Locale comes from `navigator.language` (zh, it, otherwise en).
- Votes: `POST {apiOrigin}/api/embed/feedback` with JSON `{token, vote, reasons}`, `credentials: 'omit'` and a 10-second abort. 200 shows the saved text. 404 removes the control for that answer. 429 and every other failure restore the earlier state and show the rate-limit or retry text. Selecting the chosen thumb again sends nothing.
- `src/app/embed/window/embed-rating.tsx`: `embedRatingToken`, `postEmbedRating`, `startEmbedVote` / `finishEmbedVote` (the same rules as the widget), `EmbedRatingView` (Tailwind gray palette and lucide icons, as in the UI-SPEC) and the stateful `EmbedRating`. `page.tsx` reads `message.metadata.feedbackToken` through `embedRatingToken`. Only an answer with a rating turns its row into `flex flex-col items-start`; every other row keeps its classes.
- `src/app/embed/embed-rating-strings.ts`: the UI-SPEC 12.3 table in en, zh and it, JSON-inlined into the widget script and imported by the window.

## Deviations

1. **Two new files.** `src/app/embed/window/embed-rating.tsx` holds the window control, because a Next.js `page.tsx` may export only the page. `src/app/embed/embed-rating-strings.ts` holds the shared copy. The UI-SPEC asks for a test that compares the widget and window tables; the test compares the table inlined in the served script with the module.
2. **Hover, tap highlight and touch targets (design review).** The chips get the same `#eee` / `bg-gray-200` hover as the thumbs, and both surfaces set `-webkit-tap-highlight-color: transparent`. Under `pointer: coarse` the thumbs become 44×44px and the chips at least 44px tall. Fine pointers keep the UI-SPEC's 32px.
3. **Focus return.** Disabling a focused button drops focus to the body, so after a vote the pressed control gets focus back. The UI-SPEC does not mention this.
