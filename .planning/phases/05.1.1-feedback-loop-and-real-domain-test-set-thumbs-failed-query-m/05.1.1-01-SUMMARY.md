# Phase 5.1.1 Plan 01: Feedback-loop contracts Summary

**One Pydantic definition, with generated Zod, for every shape in Phase 5.1.1: the retrieval log row, the feedback bodies, review items and expert labels, the Phase 4.1.1 and 6.1 hand-offs, mining, stats, weekly and failure reports, gate population and ship check. GoldSpan, the split manifest, review reasons and gate_population were extended without changing a committed byte.**

## Accomplishments
- `feedback_loop.py`: 22 registered models plus nested count models. Language fields go through one `LanguageCode` pattern type (D-03a). `ReviewItem.tags` follows the tag pattern and `reasons` may be empty. `document_id` is required on log candidates, review candidates and expert evidence spans (D-29).
- `ExpertLabel`: answerable needs expected_answer and evidence; not answerable forbids evidence; `golden` needs `pii_checked`; quotes need at least 2 characters; at most 20 spans and 50 not-relevant ids; triage values are closed; unknown fields are rejected.
- `TrainingPair`: no chunk-text field, at most 10 hard negatives, each with the `confirmed` description that Phase 6.1 reads. `DictionaryCandidate.canonical_language` is required for `translation`.
- `GoldSpan.document_id` is an optional UUID and is omitted from the dump when unset. Every committed golden fixture item dumps its spans unchanged.
- `GoldenSplitManifest` now accepts the docgroup rule with `group_assignments`. The item rule with group assignments is rejected, and existing manifests dump byte-identically.
- `ReviewQueueItem.reasons` accepts the five mining reasons. `gate_population` accepts `real` on reports and baselines.

## Deviations from Plan
1. **New helper file `contracts/omit.py`** (not in files_modified). It is the shared serializer and schema hook for keys that are omitted when unset. Without it, a `document_id: null` key would change committed golden bytes and would make Zod parses add the key.
2. **`tests/contracts.test.ts` extended** (not in files_modified). It now checks that each new model has a schema, a parser and a sample, along with code-only languages, tag patterns, feedback-body rejection and `real`.
3. **Extra nested models are not registered:** ScoreThresholds, MiningReasonCounts, MiningTenantResult, ChannelCounts, OutcomeCounts, VoteCounts, TriageCounts, TenantLoopStats, LayerCounts and EvalTrendPoint. They appear in the parent schemas only, which is the existing GoldSpan pattern.
4. **Stricter ExpertLabel rules than listed:** the category must agree with answerable (no_answer and small_talk exactly when not answerable, as in GoldenItem); `dictionary` triage needs at least one term; a cited chunk cannot also be marked not relevant; triage is non-empty; identical spans are rejected.
5. **The Zod `GoldenSplitManifestSchema` does not enforce the rule and group_assignments cross-check.** JSON Schema cannot express it, so Pydantic, which runs the promotion, enforces it.
6. **TDD RED for Task 1 used placeholder models.** These permissive classes made the tests fail on assertions instead of module-not-found errors. The samples test was moved into Task 2's RED commit.
