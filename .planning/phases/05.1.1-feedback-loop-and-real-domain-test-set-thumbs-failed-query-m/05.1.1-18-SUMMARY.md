# Phase 5.1.1 Plan 18: Feedback loop admin card Summary

**What it does:** operator admins get one Config UI card. In it they grant or revoke domain experts per workspace, set a workspace's retrieval-log level, and run mining or the expired-data purge, with a confirmation step before each consequential action.

## Accomplishments
- Workspace choice: single-tenant mode works on `s:default` with no chooser. Multi-tenant mode offers the `#workspace-selector` organizations as `o:<id>`, plus a typed `o:`/`u:` + UUID key. An invalid key sends nothing.
- Experts table: masked e-mail, user ID and grant date, with an empty state. Grant by user ID: 201 announces "Access granted.", 200 "This user already has access.", 400 shows the server detail at the field. Revoke runs only after the dialog.
- Logging level (inherit, ids, off): saved with PUT, showing the stored level and date. A 404 on read counts as inherit.
- Mining: From/To date fields, a confirmation dialog and a 60s timeout. Results show as a hash, reason and count table. A run that adds nothing says "No new cases.", a 404 shows the switched-off notice (`alert-info`), and no answer from the server gives `mine.unknown`.
- Purge: destructive dialog. It names the retention period from `#RAG_RETRIEVAL_LOG_RETENTION_DAYS` when that is 1–365, otherwise a generic period. The result is a two-count table; no answer from the server gives `purge.unknown`.
- A 401 or 403 from any call replaces the card's content with the sign-in alert and "Reload panel". A 503 shows `panel.unavailable`.
- 87 labels in en, zh and it (UI-SPEC 12.6). Every server value is set with textContent; the file contains no innerHTML.
