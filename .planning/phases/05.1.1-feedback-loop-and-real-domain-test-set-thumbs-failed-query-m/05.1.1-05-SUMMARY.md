# Phase 05.1.1 Plan 05: Retrieval log writer on the trace seam — Summary

**One log row per chat, embed or voice retrieval, written after the response from finishTrace. It holds ids, scores and language codes, never text. With `RAG_RETRIEVAL_LOG=off` nothing is written.**

## Accomplishments

- `src/lib/rag/feedback-loop/retrieval-log.ts`:
  - `buildRetrievalLogRow` keeps at most 50 candidate entries `{chunk_id, document_id, rank, similarity, rerank_score?, fused_score?, kept, language?}`. `top_score` is the first candidate's rerank score, else its similarity.
  - The query is passed through `maskPII`, capped at 2000 characters and fingerprinted only in `masked_query` mode.
  - D-03a: `query_language` is `result.queryLanguage` when it is a code, else the detector's language. Confidence is 1 or 0.5, and null when the detector found nothing or disagrees with the stored code. `chunk_languages` falls back to `und`. `answer_language` comes from the holder. Every value passes `toLanguageCode`.
  - `writeRetrievalLog` inserts with the admin client and asks for `id, tenant_key` back, with a 2000 ms time box. On a tenant mismatch it deletes the row. Any failure gives one codes-only `[Retrieval Log]` line, and it never throws.
- `finishTrace` (`src/lib/rag/trace/finish.ts`): a new `logContext` option. When the row is eligible, a `scheduleAfterResponse` task imports the module dynamically, builds the row from the live result and writes it. The task has its own try/catch, and Langfuse and `[RAG Trace]` behave as before.
- `runRetrieval` (`src/lib/rag/pipeline.ts`): every exit returns a result with a fresh `logOutcome` holder `{ value: 'unknown', answerLanguage: null, pipeline }`, and `input.logContext` is passed to finishTrace when runRetrieval owns the trace (voice, media).
- `src/lib/rag/index.ts` exports the types `LogChannel`, `LogContext`, `LogOutcome` and `LogOutcomeValue`.

## Deviations

1. **Holder has an optional `pipeline` field.** The plan names `{value, answerLanguage}`; I added `pipeline` because the row needs `legacy|v2` and early exits leave nothing else that says which pipeline ran. Routes do not set it.
2. **Time box uses an AbortController and a timer, not `AbortSignal.timeout(2000)`.** It has the same 2000 ms budget. The timer also wins when a client ignores the signal, and the hanging-client test can use fake timers.
3. **Candidate entries the contract cannot hold** (document id not a UUID, chunk id empty or longer than 128 characters) are left out instead of failing the whole row.
4. The plan's verification line names `npm run typecheck:new`. I ran the brief's `npx next typegen && npx tsc --noEmit -p tsconfig.json` gate instead (0 errors).
