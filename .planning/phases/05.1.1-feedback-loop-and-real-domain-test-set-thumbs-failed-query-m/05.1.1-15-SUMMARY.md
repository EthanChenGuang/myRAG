# Phase 05.1.1 Plan 15: Refusal control and source-open signal in web chat — Summary

**A user can now say, in one click under a refusal, whether an answer was expected; opening a source of a traced answer is counted once as a weak signal. Both stay invisible unless plan 09's switches send a trace id.**

## Accomplishments

- `refusal-feedback-client.ts`: `postRefusalFeedback` (validated body, `correct_refusal` always without reasons, 10 s abort, one silent 404 retry after 2 s, `{ok}` / `{retry}` / `{hidden}`), `refusalRequestFor` (same choice again does nothing; chips in a fixed order, only after `expected_answer`), `shouldShowRefusalControl`, and the D-12 helpers: a message-to-trace registry, the panel's owning message, `sourceKeyOf`, and `postSourceOpened` (keepalive, constant `{"kind":"source_opened"}`, once per trace and source key, stop after a 404, every failure swallowed).
- `refusal-feedback.tsx`: the UI-SPEC 6.3 control with the shipped Phase 5 pill and chip classes, `Check` and `Loader2` icons, the error line with Try Again, and an `sr-only` polite status region announcing `feedbackSaved` or `refusalFailed`. No text field.
- `chat-message.tsx`: renders the control directly under the message body and above the Sources button and the action row, outside the action row's hover opacity, only when the gate holds; registers the message's trace for D-12 (not in incognito) and marks the last traced message as the panel owner.
- `answer-metadata.ts`, `types/chat.ts`, `page.tsx`: `refusal` survives streaming; `refusal` and `refusalFeedback` survive save and reload; a saved vote is merged into the message and the chat is saved.
- `citation-chip.tsx` and `sources-sidebar.tsx`: the signal on a chip click and on a panel link click, Enter or middle click.
- `answer-quality.ts`: the eight UI-SPEC 12.3 keys in en, zh and it.

## Deviations

1. **Files outside `files_modified`**: `src/types/chat.ts` (persisted metadata type and `persistedMetadataOf`), `tests/chat-messages-roundtrip.test.ts` (one new case). Both were named by the plan's must_haves and by UI-SPEC section 15 item 1; `answer-metadata.ts` and `page.tsx` were in the list.
2. **`signalSourceOpened` dropped**: an earlier draft had a resolver wrapper in the client module; the chip and the panel now resolve the trace with `traceForMessage` and call `postSourceOpened` themselves, so the acceptance grep matches the call sites.
3. **Panel links resolve their message through a registry** (`setSourcesMessage` / `sourcesMessage`), because non-citation sources in the panel carry no message id and `sources-provider.tsx` is not in this plan; an unresolved source sends nothing, as UI-SPEC 6.4 allows.
4. **Interaction tests without a DOM**: the repo has no jsdom or testing-library, and no package may be added. The interactive logic lives in pure functions tested directly; the component is tested through static markup; the chip handler is tested by calling the component with mocked store hooks; the panel handler through the exported `sourceOpenHandlers`.
5. The plan's verification names `npm run typecheck:new`; the brief's `npx next typegen && npx tsc --noEmit -p tsconfig.json` was run instead.
