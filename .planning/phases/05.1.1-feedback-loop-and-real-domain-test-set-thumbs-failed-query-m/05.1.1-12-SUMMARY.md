# Phase 5.1.1 Plan 12: Expert grants and RLS-scoped review routes Summary

**Operator admins grant experts per tenant. Experts list and open their own tenant's review items through RLS, and read the snapshot's chunk text through a tenant-restricted admin fetch. A two-tenant API test with real Postgres RLS proves the isolation.**

## Accomplishments
- `/api/rag/admin/domain-experts`: the admin guard runs before anything is read. The tenant key goes through `parseTenantKey` plus the deployment-mode rule, and the user is checked with `auth.admin.getUserById`. `granted_by` is the verified admin id. The log line `[Review] grant` / `[Review] revoke` carries tenant and user hashes and the admin id. GET masks e-mails to `***@domain`.
- `/api/rag/review/items`: 404 while `RAG_DOMAIN_EXPERT_REVIEW` is off, 401 without a session, 400 for unknown query parameters (a `tag` filter included) or a cursor the route did not issue. The page holds at most 50 items, newest first by `(mined_at, id)`, so ties from one mining run page correctly. Every item passes `ReviewItemSchema`.
- `/api/rag/review/items/{id}`: the item is read through RLS, and `answer_masked` is resolved as described in key-decisions. `user_id` and `chat_id` never leave the module.
- `/api/rag/review/items/{id}/chunks`: the item is read through RLS first, then the snapshot chunks are fetched with the D-08 filter inside the item's tenant. Each request logs `[Review] chunks {expert, item: <16-hex hash>, count}`.
- D-29 and D-03a: `tags`, `query_language`, `query_language_confidence`, `answer_language` and `chunk_languages` are returned exactly as stored. No route filters on tags or writes them.

## Deviations from Plan
1. **Two files outside files_modified.** `src/lib/rag/feedback-loop/review-route.ts` holds the switch-and-session entry shared by the three review routes. `tests/helpers/pglite-rest-client.ts` is a Supabase-shaped client over PGlite that runs each query in a transaction as `authenticated` (with `request.jwt.claim.sub`) or `service_role`. The fake edge's table routes do not switch roles and do not serve `rag_review_items`, so they could not prove RLS.
2. **`src/lib/rag/index.ts` re-exports the review module.** `check-rag-boundary` rejects deep imports below `@/lib/rag` from routes. `openReviewSession` imports the SSR client lazily, as `tenant/admin.ts` does, so the index does not load `next/headers`.
3. **The two-tenant test uses personal tenants (`u:`), not organizations.** Isolation is keyed on `tenant_key` alone, so the kind of key does not change the proof.
4. **Not covered by a test:** the answer-id path of the linked answer (through `rag_retrieval_log.answer_id`). The trace-id path is tested.
5. **Chunks under non-legacy chunking profiles.** Only `document_chunks` rows are resolved. A snapshot id that is not a `document_chunks` row reads as unavailable.
