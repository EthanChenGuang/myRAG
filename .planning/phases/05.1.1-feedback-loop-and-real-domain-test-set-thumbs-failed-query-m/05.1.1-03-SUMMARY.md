# Phase 5.1.1 Plan 03: Retrieval log table and purge function Summary

**`public.rag_retrieval_log` (tenant-keyed per mode, RLS on with no policy, service-role only) with language-code columns, a chat-delete trigger and a batched `rag_purge_retrieval_log`, tested on PGlite in both modes.**

## Performance

- Tasks: 2, commits: 6 (2 RED, 2 GREEN, 1 blocking fix, this summary)
- Files: 6 created, 3 modified

## Accomplishments

- 0531 creates the table with the D-03 columns and the D-03a columns `query_language`, `query_language_confidence` (0..1), `chunk_languages text[]` (codes only, no null or empty element) and `answer_language`; there is no column for answer or chunk text. `trace_id` is unique. Indexes on `created_at` and `chat_id`. RLS on with no policy; all privileges revoked from PUBLIC, anon and authenticated; ALL granted to service_role.
- `chat_id` has no foreign key; the statement-level AFTER DELETE trigger on `public.chats` (`rag_feedback_loop_on_chat_delete`, SECURITY DEFINER, `SET search_path = ''`) deletes the rows of deleted chats. `user_id` and (multi-tenant) `organization_id` cascade.
- 0532 adds the generated `tenant_key` per mode (same expressions as 0502) and the `(tenant_key, created_at DESC)` and partial `(tenant_key, created_at) WHERE feedback_vote = -1` indexes.
- 0533 creates `rag_purge_retrieval_log(p_retention_days, p_batch_size)`: oldest first, at most one batch, returns the count, refuses bad arguments with 22023; EXECUTE only for service_role. 0410 section 1 locks it and the trigger function.
