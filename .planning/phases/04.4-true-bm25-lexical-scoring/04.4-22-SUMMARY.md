## Deviations

- **The plan split was not taken.** The plan check allowed a split, but the four tasks ran in one session with the pre-registration boundary as its own pushed commit.
- **The spec has its own class.** It is a variant (`"variant": "local_rerank_stats"`, class `LocalStatsGateSpec`) in `phase44_gate.py`, not the 4.4 class: the 4.4 validator requires bm25 on-arms. It reuses `off_identity_gate`, which gained a `latency=False` keyword, plus `drop_offenders`, `_outcome` and `render_markdown`. The 4.4 path is unchanged (its tests pass).
- **The gate's pairs are built as base config plus arm env.** They do not use the two new run configs. The two files exist for the CLI, the baselines and the impact list.
- **Gate (d)** gates rerank p95 and p50 against the per-stage budgets, which are p95 values. The spec says so.
- **Gate (c)** reads `rerank_score` per candidate from `traces.jsonl`. Ties are not orderings, and at least one compared pair is required.
- **The ancestry check** is implemented in the gate run (`registration_commit`): the commit that added the spec must be an ancestor of HEAD, and the spec unchanged since.
- **TDD order:** the Task 1 harness code was written before its test, and Task 2 had no RED commit; its tests were written with the code before the registration commit.
- **The impact tool groups runs** by effective configuration (the env without values equal to the eval pin, plus overrides and entry profile) and measures each group once.
