## Summary

BM25 can be computed in plain SQL on hosted Supabase from what the lexical index already stores. `lexical_tsv` is a positional `tsvector` built verbatim from the application tokenizer's output, so for each chunk the term frequency of a lexeme is the number of its stored positions and the chunk length is the sum over its lexemes. The missing inputs are global: chunk count, average length and document frequency per lexeme. They must be kept per tenant.

The recommended design has three parts: (1) statistics tables keyed by tenant, fed by statement triggers that stage one delta row per changed chunk and compacted off the write path; (2) a sibling search function that finds matches through the existing GIN index, ranks them cheaply with IDF-weighted `ts_rank`, and scores a bounded candidate set with exact BM25; (3) a backend path that calls it in parallel with the dense call and falls back to today's leg when statistics are not ready.

**Primary recommendation:** build it as a sibling function and never redefine `hybrid_search_chunks` (R-1). Keep the default `ts_rank_cd`; let the owner's real eval set decide the flip.

## Standard Stack

No new dependency. Postgres built-ins only: `tsvector`, GIN, `ts_rank`, `unnest(tsvector)`, `tsvector_to_array`, `pg_advisory_xact_lock`, `hashtextextended`. TypeScript and Python sides reuse the existing Supabase client, node:test with PGlite, vitest, and `rag_eval.paired`.

## Alternatives Considered

| Instead of | Could use | Why not |
|------------|-----------|---------|
| Sibling function | Redefine `hybrid_search_chunks` with a scoring parameter | R-1: overwritten by 0930; every later redefinition would have to carry BM25 |
| SQL scoring | Re-score the leg's rows in TypeScript | R-5: the right rows are not in the capped leg |
| Staged deltas | Per-lexeme counter upserts in the write trigger | About 150 upserts per chunk and row-lock contention on common lexemes under bulk ingest |
| Staged deltas | Periodic full recompute only | A full pass per refresh grows with the corpus; kept as the rebuild and drift repair |
| Staged deltas | Sharded counters | Still writes per lexeme on the write path; more rows, same contention class |
| Lucene IDF | Okapi IDF `ln((N - df + 0.5) / (df + 0.5))` | Negative for terms in more than half the chunks |
| Per-tenant statistics | One global table | Leaks vocabulary across tenants and lets one tenant move another's ranking (LEX-02) |
| Statistics by language and chunking profile | Tenant-wide only | The lexical leg filters by language per query variant and by effective chunking profile; tenant-wide counts would double-count dual-written profiles |

## Architecture Patterns

```
write path                                 off the write path                    query path (bm25)
document_chunks I/U/D                      rag_lexstats_compact(tenant)          backend.search(req.lexicalScoring)
  -> statement trigger (definer)             advisory lock per tenant              ├─ hybrid_search_chunks(p_lexical_limit = 0)   dense leg
     inert unless tenant enabled             pending -> df / corpus counters       └─ rag_bm25_search_chunks(...)                 lexical leg
     +1/-1 row: lexemes[], dl              rag_lexstats_rebuild(tenant)               pass 1: GIN matches, idf * ts_rank, top C
  -> rag_lexical_stats_pending               one-snapshot scan                        pass 2: unnest, exact BM25, top L
                                           rag_lexstats_check(tenant)              not ready / error -> ts_rank_cd leg + trace code
```

### Tables (0900)

- `rag_lexical_stats_state (tenant_key text PRIMARY KEY, status text CHECK (status IN ('building','ready')), enabled_at timestamptz, rebuilt_at timestamptz, compacted_at timestamptz)`
- `rag_lexical_stats_pending (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, tenant_key text NOT NULL, corpus text NOT NULL DEFAULT 'chunks', chunking_profile_id text NOT NULL, language text NOT NULL, sign smallint NOT NULL CHECK (sign IN (-1, 1)), lexemes text[] NOT NULL, dl integer NOT NULL, created_at timestamptz NOT NULL DEFAULT now())` with an index on `(tenant_key, id)`
- `rag_lexical_df (tenant_key text, corpus text, lexeme text, chunking_profile_id text, language text, df bigint NOT NULL, PRIMARY KEY (tenant_key, corpus, lexeme, chunking_profile_id, language))`
- `rag_lexical_corpus (tenant_key text, corpus text, chunking_profile_id text, language text, chunk_count bigint NOT NULL, total_len bigint NOT NULL, PRIMARY KEY (tenant_key, corpus, chunking_profile_id, language))`

A chunk's `language` may be null on old rows; the triggers and the rebuild store `coalesce(language, 'und')`.

### Query statistics

```sql
-- $2 tenant, $P effective profile ids (text[]), $L languages (text[] or NULL = all), $T tokens
corpus AS (SELECT sum(chunk_count)::float8 AS n, sum(total_len)::float8 / NULLIF(sum(chunk_count), 0) AS avgdl
           FROM public.rag_lexical_corpus
           WHERE tenant_key = $2 AND corpus = 'chunks' AND chunking_profile_id = ANY($P)
             AND ($L::text[] IS NULL OR language = ANY($L) OR language = 'und')),
q AS MATERIALIZED (
  SELECT t.tok, pg_catalog.quote_literal(t.tok)::pg_catalog.tsquery AS tsq,
         pg_catalog.ln(1 + (corpus.n - x.df + 0.5) / (x.df + 0.5)) AS idf
  FROM (SELECT DISTINCT tok FROM pg_catalog.unnest($T::text[]) AS u(tok)) t CROSS JOIN corpus
  CROSS JOIN LATERAL (SELECT LEAST(GREATEST(COALESCE(sum(d.df), 0), 1), corpus.n) AS df
                      FROM public.rag_lexical_df d
                      WHERE d.tenant_key = $2 AND d.corpus = 'chunks' AND d.lexeme = t.tok
                        AND d.chunking_profile_id = ANY($P)
                        AND ($L::text[] IS NULL OR d.language = ANY($L) OR d.language = 'und')) x)
```

The token list must be cleaned exactly as `rag_lexical_tsquery` cleans it (non-empty, at most 255 bytes, no quote, backslash or whitespace, at most 64 distinct), so `q` and the match `tsquery` name the same terms.

## Don't Hand-Roll

| Problem | Don't build | Use instead |
|---------|-------------|-------------|
| Finding matches | A posting table per lexeme and chunk | The existing GIN index on `lexical_tsv` |
| Term frequency and length | A stored column or a text scan | `unnest(lexical_tsv)` and `cardinality(positions)` |
| Paired bootstrap intervals | A new resampler | `rag_eval.paired._bootstrap_interval` |
| Tenant check | A new guard | `rag_assert_tenant_key` |
| Change capture | Row-level triggers | Statement triggers with transition tables (0702) |

## Common Pitfalls

1. **Tokens not cleaned the same way twice.** If the statistics lookup uses raw tokens and the match uses `rag_lexical_tsquery`, a rejected token gets an IDF and never matches, or the reverse. Build both from one cleaned list.
2. **`quote_literal(tok)::tsquery` with an empty `search_path`.** Schema-qualify every function and cast (`pg_catalog.`); 0425 and the definer-search-path test fail otherwise.
3. **Division by zero.** `avgdl` is null when the tenant has no member chunk; raise `lexical_stats_not_ready` before the query (D-25).
4. **Double counting on update.** Compare membership and the vector of the old and new row; write nothing when neither changed (R-8).
5. **Deadlocks between compactors.** One advisory lock per tenant and an `ORDER BY` on the upsert key.
6. **Enable and rebuild in one transaction.** Writers do not see the uncommitted state row and their changes are missed. Commit the enable first (D-18).
7. **Treating `lexical_score` as bounded.** BM25 has no upper bound; nothing may compare it with a threshold (D-35).
8. **Logging lexemes.** Counts and codes only (D-34).
9. **Language-literal check.** `scripts/ci/check-language-literals.mjs` fails on language codes outside the registry; `'und'` in SQL migrations is already used by 0856, but any TypeScript literal needs the registry constant or an allowlist entry.
10. **Folded setup files.** Do not edit `single-tenant-setup.sql` or `multi-tenant-setup.sql`; migrations 09xx are not folded.

## Code Examples

Verified in PGlite this session (table and function names shortened in the prototype; the plans use the names in CONTEXT).

Update trigger body (statement level, old and new transition tables):

```sql
INSERT INTO public.rag_lexical_stats_pending (tenant_key, chunking_profile_id, language, sign, lexemes, dl)
SELECT x.tenant_key, x.chunking_profile_id, COALESCE(x.language, 'und'), x.sign,
       pg_catalog.tsvector_to_array(x.lexical_tsv), public.rag_lexical_dl(x.lexical_tsv)
FROM (
  SELECT o.id, o.tenant_key, o.chunking_profile_id, o.language, (-1)::smallint AS sign, o.lexical_tsv,
         (o.is_current AND o.status IN ('ready','variant') AND o.lexical_tsv IS NOT NULL AND o.lexical_tsv <> ''::pg_catalog.tsvector) AS member
  FROM old_rows o
  UNION ALL
  SELECT n.id, n.tenant_key, n.chunking_profile_id, n.language, 1::smallint, n.lexical_tsv,
         (n.is_current AND n.status IN ('ready','variant') AND n.lexical_tsv IS NOT NULL AND n.lexical_tsv <> ''::pg_catalog.tsvector)
  FROM new_rows n
) x
JOIN old_rows o ON o.id = x.id
JOIN new_rows n ON n.id = x.id
JOIN public.rag_lexical_stats_state s ON s.tenant_key = x.tenant_key
WHERE x.member AND (
  (o.is_current AND o.status IN ('ready','variant')) IS DISTINCT FROM (n.is_current AND n.status IN ('ready','variant'))
  OR o.lexical_tsv IS DISTINCT FROM n.lexical_tsv OR o.tenant_key IS DISTINCT FROM n.tenant_key
  OR o.chunking_profile_id IS DISTINCT FROM n.chunking_profile_id OR o.language IS DISTINCT FROM n.language);
```

Compaction core:

```sql
WITH taken AS (
  DELETE FROM public.rag_lexical_stats_pending p
  WHERE p.id IN (SELECT q.id FROM public.rag_lexical_stats_pending q WHERE q.tenant_key = p_tenant_key ORDER BY q.id LIMIT p_max_rows)
  RETURNING p.chunking_profile_id, p.language, p.sign, p.lexemes, p.dl)
INSERT INTO pg_temp._lexstats_taken SELECT * FROM taken;

INSERT INTO public.rag_lexical_df AS d (tenant_key, corpus, lexeme, chunking_profile_id, language, df)
SELECT p_tenant_key, 'chunks', u.lexeme, t.chunking_profile_id, t.language, sum(t.sign)
FROM pg_temp._lexstats_taken t CROSS JOIN LATERAL pg_catalog.unnest(t.lexemes) AS u(lexeme)
GROUP BY u.lexeme, t.chunking_profile_id, t.language HAVING sum(t.sign) <> 0
ORDER BY u.lexeme, t.chunking_profile_id, t.language
ON CONFLICT (tenant_key, corpus, lexeme, chunking_profile_id, language) DO UPDATE SET df = d.df + EXCLUDED.df;
DELETE FROM public.rag_lexical_df d WHERE d.tenant_key = p_tenant_key AND d.df <= 0;
```

Two-pass scoring core (the filter and the joins of 0856 go where `<filter>` stands):

```sql
cand AS MATERIALIZED (
  SELECT c.id AS hid, (SELECT sum(q.idf * pg_catalog.ts_rank(c.lexical_tsv, q.tsq, 0)) FROM q) AS s1
  FROM public.document_chunks c JOIN public.documents d ON d.id = c.document_id
  WHERE <filter> AND c.lexical_tsv @@ $1
  ORDER BY s1 DESC, c.id LIMIT $C),
scored AS (
  SELECT cand.hid,
    (SELECT sum(q.idf * u.tf * ($K1 + 1) / (u.tf + $K1 * (1 - $B + $B * u.dl / corpus.avgdl)))
     FROM (SELECT x.lexeme, pg_catalog.cardinality(x.positions)::float8 AS tf,
                  sum(pg_catalog.cardinality(x.positions)) OVER ()::float8 AS dl
           FROM pg_catalog.unnest(c.lexical_tsv) x) u
     JOIN q ON q.tok = u.lexeme) AS score
  FROM cand JOIN public.document_chunks c ON c.id = cand.hid CROSS JOIN corpus)
SELECT hid, score FROM scored ORDER BY score DESC, hid LIMIT $13
```

`p_candidate_limit = 0` means no cap (every match is scored exactly); only tests, the benchmark and the eval overlap check send it.
