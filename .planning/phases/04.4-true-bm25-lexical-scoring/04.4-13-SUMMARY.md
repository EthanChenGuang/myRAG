# Phase 4.4 Plan 13: fixture BM25, pre-registered gates and the real-set comparison tool Summary

**A bm25 fixture run now rebuilds lexical statistics for every fixture tenant and is served by `rag_bm25_search_chunks`; the three phase gates are committed before any on-run result, and one tool compares `ts_rank_cd` with `bm25` on a real eval set with paired intervals.**

## Pre-registered gates (`eval/config/phase44-comparison.json`)

- **(a) off identity (D-36 a).** Runs `off-prechunked` and `off-ingest`, no base run config, with `RAG_LEXICAL_SCORING=ts_rank_cd`, `RAG_LEXICAL_BM25_K1=1.2` and `RAG_LEXICAL_BM25_B=0.75`. Each must have zero paired differences (retrieval and refusal) against the committed baseline of its mode, and pass the chat latency budget. The `characterization` command must also exit 0.
- **(b) on (D-36 b).** `v2-lexical-bm25-on-<mode>` is compared with `v2-default-<mode>` (the same run config, explicitly `ts_rank_cd`) in both modes. It passes when:
  - no overall, language or category slice is beyond the noise band on Recall@5, Recall@10 or MRR;
  - correct and false refusal have zero paired differences;
  - stage latency is within the chat budget.
- **(c) cap agreement (D-36 c).** Mean overlap@10 between the capped and uncapped BM25 lexical top 10 must be **at least 0.95** for both bm25 runs.
- **Report-only.** `v2-lexical-bm25-on-rerank-none-prechunked` is compared with `v2-default-rerank-none-prechunked`, both with `RAG_RERANKER=none`. It is reported, never gated.

Gate command: `python -m rag_eval.phase44_gate --spec eval/config/phase44-comparison.json --out <dir> [--only off_identity|on|cap_agreement] [--reuse <dir>]`. It writes `gate.json` and `gate.md`.
- Exit 0: every gate passes.
- Exit 1: a gate fails. Each failing slice or figure is printed.
- Exit 2: spec or usage error, including a missing run, `report.json` or overlap file.
- Exit 3: the harness failed.

## Overlap figures

The overlap figures are in **`lexical-bm25-overlap.json`** in each bm25 run's output directory (`<out>/harness/<run>/`). They are not a key in `run.json`.

Fields: `schema_version`, `tenant_hash`, `k`, `capped_candidate_limit`, `questions`, `measured`, `mean_overlap_at_k`, `min_overlap_at_k`, and `items[{item_id, overlap, uncapped}]`. The file holds ids and numbers only.

## Lexical-leg harness command

`node --import tsx eval/harness/lexical-leg-run.mts --golden <file> --tenant <key> --out <dir> [--k1 a,b] [--b a,b] [--limit 50] [--profile <id>]`

- **Connection.** It reads `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` from the environment only, and refuses without them.
- **Output path.** It refuses an `--out` that is not git-ignored.
- **Readiness.** Every bm25 arm needs ready statistics. Without them it exits 1 with `lexical_stats_not_ready` and writes no output.
- **Tokenizing.** Each question goes through `queryLexicalTokens` with the tenant's query-side lexical options. The pipeline resolves those options the same way: `resolveLexicalOptions` with `queryLanguage(question)`, only while a lexical switch is on.
- **Calls, per item and arm:**
  - `ts_rank_cd` arm: the lexical rows of `hybrid_search_chunks` (`p_dense_limit 0`, no embedding, no filter).
  - Each bm25 arm: `rag_bm25_search_chunks` with `bm25ArgsFrom(...)` and limit 50.
- **Arm labels.** `ts_rank_cd` and `bm25`. With a grid: `bm25:k1=<k1>,b=<b>`, at most 9 combinations.
- **Files written:**
  - `lexical-legs.jsonl`: per item and arm, the chunk id, document id, document name and content.
  - `manifest.json`: the eval-set sha256, the tenant hash, the profile, the limit, the arms, a summary of the lexical options, and the item counts.
- **Console.** Counts and durations only.

## Comparison tool

`python -m rag_eval.lexical_compare --golden <private file> --out <dir> (--from-reports <dir> | --base-url <url> --arm <arm>) [--lexical-leg-dir <dir>] [--k1 a,b] [--b a,b] [--seed N] [--resamples N] [--allow-committed-out]`

- **Arms.** `lexical_ts_rank_cd`, `rrf_ts_rank_cd`, `lexical_bm25` and `rrf_bm25`. With a grid, the bm25 arms get the suffix `_k1=<k1>_b=<b>`; at most 9 combinations.
- **`--from-reports`.** Reads `<dir>/rrf/<arm>/` (harness runs: `run.json`, `traces.jsonl`) and the lexical-leg directory (default `<dir>/lexical-legs`).
- **Metrics.** Computed over the answerable dev items, overall and per language: Recall@10, Recall@50, MRR and `doc_at_1`. A span is hit when `rag_eval.matching.chunk_matches_span` matches it, or the chunk's document id matches when the span names one.
- **Paired differences.** bm25 minus `ts_rank_cd`, for the lexical pair and for the RRF pair. Each has a 95% interval from `rag_eval.paired._bootstrap_interval`, with seed 20261123 and 10000 resamples by default.
- **Errors.** It refuses:
  - an item that is missing from one arm (the error names the arm and the item);
  - an eval-set hash or dev golden hash that differs from `--golden`;
  - an RRF arm whose traces ran with a different `RAG_LEXICAL_SCORING`, k1, b or `RAG_RERANKER`.
- **`--base-url`.** Runs one RRF arm with `run_harness` into `<out>/rrf/<arm>` and checks its traces.
- **Output.** `lexical-compare.json` and `lexical-compare.md` hold metrics, counts, hashes, config hashes and tokenizer switches. They hold no question, answer, chunk or token text.
