# Phase 4.4 Plan 07: Lexical statistics purge hook Summary

**Migration 0903 adds `rag_purge_hook_lexical_stats`. After the purge deletes a tenant's document versions, the hook folds the staged removals, so the counters equal the remaining member chunks and the vocabulary of purged documents is gone.**

- 04.4-04-SUMMARY.md is present, and `rag_lexstats_compact` is defined in 0902. No hand-off note for a missing upstream was needed. All depends_on plans (04.4-04, and 04.4-02 through it) have a SUMMARY on this branch.
- **Branch taken: (b).** `rag_purge_store_inventory` is not defined in any file under `supabase/migrations/`. 0976 and 1009 only mention it in guards or comments. So 0903 ships the hook only, and `handoffs/04.4-07-purge-inventory.md` lists the rows for Phase 6.3.

## Hook

`public.rag_purge_hook_lexical_stats(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint`. It is SECURITY INVOKER, with `SET search_path = ''`. EXECUTE is revoked from PUBLIC, anon and authenticated and granted to service_role.

1. It runs `rag_assert_tenant_key` first, so a malformed key or one from the other deployment mode fails with 22023.
2. It refuses with 22023 any listed id whose document is in another tenant or, when `p_lineage_id` is given, in another lineage. Ids of documents that no longer exist are accepted.
3. If the tenant has no `rag_lexical_stats_state` row, it returns 0.
4. Otherwise it loops `rag_lexstats_compact(p_tenant_key, 5000)` until a call returns 0, with at most 200 iterations, and returns the total number of pending rows folded.

- **Counts key for Phase 6.3:** `lexical_stats`.
- **Call order:** the hook folds whatever is staged for the tenant. Called before the chunk delete, it folds nothing of the purge. Phase 6.3 must call it again after the chunk delete, and `rag_purge_verify` must require `pending = 0` from `rag_lexstats_status`. The hand-off note states this rule, and a test asserts both intermediate states.

## Tests (tests/rag-db/lexical-stats-purge-hook.test.mts, both modes)

- **Function shape and grants:** one function, SECURITY INVOKER, empty search_path, returns bigint. Client roles cannot execute it; service_role can.
- **Purging two versions of a lineage:** the hook returns the 14 staged rows, the check is clean, and the remaining chunk count is right. Tenant B's counters and its own pending row are unchanged. A second call returns 0.
- **Purging every document of the tenant:** no `rag_lexical_df`, `rag_lexical_corpus` or pending row of the tenant remains.
- **Phase 6.3 order:** hook first returns 0 with pending 0. The delete then stages 5 rows and the counters alone still differ. The second call folds 5 and the check is clean.
- **Refusals:** an id from another lineage, or (multi-tenant) from another tenant, raises 22023 and nothing changes. A gone id is accepted.
- **Edge cases:** a tenant without a state row returns 0 and writes nothing. A key of the other mode, or a malformed key, raises 22023. Re-applying 0903 is a no-op.
