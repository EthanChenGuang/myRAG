# 04.4-01 Summary: lexical scoring switch and parameters

## What was built

- **Config field:** `config.v2.lexicalScoring: LexicalScoringConfig = { mode: LexicalScoringMode; k1: number; b: number }`. Types and `LEXICAL_SCORING_DEFAULTS` (`ts_rank_cd`, 1.2, 0.75) are exported from `src/lib/rag/config.ts`. Helpers: `parseLexicalScoring` and `parseBoundedDecimal`. The three variables are in the memo key.
- **Rules (D-05):** the mode is `bm25` only with `RAG_PIPELINE=v2` and `RAG_LEXICAL_SEARCH=true`. Otherwise it is `ts_rank_cd` with one warning. An unknown mode, or a k1 outside 0.5 to 3, or a b outside 0 to 1, falls back to the default with one warning each.
- **Warning keys (`[RAG Config]`):** `lexical-scoring-needs-lexical`, `RAG_LEXICAL_SCORING:<value>` (from `parseNamedChoice`), `RAG_LEXICAL_BM25_K1:<value>` and `RAG_LEXICAL_BM25_B:<value>`. The logged values are capped at 32 characters.
- **Hash (D-08):** `lexicalScoringHashBlock(config)` in `src/lib/rag/v2/config-hash.ts` returns `null` unless the mode is `bm25`. The new `RetrievalConfigHashInput.lexicalScoring` field becomes the payload key `lexical_scoring`. It is wired into `requestRetrievalConfigHash` (`src/lib/rag/v2/result.ts`). `PINNED_REQUEST_OFF_HASH` is unchanged. Every run config under `eval/config/runs/` keeps its hash under `ts_rank_cd`, whatever k1 and b are.
- **Config UI (D-39):** the controls sit in the "Phase 4 retrieval switches" box, after `RAG_LEXICAL_SEARCH` and before `RAG_RERANKER`:
  - select `id="RAG_LEXICAL_SCORING"` with options `ts_rank_cd` (selected) and `bm25`
  - number `id="RAG_LEXICAL_BM25_K1"` (min 0.5, max 3, step 0.05, placeholder 1.2)
  - number `id="RAG_LEXICAL_BM25_B"` (min 0, max 1, step 0.05, placeholder 0.75)
  - help ids: `rag-lexical-scoring-help`, `rag-lexical-bm25-k1-help`, `rag-lexical-bm25-b-help`
  - i18n keys: `RAG_LEXICAL_SCORING.label/.help`, `RAG_LEXICAL_BM25_K1.label/.help`, `RAG_LEXICAL_BM25_B.label/.help`

  The neighbouring Phase 4 box keys have no zh/it translation tables, so no translation entries were added. Load and save use the generic id/name form handling. The finishing pass is plan 04.4-13.
- **Classification:** all three variables are `side: query`, with no mechanism. Eval pin: `ts_rank_cd`, `1.2`, `0.75`.
