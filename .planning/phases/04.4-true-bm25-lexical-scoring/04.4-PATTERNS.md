## Shared Patterns

**Service-role RPC header** (source: `0864_purge_hooks.sql`):
```sql
CREATE OR REPLACE FUNCTION public.<name>(p_tenant_key text, ...)
RETURNS ...
LANGUAGE plpgsql
VOLATILE
SECURITY INVOKER
SET search_path = ''
AS $fn$
BEGIN
  PERFORM public.rag_assert_tenant_key(p_tenant_key);
  ...
END
$fn$;
REVOKE ALL ON FUNCTION public.<name>(<full signature>) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.<name>(<full signature>) TO service_role;
```

**Migration precheck** (source: `0864_purge_hooks.sql`): a `DO` block that raises `55000` naming the migrations to apply first, using `to_regprocedure` and `to_regclass`.

**Statement trigger, inert until enabled** (source: `0702_vector_sync_triggers.sql`): `AFTER <event> ... REFERENCING OLD TABLE AS old_rows NEW TABLE AS new_rows FOR EACH STATEMENT`; the function returns before reading a transition table while its enabling table has no row.

**Optional request field on the backend** (source: `versionAndIdentifierArgs` in `pgvector.ts`): spread in only when set, so a request without it is byte-identical.

**Fixture database test** (source: `tests/rag-db/hybrid-42-params.test.mts`): `createEmptyFixtureDatabase({ mode })`, `applyMigrationFiles`, both deployment modes in a loop, service and anon keys as fixture placeholders.

**Comparison spec** (source: `eval/config/phase5.1.1-comparison.json`): schema version 2, runs with `switches`, `fixture_mode`, `checks` (`paired_all_zero`, `characterization`, `latency_budget`).
