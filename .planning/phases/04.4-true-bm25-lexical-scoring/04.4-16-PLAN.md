<design>
Decisions D-43a to D-52 of 04.4-CONTEXT.md are binding. The points an executor needs while writing SQL:

**Unit (D-46).** Statistics keep their key `(tenant_key, corpus, [lexeme,] chunking_profile_id, language)`. Corpus `chunks_cluster` counts units:

- a member chunk (D-11: `is_current AND status IN ('ready','variant') AND lexical_tsv IS NOT NULL AND lexical_tsv <> ''`) with `dup_cluster_id IS NULL` is a unit by itself;
- for each `(tenant_key, dup_cluster_id, chunking_profile_id, COALESCE(language,'und'))` with at least one member chunk, the member with the smallest `id` is the unit. Its `tsvector_to_array(lexical_tsv)` and `rag_lexical_dl(lexical_tsv)` are the unit's lexemes and length.

The unit is chosen from `document_chunks` alone, not from `rag_dup_clusters.representative_chunk_id`: the representative can be of another chunking profile or language, or not a D-11 member. A cluster whose copies span two languages counts once per language bucket (accepted, tested as defined). A term that occurs only in a non-unit copy has no counter and is scored with `df = 1` by the existing clamp (D-20).

**Relation to Phase 4.2.** The statistics read only `document_chunks.dup_cluster_id` (0853). They never write a cluster, a band or a hash, and they do not change `RAG_RESULT_DIVERSITY=collapse`, which still folds copies after ranking. Clusters are built by publish (`clusterAfterPublish`) and `npm run rag:dup-clusters` only while `RAG_DUP_CLUSTERS=true`.

**Fallback ladder (D-45, D-49).**

| Situation | What serves the lexical leg | Trace code |
|---|---|---|
| `RAG_LEXICAL_DF_MODE` unset or `raw` | today's behaviour | today's codes |
| `cluster`, but scoring not effectively `bm25`, or `RAG_DUP_CLUSTERS` off | resolved to `raw` at config load, one warning | today's codes |
| `cluster` effective, tenant's `cluster_status` not `ready` or the cluster call fails with `lexical_cluster_stats_not_ready` | raw BM25 (`p_df_mode` not sent) | `lexical_scoring_bm25` + `lexical_df_cluster_unavailable` |
| `cluster` effective and ready | BM25 on corpus `chunks_cluster` | `lexical_scoring_bm25` + `lexical_df_cluster` |
| tenant's raw statistics not ready, or any other BM25 error | `ts_rank_cd` leg, as today | `lexical_stats_unavailable` / `lexical_bm25_failed` |
| cluster statistics ready and the tenant has no cluster | BM25 on `chunks_cluster`, numerically equal to raw | `lexical_scoring_bm25` + `lexical_df_cluster` |

**Staging (D-47).** For each changed chunk of a cluster-enabled tenant, with `o` the old row and `n` the new row (insert has no `o`, delete has no `n`), and "member" as in D-11:

| Old state | New state | Rows staged for the cluster corpus |
|---|---|---|
| member, no cluster | absent or not member | `-1` pending (`chunks_cluster`) |
| absent or not member | member, no cluster | `+1` pending |
| member, no cluster | member, no cluster, vector / tenant / profile / language changed | `-1` and `+1` pending |
| member, cluster A | anything that changes membership, vector, tenant, profile, language or cluster | dirty marker for A |
| anything | member, cluster B | dirty marker for B (and the `-1` of the row above when the old state was a member without a cluster) |
| member, cluster A | member, no cluster | dirty marker for A and `+1` pending |
| not member | not member | nothing |

A dirty marker is one append-only row `(tenant_key, dup_cluster_id)`; no unique key, so writers never wait on each other. The update trigger's change test for the cluster corpus adds `dup_cluster_id IS DISTINCT FROM`; the test for corpus `chunks` is unchanged.

**Reconciliation (D-48).** Inside `rag_lexstats_compact_tenant`, after the pending fold and under the same advisory lock: read up to `p_max_rows` marker rows in id order, take their distinct clusters, and for each `(cluster, profile, language)` key present in the ledger or among the cluster's member chunks: subtract the ledger row's lexemes and length from the counters (when a ledger row exists), add the recomputed unit's (when a member exists), upsert or delete the ledger row, then delete exactly the marker ids read. Counters at or below zero are deleted as today. The function returns pending rows folded plus marker rows removed, so "compact until 0" loops still end.

**Invariants the drift check tests.** For a cluster-enabled tenant:

1. `chunks_cluster` counters plus unfolded `chunks_cluster` pending deltas equal the recompute over member chunks without a cluster plus the sum of the ledger rows;
2. for every cluster with no marker row, the ledger rows equal the recomputed units (chunk id, lexemes as a set, length), with no ledger row for a key without members and no missing row.

Both hold at every commit boundary, so the check is exact even with a dirty backlog.
</design>
