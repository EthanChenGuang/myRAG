- The six functions that take a tenant key call `rag_assert_tenant_key` first. A malformed key or one from the other deployment mode fails with 22023.
- `p_max_rows` is bounded to 1..50000, and NULL means 5000.
- Compaction of a tenant with no state row returns 0 and takes no lock.

## jsonb keys

- **status:** `state` (null when not enabled), `chunk_count`, `lexeme_count` (distinct lexemes), `pending`, `oldest_pending_age_s` (integer seconds, null when none), `enabled_at`, `rebuilt_at`, `compacted_at`.
- **check:** `state`, `pending`, `df_mismatch`, `df_mismatch_with_pending`, `chunk_count_diff`, `chunk_count_diff_with_pending`, `total_len_diff`, `total_len_diff_with_pending`, `clean`.
  - The plain figures compare the counters alone. The `_with_pending` figures compare counters plus pending deltas with a recompute (D-19).
  - Chunk-count and length differences are sums of absolute per-(profile, language) differences.
  - `clean` is true when the three `_with_pending` figures are 0.
  - For a tenant that never enabled, every figure except `pending` is null, and so is `clean`.
- Neither function returns a lexeme. The test checks this.

## Error and lock

- Rebuild without a state row raises `lexical_stats_not_enabled` with SQLSTATE `55000`.
- Lock key: `pg_advisory_xact_lock(hashtextextended('rag_lexstats:' || p_tenant_key, 0))`, taken by compaction, rebuild and disable.

## Deviations

1. **Eighth function.** There is an eighth function, `rag_lexstats_compact_tenant`, which the plan allows ("shared internal function without the guard is fine"). It is service_role only.
2. **Compaction has no temp table.** It is one statement with data-modifying CTEs, so it needs none, and the plan's `CREATE TEMP TABLE ... TRUNCATE` step is gone. Rebuild uses a temp staging table as planned.
3. **Extra check keys.** `check` returns `chunk_count_diff_with_pending`, `total_len_diff_with_pending`, `clean` and `state` beyond the plan's listed keys. The behaviour "counters alone differ while counters plus pending is clean" needs both variants for every figure.
4. **compact_all is one batch per call.** It folds one batch per tenant per call rather than draining every tenant. Callers (CLI, cron, the 0903 hook through `rag_lexstats_compact`) loop until it returns 0.

## Notes for later plans

- **04.4-08:** read `state === 'ready'` and `chunk_count > 0` from `rag_lexstats_status`.
- **04.4-09 CLI:** use `clean` from `rag_lexstats_check`. Loop compaction until it returns 0.
- **Orphan pending rows.** A write that started before a disable and committed after it can leave pending rows for a tenant with no state row. Compaction ignores them, and a later enable and rebuild deletes them.
