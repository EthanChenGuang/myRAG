# 04.4-06 Summary: lexical scoring controls finished through the frontend pipeline

## What was built

- **Dependency wiring:** `updateLexicalScoringControls()` is a method of the config manager in `scripts/config-ui/index.html`.
  - With `RAG_LEXICAL_SCORING=ts_rank_cd`, `#RAG_LEXICAL_BM25_K1` and `#RAG_LEXICAL_BM25_B` get `disabled` and `aria-disabled="true"`, and they keep their values. With `bm25` both are removed.
  - With `bm25` selected and `#RAG_LEXICAL_SEARCH` unchecked, the note `#rag-lexical-scoring-needs-lexical` shows, and its id is added to the select's `aria-describedby`. The select stays editable.
  - It runs at the end of `populateFields()` and on `change` of the select and of the lexical search switch. The listeners are registered in `setupEventListeners()`, behind its `listenersInitialized` guard.
- **Note markup:** `p.label-text-alt.text-base-content.max-w-prose.mt-1[role=status][hidden]` with static text only. It has no `flex`, so `[hidden]` holds.
- **Guideline fixes:** `autocomplete="off"` on the select; the placeholders are now `1.2…` and `0.75…`.

- **No `RAG_VERSION_SCOPE` dependency script exists.** The plan says to reuse it, but on this branch `RAG_VERSION_SCOPE` is a plain checkbox, and the 04.2 combination-note script (`retrievalTuningWarnings`) is not present either.
