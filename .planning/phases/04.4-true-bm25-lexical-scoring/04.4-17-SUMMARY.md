# Phase 4.4 Plan 17: cluster-aware BM25 search, fallback ladder and operations Summary

**`rag_bm25_search_chunks` takes `p_df_mode` (migration 0938, on the 0936 body). With `raw` or the argument omitted it returns exactly what 0936 returned. With `cluster` it reads corpus `chunks_cluster` and equals the TypeScript unit reference; on the 30-copy corpus every copy now ranks above the common-term chunks, where raw ranked copies below them. The app sends `p_df_mode` only for a cluster-ready tenant under an effective `RAG_LEXICAL_DF_MODE=cluster`, and otherwise serves raw BM25 or `ts_rank_cd`. It never refuses. Operators get `rag:lexstats --cluster`. No default is flipped.**

## Behaviour

**Defaults (`RAG_LEXICAL_DF_MODE` unset or `raw`).** The request has no `dfMode`. The BM25 RPC arguments are deep-equal to today's (tested on a cluster-ready tenant too), no DF code is added, and the stage detail is today's. In SQL, with `p_df_mode` omitted or `raw`, every parity case returns the ids, order and scores that 0936 returned in the same database.

**Fallback ladder (D-49), each row tested in `pgvector-bm25.test.ts`:**

| Situation | Served by | Codes |
|---|---|---|
| raw | today | today |
| cluster, tenant cluster-ready | BM25 with `p_df_mode: 'cluster'` | `lexical_scoring_bm25;lexical_df_cluster` |
| cluster, cluster status building or not enabled | raw BM25, no `p_df_mode` | `lexical_scoring_bm25;lexical_df_cluster_unavailable` |
| cluster call refused with `lexical_cluster_stats_not_ready` | one retry without `p_df_mode`, cache dropped | `lexical_scoring_bm25;lexical_df_cluster_unavailable` |
| the retry fails too, or another BM25 error | `ts_rank_cd` leg | `lexical_bm25_failed` |
| raw statistics not ready | `ts_rank_cd` leg | `lexical_stats_unavailable` |

Every `backend.search` call of a request (variants, terminology leg, binding legs) carries `dfMode`. The translation request does not.

**Operations.** `npm run rag:lexstats -- enable --cluster` runs raw enable, `rag_lexstats_cluster_enable`, rebuild and check, then rebuilds once more when the check is not clean. `rebuild --cluster` and `check --cluster [--repair]` need a cluster-enabled tenant. `check` exits 1 on any cluster difference. `disable --cluster` removes only the cluster statistics. `status` and `check` print `cluster_status`, `cluster_dirty`, `cluster_oldest_dirty_age_s` and the four diffs for a cluster-enabled tenant (hashes and counts only). Under an effective cluster mode, `enable` without `--cluster` prints one hint and enables nothing more. `npm run rag:lexstats -- --help` prints the usage on stdout. A publish needs no new call, because compaction reconciles the markers (tested on a real publish: 0 markers, clean check). `npm run rag:dup-clusters` runs the same best-effort compaction under bm25 + cluster. Under raw it leaves the markers to compaction (tested). A failing follow-up never fails the command (tested).
