# 04.4-14 hand-off to Phase 7: BM25 parameters for the external backends

## What Phase 7 must do

Phase 4.4 adds `config.v2.lexicalScoring = { mode, k1, b }` (`src/lib/rag/config.ts`, `LexicalScoringConfig`, defaults `LEXICAL_SCORING_DEFAULTS`: `ts_rank_cd`, 1.2, 0.75; from `RAG_LEXICAL_SCORING`, `RAG_LEXICAL_BM25_K1`, `RAG_LEXICAL_BM25_B`). The external backends rank lexically with BM25 natively, so their BM25 parameters must come from this block, not from literals:

- **Weaviate** (plan 07-08, `ensureCollection`): the collection's `invertedIndex.bm25` takes `k1 = config.v2.lexicalScoring.k1` and `b = config.v2.lexicalScoring.b`. 07-08 currently pins `bm25 k1 1.2 and b 0.75`; these equal the Phase 4.4 defaults (D-06), so the default collection does not change. A collection's BM25 parameters are fixed at creation: record the pair in the collection description next to `lexical_mode`, and treat a mismatch as a re-creation (or a readiness warning), never as a silent drift.
- **Qdrant** (plan 07-07, `collection.ts` / `adapter.ts`, the lexical query and the `sparse_idf` fallback): the query-time BM25 parameters (`k`, `b`) take the same two values; `idf.corpus` stays scoped by tenant (07-03 `qdrantScopedRequest`).

`lexicalScoring` is **not a routing capability**: `requiredCapabilities` and `backendForRequest` are unchanged (D-28). `BackendSearchRequest.lexicalScoring` is set only under `bm25`; an external backend may ignore `mode` (it always scores with BM25) but must read `k1` and `b` from config so all three backends rank with one pair.

## Enforcing tests

- Phase 7's conformance suite (`runConformance`, 07-07/07-08) should assert that the collection config and the lexical query carry `config.v2.lexicalScoring.k1` and `.b` (a config with k1 1.5 must reach the request). Add that case when the adapters land.
- `tests/rag/v2/search-lexical-scoring.test.ts` already asserts that the field is absent under `ts_rank_cd`. No test yet pins that `requiredCapabilities` ignores `lexicalScoring`; Phase 7 should add one with its routing tests.

## If it is not done

The live comparison of plan 04.4-15 may move the default (its grid is k1 0.9, 1.2, 1.5; b 0.5, 0.75). A backend with literals would keep 1.2 / 0.75 while pgvector uses the new pair, and the backend parity checks of Phase 7 would compare different rankers.
