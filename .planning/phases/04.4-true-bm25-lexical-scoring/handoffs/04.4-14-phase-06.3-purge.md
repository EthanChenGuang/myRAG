# 04.4-14 hand-off to Phase 6.3: lexical statistics in the purge inventory

Plan 04.4-07 took **branch (b)**: `public.rag_purge_store_inventory()` was not on trunk, so 0903 ships the hook only and adds no inventory row. This note repeats the obligation for the Phase 6.3 owner; the full table and call-order rule are in `handoffs/04.4-07-purge-inventory.md`.

## What Phase 6.3 must do

When it creates or redefines `rag_purge_store_inventory()`, list four relations under store `lexical_stats`:

| relation | handling |
|---|---|
| `rag_lexical_stats_pending` | `hook` |
| `rag_lexical_df` | `hook` |
| `rag_lexical_corpus` | `hook` |
| `rag_lexical_stats_state` | `exempt` (tenant settings, no document reference) |

Hook: `public.rag_purge_hook_lexical_stats(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint` (0903, service_role only). The counters hold no document id, so the purge must call the hook **again after the chunk delete** in the same run, and `rag_purge_verify` must require `pending = 0` from `public.rag_lexstats_status(p_tenant_key)`.

## Enforcing tests

- `tests/rag-db/lexical-stats-purge-hook.test.mts` ("Phase 6.3 order ..."): both intermediate states of the two-call order.
- Phase 6.3's coverage test (06.3-19, `tests/rag-db/purge-store-coverage.test.mts`) fails on any public table with tenant data that is neither inventoried nor exempt, once it exists.

## If it is not done

A purged document's terms stay in the tenant's document frequencies and corpus length (no text, but vocabulary evidence of deleted content), and BM25 scores keep counting deleted chunks until the next rebuild.
