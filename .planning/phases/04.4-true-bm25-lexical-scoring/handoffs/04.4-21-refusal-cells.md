# 04.4-21 hand-off: refusal cells and the local reranker model `bm25-v3-tenant`

From plan 04.4-21 (D-56), for plan 04.4-22 and for any later default change of `RAG_RERANK_LOCAL_STATS`.

## What changed

Under `RAG_RERANK_LOCAL_STATS=tenant` the local reranker reports model `bm25-v3-tenant`, but only on a request where the tenant's
statistics served. In `pool` mode (the default) and on every fallback it reports `bm25-v2`, as today. The rank stage hands this served
model to the stage output, the trace detail and the refusal gate.

## Cells keyed to `local_bm25` today

`eval/config/refusal-thresholds.json` (read at 1643c8794, the commit of the rank-stage wiring):
- 6 cells in total. All 6 are `cohere` / `fake-quality-v1` (2 `calibrated` and 4 `insufficient_data`; source `fixture`).
- Cells with provider `local_bm25`: **0**, so none for `bm25-v2` and none for `bm25-v3-tenant`.

## Why no cell applies to the local reranker in any mode

`local_bm25` declares `scoreSemantics: 'relative'`. The threshold gate (`decideRefusal`, `src/lib/rag/refusal/gate.ts`) returns
`not_applied` with reason `relative_scores` for a relative reranker before it looks up a cell. So the similarity floor (or the
`legacy_rule` floor) decides today and after this plan, in both modes. Tested in `tests/rag/v2/rank-local-stats.test.ts` ("refusal
cells").

A future calibrated cell keyed `local_bm25|bm25-v2|…` would still not match `bm25-v3-tenant`. That is the 4.2 stale-cell rule: the floor
decides until a recalibration.

