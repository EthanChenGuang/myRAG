# 04.4-13 hand-off: running the real-set comparison (plan 04.4-15, task 3)

The command in plan 04.4-15 (one `lexical_compare --base-url ...` call for every arm) cannot work as written: a run against
`--base-url` never takes a run-config env (`rag_eval.harness_runner.merged_run_config` drops it for live runs), and no request
option or retrieval override selects the lexical scoring mode (no contract changes in this phase). The deployment's own environment
decides the scoring of an RRF arm. So the RRF arms run one deployment state at a time, and the tool checks every trace's
effective configuration (`rag_env`) against the arm and refuses a mismatch.

Eval project only (never prod). Steps:

1. Statistics: `npm run rag:lexstats -- enable --tenant <eval tenant key>`, then `rebuild` and `check --tenant <key>`.
2. Lexical alone (all arms in one call, the grid included):
   `node --import tsx eval/harness/lexical-leg-run.mts --golden <private eval set> --tenant <eval tenant key> --out eval/reports/phase-04.4-live/inputs/lexical-leg --k1 0.9,1.2,1.5 --b 0.5,0.75`
   (`NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` of the eval project in the environment; the output directory must be
   git-ignored). Without `--k1`/`--b` the arms are `ts_rank_cd` and `bm25`.
3. RRF arms: for each arm, set the eval deployment's environment, redeploy, then run
   `uv run --directory eval python -m rag_eval.lexical_compare --base-url <eval app URL> --arm <arm> --golden <private eval set> --out eval/reports/phase-04.4-live/inputs/compare [--k1 ... --b ...]`.
   - `rrf_ts_rank_cd`: `RAG_LEXICAL_SCORING=ts_rank_cd`, `RAG_RERANKER=none`.
   - `rrf_bm25` (no grid) or `rrf_bm25_k1=<k1>_b=<b>` (grid): `RAG_LEXICAL_SCORING=bm25`, `RAG_LEXICAL_BM25_K1=<k1>`, `RAG_LEXICAL_BM25_B=<b>`, `RAG_RERANKER=none`.
   - `RAG_EVAL_SECRET` must be set for the eval route. Keep the tokenizer switches the same for every arm; the report records them.
   - The grid k1 {0.9, 1.2, 1.5} x b {0.5, 0.75} is 6 bm25 deployments plus one ts_rank_cd deployment.
4. Compute: `uv run --directory eval python -m rag_eval.lexical_compare --from-reports eval/reports/phase-04.4-live/inputs/compare --lexical-leg-dir eval/reports/phase-04.4-live/inputs/lexical-leg --golden <private eval set> --out eval/reports/phase-04.4-live/inputs/compare [--k1 ... --b ...]`.
   The same `--k1`/`--b` lists as steps 2 and 3. Every arm needs every answerable dev item, and all arms must come from the same eval set.
5. Restore the eval deployment's environment (`RAG_LEXICAL_SCORING=ts_rank_cd`, its usual reranker).

Output (`lexical-compare.json`, `lexical-compare.md`) holds metrics, counts, hashes, config hashes and tokenizer switches only; copy
the metric tables into the README, not the item ids.
