# Phase 4.4 Plan 02: Lexical statistics store and change capture Summary

**Per-tenant BM25 statistics tables (0900) and inert definer statement triggers on document_chunks that stage signed deltas only for enabled tenants (0901).**

## Names

- Tables: `public.rag_lexical_stats_state` (tenant_key PK, status `building|ready`, enabled_at, rebuilt_at, compacted_at), `public.rag_lexical_stats_pending` (identity id, tenant_key, corpus, chunking_profile_id, language, sign ±1, lexemes text[], dl, created_at; index `rag_lexical_stats_pending_tenant_id_idx (tenant_key, id)`), `public.rag_lexical_df` (PK tenant_key, corpus, lexeme, chunking_profile_id, language; df), `public.rag_lexical_corpus` (PK tenant_key, corpus, chunking_profile_id, language; chunk_count, total_len). `corpus` is `CHECK (corpus IN ('chunks','translations'))`, default `chunks`; no positivity check on df or chunk_count.
- Function: `public.rag_lexical_dl(tsvector) RETURNS integer` (sum of `cardinality(positions)`, IMMUTABLE PARALLEL SAFE, `search_path = ''`, service_role only).
- Trigger functions and triggers (same names): `rag_lexstats_chunks_insert` (AFTER INSERT, NEW TABLE new_rows), `rag_lexstats_chunks_update` (AFTER UPDATE, OLD TABLE old_rows NEW TABLE new_rows), `rag_lexstats_chunks_delete` (AFTER DELETE, OLD TABLE old_rows), all `FOR EACH STATEMENT`.
- Membership predicate as written: `is_current AND status IN ('ready', 'variant') AND lexical_tsv IS NOT NULL AND lexical_tsv <> ''::pg_catalog.tsvector`.
- An update stages -1 (old) and/or +1 (new) for a row where either side is a member and membership, `lexical_tsv`, `tenant_key`, `chunking_profile_id` or `language` changed. Null language is stored as `und`.
- Each function returns before reading a transition table while `rag_lexical_stats_state` is empty, and joins to it on `tenant_key`.
