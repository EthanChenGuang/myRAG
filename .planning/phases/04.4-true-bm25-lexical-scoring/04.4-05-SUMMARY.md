Grant signature: `(text, text, public.vector, text[], integer, date, date, text[], uuid[], text[], text[], text[], text, numeric, numeric, text, jsonb, boolean, text[], boolean, date, jsonb, text[], double precision, double precision, integer)`; REVOKE from PUBLIC, anon, authenticated, GRANT to service_role. `SECURITY INVOKER`, `SET search_path = ''`, `rag_assert_tenant_key` first, no temp table.

Output: `leg = 'lexical'`, `rank` 1..n by score descending then chunk id, `lexical_score` = BM25 (real), `dense_mode = 'n/a'`, `similarity` = `1 - (c.embedding <=> $15)` under a `legacy_column` profile with a non-null embedding, else null (the 0856 expression).

## How it works

1. Argument checks: limits, k1, b, then the copied checks of 0856 (chunking override, scopes, version scope, identifiers, embedding profile).
2. Effective-profile map `{doc_type: profile_id}` (override, else active profile, else `legacy`) bound as `$24` and read with `pg_catalog.jsonb_each_text`.
3. Tokens cleaned exactly as `rag_lexical_tsquery` (non-empty, at most 255 bytes, no quote, backslash or whitespace, at most 64 distinct); the match tsquery is `rag_lexical_tsquery` of that same list.
4. Statistics (D-13), all under `p_tenant_key`: profile set = distinct effective profiles of the requested doc types (all six when none); `N`, `avgdl` from `rag_lexical_corpus` and `df` from `rag_lexical_df` over that set and, with `p_lexical_languages`, those languages plus `und`. `df` missing = 1, clamped to [1, N]; `idf = ln(1 + (N - df + 0.5) / (df + 0.5))`. IDF is computed once per token in PL/pgSQL and bound as arrays.
5. One `RETURN QUERY EXECUTE`: `q` (token, idf, tsquery), `cand` (filter + `$14` lexical-language clause + `@@`, ranked by `sum(idf * ts_rank(tsv, term, 0))`, `LIMIT NULLIF(cap, 0)`), `scored` (exact BM25 over `unnest(lexical_tsv)`), `top` (`ORDER BY score DESC, hid LIMIT p_lexical_limit`), then the 0856 `v_sel` projection.
6. The 0856 version-scope widening (`all`, `range`) is applied to the filter text with the same two `replace` calls.

## Deviations

1. **Order comparison tolerance.** Mathematically equal BM25 scores (for example tf/dl equal at b = 1) differ by one unit in the last place in both the SQL and the TypeScript reference, so the test compares rank by rank: the reference score of the returned chunk must equal the expected score at that rank within 1e-9, and the returned score must equal the reference within 1e-6 relative to max(1, score) (`lexical_score` is `real`, as in `hybrid_search_chunks`). Exact ties are asserted separately to be ordered by chunk id. The function itself orders by its float8 score, then chunk id, as planned.
2. **Statistics in tests** are inserted from a TypeScript recompute (bm25-search) or a SQL recompute (parity), because plan 04.4-04's rebuild function is not on this tree, as the plan allows.
3. **Task 3 has no RED commit.** It guards behaviour task 2 already delivers, so it passed when written; its ability to fail was shown by the mutation check above.
4. **Extra early returns** (unknown doc types, empty lexical-language list) and the NaN rejection for k1 and b, listed in key decisions.
