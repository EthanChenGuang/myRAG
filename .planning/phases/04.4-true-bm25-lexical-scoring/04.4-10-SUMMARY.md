# Phase 4.4 Plan 10: statistics maintenance after publish and relex Summary

**With `RAG_LEXICAL_SCORING=bm25`, every publish and relex keeps the tenant's lexical statistics current. With `ts_rank_cd` the write path makes no new call.**

## Hook

`afterLexicalWrite(deps: { db: () => RpcClient | null; config?: Pick<RagConfig, 'v2'>; timeoutMs?: number }, tenantKey: string): Promise<void>`

- **Mode.** It reads `config.v2.lexicalScoring.mode` when a config is given. Otherwise it lazily imports and reads `loadRagConfig(getRagDeps().ragEnv())`. Any failure counts as `ts_rank_cd`, which makes no call.
- **Calls under bm25.** First `rag_lexstats_enable`. Then `rag_lexstats_rebuild` when the state is `building`. Then one `rag_lexstats_compact` batch with `p_max_rows` 5000.
- **Timeout.** All the calls race one 5 s timer (`LEXICAL_WRITE_TIMEOUT_MS`). After a timeout the calls keep running in the database; the 0902 advisory lock orders them with any later caller.
- **Failures.** The hook never throws. An RPC error, a rejection, a timeout, a missing function or no admin client is logged once per process and tenant hash: `[Lexical Stats] <sha256[0:12]> <rpc> failed (<code>)`. The line holds no key, message or lexeme.
- **Answer shape.** A scalar answer can also arrive as one row keyed by the function name (the fake edge's shape). This goes through `scalarOf` from `cache/wire.ts`.

## Call sites

- `publishStage.run`, case `published`: after `clusterAfterPublish` and the `void afterPublish(...)`, with `{ db: () => ctx.deps.db() }` and the stage's tenant key.
- `runRelex` and `runStampedRelex`: before the final `done` line, `afterRelexWrites` calls the hook for each key of `report.tenants`, in sorted order. `dryRunRelex` and `dryRunStampedRelex` are unchanged.

## Schedule

`supabase/optional/lexical-stats-schedule.sql` adds the job `myrag-lexical-stats-compact`, running `*/5 * * * *` with the command `SELECT public.rag_lexstats_compact_all(5000);`.

- No setup or migration path applies the file.
- Without pg_cron, or without 0902, it prints a notice and changes nothing.
- The removal statement is in its comments.

No migration was added.

## Deferred

The first bm25 publish for a large tenant runs a full rebuild, which can exceed the 5 s bound. The write still succeeds and the rebuild finishes in the database. Running `npm run rag:lexstats -- enable --all` before turning on bm25 (04.4-09) avoids this; 04.4-13 (docs) should say so.
