# 04.4-06 UI review: lexical scoring controls

## What was reviewed

- Surface: the three controls plan 04.4-01 added to the "Phase 4 retrieval switches" box in `scripts/config-ui/index.html`. They are the select `RAG_LEXICAL_SCORING` and the number inputs `RAG_LEXICAL_BM25_K1` and `RAG_LEXICAL_BM25_B`, with their help lines. This plan adds the dependency note `#rag-lexical-scoring-needs-lexical` and the method `updateLexicalScoringControls()`.
- Contract: `04.2-UI-SPEC.md`. Section 5 gives the control shapes (a select is `select.select-bordered.w-full.max-w-xs` with `translate="no"`). Section 6.2 gives the combination notes: static, `hidden`, `role="status"`, never blocking a save, never the only place a dependency is stated. Section 10 gives the accessibility rules. D-39 means no new UI-SPEC.
- Method:
  - Impeccable critique from the pinned `reference/critique.md`, `reference/polish.md` and `reference/craft-floor.md`. The launcher was not used.
  - `web-design-guidelines`, from the pinned `references/command.md`, on the changed markup and script in `scripts/config-ui/index.html`.
- Render: a headless Chromium render of the box was attempted. This session's permission policy blocked it. The review is therefore code-based: the computed DaisyUI 4.4.24 classes plus the neighbours' markup. The behaviour is covered by `tests/ui/config-phase44-switches.test.ts`, which runs the real method body against stub controls.

## Impeccable critique (three controls only)

- **Flow and hierarchy:** the order (lexical switch, then scoring, then k1/b, then reranker) matches how the settings depend on each other. The two parameters sit in the same two-column grid as other numeric pairs in the card. Pass.
- **States:**
  - Before this plan the parameters looked editable under `ts_rank_cd`, where they have no effect. Now they are disabled and keep their values, so nothing is lost on save. Save reads `configManager.config`, not the form, so disabled fields still save.
  - `bm25` with the lexical leg off now shows a note.
  - Default, focus (DaisyUI focus ring), disabled (DaisyUI `:disabled` style) and the combination state are covered.
- **Copy:**
  - The note names the problem and the fix ("Turn on `RAG_LEXICAL_SEARCH` to use it"), in active voice and second person by implication. Code tokens are `translate="no"`.
  - The help line keeps the dependency on screen at all times, so the note is never the only place it is stated (spec section 10.3).
  - No example-domain words.
- **Craft floor:**
  - No new colour, component, icon or layout.
  - The note uses `text-base-content` at full strength, not `text-warning`, so its body text keeps 4.5:1 contrast. Tailwind's `flex` would override `[hidden]`, so the note does not use it.
  - Disabled inputs use DaisyUI's muted disabled style. WCAG 1.4.3 does not apply to disabled controls.

## Findings

| # | Source | Location | Finding | Fix |
|---|--------|----------|---------|-----|
| 1 | Impeccable (states) | `RAG_LEXICAL_BM25_K1`, `RAG_LEXICAL_BM25_B` | Parameters looked editable under `ts_rank_cd`, where they are ignored | `updateLexicalScoringControls()` sets `disabled` and `aria-disabled="true"` under `ts_rank_cd`; values are kept |
| 2 | Impeccable (states) | `RAG_LEXICAL_SCORING` | No signal when `bm25` is chosen with the lexical leg off (the server falls back to `ts_rank_cd`) | Static hidden note `#rag-lexical-scoring-needs-lexical` (`role="status"`, i18n key `RAG_LEXICAL_SCORING.needsLexical`), shown only for that combination; the select stays editable |
| 3 | web-design-guidelines (Accessibility) | `RAG_LEXICAL_SCORING` `aria-describedby` | A first draft listed the note id statically. `aria-describedby` reads hidden targets, so screen readers would have announced the note while it was hidden | The script adds the note id only while the note is shown and removes it otherwise |
| 4 | web-design-guidelines (Forms: autocomplete) | `RAG_LEXICAL_SCORING` | Select had no `autocomplete` | `autocomplete="off"`, as on the neighbour `RAG_ATTRIBUTE_FILTER` |
| 5 | web-design-guidelines (Forms: placeholders end with `…`) | `RAG_LEXICAL_BM25_K1`, `RAG_LEXICAL_BM25_B` | Placeholders `1.2`, `0.75` | `1.2…`, `0.75…`, as on the neighbours `RAG_SEMANTIC_CACHE_*` |

Checked with no finding:
- programmatic labels (`<label for>`)
- help lines through `aria-describedby`
- `type="number"` with `inputmode="decimal"`, `min`, `max` and `step`
- `name` equal to `id`
- `translate="no"` on code tokens
- focus visible (DaisyUI rings, no `outline-none`)
- hit areas (full-width DaisyUI controls, 3rem high)
- native select colours set by DaisyUI `select`
- no animation
- no long-content overflow (`max-w-prose` help)
- static text only (the `config-ui-xss` test passes)
