# 06.3-01 Summary: withdrawn citation and stale_index_drop contracts

Two shared contract changes land before any code writes them. `CitationRecord` can carry a withdrawn marker with an empty quote, and `validCitations` keeps such a citation. `RagTrace` has an optional `stale_index_drop` counter.

## Behaviour changes

- A stored citation with `withdrawn: true`, `quote: ''` passes `CitationRecordSchema` and `pickAnswerMetadata` / `extractStreamAnswerMetadata` keep it. Before, it was dropped silently.
- A citation with an empty quote and no flag (or `withdrawn: false`) is still refused by Pydantic and dropped by `validCitations`.
- Citations and traces written before this phase are unchanged: no new keys appear on serialization or Zod parse.
- `AnswerRecord.documents` accepts `withdrawn`. Nothing produces it yet (06.3-06).
- The cache contracts (`CachedAnswer`, `CacheCheckResponse`, `CacheStoreRequest`) embed `CitationRecord`, so their generated schemas also gained the two optional keys.
