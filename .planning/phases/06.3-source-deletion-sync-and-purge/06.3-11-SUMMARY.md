# Phase 6.3 Plan 11: scheduled source reconcile Summary

**Providers without a change feed now get a scheduled full-listing reconcile: `runSourceReconcile` lists due connections oldest first within a deadline, removes only from complete listings through the guarded `removeOrphans`, records every incomplete or failed listing without removing anything, and raises the overdue alert only after a scheduled run has had its turn at a connection. The CLI `npm run rag:source-reconcile` and `POST /api/internal/rag/source-reconcile` (behind `RAG_SIDECAR_SECRET`) both call it.**

`exec/06.3-11` from `origin/exec/06.3-05` (51730ae7). No other branch merged.

## What was built

- **Run (D-06, D-31).** Loads `nango_connections` with `status = 'connected'` (optionally `id = connectionId`), keeps the due ones (`last_full_reconcile_at` NULL or at least `RAG_SOURCE_RECONCILE_INTERVAL_DAYS` old; NULL first, then oldest). Per connection, while `now < start + deadlineMs` and the signal is not aborted: `listFiles(row)` (default `listConnectionFiles`); thrown → `failed` run (`error_code = listing_failed`); `complete !== true` → `incomplete` run with the listed count; complete → `removeOrphans(row, fileIds, 'scheduled', { complete: true, admin, outcome })`, which applies the D-09 guard and records the run (completed advances `last_full_reconcile_at` in 0721). A throw from the removal records `failed` (`removal_failed`). Due connections left when the deadline passes are counted as `skipped`. A failed connection read throws `SourceReconcileDatabaseError`.
- **Age alert (D-10, D-39).** After the loop, the connections are read again; for each one older than `RAG_SOURCE_RECONCILE_MAX_AGE_DAYS` (from `last_full_reconcile_at`, else `connected_at`) that has at least one `scheduled` run in `rag_source_reconcile_runs`, `raiseSourceAlert(row, 'overdue', { days, limit })` is called once per run. A connection 30 days old that completes its first scheduled run is not alerted; one whose first attempt is incomplete is alerted in that same run. If the runs read fails, age is not evaluated (logged).
- **State (UI-SPEC 6.3, 8.1).** `connectionReconcileState` is pure: `paused` (open, unexpired `awaiting_confirmation` run, or the row status when no run is given) comes first and can stand with `overdue` (needs a scheduled attempt); otherwise `failed` / `incomplete` with the run's `error_code` (defaults `listing_failed` / `listing_incomplete`), `not_run` before the first scheduled attempt, `in_step` after a completed reconcile. Returns `daysWithoutReconcile`.
- **Days parsing.** `parseReconcileDays`: a number in (0, 3650], else 7, with one `[RAG Config]` warning per variable.
- **CLI (D-30).** `--connection <uuid>`, `--max-seconds 1..600` (default 50); unknown/repeated option, bad uuid or range → exit 2 with the usage; no `SUPABASE_SERVICE_ROLE_KEY` → 1; any failure of the run → 1; success prints one line `[Source Reconcile] processed=… removed=… paused=… incomplete=… failed=… skipped=… overdue=…` and exits 0. Entry guard with `loadDotenv` and SIGINT as in the relex CLI.
- **Route (D-30, D-42).** `runtime = 'nodejs'`, `maxDuration = 60`; `checkSidecarSecret` first (unset secret refuses everything — the production gate, no new variable); optional strict body `{ connection_id?: uuid }` (`zod/v3`; malformed JSON, unknown field, non-uuid → 400); one `runSourceReconcile({ deadlineMs: 50_000, connectionId, signal: request.signal })`; 200 `{ success: true, …counts }` with `Cache-Control: no-store`; a throw → 503 `{ success: false, error: 'reconcile_unavailable' }`. Logs counts only.
- `vercel.json` unchanged; no cron entry.

## Deviations

1. `src/lib/nango/sync-manager.ts` (not in `files_modified`): `removeOrphans` and `deleteOrphanedDocuments` take an optional `outcome: { paused }` filled after the guard, so the run can count pauses. Callers that do not pass it are unchanged.
2. The result also carries `overdue` (count of alerts raised); the route answer spreads it next to the listed counts.
3. The plan says `removeOrphans(row, fileIds, 'reconcile')`; the 06.3-05 signature takes `'sync' | 'scheduled'` and passes `reconcile` to `applySourceDeletions` itself, so the call uses `'scheduled'` (the run is recorded with origin `scheduled`).
4. Incomplete listings record the `incomplete` run directly and never reach `removeOrphans`, so an incomplete listing can never pause or remove.
5. No migration: 0720/0721 hold every column and function used. No migration number reserved (the orchestrator asked to claim a 07xx number; this plan needs none, so none was taken to keep the block free for 06.3-09/12/13).
6. No new env variable: the interval and age variables are already in the five locations from 06.3-02.
