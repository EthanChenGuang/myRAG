<objective>
Apply the owner decision of 2026-11-25 on DATA-23 to the in-sync orphan removal: every connector, including Dropbox, Box, Confluence and any provider served by the generic Nango path, removes or soft-deletes orphans only after a complete listing, and every full-listing removal goes through the mass-delete pause (D-48, which resolves the known defect D-31 recorded).

Purpose: plan 06.3-05 added completeness flags to the non-Drive listings but, per the earlier D-31, left the default path unguarded: today a cut Dropbox page, a records call with a next cursor, a failed records call (which returns an empty list) or a failing folder in multi-folder mode can remove documents that still exist at the source. The owner has decided this is a defect to fix in this phase, not a recorded limitation. This plan closes it for every deletion mode, including the NULL default, so the D-28 byte-for-byte rule now holds for complete listings only (the characterization fixture is a complete Google Drive listing and does not change).
