## What was built

- **`syncSharePointConnection(connectionId, admin, hooks, options)`** (D-21, D-22, D-40). Reads its own `nango_connections` row (owner, mode, `metadata`); under unified refuses an owner that cannot be a tenant. Selection from `metadata.source_scope` (sites, drives, folders with `driveId`); drives read = selected drives ∪ drives of selected folders ∪ `/v1.0/sites/{id}/drives` of selected sites. Per drive: read the stored link (`readDeltaCursor`, resumable `next_link` preferred), `GraphDeltaFeed.read` (a 410 clears the row through `onResync`), merge the parent map with the stored folder map, then apply in order:
  1. deleted files, plus synced files whose stored parent chain reaches a deleted folder → `applySourceDeletions(connection, ids, 'change_feed')` in batches of 50;
  2. in-scope files → skipped when the sync record is `completed` with the same eTag (before download, `markSourceSeen` still stamps), else sync-record upsert `processing` with `metadata.drive_id/site_id/parent_id/modified_at`, Graph download through `fetchFileContent`, `processDocumentWithMetadata` with `source: 'nango'`, `sourceProvider`, `sourceFileId` = item id, `sourceConnectionId`, owner-only `accessKeys`, then `markSourceSeen` (modifiedAt, eTag) and record `completed` with `metadata.etag`; out-of-scope items are ignored; unsupported extensions count as skipped.
  3. Commit: `commitDeltaCursor` per drive only when that drive's removals and ingests had no failure, and for a full listing only when its guarded removal was not paused and did not fail. Then the folder parent map and the interrupted-enumeration ids are written back to the connection metadata (merged with other keys).
- **Full listing (D-09, D-21, D-22).** A read that finishes a token-less enumeration is a full listing; when it was resumed, its present set is the union of the stored ids of the earlier reads and this read (06.3-08's note). Candidates = synced records (`completed`/`processing`) of the fully listed drives absent from the present set (missing or now out of scope), plus — once every selected drive was fully listed and the site drives resolved — records of drives no longer selected. They go through `guardListingRemoval` (origin `sync`, `complete` only when the whole selection was listed, so `last_full_reconcile_at` advances only then) and `applySourceDeletions(…, 'reconcile')`. A pause removes nothing, raises the alert and leaves the link uncommitted, so the next sync enumerates again.
- **`listSharePointFiles(connection, admin, options)`** (D-31). Token-less enumeration of every selected drive with a throwaway cursor; never reads or writes `rag_source_delta_tokens`; returns in-scope and unknown file ids, `complete: false` when a deadline, a failed site listing or an error cuts it.
- **sync-manager.ts.** `syncDocumentsForConnection` checks `isSharePointProvider(provider)` first: switch off → zero stats with no Graph, Nango or database call; on → `syncSharePointConnection` with the shared helpers (`markSourceSeen`, `isSupportedFile`, `ownerOnlyLabel`, `processDocumentWithMetadata`, `fetchFileContent`). `listConnectionFiles` returns `{ fileIds: [], complete: false }` for the two providers with the switch off, `listSharePointFiles` with it on. `ListableConnectionRow` gains optional `metadata`.

## Deviations

1. **One RED/GREEN pair for both tasks** (shared module and test file), as in 06.3-08.
2. **`removeOrphans` not used** for the full listing: it returns a count and hides the paused decision the commit depends on; the same two functions it wraps (`guardListingRemoval`, `applySourceDeletions` with `reconcile`) are called directly with the same semantics.
3. **State storage** in `nango_connections.metadata` (`source_parents`, `source_enumeration`) rather than a new table; capped (see key decisions). Over the parent cap the map is dropped (walks become unknown, fail closed); over the id cap the enumeration is not used as a full listing.
4. **Function signature**: `syncSharePointConnection(connectionId, admin, hooks, options)` takes the connection id and reads the row itself (owner never from the caller), and takes the sync-manager helpers as `hooks` to avoid an import cycle.
5. **Deleted folders**: files under a deleted folder (stored parent chain) are also removed through change_feed, since Graph may report only the folder.
6. **Test helper**: `createNangoMemoryAdmin` gains opt-in `storeWrites` and `maybeSingle`; existing callers are unchanged (default off).

## Threat model

- T-06.3-30 (lost deletions): link committed only after a failure-free apply; tests cover a failed removal and a failed ingest leaving the stored link.
- T-06.3-31 (mass removal): full listings and narrowed selections go through the D-09 guard; the 8-of-10 test pauses with nothing removed and no commit; unknown scope never removes.
- Tenant isolation: owner and mode come from the connection row only; deletions go through the one entry point, which resolves the tenant from the owner.
- T-06.3-SC: no package added.
