# 06.3-07 Summary: source recheck before rerank on the v2 path

With `RAG_SOURCE_RECHECK=true`, the v2 path checks the deduplicated candidates against Supabase before rerank. It drops any candidate whose chunk or document is no longer current and ready in the tenant. The trace carries `stale_index_drop`. With the switch off, nothing changes.

## Behaviour changes

- Switch off (default): the v2 path does not enter the stage. Traces, retrieval config hashes and metrics are unchanged; both `test-rag` gates pass.
- Switch on: `runSearchStages` runs `source_recheck` after `dedupe` and before rerank. Stale ids are removed from the rank input. `stage_counts.source_recheck` carries `{ stale_index_drop, checked }`. The search output and the retrieval result carry `sourceRecheck: { checked, dropped }`, and the eval trace sets `stale_index_drop` to `dropped`.
- If the recheck fails or times out, the stage is `skipped` and the result is `degraded` (`source_recheck_failed` / `source_recheck_timeout`). The candidates continue unchecked, no marker is set and the request succeeds.
- Legacy chat, legacy voice, media and overview paths are untouched (plan 06.3-27).

## For plan 06.3-27

The shared stage helper is `runSourceRecheckStage` in `src/lib/rag/retrieval/source-recheck.ts`. It is generic over the candidate type (`chunkIdOf`), records the stage, filters, logs and returns `{ items, marker }`. Set `RetrievalResult.sourceRecheck` from `marker`. The low-level call is `sourceRecheck(scope, chunkIds, { client, signal })`.
