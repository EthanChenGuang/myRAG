# 06.3-28 Summary: every connector removes orphans only after a complete listing (D-48)

No connector removes or soft-deletes orphans any more after a listing that did not complete, in any deletion mode (NULL, `soft`, `purge`). This covers Dropbox, Box, Confluence and every provider that reaches the generic Nango path. Every full-listing removal still goes through the mass-delete pause. **The D-31 known defect recorded in 06.3-05 is resolved by D-48.** There is no migration, no new switch and no new env variable.

## Behaviour changes

- `deleteOrphanedDocuments(connectionId, userId, currentFileIds, admin, connection, listingComplete, { origin?, outcome? })`: `listingComplete` is a required boolean. When it is not `true`, the function returns 0 before it reads the sync records. It does three things and nothing else:
  - it logs one `logger.error('Nango', 'Orphan deletion skipped: listing incomplete', { connectionId, provider })` line, with ids only;
  - it records one run through `recordReconcileRun(…, origin ?? 'sync', 'incomplete', { listed })`, and 0721 then sets `last_reconcile_status = 'incomplete'` and leaves `last_full_reconcile_at` alone;
  - it never calls `guardListingRemoval` or `applySourceDeletions`.

  A bookkeeping failure is logged as a warning and never turns the skip into a removal.
- Before this change, an incomplete listing in NULL mode went through the guard, and a 6-of-10 cut could raise a pause with candidate ids that were not real orphans. Now an incomplete listing never reaches the pause.
- Callers:
  - The Drive single-folder and multi-folder callers pass `listing.complete` and `listingsComplete`. Both are always `true` there, because their outer checks stay, so their behaviour and log lines are unchanged.
  - The generic multi-folder caller passes `listingsComplete`: a folder that throws or reports `complete: false` makes the whole listing incomplete.
  - The generic single-folder caller passes `listing.complete`.
  - `removeOrphans` passes `options.complete ?? true` and its own origin, so the scheduled reconcile of 06.3-11 is unchanged.
- The listing functions still return the files they found, so ingestion of listed files continues. Only removal is skipped.
- D-28: the complete-listing path is unchanged. `tests/fixtures/nango/default-deletion-calls.json` has no diff from the plan start, and the characterization replays in all four pipeline × async combinations.
