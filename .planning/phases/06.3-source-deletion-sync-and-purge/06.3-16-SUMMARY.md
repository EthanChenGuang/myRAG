# Phase 6.3 Plan 16: Source sync admin routes Summary

**Admins can list the connections of the tenants they administer with their reconcile state and open paused run, set each connection's deletion mode, and confirm or dismiss a paused mass removal; the in-app connector card gets a read-only `reconcile_state`. No route starts a reconcile.**

## What was built

- **Library (`src/lib/nango/source-sync-admin.ts`, 4-space, `logger` tag `Source Sync`).** Calls the 0721 functions on the service-role client; only the fixed SQL words `not_found`, `invalid_argument`, `run_not_pending`, `confirmation_expired` leave the module, anything else is `unavailable` (code logged, message never echoed).
  - `confirmReconcileRun`: `rag_source_reconcile_run_decide(p_actor, p_run_id, 'confirm')` (24-hour window and tenant check in SQL) → loads the connection row by the returned `connection_id` and `owner_user_id`, checks `connectionTenantKey(row) === tenant_key` → `applySourceDeletions(connection, batch, 'admin')` in batches of `DELETION_BATCH_SIZE` (50) over all candidates (the admin origin caps one call at 50) → `rag_source_reconcile_run_finish(run, removed, failed)`. The mode is the connection row's `deletion_mode`. A connection that cannot be read or does not match the run's tenant removes nothing (503).
  - `dismissReconcileRun`: decide `dismiss`; returns `dismissed` or `expired`.
  - `setDeletionMode`: `rag_source_sync_set_deletion_mode`; future deletions only, nothing is purged now (D-08).
  - `listSourceSyncConnections`: `rag_source_sync_admin_connections(p_actor, limit, offset)`; state from `connectionReconcileState` with the newest run and the scheduled-attempt flag read from `rag_source_reconcile_runs` by the SQL-authorised connection ids; owner label from the auth user record (email, then name, else the id); up to 20 file names of the paused run's candidates from `nango_sync_records` (filtered by the connection's Nango id and owner), `names_not_sent = candidate_count − names sent`; page rows ordered paused, overdue, failed/incomplete, rest, then provider name, owner label.
  - `cardReconcileStates`: the same state reduced to `ok | overdue | paused` (paused first) for the session user's rows; `null` when the runs cannot be read.
- **Routes** (`runtime = 'nodejs'`, `checkAdmin` first, only `admin.userId` is the actor, `zod/v3`, `Cache-Control: no-store`, one `[RAG Admin]` line with ids and counts). The confirm and dismiss routes accept an empty body or `{}` (strict; any key, e.g. an actor, is 400).
- **`GET /api/nango/connections`** adds `reconcile_state` to each connection when the runs were read; when they were not, the field is left out and the card renders as today. Every other field is unchanged.

## Wire contract for plan 06.3-18

`GET /api/rag/admin/source-sync/connections?limit=1..100 (50)&offset=0..1000000 (0)` (any other query key → 400):

```json
{
  "success": true,
  "total": 3, "limit": 50, "offset": 0,
  "limits": { "max_age_days": 7, "max_delete_share": 0.3 },
  "items": [{
    "id": "<nango_connections.id>",
    "provider": "dropbox", "provider_name": "Dropbox",
    "owner": { "id": "<uuid>", "label": "<email | name | id>" },
    "workspace_key": "u:<uuid> | o:<uuid> | s:default",
    "status": "connected",
    "document_count": 3,
    "connected_at": "<iso>", "last_full_reconcile_at": "<iso> | null",
    "states": ["paused", "overdue"],
    "reason": "listing_failed | listing_incomplete | <error_code> | null",
    "days_without_reconcile": 12,
    "deletion_mode": "soft | purge | null",
    "paused_run": {
      "id": "<run uuid>", "found_at": "<iso>", "expires_at": "<iso>",
      "candidate_count": 25, "total_count": 40,
      "file_names": ["<up to 20>"], "names_not_sent": 5
    }
  }]
}
```

`paused_run` is `null` when no run is awaiting confirmation. States: `in_step`, `overdue`, `paused`, `failed`, `incomplete`, `not_run`.

| Call | Success | Failures |
|------|---------|----------|
| `PUT …/connections/{id}/deletion-mode` body `{ "mode": null \| "soft" \| "purge" }` (strict) | 200 `{ success: true, id, deletion_mode }` | 400 (bad mode, extra key, missing mode, non-uuid), 404 `{ success: false, error: 'not_found' }` (unknown or other tenant), 503 |
| `POST …/runs/{id}/confirm` (empty body or `{}`) | 200 `{ success: true, removed, failed }` | 409 `confirmation_expired`, 409 `run_not_pending`, 404 `not_found`, 400, 503 |
| `POST …/runs/{id}/dismiss` | 200 `{ success: true, status: 'dismissed' \| 'expired' }` | 409 `run_not_pending`, 404 `not_found`, 400, 503 |
| `GET /api/nango/connections` | each connection gains `reconcile_state: 'ok' \| 'overdue' \| 'paused'` (absent when the runs read failed) | unchanged |

Guard failures use `adminDenied` (401/403/503, `{ success: false, error }`). The 409/404 bodies carry the code in `error`.

## Deviations

1. Ordering is applied within the page: `rag_source_sync_admin_connections` pages by `connected_at DESC`, so the paused/overdue/failed grouping (UI-SPEC 6.3) is exact for one page (≤100 rows) but not across pages. No SQL change in this plan.
2. The confirm path calls `applySourceDeletions` in 50-id batches, because origin `admin` caps one call at `DELETION_BATCH_SIZE` and a paused run can hold up to 2000 candidates.
3. Confirm and dismiss accept an optional empty JSON object (quarantine release pattern); any key is 400.
4. Owner label lookup is inline in the module (auth user email, then name), mirroring `displayUsers` in `src/lib/rag/ingest/approval/admin.ts`, which is not exported from `@/lib/rag`.
5. `files_modified` matched; no migration, no new env variable, no package.
