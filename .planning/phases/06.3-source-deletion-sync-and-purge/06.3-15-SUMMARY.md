# 06.3-15 Summary: one-transaction lineage purge, audit and verification

`rag_purge_lineage` now removes every version of a lineage from every database store in one transaction. It also writes an audit row that holds only ids and hashes, and it returns the storage keys for the app to remove after commit. `rag_purge_verify` reads the version ids and hashes back from the audit row and reports what is left in each store. Read functions give admins their tenants' purge records, and tombstones keep an admin-purged connector file from being synced back.

## Task 1 decision (D-11, one-way)

**option-a**: an irreversible purge in one transaction, with an audit row and a verification query. The owner pre-authorized this choice (plan `auto_select="option-a"` plus the standing rule "decide by the recommended option"). Undo cost: purged rows cannot be restored, and the audit row records only ids and hashes. Purge tests ran only on PGlite fixture databases. No production or eval project was touched.
