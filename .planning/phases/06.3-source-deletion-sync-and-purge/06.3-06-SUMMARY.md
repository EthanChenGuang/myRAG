# 06.3-06 Summary: withdrawn sources in chat

A withdrawn source now renders as a neutral marker everywhere a citation shows. The server's answer record decides. The sources panel shows a dashed empty frame with "Source withdrawn", the detail line and, when known, the date. The citation chip keeps its number and click, turns grey and is announced as withdrawn. Text that a browser still holds for that citation is never rendered.

## Behaviour changes

- `/api/rag/answers` and `/api/rag/answers/{id}`: `documents[id]` is `withdrawn` when a stored citation of that document has `withdrawn: true`, even if the documents row is gone or still current.
- `citationDisplayEntries`: a citation flagged withdrawn, or whose document the map reports withdrawn, gives `quote: ''`, `linkDocumentId: null`, `unavailable: false`, `withdrawn: true`, `withdrawnAt` or null. Every other entry gains `withdrawn: false, withdrawnAt: null` and is otherwise unchanged.
- Sources panel: a withdrawn citation shows the muted number badge, no blockquote, the dashed frame, the detail line and the date sentence. It also gets `data-citation-withdrawn="true"`. The amber "updated or removed" line is not shown. Document entries of a withdrawn document show the frame instead of their snippet and are never links.
- Citation chip: with `withdrawn` it uses the grey tone (`hover:bg-gray-500/25`) and `aria-label`/`title` "Show source {n} (withdrawn)". Without the prop the markup is byte-identical to before (tested).
- Shared chats render through `SharedChatLayout` → `ChatMessage` and use the flag stored in message metadata. There is no answer record there, so the flag is the only signal.
- Nothing writes `withdrawn` yet (06.3-10). Until it does, no current record shows any of this, so with no withdrawn data the chat output is the same as before.
