## Deviations

1. **Expired state persistence.** The plan says a late confirm "raises confirmation_expired and the run becomes expired". A raised exception rolls back the function's own UPDATE, so both cannot happen in one call. The confirm raises `confirmation_expired` (the contract plans 16/18 map to 409); the run is written `expired` by the next `rag_source_reconcile_run_record` of that connection, the next `rag_source_sync_admin_connections` read of its tenant, or a `dismiss` past the window (which returns status `expired`). An awaiting run past `expires_at` is never confirmable in the meantime. Test: `a confirmation more than 24 hours after the run …`.
2. **0410 entries.** Added six guarded `to_regprocedure` entries to `supabase/migrations/0410_security_definer_rpc_grants.sql` (service_role-only section, inserted just before the `rag_purge_hook_identifiers` block so it does not touch the lines 06.3-07 changed). Required by `tests/rag-db/search-rpc-grants-pglite.test.mts` (upgraded-database lockdown); same practice as 06.3-07 (0723) and 04.2-03.
3. **Migration-number reservation commit.** Comment-only stub files for 0720–0722 were committed and pushed first so other executors see the numbers as taken; their bodies came in the task commits. Numbers checked on every origin branch: 0723 (06.3-07) and 0724 (06.3-10) were taken, 0720–0722 free as the plan named.
4. `rag_source_reconcile_run_finish` also re-checks the stored tenant key with `rag_ingest_assert_tenant_key` (a run of the other deployment mode cannot be finished).
