Every PGlite test applies every migration, so a plan's tests only see the migrations of the plans before it; the dependency edges guarantee that order.
- D-36 order: the contract change and `validCitations` (06.3-01, wave 1) and the display (06.3-06, wave 2) come before the first SQL that writes the withdrawn flag (06.3-10, wave 3).
- `deletion_mode = 'purge'`: 06.3-05 delivers the NULL and `soft` arms; the `purge` arm needs the purge library (06.3-20) and is added by 06.3-21 (wave 6). Between those waves a `purge` connection's batch is reported failed with its sync records kept, which is today's retry semantics.
- Phase 7 edits shared files (`eval_run.py`, generated contracts, `pipeline.ts`, `v2/stages/search.ts`, the run route, the boundary script, the five config files). Phase 6.3 edits them by symbol and regenerates generated files after every rebase.
