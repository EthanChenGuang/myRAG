<objective>
Recheck every retrieval candidate against Supabase after search and fusion and before rerank (RET-14, D-19, D-38), behind `RAG_SOURCE_RECHECK`, off by default, with the drop count on the trace.

Purpose: an index row that missed a delete, an undrained outbox or an in-flight purge must never reach the context. On pgvector the search RPCs already filter currency; the recheck closes the window and the exact-id leg. The external-backend form (Phase 7's `rag_validate_chunks`, D-20, D-38) is plan 06.3-14.
Output: migration 0723, the recheck helper, the conditional stage in every pipeline path, the trace field and the boundary rule.

Choices recorded here: stage failure policy `'skip'` (Open Question 7); stage timeouts 1000 ms in the standard tables and 300 ms in the voice table (RESEARCH A7, measured at live verification); the function is `SECURITY DEFINER` per D-02 (its analog `rag_cache_invalidate` is `INVOKER`) and uses the search-side guard `rag_assert_tenant_key` per D-43; if Phase 7's `rag_servable_chunks` view is on trunk at execution, read it but do not re-implement chunking-profile servability (a variant or legacy-fallback chunk stays a valid candidate).
