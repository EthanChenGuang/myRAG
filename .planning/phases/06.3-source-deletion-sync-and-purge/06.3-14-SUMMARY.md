## Tests (tests/rag/backend-recheck-skip.test.ts, 9 passed)

These run end to end through `runRetrieval` under `RAG_PIPELINE=v2`, using Phase 7's fake external store (`setExternalBackendForTests`) and a pgvector fixture:

2. qdrant with `RAG_SOURCE_RECHECK=false`: the recheck is forced and `stale_index_drop` is 1.
3. weaviate on the voice profile (`RAG_RETRIEVAL_BACKEND_VOICE`) with the switch off: forced, no 6.3 query.
4. Fallback to pgvector (readiness `stale`) with the switch on: the 6.3 stage runs once (`stale_index_drop` 1, `checked` 3) and the search span has no `stale_index_drop`.
5. Fallback with the switch off: no stage and no marker.
6. pgvector with the switch on: one `rag_source_recheck` call, and the stale candidate is gone (as in 06.3-07).
7. pgvector with the switch off: no stage and no marker; the span attributes are `{ backend: 'pgvector', tenant_validation_dropped: 0 }`.
8. Across these cases, exactly one recheck query per request (the external re-validation or the 6.3 query).
9. "zero drops" on qdrant: the only RPC is readiness. No 6.3 query, no `Source recheck` / `[RAG Security]` / `[Vector Sync]` log line, no repair scheduled.
