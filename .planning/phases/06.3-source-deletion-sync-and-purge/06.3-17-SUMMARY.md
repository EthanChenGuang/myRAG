## What was built

**Task 1 — tracer (D-22, D-24, D-26).**
- `GET /api/config/connectors`: `supportedProviders()` adds `sharepoint-online` and `one-drive` only when `isSharePointEnabled()`. A `connector_config` row is used when present, otherwise a default entry (enabled, shown, `PROVIDER_CONFIG` display name and neutral description). With the switch off the response is unchanged, even when rows for the two providers exist. PUT uses the same list.
- `connectors-config.js`: `attachSharePointConnections()` runs only when the server listed one of the two providers. It reads `/api/nango/connections` and sets `user_connection` (`connected`, `connection_id`, `source_scope`, `deletion_mode`) for those two only. A connected card gets one dashed button with `bi-diagram-3`, labelled "Choose sites, libraries and folders" or "Choose libraries and folders" (OneDrive). Once a selection is saved the button shows "Sites: a, libraries: b, folders: c" (OneDrive "Libraries: b, folders: c") in `text-success font-medium`. Sync stays disabled until a selection exists, with the hint "(choose what to sync first)". The selection is saved through `nangoClient.updateConnection(provider, { sourceScope })`, which is the existing PATCH call.
- `index.html`: one script tag right after `pickers/notion-page-picker.js`.

**Task 2 — picker states and grid.** `SharePointScopePickerModal`:
- **Layout:** fixed title "Choose what to sync", size lg, empty host. Breadcrumb `nav[aria-label=Location]` with `truncate max-w-40` names and their full `title`.
- **Levels:**
  - The Sites search appears on the Sites level only: visible label, 300 ms debounce, at least 2 characters.
  - Each level lists checkbox rows with Open buttons that carry the item name. A folder without sub-folders has no Open button.
  - A level with more items gets Load more (with the cursor).
  - The list scrolls in `max-h-96`, and focus moves to the hidden level heading with the count.
- **States:** loading (spinner, level text, `aria-busy`); the empty sentences of 12.6, with the query rendered as text; throttled (429) and load-failed, each with Reload list; sign-in (401/403) with Close picker.
- **Selection rules:**
  - Ancestors cover descendants: checking an ancestor removes its selected descendants.
  - A covered row is checked and disabled, with "Included by {name}".
  - The summary reads "Selected: …" or "Nothing selected". Show selection lists each item's path with a labelled Remove button.
  - The narrowing warning names the connection's mode words.
- **Saving:**
  - The dismiss button reads Close picker or Discard changes, depending on whether the selection changed.
  - Save selection is disabled while nothing changed and while saving ("Saving…").
  - Escape, the backdrop and ✕ do nothing while saving.
  - A failed save keeps the modal open with the `role="alert"` line. Success closes the modal and shows "Selection saved for {provider}.".
- **Grid:** `connector-grid.tsx` now renders `connectorGridProviders()`, which appends the two providers when `isSharePointEnabled()`. `needsFolderSelection` is unchanged (false for them), and no picker was added to the app.

- Switch on: the two providers appear in the Config UI list and the app grid. In the Config UI, a connected card shows the selection button.

## Deviations

1. **Session connection fetch.** `GET /api/config/connectors` deliberately returns no `user_connection` (asserted by `tests/api/config-admin-routes.test.ts`), so no card in the Config UI ever shows "Connected" today. To give the SharePoint card a connected state, the tab reads the operator's own row from the session-scoped `/api/nango/connections`, for the two providers only. The same gap for the other providers is listed under Deferred.
2. **Save body.** It carries `parentId` on drives (site id) and on nested folders (parent folder id). The plan sketch showed `drives: [{ id, name }]`. The 06.3-13 schema accepts `parentId`, and coverage needs it when a saved selection is reopened.
3. **Sign-in sentence.** Picker sign-in copy is new, because 12.6 names none (decision above).
4. **Sync hint.** The hint for these two cards reads "(choose what to sync first)" instead of the folder/file wording, which would be inaccurate for sites and libraries.
5. **Commit split.** Task 1 and Task 2 share the picker file, so the picker landed whole in the Task 1 commit; the Task 2 commit holds the grid change.
