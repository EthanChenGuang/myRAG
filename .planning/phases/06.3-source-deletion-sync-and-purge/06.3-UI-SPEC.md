## 0. Findings that shape this contract (read first)

Facts from the code and from research. Each one changes what the UI can show or do.

1. **None of this phase's admin routes exists yet.** `src/app/api/rag/admin/` has no source-sync or purge route. Section 8.1
   lists what each view needs. Only the purge path `POST /api/rag/admin/documents/[id]/purge` is fixed (D-34). Every other
   path, field and code name in this file is a **proposal to the backend plans**; the behaviour it supports is the contract.
2. **Two design systems.** The Config UI is a static page with DaisyUI 4.4.24 over the Tailwind Play CDN and Bootstrap Icons.
   The app is Next.js with shadcn-style local components over Radix and lucide icons. Tokens are declared per surface
   (sections 2 to 5 and 13) and never mixed.
3. **The Connectors tab has no per-connection list.** It shows providers, the operator's own connection and totals per
   provider (`/api/config/connectors`). Deletion mode and reconcile status are per connection, so they get a new panel in RAG
   administration that reads through `ragFetch` with the admin session, like the sibling panels (RESEARCH, responsibility map).
4. **A purge record holds ids and hashes only** (D-12): never a file name, a title or text. The records view therefore cannot
   show which file a record was about by name. The file name is on screen only while the purge dialog that started the purge
   is open, because the browser already had it from the Documents table.
5. **The browser cannot start a reconcile.** D-30 gives a CLI (`npm run rag:source-reconcile`) and an internal route behind
   `RAG_SIDECAR_SECRET`. No admin route starts one, so the UI never shows a "Run now" button; it names the command and the
   existing Sync button under Connectors.
6. **An alert may exist only as a status on the connection row** (D-10: the OBS-03 store is used only if Phase 5.3 is on
   trunk). The UI derives Overdue and Paused from the connection list, never from an alert feed.
7. **Delete and Purge will sit side by side** in the Documents table. `DELETE /api/documents/[id]` is unchanged (D-18) and
   already removes chunks, versions and originals. The purge dialog must say what Purge does beyond that.
8. **The default deletion mode is not "soft".** NULL keeps today's pipeline-dependent path: versions are kept under the
   unified pipeline with the async queue and deleted otherwise (D-08). The selector has three values and says so.
9. **`CitationRecord` is a strict contract** (`.strict()`, `quote` minimum length 1). App code that reads `withdrawn` ships
   with the contract change and before any SQL writes the flag (D-36); otherwise `validCitations` drops the citation and
   nothing shows the marker.
10. **The app's UI language set is 18 languages and has no `it`.** `src/translations/answer-quality.ts` carries en, zh and it
    and falls back to en. The main dictionary is read as a partial table with English fallback
    (`language-provider.tsx`), and `TranslationKeys` is `keyof typeof en`.
11. **`ragFetch` does not catch network failures and its 401, 403 and 503 messages are English only.** The new panels wrap
    every call and reuse the shared `error.signIn`, `error.network`, `error.unavailable` and `error.generic` strings of
    `window.ingestLabel` (en, zh, it), as the Chunking profiles panel does.
12. **All Config UI scripts are classic scripts in one global scope.** A second top-level `const`, `let` or `class` with a
    taken name stops the whole file. Top-level names in the new files start with the prefixes in section 6.1.
13. **The older RAG panels bind their init to the first `[data-tab="rag-administration"]` link only**, so the mobile drawer
    link never starts them. New panels bind every link, as the Ingestion panel does.
14. **The `Modal` base class writes its `title` and content through `innerHTML`.** The new picker passes a fixed title and an
    empty host element, then builds everything with DOM calls. Site, library and folder names are third-party text.
15. **`confirmDelete` in `document-manager.js` builds a `div.modal.modal-open`; the newest panels use a native
    `dialog.modal`.** Every new dialog is a native `dialog`.
16. **The Connectors tab and the Document Processing tab are English only.** The RAG administration panels since Phase 3.1
    are localized (en, zh, it) by browser language.

## 1. Design direction (frontend-design pass)

**Subject.** What happens here after something is removed at its source: is the knowledge base still in step with the
sources it copies from, and is a removed document really gone.
**Audience.** A deployment admin at a desktop who arrives with one of these questions: "a file was deleted in the shared
drive, is it still being quoted?", "why did the sync stop?", "this document must go, how do I prove it is gone?". And, in
the app, a reader who opens an old answer whose source was withdrawn, and a member looking at a connector card.
**Primary job.** Show which connections are out of step, let the admin decide a paused removal with the numbers on screen,
and give a proof of absence after a purge.

**Mode.** Impeccable "Operate". These are working tools inside an existing dashboard. Sections, sub-tabs, tables, badges,
alerts and dialogs are the ones the Ingestion and Chunking profiles panels use. No new navigation, no new control type.

**Vocabulary (one name per thing, kept through every flow).**
- Admin surfaces say **Purge** for the irreversible removal (it matches the mode value, the route, the CLI and the audit
  table), **Soft delete** for the mode that keeps versions, and **full reconcile** for the complete listing that removes
  documents whose file is gone. The panel description defines "full reconcile" once.
- Reader surfaces say **Source withdrawn**. Readers never see "purge" or "reconcile".
- A button keeps its verb: "Purge document" opens a dialog titled "Purge …?", confirms with "Purge document" and reports
  "Purged."; "Remove documents…" confirms with "Remove documents" and reports "Removed …".

**Signature element (admin): the purge receipt, a column of zeros** (section 6.6). After a purge the admin gets one small
table, store by store: how many rows were removed and how many are left. When the purge worked, the Left column reads as
zeros from top to bottom. That column is the proof DATA-24 asks for, and it is the only thing in these views built to be
looked at. A row that is not zero stands out by being a number among zeros, with one warning mark beside it. The same
receipt appears in the dialog right after a purge and under every row of Purge records.

**Signature element (reader): the empty frame** (section 6.9). Where the quoted text used to be, the sources panel keeps a
box in the same place with a dashed outline and no fill, holding the words "Source withdrawn". Absence is shown as a
kept, empty place. It is neutral grey, because a withdrawn source is a final state the reader cannot act on, not a warning.

**Review against generic defaults (what was changed and why).**
- Rejected a health dashboard of stat tiles (connections, overdue, paused). Three numbers hide the thing an admin acts on,
  which is one connection. Connections are rows; the summary is one sentence above the table, shown only when it is not zero.
- Rejected a traffic-light dot per connection. Status is a badge with an icon and a word, never colour alone.
- Rejected a countdown timer on the 24-hour confirmation limit. The limit is written as a time ("Can be confirmed until
  14:02"); nothing ticks.
- Rejected a typed-name confirmation for Purge. The required reason is already the deliberate step; the confirm button
  stays disabled until a reason is chosen, and the safe button has the focus.
- Rejected a success screen with a large tick after a purge. The result is the receipt.
- Rejected a red "deleted" treatment for withdrawn citations and a struck-through citation number. The number stays
  readable; the frame is neutral.
- Rejected a full expandable tree for SharePoint. A tenant can have hundreds of sites; the picker is a drill-down list with
  a breadcrumb that loads one level at a time.
- Rejected a "Run reconcile now" button (finding 5) and a separate alerts inbox (finding 6).
- Rejected emoji, middle-dot meta strings and arrows on buttons in new markup. The existing row buttons keep their emoji.

**Quality floor (built without announcing it).** Visible keyboard focus, `prefers-reduced-motion` respected, all text at
least 4.5:1, tabular numerals in number columns, usable down to 360px, every state in section 7 present, every server
string inserted with `textContent` (Config UI) or as a React text child (app).

## 4. Spacing Scale

Tailwind spacing utilities only; no arbitrary pixel values. Same scale as `04-UI-SPEC.md` and `03.2-UI-SPEC.md`.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `mt-1`, `ml-1` | Icon to label inside a badge or button; a value to its second line; a field to its help line; the Purge row button after Delete |
| sm | 8px | `gap-2`, `mb-2`, `mt-2`, `p-2` | Buttons in a row, badges side by side, heading to its description, picker rows, icon to text in the app marker and note |
| md | 16px | `gap-4`, `mt-4`, `mb-4`, `p-4` | Between form fields, toolbar to content, table to the line under it, padding of the paused-run block and of the picker list |
| lg | 24px | `gap-6`, `mt-6` | Between sibling panels (existing `grid gap-6`); between the receipt and the buttons in the purge result |
| xl | 32px | `.card-body` default, `py-8` | Card padding (DaisyUI default, unchanged); vertical padding of empty-state blocks |
| 2xl | 48px | `h-12` (DaisyUI `btn` height) | Touch-size row actions below 768px |
| 3xl | 64px | not used | Reserved for page-level spacing |

Exceptions: none. Every margin, padding and gap in new markup, in the Config UI and in the app, is 4, 8, 16, 24, 32, 48
or 64px. No half-step or 12px spacing utility appears in anything this phase adds. Three app elements sit next to
shipped elements; the new elements take scale values and the shipped ones are not restyled:
- Warning pill: `h-5 px-2 py-0` (height 20px set as a size, horizontal padding 8px, no vertical padding). It is as tall as
  the shipped "Connected" pill beside it.
- Withdrawn frame: `mt-2 px-4 py-2` (8px, 16px, 8px).
- Connector note: `mb-4` (16px) above the card's buttons.

Component internals outside the scale (not spacing tokens, do not restyle): DaisyUI `table-sm` cell padding, `select-sm`,
`input-sm`, `textarea-sm`, `checkbox-sm`, `btn-sm` (32px) and `btn` (48px) are used as shipped. Row actions are
`btn md:btn-sm`: 48px tall below 768px, 32px from 768px up.

Sizes that are not spacing: the app warning pill is `h-5` (20px) tall; the picker list is capped at `max-h-96` (384px, as the existing folder picker) and scrolls; the
"Show files" list is capped at `max-h-40` (160px) and scrolls; the deletion-mode select has `min-w-40` (160px).

- `index.html` gets only the two `section` skeletons: heading, description paragraph, one alert host, one status region

  everything else.
- `initSourceSyncPanel()` and `initPurgePanel()` are idempotent: the first call mounts, later calls refresh and keep the

- Neither panel reads `#workspace-selector`. Both list what the signed-in admin administers (`rag_admin_tenant_keys`), and

- Locale of the two panels and of the three dialogs: first two letters of `navigator.language`, `zh` or `it`, otherwise
  `en`, exactly as the Ingestion panel resolves it. Dates use `Intl.DateTimeFormat(locale, { dateStyle: 'medium',
  timeStyle: 'short' })` inside a `<time datetime>`; relative times use `Intl.RelativeTimeFormat(locale, { numeric: 'auto' })`
  with the absolute time in `title`. Numbers and percentages use `Intl.NumberFormat(locale)`.
- Every admin request goes through `ragFetch`. No other fetch target for the panels, no `Authorization` header, nothing
  written to `localStorage`, `sessionStorage` or a cookie. Nothing polls: lists load on mount, on Refresh and after an action.

### 6.3 Connections sub-view

  focus to it.

1. `paused.body`: count, total, percentage and the limit, or `paused.bodyAll` when the count equals the total (the source
   returned no files).
2. `paused.when`, 12px: when it was found and until when it can be confirmed, both as `<time>`.
3. `details > summary` `paused.files` with the count. Inside, a list (`max-h-40 overflow-y-auto`, 14px) of up to 20 file
   names as plain text with `break-words`; when more exist, a last 12px line `paused.filesMore`. When the server sends no
   names, the file ids in `font-mono text-xs break-all`.
4. Buttons (`flex flex-wrap items-center gap-2`): `btn btn-error btn-outline md:btn-sm` "Remove documents…" and

the count and the sentence for the connection's current mode (Default, Soft delete or Purge). "Go back" has the focus.
While the request runs, both dialog buttons are disabled, the confirm button shows a spinner with `confirm.removing`, and
Escape and the backdrop are inert. Afterwards the dialog closes, the list reloads, and the status region announces
`remove.done` or `remove.partial`.

"Dismiss run" needs no dialog (it removes nothing and the next reconcile evaluates again). The button shows a spinner,
the list reloads, the status region announces `dismiss.done`.

**Expired run** (older than 24 hours, by the server's `expires_at` or a 409 `confirmation_expired`). The block becomes a
plain `div.alert` (no warning tone) with `bi-clock` and `expired.body`; its only button is `btn btn-outline md:btn-sm`
"Dismiss run". "Remove documents…" is not rendered.

**Row focus after an action.** After Remove documents or Dismiss run the block is gone; focus moves to the connection's
deletion-mode select. After a failed action focus stays on the button that was used.

## 9. Keyboard, screen reader and focus

- Every control is a native `button`, `select`, `input`, `textarea`, `details` or `dialog`. Tab order is DOM order. No
  `tabindex` above 0, no click handler on a `div`, `span` or `tr`.
- Sub-tabs: `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`; Left and Right move between tabs, as the
  Ingestion panel does.
- Dialogs open with `showModal()`. Focus starts on the safe button ("Keep current mode", "Go back", "Keep document").
  Escape and the backdrop close them, except while a request runs. Focus returns to the opener, or to the place named in
  6.3 and 6.5 when the opener is gone.
- The deletion-mode select never commits Purge on keyboard change alone: arrowing to Purge opens the dialog only on
  `change`, and a cancelled dialog restores the previous value, so a keyboard user cannot land in Purge mode by passing
  over it.
- Status regions are `role="status" aria-live="polite"` and receive one sentence per finished action. Refusals use
  `role="alert"`. Alerts present on load (overdue summary, paused block) carry no live role.
- Badges always contain their word. Icons are `aria-hidden`. A relative time has its absolute time in `title` and in the
  `datetime` attribute.
- The receipt is a real table with a caption, column headers and row headers, so "Text chunks, Left, 0" is read as such.
- Tables that can scroll sideways sit in a focusable region with an accessible name.
- Picker: checkboxes are labelled by the item name; the "Open site", "Open library" and "Open folder" buttons carry the item name; the level heading is announced
  after each level change; covered items are `disabled` with the reason as visible text.
- App: the pill and the note are plain text in reading order after the provider name. The chip's accessible name says
  the source is withdrawn before it is opened. The frame is a paragraph, not an image or an empty quote.
- Motion: no new animation. Spinners carry `motion-reduce:hidden` and always sit next to text. The existing
  transitions of the app components are not changed.
- Visible focus: DaisyUI's default outline in the Config UI; the shipped `focus-visible:ring-2` on the app chip.

## 11. What must never be shown or done

- **No document text anywhere in the admin views.** No chunk, quote, preview or snippet in Source sync, in the purge
  dialog, in the receipt or in Purge records.
- **No file name after a purge.** Purge records, the receipt and every log or status line show ids shortened for display,
  never a file name, title, path or hash (D-12, finding 4). The file name appears only in the open purge dialog and in the
  "Show files" list of a paused run (those documents still exist).
- **The withdrawn quote is never rendered**, including from text a browser still holds, and never placed in a `title`,
  an `aria-label` or the DOM in hidden form.
- **Domain neutrality** (owner rule, 2026-11-25): no UI string, placeholder, example or fixture name in this phase uses a
  domain word or value. Wireframes and tests use neutral names ("Provider A", "file-a.pdf", "Site A", "Folder 1").
- **No tenant, lineage id, user id or file name is sent as authority** by the browser. The purge sends the document id in
  the path and the reason in the body; the mode and run calls send the connection or run id in the path.
- **No secret in the page.** `RAG_SIDECAR_SECRET` is never read, shown or sent by these views; the reconcile route is not
  called from the browser.
- **No colour-only state.** Every badge has a word; the non-zero receipt cell has an icon and hidden text.
- **No retroactive wording.** Nothing suggests that choosing Purge mode purges documents removed earlier (D-08).
- **No "notified" claim in the app note.** The app text does not say an administrator was notified (finding 6).
- **No action on the app card.** No confirm, dismiss or mode control outside the Config UI (D-26).
- **No `innerHTML` and no value-carrying template string** in new Config UI code; no `dangerouslySetInnerHTML` in new app
  code.

## 13. Color

### 13.1 Config UI

DaisyUI theme tokens are the contract; hex values are the DaisyUI 4.4 defaults, for reference only, and are never
hard-coded. These panels use no brand orange: in RAG administration `myrag-primary` already means "metered premium pages"
in the Ingestion panel and keeps that single meaning.

| Role | Token | Reference (dark / light) | Usage |
|------|-------|--------------------------|-------|
| Dominant (60%) | `base-100` | ≈ #1D232A / #FFFFFF | Tab card behind the panels; dialog and picker boxes |
| Secondary (30%) | `base-200`, `base-300` | ≈ #191E24, #15191E / #F2F2F2, #E5E6E6 | Panel cards; the new Connectors card; table borders; the picker's selection bar and list border |
| Text | `base-content`, `/70` for secondary | ≈ #A6ADBB / #1F2937 | All text; muted lines use `/70`, never lower |
| Accent (10%) | `primary` (DaisyUI) | theme primary | See the reserved list below |

| Warning | `warning` | theme warning | Overdue, Paused and Cleanup pending badges; Listing incomplete badge (outline); overdue summary; paused block; partial-removal alert; narrowing warning; throttled alert; the icon beside a non-zero Left value; sign-in alert |
| Destructive | `error` | theme error | Purge (row button, outline), Purge document, Use Purge mode and Remove documents (outline in the block, solid in the dialogs); also the Last run failed and Rows left badges (outline), refusal lines and unavailable alerts |

Accent reserved for: the picker's "Save selection" button, the SharePoint and OneDrive switch when on (`toggle-primary`,
as the switch beside it), and focus outlines. Nothing else is `primary`: not headings, not the sub-tabs, not the
deletion-mode select, not picker checkboxes (neutral `checkbox-sm`), not Refresh, Reload, Load more, Check again, Dismiss
run, Go back, Keep document, Keep current mode, Open…, Close dialog, Close picker, Discard changes or Reload list (all
default, outline, ghost or link), and not badges.
Source sync and Purge records have no primary button at all.

Success, warning and error colours describe states the server names (a reconcile state, a check result, a refusal),
never a judgement the UI makes about a number. A document count, a removed count and a percentage are never coloured. A
Left value of zero is plain text; only a value above zero gets the warning icon.
