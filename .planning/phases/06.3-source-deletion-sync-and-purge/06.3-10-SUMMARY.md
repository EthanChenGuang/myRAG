# 06.3-10 Summary: withdrawn marker scrub for answer records and chats

The first SQL that writes the withdrawn flag. After a purge, 06.3-15 can call these functions to replace stored citations of the purged versions with a marker. This covers the tenant's answer records and saved chats. The functions also count what is left.

## Behaviour changes

- New service_role-only functions only. Nothing calls them yet: 06.3-15 calls them inside the purge transaction. No switch, env variable, route or UI changed, and chat behaviour is unchanged.
- `rag_purge_scrub_answer_records`: in the given tenant only (`tenant_key` = the key), the citations of the version ids become markers in their original order. Other citations stay byte-identical, and citations that are already withdrawn are left as they are. A key of the other deployment mode is refused with 22023.
- `rag_purge_scrub_chats`: single-tenant checks every chat. Multi-tenant checks `organization_id = <org>` for an `o:` key and `user_id = <user> AND organization_id IS NULL` for a `u:` key, as 0502 maps them. In a matching chat, `metadata.citations` get markers, used-document entries are blanked and flagged, and picture links of the lineage are dropped. Other parts and messages are unchanged. Chats without a match are not updated, so their `updated_at` stays the same.
- `rag_purge_citation_leftovers`: per store (`answer_citations`, `chat_messages`), the count of unflagged citations, alsoIn entries and used-document entries of the ids in the tenant. It is 0 after a scrub.
- Every marker passes `CitationRecordSchema` and `pickAnswerMetadata` (validCitations) keeps it, so 06.3-06's withdrawn display shows it.
