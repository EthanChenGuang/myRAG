# 06.3-13 Summary: picker routes, selection saving and the switch gate

## Branch setup

`exec/06.3-13` was created from `origin/exec/06.3-08`; no other branch was merged. Dependency 06.3-08 and its dependencies 06.3-02, 06.3-03 and 06.3-04 all have SUMMARYs on this branch.

## Migration number

This plan creates no migration (the selection lives in the existing `nango_connections.metadata` JSONB column). No 07xx number was reserved and no placeholder was pushed.

## What was built

**Task 1 — listing routes (D-22, D-24).** `picker.ts` lists one Graph page per call:
- sites: `/v1.0/sites?$select=id,name,displayName`, or `/v1.0/sites?search=<q>&$select=…` for a trimmed query of 2+ characters; name = `displayName`, then `name`;
- drives: `/v1.0/sites/{site}/drives?$select=id,name`, OneDrive `/v1.0/me/drives?$select=id,name`;
- folders: `/v1.0/drives/{d}/root/children` or `/v1.0/drives/{d}/items/{i}/children` with `?$select=id,name,folder,file&$top=200`; only items with a `folder` facet are returned, `has_children` from `folder.childCount > 0`.

The next page is an opaque cursor `spc1.<base64url(path and query)>`, built from `pathAndQueryOf(@odata.nextLink)` (a next link on another host fails the request with 502) and read back only through `graphEndpointOf` with the exact listing path of the current request: a cursor of another route, drive or folder, a raw link, a dot segment or a `//` path is refused with 400 before any Graph call (T-06.3-33). Ids must match `isGraphId` (`[A-Za-z0-9!_.,-]{1,256}`, not only dots).

Each route file checks `isSharePointEnabled()` first (off → 404 `{ error: 'Not found' }`), then the shared handler checks `isNangoEnabled`, `requireSessionUser`, validates the query with `zod/v3`, looks up the connection by session user, provider and `status = 'connected'` (never from the request, T-06.3-32), and answers with `Cache-Control: no-store`. Errors: 401 no session, 404 no connection, 400 `invalid_request` / `invalid_cursor`, 429 `{ error: 'throttled' }` for a Graph 429 or a Retry-After past the deadline, 502 `{ error: 'upstream_failed' }` for anything else. Logs are `[Nango]` with kind and counts only.

**Task 2 — switch gate and selection saving (D-22, D-24, D-40).**
- `isSharePointBlocked(provider)` answers 404 `{ error: 'Not found' }` in session POST, connections POST/PATCH/DELETE and sync POST (request provider, and again for the looked-up connection's provider), before any Nango or database call (sync: before the connection lookup for the request provider). GET leaves the two providers' rows out; syncAll skips them.
- Switch on: session and connections POST/DELETE and sync use `sharePointIntegrationKey(provider)` for the two providers; other providers keep `PROVIDER_CONFIG[provider]?.integrationId || provider`.
- PATCH accepts `sourceScope` only for the two providers: `{ sites, drives, folders }` strict, entries `{ id, name, parentId? }` (folders also `driveId`), name 1–512, at most 200 entries in total, no sites for OneDrive. Valid: the current metadata is read (user + provider) and `metadata.source_scope` is written merged with the other keys; no other PATCH branch changed. GET returns it with the row; delta links stay in `rag_source_delta_tokens`.

## Behaviour changes

None with the switch off for Google Drive, Notion and Dropbox: the test `other providers behave the same with the switch off and on` records responses, database calls and Nango calls for session, connections POST/PATCH/DELETE and sync and compares off with on. With the switch off, requests naming the two providers now answer 404 (before: they would have reached Nango).

## Deviations

1. Extra file `src/app/api/nango/sharepoint/_lib/picker-route.ts` holds the handler shared by the three routes (the switch check stays in each route file).
2. Optional `provider` query parameter on drives and folders (not in the plan's URL list) so OneDrive connections can be browsed; default `sharepoint-online`.
3. `listDrives` takes an optional cursor (plan signature had none); the drives route accepts `cursor` too.
4. `isGraphId` lives in `config.ts` (re-exported from `picker.ts`) so `scope.ts` stays free of the Nango client import.
5. Folder entries of `sourceScope` require `driveId`, matching `DriveSelection` from 06.3-08.
