# Phase 06.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Seeded from `06.3-RESEARCH.md` § Validation Architecture; the planner binds each row to a task.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest (`vitest.config.ts`), `node:test` via `tsx` for `.mts` (PGlite SQL and e2e), pytest for contracts |
| **Config file** | `vitest.config.ts` |
| **Quick run command** | `npx vitest run <file>` or `node --import tsx --test <file.mts>` |
| **Full suite command** | `npx vitest run && node --import tsx --test tests/*.test.mts && node --import tsx --test tests/rag-db/*.test.mts && node --import tsx --test tests/rag-e2e/*.test.mts` |
| **Static gates** | `node scripts/check-config.mjs`; `node scripts/ci/check-rag-boundary.mjs`; `npm run typecheck:new`; `npm run gen:schemas` + schema diff |
| **Estimated runtime** | ~300 seconds full suite; task files under 60 seconds |

---

## Sampling Rate

- **After every task commit:** the task's own test file plus `npm run typecheck:new`
- **After every plan wave:** full suite and static gates
- **Before `/gsd-verify-work`:** full suite, `npm run test-rag -- --out eval/out/smoke`, schema-parity diff, all green
- **Max feedback latency:** 60 seconds per task file
