# 06.3-27 Summary: source recheck on the legacy, voice, media and overview paths

With `RAG_SOURCE_RECHECK=true`, all five retrieval paths now check their candidates against Supabase before ranking or assembly. The v2 path already did this (06.3-07); this plan adds legacy chat, legacy voice, media and overview, all through the same helper. With the switch off, none of these paths enters the stage.

## Behaviour changes

- Switch off (default): no path enters the stage. Stage lists, stage counts, results, and both `test-rag` gates are unchanged.
- Switch on: the stage runs at these points:
  - Legacy chat and embed: after the exact-id merge, before `legacy_rank`. Exact-id chunks are checked too.
  - Legacy voice: after `voice_keyword_fallback`, before `local_rerank`.
  - Media and overview: after `search`, before `injection_check` and `assemble`.
- Stale ids are removed before the next stage. `stage_counts.source_recheck` carries `{ stale_index_drop, checked }`, and the result carries `sourceRecheck { checked, dropped }`. The eval run route maps that marker to `stale_index_drop` on every path.
- If the recheck fails or times out, the stage is `skipped` and the result is `degraded` (`source_recheck_failed` / `source_recheck_timeout`). The candidates continue unchecked, no marker is set, and the request succeeds.
- Strict "information not available", webSearch with Exa, `source_images`, `{{context}}`, voice and embed are unchanged with the switch off. No code outside the four `if (config.sourceRecheck)` blocks and the result spreads changed.
