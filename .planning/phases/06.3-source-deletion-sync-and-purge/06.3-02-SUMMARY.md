## Decisions Made
- **Classification:** the four `RAG_SOURCE_*` names are `side: query` in `config/rag/settings-classification.json`. They are operational and rebuild no stored document, like `RAG_INGEST_JOB_RETENTION_DAYS`. `check-settings-classification` fails without an entry.
- **Integration keys are not secrets in the config tool:** `scripts/config-server-security.js` treated any name containing `KEY` as a secret. That would have withheld the value from the UI and made an empty save mean "unchanged", so a key could never be cleared. `BENIGN_NAME` now also matches `^NANGO_[A-Z0-9]+_INTEGRATION_KEY$`. `NANGO_SECRET_KEY`, `NANGO_WEBHOOK_SECRET` and other `*_INTEGRATION_KEY` names stay masked, and a value holding a URL with credentials is still masked. The test fails on the old code.
- **Empty field means the default:** `env.ts` reads `KEY=` through `|| '<default>'`, and the placeholder shows that default.
- **Settings block stays visible:** it is not `hidden` as `#rag-ingestion-settings` is, so the fields work until 06.3-18 moves the block into its Settings sub-tab.
- **Help ids** are `<VAR>-help`.
- **Ordering:** the manifest entries follow `RAG_EXACT_ID_LOOKUP`. The manifest is not globally sorted, and that order is not checked.
