# Phase 05.1 Plan 21: ML detectors wired into injection_check

**Prompt Guard and Lakera now run inside `injection_check`, only on the items the rules let through. Lakera sits behind one proven gate. Detector outages degrade the result but never refuse or skip, and cached verdicts never cross tenants.**

## Performance

- Tasks: 3 of 3
- Files: 6 modified, 5 created
- Commits: 4 (2 RED, 1 GREEN, 1 summary)

## Accomplishments

- **Lakera gate (B4, A-12).** The stage calls `lakeraAllowed` with the real `isMultiTenant()` before it builds any Lakera call. The adapter checks the same gate again before each request.
  - A stage-level table with a counting fetch fake proves zero requests for each refused combination.
  - Two positive controls prove the request is sent when every condition holds.
  - A route test drives the real chat route in multi-tenant mode against a fake Lakera server on 127.0.0.1. Without the acknowledgement it receives 0 requests; with it, at least 1. The answer streams in both cases.
- **Fan-out (D-07, A-11).**
  - Detectors run in parallel on rule-unflagged items, for chat, embed and eval only. Voice and media never call a detector, even with both switches on.
  - A flag from either detector is applied like a rules flag (flag, drop or downweight).
  - Counts are attributed per detector (`rules_*`, `prompt_guard_*`, `lakera_*`).
- **Prompt Guard policy (A-12).**
  - Only en and it items are sent; zh and undetected items are counted as `unsupported_language`.
  - Chat and embed read the tenant-keyed cache. On a miss they schedule a bounded background warm and do not wait for it; the item passes on the rules.
  - Eval runs Prompt Guard inline.
- **Failure policy (D-09, A-3).**
  - The fan-out runs under `AbortSignal.any([stageSignal, timeout(budget - inner_reserve_ms)])`, raced against that signal, so even a detector that ignores its signal is cut off.
  - A needed detector that fails gives stage `degraded`, detail `detector_unavailable`, result reason `injection_check_detector_unavailable`, `detectorsUnavailable` and `detectorFailures`.
  - The stage is never recorded as skipped, and `empty`/`injection_filtered` still takes precedence.
- **Cache (A-9).** Keys are (tenant scope, detector, version, sha256 of the text). Identical text in a personal and an organization scope is classified once per tenant, and each tenant follows its own verdict.

## Behaviour changes

- With every ML switch off (the default), nothing changes: no detector state, no new counts, versions or summary fields, and no timers. The full vitest suite, the characterization snapshots and `test-rag` (paired differences all zero) confirm it.
- With `RAG_INJECTION_LAKERA=true` or the acknowledgement set, the stage gains `lakera_*` counts, and a refused gate is recorded in `injection.detectorsDisabled`.
- With `RAG_INJECTION_PROMPT_GUARD=true`, the stage gains `prompt_guard_*` counts.
  - Without a sidecar this is disabled `not_configured`.
  - With a sidecar that has no model, the result is 503 and `degraded` on eval. Chat warm batches fail silently.
- `deriveStatus` and `degradedReason` know the new `injection_check` degraded record. A `degraded` search record (`lexical_icu_unavailable`) behaves as before.

## Deviations from Plan

- **Extra summary field `detectorFailures`.** The plan asks for each failure to be "recorded as unavailable with its reason", but `detectorsUnavailable` holds ids only. The new field is optional and set only on a failure.
- **`detectorsDisabled` and count emission are conditional.** They appear only when a Lakera or Prompt Guard setting is non-default, so the off state stays byte-identical. The plan's case (b), Lakera off with the acknowledgement on, still records `lakera_off`.
- **`RagDeps.lakeraDetector` is typed `() => Detector`** (string reasons) rather than `Detector<LakeraUnavailableReason>`, so tests can inject plain fakes. The default is still the real adapter.
- **RED tests reach the new test hooks through optional calls** (`injectionCheck.resetInjectionDetectorsForTests?.()`), so the red runs failed on assertions rather than on a missing export.
- **Fault test count is 9 (at least 6 required).** It adds a detector that ignores its signal and a `not_configured` no-op case.
- **Two-tenant test count is 4 (at least 3 required).** It adds a Lakera variant that also asserts each call carries its own tenant scope.
- **No migration, no new env variable, no package.**
