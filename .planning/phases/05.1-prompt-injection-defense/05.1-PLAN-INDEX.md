25 plans in 7 waves, 62 tasks. Plans in the same wave share no file in `files_modified`, every file touched by two Phase 5.1 plans is ordered by a `depends_on` path, every plan's wave is one more than its highest in-phase dependency, and the graph is acyclic (checked by script, see "Checks run").

**Closing plan: 05.1-22** (phase comparison against the baseline, AGENTS.md, full gate run). Phases 6 and 7 depend on 05.1-22, or on the last 5.1 plan that edits a shared file (table "Last editor per file" below). 05.1-23 is the live-verification plan; it is human-only and gates nothing downstream.

The phase tracer is 05.1-06 Task 1 in wave 2 (one web-chat request through legacy retrieval, the injection_check stage with rules and drop, the rebuilt candidates and the renderer's wrapDocuments, to the system prompt captured at streamText).

Three plans are not fully autonomous:
- **05.1-18** (wave 3) has two blocking-human checkpoints. Task 1 approves the Prompt Guard license, gated Hugging Face access, the build token and the package pins. Task 3 is ORCHESTRATOR-ONLY: the orchestrator runs `uv lock` and `uv sync --extra promptguard` and makes one lock commit. Executors never install, lock or sync.
- **05.1-25** (wave 4) is autonomous but runs only after the 05.1-18 lock commit. It uses `uv run --frozen --no-sync` throughout.
- **05.1-23** (wave 7) holds the four live checkpoints. The Lakera account, key, region and retention come first. Live Lakera calls go only through the stage gate and only on synthetic chunks.
