# Phase 5.1 Plan 07: Prompt Guard classify endpoint and client Summary

**The sidecar exposes an authenticated, windowed `POST /v1/injection/classify` with an injectable scorer and a deterministic fake. With no model loaded it answers 503 `promptguard_unavailable`. The app-side `classifyWithPromptGuard` returns every failure as a value.**

## Accomplishments
- `rag_sidecar.injection` package: pure windowing helpers, `InjectionScorer` protocol, `FakeScorer` keyed on the synthetic token `PGFAKE-MALICIOUS` (whitespace tokenizer, 0.995 for a window holding the marker, 0.01 otherwise), `resolve_scorer` with a lazy import of the 05.1-25 model module, and the detector config loader.
- The router is registered under the existing `/v1` router, so `SharedSecretMiddleware` covers it: 401 without or with a wrong secret, 503 when the secret is unset. There is no per-route auth.
- `classifyWithPromptGuard` posts with `x-sidecar-secret`, splits batches at 32 items, parses with the generated `InjectionClassifyResponseSchema`, cancels the body on non-OK responses, and logs only the reason and the item count.

## Behaviour changes
- New sidecar route `/v1/injection/classify`. Without a scorer, which is the default image and the default settings, it answers 503 `promptguard_unavailable`. No caller uses it yet: the stage wiring is plan 05.1-21. Existing routes are unchanged, and the full sidecar suite passes.
- Nothing changes in the app until 05.1-21 calls the client.

## Deviations from Plan
- **Extra client reasons:** the client adds `unreachable` and `invalid_request` to the planned reasons, so a transport error or an over-limit item is a named value instead of being folded into another reason.
- **Extra hardening, not in the plan:**
  - a 4 MiB body cap (413) on the route;
  - output validation of the scorer, which turns a bad result into 503;
  - an id and order check in the client.
- **Not changed:** migration numbers (none used) and no UI touched, so there is no Design skills section.

## Handoffs
- **05.1-25:**
  - `rag_sidecar/injection/prompt_guard.py` must expose `build_scorer(settings, config: PromptGuardConfig) -> InjectionScorer`, which `resolve_scorer` calls.
  - The sidecar image does not copy `config/rag/`. In the image, `load_prompt_guard_config()` therefore returns None, and the route stays 503 even with a model. The promptguard target must either ship `config/rag/injection-detectors.json` or point the loader at a shipped copy. This fails closed, not open.
- **05.1-21:** map `{ok: false}` to `degraded` / `detector_unavailable`.
  - Pass the stage's inner deadline as `timeoutMs` and its signal as `signal`.
  - The label in the response uses the config threshold. The stage may re-threshold on `score`.
