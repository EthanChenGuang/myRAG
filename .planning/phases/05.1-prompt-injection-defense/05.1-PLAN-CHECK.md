**05.1-18, B2 [packages/checkpoints]: no executor task may install or lock packages; only the orchestrator does that, after the user approves.**
- Evidence: in Task 2 the executor must "regenerate the lock with uv", and its verify runs `uv sync --locked` and `uv run --extra promptguard`, which installs torch, transformers and huggingface-hub. Approval in Task 1 does not change who runs the install.

**05.1-14 (with 05.1-13), B3 [context_compliance D-10/D-01/D-06]: released-rule exemptions must hold under both graphs, scoped to the tenant, with a two-tenant test.**
- Evidence: 05.1-13 passes the per-document released-rule set into `runInjectionCheck`, but only through the legacy `fetch-rows.ts`. 05.1-14 calls the stage on v2 with the 05.1-06 API and says "Do not modify injection-check.ts". - Example fix: have 14 depend on 13. In v2, read the released set only from rows returned under the caller's scope, pass it in, and add a v2 two-tenant PGlite case.

**05.1-08 / 05.1-21, B4 [cross-tenant/off-state]: no Lakera request in multi-tenant mode unless both the opt-in and the acknowledgement are set.**
- Required condition: `RAG_INJECTION_CHECK != off` AND `RAG_INJECTION_LAKERA=true` AND (single-tenant OR `RAG_INJECTION_LAKERA_MULTI_TENANT_ACK=true`). Each combination needs a test that zero requests are sent.

- Example fix: add a truth-table test (fetch call count == 0 for every disallowed combination) at stage level. Add one route-level multi-tenant case.
