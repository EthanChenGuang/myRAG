## Behaviour changes (switches on only)

- **Stage.** With `RAG_INJECTION_CHECK` = `flag` | `drop` | `downweight`, the legacy main graph (chat, embed and eval profiles) runs `injection_check` after `post_filter` and before `assemble`. It scans relevant candidates (content plus `metadata.image_context`) and non-empty referenced sections. The trace entry has `rules` (matched rule ids) and `counts` `{checked, flagged, dropped, downweighted}`. One `[RAG Security] Injection check` line per request carries the trace id, mode, counts, rule ids and chunk/document ids only.
- **flag** records only. **drop** removes flagged chunks and flagged referenced sections (plus that reference's `UsedDocument`), then rebuilds `FilteredCandidates` through `filterCandidates`, so `kept`, `relevantChunks`, `usedDocuments`, `sourceImages`, `refusalCandidate`, `candidates` and the route's synthetic `query_documents` result agree with the context. **downweight** removes nothing. Flagged chunks render after unflagged ones, documents with only flagged chunks go last, and with tagging on their `<doc>` carries `flagged="true"`.
- **Tagging.** With `RAG_CONTEXT_TAGGING=true`, `buildContext` replaces the rendered string with `wrapDocuments(...)` over the final blocks (references as `kind="reference"`, images `img<n>`, Phase 5 aliases `S<k>` when a labeler is present, otherwise `c<n>`, links last). Only when there is at least one entry; otherwise `NO_CONTEXT_TEXT` stays, so the strict refusal sentinel holds (Pitfall 1).
- **Status.** If the check dropped something and nothing survived assembly: `status: 'empty'`, `reason: 'injection_filtered'`, even when another stage was skipped. Strict chat with web search off then streams today's localized "Information Not Available" (en, zh, it verified) and never calls `streamText`. With web search on, or in balanced mode, the answer continues without knowledge-base context.
- **Timeouts.** The rules run synchronously before any await. `RAG_STAGE_TIMEOUTS=injection_check=1` still records the stage `ok` with the drop applied. If the stage is skipped anyway (forced stall test hook), the held rules verdict is applied and the result is `degraded` / `injection_check_stalled`. An all-dropped stall is still `empty` / `injection_filtered`.
- **Disabled.** `RAG_DISABLED_STAGES=injection_check` with the check on records the stage `disabled` and emits one `[RAG Config]` warning per process.

With every 5.1 switch at its default, no stage, field or log line is added. The characterization (chat, embed, voice), oracle, assemble-switch and both differential suites pass unchanged.

## Deviations

- `RAG_STAGE_TIMEOUTS` uses its real `stage=ms` syntax (`injection_check=1`). The plan wrote it as JSON.
- `InjectionSummary` adds `flaggedReferenceIds` and `droppedReferenceIds` (document ids of flagged referenced sections), because a full-text reference has no chunk ids.
- The `RAG_DISABLED_STAGES` warning is `warnInjectionCheckDisabled(config, mode)` in config.ts, called from the pipeline. `RagEnvInput` does not carry `RAG_INJECTION_CHECK`, so config memo keys and anything hashing `ragEnv()` are unchanged.
- The stall reason maps only a `timeout` of the injection stage to `injection_check_stalled`. A thrown stage after the rules keeps `injection_check_failed`, with the held verdict still applied.
- Eval stage budget is 60000 ms (registry maximum) rather than "no timeout" (D-09), as the plan records (PLAN-CHECK I3).
- Missing references get ids `r<n>`; the plan left the id open.

## Deferred

- `UsedDocument.content_preview` is the first 200 characters of `documents.content`. For a document that keeps some chunks after a drop, the preview can still hold the injected text in the sources panel and the synthetic `query_documents` output. Research A5 holds that this output is UI-only, and the tracer confirms the system prompt does not contain it. A follow-up should blank or recompute the preview for documents with a dropped chunk, together with the F-10 check that the synthetic result never reaches a later model step.
- Downweight does not move flagged referenced sections, and it does not yet interact with Phase 4 edge ordering (v2 only, 05.1-14, Pitfall 8).
- `[RAG Security]` per-request line: 05.1-13 owns the shared redaction test across graphs.
