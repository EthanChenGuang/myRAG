# Phase 05.1 Plan 20: Tagged context at every entry point

**With `RAG_CONTEXT_TAGGING=true`, `/api/internal/voice-rag` now also returns the voice graph's tagged `context`, and the voice agent sends that string to the model instead of building its own. Chat, embed and eval already got the tagged context through the shared assembly. New tests show each entry point has exactly one `<documents>` element and the notice once. With tagging off, nothing changes on any path.**

## Behaviour changes (tagging on only)

- **voice-rag route.** The JSON body gains `context` (notice, one `<documents>` element of `c<n>` docs with filename sources, reminder). It is only added when tagging is on and `voice.context` is a non-blank string. `results` and `source_images` are unchanged. Auth, Zod validation, 401/403/503 mapping and the empty `{results: []}` answer are unchanged. With tagging off the body has exactly today's keys.
- **Voice agent.** `RAGClient.query` returns `response.data.context` verbatim when it is a non-blank string. Otherwise it returns today's `[Context from document <id>]: <content>` string. Sources and source_images are unchanged. Either deploy order works. App first is still the documented order (A-1, recorded in AGENTS.md by 05.1-22).

## Tests that failed before the change

- Task 2 checks code that 05.1-06 and 05.1-13 already shipped, so it has no RED commit. Its first run failed only on fixture setup: the fake edge needed `documentFilenameFilter`, URLs had to come from `metadata.urls`, and the overview needed a chunk near the overview query. No production code had to change.

## Deviations

- **Leakage test placement.** The two-tenant voice harness lives in `tests/rag/voice-rag-route.test.ts`, so the two-tenant tagging case went there. `voice-rag-leakage.test.ts` (a mocked hygiene suite) gained the off-state, pass-through and blank/non-string cases.
- **Test helper.** `startRouteFixture` gained an optional `documentFilenameFilter`, so a single-tenant fixture can resolve `@mentions`. Existing callers are unaffected.
- **Embed strict.** The embed route always retrieves in balanced mode and has no strict refusal. Its "strict, no context" check is today's no-context prompt, byte-identical with tagging on and off and with no documents element. The strict refusal is covered on the chat and eval routes.
- voice-agent dependencies were installed with `npm ci --ignore-scripts` from its lockfile. Nothing was added or re-locked.

## Decisions for STATE

- Voice-rag `context` is additive and gated by `RAG_CONTEXT_TAGGING`. The agent prefers it and falls back to today's format. Deploy the app first, then the agent.
