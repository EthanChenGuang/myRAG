# Phase 05.1 Plan 12: Config UI detector summary Summary

**The Prompt-injection defense card now shows the active rule set and detector configuration, served read-only by the config server with no patterns or secrets.**

## Accomplishments

- `GET /api/config/injection-defense` returns `{rules: {version, counts: {zh, en, it, any}}, detectors: {version, prompt_guard: {model_id, revision, threshold, languages}, lakera: {detector_types, min_level}}}`. It reads `config/rag/injection-rules.json` and `config/rag/injection-detectors.json` on each request; `rules.version` is the first 12 hex chars of the sha256 of the rule file bytes (tested equal to `injectionRulesVersion()`).
- No rule pattern, rule id or env value is ever returned (tested with placeholder secrets in `.env.local`).
- A missing or invalid file gives `500 {error, code}` with codes `injection_rules_missing`, `injection_rules_invalid`, `injection_detectors_missing`, `injection_detectors_invalid` (or `injection_summary_failed`); no stack, path or parser message.
- The card gains a "Detector configuration" section (a `<dl>` of versions, counts, model, revision, threshold, languages, Lakera types and minimum level) and the A-12 line "Prompt Guard: en and it only; on CPU it runs inline only in eval runs and fills a warm cache for chat". The existing Lakera third-party note and masked key field stay as they were.
- Every value is inserted with `textContent`; a fetch error, non-2xx answer or malformed body shows exactly one `role="status"` error line and does not touch the switches above it.

## Deviations from Plan

- **"Admin guard":** the plan describes the endpoint as admin-guarded "exactly like the other config endpoints". The config server's guard for every route is the loopback/CSRF security middleware; there is no admin session check on config-server-local routes (admin sessions are checked only by the main app behind the `/api/rag` proxy). The route uses that same guard and the test compares refusals byte-for-byte with `/api/config`.
- **`counts.any`:** added beside zh/en/it so the counts add up to the rule total.
- Test file location follows the plan (`tests/ui/`), with its own small fake DOM rather than importing the chunking-panel one.
