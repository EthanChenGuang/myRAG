# Phase 05.1 Plan 08: Lakera adapter, detector config and tenant-keyed verdict cache Summary

**A Lakera Guard fetch adapter whose verdict comes only from the breakdown and which refuses every request unless check, Lakera, key and (single-tenant or acknowledgement) all hold, plus the shared detector config loader and a tenant-first verdict LRU. All of it is tested on recorded shapes with no live call.**

## Performance

- Tasks: 3 of 3
- Commits: 6 task commits plus this summary
- Files: 7 created, 4 modified

## Accomplishments

- `src/lib/rag/security/detectors.ts`: `Detector`, `DetectorVerdict`, `DetectorOutcome`, `DetectorClassifyOptions`. `loadInjectionDetectorConfig({path?})` validates `config/rag/injection-detectors.json` with the generated `InjectionDetectorConfigSchema`, freezes it and loads it once per process. A `path` reads that file and is not memoised. `detectorsConfigVersion()` returns the version.
- `src/lib/rag/security/verdict-cache.ts`: `verdictCacheKey(scope, detector, modelVersion, text)` puts `scopeKey(scope)` first. It rejects unminted scopes and hashes the text with sha256 in process. `createVerdictCache({maxEntries})` is an LRU built on Map delete and re-set. It stores frozen copies holding `flagged`, `score`, `level` and `at` only.
- `src/lib/rag/security/lakera.ts`:
  - `lakeraAllowed`: the single gate. Refusals come in the order `check_off`, `lakera_off`, `not_configured`, `multi_tenant_ack_missing`.
  - `lakeraVerdict(body, detectorTypes, minLevel)`: parses with zod/v3 passthrough and never reads `flagged`.
  - `createLakeraDetector({config, fetch, gate, timeoutMs?, now?})`: sends one chunk per request with role user and `breakdown: true`. Metadata carries only `internal_request_id`. It allows at most `config.concurrency` requests in flight and evaluates the gate before every request.
  - `lakeraSettingsFrom(securityConfig, multiTenant)`: a helper for 05.1-21.
  - Failures come back as reasons: `http_400/401/422/429/500/503`, `http_error`, `timeout`, `aborted`, `network`, `malformed`, `no_breakdown`, `detector_missing`, `too_large`, `profile_disabled` and the gate refusals.
- `tests/fixtures/security/lakera/responses.json` holds 13 recorded bodies with placeholder ids and no key:
  - flagged, clean, detect mode, a detected l4 entry, flagged by another detector only, no prompt-attack detector, no breakdown;
  - error statuses 400, 401, 422, 429, 500 and 503.
- Boundary rule `lakera-http`: `*.api.lakera.ai` or `/v2/guard` in any scanned source outside `src/lib/rag/security/lakera.ts` fails the check. Tests, `scripts/tests/` and `eval/harness/` keep their existing exemption.

## Decisions Made

See `key-decisions` in the frontmatter. The two that change behaviour relative to the research sketch:
- **`detector_missing`:** a breakdown without a configured `detector_type` is unavailable, not clean. This closes the silent fail-open of assumption A2: a project policy without a `prompt_attack` detector, or a wrong `detector_type` name.
- **`too_large`:** an item over `max_chars` is never truncated and sent. Truncation would let an injection placed after the cut pass as clean.

## Deviations from Plan

1. **Extra unavailable reasons** beyond the list in the plan: `http_error` (other non-2xx statuses), `network`, `aborted` (caller signal), `too_large`, `profile_disabled` and `detector_missing`. All are codes and carry no text. The plan's reasons keep their names.
2. **`createLakeraDetector` takes `gate: () => LakeraSettings`.** The function returns the switches, key, base URL and tenancy, and the adapter calls it before every request. That is how "evaluates lakeraAllowed before every request" is honoured with call-time config (05.1-04). A test proves a switch turned off mid-run stops later requests.
3. **Truth-table test fix:** the first RED version of the test expected 12 allowed combinations. The correct count is 9 (three active check modes, times single-tenant with either ack value or multi-tenant with ack). This was fixed in the GREEN commit and noted in its message. The 64 per-case assertions were right from the start.
4. **Host constant moved:** `DEFAULT_LAKERA_BASE_URL` moved from `config.ts` to `lakera.ts` (re-exported from `config.ts`), and the init-env comment was reworded. Without this, the new rule would have flagged the repository, and the alternative was a second exemption. With the move, the adapter is the only exemption.
5. No migration, no package, no new env variable, no contract change and no UI change.
