## Behaviour changes

- `rag_eval.phase_compare` (schema 2):
  - New check objects: `absolute_zero`, `category_noise` and `retrieval_unchanged` with `exclude_categories`.
  - New built-in checks: `gate` (the CI gate, including the absolute-zero offenders) and `report_only`.
  - `SwitchRun.env` overlays a base run config. It must be named `RAG_*` and must not look like a secret.
  - A spec can set `fixture_note` and `notes`.
  - Run results gain `run_config_env` and `injection`. Both keys are omitted when absent, so Phase 5 output is byte-compatible.
  - The Markdown report adds a run-config env line and a per-slice exposure and attack-success table.
- No product code changed.

## Deviations

1. **Extra built-in checks.** I added `gate` and `report_only`, which the plan text implies without naming. `gate` expresses "gate passes" for all-off and recommended. `report_only` expresses the reported runs.
2. **Additions to the comparison tool.** I added the `retrieval_unchanged` exclusion object and the `SwitchRun.env` overlay. The plan needs retrieval unchanged on non-injection items only, and the flag and downweight runs are sec-recommended with a different `RAG_INJECTION_CHECK`; the SEC switches are read from the run config.
3. **`fixture_note` on the spec.** It replaces the Phase 5 note ("fake citation generator"), which does not describe this run. The Phase 5 spec does not set it and keeps its note.
4. **Spec tests moved to Task 2.** They were committed with the spec in Task 2 because they need the spec file.
5. **Prompt Guard wording in AGENTS.md.** There is no optional `promptguard` image target (05.1-18 and 05.1-25 were skipped), so AGENTS.md says that no model image ships yet and names the checkpoint plans.
