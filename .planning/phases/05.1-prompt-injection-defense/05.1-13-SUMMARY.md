# Phase 05.1 Plan 13: injection_check on every legacy graph, released rules, trace fields

**With `RAG_INJECTION_CHECK` on, the overview, voice and media graphs now check what they put in front of a model, the same way the main graph does since 05.1-06. Overview and voice context can be tagged. An admin release exempts only the reviewed rule ids on that document version, read from rows the caller's scope already returned, and a two-tenant PGlite test proves it never crosses tenants. The trace records per-detector counts, rule ids and the rules version, and the `[RAG Trace]` line gains `injectionFlagged`.**

## Behaviour changes (switches on only)

- **Overview** (`generalOverview`): `injection_check` runs after `search` and before `assemble` over the overview chunks and referenced sections. Drop removes flagged chunks (and a flagged reference's `UsedDocument`). Downweight sorts flagged chunks after unflagged ones in their document and moves all-flagged documents last. With `RAG_CONTEXT_TAGGING=true` the overview context is one `<documents>` element: one `<doc id="c<n>" source="<filename>">` per document group, notice before and reminder after, no `=== Document:` header lines.
- **Voice**: `injection_check` runs after `local_rerank` and before `assemble`. It checks the ranked content including the `[Metadata: …]` suffix, rules only. With tagging on, `result.voice.context` is the wrapped string over the final results (`c<n>`, filename source, `flagged="true"` under downweight). `{results, source_images}` are unchanged. The route and agent start using `context` in 05.1-20.
- **Media**: `injection_check` runs after `search` and before `assemble`, rules only, and always drops flagged chunks, so injected text never reaches image or video prompt rewriting. Tagging never applies.
- **Status**: in all three graphs, when the check dropped something and nothing survived, the result is `empty` / `injection_filtered` (never over `error`). A stall maps to `injection_check_stalled` as on the main graph.
- **Released rules** (D-10): for a document version whose `metadata.quarantine.released_at` is set, the rules ignore exactly `released_rule_ids` (fallback `rule_ids`). Other rules still apply, and other versions and other tenants are unaffected. Applies on the legacy main graph (rows from `fetchAssemblyRows`) and on overview (its scoped documents read).
- **Trace**: the `injection_check` entry has `counts` with the 05.1-06 totals plus `rules_checked`, `rules_flagged`, `rules_dropped` and `rules_downweighted`, `rules` with the matched ids, and `versions: ["rules@<12 hex>"]`. The `[RAG Trace]` payload logs `versions` per stage and `injectionFlagged` when the check ran.

With every 5.1 switch at its default, nothing changes. No graph records a stage, the overview string is byte-identical and voice has no `context` key. The characterization suites (chat, overview, voice, embed), the media tests and both test-rag gates pass unchanged.

## Deviations

- **Count keys**: the plan says `rules.checked` and so on. The stage-count sanitizer drops keys with a dot, so the keys are `rules_checked` and so on. The 05.1-06 totals stay.
- **`detectors@<version>` is not recorded.** `detectorsConfigVersion()` belongs to plan 05.1-08, which is not on this branch, and no ML detector runs. Recording a detector version for detectors that never ran would mislead. 05.1-21 adds it through `injectionVersions` when it wires the detectors.
- **No spies on the 05.1-07/05.1-08 modules**, because they are not on this branch (Prompt Guard was skipped, 05.1-08 is not a dependency). The rules-only guarantee for voice and media is `injectionDetectorsFor`, which returns `['rules']` for those profiles whatever the switches say. The test turns both ML switches on and asserts `versions == ['rules@…']` and no `prompt_guard_*` or `lakera_*` counts.
- **Media mode**: media always drops when the check is on, even in `flag` or `downweight` mode. This follows the plan's "drop semantics" (A-11).
- **Released set on voice and media**: these graphs load no document rows, so no exemption applies there. A released document's chunks are still checked by every rule. This fails closed, consistent with "no extra query".
- **fetch-rows.ts**: the select already loads `metadata`, which holds `quarantine`, so the select is unchanged and only the `AssemblyRows` doc names the field. `tests/rag/assemble.test.ts` still pins the select string, and the query count is unchanged.
- **Overview**: when the check is on, the documents read moves before the check and is reused by assemble. That is still one documents query.
- **Harness**: `FakeEdgeCall.query` (an additive optional field) records table-read query strings, so the two-tenant test can assert that no request in B's run names A's document or chunk.
- **`RetrievalResult.injection`** is now also set by the overview, voice and media graphs.
