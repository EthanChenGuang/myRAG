# Phase 05.1 Plan 16: Reference notice on the Claude Citations path

**With `RAG_CONTEXT_TAGGING=true`, the direct Claude Citations call now has the same reference notice as every other path. It sits in the `{{context}}` replacement as: notice, the localized attached-documents sentence, one `<documents>` element with only the image-caption and links docs (escaped), then the reminder. File parts stay plain, unescaped AliasMap text. With tagging off the system text and request body are byte-identical to Phase 5.**

## Behaviour changes (tagging on only)

- `claudeSystemPrompt` on a claude-citations turn substitutes `buildClaudeContextReplacement({ attachedSentence, docs: docsFromBlocks(imageBlocks, { links }) })` for `{{context}}`. Image captions become `<doc id="img<n>" source=... kind="image">`, the links section becomes `<doc id="links" kind="links">`, and a caption holding `</doc>` is escaped. Block text never appears in the system text.
- Nothing else changes: file parts, titles, the fallback prompt (`decorateSystemPrompt`) and the chunk-alias path. The OpenRouter fallback prompt already got the notice from 05.1-06's tagged legacy renderer.

## Deviations

- Added the optional `contextTagging` field to `CitationSessionInput` so unit tests do not depend on the environment. When it is absent, the session reads `readSecurityConfig()` as the plan says, so no caller changed.
- The plan says to compare the tagging-off output "with the existing chat-claude-route fixture", but that test keeps no recorded system text. The off state is proven two ways instead: the session output equals the Phase 5 formula, and the route request body with `RAG_CONTEXT_TAGGING=false` equals the body with it unset.
- The "same post-check blocks" test triggers the session's own fallback with a 429 from the fake Anthropic server. One retrieval then produces both the Claude request and the chunk-alias prompt, and the test compares the file-part titles with the `[S<k>]` label lines under both `flag` and `drop`.
