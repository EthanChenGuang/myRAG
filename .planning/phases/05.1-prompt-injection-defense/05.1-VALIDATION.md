# Phase 05.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Every executable task in 05.1-01 to 05.1-22 has an `<automated>` command. The only non-automated items are the license, gated-access, build-token and package checkpoint (05.1-18 Task 1, blocking-human, before any install), the four live-service checkpoints in 05.1-23 (Lakera account, key, region and retention first), and two `<human-check>` walk-throughs (05.1-11 and 05.1-12) collected at the end of the phase.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5.1.1 (`tests/**/*.test.ts`, node environment); `node --import tsx --test` for `.test.mts` (database tests in `tests/rag-db/`, PGlite with the fake edge); `node --test` for `scripts/tests/*.node-test.mjs`; the voice agent's own `node --import tsx --test test/*.test.ts` through `npm --prefix voice-agent test`; pytest 9.2.0 for `eval/` and `rag-sidecar/` |
| **Config file** | `vitest.config.ts`; `eval/pyproject.toml`; `rag-sidecar/pyproject.toml`; `voice-agent/package.json` |
| **Quick run command** | `npx vitest run tests/rag/security tests/rag/context/wrap.test.ts` (plus the touched area, for example `tests/rag/v2`, `tests/rag/citations`, `tests/mcp`, or `uv run --directory rag-sidecar pytest -q tests/test_injection_classify.py`) |
| **Full suite command** | `npx vitest run && node --import tsx --test tests/*.test.mts tests/rag-db/*.test.mts && uv run --directory eval pytest -q && uv run --directory rag-sidecar pytest -q && node scripts/check-config.mjs && npm run typecheck:new && node scripts/ci/check-rag-boundary.mjs && npm --prefix voice-agent test` |
| **Estimated runtime** | quick: under 30 s per area; full: about 8 to 12 minutes (PGlite suites dominate); smoke tier about 2 minutes per configuration |

No test calls a live service. The rules detector runs on the committed rule file; Prompt Guard runs through a deterministic fake scorer in the sidecar (05.1-07) and a tiny randomly initialised local model for the real scorer (05.1-18); Lakera runs against recorded bodies in `tests/fixtures/security/lakera/responses.json` (05.1-08); the chat route runs on the route fixture with the PGlite database and captured `streamText`; the eval uses the stub extractive generator for injection items in the smoke tier.

---

## Sampling Rate

- **After every task commit:** the task's `<automated>` command (scoped to the touched area), plus `npm run typecheck:new` for TypeScript changes.
- **After every plan wave:** the full suite command above, plus the all-off smoke tier: `npm run test-rag -- --out eval/out/p51-wave && jq -e '.passed == true and .paired.all_zero == true' eval/out/p51-wave/gate.json`; from wave 4 on also the recommended configuration: `npm run test-rag -- --run-config eval/config/runs/sec-recommended.json --out eval/out/p51-wave-sec && jq -e '.passed == true' eval/out/p51-wave-sec/gate.json`.
- **Before `/gsd-verify-work`:** plan 05.1-22 Task 3 command chain green, `eval/reports/phase-05.1/comparison.json` passed (plan 05.1-22 Task 2), and `npm run gen:schemas` with a clean diff on generated files.
- **Max feedback latency:** 60 seconds for per-task commands (smoke-tier and comparison runs are per-wave or per-plan gates).
