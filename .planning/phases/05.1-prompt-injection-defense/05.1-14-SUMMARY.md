# Phase 05.1 Plan 14: The defense on the v2 pipeline, the hash and the eval trace

**Under `RAG_PIPELINE=v2` the injection check now runs where it has to: after parent expansion, before anything is budgeted, aliased or cited. Admin releases hold per tenant exactly as on legacy, downweighted text can no longer take an edge slot, tagged context comes out of the v2 renderer after compression and labelling, and both the retrieval config hash and the eval trace record the defense configuration, including whether Lakera actually ran.**

## Behaviour changes (switches on only)

- **Placement (v2 chat, embed, eval).** With `RAG_INJECTION_CHECK` = `flag` | `drop` | `downweight`, the v2 graph records `injection_check` after `expand_parents` and before `assemble`. It checks every top-k candidate, its image caption, the parent text it would be replaced by (when `RAG_PARENT_CHILD` fetched one) and referenced sections. Drop removes the chunk (or every child of a flagged parent) before budget selection, so it is in no block, no Phase 5 alias, no `kept` row and no `candidates` entry. With `expand_parents` disabled the check still runs.
- **Voice (v2).** `injection_check` runs on the voice chunks before `assemble`, rules only (both ML switches are ignored). Drop and downweight act as on legacy voice. With `RAG_CONTEXT_TAGGING=true`, `voice.context` is the wrapped result list, as on legacy voice.
- **Released rules (D-10).** A document version whose `metadata.quarantine.released_at` is set skips exactly its released rule ids. The metadata comes from the rows the scoped search returned (`hybrid_search_chunks` → `document_metadata`). No other read happens: tenant B's run issues the same requests with the check on and off and never names tenant A's document.
- **Downweight (Pitfall 8).** Flagged entries are re-ranked after the clean ones before budget selection, so they are the first excluded under a tight budget. A document group with any flagged chunk is placed after the clean groups, or in the middle of the edge-ordered clean groups when `RAG_CONTEXT_EDGE_ORDER=true`. It never sits first or last while there are at least two clean groups. With tagging on, its element carries `flagged="true"`.
- **Status.** If the check dropped something and nothing survived: `empty` / `injection_filtered` (strict chat then streams today's "information not available"). A refusal from the refusal stage keeps its own reason. A stall maps to `injection_check_stalled`. `RetrievalResult.injection` carries the summary. On eval refusals, the pre-refusal candidate list excludes dropped chunk ids.
- **Tagging (v2).** With `RAG_CONTEXT_TAGGING=true`, every v2 render (assemble, compress and the final labelled render) goes through `buildContext`'s `wrapDocuments` path. Each merged run is one `<doc>`: `S<k>` with a labeler, `c<n>` without, `img<n>` for image blocks, links last. The final context holds exactly one `<documents>` element with the compressed text.
- **Retrieval config hash (D-18).** When any 5.1 switch is not at its default, the hash input gains `security`: tagging, check mode, Prompt Guard, Lakera, `RAG_INJECTION_LAKERA_MULTI_TENANT_ACK`, `lakeraEffective` (`lakeraAllowed` for the deployment mode and key presence, never the key), tool guard, rules version and detector config version. A semantic cache keyed on it cannot serve an answer built under another defense configuration.
- **Eval trace (D-18).** `effective_config.security = {rules_version, detectors_version}` while `RAG_INJECTION_CHECK` is not off; otherwise the key is absent before parsing, so `config_hash` is unchanged.

With every 5.1 switch at its default, nothing changes. v2 records no stage and returns no `injection` field. The context is byte-identical and the assemble and compress counts are unchanged. The retrieval config hash equals the pinned pre-change value `f0bbcf06…`, and no rule or detector file is read for it. All v2 tests (tracer, matrix, refusal routing, voice budget, context stages and blocks) pass unchanged.

## Deviations

- **Files outside the plan list.** `src/lib/rag/pipeline.ts` now exports `runInjectionStage`, `injectionDropped`, `injectionFilteredAll`, `injectionReason` and `downweightOrder` so v2 shares the legacy stage logic. `src/lib/rag/context/assemble.ts` skips its "all-flagged documents last" move when the caller supplies `groupOrder`. Only v2 does, and that move would have put a flagged group in the last edge slot. The assembly sentinel was re-pinned after the differential, legacy post-filter and chat, overview, embed and voice characterization suites passed. `src/lib/rag/index.ts`, `src/app/api/internal/rag/run/route.ts` and `tests/rag/eval-route-stage-overrides.test.ts` changed for the trace block (next item). `injection-check.ts` gained only `injectionTraceVersions()`, which is additive.
- **Trace block location.** The plan put the version read in `trace.ts`. The boundary check rejects deep imports there, and importing `@/lib/rag` would break `eval/harness/run-eval.mts` (OPENAI_API_KEY check at import; `eval-v2-overlay` failed). So `buildEffectiveConfig({ security })` takes the versions, and the eval route passes `injectionTraceVersions()`. The `rules_version` grep on `trace.ts` still holds.
- **Task 2 GREEN commit.** The `contextTagging` pass-through was written with Task 1 (95dfbb9), because the v2 render input was restructured there. For Task 2's RED, the line was removed from the working tree, the tests were run and committed failing (2919ec0), and the line was put back. The wrapping-test acceptance grep matches the explanatory comment that names `wrapDocuments` in `context.ts`. The call itself lives in `buildContext`.
- **Placement inside `runContextStages`.** The plan describes the stage "between expand_parents and the context group" in `pipeline.ts`. The expanded parent text exists only inside `runContextStages`, so the chat/embed/eval check runs there. `pipeline.ts` runs the voice check and builds that path's released set.
- **No pinned hash existed** in `params-hash.test.ts`. A literal-only input and its pre-change hash (`PINNED_DEFAULT_HASH`) were added, so the all-default value cannot move silently.

## Decisions for STATE

- The v2 injection check sits after `expand_parents`, before budget and aliasing. Parent text is checked as part of each child, and a flagged parent removes its children under drop.
- Under v2, released rule ids come from `hybrid_search_chunks`' `document_metadata` (scoped). Neither graph adds a read for them.
- Downweight under v2 re-ranks before budget, and flagged groups go to the middle of the edge order. A group is flagged if any selected chunk is.
- `retrievalConfigHash.security` is present iff `anyNonDefault`, and it includes `lakeraEffective`.
- `effective_config.security` is set by the eval route through `injectionTraceVersions()`.
