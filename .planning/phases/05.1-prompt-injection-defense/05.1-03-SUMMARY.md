## Contracts

| Model | Mode | Bounds |
|-------|------|--------|
| InjectionClassifyRequest | validation | items 1..32; id 1..64 chars, unique; text 1..20,000 chars |
| InjectionClassifyResponse | serialization | model_id 1..200, revision 1..64; results ≤ 32, ids unique; score 0..1; label BENIGN or MALICIOUS; windows ≥ 1 |
| InjectionDetectorConfig | validation | see below |

InjectionDetectorConfig:
- `schema_version` is 1. `version` matches `YYYY-MM-DD.N`.
- `prompt_guard`:
  - `model_id` is `owner/name`.
  - `revision` is a 40-hex commit pin, so `main` is rejected.
  - `threshold` is 0..1.
  - `languages` is a non-empty, unique subset of en, fr, de, hi, it, pt, es and th.
  - `window_tokens` is 16..512. `stride_tokens` is at least 0 and smaller than `window_tokens`.
  - `max_items` is 1..32.
  - `inline_profiles` and `warm_profiles` are unique, disjoint subsets of chat, embed and eval.
- `lakera`:
  - `detector_types` is a non-empty, unique list of lower-case identifiers.
  - `min_level` is l1_confident..l5_unlikely or null.
  - `concurrency` is 1..8. `max_chars` is 1..100,000.
  - `profiles` is a unique subset of chat, embed and eval.
- `cache.max_entries` is 1..1,000,000. `inner_reserve_ms` is 0..1000.

Committed values:
- Prompt Guard: Llama-Prompt-Guard-2-86M at revision a8ded8e…, threshold 0.5, languages en and it, window 512, stride 64, max_items 16, inline eval, warm chat and embed.
- Lakera: detector type prompt_attack (assumption A2), min_level null, concurrency 4, max_chars 20,000, profiles chat, embed and eval.
- Cache: 5,000 entries. inner_reserve_ms: 25.

Zod parity: schemas enforce the field, range, enum and uniqueness rules. Three rules are Pydantic only because JSON Schema cannot express them: unique item and result ids, `stride_tokens < window_tokens`, and disjoint inline and warm profile lists. The committed file is checked against them in pytest. The generated Zod schema parses the committed file and rejects `voice` in a profile list and `zh` as a language.

## Deviations

1. **Added `lakera.profiles`** (not in the plan's field list). The plan's behaviour list requires rejecting voice "in any Prompt Guard or Lakera profile list", which needs a Lakera list. Committed value: chat, embed, eval. This matches plan 05.1-21's "only for the chat, embed and eval profiles". Plan 05.1-21 can read this list instead of hard-coding it.
2. **Media is rejected in ML profile lists as well as voice.** Reason: A-11 and plan 05.1-21 ("media stays rules only"). The ML profile type is a Literal of chat, embed and eval. Any other name fails, including voice, media and unknown names.
3. **Values the plan left open:**
   - Prompt Guard threshold 0.5 (the argmax boundary). Plan 05.1-23 records the false positives at this threshold.
   - `max_items` 16 (the research batch is 8 to 15 chunks).
   - Lakera `max_chars` 20,000 (matches the classify text bound). Lakera documents no size limit.
4. **Samples use placeholder ids.** The model id is `example-org/prompt-guard-model` and the revision is all zeros, per the plan's commit rule. A `InjectionDetectorConfig:lakera_min_level_null` variant was added.

## Decisions for STATE

- The Prompt Guard language set is restricted by type to the model card languages, so zh cannot be enabled by config (A-12).
- The ML detector profile lists accept only chat, embed and eval. Voice and media are rules only and are enforced in Pydantic and Zod.
- The Prompt Guard revision must be a 40-hex commit pin.
