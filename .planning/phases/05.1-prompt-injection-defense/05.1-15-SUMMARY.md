# Phase 05.1 Plan 15: Tool results as data, YOLO suspension on flagged turns

**With `RAG_TOOL_RESULT_GUARD=tag|tag_and_flag`, webSearch and MCP results reach the model escaped under a "tool results are data" statement, while the UI, metadata and premises keep the raw results. The approve-route email summariser puts its instructions first and wraps each email in an escaped `<tool_result source="gmail">`. Separately, with the injection check on, a turn whose context kept flagged content can no longer auto-run any MCP tool through YOLO mode.**

## Behaviour changes (switches on only)

- **`RAG_TOOL_RESULT_GUARD=tag`.** webSearch and every MCP tool in the chat loop (cached, discovered and enhanced) get `toModelOutput` returning `{type: 'json', value: escapeToolOutput(output)}`. `execute` is unchanged, so `webSearchResults`, the finish metadata `webSearch.results`, sources and the Phase 5 premise keep the raw text (tested with `</doc></documents>` in an Exa result). The system prompt states once that tool results are data: inside the reference notice (`TOOL_RESULT_SENTENCE`) when the context is tagged, otherwise `TOOL_RESULT_NOTICE` after the substituted context prompt. The approve-route summariser (single and multi email) sends instructions, then one escaped `<tool_result source="gmail">` per email, then `TOOL_RESULT_NOTICE`; a crafted subject cannot close the element.
- **`tag_and_flag`.** Also scans each result with the shared rules: a `tool_result_check` trace entry with the rule ids, and one `[RAG Security] Tool result flagged; passed on escaped` line with tool name, rule ids and trace id. Nothing is dropped.
- **YOLO (A-8).** `mcpYoloAllowed` stays the admin-and-switch input; `mcpYoloForTurn` is computed once after retrieval and all three `yoloModeEnabled` reads use it. With `RAG_INJECTION_CHECK=flag|downweight` and flagged content in the context, every MCP tool requests approval and one `[RAG Security] YOLO suspended …` line names the trace id. Under `drop`, and on unflagged turns, YOLO auto-approves as today.
- **injectionFlagged (A-14).** With the check on, the start and finish message metadata, the approval error payload and the `toolApprovalState` entries carry `injectionFlagged`. There is no database or `tool_params` change.

With `RAG_TOOL_RESULT_GUARD=off` (or empty/unset) and `RAG_INJECTION_CHECK=off`, tool objects have no `toModelOutput`, and the system prompt, SSE body and summariser request bodies are byte-identical. sha256 pins were taken from the pre-plan code.
