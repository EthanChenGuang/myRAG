# Phase 04.2 Plan 34: identifier normalization, near-miss distance and tenant-pattern tokens Summary

**Identifiers now have one normalization for index and query, a near-miss rule, a splitter that merges tenant patterns with the built-in shape, and tokenizer support through `options.identifierPatterns`. No caller passes patterns yet, so behaviour is unchanged.**

## Final signatures
```ts
// src/lib/rag/ids/normalize.ts
export const MAX_IDENTIFIER_INPUT_CHARS = 32_768;
export interface IdentifierEntry { raw: string; norm: string }
export function normalizeIdentifier(raw: string): string;
export function damerauLevenshtein(a: string, b: string, max?: number): number; // > max (max + 1) once exceeded
export function isNearMissIdentifier(askedNorm: string, otherNorm: string): boolean;
export function extractIdentifierEntries(text: string, extraPatterns?: readonly RegExp[]): IdentifierEntry[];

// src/lib/rag/ids/shapes.ts
export interface IdentifierSplit { text: string; identifier: boolean; extra?: true }
export function splitAtIdentifiers(text: string, extraPatterns?: readonly RegExp[]): IdentifierSplit[];
export function extractIdentifiers(text: string, extraPatterns?: readonly RegExp[]): string[];
```
- Rules: `normalizeIdentifier` is NFKC, then `toLowerCase`, then removal of `[\s\-_./]`. `isNearMissIdentifier` is false when the forms are equal or the asked form is empty. Otherwise it allows a distance of at most 1 when the asked form has at most 6 code points, and at most 2 when it is longer.
- Extra patterns are expected with `giu`. A pattern without `g` is recompiled with it, and empty matches are ignored. `extra: true` is set only on pieces where a tenant pattern won, so without extra patterns the output is the same as before (checked with `toStrictEqual`).

## Vector file format (`tests/fixtures/identifiers/near-miss-vectors.json`)
```json
{ "version": 1, "description": "...", "normalization": "...", "distance": "...", "near_miss": "...",
  "cases": [ { "id": "short-transposition", "asked": "QX4471", "other": "QX4417",
               "asked_norm": "qx4471", "other_norm": "qx4417", "distance": 1, "near_miss": true } ] }
```
- There are 31 cases. They cover width, case, each separator, whitespace runs, the ideographic space, transposition, both length classes, the 6/7 boundary, an identifier with no digit, one written with spaces, the restricted-transposition case and an asked form made only of separators.
- `distance` is the full distance with no maximum. The values were generated with an independent Python implementation (NFKC + `lower()` + OSA). The TypeScript code matches them, so the Python twin of 04.2-12 can use the same file as its oracle.

## Tokenizer behaviour with `identifierPatterns`
- **Chunk side.** A tenant match is pushed as whole + joined (+ code parts), the same as a built-in identifier. Its normalized form is added when neither of those equals it, so no duplicate is added. A tenant match that contains whitespace emits only its normalized form (pitfall 12). Every form goes through `acceptsToken`.
- **Query side.** The leading additive group is ordered dictionary, then identifier, then stem tokens, capped together at `MAX_ADDITIVE_QUERY_TOKENS` (16). It holds the normalized form of every tenant match. The form is also kept in the natural list, so with more than 16 identifiers none is lost.
- **No patterns.** With no options, `identifierPatterns: []`, or a pattern that matches nothing, the output is identical over the 19-file fixture corpus. `LEXICAL_VERSION` stays 2, and `lexical-options-identity.test.ts` passes again.
