# Phase 04.2 Plan 23: Identifier patterns panel Summary

**Workspace admins can now list, add, edit, enable, disable, delete and test their identifier patterns in Config UI, under RAG administration > Identifier patterns. The panel follows `04.2-UI-SPEC.md` sections 6.3 to 13, and every pattern match on screen comes from the test route. **Proxy finding.** `app.all('/api/rag/*path', …)` forwards every method, so PATCH and DELETE needed no allow-list change. But under Express 5, `req.params.path` is an array, and `String()` joined the segments with commas: `admin/identifier-patterns/<id>` reached the app as `admin,identifier-patterns,<id>`. This broke every multi-segment admin path through the Config UI server, not only this panel's. I fixed it in `buildRagProxyTargetPath` with a test that failed on the old code. Details are in `handoffs/04.2-23-proxy-wildcard.md`.

## What was built

- **List:** creation order; Name, Pattern with its letter-case line, Status badge (word and icon), Updated, and three named row actions. The count reads "Patterns: n of 20". At 20 patterns, Add pattern is `aria-disabled` and points to the limit line. The empty state is shown when there are no patterns. A refresh dims the list instead of clearing it.
- **Form:** opens inline between the list and the test region, with one form for both add and edit. Name, Pattern (monospace, no `maxlength`, live count, Enter inserts no line break), Ignore letter case (writes `iu` or `u`) and the three shape examples. Local checks run on every input: required fields, length, one line, the pattern compiles with `u`, and the pattern does not match the empty string. Server findings replace local ones and are wired to their field with `aria-describedby` and `aria-invalid`. A form with unsaved changes asks before closing (Discard dialog with Keep editing focused, plus `beforeunload`). Escape closes the form.
- **Enable and Disable** update the row in place and keep focus on the button. **Delete** confirms first, with Keep pattern focused. After a delete, focus moves to the row that took its place, or to Add pattern when the list is empty. A 404 on delete counts as done.
- **Test region:** the sample has a count against 10,000 and no `maxlength`. The draft is sent when the form has no Pattern finding; in edit mode the draft carries its id. The scope line states which patterns ran. The result shows the summary, the marked sample (built from the server's offsets, with overlapping matches merged), the stored-form ledger (spellings and sources joined with `Intl.ListFormat`, Cc and Cf characters shown as `[U+XXXX]`), the legend and the truncation line. It also covers the no-match block, the "positions unavailable" line, a draft the server refuses (the finding goes into the form and focus moves to Pattern), the stale state and the unavailable state.
- **Notes:** `note.indexOff` appears while `#RAG_IDENTIFIER_INDEX` is unchecked, with a button that opens RAG Modes and focuses the switch. `note.rebuild` appears after any pattern change and shows `npm run rag:identifiers -- --tenant <key>` and `npm run rag:relex -- --tenant <key>` as code elements.
- **Tenant:** in single-tenant mode, no `organizationId` is sent and the description ends with "Applies to this deployment". In multi-tenant mode, every call carries `#workspace-selector` as `organizationId`, the workspace name line is shown, and the panel reloads when the selector changes. On a workspace change, an edit form closes with a notice; an add form keeps its values and names the new workspace.
- **Errors:** `mapIdentifierPatternsError` maps every row of UI-SPEC 8.2. 401 and 403 `Admin access required` replace the panel with the sign-in alert. 403 `Forbidden` shows the workspace alert. A 503 on the list keeps earlier rows dimmed and disables writes.
- **Safety:** DOM is built with `createElement` and `textContent` only. There is no web storage, no cookie, no `Authorization` header and no `console` output. Each request has a 15-second `AbortController` timeout raced against the fetch, and a request counter drops stale list and test answers. Every top-level name carries the panel's prefix. The panel reads only two page inputs: `#RAG_IDENTIFIER_INDEX` and `#workspace-selector`.

## Deviations
1. **Bug fix outside the panel:** the Express 5 wildcard join in `scripts/config-server.js` (Rule 1: a fix with a test that failed first). The plan expected `config-server.js` to change only for a method allow-list, and no such list exists.
2. **`max-md:hidden` / `max-lg:hidden` instead of `hidden md:table-cell`:** `index.html` has `.hidden { display: none !important }`, so the UI-SPEC's responsive columns would never show. A test forbids the pattern in this file. The same defect affects 11 sibling panels; that is reported in `handoffs/04.2-23-hidden-utility.md` and was not changed here.
3. **`figure` carries `!block`:** DaisyUI's `.card figure` makes a figure a centred flex row, which put the caption beside the marked sample.
4. **Ledger codes are chips** (`bg-base-200 rounded px-1`): without them, the spellings "AB-1234 ab 1234" read as three words. Spacing stays on the 4px token.
5. **Italian copy uses ’** in place of straight apostrophes (typography rule; wording unchanged).
6. **The test in `tests/ui/config-languages-panel.test.ts` that pins the tab's intro sentence** now expects the added words "and identifier patterns", as the plan asks.
7. **Finding-code mapping beyond UI-SPEC 8.2:** see key-decisions. The copy proposal is in `handoffs/04.2-23-finding-copy.md`.
