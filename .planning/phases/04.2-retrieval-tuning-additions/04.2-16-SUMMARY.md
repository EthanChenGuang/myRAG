## Threshold rule (D-49)

`dupClusterThreshold(embeddingProfileId, { evalRun })` reads `eval/config/dup-cluster-params.json` once per process
(`process.cwd()` + `eval/config/…`), validated with `DupClusterParamsFileSchema`. It returns:

- the profile's entry when its source is `live`;
- the profile's entry when its source is `fixture` **and** `evalRun` is true;
- otherwise the file's top-level threshold;
- 0.95 with no file (ENOENT is silent);
- 0.95 with an invalid file (unreadable, not JSON, schema failure), with one `[RAG Config] eval/config/dup-cluster-params.json is invalid; the duplicate threshold 0.95 applies` warning per process.

Clustering (`clusterChunksForTenantKey`, and through it `clusterChunks`, `clusterPublishedDocument` and the `rag:dup-clusters` backfill) works out its threshold as follows. An explicit `threshold` option wins. Otherwise the rule above applies with `evalRun` (default false) and `embeddingProfileId`. When no profile is given, the active profile id is read only if the file names at least one profile. With no file there is no extra read, so behaviour is byte-identical to before. A profile lookup failure falls back to the top-level threshold. No production caller sets `evalRun`.


Exit codes: 0 ok (including `uncalibrated` or no choice), 2 usage, 3 harness.

- **Pair lines** have exactly these keys: `tenant, embedding_profile_id, chunk_a, chunk_b, hamming, cosine, same_template`. They hold ids and numbers only, and `load_pairs` refuses any other key.
- **Fit:** the smallest candidate cosine t in (0, 1] such that every pair with cosine ≥ t is `same_template` (precision 1.0). The result carries recall, n and the full table. With no positive pair, or no t at precision 1.0, the status is `uncalibrated` and nothing is written.
- **Writes:** always through `finalize_config(..., provenance_source="calibration")` and `write_config_atomically`. Only the one profile's entry changes, and the top-level threshold is never moved.
- **Fixture runs** never replace an existing `live` entry of the same profile (see Deviations).
- **Live runs** need `--pairs` and `--embedding-profile`. With `--write-params`, a pairs file inside the repository is refused.

## Choice rule (printed verbatim in the sweep report)

> A lambda is eligible when no slice (overall, every language, every category) drops on Recall@10 beyond the noise band against the reference run (the same run config with RAG_RESULT_DIVERSITY=collapse). Among eligible lambdas take the highest duplicate_flood intent_coverage, then the lowest duplicate_flood topk_redundancy, then the highest mean Recall@10 over all slices, then the largest lambda. No eligible lambda: no choice, nothing written, the default 0.7 stays.

- **Noise band:** `noise_band(noise.json)` from the retrieval sweep, `max(k·spread, floor)` with spread 0, so it equals the floor (0.02).
- **Grid:** 0.5, 0.6, 0.7, 0.8 and 0.9, on the dev split only. Each cell runs `overrides.diversity = {…base, mmr_lambda}` with env overlay `RAG_RESULT_DIVERSITY=mmr, RAG_DUP_CLUSTERS=true`. The reference runs with `collapse` plus the dup-clusters switch. A report with a non-dev split is refused.
- **Report:** per lambda, duplicate_flood intent_coverage and topk_redundancy, Recall@10 per slice and nDCG@k per slice (report-only).
- **`--write-run-config`:** fixture only. It sets that one key atomically and leaves every other key unchanged.
- **`--write-params`:** live only. Without `--base-url` it fails with "a fixture run can never replace the committed retrieval params". On a live run it writes `mmr_lambda` and nothing else, with provenance `sweep`.

## Deviations from Plan

1. **A new contract model, `DupClusterParamsFile`.** It is `DupClusterParams` plus `provenance` and `config_hash`. The plan needs a stored `config_hash`, and `DupClusterParams` is strict without those fields. `DupClusterParams` is embedded in `RetrievalOverrides`, so changing it would have altered the override schema, the baselines' schema and serialized eval overrides. The file model leaves them byte-identical. The registry, TS and the tests use the file model.
2. **A fixture run never replaces a `live` entry of the same profile.** It writes nothing and reports `write_skipped_reason`. The plan did not cover this case. The fixture database's profile id is `openai-3-small-1536`, the real legacy production id, so without this rule a fixture run could erase a live calibration.
3. **`dupClusterParamsHaveProfileEntries()`** was added so clustering reads the active profile only when the file names a profile. Without a file, the publish path makes no new call.
4. **The file is read with `readFileSync` on first use, not a static JSON import.** A static import fails the build while the file is missing, which is the normal state.
5. **`--write-run-config` together with `--base-url` is a usage error.** A live value goes to `retrieval-params.json` through `--write-params`.
6. **Recall@10 eligibility** uses per-slice means against the reference with the sweep's noise band (`noise_band`), not the paired `slice_drops`. The fake-runner tests use synthetic reports without item pairing. This keeps the rule explicit and the same as the retrieval sweep's band arithmetic.
