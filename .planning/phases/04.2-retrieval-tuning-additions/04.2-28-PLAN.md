Rules for every task:
- Domain neutrality (REQUIREMENTS.md top): invented, neutral vocabulary; structural file names; identifiers described by shape (letters, digits, separators); no word, value or example from the existing fixture file names or from `src/lib/rag/retrieval/exact-id.ts` (D-57).
- No new document may share a content word with the pre-existing corpus (research pitfall 9: new near-identical documents are distractors for the n-gram fixture embedder). A test enforces it.
- Generated copies are produced by the loaders at build time from committed templates; the 90 documents are never committed as files (D-20).
- This plan changes the corpus and the golden set, so the tree is consistent only after Task 4. No other plan may run `npm run test-rag` or build a fixture database between this plan's first commit and its last (state it in the SUMMARY); a smoke run of another plan in that window reports a data mismatch.
- Never re-record over a paired difference on an old item: stop and hand off instead (D-37).
- PGlite plan: never run at the same time as another fixture-database plan in the same tree.
- Commit with plain `git commit`; the message ends with the attribution lines the executor's own session supplies. Hand-off notes go to `.planning/phases/04.2-retrieval-tuning-additions/handoffs/04.2-28-<topic>.md`.
