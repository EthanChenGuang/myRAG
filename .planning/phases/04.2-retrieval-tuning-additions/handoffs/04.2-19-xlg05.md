# 04.2-19 hand-off for the coordinator: XLG-05 glossary pairs (D-38 d)

Date: 2026-11-26

- LANG-07 (index side, plan 04.2-19) builds the per-tenant lexical dictionary from `rag_term_effective` and **includes `translation`-kind entries** (D-08). The 4.1.1 query matcher skips translation pairs (4.1.1 D-32); the lexical resolver feeds them to the same `buildMatcher` as ordinary terms, so their canonical and variants become `_t_` tokens.
- XLG-05 glossary pairs need no extra code on the lexical side: once Phase 6.2 stores them as `translation` entries in `rag_term_entries`, the next `npm run rag:relex -- --tenant <key> --stale-dictionary` (the dictionary version changes on every write) puts them into stored lexical text, and the query side (plan 04.2-22) picks them up from the same loader.
- Qualifying rule applies to them as to every term: Han of 2 or more characters, Latin of more than one word or with an elision.
