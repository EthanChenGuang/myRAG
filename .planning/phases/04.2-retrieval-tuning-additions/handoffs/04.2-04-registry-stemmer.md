# 04.2-04 hand-off: registry fields the tokenizer does not drive yet

Date: 2026-11-26. Plan 04.2-04 took the registry branch (D-11): `config/rag/language-packs.json` and
`src/lib/rag/lang/registry.ts` exist, so `src/lib/rag/lexical/tokenize.ts` now reads stopwords
(`stopwords.lexical`), elision prefixes and suffixes (`folding.elision_*`) and the Han stopword set
(packs with `segmentation: intl_segmenter_han_bigrams`) from the shipped registry. Two fields stay open:

1. `stemmer` is `null` for every pack, `it` included. The tokenizer's stemmer availability is
   "the registry has the pack and an in-repo stemmer exists" (`lexicalStemmerAvailable`), and the
   only in-repo stemmer is `stemItalian`. Setting `stemmer` for `it` (for example `"snowball_italian"`)
   needs an edit of `config/rag/language-packs.json` and its sidecar copy `rag-sidecar/config/rag/`,
   which 04.2-04 does not own. Once set, the tokenizer can key its stemmer table by that value.
2. `folding.accents` is `true` for every pack. Folding is applied to the whole text before the language
   is known, so a per-pack `false` has no defined meaning yet; the tokenizer reports the value
   (`lexicalRegistryRules().foldAccents`) and the equality test fails when a pack turns it off, which
   forces the decision instead of silently changing every tenant's lexical text.

Also stale: the header comment of `tests/rag/lang-registry-equality.test.ts` still says the tokenizer
does not read the registry; its checks still pass and remain useful.
