## Real defects within the UI-SPEC

1. **WARNING: needsV2 ignores a switch in this box.** `retrieval-tuning-switches.js:16-25` (`RETRIEVAL_TUNING_CHECKBOXES`) leaves out `RAG_LEXICAL_QUANTITY` (index.html:6735). If an admin turns on only that switch while the pipeline is legacy, the note "these switches are read by the v2 pipeline only" stays hidden. The note's text says it covers all of these switches. Fix: add the id to the list, which also binds its change listener.
2. **WARNING: line length in zh is uneven.** In zh.png, the stored lines (for example at index.html:6722, :6766, :6779, :6797) and the diversity note (:6788) reach the full width of the box, while help lines wrap at prose width. Section 6.2 and the deliberate `max-w-prose` change expect one reading measure. Check whether `retrievalTuningFill` (js:183-200) or the `ch` measure with CJK text plus inline code is breaking the `max-w-prose` cap.
3. **Minor, copy: the RAG_LEXICAL_QUANTITY stored line has no closing period** (index.html:6739). It also wraps only the lead-in in `data-rag-i18n` and leaves the command outside the localized node. This is inconsistent with the other stored lines, which use the `{command}` placeholder pattern.
4. **Minor, spec conflict: the pointer button is coloured primary.** `btn-link` at index.html:6800 renders in primary, while section 13 says links are not primary. Either resolve it in the spec or add `text-base-content underline`.

## Deliberate deviations: verdict

- **`max-w-prose` on stored lines and notes:** good in en. In zh it does not hold (see defect 2).
- **`break-words` instead of `break-all` on commands:** correct. The 360px capture shows commands wrapping inside the box with no page scrolling sideways, which meets the intent of section 10 better than `break-all` would.
- **`min-w-0 break-words` on labels:** this is what prevents overflow at 360px. The price is that env names break mid-token, which is acceptable.
- **Pointer button with `shrink h-auto min-h-6 text-left`:** it wraps cleanly at 360px and keeps a hit target of at least 24px. Accepted.
- **RAG_ATTRIBUTE_FILTER triggers needsV2:** correct, because that control only works under v2. It also shows the gap in defect 1.

## Nice-to-haves (not defects)

- At 360px each label takes 3 to 4 lines. Wrapping the env name in a separate `text-xs` line would shorten the box.
- The needsV2 note could name the "Pipeline" control by its visible label rather than "above".
- RAG_ATTRIBUTE_FILTER and RAG_LEXICAL_QUANTITY stay in English in zh and it. They are correctly marked `lang="en"`, so this is acceptable until their own phase translates them.
