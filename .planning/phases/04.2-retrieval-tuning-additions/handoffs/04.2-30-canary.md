# 04.2-30 hand-off: canary cases for the Phase 7 RET-08 suite (D-54)

`tests/rag/canary/` does not exist on this branch (checked 2026-11-26 on `exec/04.2-30`), so plan 04.2-30 proves the four Phase 4.2 paths in the two-tenant v2 matrix only (`tests/rag-db/v2-two-tenant-matrix.test.mts`, paths `table_lookup`, `identifier`, `versions`, `dup_cluster`). The Phase 7 session that builds the RET-08 canary suite should add these four cases. The seeds and questions already exist in `eval/harness/two-tenant-v2.mts` (`seedLookupRows`, `clusterLookupCopies`, `seedTwoTenantV2Lookups`, `tableQuery`, `identifierQuery`, `versionQuery`, `V2_DUP_QUERY`); reuse them rather than writing new rows.

Every case runs in both deployment modes. In multi-tenant mode it uses tenants a, b and o. Each tenant asks once with its own markers and once with each other tenant's markers. In single-tenant mode it uses the default tenant, and the personal and organization scopes must be refused (`backend_error`).

| Case | Switches | Own markers: expected | Another tenant's markers: expected |
| --- | --- | --- | --- |
| Table rows | `RAG_TABLE_LOOKUP=true` | stage `table_lookup` ok, detail ends `rows=1`; the own table chunk heads list `table:0` | no row: detail ends `rows=0` (when the stage ran), no candidate with a `table:0` leg, no chunk or text of the other tenant |
| Identifiers and suggestions | `RAG_IDENTIFIER_INDEX=true`, `RAG_IDENTIFIER_FILTER=true` | `identifier_resolve` detail `asked=1 found=1 filtered=true`; every candidate carries the asked identifier; no suggestions | detail starts `asked=1 found=0`; no identifier suggestion names the other tenant's identifier or its one-edit neighbour; no foreign chunk |
| Superseded versions | `RAG_VERSION_SCOPE=true` (needs `RAG_LEXICAL_SEARCH=true`), `RAG_EMBED_VERSION_SCOPE=true`, request `versionScope: 'all'` | the own superseded chunk comes back (voice ignores the scope and does not return it) | neither version of the other tenant's lineage, no superseded text |
| Duplicate clusters | `RAG_DUP_CLUSTERS=true`, `RAG_RESULT_DIVERSITY=collapse` | collapse keeps one own copy; its `alsoIn` lists only own documents | the same question from every tenant; `alsoIn` on kept chunks and used documents names only the caller's documents; `rag_dup_cluster_sources(<caller key>, [<other tenant's cluster>])` returns no row, while the owner gets all its copies |

The canary suite should also keep the key-mode checks from the matrix: every Phase 4.2 tenant function rejects a tenant key of the other deployment mode with `tenant key not valid for this deployment mode`.
