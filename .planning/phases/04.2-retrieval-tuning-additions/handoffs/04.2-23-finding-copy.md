# Hand-off from 04.2-23: finding codes without their own sentence

Plan 04.2-17's service returns nine pattern finding codes; UI-SPEC 12.3 has sentences for five of them.
`mapIdentifierPatternsError` maps them as follows:

| Server code | Key shown | Note |
|-------------|-----------|------|
| `matches_empty` | `finding.no_alphanumeric` | its sentence already says "or nothing at all" |
| `backreference` | `finding.other` (code shown in a code element) | no sentence in UI-SPEC |
| `lookbehind` | `finding.other` | no sentence in UI-SPEC |
| `invalid_flags` | `finding.other` | unreachable from the panel: the route schema allows `u` and `iu` only, and the form writes only those |

Proposal for a UI-SPEC amendment (en; zh and it to be written with it):
- `finding.backreference`: "The pattern refers back to an earlier group, for example \1. Identifier patterns cannot do that. Write the repeated part out instead."
- `finding.lookbehind`: "The pattern looks behind the match, for example (?<=…). Identifier patterns cannot do that. Remove that part."
