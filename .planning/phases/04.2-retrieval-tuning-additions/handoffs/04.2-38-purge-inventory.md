# 04.2-38 hand-off: purge inventory rows for Phase 6.3 (plan 06.3-19)

`public.rag_purge_store_inventory()` was not on trunk when 04.2-38 ran (branch b), so migration 0864 ships the hooks only and leaves the inventory alone.

When 06.3-19 writes the inventory, list these relations (columns `relation, store_id, handling, reason`):

| relation | store_id | handling | reason |
| --- | --- | --- | --- |
| `rag_table_rows` | `table_rows` | `hook` | `rag_purge_hook_table_rows` |
| `rag_dup_clusters` | `duplicate_groups` | `hook` | `rag_purge_hook_duplicate_clusters` |
| `rag_dup_chunk_bands` | `duplicate_groups` | `hook` | `rag_purge_hook_duplicate_clusters` |
| `rag_identifier_patterns` (only if the walk lists it) | — | `exempt` | `tenant settings, no document reference` |

Hooks (0864): `public.rag_purge_hook_table_rows(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint` and `public.rag_purge_hook_duplicate_clusters(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[]) RETURNS bigint`. Both SECURITY INVOKER, `SET search_path = ''`, service_role only.

Call contract:
- Call them before the chunk and document delete. A listed id whose document no longer exists is skipped. A listed id of another tenant, or of another lineage when `p_lineage_id` is given, raises 22023 and removes nothing.
- Only the listed versions are purged. `p_lineage_id` is checked but does not widen the purge, so pass every version id of the lineage.
- Count the results under `table_rows` (rows removed) and `duplicate_groups` (chunk memberships removed).

The identifier index (RET-15) is the `identifiers_norm` / `identifiers_raw` columns on `document_chunks` and `documents`, so it goes with those rows and needs no hook.
