# Phase 4.2 Plan 11: voice text TTFT measured in the agent and attached to the retrieval trace

**The voice agent measures its own time to first text delta and posts it to a new internal app route, which writes `ttft_ms` and `pre_generation_ms` as NUMERIC Langfuse scores on the retrieval trace and always logs one line with ids and numbers only. `voice-rag` now returns the retrieval `traceId` on both success answers.**

## Task 1: upstream gate

`04.2-08-SUMMARY.md` exists and `postLangfuseScores` is exported from `src/lib/rag/index.ts`; 04.2-08's own dependencies (04.2-01, 04.2-02, and through them 04.1-12) have SUMMARYs, as 04.2-08's gate recorded. No upstream note. Hand-off for the coordinator (D-38 i): `handoffs/04.2-11-voice-ttft-point.md`.

## Behaviour

App, `/api/internal/voice-timing` (4-space indentation, `{ error }` shape, same check order as `voice-rag`):
- Server key unset: 500 `Server configuration error`. Missing or wrong `x-api-key`: 401 (constant-time `internalApiKeyMatches`; added to `tests/rag/internal-api-key.test.ts`).
- Body not JSON: 400 `Invalid JSON body`. Unknown field, trace id not 32 lower-case hex (`isTraceId`), a timing that is negative, fractional, a string or above 120000, or `pre_generation_ms > ttft_ms`: 400 `Invalid timing body`.
- Scope: `resolveVoiceScope`, so a missing or forged token gives 401, an unconfigured secret 503, a non-member organization token 403.
- Valid: `postLangfuseScores([{ttft_ms}, {pre_generation_ms}])` (NUMERIC), log line `[Internal RAG] voice timing { traceId, ttft_ms, pre_generation_ms, scores }`, answer 202 `{ accepted: true }`. Langfuse off (`skipped`) or failing still answers 202 and logs. A repeat post for the same trace reuses the score ids (`scoreId(traceId, name)`), so it overwrites.
- An unexpected throw answers 500 `Internal Server Error` with no stack or body echo.
- No cache score is written: voice never uses the semantic cache; the report treats voice as `bypass`.

App, `/api/internal/voice-rag`: `traceId: result.traceId` on `{ results: [] }` and on the full answer. Error answers (401/403/503/400/500) are unchanged. This is a wire change for every caller: the body gains one key.

Voice agent:
- `RAGClient.query` returns `traceId` only when the app sent a 32-hex string; with an older app the key is absent, so the result is identical to today.
- `RAGClient.reportTiming` posts to the `voice-rag` URL with `/voice-rag` replaced by `/voice-timing`, with `x-api-key` and `x-rag-scope-token`, timeout 2000 ms (constructor option `timingTimeoutMs`). 500, refused connection and timeout resolve; each failure increments a counter logged in one `console.debug` line with the status and count only.
- `processUserMessage`: `turnStartedAt` at the top, `generationStartedAt` right before `llm.chat.completions.create`, the first non-empty `delta.content` triggers `reportTiming` once, not awaited, wrapped against sync throws and rejections. No trace id (older app, retrieval failed or skipped), or an interruption before any delta: no post. The audio path is untouched; the agent makes no database call (boundary rule `voice-agent-rpc` passes).

Score names: `ttft_ms`, `pre_generation_ms`.

## Deviations from Plan

1. `tests/rag/internal-api-key.test.ts` (not in the file list) gained `voice-timing`, so the constant-time key check of the new route is covered by the shared test.
2. Existing `voice-rag-route` assertions that pinned the exact body keys (`['results', 'source_images']`, `{ results: [] }`, and equality between two answers) now include or strip `traceId`, since every answer has its own trace id.
3. The agent clamps `ttft_ms` to at least `pre_generation_ms` and rounds both, so a clock step never produces a body the route rejects.

## Decisions for STATE

- Voice TTFT is measured in the voice agent (first text delta of its own LLM stream), not server-side in the app (D-39, D-38 i).
- The timing post happens at the first delta, not at the end of the turn, and is never awaited.
- Bounds: integers 0..120000 ms, `pre_generation_ms <= ttft_ms`; a 32-hex trace id.

## Operator actions

- **Deploy the app and the voice agent together** (AGENTS.md section 8). Order: app first is safe (an old agent ignores `traceId`); an agent without the new app gets no `traceId` and posts nothing.
- No switch was added. Scores reach Langfuse only when Langfuse is configured; the log line is written regardless.
