# 04.2-31 Summary: pre-registered Phase 4.2 gates

All Phase 4.2 gates and both decision rules now have their numbers committed, before any gated run exists. The spec is `eval/config/phase42-gates.json`. It uses seven new run configs, and one command evaluates the spec. No gated configuration was run, and `eval/reports/` is unchanged.

## Command
```
uv run --directory eval python -m rag_eval.phase42_gate --spec eval/config/phase42-gates.json --out <dir> [--only <gate>]... [--reuse <dir>]
```
- Gates: `off_identity`, `diversity`, `identifier`, `table`, `versions`, `dictionary`. Rules: `stem_it`, `refusal_mode_cells`.
- `--only` can be repeated. It runs only the harness runs that the selected gates need.
- `--reuse <dir>` reads `<dir>/harness/<run>/{report.json,traces.jsonl,run.json}` from an earlier `--out` instead of running the harness again.
- Output: `<out>/gates.json` and `<out>/README.md`. Each gate records passed, numbers, offenders and decision id. Each rule records its outcome, numbers and reasons. A runs table gives each run's environment and run-config hash.
- Exit codes: 0 when every selected gate passes; 1 when one fails; 2 on usage errors (unknown gate, missing run-config file named, unreadable spec, baseline, calibration result or reused run); 3 on harness errors. The two rules are decisions, so they never cause exit 1.

### Descriptive slice (D-32)
The descriptive slice is the gated (dev-split) items whose trace in the `v2-identifier-on` run has an `identifier` block with `asked` ≤ 0. Those are the questions in which the pipeline's own extraction found no identifier. Items without the block are not counted. The slice is compared with the same item ids in `v2-default`; an id missing there is an offender. The means are taken over answerable items (`paired.item_metrics`).

### Decision rules
- **stem_it (D-10):** the outcome is `flip` only when the `language:it` Recall@10 gain of `v2-lexical-stem-it-on` over `v2-default` exceeds the band (max(k × spread, floor) of the one-run reference, so 0.02) and no slice drops. Otherwise it is `keep_off`. The record holds the on value, the reference value, the gain, the band, the dropped-slice count and the reasons.
- **refusal_mode_cells (D-23, D-24):** this rule reads the calibration result named in the spec (`eval/reports/refusal-calibration-fixture/refusal-calibration-result.json`). The outcome is `commit` only when, for every base cell considered, all three mode cells (strict, balanced, flexible) exist, have `fit_status` `fitted` with a threshold, and have status `calibrated` (holdout passed), and the strict threshold is ≥ the base (`*`) cell's threshold. Otherwise it is `keep`. A base cell is skipped when its shared cell and all its mode cells are `insufficient_data`, since none of them would be committed. If no mode cell is evaluated at all, the outcome is `keep`. On today's committed fixture result the rule says `keep`: `it|same` balanced and flexible fail holdout, as does the shared cell. That is the 04.2-07 fixture drift; 04.2-32 re-runs calibration first.
