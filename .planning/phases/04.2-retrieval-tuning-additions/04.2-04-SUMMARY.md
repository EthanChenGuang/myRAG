# Phase 04.2 Plan 04: tokenizer options, Snowball Italian stemmer Summary

**The shared lexical tokenizer takes an optional `LexicalOptions` argument that can add `_t_` dictionary tokens and `_s_` Italian stem tokens. The stems come from an in-repo Snowball port that matches all 37,426 official vectors. Without the argument the output is byte-identical and `LEXICAL_VERSION` stays 2. No caller passes options yet.**

## Accomplishments
- `stemItalian` ports `algorithms/italian.sbl` (elisions, prelude, RV/R1/R2 with the `divan` exception, attached pronouns, standard, verb and vowel suffixes, postlude) and matches the official output for every word on its first run. No package was added (D-10).
- The vectors come from `snowballstem/snowball-data` commit `019921c3a41c2b70063ee3feb215a00c8e594597`:
  - `voc.txt` SHA-256 `8081c7fd8cc1bb0608b504c3a9fb2e7697c4e00457be2db693bd5ca3fad641da`
  - `output.txt` SHA-256 `88ed5959a10f38231f5872d0a9712283f3dbf6ca123282976dacdaf6ed8426b6`
  - `COPYING` (3-clause BSD) is from `snowballstem/snowball` commit `a113a1a474cb5e5672b6c5e5ef4ded70b3ab39b8`, SHA-256 `880802872ce34f313df826e96131b1b147dcfa09c76fc82129f25503a922a678`.

  The test checks all three hashes again.
- Dictionary matching runs on the normalized text through `options.dictionary.match` (the 4.1.1 contract). Each qualifying term becomes `_t_<term>`, with whitespace runs and apostrophes replaced by `_`. Every additive token passes the same `pushToken` checks: no quote, backslash or whitespace, and at most 64 characters. A longer token is dropped, never truncated (T-04.2-13).
- With `stemIt` true and language `it`, each Latin word adds `_s_<stem>`. The stem is computed on the unfolded lowercase word and folded afterwards (D-55). In the test, `Zorverò` gives `_s_zorv` and `Zorvero` gives `_s_zorver`, which shows the stemmer reads the accent.
- In `queryLexicalTokens`, additive tokens come first, capped at 16, and natural tokens fill up to 64 in total (T-04.2-15). This is tested with an 80-word query.

## Deviations from Plan
1. **[Rule 1, perf] `foldLatin` built a RegExp on every call.** Vitest's transform turns the `\p{M}` literal inside the function into a `new RegExp` on each call. With stemming on, the per-token regex test failed (5002 regexes built). The pattern is now a module-level `COMBINING_MARKS`. Output is unchanged: the corpus digest is the same before and after.
2. **Test typo fixed in the GREEN commit.** The two-word dictionary case used a double space, which the stub matcher (not the real one) cannot find. It now uses a single space.
3. **"Stemmer availability for `it` is true" is computed, not read from the registry.** The registry `stemmer` field is `null` for every pack, and editing `config/rag/language-packs.json` and its sidecar copy is outside this plan's files. See the hand-off `handoffs/04.2-04-registry-stemmer.md`.
4. **The identity proof is two-sided.**
   - The committed test compares the omitted, `undefined`, `{}` and inert-option call forms over the corpus and every string literal of the existing tokenizer tests. Following the plan, it stores no snapshot.
   - A one-off digest of all five functions over the 19 corpus files was taken before the tokenizer change and after it. Both are `dd3562a14d13649a23ff11c194518b289f26a0296144cd767bc602f5eb1d5c03`.
