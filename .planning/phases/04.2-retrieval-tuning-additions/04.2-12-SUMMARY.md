### Exact definitions of the new item metrics
| Field | Definition |
|---|---|
| `context_k` | `len(trace.kept)`, or 0 when the trace is refused. Set on every item. |
| `ndcg_at_context_k` | Set on answerable items only. It is `ndcg_at_context_k(gold_unit_first_hits(trace, item), context_k)`, and 0.0 when k is 0. The slice reports the mean, and `k_zero` holds the count of answerable items with k = 0 (`value` = count, `n` = answerable items). |
| `group_count` | `len(evidence_groups)` when the item has groups, otherwise None. |
| `topk_redundancy` | The largest number of kept chunks sharing one `dup_cluster_id`, divided by `context_k`. A chunk without a cluster id is its own cluster. None when `context_k` is 0. The slice reports the mean. |
| `intent_coverage` | Set on answerable items with `evidence_groups`: true when every group has a kept chunk (any position) matching one of its spans. It is false when the trace is refused or the context is empty. The slice reports the rate. |
| `identifier_precise` | Set on `identifier_near_miss` items. **Answerable:** the trace is not refused, no kept chunk leaks, at least one kept chunk's `identifiers_norm` holds the asked identifier, and every cited chunk id belongs to a kept chunk that holds it. **Not answerable:** the trace is refused and nothing leaked. |
| `near_miss_leak` | Set on `identifier_near_miss` items: true when any kept chunk holds an identifier `x` with `is_near_miss(asked, x)` and does not hold the asked identifier itself. This is computed even on refused traces. |

Both identifier fields are None when any kept chunk has `identifiers_norm` None, which is the case for traces recorded before this phase. The slices report `identifier_precision` and `near_miss_leakage` as shares, with n, over the items that carry the value.

### Grouped items
`span_count` is the number of gold units, which is the number of groups when the item has `evidence_groups`. `spans_hit_at_5` and `spans_hit_at_10` count hit units, and `first_hit_rank` is the best unit rank. Spans outside every group are not counted, the same rule as 04.2-05.

## Task 3: identifier twin, identifier metrics, TTFT (D-25, D-27, D-32)
- `identifiers.py` normalizes with NFKC, then `str.lower()` (the same as `toLowerCase`, not `casefold`). It then removes the JavaScript `\s` class plus `- _ . /`. Python's `\s` is not used, because it also matches U+001C..U+001F and does not match U+FEFF. Distance is OSA over code points with an optional bound. The near-miss rule is at most 1 edit for forms of up to 6 code points and at most 2 above. All 31 shared vectors pass.
- **Tag convention:** every `identifier_near_miss` item carries `asked_identifier:<spelling as asked>`. The value is normalized with `normalize_identifier`. A missing tag, or one that normalizes to empty, raises `ValueError` naming the item id.
- **TTFT:** `EvalReport.ttft` holds nearest-rank p50, p95 and n per cache state, computed over traces that have both `ttft_ms` and `cache`. A run where no trace has `ttft_ms` gives None. `EvalReport.pre_generation` is `{"chat": ...}` over every trace with `pre_generation_ms`.
- The markdown block always lists hit, miss and bypass (n 0 shows dashes) and a pre-generation row. Each row shows the `ttft.chat.<state>` or `pre_generation.chat` budget and is marked report-only. The block is absent when neither field is set. `eval/config/latency-budgets.json` has no ttft section yet, so the budget cells show dashes until 04.2's budget plan adds one.

## Bug fixed (test that failed on the old code)
`ndcg_at_context_k([1, 1], 1)` returned 2.0: two gold units matched by the same chunk each earned a credit at position 1. That broke the `le=1` bound on `ItemResult.ndcg_at_context_k`, and the fixture test `test_table_split_block_is_in_the_report...` failed. Relevance is now per position. The test is `test_one_chunk_matching_two_units_is_one_relevant_position_and_never_above_one`.

The sweep (04.2-05) uses the same function. The committed fixture sweep values do not change; see "Sweep report" below.
