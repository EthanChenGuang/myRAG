# Phase 4.2 Plan 09: single redefinition of the search functions Summary

**0856 redefines `hybrid_search_chunks` and `rag_exact_id_documents` exactly once for the phase, adding a version scope and an identifier filter with every earlier parameter intact. 0855 adds the version lookup. The backend layer carries the new fields and never hands them to an adapter that cannot honour them.**

## Performance

- **Duration:** about 2 h
- **Tasks:** 3 of 3
- **Files:** 6 created, 12 modified

## Accomplishments

- **Task 1 (gate and order):** the gate passed. The 04.2-01 and 04.2-03 SUMMARYs exist, the 0853 and 0854 columns exist, and there was no 0855 or 0856 file. 0802 (Phase 3.2, plan 03.2-13, SUMMARY present) is the newest definition of `hybrid_search_chunks` and lies in 0801–0839. No Phase 3.2 plan without a SUMMARY redefines it. Branch taken: continue and rebuild from the newest definition. The hand-off note is `handoffs/04.2-09-hybrid-order.md`: any later redefinition numbers above 0856 and rebases on it.
- **0856:** one transaction:
  - Drops every overload of both functions through a `pg_proc` loop.
  - Recreates `hybrid_search_chunks` from the 0802 body and `rag_exact_id_documents` from the 0425 body, each with `p_version_scope jsonb DEFAULT NULL` and `p_identifiers_norm text[] DEFAULT NULL` appended.
  - Validates the scope inside the function: an object with `mode` `current`, `all` or `range`, optional `from` and `to` as `YYYY-MM-DD`, `from <= to`, no other keys. Anything else raises 22023.
  - Binds the new values as `$21`–`$23` in all three `USING` lists, then applies REVOKE and GRANT on the full signatures and sends `NOTIFY pgrst`.
  - Leaves the tenant, status, profile, scope, date and invoice predicates byte-identical to 0802.
- **0855:** `rag_document_versions`. Like the 0601 function, it is INVOKER with an empty `search_path` and calls `rag_assert_tenant_key` first. Every predicate carries the tenant, at most 500 ids are accepted, and rows come back ordered by document id.
- **Backend layer:**
  - `pgvector.ts` spreads `p_version_scope` and `p_identifiers_norm` in only when set, so a request without them sends today's argument object.
  - Hits read the three trailing columns. A row without them maps to absent fields.
  - pgvector declares `{ versionScope: true, identifierFilter: true }`.
  - `backendForRequest` returns the selected backend unless the request carries a field that backend does not declare. In that case it returns pgvector with `backend_field_unsupported`, which plans 04.2-15 and 04.2-27 record as a degraded stage detail.
  - `exactIdLookup` passes both values through.

## Deviations

- **[Rule 3, blocking]** `rag_exact_id_documents` was SECURITY DEFINER and checked the key with `rag_doc_type_tenant_key_ok`, which `service_role` cannot execute. As INVOKER it now calls `rag_assert_tenant_key`. That function accepts the same keys per mode but raises 22023 `malformed tenant key` instead of P0001 `invalid_tenant_key`. No caller or test matched the old message.
- **[Rule 2]** Two helper functions (`rag_version_history_ok`, `rag_version_period_ok`) carry the superseded and period rules for the static-SQL exact-id body. `hybrid_search_chunks` uses the same rules inline in its dynamic SQL, with the `pg_attribute` probe the plan asks for. `tests/rag-db/version-scope.test.mts` covers both.
- **[Rule 3]** Three existing re-run tests now run 0314 before 0425 (see above). Without that, 0425's own precheck stops on the removed signature.
- Migration numbers 0855 and 0856 were free, so they were used as planned.
