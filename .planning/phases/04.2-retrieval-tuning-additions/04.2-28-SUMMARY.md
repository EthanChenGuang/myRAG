## Fixture-meta keys

Template (the file itself is never returned as a document):

```
<!-- fixture-meta {"doc_type": "general", "generate": {"count": 30, "name": "faq-copy-{n}.en.md", "substitutions": [["lantern", "lantern"], ["lantern", "beacon"], ["lantern", "signal"]], "template_id": "faq-en"}} -->
```

- `generate` must hold exactly the keys `count`, `name`, `substitutions`, `template_id`. Anything else, or a missing key, is `[Fixture Corpus] invalid generate block in <relpath>`.
- `count`: integer 1..100. `template_id`: non-empty string.
- `name`: must contain `{n}` and no `/` or `\`. `{n}` is the 1-based copy number, zero-padded to `max(2, digits(count))` (`01`..`30`; `001`..`100`). Filename and relpath are `<language>/<name>`. A generated relpath that equals another document's relpath is `[Fixture Corpus] duplicate corpus document <relpath>`.
- `substitutions`: list of `[from, to]` string pairs, `from` non-empty; may be empty. Copy i (0-based) replaces every occurrence of `substitutions[i % len]`'s `from` with `to` in the template body (literal replace, same in both languages).
- Each copy gets one extra final chunk with the text `<template_id>-<n>` (the deterministic per-copy unique paragraph).
- The template's other meta keys (`doc_type`, `created_at`, `image_url`) apply to every copy. `filename`, `lineage` or `version` next to `generate` is an invalid generate block.
- Documents are sorted by relpath after expansion; for a corpus without templates the order is unchanged.

Lineage (one file per version):

```
<!-- fixture-meta {"filename": "orbit-notes.en.md", "lineage": "orbit", "version": 1, "created_at": "2025-01-10T00:00:00.000Z"} -->
```

- `lineage` (non-empty string) and `version` (integer >= 1) come together, else `[Fixture Corpus] invalid lineage in <relpath>`. A repeated (lineage, version) is `[Fixture Corpus] duplicate lineage version <lineage> <version>`.

## Seeding rule (prechunked fixture mode, D-40)

- Every version of a lineage gets `lineage_id = fixtureLineageUuid(lineage)` (sha-256 derived, as the document ids are), `source = config_upload`, `source_key = fixture-lineage:<lineage>` and its `version`.
- The highest version is inserted current. Earlier versions are inserted with the document not current, and their chunks are written like any other (current, with the fixture embedding) so relex gives them lexical text.
- After relex, `supersedeFixtureLineages` leaves each earlier version as `rag_publish_document_version` (0806) leaves a superseded one: document `is_current = false`, `status = 'ready'`, `superseded_by` = the next version's id; chunks `is_current = false`, `embedding = NULL`; its `chunk_embeddings` and `embedding_backfill_gaps` rows deleted.
- Generated documents are seeded like every other document, current and ready, with `fixture_dup_template` in `documents.metadata`.
- `prechunkedWriter` without the latest-versions map (ingest mode's prechunked-only documents) throws on a lineage document instead of seeding it wrongly.
