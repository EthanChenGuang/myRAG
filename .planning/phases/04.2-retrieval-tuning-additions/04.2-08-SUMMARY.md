# Phase 4.2 Plan 08: TTFT, pre-generation time and cache state on the trace

**The trace collector records the route's receipt time, generation start, the first answer text delta and the cache state, and derives `ttft_ms` and `pre_generation_ms` once. Langfuse root metadata and the unsampled `[RAG Trace]` line carry the three values only when timing was recorded. `withFirstTextDelta` observes a UI message stream and calls back once. A test-only setter injects a pre-generation delay; no environment variable can.**

## Behaviour

- Clock 1000 → 1180 → 1420 gives `pre_generation_ms` 180 and `ttft_ms` 420; repeat marks are ignored.
- No text delta (error part only): `pre_generation_ms` only.
- Without timing: root metadata and the log payload keys are unchanged (asserted on the exact key list and on the absence of the three keys on every span).
- No query, answer or chunk text in the timing fields (asserted).
- `ttft.ts` has no `process.env` read (grep count 0, plus a test that sets plausible variable names and reads the source).

## Decisions for STATE

- The log line's timing keys are fixed (`ttft_ms`, `pre_generation_ms` as number or null, `cache`).
