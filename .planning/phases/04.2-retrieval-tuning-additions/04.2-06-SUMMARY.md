## effectiveTuningParams

- Defaults come from the generated schemas: table lookup `{ min_cells: 2, limit: 10, weight: 1 }`, diversity `{ mmr_lambda: 0.7, mmr_window_factor: 3 }`, duplicate threshold `0.95`.
- `mmr_lambda` from the committed `retrieval-params.json` (through `effectiveRetrievalParams`) applies to every profile when present. Today the file has none, so the value is 0.7.
- Eval-only overrides (`table_lookup`, `diversity`, `dup_cluster` incl. a per-profile fixture threshold) apply for profile `eval` and are ignored for chat, embed and voice. An invalid block is dropped with one `[RAG Config] Invalid eval tuning override, entry ignored { field }` warning.

## Startup

`runChecks` adds `version_scope_needs_lexical` (when `RAG_VERSION_SCOPE=true` but lexical search is effectively off) and
`identifier_filter_needs_index` (when `RAG_IDENTIFIER_FILTER=true` but the index is off). For each, it logs one `[RAG Config]` warn line with a fixed sentence and
`{ switches: [two names] }`. Neither combination is fatal. The verdict status becomes `degraded`, which nothing gates on (search reads only
`icuAvailable`). `loadRagConfig` keeps its own 04.2-02 warning, so an operator sees one config line and one startup line per combination.
