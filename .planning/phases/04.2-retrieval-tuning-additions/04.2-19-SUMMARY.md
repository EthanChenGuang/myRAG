## Upstream gate (Task 1)
The verify command passed on `base/04.2-19` (exit 0). The 4.1.1-05 and 4.1.1-06 SUMMARYs exist under their own ids, so no renumbering note was needed. The 4.2 SUMMARYs 02, 03, 04, 14 and 34 exist, and so does the transitive 04.1-12. No 0859 file existed. No `04.2-19-upstream.md` was written.

The 4.1.1 symbols this plan adapts to:
- Loader: `loadEffectiveDictionary(scope, { signal?, bypassCache?, client?, now? }): Promise<EffectiveDictionary>`. It returns `{ tenantKey, entries: TermEntry[], sharedVersion, workspaceVersion, version }`, and the version is `s<shared>` or `s<shared>.w<tenant>`. The cache is an LRU keyed by `scopeKey(scope)`, holding 256 entries for 60 s. `invalidateTerminologyCache(tenantKey | 'all')` clears it.
- Matcher: `buildMatcher(entries, { minHanChars }): TerminologyMatcher`, whose `match(text)` returns `RawTermMatch[]` items of `{ entry, surface, start, end }`. It matches the longest term first, left to right, without overlaps. It skips `translation` entries (4.1.1 D-32).
- `TermEntry` fields: `kind` (`synonym | abbreviation | alias | identifier | translation | misspelling`), `language`, `canonical`, `variants`, `normalizedVariants`, `mode`, `sourceLanguage` and `targetLanguage`. There is no `enabled` field, because `rag_term_effective` returns only enabled entries that are not suppressed.

## Resolver (Task 2)
`resolveLexicalOptions(scope, config, { language, signal })` returns `{ options, stamp: { dictVersion, patterns }, warnings }`.
- **All three switches off:** it returns `{ options: undefined, stamp: { dictVersion: null, patterns: null }, warnings: [] }` and makes no database call.
- **Dictionary:** it reuses the 4.1.1 `buildMatcher` and does not add a second matcher. Each entry is rewritten into its lexical view before the matcher is built:
  - `misspelling` and `identifier` entries are dropped.
  - `translation` entries are kept and passed to the matcher as `synonym`.
  - The canonical and the variants are normalized and kept only if they qualify. A form qualifies if it has at least 2 Han characters, or if it is Latin with whitespace or an apostrophe.
  - Matching is `one_way` with `minHanChars: 2`.
  - The term emitted is the normalized canonical when the canonical qualifies, so a variant and its canonical share one `_t_` token. Otherwise the matched surface is emitted.
  - The matcher is cached per `EffectiveDictionary` object in a WeakMap, so it lives exactly as long as the loader's cache entry.
- **Stemming:** it sets `stemIt: true` and the given language.
- **Identifier index:** it passes the tenant's compiled patterns. The list may be empty.
- **Fingerprint rule:** the fingerprint is `p` plus the first 12 hex characters of SHA-256 over the sorted lines `id|source|flags`, joined with `\n`. One line is written per enabled pattern that validates, and the flags are written as stored (`u` or `iu`). The empty list therefore always hashes to the same value. Changing, adding, disabling or deleting a pattern changes the fingerprint.
- **Failures:** a dictionary failure gives no dictionary, `dictVersion: null` and the warning `lexical_dictionary_unavailable`. A pattern failure (`loadFailed`) gives no patterns, `patterns: null` and the warning `identifier_patterns_unavailable`. Neither throws, unless the caller's signal was aborted.
- Logs contain only the warning code.

## Ingest call sites (Task 3)
- `ingestLexical(ctx)` resolves once per document and keeps the result on `ctx.work.lexical`. With every switch off it returns the frozen OFF value (`LEXICAL_VERSION`, no options) without touching the scope. Warnings are added to `ctx.warnings` once.
- `enrich` calls it right after language detection, which already ran before the loop (D-55). It passes the options as the last argument of `chunkLexicalText` and stamps `lexical_version: effectiveLexicalVersion(config)`, plus `lexical_dict_version` and `lexical_patterns` when they are present.
- Profile children get the same options and stamps through `ProfileDocument.lexical`. `embed-write` passes `await ingestLexical(ctx)`.
- Image captions (both paths) and the invoice prefix text use `lexicalFieldsFor`. With the switches off it returns today's text and no keys, because image chunks carry no `lexical_version` today.

## Migration 0859 and relex (Task 4)
| Function | Notes |
| --- | --- |
| `rag_relex_candidates_stamped(p_after uuid, p_version integer, p_limit integer, p_tenant_key text, p_dict_version text, p_patterns text, p_stale_dictionary boolean)` | Returns the 0425 candidate columns plus `lexical_dict_version` and `lexical_patterns`. **Version mode:** `lexical_version` differs, or a non-null given stamp differs from the stored one. **Stale-dictionary mode:** only the stored dictionary stamp is compared. Stamps or stale mode without a tenant, and stale mode without a version, are refused with 22023. |
| `rag_relex_batch_stamped(p_rows jsonb, p_version integer, p_tenant_key text)` | The tenant is required and appears in the UPDATE predicate. Each row may carry `lexical_dict_version` and `lexical_patterns`; a value is written when given and the key is removed when it is null. A malformed stamp is refused with 22023. |
| `rag_lexical_stale_count(p_tenant_key text, p_dict_version text)` | Returns a `bigint` count of the tenant's current, ready chunks whose `lexical_dict_version` is distinct from the given version. |

- **Batch writer used:** a new `rag_relex_batch_stamped`. The newest `rag_relex_batch` (0425) only `jsonb_set`s the `lexical_version` key, so it cannot carry the stamps.
- All three functions are `SECURITY INVOKER` with `SET search_path = ''` and schema-qualified names. They are revoked from PUBLIC, anon and authenticated, and granted to service_role.
- `rag_assert_tenant_key` runs first whenever a tenant key is given.
- The 0425 functions were not redefined. No 0410 entry was added, because nothing is `SECURITY DEFINER`. No purge hook was added, because the migration adds no store.
- Re-applying 0859 leaves the functions unchanged, which a test checks.
- **`runRelex` without `config`, or with every lexical switch off:** the old path runs unchanged (`LEXICAL_VERSION`, `rag_relex_candidates` and `rag_relex_batch`). This covers the fixture harness and the existing tests.
- **`runRelex` with a switch on:** the stamped path runs.
  - It targets `effectiveLexicalVersion(config)`.
  - It resolves options and stamps once per tenant key with the operator scope (`backfillScope`, injectable as `resolveScope`), using `language: null`. Stemming then uses each chunk's language, or a detected one when the chunk has none.
  - It writes per tenant group, through the stamped table pass as well.
  - Its progress lines show `dict=<version|none>` and counts only.
- **USAGE line:** `usage: npm run rag:relex -- [--dry-run] [--batch-size 500] [--tenant <key>] [--stale-dictionary] [--resume-after <chunkId>]`
- `--stale-dictionary` without `--tenant` is a usage error (exit 2). With `RAG_LEXICAL_DICTIONARY` off it ends with `lexical_dictionary_off` (exit 2). If the dictionary fails to load, it writes nothing, reports the warning and exits 0.

## Behaviour changes
- **Switches off (the default):** nothing changes.
  - Enrich and profile drafts are byte-identical to the drafts built before this change, version 2, without stamp keys (tested for en, it and zh).
  - Image and extractor chunks are unchanged.
  - Plain relex runs the same RPCs as before.
  - `defaults-equal-phase3` and the existing relex tests pass unchanged.
- **`RAG_LEXICAL_DICTIONARY=true`:**
  - Chunks gain `_t_` tokens for the tenant's qualifying terms and are stamped with version 3 and `lexical_dict_version`.
  - `rag:relex -- --tenant <key> --stale-dictionary` brings stored text up to the current dictionary version.
- **`RAG_LEXICAL_STEM_IT=true`:** chunks are stamped with version 4, and Italian chunks gain `_s_` tokens.
- **`RAG_IDENTIFIER_INDEX=true`:**
  - Tenant pattern matches stay whole and also emit their normalized form.
  - Chunks get the `lexical_patterns` fingerprint.
  - Plain `rag:relex -- --tenant <key>` rewrites chunks whose fingerprint differs, so the command the Identifier patterns panel prints does what it says.

2. **Image and extractor paths** are tested through `lexicalFieldsFor`, which both call, rather than by driving the captioner and sidecar stages.
3. **`relex/run.ts` imports `config` and the resolver lazily.** The fixture harness imports `run.ts` before the app environment is set, and `env.ts` validates at import time. A static import broke every PGlite test.
4. **Stale-dictionary mode writes nothing when the dictionary fails to load.** There is no version to compare against, and rewriting without tokens would strip the stamps. Version mode still writes without tokens and without a stamp, as the must-have says.
5. **`parseRelexArgs` returns `staleDictionary: true` only when the flag is given,** so the existing shape test passes unchanged.

## Finding for the coordinator
A tenant identifier pattern stored with flags `u` (case-sensitive) that contains uppercase letters never matches lexical text. The tokenizer lowercases the text before `splitAtIdentifiers` (04.2-34 and 04.2-14 behaviour), so `QV [0-9]{3}` with `u` matches nothing. The relex test uses `iu`. Plan 04.2-17 or the validator should either add `i` to every pattern applied to normalized text or warn in the panel.

## Decisions for STATE

- The patterns fingerprint is `p` plus 12 hex characters of SHA-256 over the sorted `id|source|flags` lines.
- Relex resolves options per tenant key and stems by chunk language. Ingest stems by document language.
- Migration 0859 was taken as planned.
