# Phase 4.2 Plan Index

33 plans in 11 waves. Plans in the same wave share no file in `files_modified`; every file touched by two or more plans is ordered by a `depends_on` path (list below). The phase starts after Phase 4.1's closing plan **04.1-12**: plans 04.2-01 to 04.2-04 gate on it by SUMMARY and symbol (`RAG_REFUSAL_FLOOR`), and every other plan depends on them transitively. The LANG-07 wiring plans 04.2-19 and 04.2-22 also gate on **04.1.1-05** and **04.1.1-06** (`rag_term_effective`, `src/lib/rag/terminology/load.ts`, `matcher.ts`, `invalidateTerminologyCache`); the closing plan 04.2-32 gates on **04.1.1-14** (folded setup files, `eval/reports/phase-04.1.1/comparison.json`). Phase 3.2 has no plan ids on trunk, so its deliverables are symbol gates with the D-02 fallbacks (registry, settings classification, `RAG_TABLE_HEADER_REPEAT`, `effective_from`); the one hard precondition on Phase 3.2 is the `hybrid_search_chunks` redefinition order in 04.2-09 (D-43, D-38 g). Every plan opens with a read-only gate task that stops with a hand-off note under `handoffs/` when an upstream SUMMARY or symbol is missing.

Only plan 04.2-01 changes Pydantic contracts and generated Zod. Only plan 04.2-33 makes live vendor calls (proxy placeholder `proxy-injected`, capped) and only it may write shipped values of `eval/config/retrieval-params.json`. Fixture-fitted values (duplicate threshold, MMR lambda, per-mode refusal cells) apply in eval only and are written by their tools.
