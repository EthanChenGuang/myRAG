# Phase 4.2 Plan 18: Write-time table rows and identifiers Summary

**With `RAG_TABLE_LOOKUP=true` or `RAG_IDENTIFIER_INDEX=true`, the write stage now stores typed table rows and normalized identifiers for every chunking profile written at ingestion. It does this through one tenant-bound routine that the 04.2-35 backfills will reuse. With both switches off, nothing new is called.**

## Records for plan 04.2-35 (and 04.2-24, 04.2-27)

### Function signatures (0860)

All four are `SECURITY INVOKER`, `SET search_path = ''`, and call `rag_assert_tenant_key` first. They are revoked from PUBLIC, anon and authenticated and granted to service_role.

| Function | Returns | Notes |
| --- | --- | --- |
| `rag_index_document_chunks(p_tenant_key text, p_document_id uuid, p_after uuid, p_limit integer)` | `(id, chunking_profile_id, chunk_index, section_path text[], content)` | Keyset by chunk id. Every profile and every status of that document in that tenant. `p_limit` 1..1000. |
| `rag_write_chunk_identifiers(p_tenant_key text, p_document_id uuid, p_rows jsonb)` | `(chunks_written integer, document_changed boolean)` | Rows are `[{chunk_id, raw[], norm[]}]`. Every chunk id must be a chunk of that document and tenant, else 42501 `tenant_mismatch` and nothing is written. Only changed chunks are updated. The document union is rewritten only when it differs. |
| `rag_write_table_rows(p_tenant_key text, p_document_id uuid, p_chunking_profile_id text, p_rows jsonb)` | `(rows_written integer, rows_deleted integer)` | Deletes, then inserts, the rows of that document and profile. Version, is_current and status are copied from the document. Every chunk id must belong to that document, tenant and profile (42501 otherwise). A document of another tenant gives 42501. |
| `rag_index_backfill_documents(p_tenant_key text, p_kind text, p_after uuid, p_limit integer)` | `(document_id, version, is_current)` | Keyset over the tenant's documents with `status = 'ready'`, `NOT provisional` and `is_current OR superseded_by IS NOT NULL`. For `p_kind = 'identifiers'`, only documents that have a chunk with `identifiers_norm IS NULL`. `p_kind` is `tables` or `identifiers`. |

### Row shape sent to `rag_write_table_rows`

```
{ table_key, row_index, header: text[], cells: {name: text}, cell_tokens: text[][], cell_norm: text[], chunk_ids: uuid[] }
```

- `cells` is a JSON object keyed by header name, as the 0852 column requires.
- The 04.2-01 `TableRowSchema` contract has `cells` as an array, so it does not describe the stored row. 04.2-24 should read `cells` as an object.

### table_key format

`<document id>:t<ordinal>`, for example `0d000000-…:t0`.

- The ordinal starts at 0 for each document version and chunking profile and counts tables in chunk order.
- A continuation piece keeps the table_key of the table it continues, and its rows continue the `row_index` count.

### Cache effect of writing document identifiers

From the 04.2-03 SUMMARY: the newest `rag_semantic_cache_on_documents_update` (0603) compares only `is_current`, `status`, `version` and `tenant_key`.

- Writing `documents.identifiers_norm` or `identifiers_raw` therefore deletes no cache entry, in ingestion or in the identifier backfill.
- The union is also written only when it changed (`document_changed`).
- 04.2-35 can print "semantic cache: unaffected" in the identifier CLI output.

### Warning codes and logging

- The warning codes are `index_tables_failed`, `index_identifiers_failed` and `identifier_patterns_unavailable`. They are added to `IngestResult.warnings` and to `IndexDocumentReport.warnings`.
- Each failed part logs one line: `[Ingest] lookup indexing failed; the document is published without it`, with `{ code, documentId, error: <class name>, rpc?, sqlState? }`.
- No cell value, header, identifier or pattern is logged.
- A pattern load failure indexes with the built-in rule only. The loader logs its own `[Identifier Patterns]` line.

### Backfill reuse (04.2-35)

- Mint the tenant's scope and build `createIngestWriter({ db, scope, signal })`.
- Page through `rag_index_backfill_documents(kind)`, then call `indexDocumentForLookup({ writer, scope, documentId, tables, identifiers, signal })` for each document.
- The routine re-reads every profile's chunks, so it also covers rechunked profiles.
- A listing method on the writer was not added. The CLI can call the RPC through the same RPC client.

## Deviations

1. **Writer methods are optional members** (`listDocumentChunksForIndex?`, `writeChunkIdentifiers?`, `writeTableRows?`), following `releasedLinkTargets?` and `setImageChunkLanguages?`. The many test fakes of `IngestWriter` stay valid. A writer without them produces the warning code instead of an error.
2. **Every profile is rewritten, even with zero rows** (see key decisions). Plan 04.2-35's re-index needs this to be correct, and it costs one call per profile only while the switch is on.
3. **Two tests rename a function to inject a failure.** The failure tests rename `rag_write_table_rows`, `rag_write_chunk_identifiers` and `rag_identifier_patterns_list` with `ALTER FUNCTION … RENAME` and restore them in `finally`. This exercises the real RPC error path.
4. **A direct single-tenant run of `indexDocumentForLookup` replaces single-tenant app ingestion.** The plan asks for two tenants in both modes. Single-tenant mode has one tenant, so it is covered three ways:
   - SQL-level tests run in both modes, with a foreign-tenant chunk planted through `session_replication_role = replica`, as in 04.2-14.
   - The direct single-tenant run goes through the tenant-bound writer.
   - The app ingestion lifecycle runs on the multi-tenant two-tenant fixture. The app reads its deployment mode at import, so one process cannot run both modes.
5. **The RED commit for Task 2 contains stubs.** They export the planned names and return empty results, so the tests fail on expectations rather than on module-not-found. A few of those failures are `TypeError`s on the empty map.

## Decisions for STATE

- Write-time lookup indexes (table rows and identifiers) are written by `indexDocumentForLookup` in `runWrite`. It reads the version's chunks of every profile back by document id. It is non-fatal, with the warning codes `index_tables_failed`, `index_identifiers_failed` and `identifier_patterns_unavailable`.
- The `table_key` format is `<document id>:t<ordinal>`, the ordinal counted per version and chunking profile.
- The document identifier union is computed in SQL and written only when it changed. It never invalidates the semantic cache.
