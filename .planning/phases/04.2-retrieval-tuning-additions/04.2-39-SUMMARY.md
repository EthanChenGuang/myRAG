# Phase 4.2 Plan 39: Embed version-scope switch (D-58)

**`RAG_EMBED_VERSION_SCOPE` (default `false`) exists in every configuration location and resolves in `loadRagConfig` to `v2.embedVersionScope`, which can only be true together with the effective `v2.versionScope`. Nothing changes while it is off; plan 04.2-21 Task 4 applies it in the embed route.**

## Task 1: upstream gate

Passed: `04.2-02-SUMMARY.md` (and transitive `04.1-12-SUMMARY.md`) present, `versionScope` in `src/lib/rag/config.ts`, `RAG_VERSION_SCOPE` in `scripts/init-env.js`, `id="rag-tuning-switches"` in the Config UI. No hand-off written.

## Task 2: parsing (behaviour)

- Unset or `false`: `embedVersionScope=false`, no warning; every other `v2` field is unchanged (tested against the same env without the variable, and the 04.2-02 snapshot test via `PHASE42_V2_FIELDS`).
- `true` with `RAG_VERSION_SCOPE=true` and `RAG_LEXICAL_SEARCH=true`: true.
- `true` with the version scope off or invalid: one `[RAG Config]` warning (`RAG_EMBED_VERSION_SCOPE needs an effective RAG_VERSION_SCOPE=true; embedded chat scopes to current versions only`), false.
- Other values: one warning, false. `memoKey` and `readRagEnvInput` (process.env first) carry the variable.
