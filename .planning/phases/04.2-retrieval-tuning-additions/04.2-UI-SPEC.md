## 0. Findings that shape this contract (read first)

Facts from the code and from CONTEXT.md. Each one changes what the UI can show or do.

1. **None of this phase's backend exists yet.** There is no `/api/rag/admin/identifier-patterns` route, no `rag:identifiers`,
   `rag:table-rows` or `rag:dup-clusters` script in `package.json`, and `rag:relex` has no `--stale-dictionary` flag
   (`USAGE` in `relex/cli.ts`). Section 8.1 lists what each view needs. Field and code names there are **proposals to the backend
   plans**; the behaviour they support is the contract. The UI plans check the real names at execution (D-01 symbol rule) and map
   them in one place per file.
2. **Phases 4.1, 4.1.1 and 3.2 are not on trunk.** The Retrieval pipeline card has no `RAG_REFUSAL_FLOOR`, no `auto` reranker
   option and no terminology switches; `rag-panels/` has no `rag-ui.js` and no `terminology.js`; `index.html` has no
   `data-rag-i18n` attribute. Every anchor in this file is therefore an element id or a symbol, never a line number, and section
   6.1 says what to do when a 3.2 or 4.1.1 symbol is present and when it is absent (D-02 pattern).
3. **The eight switches and the panel live on different tabs for a reason.** The Retrieval pipeline card is on the RAG Modes
   tab, which edits `.env.local` through the config server and works with no admin session. The pattern routes are
   owner-or-admin routes of the app (D-29). An admin-session panel inside that card would put a sign-in alert in the middle of
   env switches. Same resolution as `04-UI-SPEC.md` decision 3: the panel is a section of RAG administration and a pointer sits
   next to the switch it belongs to.
4. **Booleans in the Phase 4 switch box are checkboxes whose id equals the env name.** The page loader sets
   `field.checked = value === 'true'` and the change handler saves `checked.toString()`, so a checkbox with
   `id="RAG_IDENTIFIER_INDEX"` loads and saves `true` / `false` with no new JavaScript. Enumerations are `select` elements with
   `translate="no"` whose option text equals the env value. `tests/ui/config-phase4-switches.test.ts` asserts `name` equal to
   `id`, the checkbox inside its `label`, and help text wired with `aria-describedby`.
5. **The loader sets values without firing `change`.** A script that reads the switches must re-read them when the RAG Modes tab
   is opened, not only on `change`.
6. **The page has one workspace concept: `#workspace-selector`, on the Document Processing tab.** It is hidden in single-tenant
   mode. In multi-tenant mode its empty value means the admin's default workspace and every other value is an organization id.
   The Document types and Ingestion panels follow it and send `organizationId`; `resolveAdminWorkspaceScope` answers 403
   `Forbidden` when the admin is not a member and mints the single-tenant scope when the mode is single-tenant.
7. **A 403 has two meanings.** `Admin access required` (with 401) means "sign in"; `Forbidden` means "not a member of this
   workspace". `ragFetch` replaces the message of both with the English sign-in sentence but keeps `body`, so the panel reads
   `body.error` itself (as `mapIngestionError` does).
8. **`ragFetch` does not catch network failures** and its 401, 403 and 503 sentences are English only. The panel wraps every
   call and takes the sign-in, network and generic sentences from the shared `ingestLabel` table.
9. **The built-in rule already finds most identifiers.** `IDENTIFIER_PATTERN` matches any run of letters, digits and `- _ . /`
   that contains at least one digit. Admin patterns are for what it misses: identifiers with no digit, and identifiers written
   with spaces or other separators. The panel says so, or admins will re-create the built-in rule twenty times.
10. **A pattern change makes stored data stale in two places.** D-28 stores identifiers found at ingestion; D-30 makes the
    lexical tokenizer keep tenant-pattern matches whole. After a pattern is added, changed, enabled, disabled or deleted, stored
    documents keep the old result until the identifier backfill and the relex run. No route reports how many documents are
    stale, so the panel states the fact and names the commands.
11. **The pattern is attacker-shaped input for the server, and text for the browser.** D-29 puts every safety check (nested
    unbounded quantifiers, the 10 KB probe under 50 ms) on the server. The browser compiles a draft to give syntax feedback but
    never runs it against the sample: a slow pattern would freeze the tab, and a second matcher with its own normalization would
    disagree with ingestion.
12. **All Config UI scripts are classic scripts in one global scope** (04-UI-SPEC finding 13). Every top-level name in the two
    new files starts with that file's prefix (section 6.1).
13. **DaisyUI `text-error` and `text-warning` do not reach 4.5:1 on `base-200` in the light theme.** New inline findings
    therefore colour the icon and keep the sentence in `base-content`; coloured text appears only inside DaisyUI alerts, which
    carry their own content colour.
14. **The comment above `IDENTIFIER_PATTERN` names example uses of identifiers.** It is a code comment, not copy. No string in
    this contract repeats it; examples here are shapes only (domain-neutrality rule).

## 1. Design direction (frontend-design pass)

**Subject.** How a knowledge base recognises the codes its documents are full of, and how it treats two spellings of one code as
the same thing.
**Audience.** A deployment or organization admin at a desktop, who arrives with one concrete problem: "a question that names a
code gets the wrong passage, or none". They hold a piece of text from a real document. They may never have written a regular
expression.
**Primary job.** Show what is found in that text today, let the admin add a format that is missed, prove it works on the same
text, and say what has to be rebuilt afterwards. For the switches: say in one line what each does and which ones need stored
documents rebuilt, with the command.

**Mode.** Impeccable "Operate". Both surfaces are working tools inside an existing dashboard. Cards, tables, badges, alerts,
the inline form region and the confirmation dialog are the ones the sibling panels use. The visual direction is pinned by that
surface: DaisyUI `dark` and `light` themes, the system font stack, no new colour, no new typeface.

**Design plan.**

| Axis | Choice |
|------|--------|
| Colour | Theme tokens only (section 13): `base-100` regions on `base-200` cards, `base-content` text, `primary` for two buttons, `error` for one confirm button |
| Type | Inherited sans for everything a person reads; monospace only for what a machine reads (patterns, spellings, stored forms, commands, env names) |
| Layout | One column, left-aligned: the list of patterns, then the workbench (form and test side by side in reading order, never in separate tabs) |
| Principle | The sample text is the evidence. Every claim the panel makes about a pattern can be checked on the admin's own text before anything is saved |

**Signature element: the stored-form ledger** (section 6.7). After a test, the result is not a list of matches. It is one row
per **stored form**, with every **spelling** found in the sample that collapses into it, and above it the sample itself with the
found identifiers marked. Three spellings on one row is the whole point of RET-15 shown in the admin's own text; text left
unmarked is the miss they came to fix. Nothing else in the panel is decorative.

**Review against generic defaults (what was changed and why).**
- Rejected a card per pattern. Up to twenty patterns are comparable rows: a table.
- Rejected a modal editor. A dialog would cover the test, and the draft has to be tried on the sample while it is edited.
- Rejected sub-tabs "Patterns" and "Test" (the sibling panels' device). They would put a draft and its test on different screens.
- Rejected the usual form position under the toolbar. Here the form opens between the list and the test, so the draft sits
  directly above the Run test button.
- Rejected a visual pattern builder. It would be a second pattern language to keep in step with the server; three worded
  examples of shapes do the teaching.
- Rejected matching in the browser while typing (finding 11).
- Rejected a green tick for a "valid" pattern. Validity is the absence of findings; a tick would promise more than six checks prove.
- Rejected a toggle that turns green per row. Status is a word with an icon, and the button names what it will do.
- Rejected one highlight colour per pattern in the marked sample. Colour would be the only carrier; the "Found by" column says it in words.
- Rejected a stat tile for the count. "Patterns: 3 of 20" is a line in the toolbar.
- Rejected emoji, middle-dot meta strings, arrows between spelling and stored form, and all-caps labels.
- For the switches: rejected a two-column checkbox grid (the Phase 4 box) because each new switch needs a help line; rejected
  group headings above each pair, because adjacency and a divider already say which switches belong together.

**Quality floor (built without announcing it).** Visible keyboard focus, `prefers-reduced-motion` respected, all text at least
4.5:1 in both themes (finding 13), tabular numerals in counts, usable down to 360px, every state in section 7 present, every
server and admin string inserted with `textContent`.

Rules:
- Counts use `tabular-nums`.
- Description, help and alert paragraphs cap at `max-w-prose` (line length under 80 characters).
- Patterns, spellings and stored forms use `font-mono text-sm` with `break-all` and `translate="no"`; in the pattern list the

  monospace.
- `h3` and `h4` carry `text-balance`.
- No all-caps labels, no letter-spaced eyebrows, no label above a heading, no single emphasised word inside a heading.
- The panel root carries `lang="<locale>"` (`en`, `zh` or `it`). Text left in English inside a localized panel (an unknown server
  code's message, the browser's own syntax message) is wrapped in an element with `lang="en"`. The sample, the spellings and the
  patterns are the admin's content and carry no `lang`.

### 6.5 Pattern form (add and edit)

One form, opened by "Add pattern" (empty, title `form.title.add`) or by a row's "Edit pattern" (filled, title
`form.title.edit`). It opens **between the list and the test region** (section 1), scrolls into view (`behavior: 'auto'` under
reduced motion) and moves focus to the Name field. Only one form exists.

Fields, stacked (`flex flex-col gap-4`); every field has a visible `<label for>`:

| Field | Control | Rules |
|-------|---------|-------|
| Name | `input type="text"`, `name="identifier-pattern-name"`, `autocomplete="off"`, placeholder `form.namePlaceholder` | Required; at most `max_name_length` characters (80). Help: `form.nameHelp`. Not used for matching |
| Pattern | `textarea rows="2"`, `name="identifier-pattern"`, `font-mono text-sm`, `autocomplete="off"`, `autocapitalize="off"`, `autocorrect="off"`, `spellcheck="false"`, `translate="no"`, `resize-y`, placeholder `form.patternPlaceholder` | Required; at most `max_pattern_length` characters (200); one line. Help: `form.patternHelp`. A live 12px `tabular-nums` count, `form.count`, sits at the right of the label row. **No `maxlength` attribute:** a paste that is too long must stay whole and be reported, because a silently cut pattern is a different pattern. Enter does not insert a line break |
| Ignore letter case | `checkbox checkbox-sm` in a `label` | Checked by default (the built-in rule ignores case). Help: `form.ignoreCaseHelp`. Sent as flags `iu` when checked and `u` when not; the form has no flags text field |
| Pattern examples | `details > summary` (`form.examples.summary`) | Closed by default. A `dl` of three rows: the shape in words (`dt`, 14px) and the pattern (`dd`, `code`, selectable). No "use this" button |

The three examples (shapes only; the words never say what an identifier is for):

| Shape in words (`example.1` to `example.3`) | Pattern |
|---------------------------------------------|---------|
| Two letters, an optional space or hyphen, four digits | `[A-Z]{2}[ -]?\d{4}` |
| Two groups of four letters joined by a hyphen | `[A-Z]{4}-[A-Z]{4}` |
| Three groups of three digits separated by spaces | `\d{3} \d{3} \d{3}` |

**Validation, in two layers.**
1. **Local, on every `input` event, no debounce.** Name present and within its length; pattern present; no line break; length
   within the limit; `new RegExp(pattern, flags)` compiles with `u` (compiling does not run the pattern); the compiled pattern
   does not match the empty string (`.test('')`, which costs nothing whatever the pattern). The browser checks nothing else.
2. **Server, on Save pattern and on Run test.** The server is the only judge of the nested-quantifier rule, the 10 KB probe and
   the "at least one letter or digit" rule (finding 11). Its findings replace the local ones for the same draft.

**Findings area** (`div[aria-live=polite]` above the buttons). Each finding is a 14px line: `bi-exclamation-circle` in
`text-error` (`aria-hidden`) and the sentence in `base-content` (finding 13). Each finding's element id is listed in
`aria-describedby` of its field, and the field gets `aria-invalid="true"` and `input-error` or `textarea-error`. A finding that
concerns no single field (`limit_reached`) shows in the findings area only.

**Buttons** (`flex flex-wrap gap-2 mt-4`): `btn btn-primary btn-sm` "Save pattern"; `btn btn-ghost btn-sm` "Close form". Under
them the 12px muted line `form.testHint`. Save pattern stays enabled until a request starts. On click with a local finding on
screen: no request; focus moves to the first invalid field. Otherwise `POST` (add) or `PATCH` (edit); while it runs the button
shows a spinner with `form.saving`, the fields are `disabled` and Close form is disabled.

**After success:** the form closes, the list reloads, `note.rebuild` appears, the status region says `form.saved.add` or
`form.saved.edit`, the last test result is marked stale (6.7), and focus moves to that row's "Edit pattern" button.

**Server errors** keep the form open with its values (section 8.2). Focus moves to the first field with a finding.

**Closing.** "Close form" or Escape inside the region. An untouched form closes at once and focus returns to the button that
opened it. A changed form first opens the Discard dialog (6.6). The same dialog opens when the admin selects "Add pattern" or
another row's "Edit pattern" while the form holds unsaved changes. While the form holds unsaved changes the page has a
`beforeunload` handler; it is removed when the form closes.

**Workspace change while the form is open** (multi-tenant, finding 6). Edit mode: the pattern belongs to the other workspace, so
the form closes and the status region says `form.closedWorkspace`. Add mode: the values are kept and a line `form.workspaceChanged`
(with `bi-exclamation-triangle` in `text-warning`) appears in the findings area naming the workspace the pattern will now be
saved to; it does not block saving. In both cases the last test result is cleared and the sample text is kept.

### 6.6 Enable, disable, delete and discard

**Enable pattern / Disable pattern.** No confirmation: one click, fully reversible with the button that replaces it. `PATCH`
with `{ enabled }`. While it runs, the button shows a spinner with `toggle.enabling` or `toggle.disabling` and the row's other
buttons are disabled. On success the row updates in place (no list reload flash), `note.rebuild` appears, the status region says
`toggle.enabled` or `toggle.disabled`, the test result is marked stale, and focus stays on the same button, now with its new
label.

**Delete pattern** is the one destructive action. Confirmation in a native `<dialog class="modal">` built with DOM calls (the
Ingestion panel's `confirmDelete` pattern, never `utils/modal.js`):

| | Delete pattern | Discard changes |
|---|----------------|-----------------|
| Title (16/600) | `confirm.delete.title` with the name | `confirm.discard.title` |
| Body (14px) | `confirm.delete.body`: uploads are no longer checked with it; identifiers already stored stay until the rebuild; it cannot be restored; to pause it, disable it instead | `confirm.discard.body` |
| Cancel | `btn` "Keep pattern", default focus | `btn` "Keep editing", default focus |
| Confirm | `btn btn-error` "Delete pattern" | `btn btn-outline` "Discard changes" |

Escape and the backdrop cancel. After confirming a delete, both buttons are disabled and the confirm button shows a spinner with
`confirm.deleting`; the dialog closes when the answer arrives. On success: the list reloads, `note.rebuild` appears, the status
region says `delete.done`, the test result is marked stale, and focus moves to the first action of the row that took the deleted
row's place, or to "Add pattern" when the list is now empty. If the deleted pattern was open in the form, the form closes
without the Discard dialog. Errors: section 8.2.

### 6.7 Test patterns (the signature element)

Always visible, with or without patterns, with or without the form open.

**Inputs.**
- Sample text: `textarea rows="5"`, `name="identifier-pattern-sample"`, visible `<label for>` (`test.sample`),
  `autocomplete="off"`, `spellcheck="false"`, `resize-y`, 14px in the body font (it is prose), placeholder
  `test.samplePlaceholder`, help `test.help` wired with `aria-describedby`, and a 12px `tabular-nums` count `test.sampleCount`
  against `max_sample_length` (10,000). No `maxlength` attribute, for the same reason as the pattern field.
- `btn btn-primary btn-sm` "Run test"; `btn btn-ghost btn-sm` "Clear sample" (empties the textarea and removes the result;
  focus returns to the textarea).

**What a test uses.** The built-in rule and the saved, enabled patterns of the workspace. When the form is open and has no local
finding, the test also sends the pattern in the form as a draft; in edit mode the draft replaces the saved version of that
pattern. When the form is open with a local finding, the draft is left out and the scope line says so. The scope line always
states what was tested (`test.scope.saved`, `test.scope.draft`, `test.scope.draftEdit`, `test.scope.draftSkipped`); the enabled
count comes from the answer's `tested.pattern_ids` when present, otherwise from the list.

**Run.** With an empty sample: no request, `test.sampleRequired` under the field, focus on the field. With a sample over the
limit: no request, `test.sampleTooLong`. Otherwise `POST …/test`; the button shows a spinner with `test.running` and is
disabled until the answer; the previous result stays visible, dimmed (`opacity-60`, `aria-busy="true"`).

**Result** (`div[role=region][aria-labelledby]`, replaced as a whole on each answer):

1. **Scope line** (12px muted).
2. **Summary** (14px, `tabular-nums`): `test.summary`. The status region announces the same sentence.
3. **Marked sample.** `figure` with a 12px `figcaption` (`test.marked.caption`) and
   `pre.font-mono.text-xs.whitespace-pre-wrap.break-words.max-h-40.overflow-auto.border.border-base-300.rounded-lg.p-2[tabindex=0][role=region][aria-label]`.
   The sample is rebuilt from text nodes and `mark` elements using each match's `start` and `end`; overlapping ranges are merged
   into one mark. `mark` is `bg-base-300 text-base-content font-semibold underline decoration-2 underline-offset-2 rounded-sm`:
   weight and underline carry the mark, so it does not depend on colour. When a match has no usable offsets (missing, out of
   range, or `start >= end`), the whole figure is left out and the 12px line `test.marked.unavailable` shows instead; the ledger
   below is unaffected.
4. **The ledger.** `table.table.table-sm` in `div.overflow-x-auto`, `caption.sr-only` = `test.table.caption`. One row per stored
   form, in the order of first appearance in the sample.

   | Column | Content |
   |--------|---------|
   | Stored form | `th scope="row"`, `code.font-mono.text-sm.break-all[translate=no]` |
   | Spellings found | Each distinct spelling as its own `code.font-mono.text-sm.break-all[translate=no]`, in a `div.flex.flex-wrap.gap-2`, in order of first appearance. Characters of Unicode categories Cc and Cf (zero-width and direction marks) are written as visible text `[U+XXXX]`, so two spellings that look alike can be told apart |
   | Found by | The sources of that row, joined with `Intl.ListFormat(locale, { type: 'conjunction' })`: `source.builtin`, a saved pattern's name, `source.draft`, or `source.unknown` when the answer names a pattern that is no longer in the list |

5. **Legend** (12px muted, `max-w-prose`): `test.legend`.
6. `test.truncated` (12px) when the answer says the result was cut.

**No identifiers found.** The result region shows the scope line and a centred block (`py-8`): 16/600 `test.none.title`, 14px
`test.none.body`. No figure, no table.

**Draft refused by the server.** The answer is a 400 with a pattern finding: the test did not run. The finding is rendered in
the form's findings area exactly as on Save, the result region shows `test.draftRefused` with `bi-exclamation-circle`, and focus
moves to the Pattern field.

**Stale result.** After any change to the patterns (save, enable, disable, delete), to the form's pattern or to the sample
text, a result on screen gets `opacity-60` and the 12px line `test.stale` above it. It is removed only by the next test, by
Clear sample or by a workspace change.

**Privacy.** The sample and the result live in memory only. Nothing is written to browser storage and nothing about them is
logged to the console (D-34 keeps identifiers out of logs; the browser follows the same rule).

## 8. Data and errors

### 8.1 What each view needs from the server (proposals to the backend plans, finding 1)

All routes are owner-or-admin (D-29), answer `Cache-Control: no-store`, take the workspace as `organizationId` (query string on
`GET` and `DELETE`, body otherwise) and resolve the tenant server-side with `resolveAdminWorkspaceScope`. Errors use the existing
shape `{ success: false, error, details?: [{ path, message }] }`.

| Call | When | Request | Answer the UI reads |
|------|------|---------|---------------------|
| `GET /api/rag/admin/identifier-patterns` | Mount, Refresh patterns, after add, save or delete, after any 404, on workspace change | `?organizationId=` | `items[] { id, name, pattern, flags, enabled, updated_at }` in creation order; optional `limits { max_patterns, max_pattern_length, max_name_length, max_sample_length }` (defaults 20, 200, 80, 10000 when absent) |
| `POST /api/rag/admin/identifier-patterns` | Save pattern (add) | `{ organizationId, name, pattern, flags, enabled: true }` | 201 `item` |
| `PATCH /api/rag/admin/identifier-patterns/{id}` | Save pattern (edit); Enable or Disable pattern | `{ organizationId, name?, pattern?, flags?, enabled? }` | 200 `item` |
| `DELETE /api/rag/admin/identifier-patterns/{id}` | Confirmed delete | `?organizationId=` | 200 |
| `POST /api/rag/admin/identifier-patterns/test` | Run test | `{ organizationId, sample, draft?: { id?, pattern, flags } }` | `matches[] { raw, normalized, source, start, end }` where `source` is `built_in`, `draft` or a pattern id, and `start` / `end` are UTF-16 offsets into the sample as sent; optional `tested { pattern_ids[] }`, `truncated`, `total` |

Asks of the backend plans that the contract depends on:
- **Offsets** (`start`, `end`) on test matches, into the sample as the browser sent it. Without them the marked sample cannot be
  drawn and only the ledger shows.
- **The test endpoint applies every D-29 check to a draft before running it** and answers the same 400 findings as Save.
- **The sample is neither stored nor logged**, and the answer never contains an identifier that is not in the sample. The help
  text promises this.
- **Finding codes** for the six D-29 rules, one code per rule, in `details[].message` with `path` `pattern` or `name`.
- **A cap on the sample length and on the number of matches returned**, reported through `limits` and `truncated`.

## 9. Keyboard, screen reader and focus

1. **Headings.** Panel title `h3`; the form title and "Test patterns" are `h4`. The switch box heading is `h4` under the card's
   `h3`. No level is skipped.
2. **Switches.** Each checkbox sits inside its `label` (one hit target, no dead zone) and has `name` equal to `id`. Help,
   stored-document line and pointer are siblings of the label, not inside it, so a click on a command selects text and does not
   toggle the switch. `aria-describedby` lists the help id and the stored id. The select has a `<label for>`.
3. **Combination notes.** `role="status"`; they are announced when they appear and say what to do. They are never the only
   place a dependency is stated.
4. **Form.** Every control has a visible `<label for>`. Help lines, counts and findings are wired with `aria-describedby`;
   invalid fields carry `aria-invalid="true"`. Enter in Name does not submit; Enter in Pattern does not insert a line break;
   the admin activates Save pattern explicitly. Escape closes the form (through the Discard dialog when it has changes). Paste is
   never blocked or cut.
5. **Save pattern** is never `disabled` before a request starts; with a local finding it moves focus to the first invalid
   field, whose finding is already on screen and referenced.
6. **"Add pattern" at the limit** uses `aria-disabled="true"` and stays in the tab order, with the reason referenced by
   `aria-describedby`.
7. **Dialogs.** Native `<dialog class="modal">` opened with `showModal()`, `aria-labelledby` the title, `aria-describedby` the
   body, `overscroll-behavior: contain` on the box (`overscroll-contain`). Focus starts on the safe button (Keep pattern, Keep
   editing). Escape and the backdrop cancel; the browser traps Tab. On close, focus returns to the opening button, or follows
   the rule of 6.6 when that button is gone. Pattern names are inserted with `textContent`.
8. **Live regions.** One polite status region for the panel. Announce: load finished with the count, action outcomes, the test
   summary, errors. Server findings in the form are in an `aria-live="polite"` area. The index-off and rebuild notes rendered
   with the list have no alert role.
9. **Tables.** `caption` (visually hidden), `th scope="col"`, the Name cell and the Stored form cell are `th scope="row"`. A
   table that can scroll sideways sits in `div.overflow-x-auto[tabindex=0][role=region][aria-label]`.
10. **Marked sample.** A focusable scroll region with an `aria-label`; `mark` keeps its native semantics; everything it shows is
    also in the ledger as text, so the figure is never the only carrier.
11. **Names.** Row actions include the pattern name. Icon-and-text buttons keep their text; no icon-only button exists. Dates
    use `<time datetime>`.
12. **Not colour alone.** Status, findings, notes and marks each have a word, an icon, or weight and underline.
13. **Focus visibility.** DaisyUI's `focus-visible` outline on every control; `summary`, the panel heading and the scroll
    regions add `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2`. Never `outline: none` without a
    replacement.
14. **Motion.** Only DaisyUI's spinner, hidden under `prefers-reduced-motion: reduce` (`motion-reduce:hidden`) with its text
    kept. Nothing slides, fades or pulses. `scrollIntoView` uses `behavior: 'auto'` under reduced motion.
15. **Zoom and text size.** At 200% zoom nothing clips: no fixed heights except the marked sample's maximum; cells wrap;
    toolbars and button rows wrap.
16. **Language.** `lang` on the panel root; `lang="en"` on text left in English (section 5).

## 11. What must never be shown or done

1. The panel renders only the fields named in sections 6.4 and 6.7, through builder functions, never by iterating an object's
   keys. A field the server adds later stays invisible until it is added here on purpose.
2. **No tenant key, organization id, user id (`created_by`), document name, document id or chunk text appears anywhere.** The
   workspace is shown by its name only.
3. **The panel never lists identifiers stored in the index.** The only identifiers on screen are those found in the sample the
   admin pasted. No "closest identifiers", no counts per identifier, no call to `rag_identifier_resolve`.
4. The sample, the result and the draft are never written to `localStorage`, `sessionStorage`, a cookie or the console.
5. The browser never runs a pattern against the sample (finding 11). It compiles the draft and tests it against the empty
   string, nothing more.
6. Every server and admin string (names, patterns, spellings, stored forms, codes, unknown messages) is inserted with
   `textContent`. The test stubs a name, a pattern, a spelling and a stored form containing `<img src=x onerror=alert(1)>` and
   asserts that no element is created from them; `grep -c innerHTML` on both new files is 0.
7. No `Authorization` header, no token in browser storage, no second sign-in form.
8. **No domain word or value in any label, help line, placeholder, example or test fixture** (REQUIREMENTS.md, domain
   neutrality). Copy says "identifier", "pattern", "spelling", "stored form" and describes shapes ("two letters, four digits").
   It never says what an identifier is for. Test fixtures use the synthetic shapes of section 6.3.
9. The switch box never claims a rebuild has run, never shows a count it does not have, and never offers a button for a rebuild
   that only a command can run.
10. `retrieval-tuning-switches.js` reads exactly nine page inputs (the eight switches and `#RAG_PIPELINE`);
    `identifier-patterns.js` reads exactly two (`#RAG_IDENTIFIER_INDEX`, `#workspace-selector`). Neither reads a value whose name
    matches `/(KEY|SECRET|TOKEN|PASSWORD)/i`.

## 12. Copywriting Contract

Voice: plain verbs, sentence case, names from the admin's side of the screen. A message that reports a problem says what
happened and what to do next. One action keeps one name through its whole flow: the row button, the dialog's confirm button and
the outcome message say "Delete pattern", "Delete pattern", "deleted".

**Words used, and words avoided.** "Identifier" for the thing found. "Pattern" for an admin-defined format; "built-in rule" for
`IDENTIFIER_PATTERN`. "Spelling" for an identifier as written in a text (`raw`). "Stored form" for its normalized form; the word
"normalized" appears once, in the switch help. "Keyword search" for the lexical leg. "Workspace" for a tenant. "Stored
documents" opens every rebuild line. "Regular expression" appears once, in the Pattern help. Not shown: "regex", "flags",
"tenant" (except in the one line that explains `<key>`), "backfill", "ReDoS".

**Action labels are verb + noun in every locale:** "Add pattern", "Edit pattern", "Save pattern", "Enable pattern", "Disable
pattern", "Delete pattern", "Keep pattern", "Close form", "Keep editing", "Discard changes", "Run test", "Clear sample",
"Refresh patterns", "Reload panel", "Open identifier patterns", "Open retrieval switches". In-flight text ("Saving…") is status
on a disabled button, not a label.

**Counts are written as "label: number"**, so no string needs a plural form in en, zh or it. Numbers use
`Intl.NumberFormat(locale)`; dates `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`; times `{ timeStyle: 'short' }`.

**Where the strings live.** Section 12.2: static English in `index.html`; zh and it only through the 3.2 applier when it exists
(section 6.1), except the three notes and the pointer, which `retrieval-tuning-switches.js` sets from
`RETRIEVAL_TUNING_LABELS { en, zh, it }`. Sections 12.3 and 12.4: `IDENTIFIER_PATTERNS_LABELS { en, zh, it }` in
`identifier-patterns.js`, read through one function that fills `{placeholders}` and falls back to English. A placeholder shown
as `{command}`, `{identifiers}`, `{relex}` or `{code}` is replaced by a `code` element, not by text. In the copy columns, a word between backticks (an option value, a command flag,
`<key>`) is likewise set in a `code` element with `translate="no"`; the backticks themselves are never shown.

### A.0 Findings that shape the addendum

1. **The panel has two kinds of document entry.** `CitationSourceEntry` (Phase 5: number, title, page and section line, quote,
   an amber note when the document is no longer available) and the listed source card (icon, title with inline "Referenced" and
   "Cited" marks, upload date, snippet, provider line). Both need the new lines. Web and tool sources never get them.
2. **A listed card with a `url` is one big link.** The whole card is wrapped in `<a target="_blank">`. A control that opens and
   closes cannot sit inside a link (nested interactive content), so the 'also in' line of such a card is rendered directly
   under the link, not inside it (A.4).
3. **The title is clamped to two lines** (`line-clamp-2`) and carries its marks inline, so a mark after a long title can be cut
   off. The version tag is therefore its own line under the title and is never clamped.
4. **The fields do not exist yet.** `Source`, `SourceCitation`, `CitationDisplayEntry` and the `usedDocuments` item type have no
   `version`, `isCurrent`, effective dates or `alsoIn`. Shapes below follow D-13, D-21 and F-6; names are proposals to the
   backend plans (P14, P19), mapped in one place (A.2).
5. **A cited superseded version would also get today's amber note.** The citation availability map has two values, `current`
   and `unavailable`, so a version that was already superseded when the answer was written shows "This document has since been
   updated or removed". With a version tag on the entry that sentence is wrong about the order of events (A.3).
6. **The period the backend filters on can fall back to the upload date** (F-6, Pattern 3: `effective_from`, else `created_at`).
   A label that says "in effect" must not be put on a fallback date (A.11, row A4).
7. **Sources are stored in `localStorage`** (`sources_<chatId>`) as whole objects. The new fields are stored with them, and
   entries saved before this phase have none of them. Both cases must render correctly (A.6).
8. **The panel is the main app's only.** `SourcesSidebar` is mounted in `src/app/client-layout.tsx`. The embed window, the shared
   page, voice and WhatsApp do not render it and are not changed.
9. **A refusal has no sources.** When an asked identifier does not exist (D-31), the answer is the "information not available"
   text and the panel is empty or closed. A note placed in the panel would not be seen (A.8).
10. **Existing panel strings are in `answerQualityStrings(language)`** (`en`, `zh`, `it`, other languages fall back to `en`),
    with functions for strings that take a number. Its English labels use title case ("Cited in This Answer"); short marks are
    one word ("Cited").

### A.1 Design direction

**Subject.** The provenance line of a source: which version of a document an answer read, and which other documents say the
same thing.
**Audience.** A person reading an answer who opens Sources to check it. They did not ask for metadata; they want to know "is
this the text that applies now?" and "where else is this written?".
**Primary job.** Say both in one line each, in the entry they belong to, and add nothing when there is nothing to say.

The visual direction is pinned by the existing component: its cards, its 12px grey meta lines, its amber note, its marks. The
addendum adds two lines in that vocabulary and no new colour, size, radius, shadow or motion pattern. The only emphasis is
spent on the word "Superseded", because it is the one fact that can make a correct quote the wrong answer.

Rejected: a coloured version pill in the title row (clamped away with long titles, finding 3); a timeline or version switcher
(the chat control for version scope is deferred by CONTEXT.md); a tooltip for the dates (not reachable by touch or keyboard);
a count badge with a popover for the other documents (a second layer for at most a short list); links on the other documents'
names (the payload carries no address for them); a card per other document (they are the same passage, not more sources).

### A.3 Version tag

One line of 12px text. It answers "which version, and is it the one that applies now".

```
Citation entry                                   Listed source card
┌──────────────────────────────────────────┐    ┌──────────────────────────────────────────┐
│ (2) {document title}                     │    │ ▤ {document title, up to two lines}      │
│     p. 4 · {section}                     │    │    Cited                                 │
│     ↺ Superseded  Version 2, in effect   │    │   ↺ Superseded  Version 2, in effect     │
│     1 Jan 2025 to 30 Jun 2025            │    │   1 Jan 2025 to 30 Jun 2025              │
│     ┌ quote ───────────────────────────┐ │    │   Uploaded: …                            │
│     └──────────────────────────────────┘ │    │   {snippet}                              │
│     ▸ Also in 3 other documents          │    │   Document Source                        │
└──────────────────────────────────────────┘    │   ▸ Also in 3 other documents            │
                                                 └──────────────────────────────────────────┘
```

**Placement.** Citation entry: after the page and section line (or after the title when there is none), before the quote.
Listed card: directly under the title block, before the "Uploaded:" line. In both, the tag is inside the card; it is plain
text, so it may sit inside a card that is a link.

**Markup.** `p.mt-1.flex.flex-wrap.items-baseline.gap-x-2.gap-y-1.text-xs.text-gray-500.dark:text-gray-400` with two children:

| Part | Markup | Content |
|------|--------|---------|
| Marker | Superseded: `span.inline-flex.items-center.gap-1.font-medium.text-amber-700.dark:text-amber-300` with the lucide `History` icon (`h-3.5 w-3.5 flex-shrink-0`, `aria-hidden="true"`). Current: `span.font-medium.text-gray-700.dark:text-gray-300`, no icon | `versionSuperseded` or `versionCurrent` |
| Version phrase | `span.min-w-0.break-words` | `versionOnly`, `versionFromTo`, `versionFrom` or `versionUntil`, chosen by which dates are present; each date is a `<time dateTime="YYYY-MM-DD">` formatted with `Intl.DateTimeFormat(language, { dateStyle: 'medium', timeZone: 'UTC' })` |

The row wraps and is never clamped or truncated. The marker's colours are the ones the component already uses for its amber
note; "Superseded" is carried by the word and the icon, never by colour alone.

**When it shows** (pure function `sourceVersionView(source, listHasSuperseded)`):

| Source data | Result |
|-------------|--------|
| `type` is not `document` | Nothing |
| `version` is not an integer of 1 or more, or `isCurrent` is not a boolean | Nothing |
| `isCurrent === false` | Tag with the Superseded marker |
| `isCurrent === true` and the list on screen has at least one superseded document entry | Tag with the Current marker, so the two versions can be told apart |
| `isCurrent === true` and no entry on screen is superseded | Nothing |
| A date that is missing, `null` or not a valid ISO date | That date is left out; the other parts still show |

The last-but-one row is what keeps today's panel unchanged: with `RAG_VERSION_SCOPE` off, or a scope of `current`, no
superseded chunk can be retrieved, so no tag appears even if the server were to send `version` on every source.

**With the amber note (finding 5).** A citation entry whose tag says Superseded does not also show
`documentUpdatedOrRemoved`: the tag already says this is an older version, and the note's "has since been updated" would be
wrong. An entry without a tag, or with the Current marker, keeps today's behaviour exactly.

### A.4 'Also in' line

One closed line that says how many other documents carry the same passage, and opens to their names.

**Placement.** Citation entry: last element of the text column, after the quote and after the amber note when that shows,
`mt-3`. Listed card that is not a link: last element of the text column, after the provider line, `mt-2`. Listed card that is a
link (finding 2): immediately after the `<a>`, inside the same `div[data-source-item]`, with `px-5 pt-2` so its text lines up
with the card's content.

**Markup.** Native `details` (class `group`) with a `summary` and a list. No React state, no animation of height.

| Part | Markup |
|------|--------|
| Summary | `summary.flex.cursor-pointer.list-none.items-center.gap-1.rounded.py-1.text-xs.font-medium.text-gray-700.dark:text-gray-300` plus `[&::-webkit-details-marker]:hidden` and `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[#FF6417]/60 dark:focus-visible:ring-[#FF8A4D]/60`. Children: the lucide `ChevronRight` icon (`h-3.5 w-3.5 flex-shrink-0 transition-transform duration-150 motion-reduce:transition-none group-open:rotate-90`, `aria-hidden="true"`) and the text `alsoInSummary(n)` with `n` formatted by `Intl.NumberFormat(language)` |
| List | `ul.mt-1.max-h-40.space-y-1.overflow-y-auto.pl-4.text-xs.text-gray-600.dark:text-gray-300` with `tabIndex={0}`, `aria-label={alsoInListLabel}` and the same focus ring |
| Item | `li.break-words` with the file name as a text node and `translate="no"` |
| Overflow item | A last `li.text-gray-500.dark:text-gray-400` with `alsoInMore(n)` when more than 50 names remain |

The summary is 24px tall (16px line plus `py-1`), which meets the WCAG 2.2 AA target size.

**What is listed** (pure function `sourceAlsoInView(source)`): entries of `alsoIn` that have a non-empty `filename`, without
the entry's own `documentId`, one per `documentId` (the first occurrence wins), in the order received. `n` is the length of
that list. The first 50 names are rendered; the rest are counted in `alsoInMore`.

**When it shows.** Only for a document source whose filtered list has at least one name. `alsoIn` missing, not an array or
empty after filtering: nothing is rendered, not even an empty line.

**Not shown:** `documentId`, `chunkId`, similarity, the cluster id, a link, or any text of the other documents. The names are
those of documents in the reader's own workspace, which the retrieval scope already let them see.

### A.5 Truncation and long content

| Content | Behaviour |
|---------|-----------|
| Version tag | Wraps onto more lines (`flex-wrap`); never clamped. At the panel's narrowest width (300px) it takes at most three lines |
| File name in the list | Wraps with `break-words`; never cut, because the name is the whole content of the row |
| Many other documents | The list is capped at 160px (`max-h-40`) and scrolls inside a focusable region; at most 50 names are rendered, then `alsoInMore` |

### A.6 Absent and malformed fields

The rule for both lines: **when the fields are absent, nothing is rendered and the entry's markup is byte-for-byte today's.**

| Case | Result |
|------|--------|
| Switches off (`RAG_VERSION_SCOPE`, `RAG_RESULT_DIVERSITY`) | No field is sent; the panel is unchanged |
| Sources saved in `localStorage` before this phase | No field; unchanged |
| `version` present, `isCurrent` missing (or the reverse) | No tag |
| Dates missing or invalid | Tag without that date |
| `alsoIn` empty, or only the entry's own document | No line |
| An `alsoIn` item without a file name | Dropped before counting, so the count always equals the names listed plus `alsoInMore` |
| Web or tool source carrying any of the fields | Ignored |
| No sources at all | Today's "No sources referenced" block, unchanged |

There is no loading state and no error state: both lines are rendered from data already in the message, and make no request.

### A.8 Identifier suggestions (D-31, F-13): no UI

**Recommendation, adopted: the app renders no component for `identifierSuggestions`. They reach the reader in the answer
text only.**

- F-13 already adds one localized suggestion sentence to the strict-mode "information not available" answer, and D-31 adds
  the same note in balanced and flexible mode. That text is what every channel shows: main chat, embedded chat, voice and
  WhatsApp. A panel component would exist in one of four channels.
- The refusal has no sources, so the Sources panel is empty or closed when suggestions exist (finding 9).
- The text is saved with the message, so history shows it with no new field in the client and nothing new in `localStorage`.
- Buttons that re-ask with a suggested identifier would be a new interaction with its own states; that belongs to a later UI
  phase, with its own addendum.

One ask of the backend plan (P24), because it decides how the sentence looks in the chat: write each suggested identifier as
inline code in the answer text, with backticks inside it escaped. The chat renders the answer as Markdown, where an underscore
or an asterisk inside an identifier would otherwise turn into emphasis, and a dotted identifier could be auto-linked. Inline
code keeps the spelling exact and uses the chat's existing code style, so no new styling is needed.

### A.9 Accessibility

1. Both lines are text in the reading order of their entry: title, location, version tag, quote, then the 'also in' line.
2. "Superseded" is a word with an icon; the icon is `aria-hidden`. Nothing depends on colour.
3. Dates are `<time dateTime>` elements with visible text.
4. `summary` is focusable and toggles with Enter and Space (native); the browser exposes the expanded state. Its accessible
   name is the visible text, which contains the count.
5. Focus is visible on the summary and on the list region (ring in the component's existing brand colour). No `outline-none`
   without that ring.
6. The list is a real `ul`; its scroll region is focusable and named, so a keyboard user can scroll thirty names.
7. No control is placed inside a link (finding 2), so the linked card stays one target with one purpose.
8. Motion: the chevron's 150 ms rotation only, removed under `prefers-reduced-motion`. The lines do not animate in.
9. Text is 12px in colours the component already uses for its meta lines and its amber note; the summary and the Current
   marker use `gray-700` / `gray-300`.
10. Strings follow the app language through `answerQualityStrings(language)`. File names carry `translate="no"` and no `lang`.
11. At 200% zoom and at the panel's 300px minimum width both lines wrap; nothing is cut off or overlaps.

### A.11 Decisions made in this addendum

| # | Question | Decision and reason |
|---|----------|---------------------|
| A1 | Where does the version tag go? | Its own line under the title (and under the location line in a citation entry). Not in the title row, which is clamped (finding 3) |
| A2 | When does a current version get a tag? | Only when the list on screen also has a superseded entry. A superseded entry always gets one. This keeps today's panel unchanged whatever the server sends |
| A3 | Tag and amber note together? | A Superseded tag replaces `documentUpdatedOrRemoved` on that entry (finding 5). **backend:** if the availability map later tells "removed" from "superseded", show the note again for removed documents |
| A4 | Which dates are shown? | Only the document's own effective dates, with the words "in effect". **backend:** `effectiveFrom` and `effectiveTo` are `null` when the document has none; the upload-date fallback of the period filter (F-6) is never sent in these fields |
| A5 | Disclosure control | Native `details` and `summary`: keyboard and state for free, no component state, no height animation |
| A6 | 'Also in' on a card that is a link | Rendered under the link, inside the same item wrapper (finding 2). The card's link behaviour is not changed |
| A7 | Citation entry and listed card of the same document | Each renders from its own data; no cross-suppression. A citation's `alsoIn` belongs to the cited chunk, a card's to the document's kept chunk |
| A8 | Count and plural | A string function per language, as `feedbackCharactersLeft` does; the count excludes the entry's own document and items without a name |
| A9 | Long lists | 160px scroll region, at most 50 names, then "and {n} more". No second "show more" control |
| A10 | Names as links? | No. The payload has no address for the other documents, and ids are never shown |
| A11 | Identifier suggestions | No UI; answer text only (A.8). **backend:** inline code for each suggestion |
| A12 | Where do the strings live? | `src/translations/answer-quality.ts`, the module that already holds the panel's strings; en, zh, it with English fallback |
| A13 | Field names | Proposals from D-13, D-21 and F-6. The backend plans own them; the client maps them in `citationSourcesFor` and `extractDocumentSources` only. **backend:** send the version fields only when the effective version scope is not `current` (D-13), and `alsoIn` only when diversity is `collapse` or `mmr` |
| A14 | Other channels | Embedded chat, the shared page, voice and WhatsApp are not changed: they do not render this panel |
