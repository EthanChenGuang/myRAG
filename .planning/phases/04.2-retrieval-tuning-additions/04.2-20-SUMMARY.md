# 04.2-20 SUMMARY: result diversity in the rank stage

With `RAG_RESULT_DIVERSITY=collapse` the final top-k keeps one chunk per near-duplicate cluster and the kept chunk lists the other documents of the cluster (`alsoIn`); `mmr` collapses first and then reorders the top window by maximal marginal relevance. The stage runs after the refusal decision, so refusal never depends on it. With the switch off, candidates, order and counts are unchanged; the only addition is a `diversify: disabled` stage record.

## Task 2: `diversify` (pure)

- `collapse` runs over the whole list: the first hit of a cluster is kept, later members are dropped; hits without a cluster id are never dropped. `alsoIn` per kept chunk lists dropped members' documents in rank order, each document once, never the kept chunk's own document.
- Sole-chunk guard: a hit that is the only cover of a sub-question among the input list is kept even when it is a later cluster member. With no tags the output equals the untagged run.
- `mmr`: collapse first, then greedy MMR over the first `windowFactor x finalTopK` hits; relevance is the rerank score when the rerank ran, else the fused score, min-max normalised (equal scores all count as 1, no division by zero); similarity is Jaccard of `lexicalTokens(content)` sets with default options, computed once per window hit. Ties break by original index. Hits after the window keep their order.
- Counts: `in`, `kept`, `collapsed`, `mmr_moved`. No I/O, no logging. The legacy `src/lib/mmr-scorer.ts` is not used.

## Task 3: stage, fields, trace, budget

- `runRankStages`: the `refusal` stage decides; then `diversify` (`spec('diversify', 'skip')`, detail `mode=<mode>`) runs `diversify` and then the sub-question reservation on its output, with `subq_reserved` in the diversify counts. On skip (failure or timeout) the survivors are the refusal stage's list, with the reservation applied. With the stage disabled (switch off or `RAG_DISABLED_STAGES`), the reservation stays inside the refusal stage exactly as before, and the diversify stage is recorded `disabled`.
- `mmr_lambda` and `mmr_window_factor` come from `effectiveTuningParams(profile, config, undefined, { embeddingProfileId })`; the window's final top-k is the one the pipeline already uses (voice: the match count; else `evalFinalTopK(profile, input, params.final_top_k)`).
- Voice reads the diversified `rank.survivors`; chat, embed and eval pass `rank.alsoIn` to the context stage.
- Context stage: each kept chunk carries `dupClusterId` when its hit had one and `alsoIn` when the diversify stage listed any; the assemble stage counts gain `topk_redundancy_permille` (integer) whenever a kept chunk has a cluster id, diversity on or off. Counts only, never text.
- Eval route: `kept[]` is mapped explicitly (`dup_cluster_id` when present; `alsoIn` stays out of the trace, plan 04.2-21 owns the payload), and `topk_redundancy` (largest share of kept chunks in one cluster; chunks without a cluster count alone) is set whenever a kept chunk has a cluster id.
- Budget (D-48): 50 runs of a 100-candidate mmr input (final top-k 8, window 24, 120-token chunks), three batches: p95 7.02 ms, 9.82 ms, 7.33 ms (p50 about 6.3-6.7 ms). Budget = max(5 ms, worst p95 rounded up) = **10 ms** for `chat`, `embed` and `voice` in `eval/config/latency-budgets.json`. The file has no `eval` profile section, so none was added there.

## Behaviour changes

- Switch off: unchanged candidates, order and counts; one new `diversify: disabled` stage record. Where kept chunks carry cluster ids (only after the cluster service has run), the eval trace and assemble counts gain the redundancy fields and the retrieval log row gains `topk_redundancy`.
- Switch on: duplicates leave the final top-k; the refusal record is identical across off, collapse and mmr (unit and end-to-end tests).
- Loop stats select `topk_redundancy`, and the retrieval log insert names it when set: deploy 0863 with this code.
