## What changed in behaviour

- Seven new admin routes under `/api/rag/admin/security-events`. With every switch off nothing calls them; the lists simply return what is stored, with `events_recorded: false` while `RAG_SECURITY_EVENTS` is off.
- `GET /api/rag/review/items/{id}` returns `check_details` for `output_guard` and `version_conflict` items. Before this plan those items failed the generated `ReviewItem` schema (unknown reason, null channel, null trace id), so the item route answered 500 and the list left them out. Every other item returns byte for byte as before.
- `GET /api/rag/review/items?reason=` accepts `claim_unsupported`, `output_guard` and `version_conflict`.
- Chat, embed, voice, strict "information not available", webSearch with Exa, `source_images` and `{{context}}` are untouched.

## Deviations

1. **Migration 0945 (not in the plan's file list).** The 0943 functions take tenant keys from the caller and do not resolve "every tenant" for a deployment admin, and the brief requires the tenant to be resolved in SQL. 0945 adds two service-role functions; 0945 was the next free number in 0940–0959 on every origin branch, reserved and pushed first. Not folded into the setup files.
2. **Contract change (not in the plan's file list).** `ReviewItem.reasons` now accepts `claim_unsupported`, `output_guard`, `version_conflict`; `channel` and `trace_id` may be null. Without it the D-55 items could not be returned at all. New `ReviewCheckDetails` / `ReviewCheckDocument`. `npm run gen:schemas` regenerated the JSON Schemas, samples and zod file.
3. **`review-access.ts`**: the list filter enum gained the three reasons.
4. **No `total` in the events list.** UI-SPEC 8.1 proposes a total; the 0943 function returns none and paging works with `next_cursor`. 05.2-37 can show "Load more" without it.
5. **link-previews is deployment-admin only** (see decisions).
