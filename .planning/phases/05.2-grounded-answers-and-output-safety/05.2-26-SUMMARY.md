# Phase 5.2 Plan 26: Output-cap sweep and judge calibration Summary

**Two eval tools now choose this phase's tuned values from evidence, and each is the only writer of its config file. The first, `python -m rag_eval.sweep output-cap`, picks the per-mode output cap under the 2% truncation rule. The second, `python -m rag_eval.calibrate groundedness-judge`, fits the judge's maximum unsupported share per (judge model, judge version, language). Its committed fake-judge fixture cells give an Italian fake-judged eval answer a calibrated label.**

## Accomplishments

- **Output-cap sweep (D-34, LAT-05).**
  - For each mode (strict, balanced), the sweep runs the answer tier once uncapped and once per candidate cap. The fixture runs set the cap through the env overlay `RAG_MAX_OUTPUT_TOKENS=<cap|off>`; a live sweep uses one deployment per candidate.
  - Per candidate it records answer correctness, citation recall, mean output tokens, generation latency p95 and truncation rate (`finish_reason == length`).
  - The rule: the smallest cap whose correctness and citation recall are both within the noise band of the uncapped run, and whose truncation rate is strictly below 2%. A cap at exactly 2% fails.
  - The written `OutputCaps` file is validated by the contract. A fixture sweep refuses the committed `eval/config/output-caps.json`; the CLI default `--out` exits 2 without running anything. Candidates below the app's 256-token floor are refused.
  - A missing uncapped run is an error.
- **Harness.** `run-smoke --rag-mode` passes the mode to `runEval` (`ragMode`, default strict), so the run's `rag_mode` is recorded in the manifest and report. `run_harness(answers=True)` omits `--no-answers`. Every existing caller is unchanged.
- **Labelled answers (D-27).** The file holds 72 answers, 12 per language (zh, en, it) per split.
  - Every answer has the same neutral synthetic form: "panel X holds N units" premises and three sentences, each labelled supported or unsupported.
  - Faithful answers include word-form numbers, which the fake judge misses (false positives).
  - Unfaithful answers include invented values, an unresolved reference, and a value taken from the other premise, which the fake judge misses in en and it (false negatives). This keeps recall and precision below 1.
- **run-judge.mts.** It parses each labelled line strictly; a malformed line exits 2. `--judge fake` installs `fakeJudgeClaims` per answer through `setClaimJudgeForTests`. A real judge needs `--generator-model` and runs through `judgeClaims`. The output is one JSONL line per answer with its verdicts, `judge_model` and `judge_version`.
- **Judge calibration.** The tool spawns run-judge, fits on dev, checks once on test, and merges cells keyed by (judge model, judge version, language).
  - Fixture cells come only from the fake judge, and the fake run must report `fake/judge-v1`.
  - A real judge is refused when writing from the fixture answers.
  - The committed cells were written by `python -m rag_eval.calibrate groundedness-judge --judge fake`:
