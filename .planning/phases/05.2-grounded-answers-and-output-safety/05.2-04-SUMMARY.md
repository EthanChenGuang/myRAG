# Phase 5.2 Plan 04: Registry fixed texts Summary

**The language registry now holds every fixed text of Phase 5.2 (and the three 5.2.1 texts) in zh, en and it, as typed notices, labels and instructions. `fixedText` is the one reader, and the browser gets a generated notices-and-labels subset.**

## Accomplishments

- `LanguagePack.texts` is now `LanguageTexts`, with three groups: `notices` (13 keys), `labels` (13 keys) and `instructions` (12 keys). Every group is frozen and forbids extra keys. A key that is missing from a pack makes the pack incomplete. An empty text, an unknown key, or a placeholder that is missing or not declared fails validation in every language.
- Completeness (D-04) now covers every text key. The Phase 3.2 `texts.strict_refusal` part is replaced by the 38 parts `texts.<group>.<key>`. Python, TS and the shared validator `config/rag/validate-language-settings.cjs` (used by the app, init-env and config-server) agree. The shared case file has one case per text key.
- The English values of `kb_unavailable`, `citation`, `attached_documents`, `document_updated_or_removed` and the six badge texts were moved over from today's data, not retyped. `no_information` (en) is the existing refusal text. The existing zh and it values are kept for `kb_unavailable`, `citation`, `attached_documents`, the badges and `document_updated_or_removed`. Each of these has its own equality test (`tests/rag/lang/texts-equality.test.ts`).
- The zh and it `no_information` texts and every other `notices.*` and `labels.*` value come from UI-SPEC 12.2 and 14.2.
- Instruction texts are new. They were written in English first, and zh and it say the same thing. They use abstract wording only:
  - The partial-answer example is "what are A and B?" with "A is X; nothing about B", and it contains no digits.
  - The relevance, relevance-open, general-knowledge and web-separation texts ask for each label alone on its own line in bold: `**{label}**`.
  - Labels and the sentinel are named parameters, so the label words the model is told to write are always the registry values.
- `fixedText(key, language, params?)`:
  - It reads only through `getLanguagePack`, a Map lookup, so `__proto__` and `constructor` never resolve.
  - It falls back to `RAG_PRIMARY_LANGUAGE`, or to English while the languages are not configured.
  - It rejects an unknown key and throws `MissingTextParameterError` when a parameter is missing.
  - It inserts parameter values literally, so `$&` is not treated as a replacement pattern.
- `npm run gen:schemas` now also writes `src/lib/rag/lang/texts.generated.ts`. It holds `FIXED_TEXTS` with the notices and labels for each language, keys sorted, and no instructions. A second run leaves every generated file unchanged.

## Deviations from Plan

1. **Files outside `files_modified`:**
   - `config/rag/validate-language-settings.cjs` and its `.d.cts`: the shared completeness rule read `texts.strict_refusal`. It now exports `TEXT_KEYS` and checks each key.
   - `src/lib/rag/lang/registry.ts`: it gains `TEXT_KEYS`, `TextKey` and `packText`, and `COMPLETENESS_PARTS` covers every key.
   - `tests/fixtures/rag/language-pack-completeness-cases.json`: the case `no_strict_refusal` is replaced by 38 cases, one per key.
   - `scripts/tests/gen-zod.node-test.mjs`: two new tests.
   - Without these changes, the Phase 3.2 completeness tests and the language picker validator would break.
2. **"Missing key fails validation" is read as "fails completeness".** A pack with a missing text key still loads, with the value null, and is reported incomplete key by key. This follows the Phase 3.2 D-04 model, in which a registered pack may be incomplete and cannot be enabled. The text groups themselves are required. An empty string and an unknown key fail validation.
3. **The partial-answer text uses no bold label.** UI-SPEC 6.6 makes `labels.not_covered` a phrase inside a sentence with no visual treatment, so the partial-answer text writes it inline in quotes. The texts that use the `from_documents`, `from_web` and `general_knowledge` labels ask for them in bold on their own line.
4. **The Phase 3.2 equality test was narrowed as planned.** `tests/rag/lang-registry-equality.test.ts` now pins `notices.no_information` for English only. Its other checks read the new key paths.
5. **The prototype-key guard uses a Map, not hasOwnProperty.** The registry is a `Map`, so `get('__proto__')` returns undefined; this is tested for `__proto__`, `constructor`, `toString` and the empty string. `validate-language-settings.cjs` uses `hasOwnProperty` on the raw JSON.
6. **pack_version is not bumped.** See key-decisions.
