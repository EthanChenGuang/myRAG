## Behaviour changes (all behind switches; off equals today)

- `RAG_SECURITY_EVENTS=true`: scan_injection writes one event per check that found something: `ingest_injection` (detector `injection_rules`, rule ids), `hidden_text` (detector `hidden_text`, span reason kinds), `untrusted_link` (detector `link_check`, target kinds). Action is `quarantined` when the check quarantined, else `detected`. No trace id, no chunk id, codes only.
- `RAG_UPLOADER_HOLD=manual|auto`: an uploader with an active hold gets `approval {required: true, reason: 'uploader_hold'}` at identify (inline and enqueue) and is held at publish. A run that passed identify before the hold, such as a queued job whose snapshot decided at enqueue, is held at publish. An upload without an uploader is never held and makes no lookup. Published documents are not touched.
- `RAG_UPLOADER_HOLD` on with `RAG_INGEST_PIPELINE=legacy`: every legacy knowledge-base write refuses with 503 `upload_approval_requires_unified_pipeline`. This matches the Config UI warning `warn.holdNeedsApprovalPath`.
- The lists: quarantine items carry `uploaderHeld` and pending uploads carry `heldByUploaderHold`. The routes return them as `uploader_held` and `held_by_uploader_hold`. The keys are present only while the hold is on.
