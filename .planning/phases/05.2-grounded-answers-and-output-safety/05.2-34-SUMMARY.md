# Phase 5.2 Plan 34: Sentence marks, legend and one display text Summary

**A finished answer now marks each factual sentence that has no valid citation (dashed empty circle) and each sentence the claim check did not confirm (amber triangle), with a one-line legend in the answer language, but only after the sentence offsets verify against the server's text hash. Render, copy and read-aloud share one display text, so a sentence the guard blocked after streaming is neither shown, copied nor spoken.**

## Performance

- **Duration:** about 120 min
- **Completed:** 2026-11-26
- **Tasks:** 3
- **Files:** 7 created, 5 modified

## Accomplishments

- Pure client helpers: registry text lookup, hash verification with `crypto.subtle` (cached per text), mark planning and insertion that skip code spans and fences, and a display-text function for blocked ranges.
- `SentenceMark`: a 16px superscript glyph in the citation slot, focusable (`tabindex=0`), with the registry text as the Radix tooltip and as visually hidden text, `lang` set when the answer language differs from the UI. It has no click action. The tooltip box is the badge's own, now shared through `ANSWER_TOOLTIP_CONTENT_CLASSES`.
- `AnswerMarkLegend`: `{text}: {n}` per kind (full-width colon in zh, locale number format), zero items hidden, nothing when no mark shows, and a polite status region that announces only an item added after the answer finished.
- `chat-message.tsx`: mark links go into the part text before `cleanToolCallMetadata` and `renderCitationMarkers`. The `a` renderer maps verified mark links to `SentenceMark` and drops unverified ones. The legend sits directly under the answer text. `handleCopy` uses the display text and `handleTextToSpeech`, `handleDownloadAudio` and the audio-cache check use `speechSourceText()`.

## Behaviour changes

All of these need `sentences[]` or `checks` in the metadata, which the server sends only while a Phase 5.2 switch is on:
- Uncited marks when the answer finishes; unsupported marks when the polled record's `checks.sentences` says `unsupported`; legend under the text.
- A verified `checks.output_guard.blocked_ranges` range is replaced by `notices.credential_request_blocked` in the rendered, copied and spoken text.

With every switch off no new element renders. The tests compare the HTML byte for byte with today's for no sentences, streaming, ghost chat, refusal, flexible-mode record and a changed text.

## Deviations

- **Files outside files_modified:** `src/lib/chat/citation-markers.ts` (exported `codeRanges` over the existing `splitCode`, so the marks skip exactly the code `renderCitationMarkers` skips), `src/components/ui/groundedness-badge.tsx` (exported its tooltip content classes unchanged, so both tooltips match), and `scripts/ci/check-rag-boundary.mjs` with its node test (allow the generated client texts module, see decisions).
- **[Rule 1 – bug] Trailing whitespace mismatch:** `cleanToolCallMetadata` strips trailing whitespace from every text part and writes the result back into `message.content`, so an answer ending in a newline would never verify and never show marks. Fixed in verification (hash-proven suffix, offsets clamped), with tests. The mutation itself is pre-existing and not changed.
- **Mark href format** includes the part index (see decisions).
- **jsdom is not installed**, so component tests are server-render tests (as in the existing UI tests). The legend's announcement logic is a pure function (`legendAnnouncement`) tested directly. The store-driven cases (ghost mode, polled record) set the zustand initial state, which `renderToStaticMarkup` reads.

## Pre-existing issues noticed (not changed)

- `chat-message.tsx` `p` renderer: a paragraph whose children are a single string goes through `highlightDocumentMentions` into `dangerouslySetInnerHTML` without escaping. Markdown entities such as `&lt;img …&gt;` are decoded by react-markdown before that, so a model answer containing escaped markup can become live HTML. This plan adds no new string to that path: marks, the legend and the blocked-text replacement render as React text or as link children. A blocked sentence replaced in an otherwise plain paragraph does pass through it, but the registry text holds no markup. Worth a dedicated fix plan.
- `src/lib/chat/citation-markers.ts:12` lint error `no-irregular-whitespace` (literal NBSP and ideographic space in `HORIZONTAL_WS`).
