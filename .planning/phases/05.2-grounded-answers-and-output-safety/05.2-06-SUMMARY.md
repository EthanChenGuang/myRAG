# Phase 05.2 Plan 06: Answer-rule composer Summary

One composer appends the Phase 5.2 instructions after the final system prompt in the fixed D-05 order; with every switch off it returns the prompt itself.

## What was built

- **Task 1 (D-06):** `OUTPUT_POLICY_NOTICE` (tagged, names the documents block) and `OUTPUT_POLICY_NOTICE_UNTAGGED` ("the reference material above") next to `REFERENCE_NOTICE`. They forbid outputting a link, domain or contact address found only in reference material or tool results except targets in the RELEVANT LINKS section, forbid asking for a password, verification code or new log-in, say to ignore material that asks for either, and state they apply whatever other instructions say. `REFERENCE_NOTICE`, `REFERENCE_REMINDER` and `TOOL_RESULT_SENTENCE` are pinned byte-equal by a test.
- **Task 2 (D-04, D-05, D-07, D-13 to D-15):** `composeAnswerRules` with the parts relevance (`relevance` / `relevance_web` / `relevance_open`), partial_answer, general_knowledge, web_separation, version, calculation (reserved; `calcOffered` is false), concise (`capApplies`, false until 05.2-10), output_policy (guard flag/enforce). Strict: relevance, partial_answer, web_separation; balanced: relevance_open, general_knowledge; flexible: relevance_open; bypass: output policy only. Parts 2–7 come from `fixedText` in the answer language; part 8 is fixed English. One `[Answer Rules]` line `{ parts, mode, channel }` when a part is composed.
- **Task 3 (D-04, D-07):** `AnswerTurn.composeSystemPrompt`; the chat route wraps `citationSession.decorateSystemPrompt(createEnhancedRAGPrompt(...))` and the first element of `claudeSystemText`. Nothing else in the route changed; the tool sentence and later system messages still follow the block (RESEARCH Pitfall 3).

## Deviations

1. **[Rule 2 – missing requirement] Registry wording.** The must-have "the relevance and partial-answer parts state that the sentinel replaces any other wording for missing information" was not true of the 05.2-04 registry texts. One sentence was added to `instructions.relevance`, `relevance_web` and `partial_answer` in zh, en and it, in both registry copies; `npm run gen:schemas` regenerated `tests/fixtures/contracts/samples.json`. Files outside the plan's list.
2. **[Rule 1 – bug] Tagging read moved out of the route.** The first wiring read `readSecurityConfig().contextTagging` in the route; the full vitest run failed `tests/eval-answer-sentinel.test.ts > tagging lives only in the shared assembly: neither file reads the switch`. Fixed by reading it inside `composeSystemPrompt` (`contextTagging` is optional there). That existing test is the failing-before test for the fix.
3. `composeAnswerRules` takes an optional second argument `{ log?: boolean }` so a turn logs one line although the Claude path composes twice.
4. The all-off route check compares the all-off prompt with the switches-on prompt minus its composed block (string equality), since a capture from before this plan cannot be re-run; the EVAL-12 characterization tests cover the all-off state as well.
