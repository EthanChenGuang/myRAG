# Phase 5.2 Plan 09: Answer chain, collector and route wiring Summary

**One ordered transform chain for the chat stream, with the no-answer sentinel, end-of-answer notices and a stream-end collector whose text, sentence records and notices describe exactly what the user saw.**

## Performance

- **Completed:** 2026-11-26
- **Tasks:** 3 (plus the requested pre-merge of exec/05.2-07)
- **Files:** 8 created, 7 modified

## Accomplishments

- `buildAnswerTransforms` assembles citation, sentinel, Phase 5.2.1 calculation slot, output-guard slot (05.2-13), notice and collector. With only citation transforms it returns the same array, so `experimental_transform` is unchanged (or absent) with every switch off.
- `noticeTransform` follows the RESEARCH "verified shape". It holds only `text-end`, appends at the final finish-step whose reason is not `tool-calls`, and opens a new text block when that step has none. The leading blank line is dropped when nothing was streamed before. No stream test needs a timeout.
- `createAnswerCollector` observes the final text per text part and the finish reasons. At stream end it computes sentence records for the last text part: part index among the text parts, `text_hash`, and a `truncated` tail on a `length` finish. It logs one `[Citations] Sentence records:` line with counts only and builds the finish metadata (`sentences` only with per-sentence on; `notices` on web; `answerLanguage`; `truncated`; `refusal`/`refusalOrigin` for a sentinel refusal).
- `applyAnswerPipelineToText` is the whole-text twin. It gives the same text, refusal flag, notices and truncated flag as the stream chain for the same answers (tested over five cases).
- `buildAnswerChecksInput` returns `{ sentences?, truncated, finish_reason }`, validated with `AnswerChecksSchema`.
- Chat route:
  - `citationTransformParams` returns `answerTurn.transforms(citationSession.transforms(), …)` in the same `{ experimental_transform }` or `{}` shape.
  - The finish metadata adds `...answerTurn.finishMetadata()` after the two existing spreads.
  - `groundednessEligible` adds `&& !answerTurn.refusedByModel()`.
  - The four new finish-input fields are spread only when a Phase 5.2 switch is on.
  - A sentinel refusal sets the log outcome `refused_no_context`.
  - The generation stage gets the `finish_reason:*` / `refusal_origin:*` rules and the notice, sentinel and half-marker counts.

## Deviations from Plan

1. **[Rule 2 – missing seam] `CitationSession.aliases()` and `truncatedMarkers()`** (session.ts, outside the plan's file list). The collector needs the validated aliases, and D-33 asks for the half-marker count, which the session kept private.
2. **Body `channel` precedence.** The plan says to set the turn channel from the body field. I kept the existing WhatsApp heuristic as the fallback when the field is absent, so today's WhatsApp handler (which sends no `channel` until 05.2-14) keeps `channel: 'whatsapp'` in the composer. A present but unknown value is `web`. The field is read from `data.channel` and from the top level of the body.
3. **Log outcome placement.** `refused_no_context` is set in the UI-stream `onFinish`, before `finishRagTrace`, rather than inside `finishAnswerRecord`. `finishAnswerRecord` returns early when there is no answer record (ghost, embed, WhatsApp), and the log row must be correct for those chats too.
4. **Trace fields.** The trace has no `refusal_origin` / `finish_reason` field, so both are recorded as generation-stage `rules`. Notices by kind, stripped sentinels and half markers are recorded as stage `counts`. This happens only while a collector ran. D-33's "finishReason on the trace for every turn" is therefore met for every turn with a Phase 5.2 switch on; all-off turns keep today's trace (D-03).
5. **Sentinel needs an answer language.** It is installed only when the rule switch is on *and* the turn has an answer language. Without one, the composer adds no sentinel instruction, and no refusal language could be chosen.
6. **Claude Citations path not chained.** The direct Claude stream (`startClaudeCitationStream`) has its own transforms and is not built through `citationTransformParams`. On those turns no collector runs and `answerTurn.finishMetadata()` is `{}`. The source-range input to the records stays unused here (deferred, see below).
7. **Shared test helper** `tests/helpers/answer-chain.ts` (not in the plan's list) for the cut-off and metadata stream tests.
