# Phase 5.2 Plan 25: Claim-level check and LLM judge Summary

**With `RAG_CLAIM_CHECK` on, every factual sentence of an eligible web-chat answer is now checked after it streams. English (and Simplified Chinese through Vectara) go through the sidecar's HHEM claims endpoint. Other languages go to an opt-in judge, which must come from a different model family than the generator. Results are stored per sentence, counted, queued for review and reported to Langfuse. Answer text is never touched. A judge language gets a calibrated answer label once its thresholds cell exists, and "not checked" until then.**

## Behaviour changes

- **All switches off:** nothing changes.
  - `defaultDeps.onPending` is now `createPendingStep`. It runs today's groundedness step, then the claim step, which returns right away while `RAG_CLAIM_CHECK` is off.
  - `answerFinishFields` adds `checksText` only when sentence records exist. That needs `RAG_CITATION_PER_SENTENCE` or `RAG_CLAIM_CHECK`, so with both off nothing is added.
- **`RAG_CLAIM_CHECK=true`** (which needs `RAG_GROUNDEDNESS`):
  - One extra sidecar request per eligible answer, in the same `after()` job.
  - Writes `checks.sentences[].support/scorer/reason` and `checks.claims`.
  - Can add `claim_unsupported` to the review reasons.
  - Langfuse gets a `claim_check` span and the `unsupported_claim_share` score.
- **`RAG_GROUNDEDNESS_LLM_JUDGE=true` with a judge model:** sentences in languages without an HHEM route go in one structured call to the judge model through OpenRouter. This is new egress of answer and chunk text, opt-in, to the same provider as the generator. For a judge language, the answer-level groundedness becomes the judge label, or `judge_uncalibrated`.
