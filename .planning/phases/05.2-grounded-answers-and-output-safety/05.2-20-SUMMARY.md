# Phase 5.2 Plan 20: Version and effective-date labels Summary

**With `RAG_VERSION_LABELS` on, each context block names its version and effective date in its header, in the tagged `<doc>` attributes and in the Claude document title, and citation records carry both values. With the switch off, the documents select, the headers, the attributes and the context string are unchanged.**

## Accomplishments

- `version-labels.ts`:
  - `versionLabelOf` returns `documents.version_label`, else the integer version through `labels.version`.
  - `effectiveDateOf` returns `effective_from`, else `doc_date`, as ISO dates.
  - `versionHeaderSuffix` joins the two labels.
  - `versionLabelLanguage` resolves the label language from the question.
- `fetchAssemblyRows` (legacy) adds `version, doc_type, doc_date, effective_from, version_label` to its one documents read, only while the switch is on. A `42703`/"column does not exist" error retries once with the off select and logs one `[Answer Rules]` warning per process that names 0801 and 0941.
- `buildContext`, with the switch on:
  - Sets `documentVersion`, `versionLabel` and `effectiveFrom` on chunk and referenced blocks.
  - Appends the suffix to the block title, which feeds the `[S<n>]` header, the Claude title and `<doc>`.
  - Appends the suffix to the legacy `--- Document: ... ---` line.
  - Groups sections by document id.
- `docsFromBlocks`/`renderDoc` emit `version` and `effective` attributes through `escapeAttr`.
- `buildCitationRecords` copies `versionLabel` and `effectiveFrom` when present.
