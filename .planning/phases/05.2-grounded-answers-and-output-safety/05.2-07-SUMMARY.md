# Phase 5.2 Plan 07: Sentence splitter, factual and cited rules, per-sentence instruction Summary

**One rules-based answer splitter with exact UTF-16 offsets, the D-19 factual/cited record builder, the per-sentence citation instruction on both citation paths, and a half-marker counter in the marker parser.**

## Accomplishments
- `splitAnswerSentences(text, language)` wraps the Phase 3.2 scan (`splitterFor`) for paragraph text and adds the block pass (code fence, whole table, heading or bold-only line, list item), same-length masking of markers and URLs, the merge exceptions and offsets. It never uses the platform segmenter; one test uses it as a cross-check only.
- `buildSentenceRecords({ text, part, language, aliases, sourceRanges, truncated })` returns `AnswerSentence` records (`support: not_checked`, `scorer: null`) that pass `AnswerSentenceSchema`; `text_hash` is the SHA-256 hex of the part text.
- `perSentence` on the citation session: `decorateSystemPrompt` uses `instructions.citation_per_sentence` in the same position; `claudeSystemPrompt` appends `instructions.grounding_per_sentence`. With the switch off both outputs are byte-identical to before.
- `MarkerParseResult.truncatedMarkers`: partial markers dropped when a text part ends or at `finish()` are counted and never become citations.

## Behaviour changes
- None with the switches at their defaults. `RAG_CITATION_PER_SENTENCE` (default `false`, forced off without `RAG_CITATIONS` / `RAG_CLAUDE_CITATIONS`) changes only the citation instruction text.
- `createMarkerParser` / `parseAnswerMarkers` results gain `truncatedMarkers` only when a marker was cut in half; `valid`, `invalidCitations` and `invalidAliases` are unchanged. Session and Claude callers read only those three fields, so citation records and finish metadata are unchanged.
- Nothing calls `buildSentenceRecords` yet; 05.2-09 wires it into the stream-end collector.

## Deviations from Plan

1. **[Rule 2 - Missing piece] New registry text `instructions.grounding_per_sentence`.** D-20 asks the Claude system text to ground every factual sentence, but the registry had no such text (`citation_per_sentence` asks for `[S]` markers). Added the key to the Pydantic `InstructionTexts`, the shared `TEXT_KEYS` list, both registry copies (zh, en, it), the completeness cases, the Python key list and the pinned key count in `tests/rag/lang/texts.test.ts` (38 → 39); regenerated with `npm run gen:schemas`. `pack_version` unchanged.
2. **[Rule 1 - Behaviour] Two assertions in `tests/rag/citations/marker-parser.test.ts` gained `truncatedMarkers: 1`.** Those cases end with a held partial marker (`[S2` at stream end; `end(id)` flushing `[S1`), which is exactly what D-33 now counts. Counting also at `end()` is required because real streams emit `text-end` before `finish`.
3. **`isExemptSentence(unit, context)` takes `{ texts, inUnsourcedPart }`** with `exemptionTexts(language)` exported to build `texts` once per answer; the plan left the context shape open.
4. **Route wiring of `perSentence`:** the session reads `readAnswerConfig().citationPerSentence` when the input does not set it (the `contextTagging` pattern), so `src/app/api/chat/route.ts` and the eval run route are not edited.
