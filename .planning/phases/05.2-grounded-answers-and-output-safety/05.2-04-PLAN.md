<objective>
Make the Phase 3.2 language registry the source of every fixed text of this phase: a typed `LanguageTexts` contract, the zh, en and it values, the one reader `fixedText`, the generated client subset, and the completeness and equality tests.

Purpose: LANG-09, D-63 step 2 (first part), D-08 and D-12. Plan 05.2-05 switches today's call sites behind `RAG_REGISTRY_TEXTS`; every feature of this phase that needs a text reads `fixedText` regardless of that switch (D-10).
Output: extended contract and data (with the sidecar copy), reader, generated module, tests.

Decisions recorded here:
- Phase 3.2 plan 03.2-01 created `texts` with a `strict_refusal` key and an equality test that pins each language to the text the refusal path returns today (English for zh and it, RESEARCH Pitfall 6). This plan renames it to `notices.no_information`, adds the zh and it translations of UI-SPEC 12.2, and narrows that equality test to English, because D-10 makes English the only byte-identical language. The legacy English refusal constant is moved out of the chat route by plan 05.2-05, which adds its equality test.
- `notices.no_information_web` (UI-SPEC decision 9) and `notices.prompt_too_long` (UI-SPEC decision 21, used by Phase 5.2.1) and `instructions.calculation` (D-08; composed only by Phase 5.2.1, D-70) are added now so every pack is complete once.
- Wording of instruction texts is Claude's discretion within the content each decision fixes; English is written first, zh and it say the same thing.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| language code from a request to the text lookup | untrusted string used as an object key |
| registry text to every channel | text is shown in the web chat, the embed and WhatsApp and passes the output guard on plain-text channels |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05.2-041 | Tampering | prototype keys as language codes | medium | mitigate | hasOwnProperty lookup with primary-language fallback; test with '__proto__' |
| T-05.2-042 | Spoofing | a registry text that itself asks for sign-in details or carries a link | medium | mitigate | wording rule of UI-SPEC finding 8 here; automated guard and credential scan over every text in plan 05.2-12 |
| T-05.2-043 | Information disclosure | instruction text shipped to the browser | low | mitigate | the generated client module excludes the instructions group; test asserts it |
| T-05.2-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan installs no package |
</threat_model>
