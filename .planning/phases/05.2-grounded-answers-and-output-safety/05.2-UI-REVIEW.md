## Top 3 Priority Fixes

1. **HIGH — Events table at <768px does not follow section 10** — Result column is cut off at the right edge and Time wraps to four lines, so a mobile admin cannot read what the check did without horizontal scrolling — render Result under Check (or as a third short line) below 768px and use a compact date format in the Time cell (`scripts/config-ui/rag-panels/security-events.js`, events table renderer; `cfg-sec-events-light-360.png`, `-dark-360.png`).
2. **MEDIUM — Groundedness badge texts in the chat must come from the registry when `RAG_REGISTRY_TEXTS=true`** — harness showed only the `fallback` path in Title Case ("Possibly Unreliable", "Not Checked"), which contradicts the sentence-case copy of 6.8/12.2; verify chat-message passes the registry text and normalise the fallback strings to sentence case (`src/components/ui/groundedness-badge.tsx`; `chat-light-360.png`). Partly a harness artifact (badge fed via `fallback`); the fallback casing itself is real.
3. **MEDIUM — Mark focus ring uses arbitrary colour** — `focus-visible:ring-[#FF6417]/60` (`src/components/ui/sentence-mark.tsx:52`) hardcodes the brand hex instead of a token; at 60% alpha on dark `#2A2A2A` notices it is near the 3:1 non-text limit — use the shared brand token / full-opacity ring (`chat-mark-focus.png`).

## Orchestrator verification (2026-11-28)

The auditor opened 5 of the 47 screenshots. The orchestrator checked the findings against the rest and the code:

- **Fix 1 (HIGH) confirmed, with one nuance.** `cfg-sec-events-light-360.png` shows the Result column cut at the panel edge and the Time cell on four lines. The table sits in an `overflow-x-auto` region (`security-events.js:873`) and `max-md:hidden` hides Document and Uploader as the spec asks, so the Result text is reachable by scrolling the table region (UI-SPEC section 10 allows sideways scroll inside table regions only). It stays HIGH because section 10 says Events shows Time, Check and Result below 768px, and at 360px Result is not visible without scrolling.
- **Fix 2 (MEDIUM) is withdrawn as a casing finding.** UI-SPEC "Constraints" item 14 says the three badge labels keep their existing title-case values byte for byte, and the en registry values are the same title-case strings (`labels.badge_verified` "Verified", `labels.badge_possibly_unreliable` "Possibly Unreliable", `labels.badge_not_checked` "Not Checked"). What remains is a LOW check: confirm in the real chat that a record with `textsSource: 'registry'` renders the zh/it badge texts. `tests/ui/badge-text-source.test.ts` covers this and passes.
- **Hold dialog** (`cfg-hold-dialog-{light,dark}-{desktop,360}.png`): the confirmation names the uploader, the body says what happens, the reason field is optional, and focus lands on "Keep uploads allowed". No finding.
- **Uploaders at 360px** (`cfg-sec-uploaders-light-360.png`): the rows stack, the held state shows a badge plus "Held since", an uploader without a display name falls back to the monospace id and breaks correctly, and the action buttons are full-size. No finding.
- **Artifact.** The white "Config" bar that covers the panel in several element screenshots is the page's sticky header caught by Playwright element capture. It is not a product defect.

Scores are unchanged (18/24). The corrected ranked list is in the orchestrator report: 1 HIGH, 3 MEDIUM, 5 LOW.
