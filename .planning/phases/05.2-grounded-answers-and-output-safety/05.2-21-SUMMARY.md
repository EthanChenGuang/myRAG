# Phase 5.2 Plan 21: Version label in the dates editor and from the title — Summary

**Admins can set a document's version label together with its effective dates. Both the dates list and the supersession list return it. After publish, the supersession detector fills it from the title's version marker, but only when no label is set yet.**

Both RED commits failed on assertions: the 400 from the strict body schema, the missing `version_label`, and a null label after publish.

## Behaviour

- `PUT /api/rag/admin/effective-dates/{documentId}` now takes an optional `versionLabel`:
  - The value is trimmed. It may have at most 40 characters and no control characters.
  - An empty string or `null` clears the label. Leaving the field out keeps the label unchanged and makes no label call.
  - The label is written through `rag_set_document_version_label` with the admitted tenant key. The same `documentInWorkspace` check runs first, so another tenant's document gives the same 404 and nothing is written.
  - An invalid label gives 400 with `details[].path = "versionLabel"`, before any call is made.
- `GET /api/rag/admin/effective-dates` returns `version_label` on every item. `GET /api/rag/admin/supersession` returns it on `document`, `candidate_document`, `older_document` and `newer_document`.
  - The labels are read in one admin-client query on `documents`, filtered by the ids and the admitted `tenant_key`.
  - If that read fails, the list answers 503. The editor therefore never shows an unread label as empty, which a later save would turn into a clear.
- After publish, the supersession hook calls `fillVersionLabelFromTitle`. It reads the current label inside the tenant and writes the marker only when the label is null.
  - Any failure leaves the label unchanged. Logs carry the document id and a reason word only.
  - Aborting the hook still propagates.
- With every switch off, prompts and chat paths are unchanged, because no generation code is touched. The routes accept and return the label whether `RAG_VERSION_LABELS` is on or off (D-48). The fill runs only with `RAG_SUPERSESSION_DETECT=on`, the switch that registers the hook.

  - `src/lib/rag/index.ts` exports `MAX_VERSION_LABEL_LENGTH`.
  - The two route `_lib.ts` files hold the schema and the projections.
  - `eval/harness/fake-edge.mts` allows `version_label` on `documents` for the fill's lookup.
- **Two e2e entry files instead of one.** The deployment mode and the Supabase admin singleton are fixed at import time, so the mode needs its own process (the same pattern as `upload-approval-paths-single`). Both run one shared suite, `version-label-fill-suite.mts`.
- **Small race on the fill.** "Only when null" is a read followed by the setter, not a single atomic SQL step. An admin save that lands between the two could be overwritten by the marker. The window is milliseconds, right after publish. Closing it fully needs a conditional setter in SQL; that is left for a later 05.2 migration if wanted.
