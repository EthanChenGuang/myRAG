# Phase 05.2 Plan 14: WhatsApp output guard and Baileys preview override Summary

**WhatsApp replies are filtered on their whole text before sending while `RAG_OUTPUT_GUARD` is on, every such reply asks the Baileys service not to fetch a preview, and the service reports its preview hosts on `/health`. Today's reply path is pinned by a characterization test.**

## D-91 characterization

**Outcome: fallback sentence only.** Fed the chat route's real response body (the AI SDK UI message stream as SSE `data: {"type":"text-delta",…}` lines, produced by the real `streamText` and `createUIMessageStreamResponse`), `processMessageThroughMyRAG` collects no text. The part after the first colon starts with a space and a brace, not `"`, so every line is skipped. `sendWhatsAppResponse` gets, and the user receives, only `I received your message but couldn't generate a proper response. Please try again.` This confirms RESEARCH Pitfall 16 / assumption A10. Plan 05.2-15 (parser fix, owner decision D-91: fix it) takes it from here. This plan does not change the parser.

Because of this, the whole-text guard only ever sees the fallback sentence on today's stream format until 05.2-15 lands. The guard and its tests run on the text that `sendWhatsAppResponse` receives, so they apply unchanged once the parser collects real text.

## Behaviour changes

- All switches off: no change. The /api/chat body, reply text, send call arity and payload, and the stored assistant message are identical; tests assert deep equality.
- `RAG_OUTPUT_GUARD=enforce`: links outside the allowlist, site host and user message are replaced with `notices.link_removed`. A credential sentence after a removed link is replaced exactly with `notices.credential_request_blocked`. A warned sentence gets the plain-text warning notice appended. Every send carries `linkPreview: false`.
- `RAG_OUTPUT_GUARD=flag`: text unchanged, `linkPreview: false` sent, findings recorded.
- Baileys: with `linkPreview: false`, a message is always sent with `linkPreview: null`. Without the field, behaviour is unchanged. A non-boolean field gets a 400. `/health` gains `linkPreviewHosts`.
