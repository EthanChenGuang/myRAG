# Phase 5.2 Plan 30: Scripted fakes, fake claims sidecar and run configs Summary

**The Phase 5.2 gates now have seven deterministic fake models, selected by model id through one factory: a rule-following model, one violating model per rule category, a link-repeating model, a cap-aware model and a judge. They also have a fake claims sidecar and six named run configurations that pick their generator through a new `generator_model` key.**

## Accomplishments

- **Fakes (D-54, D-42, D-34, D-27).** `fake/rule-following-v1` follows a rule only when its `[rule:<id>]` line is in the prompt:
  - With `partial_answer`, it cites each covered quote with the alias of the block that holds it and writes `<aspect>: <labels.not_covered>.` for every uncovered aspect. In strict mode with no covered quote in context, it writes only the sentinel.
  - With `relevance`, it writes only the sentinel in strict mode. In balanced mode it starts with the bold `labels.general_knowledge` line.
  - With `version`, it gives the current value (or the stale one when `historical`), followed by `labels.version` and the citation.
  - Without a rule line, it does what the matching violating fake does.
- **Violating fakes.** Each one always breaks its own category: `partial` invents a value, `versions` gives both values, `offtopic` reuses the adjacent text with its citation and no label. Each follows the rules in the other categories.
- **Repeating fake.** It repeats every context block that holds a link, with its citation. The stream cuts every link at least twice.
- **Cap-aware fake.** It stops at `maxOutputTokens` with `finishReason: length`.
- **Judge.** `fakeJudgeClaims` returns a `ClaimJudgement` decided by premise overlap.
- **Shared harness behaviour.** Every fake carries the "Harness-only … Never imported by src/" header and reads only `promptParts` plus the golden item it finds by question.
- **Fake claims sidecar.** It serves `POST /v1/groundedness/claims` and checks `x-sidecar-secret` through the shared `sameSecret`, which compares in constant time. A wrong secret gets 401. An invalid body gets 422 `invalid_claims_request`, including duplicate or unresolved refs, as in the sidecar's Pydantic rules. Scores are the overlap between each claim and its referenced premises. Languages are routed as the sidecar routes them (Vectara for en and zh-hans when allowed, local HHEM for en, otherwise `unsupported_language`).
- **Harness dispatch.**
  - `resolveAnswerGenerator` now holds the generator choice that used to be inline in `runEval`.
  - A fake `generator_model` in a run config selects the fake generator and an answer.
  - The `generator === 'fake'` branch installs `evalFakeLanguageModelFactory(items)`. It serves the seven new ids and sends every other id, including `fake/citation-alias-v1`, to the existing fake citation generator.
- **Run configs.**
  - `p52-all-off`: the 14 Phase 5.2 switches at their pinned defaults, answered by the fake citation generator.
  - `p52-rules-on`: `RAG_CITATIONS`, partial, relevance, version labels and per-sentence citations on, answered by the rule-following fake.
  - Three violating configs with the same env, each answered by its violating fake.
  - `p52-sec-output-guard`: sec-recommended plus `RAG_OUTPUT_GUARD=enforce` and `RAG_SECURITY_EVENTS=false`, answered by the repeating fake.
