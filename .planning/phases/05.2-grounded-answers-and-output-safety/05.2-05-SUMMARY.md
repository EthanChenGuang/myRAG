# Phase 5.2 Plan 05: Answer language, registry texts and notice emitter Summary

**Each chat request now has one answer language and one text source; with `RAG_REGISTRY_TEXTS` on and languages configured the strict refusal, the unavailable message and the citation instruction come from the registry in the question's language, and with it off they are byte-identical to today.**

## Performance

- **Duration:** about 75 min (including the 05.2-04 merge)
- **Completed:** 2026-11-26
- **Tasks:** 3
- **Files modified:** 12 (6 created, 6 modified)

## Accomplishments

- `resolveAnswerLanguage` implements D-09 on the existing `confident` flag (the LANG-08 stronger detector is not on this branch): a confident detection among the enabled languages wins; otherwise the previous turn (assistant `answerLanguage` metadata, else the confident detection of the previous user message), then the UI language if enabled, then `RAG_PRIMARY_LANGUAGE`. A language the registry does not ship (Spanish) has no detection evidence and follows the chain.
- `createAnswerTurn` returns a frozen `AnswerTurn`. It runs detection only when `config.anyNonDefault` is true and the language variables are set (D-02, D-03); `textsSource` is `registry` only with `RAG_REGISTRY_TEXTS` on and configured languages.
- `messages.ts`: `LEGACY_NO_INFORMATION_EN` / `_ES` hold the two refusal templates, cut verbatim; `noKnowledgeBaseResponse` returns them. New `noInformationText`, `kbUnavailableText` and their language helpers choose legacy or registry by the turn.
- Chat route: `createAnswerTurn` once, right after `fallbackLanguage`; the kb-unavailable error part, the strict refusal (and its identifier suggestion) and the `[Retrieval Log]` outcome language go through the turn; `createCitationSession` gets the answer language and `textsSource` only when the turn reads the registry.
- `notices.ts`: `NOTICE_KINDS` (answer_truncated, credential_request_blocked, credential_request_warning, reserved calc_corrected and calc_not_verified), `emitNotice` mapping each kind to its `notices.*` key through `fixedText` (missing parameter throws `MissingTextParameterError`), `renderNoticeAsText`. No stream code (05.2-09).

## Deviations from Plan

1. **Seam location (anchor moved, not missing).** The plan's anchor `function buildNoKnowledgeBaseResponse(` is no longer in the chat route: an earlier plan moved it to `src/lib/rag/generation/messages.ts` as `noKnowledgeBaseResponse` (with `noKnowledgeBaseResponseLanguage`), and the route already contained no `# Information Not Available` literal. The constants were cut from that function verbatim; the route call sites of `noKnowledgeBaseResponse` and `knowledgeBaseUnavailableMessage` were switched to the turn-aware helpers. `const fallbackLanguage`, `isSpanishText` and the `createCitationSession(` call were found and are unchanged in behaviour.
2. **Instruction source option on new functions.** `tests/rag/citations/session.test.ts` passes `citationInstruction` to `Array.map`, so adding a second parameter breaks the type check of an existing test. The registry option is on `citationInstructionText` / `attachedDocumentsText`; the originals are unchanged.
3. **`createAnswerTurn` input.** It takes `history` (request messages) in addition to an optional `previousTurnLanguage`, so the previous-turn detection only runs on the switch-on path.
4. **No language-literal allowlist change** was needed: `check-language-literals` passes with the constants in `messages.ts`.
5. **`answer_language` on trace and record (D-89)** is not written by this plan (no task covers it); `AnswerTurn.answerLanguage` is the value later plans store.
