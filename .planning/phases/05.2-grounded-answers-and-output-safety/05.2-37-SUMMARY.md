# Phase 5.2 Plan 37: Security events panel, page banner and panel additions Summary

**RAG administration now has a Security events panel. It has four sub-tabs: Alerts, Uploaders, Events and Link previews. From it an admin can hold or release an uploader's uploads and acknowledge alerts. While an alert is open, a banner above every tab says how many are open and leads to the panel. The existing panels now show the uploader, hold, version and review-reason details this phase added: Quarantine, Upload approvals, Versions and dates, the review queue and the injection-defense card. Every name, host and id is shown as text.**

## Behaviour changes

**Config UI only.** No app route, prompt, retrieval or chat path changes. Strict "information not available", webSearch with Exa, `source_images`, `{{context}}`, voice and embed are untouched.

- **Security events panel** (`#rag-administration-security-events`, after Upload approvals).
  - It calls only the `/api/rag/admin/security-events` routes, through `ragFetch`, with a 15-second timeout.
  - It mounts on any RAG administration link, or on load when that tab is active.
- **Banner.**
  - On every page load the Config UI calls `GET /api/rag/admin/security-events/alerts` once. It shows "Security alerts: {n} open" when n > 0.
  - For a signed-out page the call answers 401 and nothing renders.
- **Prompt-injection defense card.** A pointer line under the detector summary, "Open security events", opens the Events view.
- **Quarantine.**
  - A held uploader gets the Uploads held badge.
  - "Show uploader's events" appears while the page's RAG_SECURITY_EVENTS box is checked.
- **Upload approvals.** A row held by an uploader hold shows `pending.uploaderHold`. Approve and Reject are unchanged.
- **Versions and dates.**
  - The comparison gains a Version row.
  - "Edit dates" gains a Version label field, saved by Save dates. The label is sent only when it changed.
- **Review queue.**
  - New reason labels: claim_unsupported, output_guard, version_conflict, calc_mismatch and calc_unverified.
  - Items raised by output_guard or version_conflict show the check view instead of the labelling form.
- **Shared dialog.** `ragUiConfirmDialog` has a new optional `onConfirm` result, `{ keepOpen, message, focus }`. Existing callers return booleans or nothing, so they behave as before. The `config-rag-ui` tests pass.

## Deviations

1. **rag-ui.js changed.** It was not in `files_modified`. The UI-SPEC 7.2 state "Hold request fails: dialog stays open with `error.holdFailed`" cannot be met with the shared dialog, which always closed. I extended the helper instead of writing a second dialog.
2. **Label keys beyond UI-SPEC 12.4 and 12.5.** Each key exists in en, zh and it.
   - `SECURITY_EVENTS_LABELS`: `tabs.label`, `action.openSetting`, `filter.uploader`, `filter.clearUploader`, `alerts.loading`, `events.loading`, `uploaders.loading`, `previews.loading`, `col.uploaderName`, `col.opened`, `caption.*`, `refresh.previews`, `more.alerts`, `release.running`, `acknowledge.running`.

   - `REVIEW_LABELLING_LABELS`: `check.*`.
   - `INJECTION_DEFENSE_LABELS`: `pointer.action`. The card had no label table before.
3. **Version row fallback.** The UI-SPEC says "the label, else the version number". The supersession route returns no version number for its documents. The row therefore shows the label, the number only when a `version` field arrives, and otherwise "No label".
4. **Check-raised review items load no chunks.** The closing action is the panel's existing Skip case.
5. **Index.html markup landed with Task 2.** The Task 1 tests use the same skeleton, read from index.html once it exists.
6. **Purge hooks and migrations:** none. This plan adds no store, no SQL and no environment variable.

**frontend-design.** The panel follows the UI-SPEC:
- **Layout.**
  - Alerts are articles built from the Phase 3.2 hold line: state badge, sentence, action.
  - Tables are `table-sm` in focusable `overflow-x-auto` regions, with captions and `th[scope]`.
  - Hosts are `ul > li > code[translate=no]`.
- **Badges and tones.**
  - The check badge is outline with an icon and a word.
  - Held is `badge-warning` with `bi-pause-circle`.
  - The open alert uses the readable outline variant from Quarantine.
- **Primary colour** is used only on Hold uploads and the dialog's confirm button.
- **Type.** No new font. Counts are written "label: number". Times use `Intl`.

**Impeccable** (`reference/craft-floor.md`, `polish.md`). I rendered the page with Playwright at 360, 768 and 1280px, in the dark and light themes. The fixtures included 200-character names, file names and hosts, two workspaces and every check kind. Findings, all fixed in `8858c9ab`:
- **Responsive columns never showed.** The page rule `.hidden { display: none !important }` (index.html:1717) kept the `hidden md:table-cell` columns hidden at every width, along with the Uploaders header. The panel now uses `max-md:hidden` / `max-lg:hidden`. A regression test covers it.
- **Pale alert text.** `[data-theme="dark"] .card-body p` (index.html:1471) turned alert paragraphs pale on the warning and info fills, below 4.5:1. Alert paragraphs now keep the alert colour with `!text-current`. A test covers it.
- **Mid-word breaks.** Workspace names and rule ids broke mid-word in table cells. They now wrap at spaces.
- **Squeezed Events table.** At 360px the no-wrap Time column squeezed Check off-screen. Time now wraps below md, and Check has a minimum width.
- **Count without a label.** Mobile Uploaders rows showed a bare count. They now carry an `Events:` label.
- **Verified in the renders:** dialog focus starts on "Keep uploads allowed"; the dialog title wraps a 200-character name; the banner reads in both themes.

**web-design-guidelines** findings:
- `scripts/config-ui/rag-panels/security-events.js:1093` (filterSelect) — form controls need a meaningful `name` — fixed (`name` = id; test "filter selects carry a name").
- `scripts/config-ui/rag-panels/security-events.js:660` (dayText) — dates use `Intl.DateTimeFormat`, not hard-coded formats — fixed (Held since uses `dateStyle: medium`).
- `scripts/config-ui/rag-panels/security-events.js` (tables) — content handling, long text: mid-word breaks — fixed (see Impeccable).
- `scripts/config-ui/rag-panels/security-events.js` (alerts) — contrast of alert text — fixed (see Impeccable).
- `scripts/config-ui/index.html`, `rag-ui.js`, `injection-defense.js`, `quarantine.js`, `upload-approvals.js`, `versions-dates.js`, `review-labelling.js` — none. Every new control has a label or text, icons are `aria-hidden`, ids and e-mails carry `translate="no"`, and status lines are polite live regions.
- **Not applied, by UI-SPEC decision.** Sub-tab state is not in the URL: lists are snapshots, as in the sibling panels. Copy is sentence case, not Title Case (UI-SPEC 12).

## Deferred (pre-existing, outside this plan)

- **Responsive columns in other panels.** `index.html:1717` `.hidden { display: none !important }` defeats 51 existing `hidden md:table-cell` / `hidden lg:table-cell` uses. They are in Upload approvals, Versions and dates, Quarantine, Document tags and others, so those panels never show their md/lg columns. The fix is to switch them to `max-*:hidden`, or to scope the page rule to `#save-indicator`.
- **Pale alert text in other panels.** `index.html:1471` `[data-theme="dark"] .card-body p` lowers the contrast of every `ragUiAlert` paragraph inside a card in the dark theme. The fix is to add `!text-current` in `ragUiAlert` itself, or to exclude `.alert p` from the rule.
- **Document tags overflow.** Its sub-tab row (`#rag-scope-tags-tab-settings`) overflows the 360px page by 14px.
