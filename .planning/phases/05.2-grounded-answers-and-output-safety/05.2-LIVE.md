## C. Check queries (read-only, run after B)

```sql
-- C1. columns (0940, 0941, 0944)
SELECT table_name, column_name, data_type, column_default
FROM information_schema.columns
WHERE table_schema = 'public'
  AND ((table_name = 'rag_answer_records' AND column_name IN ('checks', 'texts_source'))
    OR (table_name = 'documents' AND column_name = 'version_label')
    OR (table_name = 'rag_review_items' AND column_name = 'snapshot'))
ORDER BY 1, 2;
-- expected 4 rows; checks is jsonb with default '{}'::jsonb

-- C2. check constraints (0940, 0941, 0944)
SELECT conrelid::regclass AS table_name, conname
FROM pg_constraint
WHERE conname IN ('rag_answer_records_checks_object', 'rag_answer_records_texts_source_check', 'documents_version_label_check',
                  'rag_answer_records_review_reasons_check', 'rag_review_items_reasons_check', 'rag_review_items_snapshot_check')
ORDER BY 2;
-- expected 6 rows
SELECT pg_get_constraintdef(oid) FROM pg_constraint WHERE conname = 'rag_answer_records_review_reasons_check';
-- expected to list claim_unsupported (and calc_mismatch, calc_unverified once 0950 is live)

-- C3. tables, RLS and table grants (0942, 0943)
SELECT c.relname, c.relrowsecurity
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relname IN ('rag_security_events', 'rag_security_alerts', 'rag_uploader_holds');
-- expected 3 rows, relrowsecurity true
SELECT table_name, grantee, string_agg(privilege_type, ',' ORDER BY privilege_type) AS privileges
FROM information_schema.role_table_grants
WHERE table_schema = 'public' AND table_name IN ('rag_security_events', 'rag_security_alerts', 'rag_uploader_holds')
  AND grantee IN ('anon', 'authenticated', 'service_role', 'PUBLIC')
GROUP BY 1, 2 ORDER BY 1, 2;
-- expected service_role only: INSERT,SELECT on rag_security_events; INSERT,SELECT,UPDATE on the other two

-- C4. functions: present, empty search_path, service_role only (0941, 0943, 0944, 0945 after the 0410 re-run)
SELECT p.proname,
       p.prosecdef AS security_definer,
       p.proconfig AS settings,
       has_function_privilege('anon', p.oid, 'EXECUTE') AS anon_exec,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') AS authenticated_exec,
       has_function_privilege('service_role', p.oid, 'EXECUTE') AS service_role_exec
FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'public' AND p.proname IN (
  'rag_set_document_version_label', 'rag_record_security_events', 'rag_hold_uploader', 'rag_release_uploader_hold',
  'rag_acknowledge_security_alert', 'rag_uploader_hold_active', 'rag_active_uploader_holds', 'rag_list_security_events',
  'rag_list_security_alerts', 'rag_list_security_uploaders', 'rag_mine_failed_queries', 'rag_enqueue_review_item',
  'rag_security_admin_keys', 'rag_security_uploader_in_tenant')
ORDER BY 1;
-- expected 14 rows; settings contains search_path=""; anon_exec false, authenticated_exec false, service_role_exec true on every row

-- C5. indexes (0942, 0943)
SELECT indexname FROM pg_indexes
WHERE schemaname = 'public' AND indexname IN ('rag_security_events_tenant_created_idx', 'rag_security_events_tenant_uploader_created_idx',
  'rag_security_alerts_window_key', 'rag_security_alerts_tenant_created_idx', 'rag_uploader_holds_active_key')
ORDER BY 1;
-- expected 5 rows
```

1. Sidecar: build the HHEM image from the repo root (`docker build --target hhem rag-sidecar`; plan about 2 GB of memory) and point the app at it (`RAG_SIDECAR_URL`, `RAG_SIDECAR_SECRET`). For zh claims, Vectara runs only with `RAG_GROUNDEDNESS_VECTARA_OPT_IN=true`. In multi-tenant mode it also needs `RAG_GROUNDEDNESS_VECTARA_MULTI_TENANT_ACK=true`, which you set only after the Vectara retention terms are recorded.
2. Switches on a staging deployment: `RAG_CITATIONS=true`, `RAG_GROUNDEDNESS=true`, `RAG_CLAIM_CHECK=true`, `RAG_CITATION_PER_SENTENCE=true`, `RAG_GROUNDEDNESS_LLM_JUDGE=true`, and `RAG_GROUNDEDNESS_JUDGE_MODEL=<model of another family than the generator, see config/rag/model-families.json>`. Languages: `RAG_SUPPORTED_LANGUAGES=zh,en,it`, `RAG_PRIMARY_LANGUAGE=en`.
3. Upload one synthetic test document per language: five short neutral sentences that each state one fact about a fictional item.
4. In each language, ask three questions. Each answer should combine one supported fact and one fact that the document does not contain.
5. Confirm that the unsupported sentences are marked "not confirmed by the documents" and that no text was removed. Record the per-claim latency against the `claim_check` and `groundedness_judge` budgets in `eval/config/latency-budgets.json`, and the judge cost.
6. Calibrate from `eval/`: `uv run python -m rag_eval.calibrate groundedness-judge --judge <judge model> --generator-model <generator model>`. Commit only the tool-written `eval/config/groundedness-judge-thresholds.json` cell, never a hand edit, and record the run id here.
7. Ask one Italian question again and confirm that the badge reads `verified` or `possibly_unreliable`, not `not_checked` / `judge_uncalibrated`.
