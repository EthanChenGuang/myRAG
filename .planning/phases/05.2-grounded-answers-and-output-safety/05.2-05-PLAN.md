<objective>
Compute the answer language once per request, switch today's refusal, unavailable and citation-instruction call sites to the registry behind `RAG_REGISTRY_TEXTS`, create the per-request `AnswerTurn` holder, and add the notice emitter core.

Purpose: LANG-09, D-63 step 2 (second part), D-09, D-10, D-11. This is the first of five plans that edit the chat route (05.2-05, 06, 09, 10, 13, chained by depends_on, D-64).
Output: answer-language resolver, AnswerTurn, legacy constants moved to messages.ts, registry selection, emitNotice, tests.

Design recorded here (Claude's discretion on file layout, D-64 "keep the logic in src/lib/rag/"): `AnswerTurn` in `src/lib/rag/generation/answer-turn.ts` is created once per chat request next to the existing per-request state and carries the answer config, the answer language and its source, and the text source (`registry` or `legacy`). Later plans add methods to it (system prompt composition, transforms, finish metadata, checks input, output cap, guard policy) so that each later route edit is one call at a named seam.
