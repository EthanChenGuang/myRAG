# Phase 05.2 Plan 13: Output guard on the chat stream Summary

**With `RAG_OUTPUT_GUARD` on, chat answers are filtered on the live stream (OpenRouter and direct Claude paths) with the turn's own allow evidence; every finding is counted on an `output_guard` span, logged with ids only, attributed to context chunks, recorded as security events and stored in `checks.output_guard`. The links section and link instructions offer the model only allowlisted targets, and the approve route's summary is filtered too. Off, nothing changes.**

## Accomplishments

- Task 1: `outputGuardTransform` and `guardSlot`; real-stream property tests over all 55 fixture answers at every split point (enforce) and per-character (flag).
- Task 2: per-turn policy, span, log, events and checks in `AnswerTurn`; chat route passes one getter object (`outputGuardSources`) to `answerTurn.transforms` and to the direct Claude call; `flaggedToolResults` set filled by the 05.1-15 tool-result guard callback.
- Task 3: `formatGuardedLinks` / `linkUsageInstructions` at the server call sites (assembly, wrap, Claude citation context, embed route); `guardSummaryText` on the approve route's email summary.

## Behaviour changes

- Off (default): no guard transform, no new span, log, event or checks key; links section and instructions byte-identical (tests assert array equality and exact strings).
- `flag`: text unchanged; span, log, events and `checks.output_guard` recorded; links section and instructions narrowed (D-06 applies to both on-modes).
- `enforce`: links outside the four allow rules become `notices.link_removed`; credential sentences blocked or warned per D-39; notices in web metadata or as text on plain channels; late blocks recorded as `blocked_ranges` (part, start, end, text_hash).
- WhatsApp: the handler's whole-text pass no longer appends a second warning when the streamed reply already holds it.
