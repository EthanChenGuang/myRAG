# Phase 05.2 Plan 33: Embed and voice answer rules and output safety Summary

**The embed route now gets the same answer-rule block, output cap, registry unavailable text and live output guard as chat (in its balanced retrieval mode); voice-rag appends the voice block to the context string the agent already reads, and voice-chat checks stored spoken answers after the fact in flag behaviour. With every switch off, the embed stream, the voice-rag response and the stored voice turn are unchanged.**

## Behaviour changes

- Off (default): none. Embed passes no `experimental_transform`, `maxOutputTokens` stays 2000, the prompt has no rule block, the unavailable text is today's; voice-rag returns the same keys and context; voice-chat stores the same rows and runs no check.
- Embed with switches on: `[rule:…]` parts after the strict-wrapper prompt (mode balanced), min(2000, cap), guard and notices on the stream, events for channel `embed` (review enqueue through 05.2-16's direct route), registry unavailable text in the answer language.
- Voice with switches on: the voice block after the Phase 5.1 reminder; with tagging off a `context` field (agent fallback format plus block) is now sent.
- Voice-chat with the guard on: `[RAG Security]` events for channel `voice`; the stored text never changes.
