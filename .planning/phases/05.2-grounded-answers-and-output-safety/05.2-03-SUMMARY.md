# Phase 5.2 Plan 03: Answer checks, version label, security events, alerts and holds — Summary

**Migrations 0940–0943 add the answer `checks` record, the document version label and the per-tenant security event, alert and uploader-hold store. Every new function is service-role only and starts by checking the tenant key. Tests prove each migration is idempotent and tenant-isolated on PGlite in both modes.**

## Behaviour

- No app code is changed and no switch is added. Rows only appear once later plans call the functions, so the chat paths stay byte-identical to before.
- Threshold 0 (the default) stores events and never alerts. An event without an uploader is stored but never counted or held. Releasing a hold approves no document.
- The plan's "concurrent calls" case is covered two ways. A pre-seeded conflicting alert row checks that `ON CONFLICT DO NOTHING` causes no error and no duplicate. Two `Promise.all` calls check that exactly one alert is written. PGlite is a single connection, so the calls run serialized there. Under real concurrency the unique index is what protects.
