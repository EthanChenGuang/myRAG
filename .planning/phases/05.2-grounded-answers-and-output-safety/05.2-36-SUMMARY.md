# Phase 5.2 Plan 36: Answer rules card, read-only blocks and warnings Summary

**The "Answer rules and output safety" card in RAG Modes now shows the state behind its switches. It shows the answer limits chosen by evaluation and the smallest accepted limit, which languages need the judge and whether each is calibrated, the allowed link domains and the sign-in request rule set. It warns about the nine switch combinations that do nothing or surprise. All of it comes from one read-only config-server call and is rendered as text. The card is translated to zh and it on mount.**

## Behaviour changes

- **Config server:** new `GET /api/config/answer-rules`.
  - It is read-only and sits behind the existing Host/Origin gate.
  - It reads `.env.local` and the data files on every call.
- **Config UI:** `answer-rules.js` loads on the page. It mounts when a RAG Modes link is clicked, or on load when RAG Modes is the active tab.
  - It changes nothing that is saved: every input keeps its id, name and value.
  - It sets the `min` of the limit number input to the floor.
  - It marks a stored fixed limit under the floor `aria-invalid`. The hidden value is left unchanged.
- **App:** nothing changes. Chat, strict refusal, webSearch, `source_images`, voice and embed are untouched.

## Deviations

1. **Judge calibration ignores the judge version.** The config server marks a language calibrated when a calibrated cell exists for that judge model and language. It does not compare `judge_version`, because that is a hash of `JUDGE_PROMPT`, which lives only in `judge.ts`. After a judge prompt or rubric change, the card can show "Calibrated" while the app falls back to `judge_uncalibrated`, until the cells are re-fitted. A follow-up could move the prompt into a shared data file or have the eval write the version the app uses.
2. **Judge rows when no languages are chosen.** The UI-SPEC says "supported languages". With no supported languages set, the endpoint lists every registry language without a scorer, because the claim step detects the answer language over the whole registry.
3. **Same-family check uses the default model.** `sameFamily` compares the judge with the default model of the configured provider. A chat that picks another model can still differ.
4. **Commands not implemented yet.** The two commands shown with Copy command, `python -m rag_eval.sweep output-cap` and `python -m rag_eval.calibrate groundedness-judge`, are the names used in the phase plans. Neither exists in `eval/` yet.
5. **Open security events waits for 05.2-37.** The button is not rendered until the Security events panel exists on the page.
6. **Rule-count languages come from the server.** `ruleCounts` languages come from the summary, which reads them from the registry, because `check-language-literals` refuses hard-coded codes. The `guard.rules` template keeps the UI-SPEC's `{zh}`, `{en}` and `{it}` placeholders.
