# Phase 5.2 Plan 35: Notices, labelled parts, version line and badge texts Summary

**Assistant messages now show the server's notices under the answer (blocked, caution, calculation, truncated, unknown), bold registry part labels get their icon, the sources panel shows a citation's version, effective date and "Older version", and the groundedness badge speaks the answer's language when the record says registry texts apply. The embed renderer moved to a library module with a render test, and a pre-existing XSS in the chat paragraph renderer is fixed.**

## Performance

- **Duration:** about 100 min
- **Completed:** 2026-11-26
- **Tasks:** 3
- **Files:** 9 created, 6 modified

## Accomplishments

- `AnswerNotices` (UI-SPEC 6.4): one `role="note"` block per notice inside one polite live region, in the fixed kind order. Icons are `ShieldX`, `ShieldAlert`, `Calculator`, `Scissors` and `Info`, all present in the installed lucide, so no fallback was needed. Tones use the badge's neutral and caution sets plus the red blocked set. The server's text and `lang` are shown as sent.
- `chat-message.tsx`:
  - Renders `AnswerNotices` after the mark legend for every assistant message whose metadata has notices, outside the citation-aware gate.
  - The blocked-range display text from 05.2-34 is unchanged. It already read `checks.output_guard.blocked_ranges`. The new tests pin the verified and unverified cases together with the red notice.
- Part labels (UI-SPEC 6.6): `strong` renderers in `chat-message.tsx` and `markdown.tsx` render `span[data-part-label]` with `FileText`, `Globe` or `Lightbulb` (`aria-hidden`), but only for an exact registry label.
- `renderEmbedMarkdown`: the embed page's `renderMarkdown` and `processInlineFormatting` moved byte for byte. The page imports it.
- `CitationSourceEntry` gains the version line between the title and the page line. `citationSourcesFor` attaches the version fields only when they exist.
- `GroundednessBadge` picks its text source per UI-SPEC 6.8. Shape, icons, tones and `groundednessBadgeState` are unchanged.

## Behaviour changes

- Switch-dependent (the server sends the data only while a Phase 5.2 switch is on):
  - Notices under answers.
  - The version line.
  - The registry badge texts.
- Part labels: the model writes them only under the 5.2 instruction texts. A plain `**…**` that is not an exact registry label renders `<strong>` exactly as today.
- **Fix, always on:** the chat paragraph renderer used to put the paragraph string into `dangerouslySetInnerHTML` unescaped. react-markdown decodes entities first, so model text such as `&lt;img src=x onerror=…&gt;` became a live element. The string is now HTML-escaped before the `/mention` spans are added. Mention highlighting still works, and mention names are escaped too. Plain text renders the same, except that `&`, `<`, `>` and quotes now show as text instead of being parsed.

With every switch off and no notices, the message HTML equals today's (test `with no notices the message is today's`). The sources entry has no new attribute (test `with no Phase 5.2 field the entry is today's markup`). Legacy and missing `textsSource` render the same badge HTML.

**frontend-design.** Every new element follows the UI-SPEC's "the server's words, quietly" direction:
- Notices are small inset-ring blocks in the badge's own tones.
- Labels are an icon in front of the bold run the model already wrote.
- The version line uses the muted meta colour of the page line.
- Nothing new is orange, animated or clickable.

**Impeccable (craft-floor.md, harden.md).**
- Notice text keeps the badge's contrast sets: gray-700 on gray-100, amber-900 on amber-50 and red-900 on red-50, with the dark equivalents.
- The icon box is one text line high, so the icon stays on the first line when zh or it text wraps.
- Every state is covered: empty (no container, no line), unknown kind (neutral `Info`), partial (each version part alone) and injected markup (text).
