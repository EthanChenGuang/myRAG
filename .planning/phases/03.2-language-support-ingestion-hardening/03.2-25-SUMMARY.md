# Phase 3.2 Plan 25: Character-exact zh/it scan fixture (D-18)

**The parse test set has a new class, `scan_zh_it`. Its page is image-only and has Chinese text with full-width punctuation and Italian text with precomposed grave accents. The recorded Docling, LlamaParse and chain outputs equal the exact expected text code point for code point after NFC. CI checks that both parser requests carry the registry OCR codes.**

## Behaviour

- No product code changed. Only fixtures, tests and the eval harness's exclusion set changed.
- `scan-zh-it.pdf` is a single page. It is rendered as one JPEG with the recorded scan font (WenQuanYi Zen Hei, sha256 `79c18ebe…`, the font in `eval/fixtures/ingest/pdf/build-info.json`). The page has no text layer: the content stream has no text-show operator, and a test checks this. The text is neutral synthetic sentences. It has `，；：。` and the Italian words qualità, è, più, ciò, unità, già.
- Recordings, all equal to `expected/scan-zh-it.txt` after NFC:
  - `structured_ocr/page-1.json` (the Docling recording)
  - `premium/page-1.md` (the LlamaParse recording)
  - `chain/scan-zh-it.parse.json` (the ParseResult that the fake sidecar serves)
- None of these recordings contains a base letter followed by a combining mark, or a half-width `.,;:` directly after a Chinese character.
- The tests and the threat-model note say what these recordings prove. They are built from the spec through the adapters (`build_recorded.py`, `record_chain_results.py`). They prove the request shape and that the text travels unchanged. They do not prove OCR quality (T-03.2-252).
- Requests with `RAG_SUPPORTED_LANGUAGES=zh,it` and primary `zh`:
  - The Docling request has `ocr_languages: ['zh','it']`. The sidecar maps it to the PP-OCR engine code `['ch']`, because RapidOCR uses only the first code.
  - The LlamaParse v2 configuration has `processing_options.ocr_parameters.languages: ['ch_sim','it']`.
  - Both bodies are stored in `recorded/<sha>/requests/`. The TS test compares the captured bodies with these files, so a change to the request shape shows up as a test failure and a diff.
- Through inline `ingest()` (unified pipeline), on both the Docling and the LlamaParse path, the markdown that reaches `chunkDocument` equals the expected text block for block. Every line of every Docling chunk is a line of the expected text.

Only the scan-zh-it row was added.
