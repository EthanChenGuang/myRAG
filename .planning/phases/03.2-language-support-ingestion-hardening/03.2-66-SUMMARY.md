## What changed

- **All-off parity (Task 1).** `tests/rag-e2e/phase32-all-off-probe.mts` builds the pre-phase fixture corpus (14 corpus files, 12 typed and 5 parse fixtures: 30 documents, 116 chunks) inline and through the queue. It snapshots every `documents`/`document_chunks` column, the row count of every public table and every non-Supabase HTTP call, then runs 11 single-turn questions through legacy and v2. `phase32-all-off-record.mts` ran the same probe on a worktree at `0e740fc5`. The test checks:
  - pre-phase columns match;
  - columns added since hold their defaults, except the additive list;
  - tables created since are empty;
  - there is no inline ledger row;
  - the external calls match, and nothing calls `/v1/hidden-text` or `/v1/embed`;
  - status, reason, context hash, `source_images`, candidates and `retrievalConfigHash` match.
- **Defaults test.** `defaults-equal-phase3.test.mts` now clears the eighteen D-47 variables and asserts that each one resolves to its off value in `loadIngestConfig` and `loadRagConfig`.
- **Per-switch comparison (Task 2).** Schema 3 of `rag_eval.phase_compare`:
  - It reports per arm, for each judged slice: off, on, the paired difference with its 95% CI, beyond-band and direction.
  - Any gated slice that the on-run drops beyond the band is listed as a failure of that arm, with the slice named.
  - Fixture runs (fixture embedder) are labelled wiring proof and carry no recommendation. The notes name plan 03.2-53 as the source of real observations.
  - An optional arm without runs shows as "not run". A required one fails.
- **Harness.** `run-phase32-compare.mts` runs each arm's two runs as child processes, with the switch in the ingest build env, so the chunks are rebuilt for each run. The `doc_translation` arm comes from `run-translation-compare.mts` (arm A against arm B).

## Deviations

1. **The probe does not run the legacy ingestion writers.** `processDocument` inserts rows through PostgREST, and the fixture edge serves RPCs only (`unsupported method POST for /rest/v1/documents`). Extending the fake edge is outside this plan's files. Phase 3.2 changed the legacy writers in only two places: the LlamaParse language codes (03.2-24) and scope tags at upload (03.2-43). Both are covered by the legacy-writer tests listed in the gates. The probe's "legacy" is the legacy retrieval pipeline.
2. **v2 retrieval sets the languages.** The probe sets `RAG_SUPPORTED_LANGUAGES=zh,en,it` and `RAG_PRIMARY_LANGUAGE=en` for the v2 run in both trees, because since D-02 v2 answers `languages_not_configured` without them. The pre-phase tree ignores both variables. The legacy run leaves them unset.
3. **The probe asks for `maxResults: 100`.** Plan 04.1-15 (`e4126753`, found by bisecting the merge trains, then train 20) caps the final v2 list at the request's `max_results`. Before that, a refused request returned the whole 75-candidate pool. 100 is above the pool, so the cap removes nothing in either tree.
4. **Candidates compare as sets.** Chunk ids are random, so equal scores come back in random order. The pre-phase tree does not even reproduce its own order run to run. Candidates are compared as sets above the pool's lowest similarity, and only their number at it. Status, context hash and config hash are compared exactly.
5. **`embedding_profiles` row count is allowed to differ.** Migration 0440 (Phase 3.1.1) seeds three catalog rows; no write path adds them.
6. **Additive-field list.** It also includes `processing_state.parserVersion` (inline path), which 03.2-17 added so a resumed run can build the fingerprint. It is a fingerprint input, not a defect, so no plan was changed.
