# Phase 3.2 Plan 16: Upload approval admin routes Summary

**Held uploads can be listed, approved, rejected and exempted over HTTP by a deployment admin or by the organization's own owner or admin, with one workspace per request and the database as the final check.**

## Accomplishments
- `approval/admin.ts` after `quarantine-admin.ts`: RPCs on the admin client, bare reason words only, uploader display from the auth user record with the id as fallback, workspace pre-check of document and exemption ids.
- Four route files with `checkAdminOrOrgAdmin`, `.strict()` Zod schemas from `zod/v3`, `Cache-Control: no-store`, `[RAG Admin]` logs with ids and counts only.
- `checkAdminOrOrgAdmin`: deployment admin first; otherwise (multi-tenant only) the verified user must be owner or admin of exactly the named organization. Fails closed on every lookup error.
- Migration 0814 so the SQL functions accept organization admins who are not deployment admins (see Deviations).

## Behaviour changes
- New routes only; nothing changes for existing routes. `requireRagAdmin` is unchanged in behaviour (its session part moved to `verifyRagUser`; `tests/rag/rag-admin-guard.test.ts` passes unchanged).

## Deviations
1. **[Rule 2, security-relevant correctness] Migration 0814 outside `files_modified`.** The plan and PATTERNS assumed `rag_admin_tenant_keys` already admits organization admins. It raises `not_admin` for anyone outside `admin_users`, so with 0803 alone an organization admin admitted by the route would get `not_found` for everything. 0814 redefines `rag_upload_approval_keys` only (same signature, SECURITY DEFINER, `SET search_path = ''`, revoked from PUBLIC/anon/authenticated, granted to service_role; it is already in the 0410 lockdown list). Number 0814 was free.
2. **Org-admin denial body.** The plan says the organization admin of O naming P gets `403 Forbidden`. It gets 403 with the standard body `Admin access required`, because it is not an admin of P, the same as a plain member ("everyone else gets the standard denial"). `Forbidden` is used for a deployment admin naming an organization it does not administer, as in ingest-jobs. The panel treats both as 403.
3. **Exemption removal by query.** `DELETE .../exemptions?id=<uuid>&organizationId=...` (no body).
4. **Extra exports:** `verifyRagUser`, `adminWorkspaceDenied`, `ORGANIZATION_ADMIN_ROLES`, `exemptionChoices`.
