# Phase 03.2 Plan 31: Native-review gating of drafted zh/it golden items Summary

**Machine-translated or LLM-drafted zh/it golden items now count in gated slices, paired differences and denominators only once a named native speaker has approved them; the report lists them as report-only and prints a native review backlog for the owner.**

## Accomplishments
- `counts_in_gated_slices` (golden item or scored item) and `review_backlog` in `eval/src/rag_eval/native_review.py`.
- `score_items` marks held items `report_only_reason: native_review_pending`; `aggregate` and `paired_report` keep them out of every gated slice; the gate needs no change because it reads the aggregated slices.
- `report.md` gains "Report-only items (native review pending)" (only when an item is held) and "Native review backlog" (always when built from golden, count 0 when empty).
- Existing goldens: all 164 + 46 items carry no `native_review`, so all count. On the smoke tier the backlog lists 118 existing zh/it items (it 60, zh 58); the ingest tier lists 138 (zh 70, it 68), all `existing_unreviewed`.

1. **[Rule 3 - Blocking] Report contract extended.** `paired.py` and the gate read only `report.json`, which carried no review state. Added `ItemResult.report_only_reason` and `EvalReport.native_review_backlog` (+ `NativeReviewBacklogEntry`) to `rag-sidecar/src/rag_sidecar/contracts/report.py`, both omitted while unset, and regenerated `EvalReport.schema.json` and the Zod (`npm run gen:schemas` leaves no diff). Files outside the plan's `files_modified`.
2. **[Rule 3] `metrics.py` touched.** Gated slice membership is built in `aggregate`, so the filter lives there (and `score_items` sets the marker); `slices_by` exposes the grouping for the report-only table.
3. **Byte-identity reading.** The gating change alone is byte-identical on both golden files (verified by run comparison; gate.json identical). Task 2 requires the backlog section, so `report.json` gains one key and `report.md` one section. The Phase 5 pin `test_report_without_citation_data_is_byte_identical_to_before` now asserts the old hashes for the backlog-free render and pins the full output with new hashes.
4. **Cross-lingual per-side review.** The contract has one `native_review` per item, so "every zh/it side approved" is the item's single status; documented in key-decisions.
