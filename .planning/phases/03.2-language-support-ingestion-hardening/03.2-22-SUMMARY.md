# Phase 3.2 Plan 22: Per-chunk language, `und` and the document language list Summary

**With `RAG_LANGUAGE_AWARE_INGEST=on`, every chunk written by the unified pipeline gets its own language among the enabled languages, with a 4-decimal confidence, or `und`. The document gets the token-weighted dominant language and the list of languages holding at least 10% of the detected tokens. With the switch off, the enrich stage and every written row are unchanged.**

## Behaviour

- **Switch off (default):** `enrich` runs the existing code unchanged (`detectLanguage` on the parse text, `setFields({ language })` when not null). Chunks carry no `language` or `language_confidence` key, so `rag_write_chunks` mirrors the document language and leaves the confidence null. No `und` row is written.
- **Switch on**, languages configured:
  - Each chunk is detected with `detectLanguageWithConfidence(content, enabledLanguages)`. It is `und` when there is no language, the answer is not confident (an en/it tie), or the 4-decimal confidence is below `UND_CONFIDENCE_FLOOR = 0.15`. Empty, whitespace-only and numbers-only chunks are `und` with confidence 0.
  - Monolingual mode (D-03): every chunk gets the single language with confidence 1. `und` is never written.
  - `documents.language` is the language with the most `cl100k_base` tokens (ties go to the earlier registry language). `documents.languages` lists, in registry order, every language with `tokens * 10 >= total`, on integer counts. `und` tokens are left out of the total.
  - With no chunk, or only `und` chunks, only `languages: []` is written and `documents.language` stays unset.
  - `processingLanguage(language, primary)` gives the primary language for `und`. This is the seam for plans 20 and 23. Nothing in this plan consumes it yet.
- **Switch on, languages not configured:** the switch-off branch runs.
- `detectLanguageWithConfidence` itself is untouched. The tie is still `{ en, false, 0 }`.
- **Migration 0812:**
  - `rag_write_chunks` reads an optional chunk key `language`. A code matching `^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$` (`und` included) goes to `document_chunks.language` and `metadata.language`.
  - Without the key, or with null, the function behaves exactly as 0801. Any other value raises `invalid_chunk: language ...`.
  - The function keeps its signature and SECURITY DEFINER, with `SET search_path = ''`. It is revoked from PUBLIC, anon and authenticated and granted to service_role.
  - The tenant check (document selected by id and `p_tenant_key`) is unchanged.
- `rag_tenant_language_shares` needs no change. It reads `documents.language`, and the database test shows the mixed document counted under zh.
