# Phase 3.2 Plan 05: Ingestion-side contracts Summary

**Ten new Pydantic contracts with generated Zod and samples, and the job snapshot, parse request and ledger job extended without breaking recorded payloads or an older sidecar.**

## Accomplishments

- `ingest_security.py`: `QuarantineReason` (one named sample variant per kind), `HiddenTextRequest` (JSON part; bytes travel as the multipart file part), `HiddenTextReport` (status, spans with page/text/reason/bbox, link_targets, checker_version, `dropped`; at most 200 spans of 2,000 characters), `HiddenTextRules` (schema_version, rules_version, `pdf`, `docx`, `zero_width_threshold`; names and ranges only), `LinkCheckResult`, `UploadApproval`.
- `ingest_settings.py`: `LanguageSettings` (unconfigured means no languages, no primary, not monolingual; configured needs ≥1 unique registry code, primary among them, monolingual exactly when one language), `SettingsClassification`, `IngestFingerprintParts`, `FingerprintImpact` (counts ≥ 0, unique mechanism/doc_type rows, aggregates only).
- `JobSettingsSnapshot` gains `language_aware`, `languages`, `primary_language`, `repeat_table_header_effective` (null = use the profile), `carry_table_header`, `row_serialization`, `hidden_text_check` (`off`), `approval` (null), `hold_publish`; `ParseJobRequest` gains `language_aware`, `languages`, `primary_language`, `carry_table_header`. All default to today's behaviour; `primary_language` must be one of `languages`.
- `IngestionJob` accepts kind `translate` and status `pending_review`.
- The pre-plan `JobSettingsSnapshot`, `ParseJobRequest` and `IngestionJob` payloads are copied into the Python test as literals and validate unchanged; `exclude_defaults` dumps of them add no key.
- App side: `sidecar-docling.ts` and `buildJobSettings` drop the new fields while they hold their defaults, so the parse request body and the stored snapshot keep exactly the pre-phase key set (tested).

## Behaviour changes

- With every new field at its default: none. The docling request body and the ledger snapshot are byte-for-byte the same key sets as before.
- Pydantic now accepts `kind: translate` and `status: pending_review` on ledger jobs; the SQL check constraints are unchanged here (F-15/F-16 migrations belong to their plans).

## Deviations from Plan

1. **[Rule 1 – bug caused by this change] Wire defaults (`42992fd`).** After regeneration, `ParseJobRequestSchema.safeParse(...).data` and `JobSettingsSnapshotSchema.parse(...)` fill the new defaults, so the app would have sent `language_aware: false` etc. to the sidecar and stored them in the ledger snapshot; a sidecar deployed before this plan rejects them (extra=forbid, Pitfall 17). Added `src/lib/rag/ingest/wire-defaults.ts` and used it in `sidecar-docling.ts` and `routing/settings-snapshot.ts`; `buildJobSettings` and `EnqueueJobArgs.settings` now use the Zod input type (`JobSettingsSnapshotWire`). These three files are outside the plan's `files_modified`. Plans 14 and 21 get "send only when set" for free; a field they add to the defaults lists must also be added to the constants there.
2. **QuarantineReason as a discriminated union** rather than one flat model, so the "hidden_text with targets only is rejected on both sides" truth holds in the generated Zod too.
3. **Additions beyond the plan's field lists:** `HiddenTextReport.dropped` (plan 35 reports a dropped count), `PdfHiddenTextRules.outside_page_margin_pt` and `covered_overlap_min` (thresholds for the off-page and covered-text checks of D-33), `QuarantineSpan.page` nullable (zero-width hits in connector text have no page).
4. **`tests/test_routing_contracts.py`**: the pinned `JobStatus` count moves from 11 to 12 (intended change).
5. Python lax mode coerces `"yes"` to a bool like every existing field, so the rejection case uses `"maybe"`; the new bool fields are not made strict.
