# Phase 03.2 Plan 34: Quarantine reasons and the zero-width hidden-text check Summary

**Quarantine now carries typed reasons from separately switched checks to the admin list and release, and zero-width characters are removed before chunking.**

## Accomplishments
- `scan_injection` is a list of checks. Each one has its own switch and its own outcome. The injection rules check is unchanged. The new hidden-text check counts U+200B, U+200C, U+200D, U+2060 and U+FEFF by code point; a U+FEFF at position 0 is a byte-order mark and is not counted. The link entry is left for plan 39. No model call was added.
- `flag` mode records `metadata.hidden_text_report` and changes nothing else. `quarantine` mode strips the characters from the parse text and the parser's chunks. Below the threshold it logs one `[RAG Security]` warning with the count only. At or above the threshold it quarantines the document with a `hidden_text` reason and sets `hidden_text_check = hidden_found`. A resumed run strips the stored parse text again.
- Migration 0804 adds `rag_list_quarantine_reasons`. It is the old list plus reasons, the unlocated count, `hidden_text_check`, pending approval and the uploader. It also adds `rag_release_quarantine_reasons`, which records the released targets and stamps the approval, and `rag_list_not_checked`. The 0425 functions keep their signatures. `rag_release_quarantine` now wraps the new release. Every function is service_role only, uses `SET search_path = ''` and has one overload.
