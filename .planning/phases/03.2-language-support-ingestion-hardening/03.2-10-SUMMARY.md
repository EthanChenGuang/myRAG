# Phase 3.2 Plan 10: Registry-driven detectors and OCR mapping Summary

**The ingest language detector and its Python twin now read stopwords and languages from `config/rag/language-packs.json`. Both take an optional candidate list and return a 0..1 confidence. Every language and confident value recorded before this plan is unchanged. The Docling OCR code mapping and the default OCR language list come from the registry too, and the four 03.2-10 entries are gone from the language-literal allow-list.**

## Behaviour

- `detectLanguageWithConfidence(text, candidates?)` returns `{ language, confident, confidence }`. With no candidates it considers every registry pack, which is the same set as today. On all 33 earlier vectors, and on 5 new vectors without candidates, `language` and `confident` match the pre-plan code. The new no-candidate vectors were checked against `git show HEAD:src/lib/rag/lang/detect.ts` before they were pinned.
- **Candidates:**
  - Codes are filtered to the registry, in registry order.
  - One candidate returns `{ code, true, 1 }` without reading the text, even for empty text.
  - With no known candidates the result is `{ null, false, 0 }`.
  - If the Han-script pack is not a candidate, Han text falls through to stopword counting among the candidates.
- **Confidence:** the formula is in key-decisions. The en/it tie still returns `language: 'en', confident: false`, now with confidence 0.
- **Type change:** `DetectedLanguage` is now `string` (a registry code). Two allow-listed callers that need the literal union now narrow explicitly, so their behaviour is the same for the shipped registry:
  - `queryLanguage` in `query/language.ts`.
  - `answerGroundednessLanguage` in `generation/groundedness.ts`. A future non-zh/en/it code maps to `unknown`, and the scorer only scores en and zh-Hans anyway.
  - `EN_STOPWORDS` and `IT_STOPWORDS` are no longer exported.
- **Python twin (`rag_sidecar.ingest.lang`):**
  - Mirrors the rules and formula and keeps `import regex` local to this module.
  - `detect_language(text)` still returns `(language, confident)` for `ingest/quality.py`.
  - The new `detect_language_with_confidence` takes an optional `registry=` argument for tests.
- **Docling OCR codes:**
  - `to_ppocr_code` looks up `ocr_codes.docling.rapidocr` per registry language. A code with no pack, or a pack whose `docling` is null, passes through as before, and the PP-OCRv6 set check still applies.
  - `['zh'] → ['ch']`, `['it','zh'] → ['it']`, `['zh','it'] → ['ch']`: unchanged. Parse-cache keys are unchanged (`test_ingest_cache_keys.py` passes as is).
  - The default list when `ocr_languages` is empty or None is `list(language_codes())`, which is `['zh','en','it']` today. This applies to `convert_range`, `convert_whole` and `preset_option_dict`.
- **Detector 3 (`docling_adapter.detect_language`):** keeps its own stopword lists, the 0.3 CJK share and None on ties. Its Han code is the registry pack with script `Hani`, and its stopword lists are kept only for codes the registry lists. Its outputs are pinned on every vector without candidates, including the new ones. Detector 3 differs from detectors 1 and 2 on `en-it-tie-four` (None) and `mixed-zh-en-balanced` (en), which is the old behaviour and is pinned.
- **No new switch, env variable, migration or store.** No purge hook is needed: this plan adds no 3.2 store.
