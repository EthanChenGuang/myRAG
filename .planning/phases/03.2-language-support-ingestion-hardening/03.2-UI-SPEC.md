## 0. Findings that shape this contract (read first)

Facts from the code and from research. Each one changes what the UI can show or do.

1. **None of this phase's admin routes exists yet.** `src/app/api/rag/admin/` has no `languages`, `ingest-fingerprint`,
   `upload-approvals`, `scope-vocabulary`, `documents/[id]/scopes`, `supersession`, `effective-dates` or `translation-settings`
   route. Section 8.1 lists the fields each view needs. Field names there are **proposals to the backend plans**; the behaviour
   they support is the contract.
2. **Two design systems.** The Config UI is a static page with DaisyUI 4.4.24 over the Tailwind Play CDN and Bootstrap Icons.
   The app is Next.js with shadcn-style local components over Radix and lucide icons. Tokens are declared per surface
   (sections 2 to 5 and 13) and never mixed.
3. **The first-run picker cannot depend on an admin session.** On a new install there may be no admin, no database and no
   running app. D-08 says the picker "saves through `scripts/config-server.js`". So the pack list, the current values and the
   validation come from the config server; only the per-language document counts come from the app route and are optional
   (section 6.2).
4. **`saveConfig()` posts the whole `this.config` object** to `POST /api/config` and is called from the header button and from
   about ten auto-save handlers (`index.html` 10228 to 10724). An ingestion-side value typed into a page input would be saved
   without any count or warning. D-11 requires the count and warning before saving, so the save needs one guard (section 6.4).
5. **Not every rebuild can be started from a browser.** Chunking profiles have a build route (45-second steps). Re-embed,
   relex, recaption and retranslate are CLI commands today, and a `reparse` batch needs `RAG_INGEST_ASYNC=on` (D-11). The
   impact view therefore shows, per mechanism, either a button or the exact command; it never shows a button that cannot run.
6. **Activation already has a home for two mechanisms.** `rechunk` and `reembed` are activated by the existing pointer flips
   (D-12), which the Chunking profiles and Embedding profiles panels already own. Only a held `reparse` batch gets Activate
   and Roll back in the new panel.
7. **The Quarantine panel uses `window.confirm` and renders rule ids and snippets only.** Release now has consequences that
   differ by reason (hidden spans stay removed, link targets are recorded as reviewed, release counts as approval), so both
   confirmations move to the page's `dialog.modal` pattern.
8. **The app has one knowledge-base upload surface with a doc-type picker:** the upload queue in
   `src/components/ui/document-dashboard.tsx` (line 1442). `unified-upload-button.tsx` uploads images and temporary documents,
   which D-37 excludes. The tag picker and "Replaces…" attach to the dashboard queue row only.
9. **The app has no popover, command or badge primitive.** `src/components/ui/` provides `dropdown-menu` (with
   `DropdownMenuCheckboxItem`), `dialog`, `select`, `checkbox`, `input`, `button`, `scroll-area`. The new app controls are built
   from these; no shadcn block is added.
10. **The app's ingest status has no `pending_review`.** `LabelKey` and `TONES` in `ingest-status-labels.ts`, `TERMINAL_STATUSES`
    in `use-ingest-job-status.ts` (line 54) and in `doc-type-picker.tsx` do not know it; without the terminal entry the badge
    would poll for ten minutes.
11. **The app's UI language set is 18 languages; the two label modules carry en, zh and it only** and fall back to English.
    New app strings follow those modules. The Config UI panels pick `zh` or `it` from `navigator.language` and fall back to
    `en`.
12. **All Config UI scripts are classic scripts in one global scope** (04-UI-SPEC finding 13). Top-level names in the new
    files start with the prefixes in section 6.1.
13. **The older panels bind their init to the first `[data-tab="rag-administration"]` link only**, so the mobile drawer link
    never starts them. New panels bind every link, as the Ingestion panel does. `quarantine.js` is fixed the same way when
    it is extended.
14. **The Config UI queue item is built with a template string and `escapeHtml`** (`index.html` 14149 to 14175). The new
    queue controls are built with DOM calls and mounted into a host element; no new value goes through a template string.

## 1. Design direction (frontend-design pass)

**Subject.** The control room of a company knowledge base: which languages it speaks, which documents are being held out of
answers, why, and who lets them back in.
**Audience.** A deployment or organization admin at a desktop, who arrives with one of these questions: "which languages do
we support?", "why is this file not searchable?", "may this upload go live?", "is the 2023 policy still being used?", "what
happens to stored documents if I change this switch?". And, in the app, a member who uploads a file and needs to know it
is waiting for someone.
**Primary job.** Let the admin decide, with the evidence on screen, and say exactly what the decision changes.

**Mode.** Impeccable "Operate". These are working tools inside an existing dashboard. Sections, sub-tabs, tables, badges,
alerts and dialogs are the ones the Ingestion and Chunking profiles panels use. No new navigation, no new control type.

**Organizing idea: every held document states its reason and its way back.** Quarantined, awaiting approval, replaced, not
yet effective, not rebuilt: wherever a document is kept out of retrieval, the row carries one **hold line** in the same three
parts and order: the state (badge with icon and word), the reason (a sentence), the action that ends it (one primary
button). An admin who learns the line in Quarantine can read Upload approvals and Versions and dates without learning
anything new.

**Signature element: the inert evidence block** (section 6.5.1). Hidden text and link targets are the only attacker-written
content these screens display. They appear in one fixed form used nowhere else: a block with a 4px left rule, monospace
text, a caption that says what kind of evidence it is and where it was found, and the standing line "Shown as text. Never
a link." Nothing in the block is clickable, fetched, rendered as markup or auto-linked. The form itself tells the admin
"this is a specimen, not content". Everything around it stays plain.

**Review against generic defaults (what was changed and why).**
- Rejected a blocking first-run wizard modal. With languages unset the legacy pipelines keep answering (D-02) and an admin
  may have come for Quarantine. The first-run step is the first section of the tab and blocks nothing.
- Rejected flags for languages. A flag names a country; zh, en and it are languages. Each language is shown by its native
  name, its name in the UI language and its code.
- Rejected a stat tile per language and a "coverage" chart. The counts are three numbers; they sit in the table rows.
- Rejected a numbered stepper for "count, warn, save, rebuild, activate". Each rebuild is at its own step, so the step is that
  row's badge and its one button.
- Rejected a kanban or card wall for approvals. Pending uploads are comparable rows; a table lets twenty be read at once.
- Rejected a side-by-side text diff for older and newer versions. Chunk text never enters these screens (section 11); the
  two documents are compared by title, type and dates.
- Rejected one colour per tag dimension. Dimension is written in words; colour would be the only carrier.
- Rejected a toggle that turns red or green for the security checks. Each check is a three-value select
  (off, flag, quarantine) with a sentence that says what the value does.
- Rejected emoji, middle-dot meta strings and arrows on buttons. The Embedding profiles summary line keeps its existing
  dots; nothing new uses them.

**Quality floor (built without announcing it).** Visible keyboard focus, `prefers-reduced-motion` respected, all text at least
4.5:1, tabular numerals in number columns, usable down to 360px, every state in section 7 present, every server string
inserted with `textContent` (Config UI) or as a React text child (app).

## 4. Spacing Scale

Tailwind spacing utilities only; no arbitrary pixel values. Same scale as `03.1-36-UI-SPEC.md` and `04-UI-SPEC.md`.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `mt-1` | Icon to label inside a badge or button; a value to its second line; a field to its help line; the evidence block's left rule width |
| sm | 8px | `gap-2`, `mb-2`, `p-2` | Buttons in a row, badges side by side, heading to its description, padding inside the evidence block, gap between app queue controls |
| md | 16px | `gap-4`, `mt-4`, `mb-4`, `p-4` | Between form fields, toolbar to content, table to the line under it, padding of inline form regions, rebuild rows and candidate cards |
| lg | 24px | `gap-6`, `mt-6` | Between sibling panels (existing `grid gap-6`); between sub-blocks of one sub-view (summary, table, notes) |
| xl | 32px | `.card-body` default, `py-8` | Card padding (DaisyUI default, unchanged); vertical padding of empty-state blocks |
| 2xl | 48px | `h-12` (DaisyUI `btn` height) | Touch-size row actions below 768px |
| 3xl | 64px | not used | Reserved for page-level spacing |

Exceptions: none. No 2px, 6px, 10px or 12px spacing appears in new markup.

Component internals outside the scale (not spacing tokens, do not restyle):
- DaisyUI `table-sm` cell padding, `input-sm`, `select-sm`, `textarea-sm`, `checkbox-sm`, `radio-sm`, `btn-sm` (32px) and `btn`
  (48px) are used as shipped. Row actions are `btn md:btn-sm`: 48px tall below 768px, 32px from 768px up.
- DaisyUI `progress` is 8px tall as shipped.
- App: the two new triggers are `h-8` (32px) with `px-2` and `gap-1`, equal to the `DocTypePicker` trigger beside them. 32px
  meets the WCAG 2.2 AA target size (24px); the row's existing remove button is 24px and is not changed.
  `DropdownMenuContent` and `DialogContent` keep their shipped padding.

Sizes that are not spacing: the evidence block's `pre` is capped at `max-h-40` (160px) and scrolls; the app chooser list is
capped at `max-h-72` (288px).

## 5. Typography

### 5.1 Config UI

Exactly four sizes and two weights, the same as the sibling panels.

| Role | Size | Weight | Line height | Tailwind | Where |
|------|------|--------|-------------|----------|-------|
| Panel heading | 18px | 600 | 1.33 (`leading-7`) | `text-lg font-semibold` | The seven panel titles |
| Sub-heading | 16px | 600 | 1.5 (`leading-6`) | `text-base font-semibold` | Settings group names, dimension names, candidate titles, the banner's first line, dialog titles, empty-state titles |
| Body | 14px | 400 | 1.43 (`leading-5`) | `text-sm` | Descriptions, table cells, alert text, status messages, form labels, buttons |

Rules:
- Number columns and counts use `tabular-nums`; numbers are right-aligned in their columns.
- Description and alert paragraphs cap at `max-w-prose`.
- Native language names are written in their own script and carry `lang="<code>"` (`中文` with `lang="zh"`, `Italiano` with
  `lang="it"`), so screen readers and CJK font selection are right whatever the UI language is.
- Language codes, tag values, ids and env names use `font-mono text-xs` with `translate="no"`. The evidence block uses
  `font-mono text-xs` (section 6.5.1). Commands use `code.font-mono.text-xs.break-all`. Nothing else is monospace.
- No all-caps labels, no letter-spaced eyebrows, no label above a heading, no single emphasised word inside a heading.
- Each panel root carries `lang="<locale>"`. Text left in English inside a localized panel (unknown server messages) is
  wrapped in an element with `lang="en"`.

The order reads as a sentence: which languages, what goes in and how, what is held back, what narrows retrieval, then the
profiles. Languages is first because it is the first-run step (D-08). The tab's intro sentence becomes: "Choose languages,
manage document-type defaults, ingestion and its changes, held uploads, tags, versions and translation, and the embedding
and chunking profiles, using your existing admin session."

- **Shared helpers.** One new file, `rag-panels/rag-ui.js`, loaded after `rag-fetch.js` and before every panel of this phase. It
  holds what the six new files and `quarantine.js` share: the element builder, icon, spinner, alert, sub-tabs with arrow-key
  handling, the confirmation dialog, the evidence block (6.5.1), the hold line, the error mapper (section 8.2), the locale
  resolver and the shared label table `RAG_UI_LABELS`. The existing Ingestion, Chunking and Refusal panels keep their own
  helpers and are not refactored.
- **Global names.** Every top-level `const`, `let`, `class` and function in a file starts with that file's prefix:
  `ragUi` / `RAG_UI_`, `Languages` / `LANGUAGES_`, `IngestImpact` / `INGEST_IMPACT_`, `Quarantine` / `QUARANTINE_`,
  `UploadApprovals` / `UPLOAD_APPROVALS_`, `ScopeTags` / `SCOPE_TAGS_`, `VersionsDates` / `VERSIONS_DATES_`,
  `TranslationTargets` / `TRANSLATION_TARGETS_` (finding 12).
- **Skeleton.** `index.html` gets, per new panel, only a `section` with heading (`h3`, `tabindex="-1"`, `scroll-mt-4` on the
  section), description paragraph, one alert host, one content host and one status region
  (`div.text-sm.mt-4[role=status][aria-live=polite]`). Scripts build everything else.
- **Mount.** Each `init…Panel()` is idempotent: the first call mounts, later calls refresh and keep the selected sub-tab, open
  forms with their values and a running poll. Bind to **every** `[data-tab="rag-administration"]` element and call on
  `DOMContentLoaded` when the tab is already active (finding 13).
- **Locale.** `navigator.language` first two letters, `zh` or `it`, otherwise `en`, as the Ingestion panel resolves it.
  Document-type names come from `window.docTypeLabelForLocale`. Sign-in, network and generic-failure sentences come from
  the shared `ingestLabel` table (section 8.2).
- **Workspace.** Upload approvals, Document tags, Versions and dates and Translation targets follow `#workspace-selector`
  (the page's one workspace concept, as Ingestion and Document types do), show a 12px line "Workspace: {name}" under the
  description and reload on its `change`. Languages, Ingestion changes and Embedding profiles are deployment-wide and say
  so in their descriptions. Quarantine keeps listing every tenant the admin administers.
- **Requests.** App routes go through `ragFetch` with the full path. Config-server routes (`/api/config/…`) go through
  `fetch` with `credentials: 'same-origin'`. No `Authorization` header, nothing written to `localStorage`, `sessionStorage`
  or a cookie. Every call is wrapped in `try/catch` and has a 15-second client timeout.

### 6.4 Ingestion changes (LANG-04, D-11, D-12)

#### 6.4.1 The save guard and the impact dialog

`ingest-impact.js` exposes `window.ragBeforeConfigSave(changed)`, which returns a promise of `true` (save) or `false`.
`saveConfig()` in `index.html` computes the keys whose value differs from the last saved snapshot and awaits the guard before
its `POST /api/config`. When the guard is missing or throws, the save proceeds as today. The guard asks the impact route
(section 8.1) about the changed keys; the route, not the browser, decides which keys are ingestion-side.

| Answer of the impact call | What happens |
|---------------------------|--------------|
| No changed key is ingestion-side | Save proceeds, no dialog |
| Ingestion-side keys changed, 0 documents affected | Save proceeds, no dialog; the page toast adds `impact.none` |
| Ingestion-side keys changed, documents affected | Impact dialog |
| 401, 403, 503, network failure, timeout | Impact dialog in its "count unavailable" form (`impact.unknown` in place of the table) |

```

  impact.title                                                   16/600
  Changed settings                                               dl, one row per ingestion-side key
      Table header repetition    Follow the document type, changed to: Always
      RAG_TABLE_HEADER_REPEAT                                    code, 12px
  ┌──────────────────────────┬─────────────────────┬───────────┐
  │ Rebuild                  │ Document type       │ Documents │   caption sr-only
  ├──────────────────────────┼─────────────────────┼───────────┤
  │ Rebuild chunks           │ General             │       212 │
  │ Rebuild chunks           │ Contract & legal    │        41 │
  │ All affected documents   │                     │       253 │   last row, font-semibold
  └──────────────────────────┴─────────────────────┴───────────┘
  impact.warning                                                 14px, with bi-exclamation-triangle
  impact.security                                                only when a security check changed
  impact.fingerprintGap                                          only when documents without a fingerprint exist
```

- The dialog opens at once with a spinner and `impact.counting`; **Save settings** is disabled until the count arrives or
  fails. A changed value is written in words (`impact.change`: "{from}, changed to: {to}"), with human option labels.

## 9. Keyboard, screen reader and focus

1. **Headings.** Panel titles are `h3`; sub-headings inside a panel and card titles are `h4`. No level is skipped.
2. **Sub-tabs.** `role=tablist` with an `aria-label`; each `button[role=tab]` has `aria-selected`, `aria-controls` and a roving
   `tabindex`. Left and Right move and activate, Home and End jump. Panels are
   `div[role=tabpanel][aria-labelledby][tabindex=0]`.
3. **Languages table.** The checkbox and radio of a row are labelled with the language name. The radio group is one
   `radiogroup` named `col.primary`. A disabled checkbox's reason lines are wired with `aria-describedby`.
4. **Forms.** Every control has a visible `<label for>`; checkbox and radio groups are `fieldset` with `legend`. Help lines and
   findings are wired with `aria-describedby`; invalid fields carry `aria-invalid="true"`. Tag values and the allowlist have
   `autocomplete="off"`, `spellcheck="false"` and `translate="no"`. Enter in a text field does not submit; Escape closes an
   inline form or editor and returns focus to the button that opened it.
5. **Disabled primary buttons.** The reason is on screen and referenced by `aria-describedby` (Save languages, Confirm
   replacement, Save targets, Create tag, Add exemption).
6. **Dialogs.** Native `<dialog class="modal">` with `showModal()`, `aria-labelledby` and `aria-describedby`. Focus starts on
   the safe button (the "Keep…" one). Escape and the backdrop cancel; while a request runs they do nothing. On close, focus
   returns to the opening button, or to the status region when that button is gone. File names are inserted with
   `textContent`.
7. **Evidence blocks.** Each `pre` is a focusable scroll region (`tabindex="0"`, `role="region"`, `aria-label` = its caption).
   The line "Shown as text. Never a link." is real text, read once per reason group.
8. **Hold line.** The badge's word is text, not a `title`. Order in the DOM equals reading order: state, reason, action.
9. **Row actions** carry the file, tag or language name in their accessible name (`*.aria` keys: "Approve upload:
   handbook-2026.pdf"). There is no icon-only button in the Config UI panels. Dates use `<time datetime>`.
10. **Live regions.** One polite status region per panel. Announced: load finished with counts, action outcomes, errors,
    rebuild progress at most every 30 seconds. A refused activation and a refused language save are `role="alert"`, because
    they answer an action just taken. Warnings rendered on load have no alert role.
11. **Tables.** Visually hidden `caption`, `th scope="col"`, the file or tag cell as `th scope="row"`. A table that can scroll
    sideways sits in `div.overflow-x-auto[tabindex=0][role=region][aria-label]`.
12. **Not colour alone.** Every state, reason kind and warning has a word and an icon.
13. **Focus visibility.** DaisyUI's `focus-visible` outline on every control; `summary` elements, `pre` regions and scroll
    regions add `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2`. Never `outline: none` without
    a replacement. In the app, the shipped `focus-visible:ring-2` of `Button` and the Radix focus styles are kept.
14. **Motion.** Only DaisyUI's spinner and the browser's progress bar. Under `prefers-reduced-motion: reduce`, spinners are
    hidden (`motion-reduce:hidden`) and their text remains. Nothing slides, fades or pulses. The app's hourglass is static.
15. **App chooser.** `role="radiogroup"` with roving `tabindex`; Up and Down move, Space or Enter selects, Escape closes and
    returns focus to the "Replaces…" trigger. The search field is labelled and focused on open.
16. **App tag menu.** Radix handles arrow keys, type-ahead and Escape; `DropdownMenuCheckboxItem` exposes `aria-checked`. The
    trigger's name includes the file name and the count.
17. **Zoom and text size.** At 200% zoom nothing clips: no fixed heights except the capped scroll regions; cells, toolbars
    and button rows wrap.
18. **Language.** `lang` on each panel root; native language names carry their own `lang`; text left in English carries
    `lang="en"`.

## 11. What must never be shown or done

1. **Evidence is inert** (6.5.1). Hidden spans, rule snippets, link targets and date quotes are never an `<a>`, never an
   `href`, `src` or `title` value, never passed to `window.open`, `fetch`, an image or an embed, and never auto-linked. No
   panel requests, resolves or previews a target (D-35, D-50, research anti-patterns).
2. **Every server string** (file names, uploader names, tag labels and aliases, reasons, codes, `details[].message`) is
   inserted with `textContent` in the Config UI and as a React text child in the app; never `innerHTML`, never
   `dangerouslySetInnerHTML`, never a template string that becomes markup. Tests stub each of them with
   `<img src=x onerror=alert(1)>` and assert that no element is created.
3. **No document text** beyond the evidence these checks produce: no chunk text, parse text, translation text, caption text
   or page image appears in any panel, and the panels call no route that returns one.
4. **Views render named fields only,** through builder functions, never by iterating an object's keys. A field the server
   adds later stays invisible until it is added here on purpose.
5. Never rendered even when a response carries it: bounding boxes, checker versions, fingerprint hashes and their parts,
   similarity or overlap scores of a candidate, raw `signals` objects, batch and run ids, tenant keys other than the
   existing Quarantine "Workspace" value, user ids when a display name exists, model names of the translation or
   suggestion call, cost figures.
6. No value of a variable whose name matches `/(KEY|SECRET|TOKEN|PASSWORD)/i` is read or rendered by any new script.
7. No `Authorization` header, no token in browser storage, no second sign-in form.
8. **Nothing is logged** to the console from evidence, targets, file names or uploader names; panel logs carry counts and
   codes only (D-51).
9. A suggestion (tag or date) is never applied without an explicit admin action, and the UI never pre-ticks a suggested tag.
10. The app never shows a member who approved or rejected their upload, and shows no reason for a rejection.

## 12. Copywriting Contract

Voice: plain verbs, sentence case, names from the admin's side of the screen. A message that reports a problem says what
happened and what to do next; errors do not apologize. One action keeps one name through its flow: the row button, the
dialog's confirm button and the outcome message say "Approve upload", "Approve upload", "is approved". "Reload panel" always
means reloading a view.

**Words used, and words avoided.** "Supported languages" and "primary language" (the env names appear only in `code`).
"Held out of answers" for any document retrieval skips; "searchable" for the opposite. "Quarantine" as today. "Awaiting
approval" for `pending_review` (in zh "等待批准", never "待审核", which the Ingestion panel already uses for `needs_review`).
"Tags" with the dimension names "Region", "Legal entity", "Department"; the word "scope" is not shown. "Replaces" and
"replacement" for supersession; "supersede" is not shown. "Rebuild" for every side-by-side mechanism; the mechanism names
(`rechunk`, `relex` and so on) appear only as the human labels of 12.3. "Fingerprint" appears only in the one sentence that
names the backfill command. "Hidden text" and "link targets" for the evidence; "span" is not shown.

**Action labels are verb + noun in every locale.** Accessible names extend the visible label and start with the same verb
("Approve upload: {file}"). In-flight text ("Approving…") is status on a disabled button, not a label. Not actions, so not
verb + noun: sub-tab names, filter radios, select options. "Replaces…" keeps the wording D-41 fixes.

**Counts are written as "label: number"** ("Pending: 3", "Documents: 132"), so no string needs a plural form in en, zh or it.

**Where the strings live.** One `{ en, zh, it }` table per file (`RAG_UI_LABELS`, `LANGUAGES_LABELS`, `INGEST_IMPACT_LABELS`,
`QUARANTINE_LABELS`, `UPLOAD_APPROVALS_LABELS`, `SCOPE_TAGS_LABELS`, `VERSIONS_DATES_LABELS`, `TRANSLATION_TARGETS_LABELS`), read
through one function per file that fills `{placeholders}` and falls back to English. Sign-in, network and generic-failure
sentences are not copied; they come from the shared `ingestLabel` table. Document-type names come from
`docTypeLabelForLocale`. A placeholder shown as `{command}` or `{variable}` is replaced by a `code` element, not by text.
Numbers use `Intl.NumberFormat(locale)`; dates `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`; ISO dates the admin
edits stay `YYYY-MM-DD`. App strings live in `scope-tag-labels.ts`, `replaces-labels.ts` and `ingest-status-labels.ts` in the
`doc-type-labels.ts` shape; these modules take their locale type from wherever the D-06 conversion leaves it and declare no
new `zh | en | it` union.
