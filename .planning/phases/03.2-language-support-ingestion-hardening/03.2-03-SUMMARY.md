## What changed

- **Defaults (D-47):** RAG_SUPPORTED_LANGUAGES and RAG_PRIMARY_LANGUAGE are empty. The other defaults are LANGUAGE_AWARE_INGEST off, TABLE_HEADER_REPEAT profile, TABLE_ROW_SERIALIZATION false, CAPTION_LANGUAGE en, BGE_M3_SERVING hosted, DOC_TRANSLATION off, DOC_TRANSLATION_MODEL empty, HIDDEN_TEXT_CHECK off, INGEST_LINK_CHECK off, OUTPUT_LINK_ALLOWLIST empty, UPLOAD_APPROVAL off, SCOPE_TAGS false, SCOPE_TAG_SUGGEST false, SUPERSESSION_DETECT off, EFFECTIVE_DATES false and EFFECTIVE_DATE_LLM_EXTRACT false.
- **Typed config:** the values come from closed sets. An unknown value falls back to the default and logs one warning that names the variable. It never throws. `true`/`false` switches accept only those two words, in any case.
- **D-01:** the two language variables are mirrored only in `src/lib/env.ts`. They are not in IngestEnvInput or RagEnvInput, and nothing under `src/` reads them yet. A test checks that no parsed config field carries them.
- **All-off parity (D-46):** a test checks that the pre-existing fields of both config objects deep-equal a literal snapshot of the values before this plan.
- **Config UI:** `#rag-phase032-settings` (class `hidden`) holds eight `data-rag-settings-group` divs. Each control's id and name equal its env name and each option value equals its env value. Option text, labels and help come from UI-SPEC 12.9, with `data-rag-i18n` keys for zh and it. The two language inputs are `input[type=hidden]`. The allowlist is a textarea with autocomplete, spellcheck and translate off. Exactly the ten ingestion-side controls end their help with `settings.affectsStored`. The block adds no script.

## Deviations

1. **[Rule 3 - blocking] `src/lib/rag/ingest/deps.ts` and `src/lib/rag/deps.ts` (not in files_modified):** `ingestEnv()` and `readRagEnvInput()` build the env snapshot that the loaders read. Without the new names in them, the typed fields would always read their defaults at runtime.
2. **[Rule 3 - blocking] `eval/harness/eval-env.mts` (not in files_modified):** the pin is derived from `scripts/init-env.js` and checked by `eval-env --check`. A hand-edited `zh,en,it` would fail the existing equality test, so the derivation now overrides the two language values (D-02), and the JSON was regenerated with `--write`.
3. **[Rule 1] `tests/rag/ingest/config.test.ts`:** its full `DEFAULTS: IngestConfig` literal gained the new fields. The pre-existing values are unchanged.
4. **Transient:** after commit 7400c66 and until 6808dcb, `tests/eval-env-pin.test.ts` failed because init-env had new defaults and the pin did not yet. Task 3 fixed it.
5. **Markup:** help lines use `div.label` instead of the analog's bare `<label class="label">`, because a label with no associated control is not valid. Selects carry no `translate="no"`, because their option text is now human copy; the env name sits in `code[translate=no]`.
