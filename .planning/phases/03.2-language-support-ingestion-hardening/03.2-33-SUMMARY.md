# Phase 3.2 Plan 33: Captions in the document language and the recaption mode Summary

**With `RAG_CAPTION_LANGUAGE=document`, picture captions are asked for in the document's language (else the tenant's largest language share, else the primary language) and each caption chunk is stored with the language detected on the caption actually written. `npm run rag:reembed -- --recaption` rewrites existing captions in another language from the stored image, with a dry run, a cursor, resume and rollback. With the default `en`, the prompt and every written row are unchanged.**

## Behaviour

- **Prompt (D-23).** `captionPromptFor(code)` returns `IMAGE_CAPTION_PROMPT` for no target or an unknown code, otherwise the pinned prompt, one space and one sentence built only from the registry `native_name` (中文, English, Italiano). `captionImage` sends `captionPromptFor(options.targetLanguage)`. Callers pass a target only with the switch at `document`, so with `en` the vision call carries the pinned prompt byte for byte; the existing prompt-pin test is unchanged and passes.
- **Target order.** `resolveCaptionLanguage`: the document's language when it is one of `RAG_SUPPORTED_LANGUAGES`; else the configured language with the largest share from `rag_tenant_language_shares` (ties in registry order; shares outside the configured set are ignored); else `RAG_PRIMARY_LANGUAGE`. A failed share lookup logs one `[Ingest]` warning and falls to the primary language; the stage does not fail. With the languages unset it returns no target, the pinned prompt is used, and one `[Ingest]` warning per process names `RAG_CAPTION_LANGUAGE`.
- **Once per run.** `captionTargetForRun(ctx, documentText)` caches the target on `ctx.work.captionTarget`, so a run reads the shares at most once. The document language is detected on the parse text among the configured languages, as the enrich stage does; a picture upload has no text and goes to the shares.
- **Both callers.** The unified `images` stage (picture documents and pictures inside documents) and the parse-external native mode (`callbacks/native.ts`) use the same resolver.
- **Stored language.** Under `document`, each image draft gets `language` and `metadata.caption_language` detected on the caption as written (an English answer to a zh request is stored as `en`). A picture document's document language is that language (as today, now detected among the configured languages). For pictures inside a document, the write stage calls `rag_set_image_chunk_languages` after the chunks are written, which sets `document_chunks.language` and `metadata.language` of the version's image chunks by image URL. Visible text is quoted as returned: no transliteration or accent stripping happens anywhere on the path.
- **Empty caption.** As today: a picture upload fails with `caption_empty` and writes no chunk; a picture inside a document is skipped with a warning and no image chunk or language call is made.
- **Recaption (D-24).** `rag:reembed -- --recaption [--tenant <key>] [--dry-run]`:
  - needs `RAG_CAPTION_LANGUAGE=document` and configured languages, otherwise exits 2 with a message naming the variable;
  - selects current ready image chunks with `metadata.image_url` whose caption language (detected on the caption text) differs from the target (picture documents resolve without a document language, as at ingest);
  - dry run: per tenant the image chunks and those to recaption, and an estimated cost (vision at about 0.005 USD per image plus embedding tokens of the current caption for every profile the chunk holds, priced with the registry table); writes nothing, no run row;
  - run: reads the picture from the project's own public storage only (same origin as `NEXT_PUBLIC_SUPABASE_URL`, path under `/storage/v1/object/public/`, no redirects, 30 s timeout, 10 MB cap), captions with the target, embeds for every profile that holds a vector of the chunk, and calls `rag_recaption_write_chunk` once per chunk: one transaction rewrites content, content_hash, lexical_text, language, metadata (`previous_caption`, `caption_language`, `recaption_run_id`), the legacy vector and the chunk_embeddings rows, and moves the cursor. The database refuses a write that does not name exactly the profiles holding a vector, a chunk outside the run tenant, or wrong dimensions. Zero parser calls (asserted with counting parsers);
  - `--recaption --resume <runId>` continues from the cursor; `--recaption --rollback <runId>` restores every chunk that still carries the run id from the stored previous state (refused while the run was active in the last 10 minutes).

## Purge hooks

Added `rag_purge_hook_recaption(p_tenant_key text, p_lineage_id uuid, p_document_ids uuid[])` (service_role only, `SET search_path = ''`, tenant asserted): it removes the `rag_recaption_items` rows (previous caption text and vectors) of the given documents and of every version of the lineage in that tenant. `rag_recaption_runs` holds no document data. Items also go by cascade when their chunk is deleted.

## Deviations

1. **[Rule 2, security] Own recaption ledger instead of `embedding_backfill_runs`.** D-24 names the `embedding_backfill_runs` cursor. A recaption row there would be visible to `rag_reembed_resume_run` (which moves a non-active profile to `backfilling`) and `rag_reembed_rollback_run` (which deletes every vector of the run's profile embedded in the run window), and those functions may not be redefined here. `rag_recaption_runs` has the same cursor, counts, status and resume/rollback semantics; a recaption run id given to the plain `--rollback` is simply not found.
2. **Migration number 0813.** 0801–0811 are assigned to other plans (PLAN-INDEX) and 0812 went to 03.2-22, so the orchestrator renumbered this file from 0812 to 0813 at merge time; 0813 is in the 0812–0839 gap-closure block. Plan 65 (live push of 0801–0810) does not cover it: the operator pushes 0813 after 0801–0810.
3. **[Rule 2] Image chunk language setter in SQL.** The chunk writers copy the document language onto every chunk, so a caption language different from the document's could not be stored. Rather than redefining `rag_write_chunks` / `rag_write_profile_chunks` (which plan 22 may also touch), 0813 adds the narrow `rag_set_image_chunk_languages`, called by the write stage only when a draft carries a caption language. A later `rag_set_document_fields` call naming language, doc_type, doc_date, parser_used or status copies the document language back onto all chunks (0801 behaviour); `metadata.caption_language` survives that, and recaption detects the language on the caption text anyway.
4. **Rollback restores stored vectors** rather than re-embedding `metadata.previous_caption`; `previous_caption` is still kept on the chunk as specified.
5. **Extra files:** `stages/embed-write.ts` (the setter call), `types.ts` (two optional fields), `writer.ts` (two optional writer methods), `tests/helpers/ingest-fakes.ts` (answers for the two new RPCs), `tests/rag/ingest/parse-external.test.ts` (native caller case).
6. **Plan's `npm run typecheck:new`** was run (0 errors) besides the full tsc gate.
