# Phase 3.2 Plan 36: Word hidden-text checker Summary

**The sidecar now finds vanished runs, white or near-background text, tiny text, comments and tracked deletions in Word files through `POST /v1/hidden-text`, refuses zip bombs and entity files with `unsafe_package`, and ships both checkers in the new `hidden-text` extra.**

## Accomplishments

- `security/docx_checks.py`: opens the package with `zipfile` and checks the central directory first (member count, each declared uncompressed size, their sum, encrypted-member flag), then reads only the parts reached through internal relationships from `_rels/.rels` and `word/_rels/document.xml.rels` (styles, headers, footers, footnotes, endnotes, comments). External relationships and targets with a scheme or escaping the package are skipped; nothing is fetched. Every part is parsed with defusedxml with DTDs, entities and external references forbidden. The walk handles tables, cells, `w:del`/`w:moveFrom`, text boxes inside runs and `mc:AlternateContent` (first choice only, so content is not counted twice).
- `hidden_text.py`: dispatches the Word MIME type to the checker (lazy import, so a missing extra is `CheckerUnavailable` → 503); `UnsafePackage` added. `router.py` maps it to 422 `unsafe_package`.
- `pyproject.toml`: extra `hidden-text = [pypdfium2==5.15.2, pdfplumber==0.11.11, python-docx==1.2.0, lxml==6.1.3, defusedxml==0.7.1]`. Dockerfile: `--extra hidden-text` on both `uv sync` lines of the `docling` and `runtime` stages.
- Generator: 6 hidden fixtures (hidden-run, white-text, tiny-size in it, comments in zh, tracked-deletion, vanish-by-style with a local override run) and 3 clean ones (plain; styled: coloured heading, character style, dark header cell with white text, white text in a cell shaded only by the table style's first-row fill, grey-shaded paragraph, 7 pt superscript, 8 pt small print, white text on dark run shading, highlight, an external hyperlink relationship; empty). Hostile packages (too many members, oversized member, oversized package, entity expansion) are built in memory by the tests and never written to the fixture folder.

## Known limit

When a cell's only background comes from a table style, which fill lands on which cell depends on conditional formatting (first row, banding) that the checker does not resolve; it then flags near-background text only if the text is near the page background and every fill the style defines. White text placed in a table whose style paints at least one dark fill somewhere is therefore not reported. Direct cell, paragraph and run shading are resolved exactly.
