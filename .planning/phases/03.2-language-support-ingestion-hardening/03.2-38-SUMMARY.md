# Phase 03.2 Plan 38: Hidden-text check on the queued path, and the sidecar guard in the config server. Summary

**With tiered routing, the sidecar worker checks the original for hidden text during preflight and sends the report to the app with the advance calls. The app's scan stage uses that report and does not call the sidecar a second time, so a queued document ends in the same state as an inline one. The config server also refuses to save `quarantine` mode when no sidecar is configured.**

## Task commits

1. `dfd1167` feat: the worker hook, the `AdvanceRequest.hidden_text_report` contract field (regenerated), the advance and scan wiring, the snapshot field, the stricter-of mode and the tests (Task 1).
2. `ec44112` feat: the config-server guard `hidden_text_needs_sidecar` and its node test (Task 2).
3. SUMMARY (this commit).

## Behaviour changes

- **`RAG_HIDDEN_TEXT_CHECK=off` (the default): nothing changes.** The snapshot has no `hidden_text_check` key and the worker runs no check. The advance body has no new key, and ledger rows and cache keys are identical to today. Tested in the sidecar suite and by `defaults-equal-phase3` in the full e2e run.
- **`flag` or `quarantine` with tiered routing.** The worker checks PDF and Word originals and the app makes no `/v1/hidden-text` call. A checker failure under `quarantine` fails the job before anything is handed to the app (D-34, fail closed).
- **Queued jobs (fixed or tiered).** The snapshot now records `hidden_text_check` when it is not `off`. A job runs under the stricter of the variable and its snapshot.
- **Config server.** `POST /api/config` answers 400 `hidden_text_needs_sidecar` for a save that would leave `quarantine` with an empty `RAG_SIDECAR_URL` or `RAG_SIDECAR_SECRET`.

## Deviations from plan

1. **[Rule 3] Files outside `files_modified`:**
   - `contracts/queue.py` plus the regenerated `AdvanceRequest.schema.json` and `contracts.generated.ts`. The advance contract had no free-form field, which is the case the plan allowed for.
   - `tiered.py` and `progressive.py`. The preflight runs in `tiered.py`, and the provisional progressive run also publishes a version, so it carries the report too.
   - `scan-injection.ts`, `types.ts`, `queued-context.ts`, `settings-snapshot.ts`, `enqueue.ts` and `backfill/run.ts`. These consume the report and write the snapshot field.
   - The unit tests were added to the existing `scan-three-checks.test.ts` and `settings-snapshot.test.ts`.
2. **Changed function.** `requestHiddenTextReport` is unchanged. The scan stage reads `ctx.workerHiddenText` before it would call the client, which gives the same result: no network call.
3. **Inline comparison.** The queued e2e runs an inline baseline of the same file in the same harness and compares the parsed `QuarantineReason` lists. It does not compare against a run from plan 37's own suite. Both checker versions are `hidden-text/1/2026-11-25.1`, so the reasons are equal, checker version included.
4. **Shared constants.** The app has no shared constant for the sidecar variable names, only `env.RAG_SIDECAR_URL` and `env.RAG_SIDECAR_SECRET`. The config server names them in one constant that points at the app's client.

## Threat model

- **T-03.2-381.** The callback stays behind the shared secret. A schema-invalid report is refused with 400 and nothing runs. An inconsistent report is treated as checker-unavailable (unit test). A report for another original is ignored.
- **T-03.2-382.** The snapshot carries the mode. The worker is tested with the check on and off, the queued and inline runs are tested for equality, and the stricter-of rule stops a later relaxation from skipping the check.
- **T-03.2-SC.** Nothing was installed or re-locked.

## Purge hooks

No table or store was added: the report travels only in the request and in the existing run state. So there is no `rag_purge_hook_*` and no `rag_purge_store_inventory()` registration.

## Operator actions

- Deploy order: the app first, then the sidecar. An older app's strict `AdvanceRequestSchema` rejects a body with `hidden_text_report`. A job snapshot with `hidden_text_check` already needed a sidecar from plan 05 or later.
- Under tiered routing the worker image needs the `preflight` extra (pdfplumber and pypdfium2), which tiered PDF routing already requires.
- A live check against a real sidecar and app was not run here; it is an operator action.

## Decisions for STATE

- The queued hidden-text mode is the stricter of the variable and the job snapshot.
- The worker's hidden-text report is passed in `AdvanceRequest.hidden_text_report`, not stored in the ledger.
