# Phase 03.2 Plan 44: Supersession candidates and lineage links Summary

**An older version uploaded as a different file is retired only by an admin's confirmation, and publish keeps a retired lineage retired until an admin decides otherwise.**

## Accomplishments
- Migration 0806 adds the candidates and links tables plus raise, confirm, dismiss, undo, list and a purge hook. Every function is service_role only with `SET search_path = ''`. The definer functions resolve tenant access through `rag_upload_approval_keys`.
- `rag_publish_document_version` now starts from the 0803 body. The quarantined, pending_review and held branches still return first. After the lineage advisory lock it checks for a confirmed link. A version of a retired lineage then returns `superseded_lineage`, stays non-current and raises one pending candidate.
- `rag_approve_upload` starts from the 0803 body and treats `superseded_lineage` as a completed decision.
- 46 PGlite tests (22 per mode plus 2 file checks), covering both deployment modes and two tenants.
