## Conflicts between prior decisions and how they were resolved

1. **CHK-06 ("always repeats") against the switch rule and success criterion 7.** Resolved with `RAG_TABLE_HEADER_REPEAT`, default `profile`; the default flip is ADM-02's (D-19).
2. **SEC-08 uses `RAG_OUTPUT_LINK_ALLOWLIST`, which SEC-06 (Phase 5.2) introduces later.** The variable and parser are defined here and reused by 5.2; ingestion gets its own switch (D-35).
3. **Phase 3 D-03 (legacy writers byte for byte) against LANG-06 and the DATA-05 delta (fix the legacy routes).** Legacy stays identical while the languages are unset or the switch is off; with it on, uploads go through the unified path (D-16).
4. **Phase 3 D-22 (OCR languages from the profile) against LANG-01 (from the supported set).** The supported set wins when configured; the profile field is the fallback (D-17).
5. **LANG-01 "refuses to start" against Phase 3 D-37 (never crash the app).** Refusal is per request with a startup log (D-02).
6. **XLG-04 applies the XLG-05 glossary, which is Phase 6.2.** A seam that returns nothing until then (D-29).
7. **Criterion 7 (native review) against existing gated zh/it synthetic items.** Existing items keep counting; a backlog report is produced (D-45).
8. **Phase-prefixed migration numbers against function replacement order.** `08xx` block (D-48).

## Owner decisions after the auto pass (2026-11-25)

- **D-02 unset languages:** the owner chose the fallback over refusal. With languages and pipelines unset, legacy is served with one startup log and a Config UI banner; only an explicit `RAG_PIPELINE=v2` or `RAG_INGEST_PIPELINE=unified` without languages fails with `languages_not_configured`. Reason: an upgraded deployment must keep answering; this matches DFLT-04.
- **D-19 header repetition default:** the owner chose to flip the default to `always` inside Phase 3.2 once the `table_split` eval gate passes, instead of leaving it to ADM-02 in Phase 7. Reason: the Q9 failure (headers lost in `general` documents) should not wait several phases, while the eval gate keeps the change proven.
