## Behaviour

**Panel (follows `#workspace-selector`, `organizationId` on every call, "Workspace: {name}" line).** Sub-tabs Vocabulary (default), "Documents with suggestions: {count}" (from `suggested_total`) and Settings. The three dimensions are written in words in the fixed order Region, Legal entity, Department; colour never carries the dimension or state alone.

**Vocabulary.**
- One `h4` and table per dimension: Label (row header), Value (`code.font-mono`, `translate="no"`), Other names, State badge (`bi-check-circle` In use / `bi-archive` Retired), Actions. A dimension without tags shows `vocab.emptyDimension`; an empty vocabulary shows `vocab.empty.*`.
- New tag opens an inline form: Dimension select, Label, Value (suggested from the label as a slug until edited; `autocomplete="off" spellcheck="false" translate="no"`), Other names. Create tag stays disabled until the label is present and the value matches the contract's slug rule; the findings line (`vocab.needLabel` / `vocab.badValue`) is wired by `aria-describedby`. A 409 `tag_exists` marks the Value field `aria-invalid` with `error.tagExists` and focuses it. Escape closes the form.
- Edit tag turns Label and Other names into inputs; the value is never an input. Save tag sends `PATCH {id, label, aliases}`.
- Retire tag asks for confirmation (`ragUiConfirmDialog`, primary tone, focus on "Keep tag in use") and sends `{id, active:false}`. A retired row offers Restore tag (no dialog). There is no delete control.

**Documents.** Filter radios (With suggestions default, Untagged, All), a Tag select (every value, retired ones marked), and a file-name search (Enter or 400 ms). Rows show file, document type (hidden below 1024 px), tags as "Dimension: Label" lines (an unknown value as its code), suggested tags with the Suggested badge and their source ("Found by a rule" / "Found by a model"). 50 rows, then Load more documents. A filter with no result shows `docs.empty` in place of the rows.
- Edit tags opens a full-width editor row: one `fieldset` + `legend` per dimension, checkboxes over active values (plus any retired or unknown value the document already carries, checked, so saving never drops it silently) in a `max-h-72` focusable scroll region. Suggestions sit in the dimension's fieldset, unticked, with Add suggested tag (ticks the box only) and Dismiss suggestion. Save tags sends the full sorted set with `PUT documents/{id}/scopes`. A 400 `unknown_scope_value` reloads the vocabulary, unticks values that no longer exist and shows `error.unknownTag` at the affected dimension.

**Settings.** The `scopes` group (`RAG_SCOPE_TAGS`, `RAG_SCOPE_TAG_SUGGEST`) moves in, localized through `data-rag-i18n`. Warnings in the alert host, recomputed on change of the four inputs: `warn.suggestNeedsTags`, `warn.datesNeedV2`, and `warn.needsUnified` (UI-SPEC 6.3 lists `RAG_SCOPE_TAGS=true` for it too).

**States.** First load spinner, refresh dims with `aria-busy`, 401/403 sign-in alert in place of the data views (Settings stays usable), 403 Forbidden workspace sentence, 503/network unavailable alert with Reload panel, 404 `Not found` (switch off) shows `tags.off` with "Open tag settings" in both data sub-views, 404 on an action reloads with `error.changed`.

**Upload queue (Document Processing).**
- `createQueueItemHTML` emits `<div data-queue-extras="{id}">` only when the picker-defaults answer has `tags.enabled` or `replaces.enabled`; with both off the markup is byte-identical to before (tested).
- `scopeTagsMountQueueControls` fills each host with DOM calls: a `details.dropdown` tag control (trigger "Tags: {count}" plus a screen-reader "(for {file})", one fieldset per dimension, `max-h-72` scroll, Escape and outside click close it) and a "Replaces…" button that opens a native dialog chooser (search field focused, `ul[role=radiogroup]` of the workspace's current documents with Up/Down and Space/Enter, Choose document disabled until a pick, Close chooser changes nothing). A choice shows "Replaces: {name}" and Clear replacement.
- `scopeTagsAppendUploadFields` adds `scopes` (one per tag, only values of the current vocabulary, at most 20, sorted) and `replaces_document_id` only when the control is enabled and a value is chosen.
- Upload refusals `unknown_scope_value` (also reloads the picker defaults), `too_many_scopes`, `replaces_not_found` and `replaces_same_lineage` are shown as sentences instead of the bare code.
- The copy never describes tags as permissions or access control (tested in en, zh and it).

## Deviations

1. **[Rule 3] `doc-types.js` changed** (not in files_modified): `fetchUploadPickerDefault` returned only `enabled`, `docType` and `origin`, so the queue could not know whether tags or Replaces were enabled. It now passes the `tags` and `replaces` objects through; `scope-tags.js` validates them.
2. **Dismiss suggestion is client-side only.** UI-SPEC 6.7 says a dismissed suggestion is removed on save, but no route writes suggestions (PUT scopes takes only `scopes`; suggestions live in `documents.metadata.scope_suggestions`). Dismiss hides the suggestion for that edit and the status line says it stays stored and returns after a reload. Deferred: a backend write that clears dismissed suggestions.
3. **"Replaces…" document list.** The Config UI user is an admin, so the chooser lists the workspace's current documents through `GET /api/rag/admin/documents?filter=all&q=`. That route answers 404 while `RAG_SCOPE_TAGS=false`; the chooser then searches by file name through `GET /api/rag/admin/effective-dates?query=` and asks the admin to type part of a name first.
4. **Retired and unknown values the document carries** are offered checked in the editor so that a save does not drop them without the admin unticking them (the spec lists active values only).
5. **Added `warn.needsUnified`** to the Settings warnings next to the two the plan names, because UI-SPEC 6.3 shows it for `RAG_SCOPE_TAGS=true`.
6. **Extra files**: the test harness `tests/ui/helpers/scope-tags-harness.ts`, a binding row in `config-rag-panel-binding.test.ts` and an XSS row in `config-ui-xss-scripts.test.ts`.
