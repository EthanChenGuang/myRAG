# Phase 3.2 Plan 58: Quarantine panel with reasons, inert evidence, Checks and Not checked

**The admin now sees why each document is held, with the hidden text and link targets shown as plain text that is never a link, and releases it from a dialog that says what release will do. The checks, the allowlist and the list of unchecked documents sit in the same panel.**

## Behaviour

**Quarantined (UI-SPEC 6.5.2).**
- One card per held document:
  - the file name;
  - one hold line: the "Quarantined" badge with its icon, "Held out of answers: {reasons}." and the Release document button;
  - a meta line: Workspace (the tenant key, as before), Source, Version, Uploaded by (display name, or the id in monospace), and the quarantine time.
- One reason group per kind, in the fixed order injection_rule, hidden_text, untrusted_link, invoice_extraction. An unknown kind follows the known ones, with its code in monospace inside a full sentence.
- Each group has a kind badge and icon, a detail sentence, the line "Shown as text. Never a link." once, then the evidence:
  - rule snippets and hidden spans each go in a `ragUiEvidence` block. The caption is the span reason label plus the page, for example "Very small text, page 3".
  - link targets are a `ul` of `code` elements in the same figure shape.
- At most 5 spans or snippets and 10 targets show directly. The rest sit behind "Show all: {count}".
- An item written before this phase has no `reasons`. Its rule ids and snippets render as an injection_rule reason.
- When `unlocated` is above zero, the card and the release dialog both show `release.unlocated`.
- Release document opens `dialog.modal` with Keep in quarantine focused. The body lists the consequences for the reasons present: searchable at once, hidden text stays removed, link targets recorded as reviewed, rules recorded as reviewed, and, with `pending_approval`, that release approves the upload.
- Delete document opens the error-coloured dialog with Keep document focused.
- A 404, or a 409 such as `not_quarantined`, shows `error.changed` and reloads the list. `window.confirm` is no longer used.
- The list pages by 50 with Load more documents. Loading, refresh, sign-in, workspace, unavailable and empty states follow UI-SPEC 7.1.
- Bounding boxes, checker versions and other keys the server adds are never rendered. View models read named fields only.

**Not checked (6.5.3).** Read-only.
- The description sentence, then a table of File, Document type (`docTypeLabelForLocale`), Source and Uploaded, paged by 50.
- With no rows it shows `notChecked.empty`.
- While `#RAG_HIDDEN_TEXT_CHECK` is off it shows `notChecked.off` instead of the table. The view re-renders when the select changes.

**Checks (6.3, 6.5.4).**
- The `security` settings group moves in from `#rag-phase032-settings`, so the ids, the page load and "Save All Changes" keep working.
- zh and it come through `data-rag-i18n`.
- Above the group, a read-only mirror of `#RAG_INJECTION_SCAN` shows the value, its effect, "Set under RAG Modes." and the env name.
- Each select's effect sentence ("What it does now") follows its value on `change`, before saving.
- The allowlist textarea shows the saved comma-separated value one domain per line.
- Each line is checked in the browser: a host name with at least one dot, and no scheme, path, port, wildcard or space. Case and duplicates are normalized silently.
  - Each invalid line is listed with the line in `code`.
  - The field gets `aria-invalid` and `aria-describedby` points at the list.
- The save guard wraps `window.ragIngestImpactGuard`:
  - An invalid allowlist refuses the save. It opens Checks and puts `allowlist.refused` in the status region and in a toast.
  - A valid list is written comma-separated before the impact check. The saved value is normalized the same way, so the impact check does not count reformatting as a change.
- `allowlist.own` shows the host of `NEXT_PUBLIC_SITE_URL`.
- `warn.emptyAllowlist` shows while the link check is quarantine and the list is empty.
- A 400 `hidden_text_needs_sidecar` from `POST /api/config` reaches the panel through `rag:config-save-rejected`. The sentence appears under the hidden-text select, with `aria-invalid` and `aria-describedby`. It clears when the select changes.
- Rescan: the panel reads the `rescan` row of `GET /api/rag/admin/ingest-fingerprint`.
  - `start: ui` shows Rescan existing documents. It opens a confirmation with the count and Keep documents as they are focused, then posts `{ mechanism: 'rescan' }` to the rebuild route.
  - Any other `start` shows the command exactly as the server sends it. Today that is always the case: the rescan is CLI-only (03.2-40).

**Mount.** `initQuarantinePanel` is idempotent. It is bound once to every `[data-tab="rag-administration"]` link, desktop and mobile drawer, and runs on DOMContentLoaded when the tab is already active.

Off-state: nothing changes in the app or its routes. The panel only reads existing admin routes. The rebuild POST is sent only when the server declares `start: ui`.

## Deviations from Plan

1. **`index.html` edited (7 lines in `saveConfig`).**
   - The plan said `index.html` is not edited. But `saveConfig` discarded the 400 body, so nothing could show `hidden_text_needs_sidecar` at the select.
   - On a refused save it now dispatches `rag:config-save-rejected` with the status and body. The existing toast and indicators are unchanged.
2. **Allowlist refusal through the impact guard.**
   - "The save is refused" is implemented by wrapping `window.ragIngestImpactGuard`, the one pre-save hook `saveConfig` has.
   - The wrapper is flagged, idempotent, and installed at load and at DOMContentLoaded, so it also wraps a guard assigned later.
3. **`tests/ui/config-rag-panel-binding.test.ts`.** Added the quarantine row so the every-link binding is enforced with the other panels.
4. **Checks layout.**
   - The moved form controls keep their own labels and help lines. The "What it does now" sentence is the first part of each help line and updates on change. The injection-rule row is a read-only block above them.
   - The UI-SPEC sketch shows a three-column table. Moving the selects into table cells would have split each label from its control.
5. **Copy keys beyond UI-SPEC 12.4**, all in en, zh and it:
   - `panel.*`, `tabs.label` and `hold.kind.*`, which the hold sentence needs to name the reasons in running text;
   - `reason.invoice`, `span.unknown`, `meta.none` and `list.loaded`;
   - the `notChecked` loading, unavailable and caption keys, and `col.*`;
   - `check.rules.*` (the spec gives none for `RAG_INJECTION_SCAN`) and `check.unknown`;
   - `allowlist.refused`, the `warn.emptyAllowlist` sentence, `rescan.cli`, `rescan.loading`, `rescan.unavailable`, the running texts, and the settings option and `settings.affectsStored` texts used for `data-rag-i18n`.

   `warn.emptyAllowlist` is named in UI-SPEC 6.3 without copy.
6. **Hold-line badge colour.** The badge keeps a warning border and icon with `base-content` text, as the Languages, Ingestion changes and Upload approvals panels do, because outline warning text is below 4.5:1 on the light theme.

## Decisions for STATE

- Panels that need to refuse a page-wide save wrap `window.ragIngestImpactGuard` (flagged, idempotent) rather than editing `saveConfig`. A refused save is announced as `rag:config-save-rejected` on `document`.
- The quarantine evidence figures add `!block`, because DaisyUI's card rule overrides `ragUiEvidence` inside `.card`. Later panels that render `ragUiEvidence` inside a card (Versions and dates quotes, 6.8) need the same.
