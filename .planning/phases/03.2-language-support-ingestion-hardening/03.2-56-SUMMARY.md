## Behaviour

**Page banner (D-02, UI-SPEC 6.2.1).**
- `languages.js` renders it into `#rag-language-banner` on `DOMContentLoaded` from `GET /api/config/languages`. It is visible on every tab, cannot be dismissed and has no alert role.
- Notice form (`alert-warning`, translate icon): languages not configured and no pipeline variable forces a newer pipeline.
- Blocking form (`alert-error`, octagon icon): `RAG_PIPELINE=v2` or `RAG_INGEST_PIPELINE=unified` is set explicitly. The sentence names that variable in a `code` element.
- Choose languages (neutral `btn btn-sm`) clicks the first RAG administration menu link, starts the panel, scrolls to the section and focuses its heading.
- The banner is not rendered when the config server does not answer. A successful save removes it without a reload.

**Languages panel (D-07, D-08, UI-SPEC 6.2.2).** It is the first section of the RAG administration tab.
- One row per complete pack, in registry order: native name with its `lang`, the name in the UI language (from `Intl.DisplayNames`, omitted when equal), the code in mono with `translate="no"`, document count, Use checkbox, and Primary radio enabled only on checked rows.
- A pack the server marks not selectable has a disabled checkbox. Its reason lines (`blocked.embedding`, `blocked.reranker`, with the id in `code`) are wired by `aria-describedby`. The browser does not re-run D-07.
- First run with counts: languages with documents are pre-checked, and the one with the most is primary. Without counts: nothing is pre-checked, an em dash with the hidden "Count unavailable" shows, and the `docs.unavailable` note appears. The picker still saves.
- Unchecking the primary row moves the primary to the first checked row and announces it. With one language checked, its radio is checked and the monolingual note shows. Groundedness `none` and removed-language notes are recomputed on each change.
- Save languages is disabled while nothing is checked, with `save.needOne` on screen and referenced by `aria-describedby`. On a configured deployment it is also disabled while nothing differs from the saved values. Reset selection restores the saved set and primary.
- Save posts `{ languages (registry order), primary }` with same-origin credentials and no Authorization header.
  - 200: writes the two hidden mirrors and `configManager.config`, shows the server's warnings in one warning alert, announces `save.done`, adds the `save.restart` line and removes the banner.
  - 400: one `alert-error` with `role="alert"`, one sentence per D-07 code (language names, profile and reranker ids in `code`), and focus on the alert. The selection is kept.
  - Other failures: the shared generic or network sentence in the status region, in error style.
- `verifiedAgainstActiveProfile: false`, in the load or the save answer, shows `warn.notVerified` as a warning line in the findings area. Nothing renders a pass mark for that check. This is always the case today (03.2-09 deviation 2).
- Impact hook: a changed language set on a configured deployment awaits `window.ragIngestImpactGuard(next, saved)` when plan 57 defines it. `next` and `saved` are `{ RAG_SUPPORTED_LANGUAGES, RAG_PRIMARY_LANGUAGE }`. The save proceeds on `true`, or on an object that keeps the new `RAG_SUPPORTED_LANGUAGES`. A guard that throws lets the save proceed, as UI-SPEC 6.4.1 says for `saveConfig`. A primary-only change, the first choice from unset, and a missing guard all save directly.
- Loading: a spinner with "Loading languages…" on the first load; `opacity-60` with `aria-busy` on refresh. When the config server cannot be reached, the error alert shows `list.unavailable` with Reload panel and earlier content stays dimmed. While saving, the button shows a spinner with "Saving…", and Reset and the row inputs are disabled.
- On mount the `languages` settings group (the mirrors) moves from `#rag-phase032-settings` into the panel, so "Save All Changes" still finds the ids.
- `initLanguagesPanel` is idempotent and bound to every `[data-tab="rag-administration"]` link (desktop and drawer).

**rag-ui.js (UI-SPEC 6.1).** Every top-level name starts with `ragUi` / `RAG_UI_` (a test enforces this).
- `RAG_UI_LABELS` (en, zh, it).
- `ragUiEl`: builds elements with `textContent`. It refuses `on*`, `href`, `src`, `srcdoc`, `formaction` and `style` attributes.
- Smaller helpers: icon, spinner, alert, template nodes (a `{placeholder}` becomes a `code` element), number and count formatting ("label: number", `Intl.NumberFormat`), locale resolver.
- Requests: `ragUiFetchJson` (config server, same-origin, 15 s timeout, only Accept and Content-Type headers) and `ragUiRagRequest` (`ragFetch` with a timeout).
- `ragUiMapError`: every row of UI-SPEC 8.2. A 409 it does not know becomes `kind: 'conflict'` with `code` and `reason`, so a panel can map `gate.*`.
- Other helpers: `ragUiCodeSentence` (unknown codes), `ragUiSubTabs` (roving tabindex, arrows, Home and End), `ragUiConfirmDialog` (`dialog.modal`, focus on the safe button, Escape ignored while running, focus returns to the opener), `ragUiVisibleControls` and `ragUiEvidence` (Cc and Cf as `[U+XXXX]`, cut at 2,000 characters, focusable `pre` region, never a link), `ragUiHoldLine`, list states (loading, busy, sign-in, unavailable) and `ragUiButtonBusy`.

No new env variable, switch, migration, SQL function or data store. So there is no purge hook and no `rag_purge_store_inventory()` registration. Off-state behaviour of the app is unchanged; only the Config UI page gains the banner and the panel.

## Deviations

1. **[Rule 2] `tests/ui/helpers/languages-harness.ts` (not in files_modified).** It is the page skeleton and fetch stubs shared by the panel tests.
2. **[Rule 2] `tests/ui/config-ui-xss-scripts.test.ts` (not in files_modified).** The threat model (T-03.2-561) asks for the existing XSS script scan to be extended to the new files.
3. **One shared label not in UI-SPEC: `code.unknown`.** en "The server reported {code}.", zh "服务器返回了 {code}。", it "Il server ha indicato {code}.". UI-SPEC 7.1 requires an unknown code inside a full sentence but gives no generic copy (only the per-panel `reason.other`, `signal.other` and `gate.other`). The language save uses it for D-07 codes that are not in the table, for example `unknown_language`.
4. **Copy typography.** UI-SPEC section 12 writes en quotes and apostrophes straight. The strings use curly quotes and apostrophes, as the 03.2-03 settings block and its test already do.
5. **Evidence labels in `RAG_UI_LABELS`.** `evidence.inert`, `evidence.cut` and `evidence.showAll` are copied verbatim from UI-SPEC 12.4 into the shared table, because `ragUiEvidence` is the shared builder. Plan 58 can use them without copying.
6. **The radio group has no `role="radiogroup"` element.** The radios share `name="rag-primary-language"` and each carries `col.primaryAria`. A radiogroup role on `tbody` would break the table semantics.
7. **Save languages disabled when nothing differs from the saved values** has no on-screen reason, because UI-SPEC 12.2 has no string for that state. The table already shows the saved set checked.

## Decisions for STATE

- `rag-ui.js` is the shared helper file for plans 57 to 62. Panels reach it through a small resolver, because a `const` alias in a classic script would redeclare the helper.
- The contract for `window.ragIngestImpactGuard(next, saved)` is fixed from the Languages side: it resolves `true`, `false`, or an object holding the config to save.
- The Languages counts come from `GET /api/rag/admin/languages` through `ragFetch`. Any failure counts as "no counts" (D-08: first run without an admin session).
