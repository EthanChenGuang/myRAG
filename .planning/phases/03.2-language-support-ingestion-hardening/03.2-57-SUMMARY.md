## Behaviour

**The save guard (D-11, UI-SPEC 6.4.1, decisions 4 and 5).**
- `saveConfig()` in `index.html` first awaits `window.ragIngestImpactGuard(this.config, this.savedConfig)`. The header button, "Save All Changes" and every auto-save call `saveConfig()`, so all of them pass the guard. A missing guard or a thrown error saves as before.
- `this.savedConfig` is taken in `loadConfig()` and refreshed after each successful POST.
- The guard sends `{ proposed }` with only the changed `RAG_*` names to `POST /api/rag/admin/ingest-fingerprint/impact`, at most 200 names per request. The route decides which names are ingestion-side. Never sent: names matching `/(KEY|SECRET|TOKEN|PASSWORD)/i` (none of them is ingestion-side), non-`RAG_` names, and values over the route's 2,048-character limit.
- What happens next:

  | Impact answer | Result |
  |---------------|--------|
  | No ingestion-side key | Saves, no dialog |
  | Ingestion-side keys, 0 affected and every document counted | Saves, no dialog; toast `impact.none` |
  | Affected documents, or documents without a fingerprint that could not be counted | Impact dialog |
  | 401, 403, 503, network failure, or no answer within 15 s | Dialog in its "count unavailable" form |
  | First language choice (saved set empty, only the language keys changed), count zero or unavailable | Saves, no dialog |

- Dialog contents:
  - Title, and "Changed settings": each setting's visible label, then "{from}, changed to: {to}" with the option text read from the page's own select, then the env name in `code`.
  - Count table (Rebuild, Document type, Documents), with "All affected documents" as the last row in semibold. Rows with zero documents are left out.
  - The warning sentence, which the dialog's `aria-describedby` points to. `impact.security` is added when the rescan mechanism is involved, and `impact.fingerprintGap` (with the backfill command) when documents have no fingerprint.
  - Focus starts on "Keep current settings". Escape and the backdrop also keep.
- Counting: if no answer comes within 300 ms, the dialog opens with "Counting affected documents…" and Save settings stays disabled until the answer or the 15-second timeout. If the answer then says nothing is affected, the dialog closes by itself.
- Keep current settings puts the ingestion-side inputs (in the unknown form, every changed `RAG_*` input) back to their saved values without firing `change`. It resolves with a copy of the config holding the saved values, so the other changes still save. The panel's status region then says `impact.kept`.
- Save settings saves everything and the toast says `impact.saved`. Saving rebuilds nothing.
- Guard calls are queued, so an auto-save that fires while the dialog is open waits for the decision. A change the admin already accepted is not asked again.
- `guard(next, saved, options)` accepts a caller-supplied `title`, `rowLabels` (per mechanism), `totalLabel` and `note`. This is the seam 07-52 needs, so it can use the dialog without editing the file.

**Ingestion changes panel (UI-SPEC 6.4.2, D-12, findings 5 and 6).** It sits between Ingestion and Quarantine, with the sub-tabs Rebuilds (default) and Settings.
- Settings: on mount, the `ingest` group (four selects) moves into this sub-view, so "Save All Changes" still finds the ids. zh and it labels are applied through `data-rag-i18n`. Combination warnings `warn.needsLanguages` and `warn.needsUnified` are recomputed when any of the four selects, `RAG_INGEST_PIPELINE` or `RAG_SUPPORTED_LANGUAGES` changes.
- Rebuilds:
  - A toolbar with "Updated {time}" and Refresh rebuilds. The `coverage.missing` line with the backfill command appears when documents have no fingerprint.
  - "Documents on previous settings": one row per mechanism with documents. The Next step cell follows `start`:
    - `ui`: Start rebuild. It posts `{ mechanism }` only and shows "Starting…" while running.
    - `cli`: the command in `code`, with Copy command.
    - `needs_async`: the needs-async sentence, the command and Copy command.

    Copy command is rendered only when `navigator.clipboard.writeText` exists.
  - "Rebuilds" table, columns:
    - Rebuild.
    - Documents: a native `progress` and "{done} of {total}" while running; a gaps line when any document could not be rebuilt.
    - State: badge with word and icon. An unknown state shows its code in mono.
    - Started: a `time` element, hidden below 1024 px.
    - Actions:
      - Activate rebuild (state `built`) and Roll back rebuild (state `active`), only for `activation: rebuild_batch`.
      - Open chunking profiles or Open embedding profiles for `chunking_profiles` / `embedding_profiles`. The button scrolls to that panel and focuses its heading.
      - Nothing for `none`.
  - Rows are ordered running, incomplete, built, active, then newest start first. 20 rows are shown, then Load more rebuilds.
  - Activate and Roll back open the confirmation dialog with focus on Keep current versions. On success the status region announces it and the list reloads.
    - A 409 `activation_refused` / `rollback_refused` / `start_refused` shows `gate.eval_missing`, `gate.eval_failed` or `gate.incomplete` in an `alert-warning` block with `role="alert"` in the alert host. Any other reason uses `gate.other` with the code in `code`. The list reloads.
    - A thrown request gives `error.outcomeUnknown` and a reload. A 404 gives `error.changed` and a reload.
  - States:
    - Nothing pending and no rebuild: the empty title and body.
    - Pending documents but no rebuild: `rebuilds.none`.
    - A rebuild with gaps: Incomplete badge, gaps line, and the pending row offers Start rebuild again.
    - 401 or 403: the shared sign-in alert with Reload panel; Settings stays usable.
    - 503 or network failure: `rebuilds.unavailable` with Reload panel, earlier content dimmed.
  - Polling runs only while a rebuild is running, the RAG administration tab is active and the document is visible. It reloads every 15 s and resumes on `visibilitychange`. Progress is announced at most every 30 s; the end state of a run is always announced; load counts are announced on the first load and on Refresh.
  - Never rendered: run ids (kept only for the action URL), batch ids, fingerprints, or any field not read by name.
- `initIngestImpactPanel` is idempotent and bound to every `[data-tab="rag-administration"]` link (desktop and drawer).

No new env variable, switch, migration, SQL function or data store, so there is no purge hook and no `rag_purge_store_inventory()` registration. The app's behaviour is unchanged. On the Config UI page, the only new behaviour is the dialog before an ingestion-side save, and the new panel.

## Deviations

1. **[Rule 2] `tests/ui/helpers/ingest-impact-harness.ts` and `tests/ui/config-ui-xss-scripts.test.ts` (not in files_modified).** The harness loads the real section and settings markup from `index.html` into the fake DOM. The XSS case is what T-03.2-572 asks for.
2. **[Rule 2] `tests/ui/config-rag-panel-binding.test.ts` (not in files_modified).** One row for the new panel, as the plan's verify command runs that file.
3. **Guard name.** UI-SPEC 6.4.1 names `window.ragBeforeConfigSave(changed)`. The plan, plan 56 and the Languages panel use `window.ragIngestImpactGuard(next, saved)`, so that name and shape are kept. The guard computes the changed keys itself.
4. **Dialog opens after 300 ms, not at once.** If it opened at once, a query-side change would flash a dialog on every auto-save. If no answer comes within 300 ms, it opens with the counting text and Save settings stays disabled, as specified.
5. **Uncounted documents keep the dialog.** With 0 counted documents but documents without a fingerprint, the dialog opens with the gap line, because "no document is affected" cannot be claimed. The first language choice is the exception (decision 5).
6. **Labels not in UI-SPEC 12.3** (en, zh, it):
   - Accessible names: `action.activateAria`, `action.rollbackAria`, `action.copyAria`.
   - In-flight text: `rebuild.activating`, `rebuild.rollingBack`.
   - Announcements: `rebuild.announce` (progress), `rebuild.ended` (end state), `rebuilds.loaded` (load counts), `rebuild.nothing` (a start that had nothing to do).
   - Captions and other text: `copy.failed`, `impact.caption`, `impact.notSet`, `tabs.label`.
7. **Two badge colours deviate from UI-SPEC 6.4.2** for contrast. See the Impeccable findings.
8. **Unknown `start` values render as `cli`** (the command and Copy command), so the panel never shows a Start rebuild button the server did not declare.

## Decisions for STATE

- `saveConfig()` is the only path that posts the whole config. The other `/api/config` writers in the Config UI post fixed names that are not `RAG_*` (WhatsApp, reasoning, LlamaCloud chunking, MCP endpoints), and none of those names is classified as ingestion-side.
- `window.ragIngestImpactGuard(next, saved, options?)` resolves `true` or a config copy with reverted keys. `options` (`title`, `rowLabels`, `totalLabel`, `note`) is the extension seam for 07-52.
- `ingestImpactCreateGuard({ openDelayMs, timeoutMs })` and `initIngestImpactPanel({ pollMs, announceMs })` take timing overrides for tests only. The defaults are 300 ms, 15 s, 15 s and 30 s.
