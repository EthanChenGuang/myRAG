# Phase 03.2 Plan 26: Long-table fixtures Summary

**Six deterministic 60-row table fixtures in zh, en and it, plain and page-continued, defined by column roles and a target row, recorded through the sidecar adapter and kept out of the loaded fixture tenant.**

## Performance

- **Duration:** about 50 min
- **Completed:** 2026-11-25
- **Tasks:** 2
- **Files modified:** 30 (24 new fixture files, 6 changed)

## Accomplishments

- `long-table-{zh,en,it}`: heading, intro, one table of header + 60 data rows over pages 1–2 (header on page 1 only), closing line on page 2. Recorded as one Docling table of 61 rows with provenance on both pages.
- `long-table-{zh,en,it}-continued`: the same rows as two tables, the second starting page 2 with data row 44 and no header row, same column count. Recorded as two table items; the Markdown text artifact separates them only by a blank line. The target row is in the second table.
- Column roles and the target row are data in `facts.long_table` (and so in the manifest's `expected`), so later plans read them instead of hard-coding cells.
- Generating all ingest PDFs again leaves every existing PDF byte-identical; the recorder leaves every existing recording unchanged.

### Subjects chosen (owner rule of 2026-11-25)

| Document | Subject | Key columns | Value columns (same unit) | Category |
|---|---|---|---|---|
| `long-table-en` | water levels of six invented storage basins | Basin, Survey week | Morning level (cm), Evening level (cm) | Trend |
| `long-table-zh` | 六个虚构试验地块的作物株高 (plant height on invented trial plots) | 地块, 测量批次 | 首测株高（厘米）, 复测株高（厘米） | 长势 |
| `long-table-it` | spessore di campioni di vetro sintetici (glass sample thickness) | Lotto, Campione | Spessore iniziale (mm), Spessore finale (mm) | Esito |

None of these subjects, column names or values comes from the illustrative examples in CONTEXT, RESEARCH, UI-SPEC or ROADMAP: a grep of the phase directory and ROADMAP for the subject words (basin/reservoir, 株高/地块, spessore/campioni/vetro) finds nothing, and a test rejects a list of the planning documents' sample-domain words in the fixture text. Values come from a fixed rule, not from any document.

## Decisions Made

- Isolation is done in this plan by data shape: the long tables are listed under `manifest.long_table_fixtures`, which no loader reads today. Ingest mode, the fake sidecar, `tests/rag-db/ingest-typed-fixtures` and `ingest-mode-multi-tenant` keep their document sets. Plan 30 reads the new list for its own tenant.
- `doc_type: general` for all six, so recordings reflect the profile flag `repeat_table_header: false`.
- "Beyond the first chunk at every chunk size" is checked as: the cl100k token count of the table Markdown before the target row exceeds the largest `chunker.max_tokens` of the six profiles (1024). Margins: en 1219, zh 1389, it 1348 tokens.
- Binary hashes in recordings: existing fixtures keep 2001–2012; long tables use 3001–3006.
