# Phase 03.2 Plan 13: hybrid_search_chunks scopes, effective dates and und rule

**Migration 0802 replaces `hybrid_search_chunks` once for the whole phase: the `und` language rule in both language predicates, a `p_scopes` filter over three fixed dimensions and an inclusive `p_effective_on` predicate, with default calls unchanged.**

## Accomplishments
- `supabase/migrations/0802_hybrid_search_scopes_dates_und.sql`: body copied from 0602; drops the 0407 and 0602 signatures; appends `p_scopes`, `p_scopes_include_untagged`, `p_effective_on`; keeps `SECURITY INVOKER`, `VOLATILE`, `SET search_path = ''`; REVOKE from PUBLIC, anon, authenticated and GRANT to service_role on the exact new type list; `NOTIFY pgrst`.
- `und` rule: `c.language = ANY($8) OR (c.language = 'und' AND d.language = ANY($8))`, and the same inside the `p_lexical_languages` predicate (research Open Question 4).
- Scopes are split once at the top of the function into three arrays; each set dimension adds `c.scopes && $n OR ($19 AND no tag with that prefix)`. Dates add `(effective_from IS NULL OR effective_from <= $20) AND (effective_to IS NULL OR effective_to >= $20)`. Tags and the date are bound parameters, never concatenated.
- Predicates are AND-ed after the tenant/current/status filter, so they only narrow; the tenant still comes only from `p_tenant_key` through `rag_assert_tenant_key`.
