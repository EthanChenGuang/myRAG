## Behaviour

**Pending (default sub-tab, label "Pending: {count}").**
- Follows `#workspace-selector`: requests carry `organizationId` when a workspace is chosen. The 12px line under the description reads "Workspace: {option text}", or "Default workspace". A change of workspace reloads the list (and Exemptions when open).
- One `table.table-sm` in a focusable scroll region: visually hidden caption, `th scope="col"` headers, the File cell as `th scope="row"`. The File cell holds the hold line: file name, the "Awaiting approval" badge with `bi-hourglass`, then the reason. The reason is `pending.newVersion` for a new version of a live document, otherwise `pending.reason`.
- Columns: Uploaded by (display, or the id in `font-mono` with `translate="no"` when there is no display name; "Unknown uploader" when null), Source (known values labelled; an unknown value as the code inside a sentence), Document type (`docTypeLabelForLocale`), Uploaded (`<time datetime>`, `Intl.DateTimeFormat`), Actions.
- Pages by 50. Load more uploads asks for the next page from the number of rows still listed, so approving rows first neither skips nor repeats one. Focus moves to the first new row's Approve upload.
- Approve upload acts at once. Both row buttons disable, the button shows "Approving…", and on success the row is removed and the status region says "{file} is approved and searchable." Focus moves to the next row's Approve upload, the previous row's, or the status region.
- Reject upload opens `ragUiConfirmDialog` with `tone: 'error'`: "Reject {file}?", the body, "Keep upload" focused, "Reject upload" in `btn-error`. It posts only on confirm, with no body and no reason. The file name is text. Keep returns focus to the opener.
- A 404 or a 409 `not_pending` / `superseded_by_newer` on approve or reject shows `error.changed` and reloads. A sign-in failure re-renders the sign-in alert. Other errors stay in the status region and the row is kept.
- States: first-load spinner; refresh dims with `aria-busy`; 401/403 sign-in alert in place of the data views; 403 `Forbidden` the workspace sentence; 503 or network the unavailable alert in the alert host with Reload panel, earlier rows dimmed; empty title and body; mode off shows `pending.off` with "Open approval settings" (`btn-link`, selects and focuses the Settings tab); `pending.quarantineNote` under the table.

**Exemptions.**
- Loaded when the sub-tab is first opened: `GET …/exemptions` with the workspace.
- Inline form (`fieldset`, `bg-base-100 rounded-lg p-4`): Kind select, then a Name select filled from that kind's choices, then Add exemption. Add stays disabled until both are chosen; the reason line is referenced by `aria-describedby` while disabled. `exempt.noChoices` replaces it when the kind has nothing to exempt.
- Table: Kind, Name (row header; the ref in monospace when there is no display name), Added by, Added, Remove exemption (no dialog, accessible name with the name). With no rows, `exempt.empty` shows under the form.
- Add posts `{ kind, ref }`; remove sends `DELETE …/exemptions?id=…`. Both reload and announce. Focus goes back to the Kind select after add, and to the next row's Remove (or the Kind select) after remove.

**Settings.** The `approval` group moves from `#rag-phase032-settings` into the sub-view, localized through `data-rag-i18n` for zh and it. `warn.approvalLegacy` shows in the alert host (above the sub-tabs, so it is visible from every sub-view) while `RAG_UPLOAD_APPROVAL` is not `off` and `#RAG_INGEST_PIPELINE` is not `unified`, recomputed on change of either. Settings stay usable when the data calls answer 401.

**No notification** beyond the count in the sub-tab label (D-37). No `role="alert"` on load.

**Ingestion panel.**
- The `other` filter asks for `quarantined`, `skipped_duplicate` and `pending_review` (`INGESTION_STATUS_FILTERS`). Its label reads "Held or skipped" / "已暂缓或跳过" / "Trattenuti o saltati", and the static radio name in `index.html` matches.
- The filter radios get their localized names on mount (they were English in every locale).
- A `pending_review` job reads "Awaiting approval" with the hourglass badge.

**Shared label.** `status.pending_review` (en, zh 等待批准 per decision 17, it) is added to `INGEST_STATUS_LABELS`. `pending_review` is terminal in `INGEST_TERMINAL_STATUSES`, so the Config UI upload monitor stops polling at it.

## Decisions for STATE

- Config UI panels that build their own form controls with an `id` stop those controls' `change` events. Otherwise the page's auto-save records the id as a config key (the config server drops hyphenated names, but the save cycle still runs).
- `pending_review` is a terminal status in the Config UI status monitor, labelled "Awaiting approval" / 等待批准 / "In attesa di approvazione".
- Purge coverage (06.3-19): this plan adds no store, so no purge hook or inventory row.
