# Phase 03.2 Plan 48: chunk translation storage, search and ledger kind

**Migration 0810 stores retrieval-only chunk translations beside their source chunks, searches them with `hybrid_search_translations` under the same tenant, lifecycle and DATA-08 filters as `hybrid_search_chunks`, and lets the ingestion ledger carry `translate` jobs.**

## Accomplishments
- `chunk_translations` (`UNIQUE (chunk_id, language)`, FK cascade to chunk and document, generated `lexical_tsv` with GIN index) and `chunk_translation_embeddings` (halfvec, PK `(translation_id, profile_id)`, five partial HNSW indexes in the 0308 form). Guard triggers copy `tenant_key`/`document_id` from the source and refuse a different value; the vector guard checks dims against the profile and refuses scoped profiles.
- `rag_write_chunk_translations` upserts text, lexical text, hash, model, glossary version and the vector in one call, refusing any chunk outside `p_tenant_key`.
- `hybrid_search_translations`: `rag_assert_tenant_key` first, the 0802 filter text with the same positional parameters, joined to the source chunk and document; returns the source chunk id with `translation_id`, `translation_language`, per-leg rank, `translation_similarity` or `lexical_score`.
- `rag_translation_settings` table with get/set, `rag_translation_coverage`, `rag_translation_pending_page`, `rag_language_document_counts` (aggregates only), `rag_purge_hook_chunk_translations`.
- Ledger: `rag_enqueue_ingestion_job`, `rag_claim_ingestion_job`, `rag_claim_ingestion_jobs`, `rag_advance_ingestion_job` (0801 bodies) and `rag_fail_ingestion_job` (0422 body) replaced with `CREATE OR REPLACE`, signatures, SECURITY DEFINER, `SET search_path = ''` and grants kept.
- All new functions are `SECURITY INVOKER`, `SET search_path = ''`, revoked from PUBLIC, anon, authenticated and granted to service_role; tables have RLS on and no policies.
