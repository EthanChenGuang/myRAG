# Phase 03.2 Plan 42: Scopes filter and effective dates in v2 retrieval

**A request can narrow v2 retrieval to documents carrying given scope tags. With RAG_EFFECTIVE_DATES on, documents outside their effective window are not retrieved. Both feed the semantic-cache key; the date also feeds retrievalConfigHash. With the switches off, requests, keys and hashes are unchanged.**

## Behaviour changes

- v2 chat, embed and eval: `retrievalFilters.scopes` (`region`, `legal_entity`, `department`; slug values) and `includeUntagged`. Values within a dimension are OR'ed and dimensions are AND'ed in SQL. Untagged documents match only with `includeUntagged: true`. A filter can only narrow the server-verified tenant.
- `RAG_SCOPE_TAGS=false` plus a non-empty scopes filter under v2 answers 400 `scopes_disabled`.
- `RAG_EFFECTIVE_DATES=true` sends today's UTC date (from the `RagDeps.now` clock) as `p_effective_on` on every v2 search call. The exact-id leg stands down. The date joins retrievalConfigHash.
- Off states: the filter-free RPC body is byte-identical to the recorded one, the cache key equals the recorded hash, and the config hash is unchanged.
