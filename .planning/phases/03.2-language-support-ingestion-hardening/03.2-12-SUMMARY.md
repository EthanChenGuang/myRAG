# Phase 03.2 Plan 12: Publish hold and upload approval Summary

**The database refuses to publish a pending or batch-held document; approval, rejection, exemptions and hold release are tenant-scoped service-role functions.**

## Accomplishments
- `rag_publish_document_version` gained two early returns beside the quarantined branch: `pending_review` (status) and `held` (`metadata ? 'publish_hold'`). Both return before the lineage lock, so a held document supersedes nothing and invalidates no cache entry.
- Hold, approve, reject and list functions for pending uploads, all following the `rag_release_quarantine` model (Pattern 4).
- An exemptions table with actor-scoped admin functions and a pipeline read, `rag_is_tenant_admin`, `rag_release_publish_hold` and `ingestion_batches.hold_publish`.
- 44 PGlite tests (22 per mode): hold, direct publish refusal with v1 still current and retrievable (lexical leg), approval stamps on document and every chunk (including a `variant` chunk), two-tenant `not_found`, reject both ways, `not_pending` on repeat, `superseded_by_newer`, cache invalidation on approve and none on a refused publish, list order and paging, role denial on the table and every function, empty `search_path`, second apply leaves the catalog unchanged.

The test now expects `pending_review` from the direct call, moves the document back to `processing` with the setter and then publishes.
- **[Rule 3] `supabase/migrations/0410_security_definer_rpc_grants.sql`**: seven entries added (approve, reject, list, approval keys, exemption add, list and remove), following the precedent of 0603, 0701 and 0801. This is outside `files_modified`.
- **Extra helper `rag_upload_approval_keys(uuid)`** (SECURITY DEFINER, service_role only): a shared not_admin-to-empty mapping, so the plan's `not_found` for a non-admin holds without changing `rag_admin_tenant_keys`.
- **Reject path split** (see key decisions): the plan says reject goes "through the soft-delete seam", but the seam deletes the whole lineage. It is used only when the pending document is the lineage's only live version.
