# Plan 03.2-47 Summary

**Ingestion now reads effective dates stated in a document and suggests scope tags from the tenant's own vocabulary; dates go through the D-43 apply rule and tags are only ever suggestions for an admin.**

## What was built

- `extractors/effective-dates.ts`: rules from the document language's pack (start and end phrases), ASCII and full-width digits, the pack's written date forms, deterministic choice; optional model step (`RAG_EFFECTIVE_DATE_LLM_EXTRACT`) with `EffectiveDateExtraction`, accepted only with a verbatim quote; never throws except on abort.
- `extractors/scope-suggest.ts`: label and alias matching in title and first page, optional model step with `ScopeTagSuggestion` limited to active vocabulary values; result validated with the generated schema.
- `stages/extract.ts`: after the profile extractors, `recordEffectiveDates` (computes `decideEffectiveDateProposal`, then `recordExtractedEffectiveDates` applies or stores the proposal) and `recordScopeSuggestions` (reads `rag_scope_vocabulary_for`, writes `metadata.scope_suggestions`). Both turn failures into warnings (`effective_dates_unavailable`, `scope_suggestions_unavailable`).
- `dates.ts`: `findDateSpans` (date with its length); `findDateCandidates` unchanged in output.
- `LanguagePack.effective_date_end_patterns` (contract, both pack copies, generated schemas and samples); `registry.ts` compiles it too.

## Behaviour changes

- Default switches: the date rules run in every `ingest()` run (the unified pipeline). A document stating a start date in the past or an end date in the future gets `effective_from` / `effective_to` with origin `extracted` and confidence 0.9; a date that would hide it today is stored as `metadata.effective_date_proposal` (awaiting confirmation). No retrieval reads these columns while `RAG_EFFECTIVE_DATES` is false. The legacy ingest pipeline is untouched; no model is called and no suggestion stored with the model and suggestion switches off. `defaults-equal-phase3` reports no difference.
- `RAG_SCOPE_TAGS=true` + `RAG_SCOPE_TAG_SUGGEST=true`: one vocabulary read per ingest and `metadata.scope_suggestions` when something matched; `documents.scopes` and chunk rows are unchanged.
- No new switch, env variable, migration or SQL function. Purge: no new store (both writes are keys in `documents.metadata` and existing columns), so no `rag_purge_hook_*` or inventory registration was needed.
