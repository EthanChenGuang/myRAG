# Phase 03.2 Plan 49: chunk translation producer

**Published chunks are translated into the tenant's target languages after publish, for opted-in tenants only, with protected tokens kept, gaps recorded, a time budget inline and `npm run rag:translate` for the rest.**

## Accomplishments
- `translateChunk`: the generated `ChunkTranslation` structure, `extractProtectedTokens`/`keepsProtectedTokens` unchanged, one retry, gaps `too_long`, `protected_token_lost`, `empty_output`, `invalid_output`. The prompt keeps the passage out of the system prompt and marks it as data.
- `glossaryFor(scope, source, target)` returns no terms and version `none`; the version is stored with every translation.
- `translateDocumentChunks(documentId, tenantKey, { budgetMs, languages? })` and `translatePending(tenantKey, { budgetUsd, reembedOnly })` share one gate and one loop; vectors for the active global profile only; written through `rag_write_chunk_translations`.
- Post-publish hook `translation`, registered only while the switch is on, the deployment has more than one language and async ingest is off.
- `npm run rag:translate -- --tenant <key> [--dry-run] [--budget <USD>] [--resume] [--language <code>]` and `--reembed --budget <USD>`.
- Migration 0820 (service_role only, `SET search_path = ''`, tenant from `p_tenant_key`).
