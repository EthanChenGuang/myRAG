# Phase 3.2 Plan 41: Scope vocabulary and document tags Summary

**Each tenant now has its own tag vocabulary (region, legal entity, department) and admins can tag documents and their chunks in one transaction, with the cache entries naming the document dropped, through routes open to deployment admins and the organization's own admins only.**

Scope tags narrow retrieval inside the caller's already verified tenant. They are not access control: no route, comment or answer describes them as permissions, and they grant, hide or protect nothing.

## Accomplishments
- 0805: `rag_scope_vocabulary` (unique per tenant, dimension and slug value; RLS on, no policies, service_role SELECT only) and the service_role functions for list, create, update (label, aliases, active; never value or dimension), the service-path `rag_scope_vocabulary_for`, `rag_set_document_scopes`, `rag_list_documents_with_scopes` and the purge hook. All functions `SET search_path = ''`, revoked from PUBLIC, anon and authenticated, granted to service_role; definers are also in the 0410 upgrade lockdown list.
- `scopes/admin.ts` after `approval/admin.ts`: one RPC funnel, bare reason words only, typed row readers that fail closed, slug normalization twin of `rag_scope_slug`, suggestion items allow-listed to `{dimension, value, source}`.
- Three route files with the switch gate first, `checkAdminOrOrgAdmin`, strict `zod/v3` schemas (vocabulary fields from the generated `ScopeVocabularyEntrySchema`), `Cache-Control: no-store`, `[RAG Admin]` logs with ids and counts only.

## Route contract (for the Config UI plan)
- `GET /api/rag/admin/scope-vocabulary?organizationId=` → `{ success, dimensions: ['region','legal_entity','department'], items: [{ id, dimension, value, label, aliases, active, updated_at }] }`
- `POST` same path, body `{ dimension, value, label, aliases? }` → 201 `{ success, item }`; 409 `tag_exists`; 400 `invalid_value` (nothing left after slug normalization)
- `PATCH` same path, body `{ id, label?, aliases?, active?, dimension?, value? }` → `{ success, item }`; 400 `value_immutable` when `dimension` or `value` differ from the stored ones; 404 `Tag not found`
- `GET /api/rag/admin/documents?organizationId=&scopes=dim:value(&scopes=…|,…)&q=&filter=all|suggested|untagged&limit=50&offset=0` → `{ success, total, suggested_total, limit, offset, items: [{ id, file_name, doc_type, status, version, tags, suggestions: [{ dimension, value, source }], uploaded_at }] }`
- `PUT /api/rag/admin/documents/{id}/scopes?organizationId=`, body `{ scopes: string[] }` (full set, max 20) → `{ success, id, scopes }`; 400 `unknown_scope_value` or `too_many_scopes`; 404 `Document not found` for unknown and foreign ids
- With `RAG_SCOPE_TAGS=false` every route answers 404 `{ success: false, error: 'Not found' }`.

## Behaviour changes
- New routes, table and functions only. With `RAG_SCOPE_TAGS=false` (default) the routes answer 404 and nothing is written; retrieval, upload, strict mode, webSearch, `source_images`, voice and embed chat are untouched (no retrieval code changed; the filter is plan 42).
