# Phase 3.2 Plan 35: PDF hidden-text checker Summary

**The sidecar finds white-on-white, tiny, off-page, covered and invisible text in the original PDF through `POST /v1/hidden-text`, with zero false positives on the clean fixture corpus.**

## Accomplishments

- `security/pdf_checks.py`: walks every page's pdfium objects in content order (recursing into form XObjects, mapping their bounds to page space), reads per text object the fill/stroke colour and alpha, effective font size (Tf × matrix scale), render mode and bounds; filled paths and images give the local background (drawn before) and covers (drawn after). Consecutive hidden objects with the same reason are merged into one span. Link annotation URI targets are read with `FPDFLink_Enumerate` / `FPDFAction_GetURIPath`; nothing is fetched or resolved.
- `security/hidden_text.py`: MIME dispatch (PDF now; everything else `not_checked`), the report bounds (sort by page, then top-to-bottom, then left; 200 spans, 2,000 characters per span, `dropped` count; link targets deduplicated, 200 × 2,048), rules loading through `resolve_config_file`, `checker_version` = `hidden-text/1/<rules_version>`.
- `security/router.py`: multipart upload into a temp directory with `max_upload_bytes`, `HiddenTextRequest` validation, size and sha256 check, the check in a thread with a 60 s timeout; logs counts and reason kinds only (D-51).
- Fixture generator: stdlib-only raw PDF writer (Helvetica WinAnsi for en/it, non-embedded STSong-Light UniGB-UCS2-H for zh, uncompressed, no dates or ids). Corpus: 6 hidden fixtures (white-on-white, tiny-font zh, off-page it, invisible-render, covered-text it, form-white-text) and 8 clean ones (plain, dark header, footnotes, crop marks, scan, OCR layer, link annotation, zero pages). In-test builders: 500 fragments, 10,000-character span, 2-character fragment.

## Fitted thresholds and evidence

Values in `config/rag/hidden-text-rules.json` (`rules_version` `2026-11-25.1`); measured on the corpus with the checker's own helpers:

| Rule | Value | Hidden fixture | Closest clean value |
|------|-------|----------------|---------------------|
| `pdf.color_distance_max` (RGB distance / √3) | 0.1 | white-on-white 0.0, form-white-text 0.0 | 0.785 (white header text on the dark cell); black on the 0.93 grey zebra row ≈ 0.93; all other clean text 1.0 |
| `pdf.min_font_size_pt` | 4.0 | tiny-font 1.0 pt | footnote superscripts 5.5 pt, footnote lines 7 pt |
| `pdf.min_font_size_ratio` | 0.5 | tiny-font 1.0 / 11.0 = 0.09 | superscripts 5.5 / 10.5 = 0.52 (passes the absolute rule anyway) |
| `pdf.outside_page_margin_pt` | 6.0 | off-page text centre ≈ 116 pt below the page | crop-marks: all text inside the crop box; the marks are paths |
| `pdf.covered_overlap_min` | 0.5 | covered-text 1.0 | 0.0 on every clean fixture; OCR layer over its image 1.0 (exempted as an OCR layer) |
| `pdf.min_span_chars` | 3 | every hidden sentence > 40 | the 2-character white fragment is dropped (clean) |
| `docx.*` | 0.1 / 6 half-points / 3 | — | provisional; plan 36 fits them on Word fixtures |
| `zero_width_threshold` | 5 | — | provisional; plan 34 fits it on its zero-width fixtures |

## Tests that failed before the fix

- `test_a_zero_page_file_is_clean_even_after_a_failed_open`: pdfium sets no error code for an empty page tree, so after an earlier failed open the stale FORMAT code made the zero-page fixture answer 422 `unreadable_document` (it passed alone and failed in the full suite). The fix counts pages with pdfplumber whenever pdfium cannot open the file, before looking at the error code.

## Behaviour changes

- A new sidecar route `POST /v1/hidden-text`. Nothing in the app calls it yet (plan 37 wires it into `scan_injection`), so every existing path is unchanged; no env variable is added in this plan.

## Error codes for plan 37

| Status | Body `error` | Meaning |
|--------|--------------|---------|
| 401 / 503 | `unauthorized` / `sidecar secret not configured` | shared-secret middleware |
| 413 | `upload_too_large` | over `RAG_SIDECAR_MAX_UPLOAD_MB` |
| 422 | `invalid_hidden_text_request` | malformed multipart or `HiddenTextRequest` |
| 422 | `hidden_text_mismatch` | size or sha256 differ from the uploaded bytes |
| 422 | `unreadable_document` / `encrypted_document` | PDF cannot be opened / needs a password |
| 503 | `checker_unavailable` | preflight extra missing or rules file unreadable |
| 504 | `hidden_text_timeout` | check exceeded 60 s |
| 500 | `hidden_text_failed` | unexpected checker error |

Plan 37 decides how `quarantine` treats each (D-34: fail closed when the checker is unavailable).

## Deviations from Plan

1. **pdfium page objects instead of pdfplumber rectangles for the background.** The covered-text rule needs the drawing order (a fill drawn before the text is its background, one drawn after it covers it); pdfium's page-object list carries that order and pdfplumber's does not. pdfplumber is still used to count pages when pdfium cannot open a file. Character-level data comes from pdfium text objects (one per show operator), which carries the same colour, size and render mode as the per-character calls.
2. **Extra fixtures:** `clean-ocr-layer.pdf` (invisible OCR text over a scan must stay clean, Pitfall 14), `form-white-text.pdf` (hidden text inside a form XObject), `link-annotation.pdf`, `zero-pages.pdf`, and `manifest.json` with each fixture's sha256, expected status and reason.
3. **Fixture generator without reportlab.** The sidecar environment has no reportlab, and the plan's tests rebuild the fixtures there; the generator is stdlib-only, so `python3 eval/fixtures/security/generate_hidden_pdfs.py` regenerates the corpus anywhere.
4. **Task 3 had no RED commit.** The lazy imports and report bounds were already part of the Task 1 design (`build_report`, function-level imports), so its tests passed when written.
5. **`rag-sidecar/tests/test_image_config.py`** (not in `files_modified`): `hidden-text-rules.json` added to `REQUIRED_CONFIG_FILES`, as PATTERNS.md asks; the byte-equality test already covers every JSON in the copy directory.
6. **Additions:** the sha256/size match check and the encrypted/unreadable 422 answers on the route.
