## Behaviour

- **`GET /api/config/languages`** (behind the existing loopback, Host and CSRF guard) reads `.env.local`, the registry and the declarations on every call. It answers `configured`, `languages`, `primary`, `variablesSet` (per language variable), `pipelines` (`RAG_PIPELINE` and `RAG_INGEST_PIPELINE` as `{ value, explicit }`, where explicit means a non-empty value), `reranker` (`{ id }` or null), `embeddingProfile` (`{ id }` or null), `verifiedAgainstActiveProfile` (always false, see Deviations) and `packs`. Each pack has `{ code, nativeName, englishName, groundedness, selectable, reasons: [{ code, id }] }`. Only complete packs are listed, in registry order.
- **`POST /api/config/languages`** takes `{ languages: string[], primary: string }`. A body that does not have this shape (for example, a string instead of a list, or more than 64 entries) answers 400 `Invalid request body`. A validator error answers 400 `{ success: false, error: 'Invalid language settings', details }`, where `details` lists the validator's ordered errors as `{ code, language?, id? }`, and nothing is written. On success it writes `RAG_SUPPORTED_LANGUAGES` (registry order) and `RAG_PRIMARY_LANGUAGE` and answers 200 `{ success, languages, primary, warnings, verifiedAgainstActiveProfile }`.
- **Write:** existing lines are replaced in place, duplicate lines collapse to one, and missing variables are appended. The file is written to a temp file next to `.env.local` and renamed over it, keeping the existing file mode. Values come only from the validated `normalized` result, never from the raw body (T-03.2-092).
- **init-env picker:** it prompts only when stdin and stdout are TTYs, `CI` is empty and `RAG_SUPPORTED_LANGUAGES` has no value in the environment or in `.env.local`.
  - It lists complete packs as `native · English (code)`, or `name (code)` when the two names are equal, and says in one line that the embedding check is not verified against the active profile.
  - Answers can be numbers or codes. With one language the primary question is skipped.
  - An empty answer or closed input writes nothing. After three invalid answers both variables stay unset. The validator's errors are printed before each retry.
- **Suggestions:** when `.env.local` already holds `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`, the picker makes one PostgREST request (`documents?select=language&is_current=eq.true&status=eq.ready&language=in.(…)&limit=10000`, 3 s timeout) and marks the languages that have documents as suggested.
  - Credentials given only in the environment, or any failure, mean no request result and no suggestion.
  - The key is never printed, and nothing is saved from a suggestion.
- **Non-interactive runs are unchanged** (`CI=1 node scripts/init-env.js`, piped stdin): same output, and no read of stdin.
- **Validation context (`scripts/rag/language-settings-context.js`):**
  - Reranker table: cohere and voyage cover the packs with golden slices; local_bm25 covers the packs with a segmentation method. A test keeps it equal to `rerankerSupportedLanguages` for the shipped registry and for a changed registry.
  - The embedding declaration of the default profile (`openai-3-small-1536` / `openai` / `text-embedding-3-small`, or `default_profile` in the file) is read from `config/rag/embedding-model-languages.json` when that file exists. The reader accepts `models` as a list of `{ provider, model, supported_languages }` or as an object keyed `provider/model`.
- **No new env variable, no switch, no migration, no new data store.** There is therefore no purge hook and no `rag_purge_store_inventory()` registration.

## Deviations

1. **[Rule 2] `scripts/rag/language-settings-context.js` (not in files_modified):** this is the "small helper the config server uses" that the plan asks init-env to share. It holds the reranker table, the declarations reader, the complete-pack filter and the atomic writer, so the two scripts cannot drift.
2. **`verifiedAgainstActiveProfile` is always false in both scripts.**
   - The plan implies the config server reports true when the declarations file exists. But neither script reads the active profile pointer: the config server does not query the database, and D-07 says the default-profile check is "not verified against the active profile".
   - When the file exists, the embedding rule still runs (errors and blocked packs appear), but the flag stays false.
   - The parity test compares every field with the app adapter and expects the flag false for the script adapters. 03.2.1-01's "no database → default profile, flag false" case already matches this. If 03.2.1-01 wants a true flag from the config server, it must add an active-profile read there.
3. **The POST 400 `details` keep the validator's `id`** (`{ code, language?, id? }`, not only `{ code, language? }`), so the panel can name the profile or reranker (UI-SPEC 8.2: "language and profile names filled in").
4. **[Rule 1] `init-env.js` runs `checkAndCreateEnvFile()` only when it is the main module.** Before, requiring it created `.env.local` as a side effect. `config-server.js` `start()` already calls the function explicitly. `init-env.js` now also honours `MYRAG_CONFIG_ROOT`, as `config-server.js` does, so the spawn tests run against a temp root.
5. **`RAG_RERANKER=auto` does not exist on this branch.** `parseRerankProviderId` and the script table both treat `auto` as no reranker. Seam: when `auto` is added, its resolution must go into `rerankerDeclaration` (scripts) and `activeRerankerDeclaration` (app). The parity test asserts the two agree for `auto`.
6. **`resolveEffectivePipeline` (04.1-04) is not on this branch.** GET reports the raw pipeline values with an `explicit` flag. Plan 56 decides notice or blocking from that, which is the D-02 data the resolver seam needs.
7. **The guard tests for the new paths are in `config-server-languages.node-test.mjs`** (cross-site POST, foreign Host on GET and POST), not added to `config-server-security.node-test.mjs`. That file only tests masking.
8. In the Task 2 test, the expected primary for answer `3,1` was corrected: the primary list is shown in registry order, so choice `1` is `zh`.
