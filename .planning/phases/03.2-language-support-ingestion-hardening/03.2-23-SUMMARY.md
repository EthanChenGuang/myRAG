# Phase 3.2 Plan 23: Language-aware sentence splitting on the Docling path Summary

**When a parse request has `language_aware: true`, the sidecar's Docling chunker cuts over-long text at the sentence ends of the text's own language (。！？ for zh, .!? for en and it, never at a semicolon). It packs sentences up to the available token budget with the chunker's cl100k_base tokenizer and hard-splits only a single over-long sentence. The Python splitter is a twin of `src/lib/rag/lang/sentences.ts`, and one shared case file holds the two equal. Without the flag, the chunker is the unmodified `HybridChunker`.**

## Behaviour

- **Off (the default `language_aware: false`):** `build_chunker` returns a plain `HybridChunker` with the same arguments as before. The chunks equal a direct `HybridChunker` run, and `test_ingest_fixture_recordings.py` (byte-equality of the recorded fixtures) passes unchanged.
- **On, with `languages` and `primary_language`:** each over-long text chunk is split by the twin splitter. Chunks that hold a table go through the parent's table branch, so header repetition is unchanged; a test checks that the table chunks and headers are identical with and without the flag.
- **On, without a primary language:** parent behaviour, the same as the TS chunkers.
- **Within a segment, sentences are re-joined with nothing for zh and with one space for en and it,** so whitespace between sentences inside an over-long item becomes the joiner. This is the same as the TS chunkers.
- **App side:** nothing sends `language_aware: true` yet. Plan 03.2-21 adds it to the inline request and the snapshot when `RAG_LANGUAGE_AWARE_INGEST=on`, so the sidecar is deployed first, as Pitfall 17 requires.
- **No new switch, env variable, migration, contract field or store.** No purge hook or `rag_purge_store_inventory()` registration was needed.

## Deviations from Plan

- **The table delegation is wider than in the research sketch.** The sketch delegated only a single TableItem when `repeat_table_header` was on. The override delegates any chunk that contains a TableItem, so table text never takes the language rule. This matches "table rows are never split" in the TS chunkers.
- **The non-tiktoken guard is new.** If the chunker's tokenizer is not a tiktoken `Encoding`, `segment()` uses the parent. The adapter always builds an `OpenAITokenizer`, so this is defensive only.
- Otherwise the plan ran as written.

## Notes and deferred

- **Hard-split cost:** the hard split of one very long sentence with no sentence end re-encodes the remaining text on each cut, as `graphemeSafeHardSplit` in TS does. Windowed encoding would change token boundaries and break parity, so it was not done. Cost is bounded by text length times the number of cuts.
- **Operator actions:** none. No live API was called.
