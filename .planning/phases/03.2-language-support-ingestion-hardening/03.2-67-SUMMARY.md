## Branch taken: `always`

From `eval/decisions/03.2-table-header-default.json` (`reason: gain_without_regression`; band 0.02; runs off `224401d6-dea7-4966-8019-54d56649b422`, on `2409bb81-803b-4316-8156-8691fbd85804`; source `eval/reports/phase32/comparison.json` sha256 `a3942bf0…`):

| category:table_split (5 counting items) | profile | always | paired diff | beyond band |
|---|---:|---:|---:|---|
| mrr | 0.866667 | 1.0 | +0.133333 | yes (up) |
| recall_at_5 | 1.0 | 1.0 | 0 | no |
| recall_at_10 | 1.0 | 1.0 | 0 | no |
| false_refusal_rate | 0.0 | 0.0 | 0 | no |

There are 48 other gated rows (overall, language:*, category:cross_lingual, pair:*). Two are non-zero, both up and inside the band: language:en mrr +0.006944 and overall mrr +0.002801. Those two come from the same table_split items. No gated slice drops, so `failing_slices` is empty.

The rule, as fixed in code (`TABLE_HEADER_RULE`): the default becomes `always` only if at least one table_split metric improves by more than the band, and no gated slice, table_split included, drops on any metric by more than the band. Otherwise it stays `profile`, with reason `no_gain`, `regression` (the failing slices listed) or `insufficient_evidence`. Insufficient evidence covers: no comparison, not schema 3, no arm, arm not run, no counting rows, or no counting table_split item. `--check` recomputes the record and fails if the committed file differs. The record keeps its date, so reruns write the same bytes.

## Deviations

1. **`phase_compare.py` was extended and `comparison.json` regenerated** (neither is in the plan's file list). The plan-66 output kept only judged rows over all items. The record must carry every other gated slice's difference, the counting table_split values and the run ids, and the rule must read counting items. The new fields are additive, and every existing field is byte-identical after the rerun.
2. **CI legacy smoke tiers are not pinned to `profile`.** Those tiers check that an explicit `RAG_PIPELINE=legacy` run equals the committed default baselines, with paired all-zero. Pinning `profile` there would compare a `profile` build with the `always` baseline, unless a second ingest baseline were kept just for them. Instead, `profile` is pinned in every test that asserts pre-phase chunking: the all-off probe, `defaults-equal-phase3` and the two snapshot tests. Both legacy tiers pass all-zero against the re-recorded baselines.
3. **The evidence is fixture (wiring-proof) evidence.** Plan 66's notes say a fixture comparison is never a reason to flip a default. D-19 as amended by the owner, and this plan, direct the decision from plan 66's committed comparison by a fixed rule, so I followed the plan. The record carries `wiring_proof: true` and a caveat naming the 03.2-53 live checks.
4. **Help text unchanged.** The help line describes what the switch does and names no default, so only the `selected` option changed. The zh and it strings in `ingest-impact.js` stay in parity.
