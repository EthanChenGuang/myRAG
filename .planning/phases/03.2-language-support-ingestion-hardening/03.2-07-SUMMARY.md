## Behaviour

- **Reader:** `getLanguageSettings()` reads the raw `process.env` values (env.ts turns unset into `''`, see 03.2-03), caches the result and never throws. It returns `{ configured, languages, primary, monolingual }`. `configured` is true only when the registry-level rules pass (non-empty set, all codes known, primary in the set, complete packs). Otherwise it returns `{ configured: false, languages: [], primary: null, monolingual: false }`. It never hands back a partly repaired set.
- **Validator result:** `{ ok, errors, warnings, verifiedAgainstActiveProfile, normalized }`. `normalized` is `{ languages, primary, supported }` in registry order when `ok`, else null. Savers write `normalized.supported` back.
- **Error order:** empty_set, unknown_language (sorted by code point, so the input order has no effect), primary_not_in_set, incomplete_pack, embedding_profile_unsupported, reranker_unsupported. Inside each kind, errors follow registry order. Error objects are `{ code, language?, id? }`. An empty set with no primary gives both `empty_set` and `primary_not_in_set`. `groundedness_not_checked` is only a warning.
- **Normalization:** codes are trimmed and lower-cased for ASCII letters only. `zh-CN` becomes `zh-cn`, which is `unknown_language`. A full-width `ｚｈ` stays `unknown_language`. Nothing is ever mapped to a registry code.
- **Embedding profile:** the app passes `embeddingProfile: null`, so the result says `verifiedAgainstActiveProfile: false`. When a profile is given, the rule is enforced (covered by cases).
- **Rerankers:** `RAG_RERANKER=none` (or an unsupported value) applies no reranker rule. `parseRerankProviderId` is tested to match `loadRagConfig`.
  - cohere and voyage declare the packs with golden slices (the languages they are evaluated on): zh, en, it today.
  - local_bm25 declares every pack with a segmentation method.
  - Both lists are read from the registry, so there are no literals.
- No new switch and no env variable. Retrieval and ranking are unchanged: `supportedLanguages` is declared only, and no stage reads it.

## Deviations

1. **[Rule 2] `src/lib/rag/rerank/languages.ts` (not in files_modified):** this module holds the reranker declarations. The validator needs the active reranker's languages without building an adapter, which would need an API key. `settings.ts` reads raw `RAG_RERANKER` here and does not import `deps.ts`/`config.ts`, which avoids a future import cycle when `loadRagConfig` consumes the settings (research Pattern 1).
2. **[Rule 3] Test fakes:** four test files that build a full `Reranker` object gained `supportedLanguages: []`, because the field is now required.
3. **Hosted reranker declaration rule:** the plan says "the registry codes they are evaluated on today (zh, en, it)". This is implemented as packs with `fixtures.golden_slices`, so a future pack without golden slices is not declared automatically.
4. **Task 1 and Task 3 have no separate RED commit.** A Task 1 RED would have failed on module-not-found, and Task 3 needed a new module as its seam. Task 2 has a real assertion RED.
5. `check-language-literals.mjs` (plan 02) is not on this branch, so it was not run. The new src files contain no zh/en/it literal list.
6. **Extra tests:** the `.cjs` completeness rule is checked against `packMissingParts` over `tests/fixtures/rag/language-pack-completeness-cases.json` (drift guard, T-03.2-072). There are also a no-repair test and a revalidation check on every `ok` case.
