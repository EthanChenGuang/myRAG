# Phase 03.2 Plan 39: Link allowlist and the ingestion link check Summary

**With `RAG_INGEST_LINK_CHECK=quarantine`, a document whose text (or PDF link annotation) points at a URL, bare domain or e-mail address outside `RAG_OUTPUT_LINK_ALLOWLIST` and the app's own host goes to the admin quarantine with the targets as the reason. Clean documents in zh, en and it pass. A release covers that document's reviewed targets on its later versions and never widens the allowlist.**

## Accomplishments

- `link-allowlist.ts` is a pure module. It parses the allowlist into a normalized host set and always adds the host of `NEXT_PUBLIC_SITE_URL`. A host matches when it equals an entry or ends with `.` + entry, after WHATWG URL parsing, lower-casing, punycode and trailing-dot removal. `evilexample.com`, `example.com.evil.org` and `notexample.com` do not match `example.com`.
- `extractLinkCandidates` in `url-extractor.ts` finds scheme URLs, e-mail addresses, `www.` hosts and bare hosts. It handles CJK text around a link. `extractURLs` is unchanged; a test pins its output on the old file.
- `checkLinks` normalizes, filters by the allowlist, skips released targets, de-duplicates and sorts by kind and then target. It keeps at most 100 and counts the rest. Its result is validated with the generated `LinkCheckResultSchema`.
- `scan_injection` registers `links` as its third check. `flag` records `metadata.link_check`. `quarantine` also adds one `untrusted_link` reason, and the chunks are written quarantined. The log line carries the mode and the counts only.
- Migration 0817 adds `rag_released_link_targets`. The stage reads it for versions after the first.
- The fixtures are deterministic (stdlib only). The real sidecar checker (`check_hidden_text`) reports `https://outside.example.net/reference/overview` for `bad-annotation.pdf` and the allowlisted target for `clean-annotation.pdf`; this was checked locally with the `preflight` extra.

### Rules fitted on the fixtures (config/rag/link-rules.json, rules_version 2026-11-25.1)

- Schemes: http, https, ftp, ftps, ws, wss. A `www.` prefix makes a host count with any letter TLD.
- Bare hosts count only when the last label is lower case and in: com, net, org, info, biz, io, co, app, dev, ai, xyz, online, site, top, club, shop, store, live, link, click, cn, hk, tw, jp, kr, it, eu, uk, de, fr, es, nl, ch, ru, ca, au, br.
- These English-word labels were left out on purpose: at, be, in, me, us. Without that, sloppy text such as `set.In` would read as a domain.
- File extensions that are never domains: pdf, doc(x), xls(x), ppt(x), csv, tsv, txt, md, rtf, od*, json, xml, yaml, yml, html, htm, the image, archive and code extensions, log, bak, tmp, ini, cfg, conf, and the media extensions.
- max_targets: 100.
- Clean fixtures contain `report.pdf`, `notes.docx`, `v2.0`, `3.2.1`, `e.g.`, `i.e.`, `Art. 5`, `第3.2条`, `data.json`, `1.4.2`, an allowlisted URL and an address at the allowlisted domain. None is quarantined.

## Operator actions

- Apply migration 0817 (idempotent). Deploy order: the migration before the app. An app without it would only fail the read, which is logged and treated as no reviewed targets.
- Set `RAG_OUTPUT_LINK_ALLOWLIST` before switching `RAG_INGEST_LINK_CHECK` to `quarantine`. An empty list quarantines every document with an external link.
- PDF annotation checks need `RAG_HIDDEN_TEXT_CHECK` at `flag` or `quarantine` and a reachable sidecar.

## Decisions for STATE

- A release records reviewed link targets per document lineage. They are skipped on every later version of that lineage only, and `RAG_OUTPUT_LINK_ALLOWLIST` is never written by a release.
- `link-allowlist.ts` is the single host-matching rule for ingestion and for SEC-06 (Phase 5.2).
