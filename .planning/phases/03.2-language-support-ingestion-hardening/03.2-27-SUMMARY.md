# Phase 3.2 Plan 27: Table header repetition and carry-forward in the TS chunkers

**With `RAG_TABLE_HEADER_REPEAT=always`, every table chunk in all six processing profiles starts with its header. A table that continues another one without its own header (for example after a page break) takes the previous table's header, and its chunks carry `metadata.table_header_carried = true`. With `profile` (the default), chunking is byte-identical to before.**

## Behaviour

- **`profile` (default).** `chunkDocument` and `buildProfileChunks` pass the processing profile's own chunker object and run no carry pass. `config/rag/processing-profiles.json` is not edited.
- **`always`.**
  - `effectiveTableHeader` sets the header flag to true for every profile. `chunkDocument` (ingest chunk stage), `buildProfileChunks` (embed-write stage and `rag:rechunk`) and the structure branch of `chunkParentChild` receive the chunker with that flag.
  - Before any chunker runs, `carryTableHeaders` rewrites each continuation table under the previous header. A continuation is a table that:
    - follows a table with a header, with only blank lines between them,
    - has the same column count,
    - has a first row that is not header-like.
  - The continuation's first row becomes a data row again and its separator row is dropped.
  - Chunks and children that hold a carried row get `metadata.table_header_carried = true`. Chunks of the first table do not.
- **Never changed.** Rows are never split. Tables stay parents under parent-child chunking. A header-only table is one chunk with the header once. Docling's own chunks are returned unchanged; the Docling-document rule is plan 03.2-28.
- **Overlap.** The `markdown_sections` profiles (overlap 64) can repeat the last rows of one chunk at the start of the next. Under `always`, such a chunk still starts with the header. The test checks that every row appears, in source order, as one contiguous run per chunk, rather than exactly once.

## Fitted thresholds (`config/rag/table-header-rules.json`, rules_version 2026-11-25.1)

| Measure | Real headers (6 fixtures) | Data rows (360, plus the 3 continuation first rows) | Threshold |
|---------|------|------|------|
| Share of non-empty cells that are not numeric | 1.0 | 0.6 (every row) | ≥ 0.8 |
| Share of non-empty cells that reappear in the same column | 0.0 | 0.6 (every row) | ≤ 0.3 |

The thresholds sit at the midpoint of the gap, and both conditions must hold. Every real header is header-like and no data row is. A cell is numeric when it matches `numeric_cell_pattern` (`^[+-]?\d+(?:[.,  ]\d+)*\s*%?$`; it covers `2,530`, `387.8` and `12 %`, and not `Survey week 05`). The same pattern compiles in JavaScript and Python. The thresholds were measured with a one-off script over `eval/fixtures/ingest/text/long-table-*.md`.

## Known limits

- **Numeric header rows.** A real header whose cells are mostly numeric (for example only year columns) is not header-like. If such a table directly follows a table with the same column count across blank lines, it would take the previous header. This happens only under `always`, and every carry is recorded in `metadata.table_header_carried`.
- **All-text data rows.** A continuation whose first data row is all text with unique values reads as header-like, so nothing is carried. This falls back to today's behaviour.
