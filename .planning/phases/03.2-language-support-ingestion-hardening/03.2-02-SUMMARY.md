# Phase 3.2 Plan 02: Registry-derived Language type and literal check Summary

**The contracts' `Language` type now comes from `config/rag/language-packs.json`, and CI fails on a new hard-coded `zh/en/it` union, tuple or list outside an owner-tagged allow-list.**

## Accomplishments

- `contracts/languages.py`: `language_codes(registry)`, `build_language_type(codes, extra=())` and `LANGUAGE_CODES` / `Language` built at import from the default registry. The validator rejects unknown codes ("unknown language code ..."), the schema is an explicit enum in registry order.
- `golden.py` imports `Language` (`from .languages import Language`); `ingest.py`, `query.py`, `retrieval.py` import it too. Field names, optionality and defaults unchanged. `samples.py` builds `ocr_languages` from `LANGUAGE_CODES`.
- `npm run gen:schemas` produces no diff under `rag-sidecar/schemas`, `contracts.generated.ts` or `tests/fixtures/contracts/samples.json`.
- Drift proof (run by hand, then restored): adding a fourth pack `qx` to the registry and running `npm run gen:schemas` changed 7 generated files (188 insertions), so the existing drift job fails when the registry changes without regeneration.
- All 210 non-empty lines of `eval/fixtures/golden.jsonl` and `eval/fixtures/ingest/golden-ingest.jsonl` validate (asserted ≥ 192); `language: "xx"` is rejected by Pydantic and by the generated Zod (`tests/contracts.test.ts`).
- `check-language-literals.mjs`: scans `src/`, `rag-sidecar/src/`, `eval/src/`, `scripts/` (`.ts .tsx .mts .js .mjs .cjs .py`); exempts the registry and its copy, `contracts.generated.ts`, `rag-sidecar/schemas/`, and any `tests`, `fixtures` or `__tests__` segment; `--root` and `--allowlist` for the self-test. On the repository: `ok: 886 file(s) scanned, 24 allow-listed file(s), codes zh, en, it`.

With the config directory missing, the import now fails with `RagConfigMissing` naming `language-packs.json` (previously the first missing file was `parse-routing.json`, at first use). `test_image_config.py::test_a_missing_config_fails_with_an_error_that_names_the_paths_it_tried` updated to that path.
