# Phase 03.2 Plan 45: Supersession detection, Replaces… and admin routes Summary

**After publish, a rules-only detector flags likely older versions as pending candidates. An uploader can name the document a new one replaces, and admins decide candidates for their own workspace. Nothing is superseded without an admin's confirmation.**

## Accomplishments
- The detector runs as a post-publish hook, only while `RAG_SUPERSESSION_DETECT=on`. It never delays or fails ingestion and makes no model call. It reads a bounded peer set through 0819 and raises candidates through 0806 (`origin detected`).
- Two rules, with all thresholds stored as data:
  - **Title rule:** titles that are equal once the registry's version markers are removed.
  - **Content rule:** stored contents that overlap strongly while their numbers differ.
- Direction comes from the year marker, then `doc_date`, then `effective_from`. If none of these decides, there is no direction and the admin chooses.
- "Replaces…" is accepted on both upload routes and carried through the queued input. An admin's choice is confirmed right after publish; a member's becomes a pending candidate.
- The picker defaults report `replaces: { enabled, confirmedAtOnce }`.
- New admin routes under `/api/rag/admin/supersession`: list, confirm, dismiss and undo.
