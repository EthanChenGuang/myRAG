<objective>
Make sure expansion can reach the reranker whatever the candidate pool and rerank cap are, without ever letting an expansion-only hit outrank an original one.

Purpose: TERM-06 on real corpora. RRF arithmetic puts every chunk found only by `term:0` below every chunk an original list ranks in its first `rrf_k` places or so; with full original lists such a chunk never enters the rerank input at any cap, and the fixture corpus hides this because it is smaller than the pool (RESEARCH "Reach beyond the pool", D-34). Phase 4.2 lowers the cap floor to 25 (LAT-01, RNK-02), which makes it more certain. This plan adds the bounded reservation of D-34 and proves reach with full lists.
Output: reserve.ts, its wiring in the search stage, a unit test and a search-stage test with full fake lists.

Rules for every task: code is named by symbol and re-read at execution time (D-38); every value of the pool, the cap, the leg weights and `rrf_k` is read from the effective retrieval params at run time or passed explicitly by the test (D-34); test data uses D-37 placeholder chunk ids and texts.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan.
</objective>
