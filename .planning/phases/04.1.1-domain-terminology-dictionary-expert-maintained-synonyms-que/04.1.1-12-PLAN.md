<objective>
Turn missed queries into a review list: a miner that proposes candidate terms per tenant and admin routes to accept (through the normal create path) or dismiss them.

Purpose: the review half of TERM-09 (D-26, PO-7). Coordination (CONTEXT D-25a, FBK-07 amendment): `rag_term_misses` is the interim miner source because this phase ships first. Phase 5.1.1's `rag_retrieval_log` replaces it as the miner source behind the single reader `readMisses()` (a one-file change made by 5.1.1 or a follow-up), after which `RAG_TERMINOLOGY_MINING` recording is retired. Phase 5.1.1 never writes `rag_term_*` tables: its expert-labelled pairs arrive as `DictionaryCandidate` JSONL through the plan-11 import (dry run, then apply). The reserved `source` values `feedback` and `langfuse` stay unused unless 5.1.1 chooses to feed this log instead.
Output: miner, CLI, candidate service and routes, tests.

Ordering: `src/lib/rag/index.ts` is edited by plans 17, 09, 11 and 12 in that order.

Rules for every task: code and SQL are named by symbol and re-read at execution time (D-38); every test term is a D-37 placeholder (a mined term such as 术语丁戊 or termdelta that is in no dictionary and no corpus chunk of the test); logs carry counts only.

Execution note: builds PGlite databases; do not run alongside another fixture-database plan in the same tree.

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan.
