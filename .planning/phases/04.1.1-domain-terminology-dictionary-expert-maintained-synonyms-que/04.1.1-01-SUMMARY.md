# Phase 4.1.1 Plan 01: Terminology contracts Summary

**Every terminology shape (entries with the translation-pair encoding, params, matches, expansion, preview, import, candidates and the TerminologyLexicon read contract) is now one Pydantic v2 model with generated, parity-checked Zod. The `terminology` stage name is registered for the eval contract.**

## Performance

- **Duration:** about 45 min
- **Tasks:** 2
- **Files modified:** 25

## Accomplishments
- `contracts/terminology.py`: TerminologyEntry, TerminologyImportRow (the nine D-23 columns), TerminologyParams (defaults 8/4/24/0.5/0.5/2/2, bounds per D-17 and D-34), TerminologyMatch, TerminologyExpansion, TerminologyPreviewRequest/Response, TerminologyValidationIssue, TerminologyImportReport, TerminologyCandidate, TerminologyLexiconTerm, TerminologyTranslationPair and TerminologyLexicon. All are frozen with `extra='forbid'`.
- Language fields use the Phase 3.2 registry type: `Language` for source/target/candidate, and `TermLanguage` (registry codes plus `any`) for entries, matches and lexicon terms. `terminology.py` writes no language code.
- Translation-pair rules (D-04, D-32) live in one validator. A translation needs both languages, they must differ, `language` must equal `source_language` and the mode must be `one_way`. Every other kind must leave both fields null.
- `StageName` gains `terminology` between `decompose` and `semantic_cache`, and `StageTimeoutsMs.terminology` is added. `RagRunOptions` accepts both.
- 13 schemas exported, samples added (plus `TerminologyEntry:translation_pair` and `TerminologyEntry:suppression` variants, placeholder vocabulary only), Zod regenerated with `npm run gen:schemas`.
