# Phase 4.1.1 Plan 03: Terminology Schema Summary

**Migration 0471 adds the terminology dictionary tables. They are readable only by service_role. The one read retrieval uses, `rag_term_effective`, is checked against the tenant key and proven in both deployment modes, including a two-tenant isolation suite.**

## Performance

- **Duration:** about 45 min
- **Completed:** 2026-11-26
- **Tasks:** 2
- **Files modified:** 2 (both new)

## Accomplishments

- `rag_term_layers`: `layer_key` primary key, `version bigint DEFAULT 0`, `entries_sha256`, `updated_at` and `updated_by`.
- `rag_term_entries`, with these CHECKs:
  - layer key: `shared` or the `TENANT_KEY_RE` shape;
  - language: shape only;
  - kind and mode: closed sets;
  - suppression rows: on a tenant layer only, with no variants;
  - variants: 1 to 16, none NULL or empty;
  - translation pairs: both languages set exactly for `translation`, different from each other, neither `any`, `language = source_language`, mode `one_way`.
- Unique indexes on `rag_term_entries`:
  - `(layer_key, language, COALESCE(target_language,''), lower(canonical))` for rows that are not suppressions;
  - `(layer_key, suppresses_entry_id)` for suppressions.
- A GIN index on `normalized_variants`.
- `rag_term_audit` with a closed action set. UPDATE, DELETE and TRUNCATE are blocked by triggers that raise `rag_term_audit is append-only`. The trigger function has an empty search_path.
- Privileges: RLS is on with no policies. Everything is revoked from PUBLIC, anon, authenticated and service_role, then SELECT is granted to service_role only.
- `rag_term_effective(p_tenant_key)`:
  - checks the key with `public.rag_assert_tenant_key` first, so `shared`, malformed keys and keys from the other deployment mode raise 22023;
  - returns enabled shared entries the tenant has not suppressed, then the tenant's own enabled entries;
  - returns the columns `layer` (`shared` or `workspace`), the two language columns, `shared_version` and `tenant_version` (0 when the layer row is missing);
  - is SECURITY INVOKER, STABLE, with `SET search_path = ''` and every name schema-qualified;
  - is revoked from PUBLIC, anon and authenticated and granted to service_role; ends with `NOTIFY pgrst`.
- The file is idempotent: applying it twice keeps the rows, the audit lock and the grants.

## Decisions Made

See `key-decisions` in the front matter. Decisions to record in STATE:

- 0471 is the number in use.
- `rag_term_effective` is SECURITY INVOKER.
- Suppressions cascade when the shared entry they hide is deleted.
- Variant length and the per-layer limit are enforced by the writers and the app, not by SQL.

## Deviations from Plan

**1. SECURITY INVOKER instead of SECURITY DEFINER for `rag_term_effective`**
- **Why:** The plan's must-have and CONTEXT D-07 say DEFINER. The execution brief for this run says the read function is SECURITY INVOKER, and 0705's service-role read functions use INVOKER.
- **Effect:** Access is the same (service_role only, tenant key asserted, empty search_path), and the function cannot read past what its caller can read directly. The test asserts `prosecdef = false`.
- **Follow-up:** The 0472 writers remain SECURITY DEFINER. Plan 14's lock-down block should list this function under its revoke and grant, the same as the DEFINER functions.

**2. One RED commit for both TDD tasks**
- Both tasks edit the same two files, so the failing tests for Task 1 and Task 2 went into one test commit, followed by one migration commit.

**3. `createEmptyFixtureDatabase` instead of `createFixtureDatabase`**
- The migration stack is the same; only the corpus load is skipped, which this schema test does not need. The fake-edge case runs on the same database.

**4. Extra constraints beyond the listed behaviour**
- Variant count 1 to 16 with no empty element, the closed kind, mode and action sets, the `entries_sha256` hex shape and `version >= 0`. All come from D-04, D-05 and D-06.
