# Phase 4.1.1 Plan 04: Terminology Writers Summary

**Migration 0472 adds the only way to change the dictionary: six service-role functions. Each checks the actor against the layer, bumps the layer version once, recomputes `entries_sha256` and writes its audit rows in the same transaction. Imports are all-or-nothing. All of it is proven on PGlite in both deployment modes with two admins and two tenants.**

## Accomplishments

- `rag_term_upsert_entry(p_actor, p_layer_key, p_entry jsonb, p_expected_version)`:
  - no `id` in the JSON creates an entry; an `id` replaces that entry of the layer;
  - returns `entry_id`, `layer_version`, `entries_sha256` and `action`.
- `rag_term_delete_entry(...)`: deletes the entry. For a shared entry it first audits, as `unsuppress`, every tenant suppression the cascade will remove, and bumps those tenant layers.
- `rag_term_set_suppression(...)`:
  - the suppression row copies the shared entry's canonical, kind, mode and languages and has no variants;
  - audits are `suppress` or `unsuppress` on the tenant layer, with `entry_id` set to the shared entry id;
  - the shared layer itself is refused with `invalid_entry`.
- `rag_term_apply_import(p_actor, p_layer_key, p_rows jsonb, p_mode, p_expected_version)`:
  - parses every row first, then writes;
  - duplicate keys in the file, a bad row or a CHECK violation abort everything (`invalid_entry`, with DETAIL `{"row": n}` where a row is known);
  - merge key is `(language, COALESCE(target_language,''), lower(canonical))`;
  - `replace` also deletes absent entries but keeps the tenant's suppressions;
  - limits: more than 5,000 rows, or more than 20,000 entries in the layer afterwards, raises `limit`;
  - returns created, updated, unchanged and deleted counts.
- `rag_term_list_entries(...)`: one page, at most 100 rows. Suppression rows are included, marked by `suppresses_entry_id`. `p_search` is a case-insensitive substring match (`strpos`, so `%` is literal) on canonical and variants. Each row carries `layer_version` and `total_count`.
- `rag_term_list_audit(...)`: newest first, by layer version, then time, then id. Actors are ids only; nothing joins `auth.users`.
- Authorization (in `rag_term__authorize`):
  - `not_admin` when the actor is not in `admin_users`;
  - `shared` is open to any admin;
  - in single-tenant mode, every other layer gets `workspace_layer_unavailable` (detected the way `rag_admin_tenant_keys` does it);
  - otherwise the layer key must be in `rag_admin_tenant_keys(p_actor)`, else `not_admin_of_layer`.
  - An entry id of another layer is `not_found`.
- Versions (in `rag_term__bump`):
  - creates the layer row at 0 if needed and locks it `FOR UPDATE`;
  - a NULL or stale expected version raises `version_conflict` with DETAIL `{"current_version": n}`;
  - increments the version, sets `updated_by` and `updated_at`.
- The writers do not normalize. `normalized_variants` are stored as sent and must have the same length as `variants`. Each variant may be at most 64 characters. Enabled is a JSON boolean, and every string field must be a JSON string.
- No language code appears in the migration (D-35). The tests take codes from `config/rag/language-packs.json`.
- Privileges:
  - the six functions are SECURITY DEFINER with `SET search_path = ''`, revoked from PUBLIC, anon and authenticated, and granted to service_role;
  - the helpers are revoked from everyone, service_role included;
  - 0410 section 1 has guarded entries for the six functions.

## Deviations from Plan

**1. Internal helpers are SECURITY INVOKER, so two acceptance greps differ**
- The plan asked for definer helpers with no grant. `tests/rag/search-rpc-grants.test.ts` fails any SECURITY DEFINER function that is not granted to service_role. Granting the helpers would let service_role bump a version or rewrite the hash without an audit row.
- **Decision:** the helpers are invokers with `SET search_path = ''` and no grant. They run as the owner inside the definer writers. The test asserts `prosecdef = false` and no EXECUTE for anon, authenticated or service_role.
- **Effect on the greps:**
  - the SECURITY DEFINER count is 6 (the six public functions), not >= 7;
  - the `SET search_path = ''` count (13) is above the definer count, because the invokers carry one too.
  - The intent behind both greps still holds: every definer function has the empty search path, which the vitest scanner enforces.

**2. `entries_sha256` ignores the row id and orders by content**
- This follows the behaviour "equal for equal content", which `ORDER BY id` would break after a delete and re-create. The layer key stays in the hashed JSON.

**3. 0410 edited (not listed in files_modified)**
- Required by `search-rpc-grants-pglite.test.mts`. This is the standing rule that every new privileged function gets a guarded 0410 entry.

**4. Extra behaviour beyond the listed cases**
- version_conflict DETAIL with the current version, which plan 09 needs for its 409 body.
- Import row DETAIL.
- Re-suppressing re-enables a disabled suppression row.
- Upsert collision is `invalid_entry`.
