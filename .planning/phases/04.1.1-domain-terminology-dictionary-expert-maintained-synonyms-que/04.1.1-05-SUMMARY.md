# Phase 4.1.1 Plan 05: Terminology tracer Summary

**Under v2 with lexical search on, an informal variant in the standalone query now loads the tenant's dictionary, matches, expands into a separate lexical-only `term:0` RRF list weighted at `expansion_weight` × the lexical leg weight, and shows up in the trace as counts and a version only. With `RAG_TERMINOLOGY=false` (the default) nothing runs and the stage is recorded `disabled`.**

## Accomplishments

- `normalizeLexical()` exported from the tokenizer. It is the module's `normalize` and adds no behaviour; `LEXICAL_VERSION` is unchanged (D-09).
- `matcher.ts`: longest-match-first, left-to-right, non-overlapping matching over normalized text. Han edges match as substrings; Latin edges need a token boundary. Han-only surfaces shorter than `min_han_chars` are left out. Entries of kind `translation` are never added (D-10, D-11, D-32).
- `expand.ts`: one hop only. `one_way` adds the canonical; `equivalent` adds the canonical and the other members. Terms are tokenized with `queryLexicalTokens`, deduplicated against the original query's tokens, and capped by `max_matches`, `max_terms_per_match` and `max_expansion_tokens` from `TerminologyParamsSchema.parse({})`. Any cut sets `capped` (D-13, D-17).
- `load.ts`: the only module that calls `rag_term_effective`. It calls it on the service-role client from `getRagDeps()` with `scopeKey(scope)`. It keeps every entry (translation pairs included) and both versions, and caches the dictionary and its matcher per tenant key: LRU 256, TTL 60 s, `invalidateTerminologyCache(key | 'all')`, and `bypassCache` for the preview (D-22, D-33).
- Stage: `runTerminologyStage` runs as `runStage(spec('terminology', 'skip'))` on the standalone query only. A load failure or timeout records `skipped`, so the request is `degraded` by `deriveStatus` and continues without expansion (D-15, D-21).
- Search: when the expansion has tokens and lexical search is usable (switch on, ICU available), one `backend.search` runs inside the existing `Promise.all`. It uses `denseVector: null`, `denseLimit: 0`, `lexicalLanguages: null`, the effective `candidate_pool_size`, and the same scope, filters, chunking override and signal as the variant legs. Its hits become `{ id: 'term:0', weight: expansion_weight × leg_weights.lexical }`, fused with the other lists. The delegated (query framework) path passes the same list as an extra list (D-16, D-34).
- Harness: `terminologySeed` rows are written as the database owner, with `normalized_variants` from `normalizeLexical` and a version-1 `rag_term_layers` row per layer. Both fixture modes support it, and `prepareInProcessEval` passes it through (D-27).

## Phase 6 branch (D-40)

Phase 6's query layer is on trunk, so the "present" branch applies:
- With the layer active, `runQueryLayer` calls the new `afterTransforms(standalone)` hook after the parallel transform group has settled and the plan is built, and before `runSemanticCacheStage`.
- With the layer off, or when it returns early because `query_gate` was skipped, `runQueryStages` runs the stage after the Phase 4 `translate` stage on the request query.
- On a small-talk short-circuit it does not run.

The Phase 6 variant-cap accounting (D-31) is plan 07's job. Until plan 07 lands, a request with the switch on can make one more search than Phase 6's `max_searches`; the switch is off by default.

## Deviations

- **Files outside `files_modified`:** `src/lib/rag/query/run-layer.ts` gained the optional `afterTransforms` hook. Without it the stage cannot sit between the layer's join and `semantic_cache`. With the hook absent, the layer behaves exactly as before. `tests/rag/terminology/term-leg.test.ts` was added for the T-0411-46 mitigation ("asserted on the fake backend's recorded request").
- **TDD for Task 2:** everything Task 2 specifies (caps, hop, cache, failure) shipped with Task 1's implementation, because the tracer needed the loader, matcher and expansion. So Task 2's cases were written after that code and have no separate RED commit. Two first-run failures were test-side: `refs` records nothing without referenced documents, and disabled records were counted in the order check.
- **Stage-order edge:** see key-decisions. The order rule holds for every stage that ran, with one exception: with the layer on, layer translation off and `RAG_LEXICAL_TRANSLATION=true`, the Phase 4 translate stage runs after `semantic_cache` (Phase 6's order), so it also comes after terminology.
- **Matcher scope:** elision handling and identifier spellings are not in this matcher. Plan 06 hardens it without changing the interface.
- **Placeholder variants:** the tracer uses the made-up tokens `termalpha`, `vocealfa` and `termgamma`. A variant must share no lexical token with the corpus, and the D-37 Han placeholders all share the bigram `术语`. The zh entry therefore has a Latin variant.
