# Phase 4.1.1: Domain Terminology Dictionary - Research

**Researched:** 2026-11-24
**Domain:** query-time synonym expansion for hybrid (pgvector + verbatim tsvector) retrieval, zh/en/it; expert-maintained, tenant-scoped dictionaries; miss-log mining
**Confidence:** HIGH on the codebase findings (read at base e90d9cd), MEDIUM on default caps and weights (to be tuned by the 04-25 sweep tool), LOW on real-domain effect size (no real items yet).

## Summary

The v2 pipeline already has every seam this phase needs: an optional-stage runner with skip semantics, a variants list, a weighted RRF over per-variant lists, a lexical-only backend call, a per-request config hash, PGlite fixture databases that apply every migration, run configs, and a RAG Administration tab in the Config UI with a fetch helper and admin guard. Postgres cannot do index-time synonyms here, both because hosted Supabase does not allow dictionary files and because the Phase 4 lexical index deliberately bypasses the text-search parser. The recommended design is query-time expansion into a separate, down-weighted RRF list, with the dictionary stored in service-role-only tables, versioned and audited per layer.

**Primary recommendation:** query-time only; separate `term:0` RRF list at weight 0.5; Han substring longest-match with a two-character minimum; one-hop expansion; per-tenant cached matcher with 60 s TTL; switch off by default and proven on synthetic colloquial items, with real items gating later (EVAL-14).

## External Best Practice

- **Search-time synonyms are the default recommendation.** Elastic: "Search time is recommended because you can update your synonym sets without reindexing"; synonyms API sets are search-time only, with `updateable: true` analyzers reloaded on change; `synonym_graph` handles multi-word synonyms at search time. The cost is more query terms, judged worth it. [Configure synonyms in Elasticsearch](https://www.elastic.co/guide/en/elasticsearch/reference/current/search-with-synonyms.html), [Synonyms API blog](https://www.elastic.co/blog/update-synonyms-elasticsearch-introducing-synonyms-api), [Boosting the power of Elasticsearch with synonyms](https://www.elastic.co/blog/boosting-the-power-of-elasticsearch-with-synonyms), [Synonym graph token filter](https://www.elastic.co/guide/en/elasticsearch/reference/master/analysis-synonym-graph-tokenfilter.html).
- **Postgres dictionaries are file-based and index-time.** The `synonym` template reads `$SHAREDIR/tsearch_data/<name>.syn`; `thesaurus` adds phrases but must be applied at index time and needs a reindex on change; neither works through our verbatim tsvector builders. [PostgreSQL: Text Search Dictionaries](https://www.postgresql.org/docs/17/textsearch-dictionaries.html), [dict_xsyn](https://www.postgresql.org/docs/17/dict-xsyn.html). Hosted Supabase gives no write access to `$SHAREDIR` (not confirmed by a Supabase doc page in this pass; irrelevant to the decision because of the parser bypass).
- **Query expansion drifts.** Classic IR work shows expansion raises recall but can hurt precision when expansion terms dominate; standard mitigations are down-weighting expansion terms relative to original terms and capping their number (Carpineto & Romano, "A Survey of Automatic Query Expansion in Information Retrieval", ACM CSUR 2012). Our separate weighted RRF list is the fusion-level form of that down-weighting (Cormack, Clarke & Büttcher, "Reciprocal Rank Fusion outperforms Condorcet and individual rank learning methods", SIGIR 2009).
- **Directional synonyms.** Elastic/Solr distinguish equivalent (`a, b, c`) and explicit one-way (`a => b`) mappings; one-way avoids flooding a precise query with colloquial forms. We keep both (`mode`), default one-way.
- **Chinese.** Word segmenters split colloquial and abbreviated medical terms unpredictably (心梗 may stay one token or split); character n-gram indexing plus substring dictionary matching is the robust choice when the index is bigram-based, which ours is.
- **Expert-in-the-loop mining.** Mining zero-result queries for vocabulary gaps and routing them to curators (never auto-applying) is standard practice in site search (e.g. Elastic App Search / Algolia "no results" analytics feeding synonym curation). We mirror that: candidates only.

## Index-time Cost Estimate (for D-14)

If canonical terms were written into `lexical_text`, every edit touching variant v would require relexing every chunk whose tsvector contains any token of v, per tenant; for the shared layer that is every tenant. `rag:relex` processes 500 rows per batch (`DEFAULT_BATCH_SIZE`, `src/lib/rag/ingest/relex/run.ts:58`), so 100k affected chunks are 200 batches of tokenize-and-update; no throughput was measured in this pass (estimate unverified). A shared-layer edit would be a corpus-wide write across every tenant, and the effective `lexical_text` would then depend on a dictionary version, which the config hash and `lexical_version` do not capture today. Query-time expansion costs one extra parallel lexical query (≤ 24 OR terms) and an in-process trie lookup (microseconds) per request.

## Architecture

```
query ──► refs ─► analyze ─► translate ─► terminology (new, optional, skip on failure)
                                              │  load effective dictionary (cache, 60 s)
                                              │  match (Han substring / Latin boundary / identifier forms)
                                              │  expansion tokens (capped) ; optional dense variant ; hint for Phase 6
                                              ▼
embed (batched, + optional terminology variant) ─► search: dense:i, lexical:i (unchanged)
                                                           term:0 (lexical-only, weight 0.5)   ◄── new
                                                 ─► fuse (RRF) ─► dedupe ─► rerank ─► refusal ─► context
finish ─► trace (counts + version) ─► config hash (+terminology block when on) ─► miss log (opt-in)
```

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Cross-tenant leak of dictionary entries or mined queries | critical | Service-role-only tables, `rag_term_effective(p_tenant_key)` asserts the key, cache keyed by tenant, two-tenant tests for read, write, preview, mining df, candidates (plans 03, 04, 05, 07, 10, 11). |
| Expansion swamps original intent | high | Separate list, weight 0.5, caps; eval checks every non-term slice within noise. |
| Han false matches (one-character variants) | high | `min_han_chars` 2 rejected at write, property tests. |
| Dictionary failure turns strict mode into "temporarily unavailable" | medium | Stage is skip-on-fail → `degraded` with documents still answers; tested. |
| Off-switch changes behaviour (stage record, hash) | medium | Test asserts identical candidates, order, scores and hash with the switch off and a seeded dictionary. |
| PII in miss log | high | Opt-in, `maskPII`, length cap, 30-day purge, service role only, no logging of text. |
| CSV formula injection on export | medium | Prefix neutralisation (OWASP CSV injection guidance). |
| Migration number collision with parallel Phase 4.1 planning | medium | 047x block, re-check before writing (D-08). |
| Synthetic items overfit the fixture dictionary | medium | Items are report-only; default stays off until real items (5.1.1). |
| Lost updates between two experts | medium | `p_expected_version`, 409. |

## Validation Architecture

- Unit (vitest): normalizer parity with tokenizer; matcher (Han longest-match, overlap, min length, Latin boundaries, elisions, identifier forms); expansion caps and dedupe; validator (conflict, chain, cycle, overlapping sets); CSV parser and formula neutralisation; cache keyed by tenant.
- SQL on PGlite (both modes): schema, RLS/grants (anon and authenticated denied), version bump and audit per write, `version_conflict`, append-only audit, not_found for foreign tenants, import atomicity, suppression, miss purge, df restricted to tenant.
- Pipeline: tracer through `/api/internal/rag/run` (eval route) on a seeded PGlite: a colloquial query finds the gold chunk only with the switch on; switch-off identity; failure → degraded.
- Routes: admin guard, Zod 400 shape, workspace scope, two-tenant matrix.
- Eval: smoke tier with the new items; on/off comparison per slice; latency vs budgets.
- Contracts: `npm run gen:schemas` parity check in CI.
