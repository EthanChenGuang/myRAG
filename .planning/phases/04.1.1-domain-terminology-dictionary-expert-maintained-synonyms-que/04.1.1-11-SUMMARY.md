# Phase 4.1.1 Plan 11: Terminology CSV import/export and expansion preview Summary

**Experts can now import a CSV or DictionaryCandidate JSONL file into a layer, with a dry run that reports the diff and every validation issue, then an atomic apply that checks the version the dry run saw. They can export a layer as a CSV that is safe to open in a spreadsheet, and preview what a query will expand to, draft entries included, without writing anything.**

## What was built

- **CSV (`csv.ts`).** A linear state-machine parser and a serializer for the nine D-23 columns.
  - The parser never throws: a wrong header is one error on row 0, and a bad row gets its 1-based number.
  - Files over 1 MB or 5,000 rows are refused.
  - Export prefixes a cell that starts with `= + - @`, tab or CR with `'`. The prefix check also covers values that already start with quotes before such a character, so the round trip is lossless. Import strips exactly one leading `'`, and only before those characters.
  - Variants are neutralised one by one, so the variants cell is safe too.
- **Import (`import.ts`).**
  - Row → `TerminologyEntry`. The id of the stored entry with the same diff key `(language, target_language or '', lower(canonical))` is attached, so a row replaces its stored entry during validation.
  - `validateEntries` runs with the enabled languages from the Phase 3.2 settings module, and with the shared layer for a workspace import. In replace mode the current layer is empty.
  - Counts: create, update, unchanged, delete (replace mode only; suppression rows are never deleted).
  - Apply re-reads the layer, re-validates, checks `expected_version`, and calls `rag_term_apply_import` with normalized variants. It invalidates the cache for the layer.
- **Candidate adapter (D-25a).** `observed_term` becomes a variant, `canonical_term` the canonical, `relation` the kind. A translation takes `language` as its source and `canonical_language` as its target. Without `canonical_language`, the validator reports `invalid_translation`. `tenant_key` must equal the resolved workspace key.
- **Export.** `text/csv; charset=utf-8`, `attachment; filename="terminology-<layer>-v<version>.csv"`, `no-store`, `nosniff`. Rows are sorted by the diff key, and suppression rows are left out.
- **Preview (`preview.ts`).**
  - SQL checks the actor for each layer it reads.
  - `loadEffectiveDictionary(scope, { bypassCache: true })` loads the dictionary.
  - Drafts are validated and applied in memory. A draft with a stored id replaces that entry, and a workspace suppression draft hides its shared entry.
  - A fresh `buildMatcher` runs without translation pairs, then `expandMatches`.
  - Overrides are the validator's `override` warnings, computed from the workspace entries against the shared ones.
  - The response matches `TerminologyPreviewResponseSchema`. The query is never logged.

## Known limitation

A variant containing `|` cannot be written to CSV: the export would split it. The CSV import can never create one, but the single-entry API can. Plan 13 (the Config UI) or a validator rule could refuse `|` in variants.
