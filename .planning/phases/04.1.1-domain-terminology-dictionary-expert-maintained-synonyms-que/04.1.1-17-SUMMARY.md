# Phase 4.1.1 Plan 17: Terminology read API Summary

**Later phases now read the dictionary through one tenant-scoped, versioned, shape-locked call, `getTerminologyLexicon(scope, opts?)` from `@/lib/rag`. CI fails any `rag_term_*` RPC or table access under `src/` outside `src/lib/rag/terminology/`.**

## Accomplishments

- `lexicon.ts` builds on `loadEffectiveDictionary(scope)` from plan 05. The only tenant input is the minted `TenantScope`, and the loader sends `scopeKey(scope)` to `rag_term_effective` on the service-role client. A dictionary whose `tenantKey` differs from the scope's key is refused.
- The projection drops shared entries that collide with a workspace entry. It emits distinct `(normalized, language, kind)` terms from canonicals and variants, adds translation pairs only with `includeTranslations: true`, applies the `languages` filter (which always keeps `any`) and the `kinds` filter, then sorts and hashes the result.
- The projection is memoized per tenant key, version and options, on top of the loader's 60 s cache. A new process starts empty.
- A load failure, including a missing admin client, rejects with `TerminologyUnavailableError` (cause attached). Nothing is cached on failure, and the module reads no switch (`process.env`/`loadRagConfig` grep = 0).
- `@/lib/rag` exports the function, the error and the types. The contract test checks that the barrel export is the module's own.
- Boundary rule `terminology-rpc`: its self-test covers the rpc, template-literal rpc and generic `.from<Row>()` forms, files under `src/app` and `src/lib`, a file inside `src/lib/rag` but outside the terminology module, the terminology module itself (pass), `tests/` and `eval/harness/` (pass), and comments and bare strings (pass).

## Deviations

- **Version string:** the plan says `version` is "the one the trace and config hash record". The plan-05 loader records `s<n>` when the tenant layer version is 0, but the generated contract (`^s\d+\.w\d+$`) and this plan's single-tenant case require `s<n>.w0`. The lexicon therefore always writes `.w<n>`. The trace string is unchanged.
- **Two-tenant test was not RED:** Task 1 had already implemented the function, so the PGlite proof passed on first run. It is a proof of isolation, not a regression test for a code change.
- **Contract test import:** in the RED commit the type import came from the module, because the barrel export belongs to Task 2. Task 2 switched it to `@/lib/rag` and added a runtime check of the export.
- **Canonical JSON:** a small sorted-key serializer is inlined rather than imported from `v2/config-hash.ts`, which would pull the security modules into the read API.
- **Purge hooks:** no new store, so none are needed (the standing 4.2/3.2 purge-hook rule does not apply).
