> Visual and interaction contract for plan 04.1.1-13, the phase's only new UI surface. Written in the executor session of plan
> 13 with the `frontend-design` skill, under the owner's standing instruction (2026-11-27) that checkpoint decisions are taken

## 0. Findings that shape this contract

1. **All routes exist** (plans 09, 11, 12): list/create, patch/delete, suppressions, versions, audit, import, export, preview,
   candidates and candidate decisions. No field is proposed here; the panel consumes the shapes as built.
2. **The config-server proxy only relays JSON.** `GET …/terminology/export` answers `text/csv`; the proxy parses every body as
   JSON and would answer 502. The proxy must pass a CSV attachment through unchanged (content type, disposition, `nosniff`,
   `no-store`), and only that.
3. **The config-server JSON body limit is Express's default 100 KB.** An import body may be up to 1.5 MB (the route's own cap).
   The terminology import path needs its own `express.json({ limit: '1.5mb' })` ahead of the global parser.
4. **The workspace comes from the page-wide `#workspace-selector`** (Document Processing), as for every Phase 3.2 panel. The
   panel does not add a second organization picker; it follows that one and says so in its description.
5. **Single-tenant is known from the server**: `GET …/versions` returns `workspace: null`. The layer switch is hidden then and
   the layer is always `shared`. In multi-tenant mode the workspace layer is the selected organization, or the admin's own
   workspace when none is selected.
6. **Languages come only from `enabled_languages`** of the list or versions response (D-35). The panel holds no language code.
   Names are shown with `Intl.DisplayNames` in the language itself (as Translation targets does), the code next to it.
7. **Validation issues carry a code and a message, no field path.** The editor places each issue next to a field by its code
   (section 6.3).
8. **A suppression is a workspace row** that hides one shared entry. It is created from the shared list while a workspace is
   selected and removed from the workspace list.

## 1. Design System

| Property | Value |
|----------|-------|
| Tool | none (static page) |
| Preset | not applicable |
| Component library | DaisyUI 4.4.24 classes; `rag-ui.js` helpers (`ragUiEl`, `ragUiAlert`, `ragUiSubTabs`, `ragUiConfirmDialog`, `ragUiMapError`, `ragUiButtonBusy`) |
| Icon library | Bootstrap Icons (decorative, `aria-hidden`, always next to a word) |
| Font | page default (system sans); `font-mono` for terms, tokens, codes and versions |

Direction (frontend-design): a working tool for domain experts, not a dashboard. Dense, quiet tables; terms set in mono so
variants, spacing and punctuation are visible exactly as stored; one primary action per view; colour only for state (error,
warning, success) and the single primary button. The panel sits as one card in the RAG administration column, like its
neighbours, and is organised by sub-tabs so the card stays one screen tall.

## 2. Spacing, typography, colour

Reused from `03.2-UI-SPEC.md` sections 2 to 5 without change: card `bg-base-200`, inner blocks `bg-base-100 rounded-lg p-4`,
gaps 8/16/24 px (`gap-2`, `gap-4`, `mt-6`), headings `text-lg font-semibold` (card) and `text-base font-semibold` (block),
body `text-sm`, help `text-xs text-base-content/70`, tables `table table-sm`, buttons `btn md:btn-sm` with 44 px touch height
below `md`. Accent (`btn-primary`) is reserved for: Save entry, Check file, Apply import, Preview. Destructive (`btn-error`)
only inside the delete, replace-import and dismiss confirmations.


## 4. Surfaces

### 4.1 Section, layer switch, workspace (surface 1)

- Title "Terminology"; description: maintains the dictionary that expands search queries with synonyms, abbreviations and
  other spellings; translation pairs are stored for translation features. Follows the workspace chosen under Document
  Processing.
- Layer switch: a `fieldset` with legend "Dictionary layer" and two radio buttons styled as a `join`: Shared (all workspaces)
  and Workspace (this workspace only). Changing it reloads the entries, candidates stay workspace-scoped.
- Hidden when the versions response says single-tenant.

### 4.2 Entry list (surface 2)

- Toolbar: search input (label "Search terms", max 64, debounced 300 ms, `type=search`), New entry button, count line
  "Entries: N".
- Table columns: Term (canonical, mono), Variants (mono, comma-separated, wraps), Kind, Language (name; for a translation pair
  "source → target"), Mode, Status (Enabled / Disabled; a suppression row says "Hidden shared entry"), Actions.
- Actions per row: Edit, Delete. In the shared list while a workspace exists: "Hide in workspace". In the workspace list a
  suppression row has only "Show again".
- Pagination: 25 per page, Previous / Next buttons and "Showing a–b of N".
- Empty: "No entries in this layer yet." plus "Create the first one with New entry, or import a CSV file."
- No match: "No entries match this search."

### 4.3 Create and edit form (surface 3)

An inline block (not a modal) under the toolbar, heading "New entry" or "Edit entry", focus moves to the first field.

| Field | Control | Rules shown |
|-------|---------|-------------|
| Term (canonical) | text, max 64, required | "The term the documents use." |
| Variants | textarea, one per line, 1–16 lines, each ≤ 64 | "Other ways people write it. One per line. A variant cannot contain the character `\|`." |
| Kind | select: Synonym, Abbreviation, Alias, Identifier, Misspelling, Translation pair | — |
| Language | select: Any language + each enabled language | non-translation kinds only |
| Source language / Target language | two selects of the enabled languages | translation only; must differ |
| Mode | select: One way (variant finds the term) / Equivalent (each finds all) | translation: fixed text "One way", no control |
| Enabled | checkbox | — |
| Note | textarea, max 500 | optional |

- Translation: the variants are the source-language terms, the term is the target-language term; the form says so.
- Client checks before sending: required term, at least one variant, limits, `|` in a variant, translation languages set and
  different. Client issues use the same issue list as server issues.
- Save sends `expected_version` = the loaded layer version. 201/200 with warnings: the success line plus each warning.
- 422: each issue under its field (section 6.3), plus a summary alert "Not saved. Fix the issues below." with focus on it.
- 409: alert "This dictionary changed since you loaded it." with a Reload button; the draft stays in the form.
- Cancel closes the form; Escape inside the form does the same.

### 4.4 Delete and suppress confirmations (surface 4)

- Delete: `ragUiConfirmDialog`, tone error. Title "Delete this entry?", body names the term (text) and says the change applies
  to searches within a minute. Keep: "Keep entry"; confirm: "Delete entry".
- Hide in workspace: tone primary. Title "Hide this shared entry in this workspace?"; body: the workspace stops using it, other
  workspaces keep it. Confirm: "Hide entry". Show again needs no confirmation (it restores).

### 4.5 History (surface 5)

- Versions line: "Shared layer: version N" and, when present, "Workspace layer: version N", each with the first 12 characters
  of `entries_sha256` in mono.
- Recent changes table for the current layer (20 rows, newest first, More button): When (locale date-time), Action (create,
  update, delete, suppress, unsuppress, import, candidate accept, candidate dismiss; unknown actions shown as the code), Term
  (canonical of `after` or `before` when present), Version, By (first 8 characters of the actor id, mono).

### 4.6 Import and export (surface 6)

- Columns explained: a definition list of the nine CSV columns (`canonical, variants, language, kind, mode, enabled, note,
  source_language, target_language`), each with one sentence; variants are separated by `|`; the last two only for kind
  `translation`; UTF-8, at most 1 MB and 5,000 rows.
- Steps: 1 choose a file (`.csv` or the DictionaryCandidate `.jsonl` export), 2 choose Merge (add and update) or Replace
  (the layer becomes exactly the file), 3 Check file (dry run), 4 Apply import.
- Report: counts (To create, To update, Unchanged, To delete) and an issue table (Row, Severity, Issue, Detail). Apply is
  enabled only after a dry run of the same file and mode with no error issue; it sends `layer_version_seen`.
- Replace with deletions confirms first: "Replace the layer? N entries not in the file will be deleted."
- 400 `invalid_file`: alert "The file could not be read." with the row-numbered errors listed. 413: "The file is too large
  (1 MB or 5,000 rows at most)." 409 on apply: the changed-dictionary alert and "Check the file again."
- Export: button "Export CSV" downloads `terminology-<layer>-v<version>.csv` through the app route; the server neutralises
  formulas.

### 4.7 Query preview (surface 7)

- Textarea "Query" (max 1,000), Preview button. Checkbox "Include the entry being edited" when the editor holds a draft.
- Result: version (mono), Matches table (Found text, Term, Kind, Layer), "Added to the search" token chips (mono), "Original
  tokens" chips, Overrides list (workspace entries that replace a shared one), issues list.
- Empty: "No dictionary term was found in this query." Translation pairs never match (stated in help text).

### 4.8 Candidate review (surface 8)

- Workspace-scoped list of pending candidates, 25 per page with More: Term (mono), Language, Support ("Queries: N"),
  Documents ("Documents: N", the corpus df), Last seen, up to three masked example queries in a collapsed `details` (text only).
- Add to dictionary: switches to Entries, opens New entry with the candidate as the first variant, its language (or Any when
  it is not enabled), kind Synonym; after a successful save the panel accepts the candidate with the new entry id.
- Dismiss: confirmation, tone error: "Dismiss this candidate? It will not be suggested again."
- Empty: "No candidates to review." plus "Candidates come from searches that found nothing; the operator runs the miner."
- 409 not_pending: "This candidate was already decided." and the list reloads.

### 4.9 Terminology switches in the v2 retrieval card (surface 9)

Plan 02 placed `RAG_TERMINOLOGY`, `RAG_TERMINOLOGY_DENSE` and `RAG_TERMINOLOGY_MINING` next to `RAG_LEXICAL_TRANSLATION`, each
with a help line tied by `aria-describedby`. Reviewed for consistency: same checkbox class and label pattern as the card's
other switches; help text is plain and neutral. No change required.

## 5. Copywriting rules

- en, zh and it tables with key parity; English is the fallback. No domain content (D-37): placeholders in fields use the
  D-37 placeholders `termalpha` (variant) and `term alpha beta` (term) only.
- Counts are "label: number" (`ragUiCount`), never plural forms.
- Server issue messages are shown as given (English), after the localized issue name.

## 6. Behaviour rules

1. **Text only.** Every value from the server (terms, variants, notes, examples, issue messages, audit fields) is set with
   `textContent` through `ragUiEl`. The file contains no `innerHTML`.
2. **Requests** go through `ragUiRagRequest` → `ragFetch` to `/api/rag/admin/terminology*`; export uses `buildRagFetchInit`
   with `Accept: text/csv`. 401/403/503 use `ragUiMapError` (sign-in, workspace, unavailable alerts).
3. **Issue placement**: `conflict`, `chain`, `cycle`, `duplicate`, `invalid_variant` → Variants; `invalid_language` → Language
   (or Source language for a pair); `invalid_translation` → Target language for a pair, otherwise Kind; `override` → a warning
   under Term; `limit` → the summary. Each issue line is an icon, the localized issue name and the server message.
4. **Version**: every write sends the version the list returned; a 409 never retries by itself.
5. **Focus**: the form heading on open, the summary alert after a failed save, the row's Edit button after a save or cancel,
   the status line after delete.

## 9. Decisions taken in this session

1. Inline editor, not a modal: experts often edit several entries in a row and compare with the list.
2. Sub-tabs keep the card short; Entries is the default tab.
3. The page-wide workspace selector is reused (finding 4); no second picker.
4. The client refuses `|` in a variant (closes plan 11's known limitation for the UI path; the API path stays as is).
5. The config server gets the two narrow changes of findings 2 and 3; nothing else in the proxy changes.
