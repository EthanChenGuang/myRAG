# Phase 4.1.1 Plan Index

16 plans in 9 waves (plan 16 was split out of the tracer plan 05 and runs in wave 3). Plans in the same wave share no file in `files_modified`; every file touched by two plans is ordered by a `depends_on` path (`src/lib/rag/index.ts`: 09 → 11 → 12; `stages/query.ts`, `stages/search.ts`, `terminology/expand.ts`: 05 → 07; `terminology/matcher.ts`: 05 → 06; `v2/result.ts`: 16 → 08; Config UI files: 02 → 13). The phase tracer is 04.1.1-05 Task 1 (seeded dictionary → `terminology` stage → `term:0` list → RRF → eval route). Every plan runs after Phase 4.1 is complete. Live checks are plan 15; everything else is automated (see `04.1.1-VALIDATION.md`).

Execution note: plans 03, 04, 05, 07, 08, 09, 10, 11, 12, 16 build PGlite fixture databases (`createFixtureDatabase` applies every migration). `.planning/config.json` has `use_worktrees: false`, so within one working tree never run two of them at the same time; run same-wave plans of that set one after another, or in separate worktrees.

UI note: plan 13 is the only new UI surface. `/gsd-ui-phase 04.1.1` must produce `04.1.1-UI-SPEC.md` before plan 13 Task 2 (Task 1 is a blocking gate). The UI-SPEC can be produced any time after this index is approved; it does not block waves 1–6.

Migration numbers: 0471, 0472, 0473 (CONTEXT D-08). Plan 03 re-checks for collisions with Phase 4.1 and open branches before writing and renumbers everywhere if needed.
