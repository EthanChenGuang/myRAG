# Phase 4.1.1 Plan 06: Matcher hardening and validator Summary

**The terminology matcher now handles Han, Latin-script words (elisions, possessives, accents), identifiers in their whole, spaced and joined spellings, and mixed-script queries, and never matches inside an identifier or from a translation pair. `validateEntries` checks every D-24 rule, the language rules and the translation-pair rules before any write, with the enabled languages passed in by the caller.**

## Accomplishments

- `matcher.ts`: the normalized query is cut into units (one Han character, or one Latin-script word). Elided articles and possessive suffixes are masked the way `stripElisions` drops them, with the prefixes and suffixes read from `lexicalRegistryRules()`, so the list is never repeated here. Non-identifier surfaces are held in a unit trie, which gives longest-match-first matching in time linear in query length × the deepest surface (T-0411-17). Identifier entries are keyed by `identifierLexicalLookupForms` with separators removed, so `AB-1234-C`, `ab-1234-c`, `AB 1234 C` and `AB1234C` meet. No match may cut an identifier piece from `splitAtIdentifiers`. Translation pairs are still left out when the matcher is built. The exported signatures are unchanged; `termKey` is new.
- `expand.ts`: an identifier entry whose term is one identifier expands to its identifier forms (`cd-5678-e`, `cd5678e`) instead of all its query tokens (D-12).
- `validate.ts`: `validateEntries(candidates, { layer, current, shared?, enabledLanguages, minHanChars? })` is pure and deterministic, never throws on malformed input, and sorts issues by row, then code. Per entry it checks limits, duplicates (rule 4), short Han variants and tokenless variants (rule 5), languages (rule 7) and translation-pair shape (rule 8). Across the layer it checks variant conflicts (rule 1), chains (rule 2), cycles via Tarjan SCC (rule 3), overlapping equivalent sets (rule 6) and translation target conflicts (rule 9). For workspace layers it reports collisions with shared entries as override warnings. A candidate whose id is a current entry replaces that entry. It reads no environment variable and holds no language list (D-35).

## Behaviour changes (only under `RAG_PIPELINE=v2` with `RAG_TERMINOLOGY=true`; the switch is off by default)

- Latin variants now also match across a possessive (`alpha's beta`), repeated whitespace and hyphens (`alpha-beta`).
- Identifier entries match spaced and joined spellings.
- A Latin entry no longer matches a piece of an identifier: before, `ab` matched inside `AB-1234-C`.
- Identifier expansions emit whole and joined forms only.
