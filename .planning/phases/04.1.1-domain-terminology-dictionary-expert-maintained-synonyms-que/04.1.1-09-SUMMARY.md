# Phase 4.1.1 Plan 09: Terminology admin API Summary

**Admins can now list, create, update, delete and suppress dictionary entries of every kind, translation pairs included, and read versions and audit. Every request passes `checkAdmin`, a strict generated-Zod body and a server-resolved workspace, and every write is validated before it reaches the 0472 writers.**

## Accomplishments

- `src/lib/rag/terminology/admin.ts` is the one service for dictionary administration. It returns `{ ok: true, ... } | { ok: false, reason }`, where reason is one of not_admin, not_found, version_conflict, workspace_layer_unavailable, limit, invalid or unavailable. SQL words map exactly: not_admin and not_admin_of_layer become not_admin, invalid_entry becomes invalid, and anything else (including a message that merely starts with a code word) is unavailable. version_conflict takes `current_version` from the SQL DETAIL.
- Writes store `normalizeLexical` variants and pass both languages of a translation pair. They invalidate the loader cache for the tenant key, or for `'all'` after a shared write. The writing instance therefore sees the change at once; other instances see it within 60 s (D-22).
- Routes under `/api/rag/admin/terminology`:

  | Route | Success | Body / query |
  |-------|---------|--------------|
  | `GET /` | 200: items, total, limit (≤ 100), offset, layer_version, entries_sha256, enabled_languages | layer, organization_id, search, limit, offset |
  | `POST /` | 201: entry_id, layer_version, entries_sha256, warnings | entry fields + layer, organization_id, expected_version |
  | `PATCH /[id]` | 200, same fields | partial entry fields + layer, organization_id, expected_version |
  | `DELETE /[id]` | 200: layer_version, entries_sha256 | query: layer, organization_id, expected_version |
  | `POST /suppressions` | 200: layer_version, entries_sha256, suppressed | organization_id, shared_entry_id, suppressed, expected_version |
  | `GET /versions` | 200: shared and workspace `{version, entries_sha256}` (workspace null in single-tenant), enabled_languages | organization_id |
  | `GET /audit` | 200: items (newest first), total, limit, offset | layer, organization_id, limit, offset |

  Failure statuses: 400 for bad input and for workspace_layer_unavailable, 403, 404, 409 with current_version, 413 limit, 422 `{ error: 'Validation failed', issues }` and 503. Every response carries `Cache-Control: no-store`. Failure bodies are fixed strings, and logs carry only `[RAG Admin]`, the action, the layer, the kind and the version.

## Deviations from Plan

1. **Validation is in the service, not in each route.** The plan has the routes run `validateEntries`. Here the service does it, because only the service can read both layers on the snapshot the version check accepts. The routes still take the enabled languages from the settings module through `terminologyEnabledLanguages()` (the list and versions responses).
2. **`checkAdmin` is called in each route, not in `_lib.ts`.** The plan's key_link names `_lib.ts → checkAdmin`. The acceptance grep requires `checkAdmin` in the route files, and calling it first in each handler makes the guard visible where it runs.
3. **`eval/harness/fake-edge.mts` edited** (not in files_modified). It adds read-only `admin_users` and `rag_term_layers` to the table allowlist. Without them the real admin guard and the versions read cannot run through the fake edge. Both test-rag gates still pass.
4. **Workspace resolution passes no `requiredOrganizationRoles`.** The fake edge supports `in` filters on uuid columns only, so a role filter would break the matrix test. The 0472 SQL (`rag_admin_tenant_keys`) refuses a plain member anyway, and `versions` authorizes each layer through `rag_term_list_entries` before it reads the layer row.
5. **Extra:** a one-time re-read of the shared layer on a concurrent shared write (commits 6), with its failing-first test.

## Notes for later plans

- **Plan 11 (preview) and plan 12 (import/export):** reuse `_lib.ts` (`layerKeyFor`, `workspaceKey`, `failure`, `invalid`, `readJson`, `NO_STORE`). Add the next `@/lib/rag` exports after the plan-09 block in `index.ts`.
- **Plan 13 (Config UI):** take enabled languages from `GET /` or `GET /versions` (`enabled_languages`) and the expected version from `layer_version`. A 409 body has `current_version`; a 422 body has `issues` in the `TerminologyValidationIssue` shape.
- Validation reads the whole layer through paged `rag_term_list_entries` calls (100 per page, 8 in parallel). A 20,000-entry layer is 200 calls per write. If that turns out too slow live, a bulk read in the terminology module is the fix; no route change would be needed.
