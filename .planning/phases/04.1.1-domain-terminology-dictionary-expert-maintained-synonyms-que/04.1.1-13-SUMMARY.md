# Phase 4.1.1 Plan 13: Terminology Config UI panel Summary

**Domain experts can now maintain the terminology dictionary entirely from the Config UI. They can browse and search a layer, create and edit entries of every kind (including translation pairs), delete entries, and hide shared entries per workspace. They can also import a CSV file (dry run, then apply) or export one, preview what a query expands to, review mined candidates, and see versions and recent changes.**

## What was built

- **Section** `#rag-administration-terminology` in the RAG administration tab, after Translation targets. The script tag comes after `translation-targets.js`. A layer switch (Shared / Workspace) is shown only when the versions route reports a workspace, so it is hidden in single-tenant mode.
- **Entries:** a search with 300 ms debounce, a 25-row table with Previous and Next, and an inline editor.
  - A translation pair shows Source and Target language selects filled only from `enabled_languages`. Mode is fixed text ("One way"). The panel sends `language = source_language`.
  - Every other kind shows one language select with Any language plus the enabled languages.
  - Client checks run before any request: required fields, limits, a `|` in a variant, and translation languages that are missing or equal.
  - A 422 places each issue next to its field. A 409 `version_conflict` shows "This dictionary changed since you loaded it." with a Reload button, and the draft stays in the form.
  - Delete, Hide in workspace and Dismiss candidate ask for confirmation through `ragUiConfirmDialog`.
- **Import and export:**
  - The file is read client-side, with a 1 MB pre-check. A `.jsonl` file is sent as `dictionary_candidates_jsonl`.
  - Merge or Replace, then Check file, which shows the counts and a table of issues with their rows.
  - Apply import is enabled only after a dry run of the same file, mode and layer with no error. It sends `layer_version_seen`. A Replace that would delete entries asks for confirmation first.
  - `invalid_file` errors are listed with their row numbers, and 413 has its own message.
  - The nine CSV columns are explained in a collapsible block.
  - Export downloads the route's CSV attachment.
- **Preview:** shows the query, then the matches (found text, term, kind, layer), the added tokens, the original tokens, overrides, issues and the version. "Include the entry being edited" sends the open draft as `draft_entries`.
- **Candidates:** each pending candidate shows support, document count, last seen, and masked examples in a closed `details`. Add to dictionary and Dismiss are on each row, and More loads the next page.
- **History:** layer versions with a short sha, and recent audit rows (when, action, term, version, actor prefix).
- **Labels:** full en, zh and it tables with key parity, which a test checks. Copy uses only the D-37 placeholders. Every server value is set as text through `ragUiEl`, and the file contains no `innerHTML`.

## Config server (outside the plan's file list, needed for the panel to work)

1. **Pre-existing bug fixed: nested `/api/rag/*` proxy paths.**
   - Under Express 5.1, the `*path` wildcard arrives as an array, and `String(array)` joined it with commas. The proxy therefore forwarded `/api/rag/admin,terminology,versions` for every nested path. That breaks every Config UI panel that goes through the proxy, not only this one.
   - `buildRagProxyTargetPath` now re-encodes and joins the segments with `/`. The existing `.`/`..` checks and the `/api/rag` prefix check still run.
   - The test "forwards a nested path with its slashes" fails on the old code; a climb-out path is still a 400.
2. **CSV pass-through.** Only for `/api/rag/admin/terminology/export`, and only for a 2xx `text/csv` answer: the body passes through with a validated `Content-Disposition`, `nosniff` and `no-store`. Every other non-JSON answer is still a 502.
3. **Import body limit.** `express.json({ limit: '1.5mb' })` applies to `/api/rag/admin/terminology/import` only, to match the route's own cap. Other paths keep the 100 KB default; a test checks that a large body never reaches the app.
