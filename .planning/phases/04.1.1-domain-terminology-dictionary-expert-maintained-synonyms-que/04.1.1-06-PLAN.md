<task type="auto" tdd="true">
  <name>Task 2: Validator for conflicts, chains, cycles, languages and translation pairs (D-24, D-32, D-35)</name>
  <files>src/lib/rag/terminology/validate.ts, tests/rag/terminology/validate.test.ts</files>
  <read_first>

  </read_first>
  <behavior>
    - the same normalized variant "alpha beta" under two canonicals in one layer and language → conflict naming both entry ids; in two different languages → no issue; an entry with language any collides with every language
    - entry A (canonical term gamma delta, variant alpha beta) and entry B (canonical alpha beta) → chain
    - A ↔ B ↔ C loop through variants/canonicals → cycle (detected by DFS over the canonical/variant graph)
    - overlapping equivalent sets → conflict
    - variant equal to canonical → warning duplicate, dropped
    - Han variant of 1 character, a variant made only of stopwords, a variant made only of punctuation → invalid_variant
    - workspace entry colliding with a shared entry → override (warning, not error)
    - more than 16 variants or 64 characters → limit
    - a language that is not in context.enabledLanguages → invalid_language; language any is accepted for every kind except translation
    - translation pair: valid when source and target are two different enabled languages, language equals source and mode is one_way; each of these gives invalid_translation: target missing, source equal to target, language any, language different from source, mode equivalent, source_language set on a synonym
    - a translation pair whose source term is also the canonical of a same-language entry → no chain and no conflict
    - two translation pairs with the same normalized source term and the same language pair but different targets → conflict; the same source term with two different target languages → no issue
    - with a single enabled language every translation pair is rejected (the target cannot be enabled and different)
    - 5,000 entries validate in under 500 ms on the dev machine (timing assertion with a generous bound)
  </behavior>

Write the tests first, then implement `validateEntries(candidates, context)` where context holds the current layer, for workspace layers the shared layer, and `enabledLanguages` (D-24). Everything is normalized with normalizeLexical. Per D-35 the function takes the enabled languages from its argument only; the routes and the import pass them from the Phase 3.2 settings module. Return issues sorted by row then code; never throw on user input.
