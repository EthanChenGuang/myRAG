# Phase 3.1.1 Plan 04: Scoped embedding profiles and bindings schema Summary

**Migration 0440 adds per-doc-type scope to embedding profiles, three scoped Voyage candidates with their own HNSW indexes, a scope-aware chunk_embeddings guard and the service-role-only `embedding_profile_bindings` table. The database enforces every invariant in both deployment modes.**

## Accomplishments
- `embedding_profiles.doc_types text[]`, with CHECK `embedding_profiles_doc_types_check` (NULL, or a non-empty subset of the six doc type ids).
- Scope trigger `rag_embedding_profiles_scope_guard` (SECURITY INVOKER, `SET search_path = ''`). It refuses `active` (`activation_refused: scoped_profile`) and `backfilling` (`profile_status_refused: scoped_profile`) on a scoped profile. It also refuses a scope change once the profile has vectors, or when the change would drop a doc type the profile is bound to (`profile_status_refused: scope_locked`). The Phase 3 gate and set-status functions are not edited.
- Seeds use `ON CONFLICT DO NOTHING`: `voyage-law-2-1024` {contract_legal}, `voyage-finance-2-1024` {financial_report, invoice_receipt} and `voyage-4-large-1024-domain` {contract_legal, financial_report, invoice_receipt}. All are `available` and none is bound. Each has a partial HNSW index on `embedding::public.halfvec(1024)` with `halfvec_cosine_ops`, `m = 64` and `ef_construction = 200`.
- `rag_chunk_embeddings_guard()` starts from the 0425 body (md5 `f7aa72d3c0bcc173f7dd103cced69c03` in both modes; the header has a dry-run query). The only addition is the `COALESCE(c.doc_type, d.doc_type)` scope check (`embedding_profile_mismatch: doc_type_scope`). It keeps the empty search_path, the qualified names and the grants.
- `embedding_profile_bindings` has these unique indexes: `_single_active`, `_single_backfilling` and `_triple_ux`. Its guard `rag_embedding_bindings_guard` (SECURITY DEFINER, `SET search_path = ''`) checks the profile scope and calls `public.rag_assert_tenant_key` for a non-null tenant key. RLS is on with no policies. The table and guard are revoked from PUBLIC, anon and authenticated and granted to service_role.

## Deviations from Plan
1. **[Rule 2, missing critical] Scope lock against bindings.** The plan locks the scope only when vectors exist. Without more, a profile with a binding but no vectors could be re-scoped away from the bound doc type, which would break the D-06 invariant. The scope trigger now also refuses that change. Tested in "a profile cannot be re-scoped away from a doc type it is bound to".
2. **[Rule 3, blocking] 0410 lock-down entry.** `search-rpc-grants-pglite` simulates an upgraded database with open grants and requires 0410 to close every definer function. `rag_embedding_bindings_guard()` was added to 0410 section 1, as 07-02 did for 0702.
3. **[Rule 3, blocking] Phase 3 tests updated.** `embedding-profiles.test.mts` counted exactly five profiles and now counts the three scoped rows. `ingestion-schema.test.mts` re-applies 0425 after 0351 and now re-applies 0440 too, since 0440 supersedes 0425's guard.
