# Phase 03.1.1 Plan 08: binding-aware ingest targets Summary

New and replaced documents of a bound doc type are now written to the binding profile of their own tenant (or the deployment-wide binding) in the same `rag_write_chunks` call as the global profiles; rechunk does the same.

## Behaviour

- `RAG_DOMAIN_EMBEDDINGS=off` (default), or no binding for the document's doc type and tenant: the target list is identical to Phase 3 and no binding registry read happens.
- On: active and backfilling bindings add their profile as role `binding`. A failing binding vendor never fails the document: its vectors are left out, `embedding_gap:<profile>` is warned and each chunk is recorded as a gap of the binding's running run.
- Tenant isolation: a tenant binding applies only to that tenant's documents; a deployment binding to all. The two-tenant test asserts no `chunk_embeddings` row with a tenant other than its chunk's.
- `rag_vectors_complete` still checks only the active global profile: a contract with missing law-2 vectors publishes.
- Unchanged: `src/lib/rag/ingest/backfill/orchestrate.ts` and the deferred (Batch API) embed stage call without a scope, so they write no binding vectors.

## Deviations

1. `src/lib/rag/ingest/rechunk/cost.ts` (not in files_modified) gained the optional `RechunkCostTarget.tenantKeys`, so the dry run prices a tenant binding only for its tenant. Without a binding it computes exactly what it did before.
2. The two-tenant fixture has user tenants `u:A` / `u:B` and a single org, so the two-tenant cases use `u:` keys instead of `o:A` / `o:B`. The SQL tenant check is the same for both prefixes.
3. The fake edge's Voyage route always answers `voyage-4-large`, so the test runs its own small Voyage-shaped endpoint that echoes the model. The real Voyage provider (`createVoyageProvider({ model: 'voyage-law-2' })`) is used, so the request checks (model, no `output_dimension`) cover the real request body. The harness itself was not edited.
4. Added a rechunk DB test (binding vectors per tenant, dry-run pricing) beyond the plan's listed behaviours.
