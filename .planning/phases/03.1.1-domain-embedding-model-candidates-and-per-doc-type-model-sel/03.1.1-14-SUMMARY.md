## Task 1: Off and on-without-bindings equal the baseline

`tests/rag-e2e/domain-embeddings-off-parity.test.mts` (12 tests) runs seven smoke arms, each in its own process through `tests/rag-e2e/domain-parity-arm.mts`. The arm calls `runEval` in process with the same golden selection as `npm run test-rag`, passes the arm's variables as `appEnv`, and wraps `globalThis.fetch` to record every request URL and JSON `model`.

| Arm | Fixture | Variables |
|-----|---------|-----------|
| prechunked-off | prechunked | defaults |
| prechunked-on | prechunked | `RAG_EMBEDDING_PROFILES=on`, `RAG_DOMAIN_EMBEDDINGS=on` |
| prechunked-domain-only | prechunked | `RAG_DOMAIN_EMBEDDINGS=on` (the loader forces it off without profiles) |
| ingest-off / ingest-on | ingest | defaults / both on |
| v2-off / v2-on | prechunked | `RAG_PIPELINE=v2` / plus both on |

It checks that:
- each arm's traces record the variables it asked for;
- prechunked-off, prechunked-on, ingest-off and ingest-on each pass `rag_eval.gate` against `eval/baselines/fixture-baseline.json` or `fixture-ingest-baseline.json` with `paired.all_zero` true;
- every pair (off vs on, off vs domain-only, ingest off vs on, v2 off vs on) returns identical per-item results: the whole trace minus `stage_latency_ms`, `config_hash` and `effective_config` (which records the switch values), so chunk ids, ranks, scores, kept chunks, context, refusal and stage status all match;
- v2: every item's `retrieval_config_hash` is non-null and identical between off and on;
- positive control: the v2-on arm calls `rag_list_embedding_bindings` (the off arm never does) and no trace carries a `dense_domain:` leg;
- no arm sends a request with model `voyage-law-2` or `voyage-finance-2`, or to a Voyage embeddings route.

The test passed on the first run (39 s); the phase had already built the behaviour. Manual run as in the plan's verify: `npm run test-rag -- --out eval/out/p3.1.1-14-off`:

## Deviations from Plan

1. **New helper file.** `tests/rag-e2e/domain-parity-arm.mts` is not in `files_modified`. Each arm needs its own process because the app reads part of its environment at import time, and the run-config overlay rejects `RAG_DOMAIN_EMBEDDINGS`, so `run-smoke` cannot take the arm's variables.
2. **Ingest arms vary retrieval only.** The ingest fixture build always uses `INGEST_MODE_FEATURE_ENV`, so `RAG_DOMAIN_EMBEDDINGS` reaches the query side but not the fixture's write path. Write-path parity is covered by plan 08's DB tests. I did not change the shared harness.
3. **The spy sees global fetch only.** The OpenAI SDK's embedding calls do not go through `globalThis.fetch`. The Voyage embedder does (`src/lib/rag/embeddings/voyage.ts`), and so do all Supabase REST/RPC calls, so the vendor assertion covers the domain models.
4. **The schema-equality test gained a dedicated `assertDomainBindingsSecured`** besides the object-list extension, to name the 0440-0442 objects explicitly.
