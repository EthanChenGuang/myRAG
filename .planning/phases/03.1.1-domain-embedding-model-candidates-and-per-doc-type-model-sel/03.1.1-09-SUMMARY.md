# Phase 3.1.1 Plan 09: Binding legs at query time

**v2 retrieval now adds one dense leg per active, non-stale doc-type binding of the request's tenant, fused by RRF with similarity kept out of calibration; a failing leg degrades the search stage and never fails the request; with the switch off, or no planned leg, calls, fused output, trace and config hash are unchanged.**

## Accomplishments

- `binding-legs.ts`: `planBindingLegs` (D-07 effective bindings via `getEffectiveBindings(scopeKey(scope))`, stale skipped, docTypes intersection, sort by doc type, `maxLegs` cap; eval override and control leg for profile `eval` only), `startBindingEmbeds` (one embed per leg with `embedQueryForEvalProfile`, own timer, never rejects), `runBindingLegs` (backend request with the request's `TenantScope`, `embeddingProfileId` = binding profile, `docTypes: [type]` and every other filter unchanged, `lexicalTokens: []`, `lexicalLimit: 0`, `denseLimit: candidate_pool_size`; hits mapped to `similarity: null`; list `dense_domain:<type>` with weight `leg_weights.domain ?? 1`).
- `pipeline.ts`: plans legs after the query stages and starts their embeds (original variant text) before the embed stage; passes plan and embeds to the search stage and the hash fields to `buildV2Result`.
- `search.ts`: binding legs run inside the `search` stage concurrently with the variant searches; their lists join the RRF input after the variant and exact-id lists; counts gain `domain` (and `domain_control`); a dropped leg records the stage `degraded` with `binding_leg_<reason>:<doc_type>`.
- `config-hash.ts` / `result.ts`: optional `embeddingBindings` and `domainControlLeg`, emitted as `embedding_bindings` / `domain_control_leg` only when present.
- Acceptance greps: `dense_domain:` in binding-legs.ts = 1, `similarity: null` = 1, `startBindingEmbeds` in pipeline.ts = 2, `runBindingLegs` in search.ts = 2.

## Behaviour changes

- None with `RAG_DOMAIN_EMBEDDINGS=off` (default), `RAG_EMBEDDING_PROFILES=off`, `RAG_DOMAIN_EMBEDDING_MAX_LEGS=0`, the legacy pipeline, voice, or no effective non-stale binding in the request's tenant: no binding read (off/voice), no extra backend call, same fused output, stage records and retrieval config hash (snapshot and pipeline tests).
- With it on and a planned leg: one extra backend call per leg, extra RRF lists, `counts.domain` on the search stage, and a different retrieval config hash for that tenant's requests. A dropped leg marks the search stage (and so the result status) `degraded`; the answer still uses the global legs.
- Strict "information not available", webSearch with Exa, `source_images`, `{{context}}`, voice and embed chat: unchanged with the switch off. With it on, binding-only hits carry similarity null and the similarity floor and refusal calibration keep reading the global similarity (D-20).
