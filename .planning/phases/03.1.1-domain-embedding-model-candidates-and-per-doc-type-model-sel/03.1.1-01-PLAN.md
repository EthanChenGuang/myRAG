<objective>
Make the embedding layer serve more than one model per provider, from one catalog of official model facts (D-01, D-02).

Purpose: today `createVoyageProvider` in `voyage.ts` hardcodes `voyage-4-large` (`model: VOYAGE_MODEL_ID`) and every model check compares `provider.model` with `profile.model`, so a `voyage-law-2` profile would be reported as a model mismatch at startup, ingest and query. This plan removes that blocker without changing behaviour for existing profiles.
Output: catalog.ts, a model-aware Voyage provider and registry lookup, per-model prices, tests. The provider lookups (ten in seven files at 8115886) move to the model-aware lookup in plan 03.1.1-16 (split for plan-check W2).

Runs after Phase 3 is complete. Relies on 03-08 (providers, registry) and 03-36 (re-embed run reads `run.provider`).

Commit rule for every task: plain `git commit`; the message ends with the attribution lines the executor's own session supplies; never copy them from a plan. No keys, no vendor response text in errors or logs.
</objective>
