# Phase 03.1.1 Plan 13: binding admin routes and Config UI panel Summary

Admins can list, create, stage, activate, roll back and deactivate domain-embedding bindings over authenticated routes and from a new "Embedding bindings" panel in the Config UI.

## Behaviour

- New routes only; no existing route, retrieval, ingest or chat path changed. With `RAG_DOMAIN_EMBEDDINGS=off` the panel still manages bindings (they are stored, not used) and says so.
- `GET /api/rag/admin/embedding-bindings`: bindings with doc type, scope, profile, model, status, stale, has_evidence, baseline, activated_at/by and completeness; never an evidence body or chunk text.
- `POST` `{action:'create', doc_type, profile_id, tenant_key}` → 201/200; `{action:'set_status', binding_id, status: available|backfilling|retired}` → 200; `active` → 400.
- `POST [id]/activate` (empty body) → 200 `{activated, previous}`; `rollback` / `deactivate` `{doc_type, tenant_key}` → 200; gate refusal → 409.
- Panel: one table per doc type, Activate disabled without evidence with the `record-binding-evidence` command shown, confirmation dialog for activate, roll back and deactivate, refusal reason and detail shown verbatim.
