## Top 3 Priority Fixes

1. **Mobile table collapses the Profile column** (BLOCKER) — on 390px the operator cannot read the profile id or see status/actions without scrolling the table sideways (`screenshots/03.1.1-bindings-populated-mobile.png`) — give the table a minimum width (e.g. `min-w-[48rem]` is off-contract; prefer `min-w-max` on `table`, or stack below `md` as a card list) and drop `min-w-40` on the Scope `th` below `md` (`embedding-bindings.js:544-545`).
2. **Submit not disabled when no profile is scoped to the chosen type** (WARNING) — spec L286 says submit is disabled; code lets the user submit and then shows an error (`embedding-bindings.js:900`, `:959`) — set `disabled` on submit when `noProfile`.
3. **Stale hint with missing baseline reads "recorded against None"** (WARNING) — confusing sentence (`populated-desktop.png`, `embedding-bindings.js:600`) — when `baseline_global_profile` is null use `evidence.noBaseline` phrasing or a separate copy key instead of substituting `state.none`.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- WARNING: `form.profile.none` differs from spec L429; code adds "Choose another document type;" (`embedding-bindings.js:97`). Either update spec or revert copy; the two must agree.
- WARNING: Form secondary button is generic "Cancel" (`embedding-bindings.js:101`, spec L288/L432) — checker BLOCK; suggest "Close form" or "Discard binding".
- WARNING: `hint.stale` renders "recorded against None" when baseline is null (`:600`, `populated-desktop.png`). Synthetic data, but the code path exists.
- INFO: Single-verb row labels (Activate, Retire, Deactivate, Refresh) are disambiguated by `aria.action` (`:632`), so acceptable; checker FLAG noted.
- INFO: English only (U-05). Project rule asks zh/en/it parity for Config UI copy where applicable; doc-type labels already follow the locale, static copy does not. Track as follow-up.
- PASS: refusal reason shown verbatim; `error.unconfirmed` does not claim success.

### Pillar 2: Visuals (2/4)
- BLOCKER: Mobile (`populated-mobile.png`): Scope column holds `min-w-40` + long tenant key, Profile column shrinks to ~4 chars per line (`break-all`), Status is clipped, Complete/Evidence/actions require horizontal scroll inside `overflow-x-auto`. The page itself does not overflow, but the table is not usable. Same in `empty-mobile`/`form-open-mobile` only for the form (fine).
- WARNING: Disabled `btn-primary` Activate renders as a near-invisible block (`populated-desktop.png`, rows 2 and 4); only the visible hint below explains it. Acceptable per spec, but the button outline is lost; consider `btn-outline` styling when gated or rely on the hint being adjacent.
- WARNING: The evidence-needed hint repeats a long CLI command right-aligned under the actions, producing ragged right-aligned mono lines that dominate the row (`populated-desktop.png`). Left-align the `code` or let it sit in its own block (`:639`).
- WARNING: "Retire" (`btn md:btn-sm`, no outline) reads as plain text on base-200 and wraps to a second line alone (`populated-desktop.png`).
- PASS: Status cell is the clear focal point; badges always carry words; icons `aria-hidden`.

### Pillar 3: Color (3/4)
- PASS: `btn-primary` only on row Activate (`:311`), Create binding (`:900`), dialog confirm (`:684`), empty-state New binding (`:499`) — matches spec L137.
- PASS: No hex colors; tokens only; warning/success/info always paired with text.
- WARNING: Disabled primary contrast (see Visuals) — the gated state loses its accent and nearly its shape.
- INFO: "On" badge is `badge-success badge-outline` (`:469`) as specified.

### Pillar 4: Typography (3/4)
- Sizes used: `text-xs`, `text-sm`, `text-base`, `text-lg` (spec's four). Weights: 400, 600. PASS.
- WARNING: `bindingsMono(..., 'font-mono break-all')` for actor and baseline (`:595`, `:610`) omits a size class, so it inherits the hint's `text-xs`; fine, but `bindingsMono` default `text-sm` is used inside `text-xs` contexts elsewhere (tenant key under Scope at `text-sm` vs label text-sm OK). Minor drift; keep size explicit.
- INFO: Group heading mixes label (`text-base`) and id (`text-xs` mono) on one baseline — spec-compliant.

### Pillar 5: Spacing (3/4)
- PASS: `gap-1/2`, `mb-2/4`, `py-4`, `p-4`, `mt-4`, `py-8`, `gap-x-6` all on the 4px grid.
- INFO: `mt-0.5` on alert icons and field-error icons (`:289`, `:616`, `:798`) — declared exception (spec L109); checker FLAG.
- WARNING: In the Complete cell the `flex items-center justify-end gap-1` missing-line wraps, leaving the warning triangle vertically centered far left of a three-line text block (`populated-desktop.png`). Use `items-start` and/or `whitespace-nowrap` on the count (`:579`).
- WARNING: `mt-2` on the info alert and the no-profiles line inside a host that already has `mb-4` (`:482`, `:485`) — small double spacing; acceptable.

### Pillar 6: Experience Design (2/4)
- PASS: loading (spinner + live status), refresh dimming with `aria-busy`, 401/403 sign-in alert (`signed-out-desktop.png`), 503 registry alert (`registry-503-desktop.png`), network (`real-unmocked-desktop.png`), empty (`empty-desktop.png`), no scoped profile (`no-scoped-profile-desktop.png`), switch off (`switch-off-desktop.png`), dialog with keep focused and busy state (`confirm-dialog-desktop.png`), 409 note rows, one-mutation-at-a-time via `setBusy`.
- BLOCKER (shared with Visuals): on mobile, row actions sit beyond the scroll edge; touch users must discover the in-table horizontal scroll.
- WARNING: Submit not disabled when `form.profile.none` applies (spec L286; `:900`, `:959`).
- WARNING: Form 409/400 path: after `setBusy(false)` the form is re-rendered but `this.newBtn` may stay enabled while the form is open; harmless. More importantly a POST 401 inside the form (`:982`) leaves `formOpen` true while content is hidden; reopening after reload shows a stale form. Reset `formOpen` in `showSignIn`.
- WARNING: `mutate` captures status text, then `load()` clears/sets, then restores — on a 503 GET after a mutation the registry alert and the mutation message both show; acceptable but noisy.
- WARNING: Esc closes the form only while focus is inside the `<form>` (`:921`); spec says Esc closes the form — fine in practice, note only.
- INFO: no destructive actions; all flips confirmed with dialog per U-04.
