## Decisions made here

No question was put to the user; each choice below is recorded so it can be overturned in one place.

| # | Decision | Reason |
|---|----------|--------|
| U-01 | The panel is a new `<section id="rag-administration-bindings">` inserted between the "Embedding profiles" section (`index.html:9446-9456`) and the "Chunking profiles" section (`index.html:9458`). | "Next to Embedding profiles"; bindings read after profiles. |
| U-02 | No new CSS, no `<style>` rule, no new CDN asset, no new color. Only classes that already appear in the RAG administration panels. | The panel must look like its neighbours. |
| U-03 | Layout is one block per document type with a table, the pattern of the Chunking profiles panel (`rag-panels/chunking-profiles.js:1617`, `:1691`), not the article cards of Embedding profiles (`rag-panels/embedding-profiles.js:74-75`). | A grouped table is required; the cards cannot show scope, completeness and evidence side by side. |
| U-04 | Confirmation uses the `<dialog class="modal">` pattern (`chunking-profiles.js:2321-2376`), not `globalThis.confirm` (`embedding-profiles.js:119`, `quarantine.js:96`). | The confirmation must name document type, scope and profile, show a busy state and return focus. |
| U-05 | Static copy is English only, like the Embedding profiles and Quarantine panels and the 03.1.1-03 fields. All strings live in one keyed table (`BINDINGS_COPY`), so zh and it can be added without touching render code. Document type names come from the existing label source, which already has en, zh and it. | Matches the adjacent panels; keeps doc-type label parity. |
| U-06 | A document type is shown as its label from `window.docTypeLabelForLocale(id, locale)` (`doc-types.js:52-55`, `:237`) with the id beside it in mono. When the function is missing or returns the id, only the id is shown. The panel file holds no document type id or label of its own. | Plan must_have "ids/labels from the existing doc-type label source"; owner neutrality rule. |
| U-07 | The only client-side gate is evidence: Activate is disabled when `has_evidence` is false. Every other rule is the server's; its refusal is shown verbatim. | Avoids a second copy of the gate that would drift from 0441. |
| U-08 | "Stale" is the API `stale` flag (active rows only). "Incomplete" is an active row whose completeness is measured with `missing > 0`. A backfilling row shows its percent without a warning badge. | Being incomplete is expected while backfilling; it is a problem only once active. |
| U-09 | No evidence upload, no preset binding, no delete action, no default document type or profile in the form. | D-13, owner rule. |
| U-10 | Panel logic goes in `scripts/config-ui/rag-panels/embedding-bindings.js`, loaded by a `<script>` tag after `index.html:76`, with pure view functions exported through `module.exports` (pattern `embedding-profiles.js:130-154`). ## Design System

| Property | Value |
|----------|-------|
| Tool | daisyUI 4.4.24 on the Tailwind Play CDN (`index.html:29-30`). shadcn (`components.json`) exists for the Next.js app and cannot be used in this static page. |
| Preset | not applicable |
| Component library | daisyUI component classes; no JS component library |
| Icon library | Bootstrap Icons 1.11.3 (`index.html:31`), `<i class="bi bi-…" aria-hidden="true">` |
| Font | Tailwind default sans stack (no webfont is loaded); `font-mono` for ids, env names and commands |

Design direction (frontend-design skill, applied inside the existing system): the audience is an operator who also uses the CLI, and the job is to see which binding is in which state and what blocks the next step. The one emphasized element is the Status cell: state badge, problem badges and one sentence of consequence, read in a single glance. Everything else stays quiet: no decoration, no extra color, no motion beyond the existing spinner. Ids are mono because they are copied into CLI commands, not as ornament. Meta strings are not joined with middle dots; each fact has its own cell or line.

## Data to view

Source: `GET /api/rag/admin/embedding-bindings` through `ragFetch('admin/embedding-bindings', { method: 'GET' })`. The panel calls only this route and the four POST routes in "Actions".

**State line** (`data-rag-bindings-state`): a `dl.flex flex-wrap gap-x-6 gap-y-1 text-sm` with two pairs.
- "Domain embeddings": badge "On" (`badge badge-success badge-outline badge-sm`) when `switch === 'on'`, else "Off" (`badge badge-ghost badge-sm`); then `<code>RAG_DOMAIN_EMBEDDINGS</code>`.
- "Global active profile": `global_active` in mono, or the dash with sr-only "None" when null.
- When `switch === 'off'`: below the `dl`, an `alert alert-info` with `bi-info-circle` and copy `off.note` (or `off.noteProfiles` when `profiles_switch === 'off'`). It is a standing note, not a live region. All actions stay enabled while the switch is off.

**Groups:** one block per document type that has at least one binding, in the order of the API `doc_types` array. Block heading: label (U-06) as `h4`, then the id as `span.font-mono text-xs text-base-content/70` with `translate="no"`. Document types without bindings get no block; they are reached through "New binding".

**Rows:** one per binding. Order inside a block: deployment-wide rows (`tenant_key === null`) first, then tenant rows by `tenant_key`; inside one scope by status `active`, `backfilling`, `available`, `retired`, then by `profile_id`.

| `completeness` | Cell |
|----------------|------|

## Actions

All through `ragFetch` with `method: 'POST'`. One mutation at a time: while a request runs, every action button and both toolbar buttons are `disabled`, and the acting button shows the spinner before its label.

| Row status | Buttons, in order | Class | Request | Confirm |
|------------|-------------------|-------|---------|---------|
| available | Stage for backfill | `btn btn-outline md:btn-sm` | `admin/embedding-bindings` `{ action: 'set_status', binding_id, status: 'backfilling' }` | no |
| available, backfilling | Activate | `btn btn-primary md:btn-sm` | `admin/embedding-bindings/{id}/activate`, body `{}` | yes |
| backfilling, retired | Mark available | `btn btn-outline md:btn-sm` | `set_status` with `status: 'available'` | no |
| available, backfilling | Retire | `btn md:btn-sm` | `set_status` with `status: 'retired'` | no |
| active, `previous_binding_id` not null | Roll back (with `bi-arrow-counterclockwise`) | `btn btn-outline md:btn-sm` | `admin/embedding-bindings/rollback` `{ doc_type, tenant_key }` | yes |
| active | Deactivate | `btn btn-outline md:btn-sm` | `admin/embedding-bindings/deactivate` `{ doc_type, tenant_key }` | yes |

- `tenant_key` is sent as the row's value, `null` for a deployment-wide row. The id in the activate path is passed through `encodeURIComponent`.
- Every row button has an `aria-label` from `aria.action` (action, profile, document type, scope) and `data-rag-bindings-focus="{action}:{binding id}"`.
- **Activate without evidence:** `disabled`, `aria-disabled="true"`, `title` = `activate.needsEvidence.short`, and `aria-describedby` pointing at a visible line under the buttons (`text-xs text-base-content/70 text-right mt-1 max-w-prose ml-auto`) with `activate.needsEvidence` followed by `<code translate="no">npm run rag:embedding -- record-binding-evidence &lt;comparison.json&gt; --binding {binding id}</code>`. The binding id is the row's real id. The explanation is visible text because a disabled button cannot be focused or hovered on touch.

### Confirmation dialog (activate, roll back, deactivate)

Structure and behaviour as `chunking-profiles.js:2337-2376`: `dialog.modal` with `aria-labelledby="rag-bindings-dialog-title"` and `aria-describedby="rag-bindings-dialog-body"`; title `h4.text-base font-semibold break-words text-balance`; body `p.text-sm mt-2 break-words`; `modal-action flex-wrap` with the keep button (`btn`, focused on open) then the confirm button (`btn btn-primary`). Esc and the backdrop close it without a request. After confirm: both buttons disabled, Esc blocked, confirm shows spinner and the busy label, the request runs, the dialog closes. Cancel returns focus to the button that opened it. Copy keys: `confirm.{activate,rollback,deactivate}.{title,body,action,busy}` and `confirm.keep`. When `switch === 'off'`, the activate body ends with `confirm.activate.off`.

### Create form

Opened by "New binding" (`aria-expanded` toggles; a second click focuses the first field). Region as in the inventory, `id="rag-bindings-form"`, title `form.title`. A real `<form novalidate>`; Enter submits, Esc closes and returns focus to "New binding".

## Feedback and errors

`ragFetch` does not catch a rejected `fetch`; every call is wrapped in `try/catch` and a rejection is handled as "network".

| Case | Where | What |
|------|-------|------|
| Action succeeded | status line | The matching `result.*` copy. List reloads; focus moves to the status line. |
| 409 `binding_refused` | status line, and a note row under the affected row (`tr > td[colspan=6]` holding `alert alert-error` with `bi-x-octagon`) | Status line: `refusal.status` with the reason. Note: `refusal.lead`, then `body.reason` exactly as received in `code.font-mono text-xs break-words` with `translate="no"`; when `body.detail` is a string different from `reason`, it follows on its own line, also verbatim. No mapping, no translation, no trimming of the `binding_refused:` prefix. Missing reason falls back to `binding_refused: unknown` (`embedding-profiles.js:5-13`). The note stays until the next action on that row or a refresh. |
| 400 outside the form | status line (`text-error`) | `body.error`, then the `details[].message` values joined with "; ". |
| 401 or 403 (any call) | alert host | `alert alert-warning` with `bi-person-lock`, text `authMessage(status)` verbatim (`rag-fetch.js:15-23`), button "Reload panel" (`btn btn-sm`). `data-rag-bindings-content` is hidden. Pattern `chunking-profiles.js:1475-1481`. |
| 503 on GET | alert host | `alert alert-error` with `bi-exclamation-octagon`, copy `error.registry`, button "Try again" (`btn btn-sm`). With earlier data the list stays, dimmed by `opacity-60`; without it the list is empty. "New binding" is disabled. |
| 503 or network on a POST | status line (`text-error`), then reload | `error.unconfirmed`. The change may have been applied, so the copy does not claim otherwise. |
| Network on GET | alert host | `alert alert-error`, copy `error.network`, button "Try again". |
| Other status | status line (`text-error`) | The `message` from `ragFetch`. |

The status line is the only live region (`role="status"`, polite). Error text on it adds `text-error` and a leading `bi-exclamation-circle` (`chunking-profiles.js:1483-1491`). Note rows and alerts carry no live role, so one outcome is announced once.

## Accessibility

- Landmarks and names: the section is labelled by its `h3`; each document type block is `role="group"` labelled by its `h4`; the form is `role="region"` labelled by its title.
- Tables: sr-only caption, `th scope="col"`, the Scope cell is `th scope="row"`.
- Buttons with the same visible text on several rows have distinct `aria-label`s. Icons are `aria-hidden="true"`.
- Results reach assistive technology through the polite status line, which also receives focus after a mutation (`tabindex="-1"`, visible focus ring classes in the markup above).
- Dialog: native `<dialog>` with `showModal()` gives the focus trap and Esc; initial focus is the keep button; focus returns to the opener on cancel.
- Form: every control has a `<label for>` or a `legend`; help text is linked with `aria-describedby`; an invalid field gets `aria-invalid="true"` and its message id in `aria-describedby`.
- Keyboard: only native buttons, selects, radios and inputs; Tab order follows the visual order (toolbar, form, blocks top to bottom, actions left to right). No hover-only information: the reason Activate is disabled is visible text.
- State is never carried by color alone: every badge has a word, every warning has an icon and a sentence.
- `translate="no"` on ids, tenant keys, env names, commands and refusal text.
- Motion: only the existing spinner, hidden under `motion-reduce`.
- Touch: row actions are 48px high below `md`.
- Dates use `<time datetime>` and `Intl.DateTimeFormat`; numbers use `Intl.NumberFormat`.
